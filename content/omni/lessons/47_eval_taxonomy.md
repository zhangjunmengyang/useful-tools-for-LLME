# 第 47 课：把六类评测数字分桶记账

> 内容：六类评测协议分类、互斥标签与分桶账本，不引入新模型<br>
> 建议周期：阅读约 70 分钟；浏览器分桶实验约 10 分钟；CPU 互斥夹具数分钟<br>
> 硬件：无 GPU 可完成本课阅读、教学模拟与 CPU 机制实验。复现论文规模评测需要对应基准的推理或虚拟机资源<br>
> 产物：六类协议卡、互斥标签夹具、禁止横比的分桶账本

## 1. 六类评测数字为什么不能横着比

到这一课，课程里已经出现过三套看起来都能写成百分数的账。[第 01 课](01_baseline_reproduction.md) 要求 golden case 按模态、长度、speaker 分桶，禁止把官方 full checkpoint 的分数写成 mini 复现误差。[第 23 课](23_grounding_ocr_spatial.md) 要求 VQA 准确率和 grounding 命中分列，幻觉率只在物体不存在的负例上计算。[第 31 课](31_vla_evaluation.md) 要求 LIBERO 四套件、SIMPLER 视觉域相关、CALVIN 长程链和真机小样本不能横着减。本课把这三套纪律合成一张更大的表，覆盖整条 Omni 与身体线上最常被并排展示的六个公开基准：MMMU、Video-MME、OmniBench、OSWorld、LIBERO、SIMPLER。

一张幻灯片上很容易出现这样六个数：MMMU 测试集 GPT-4V 55.7%；Video-MME 上 Gemini 1.5 Pro 无字幕 75.0%；OmniBench 上 Qwen2.5-Omni-7B 56.13%；OSWorld 上 GPT-4 读无障碍树 12.24%；LIBERO 四套件 OpenVLA fine-tune 宏平均 76.5%；SIMPLER Google Robot Visual Matching 平均 Pearson $r=0.924$。六个看起来都在 0 到 1 附近的量，听起来像同一把尺子量出来的“多模态能力”。

它们不是同一把尺子。MMMU 的 1 次正确，是大学试卷上对一张图表或谱面选出选项或写出短答案。Video-MME 的 1 次正确，是看完一段 11 秒到 1 小时的视频后，四选一命中。OmniBench 的 1 次正确，必须同时用图和声，缺一不可。OSWorld 的 1 次成功，是虚拟机里脚本确认亚马逊 cookie 被删了、表格被改对了。LIBERO 的 1 次成功，是 robosuite 里一组谓词全部为真。SIMPLER 的 0.924 根本不是成功率，是仿真排序和真机排序的相关系数。把这六个数减成“我们高了 20 个点”，等于把期末考试、马拉松分段、三科会考、修电脑工单、仿真抓杯子和天气预报相关写成同一列。

类比到此结束。类比失效处：体育成绩至少还共享“时间”或“距离”；这里连单位都不共享。准确率、执行成功率、Pearson $r$ 不能代数相加。本课不训新模型，不改 MiniMind-O 结构，不引入新的骨干或新的损失函数。要改的是记账协议：每条数字必须打上六类里恰好一个标签；把 LIBERO 平均写进“真机能力”必须判非法。浏览器 Lab 把六张卡拖进桶，拖进陷阱格就标红，移出后红色消失。CPU 实验证明六类标签互斥、非法映射被拒绝，并沿用第 31 课 $N=25$、$k=20$ 的 Wilson 区间，只允许同类比较。夹具数字禁止写入模型卡，也禁止标成 SOTA 或真机能力。请把这一点写在实验报告的第一页。

六类的划分标准是测量对象，不是模型名字。同一个 Qwen2.5-Omni-7B，MMMU val 进 C1，Video-MME 进 C2，OmniBench 进 C3，TTS WER 进第 01 课的语音账。同一个 OpenVLA 权重，LIBERO Table 12 进 C5，Google Robot 出厂 5 次试验进真机行，两者不能因为权重相同就合并。类标签贴在数字上，不贴在模型卡片上。这是本课和“排行榜思维”的分界：排行榜问谁更大，本课问这格是什么。更大的数字如果类错了，连进表的资格都没有。

本课术语：

| 术语 | 简要解释 |
|---|---|
| 评测类（eval class） | 一条数字所属的互斥账本：C1 到 C6 恰好一类 |
| 协议卡 | 基准名、划分、模态、成功定义、$N$、是否 fine-tune、单位 |
| 互斥标签 | 一条记录不能同时属于两类；两类的数字不能直接做差 |
| 单位 | 准确率、成功率、Pearson $r$、MMRV、IoU 命中，不可混列 |
| 专家静态图文 | MMMU：大学学科、异构图像、交织图文 |
| 视频时序 | Video-MME：短 / 中 / 长视频多项选择，字幕与音频可选 |
| 三模态同时 | OmniBench：图像、声音、文本缺一不可 |
| 计算机执行 | OSWorld：真实电脑环境、脚本判定任务完成 |
| 仿真操作 | LIBERO 等：仿真器谓词成功率，不是真机 |
| 仿真-真机排序 | SIMPLER：相对排序相关，不是绝对成功率 |
| 真机能力 | 真实机器人、真实桌子上的 0/1；本课陷阱格 |
| Wilson 区间 | 第 31 课已手算的二项比例区间，本课沿用不重推 |

术语表只服务本课。前面课已经解释过的词直接链回去：loss mask、golden case、trace 见[第 01 课](01_baseline_reproduction.md)；IoU、POPE、Hit 见[第 23 课](23_grounding_ocr_spatial.md)；套件、distractor、谓词、Wilson、MMRV、Visual Matching 见[第 31 课](31_vla_evaluation.md)；SoM 作为接地接口见[第 32 课](32_gui_agent_grounding.md)。本课若再把这些词展开一遍，会和前三课抢篇幅。需要时点链接，本课只把它们接到六类标签上。

## 2. 本课解决的问题

当前系统（以及你在论文或模型卡里看到的任何 Omni / VLA / GUI 数字）默认验收是“报一个百分数”。它解决不了六类失败，而且这六类会在总平均里被兑掉：

1. 把 MMMU 大学试卷准确率写成“已经会看视频”。
2. 把 Video-MME 有字幕的上涨写成“已经是 Omni，三模态同时过关”。
3. 把 OmniBench 三模态准确率写成“电脑代理或机械臂也会了”。
4. 把 OSWorld 脚本成功率写成“和 LIBERO 仿真抓取同一类身体智能”。
5. 把 LIBERO 四套件宏平均写成真机能力。
6. 把 SIMPLER 的 Pearson $r$ 填进成功率格，再声称 sim-to-real 已经 1:1。

本课的改造范围只包括评测分类、记录字段和一小段可手算的互斥规则。不更换视觉编码器，不重做第 02 课的 connector，不重训[第 08 课](08_dynamic_vision.md)的切片器，不比较离散动作 token 与 flow matching（那是第 25、27、28 课），不把屏幕点击当成机械臂（那是[第 32 课](32_gui_agent_grounding.md) 的接地，本课只接管 OSWorld 这个数字该进哪一类）。

以下结果不能支持“模型已经是通用 Omni”或“已经具备真机能力”：

- 只报一个跨基准均分，没有类标签；
- 把 LIBERO 平均和真机 $N=25$ 写进同一句“操作成功率 80%”；
- 把 SIMPLER $r=0.924$ 读成“仿真成功率约等于真机”；
- 用 MMMU 答对代替第 23 课的 IoU / POPE；
- 用 Video-MME 有字幕分代替 OmniBench 的图声同时约束；
- 把 OSWorld 12.24% 和 LIBERO 76.5% 减出“GUI 比机器人差 64 个点”。

执行顺序固定：先在 CPU 夹具上证明六类标签互斥、非法映射被拒绝，再在浏览器里亲眼看到 LIBERO 拖进真机格被标红，最后如果有 GPU 或虚拟机，才把同一套协议卡接到真实评测脚本上。没有 GPU 时，前两步已经构成完整交付。

和第 31 课的边界再钉死一次，避免两课抢题。第 31 课管执行侧内部：LIBERO 四套件、SIMPLER 视觉域、CALVIN 长程、真机小样本，以及 Wilson 区间。本课接管这些数字的类标签，并补上理解侧三本账。31 课已经证明 76.5% 不能当真机；本课证明它连和 OSWorld、MMMU 也不能横着写在“能力”这一列。第 23 课管理解侧内部的接地与幻觉；本课禁止用 C1 准确率填那两格。第 01 课管复现与类内分桶；本课禁止用跨类平均制造新的“复现成功”。三课的检查票要一起用：先问类，再问类内桶，再问探针，再问 $N$。

本课固定四个可证伪命题：

1. 存在一张六类标签表，使得每条记录恰好一类，两类碰撞时互斥检查失败。
2. 把 LIBERO 宏平均的声称类别写成 `real_robot`，必须被拒绝。
3. MMMU 与 Video-MME、Video-MME 与 OmniBench、OSWorld 与 LIBERO 三对之间，`may_compare` 为假。
4. 跨六类的算术平均可以算出来一个数，但该数不得作为能力标量入账。

四条都通过，只能说明评测被写成了可审计分类。它们不能说明 Qwen2.5-Omni-7B 的 56.13% 可以搬到你的机械臂，也不能说明 OSWorld 12.24% 等于“电脑使用已解决”。

## 4. 完成后应具备的能力

完成后，拿到任意“Omni / VLA / GUI 总表”，应能完成以下检查：

1. 指出每个数字属于 C1 到 C6 中的哪一类，或声明“本课六类之外，另开新账”；
2. 写出协议卡：基准、划分、输入模态、成功定义、$N$、是否 fine-tune、单位；
3. 拒绝把 LIBERO 宏平均写成真机能力，并能指出 OpenVLA Table 12 的 76.5% 是独立 fine-tune；
4. 拒绝把 SIMPLER $r=0.924$ 写成成功率；
5. 说明 MMMU 答对为什么代替不了第 23 课的 grounding 命中和 POPE 幻觉率；
6. 说明 Video-MME 加字幕的 +6.2 个点为什么不等于 OmniBench 的三模态硬约束；
7. 说明 OSWorld 人类 72.36% 对 GPT-4 12.24% 可以在 C4 内部比，不能和 LIBERO 76.5% 比；
8. 沿用第 31 课：对 $N=25$、$k=20$ 写出 Wilson 约 $[0.609,0.911]$，并判断它只服务同类成功率；
9. 在 Lab 里先预测“LIBERO 平均最常被填进真机能力”，再拖桶；拖进陷阱格必须看见标红；
10. 引用任何公开百分数时，能在 30 秒内指出表号、类标签、划分；指不出就从讲稿里删掉该数。

五分钟审稿可以按这个口令做。打开一篇 Omni 或 VLA 的总表，从左到右给每一列贴便利贴：C1、C2、C3、C4、C5、C6、真机、其他、未测。出现两列同一类，再检查划分和 fine-tune 能不能比。出现 LIBERO 和真机相邻且正文有“因此”，便利贴改红。出现 $r$ 却画成柱状百分数，便利贴改红。出现 MMMU 却在讨论接地，便利贴改红。全部便利贴都有类、红色为零，这篇表可以进笔记；否则只许引用分列后的单格，不许引用作者的总平均句。口令短，是为了在组会当场用，不是为了代替协议卡。协议卡在会后补。

完成能力第 1 到 4 条可以在纸上验收：CPU 实验的 `six_class_labels_are_mutex` 与 `libero_macro_rejected_as_real_robot` 必须为真。第 5 到 7 条口头能讲清单位。第 8 条用手算对到 $10^{-6}$。第 9 条在教学桶上验收。漏掉第 3 条（LIBERO 不当真机）等于本课没上。

## 5. 原理：边造边讲

十二个机制，每个按同一节奏：为什么需要、怎么运转、精确定义、在公开实现里落在哪、怎么证明做对了。本课没有 MiniMind-O 源码可改，代码落点改到各基准的评测脚本和本课夹具里那些“打标签、拒收、禁止做差”的函数。

### 5.1 六类是互斥分类，不是六列可以减的百分数

为什么需要。模型卡喜欢一张总表。总表有阅读价值，也是错误的主要来源：读者会把“MMMU 高”读成“视频强”，把“Video-MME 加了字幕”读成“已经是 Omni”，把“LIBERO 高”读成“真机强”，把“SIMPLER 相关高”读成“仿真成功率可以当真机用”。

怎么运转。先按测量对象分六类，再决定能不能做差。

| 类 | 代表基准 | 测什么 | 典型数字（必须带出处） | 不能当成什么 |
|---|---|---|---|---|
| C1 专家静态图文 | MMMU | 大学学科、异构图、交织图文 | GPT-4V 测试集 55.7%（Table 2） | 视频能力；接地；真机 |
| C2 视频时序 | Video-MME | 短中长视频 MCQ | Gemini 1.5 Pro 无字幕 75.0%（Table 4） | 三模态硬约束；操作执行 |
| C3 三模态同时 | OmniBench | 图+声+文缺一不可 | Qwen2.5-Omni-7B 56.13%（其 Table 8 / OmniBench Table 3） | 长视频；电脑任务；抓取 |
| C4 计算机执行 | OSWorld | 真实电脑、脚本 0/1 | GPT-4 无障碍树 12.24%，人类 72.36%（Table 5） | 试卷准确率；仿真抓取 |
| C5 仿真操作 | LIBERO | 套件谓词成功率 | OpenVLA fine-tune 宏平均 76.5%（Table 12） | 真机能力；未经 fine-tune 的出厂能力 |
| C6 仿真-真机排序 | SIMPLER | Pearson $r$、MMRV | VisMatch 平均 $r=0.924$（Table I） | 某个政策的绝对成功率 |

数学。令评测记录 $m$ 的标签为 $c(m)\in\{C_1,\ldots,C_6\}$。本课要求 $c$ 是函数：每条记录恰好一个值。两类标签碰撞时，分类失败。差值有定义，当且仅当标签、单位、协议三者都对得上：

$$
\Delta(m_a,m_b)\ \text{allowed}
\iff
c(m_a)=c(m_b)
\ \wedge\
\mathrm{unit}(m_a)=\mathrm{unit}(m_b)
\ \wedge\
\mathcal{P}(m_a)\simeq\mathcal{P}(m_b)
$$

跨类宏平均

$$
\bar p=\frac{1}{6}\sum_{i=1}^{6}p_i
$$

可以当作算术练习算出来，不能当作能力标量 $\theta(\pi)$。CPU 夹具里六个数的算术平均大于 0.5，且与 LIBERO 宏平均 0.765 差出 5 个点以上，检查 `cross_class_macro_is_not_a_capability` 为真：算得出，不等于能用。

验证。拿同一张“Omni 总表”做一次横向拒绝：Qwen2.5-Omni-7B 的 MMMU val 59.2%、Video-MME 无字幕 64.3%、OmniBench 56.13%（技术报告 Table 5 / 7 / 8）。三个数字可以并排展示，因为作者已经按「图像到文本」「无音频视频到文本」「混合模态到文本」分过节。它们仍然不能减出“视频比试卷高 5 个点所以视频模块更强”——划分、模态、题型都不同。

### 5.2 协议卡：一条数字必须带齐的字段

为什么需要。第 01 课已经要求：指标必须追溯到 case 和生成参数。第 31 课把这条放大成机器人协议卡。本课把协议卡从 VLA 推广到六类：缺字段的数字不得入账，哪怕它印在摘要第一句。

怎么运转。一张卡至少包含：

1. `class_id`：C1 到 C6。
2. `benchmark` 与 `split`：例如 MMMU test，不是“MMMU 大概”。
3. 输入模态：静图、视频帧、视频+字幕、图+声、截图、仿真相机。
4. 输出与成功定义：选项字母、短答案、脚本谓词、仿真谓词、相关系数。
5. $N$ 或题量：11550、2700、1142、369、500 trials×4、六个 checkpoint。
6. 是否 fine-tune / 是否用了腕部相机 / 是否过滤失败示范。
7. 单位：accuracy、success_rate、pearson_r、MMRV、Hit_0.5。

数学。把一条公开数字写成三元组 $(p,\mathcal{P},u)$。报告估计的是 $p(\pi,\mathcal{P})$ 在单位 $u$ 下的值，不是与协议无关的标量。缺少 $\mathcal{P}$ 或 $u$ 时，该格只能标 `unspecified`，不能进对照表。

代码落点。CPU 实验把六条记录写成带 `class_id` / `unit` / `n` / `fine_tune` 的字典。`claim_is_legal` 在声称类别不等于真类、或把 `pearson_r` 说成 `success_rate`、或写 `real_robot` 时返回假。

验证。缺 `fine_tune` 就引用 76.5%，本课视为未完成记录：OpenVLA Appendix E 写明各套件独立 LoRA。缺 `unit` 就引用 0.924，本课视为未完成记录：那是 $r$。

字段不全时不要用“大概是这类”凑过去。常见凑法有三种。第一种：基准名对、划分空，把 MMMU val 的 56.8% 和 test 的 55.7% 当同一个点，再和别人的 val 比。第二种：单位对、模态空，把 Video-MME 有字幕 81.3% 和别人的无字幕 75.0% 画成进步曲线。第三种：类标签对、成功定义空，把 OSWorld 部分分和 0/1 成功率兑在一起。协议卡把这三件事写成必填，空值不得进 `may_compare` 的真分支。实现上，CPU 夹具只检查类和单位；划分与成功定义留给你手写的卡。夹具通过不等于卡已经填完。

### 5.3 C1 MMMU：专家静态图文，不测视频也不测接地

为什么需要。日常 VQA 和 ScienceQA 多数停在常识或中小学。MMMU 要把尺子抬到大学学科，并且强迫模型读图表、谱面、分子式，而不是只读照片。没有这一类，Omni 报告会用“会看猫狗照片”冒充“会读学科图”。

怎么运转。原文（Yue et al., 2024, CVPR；arXiv:2311.16502）收集 11550 题，来自大学考试、测验和教材。六大学科：Art & Design、Business、Science、Health & Medicine、Humanities & Social Science、Tech & Engineering。30 个科目、183 个子领域、30 种高度异质的图像类型：图表、示意图、地图、表格、乐谱、化学结构等。划分：开发 150（每科 5 道 few-shot）、验证 900、测试 10500。难度 Easy : Medium : Hard = 28% : 45% : 27%。选择题 10861（94.03%），开放题 689（5.97%）。主实验是零样本。评价指标是微观平均准确率，长回答用正则抽关键短语再匹配。

数学。设测试集 $\mathcal{D}_{\text{test}}$，$|\mathcal{D}_{\text{test}}|=10500$。

$$
\mathrm{Acc}_{\mathrm{MMMU}}
=\frac{1}{|\mathcal{D}_{\text{test}}|}
\sum_{i\in\mathcal{D}_{\text{test}}}
\mathbf{1}[\hat y_i=y_i]
$$

选择题抽不出合法选项时，原文用随机选择补救；开放题抽不出则记错。这和 OSWorld 的执行脚本、LIBERO 的谓词合取不是同一个指示函数。

公开数字只引原文表。Table 2：随机选择验证 22.1%、测试 23.9%；GPT-4V 验证 56.8%、测试 55.7%；验证集人类专家最差 / 中位 / 最好为 76.2% / 82.6% / 88.6%。摘要另外给出 GPT-4V 56%、Gemini Ultra 59%。GPT-4 纯文本测试集 33.8%，加 OCR 或 LLaVA 配文几乎不涨（FLAN-T5-XXL 31.2% 到 31.9%），说明题目需要图文合读，不是把字认出来就结束。错误分析 150 条 GPT-4V 错例：感知 35%、缺知识 29%、推理 26%。难度分解：GPT-4V Easy 76.1%、Medium 55.6%、Hard 31.2%，难题上优势几乎消失。

代码落点。MMMU 仓库按科目存图文，评测脚本对输出做选项解析。你自己的探针如果只抽 Art & Design 的画作题，会高估；只抽 Tech & Engineering 的电路图，会低估。Table 2 里 GPT-4V 测试集 Humanities 76.3%、Tech & Eng. 41.7%，学科桶差三十多个点，和第 01 课“不能只报平均数”同构。

验证。C1 测的是学科知识加静态图感知加推理。它不测：视频时间轴、必须同时出现的音频、框或点是否落在被问物体上、电脑上是否真的改了文件、夹爪是否抓住杯子。把 55.7% 写成“多模态已经接近专家”，和专家 88.6% 的验证集对照也不成立，更跨不到真机。

学科桶要把“会读自然图”和“会读专业图”拆开。Table 2 里 GPT-4V 测试集：Art & Design 65.3%，Business 64.3%，Science 48.4%，Health & Medicine 63.5%，Humanities & Social Sci. 76.3%，Tech & Engineering 41.7%。艺术和人文相对高，科学与工科相对低，作者把原因写在视觉更复杂、推理链更长。你自己的 MiniMind-O 若只拿了几张照片问答当“视觉回归”，测的连 C1 的工科桶都不是。图像类型上，原文 Figure 4 指出开源模型在照片、绘画上相对像样，在几何图形、乐谱、化学结构上接近随机。协议卡的 split 字段除了 test/val，还应能写 `image_type=chemical_structure` 这种子桶。缺子桶时，55.7% 只是总账，不能解释“发票小字”或“电路符号”有没有过关。

交织输入是 C1 的另一条协议。题目常常是一段文字中间插图，再接一段文字。纯 OCR 把图里的字抠出来拼进提示，FLAN-T5-XXL 从 31.2% 到 31.9%，几乎不动。这说明失败不在“图里有没有字”，在“字和图必须合读”。第 08 课动态切片提高的是可读面积，第 23 课探针检查的是读了哪一块，C1 检查的是读完之后会不会用学科知识往下推。三课可以测同一张发票，必须三个 `run_id`。

难度分解提供第三条禁则。GPT-4V Easy 76.1%、Hard 31.2%。只抽 Easy 科目做内部回归，会得到一张好看的表，和测试集 55.7% 对不上。第 01 课禁止把 mini 英文无视觉 recipe 的分数和发布权重比；这里禁止把 Easy 子集和 Full test 比。

第 23 课的对照在这里最硬。MMMU 可以整题答对，注意力却落在错误子图上：乐谱题靠文字选项里的调号猜，电路题靠题干单位猜。没有 IoU、没有注意力质量分数、没有 POPE 负例，C1 的准确率不能填进 grounding 格。CPU 夹具里 POPE 幻觉率 $3/4$，MMMU 的 0.557 与它差出 0.1 以上，且 Yes 比例 $5/6$ 不等于幻觉率：这就是 `pope_hallucination_is_not_mmmu_accuracy`。

### 5.4 C2 Video-MME：视频时序，字幕是可选增益

为什么需要。静态图的高分不能代表会看时间。现有视频基准往往时长短、领域窄、自动出题。Video-MME 要覆盖 6 个视觉域、30 个子类，并且把短、中、长三档写进同一套协议。

怎么运转。Fu et al., arXiv:2405.21075。900 条 YouTube 视频，每条人工出 3 道四选一，共 2700 题。时长：短（小于 2 分钟，表内平均 80.7 s）、中（4–15 分钟，平均 515.9 s）、长（30–60 分钟，平均 2466.7 s），总体平均约 1018 s，从 11 秒到 1 小时。744 条有字幕，900 条都有音频。标注后用纯文本把 Gemini 1.5 Pro 能答对的题滤掉，文称纯文本准确率低于 15%，避免“不看视频也能答”。选项 A/B/C/D 近均匀（25.1 / 27.2 / 25.3 / 22.4%）。证书长度（回答该题所必需的最短片段之和）中位数：短 26.0 s、中 164.7 s、长 890.7 s。

数学。按时长桶 $b\in\{\mathrm{S},\mathrm{M},\mathrm{L}\}$，每桶 900 题：

$$
\mathrm{Acc}_b=\frac{1}{900}\sum_{i\in b}\mathbf{1}[\hat y_i=y_i],
\quad
\mathrm{Acc}_{\mathrm{overall}}=\frac{1}{3}\sum_b\mathrm{Acc}_b
$$

因为三桶题量相同，总体准确率等于三桶宏平均。协议还必须声明输入：仅帧、帧+字幕、帧+音频。字幕与采样帧对齐，不是把整份 6.5K 词字幕无条件塞进所有模型。

公开数字只引 Table 4 与 Table 5。仅帧：Gemini 1.5 Pro 短 / 中 / 长 / 总 = 81.7 / 74.3 / 67.4 / 75.0%；GPT-4o = 80.0 / 70.3 / 65.3 / 71.9%；VILA-1.5-34B = 68.1 / 58.1 / 50.8 / 59.0%。加字幕后 Gemini 总 81.3%（+6.2），GPT-4o 总 77.2%。Table 5：Gemini 加字幕在长视频 +10.1，短视频只 +2.8；加音频总 +4.3，长视频 +6.2。体育长视频加字幕 +19.2，艺术表演加音频为 0。开源模型多数不支持音频，论文对它们省略音频列。

代码落点。评测比较模型输出与标准答案字母，不用 GPT 当裁判。抽帧策略必须写入协议卡：开源模型常固定 8 帧，时长变长则信息密度下降，这是性能掉点的原因之一，不是“模型突然不会推理”。

验证。C2 测视频理解。它不测大学化学结构（那是 C1），不测“没有音频就一定答错”（OmniBench 的硬约束），不测是否真的点开了播放器设置（C4），不测抓取。把无字幕 75.0% 和有字幕 81.3% 兑成“视频 78%”，会把可选模态增益洗掉。第 01 课的分桶在这里的对应物：必须分短中长，必须声明有无字幕。

C2 与 C3 的边界要写死。Video-MME 可以只喂帧；加字幕或音频是消融，用来看增益。OmniBench 的验收是：用纯图或纯声就能答对的题，在质检阶段被打回。把 C2 的“+Audio 4.3 个点”写成“已经通过三模态同时测试”，是把可选增益写成硬约束。CPU 里 `videomme_not_comparable_to_omnibench` 必须为真。

抽帧密度要写进 C2 的协议卡，否则短视频 81.7% 和长视频 67.4% 的差会被误读成“模型不会长程推理”。原文分析给出三条并存的原因：长视频推理题比例更高；开源模型固定帧数导致长视频信息更稀；即便 Gemini 增加了采样帧，长上下文理解仍然掉点。设视频时长 $L$ 秒、采样 $F$ 帧，平均间隔 $\Delta t=L/F$。短视频 $L\approx 80$、$F=8$ 时 $\Delta t\approx 10\,\mathrm{s}$；长视频 $L\approx 2400$ 时 $\Delta t\approx 300\,\mathrm{s}$。同一 $F$ 下，长视频丢的是整段情节。字幕平均词数从短视频 198.6 升到长视频 6515.6，所以“加字幕救长视频”可能只是在补抽帧漏洞，不是模型突然学会了听。协议卡要写 $F$ 和是否固定 fps。写了“我们评了 Video-MME”却不写抽帧，C2 这一行仍算字段不全。

证书长度是另一条类内尺子。EgoSchema 中位证书约 100 秒量级；Video-MME 中视频 164.7 秒、长视频 890.7 秒。把 EgoSchema 分数和 Video-MME 长视频分数横比，属于 C2 内部的协议不同，本课虽然不单开第七类，也不允许这两行无注释相减。12 种题型里，计数是原文点名的共同瓶颈，感知题和推理题的雷达图不能兑成一个“视频理解分”。短视频偏感知，长视频偏推理，总体 75.0% 会让短视频的动作识别替长视频的情节推断说话。

### 5.5 C3 OmniBench：三模态同时，缺一不可

为什么需要。许多所谓 Omni 模型只是“能吃图或能吃声”，评测时把缺的模态换成转写或配文。OmniBench 要卡住一件更窄的事：同一道题必须同时识别、解释、推理图像、声音和文本。

怎么运转。Li et al., arXiv:2409.15272。1142 道四选一。任务三类：因果推断、时空实体、抽象概念；音频三类：语音 771、声音事件 265、音乐 106。图像最短边至少 480P，音频最长 30 秒，平均 9.22 秒。标注原则：正确答案必须同时依赖图和声。质检分人工交叉和 LLaVA-1.6-34B 自动消融：只给图、只给音频转写、只给文本，模型若在缺模态时仍能答对，样本打回。通过的样本里 76% 无需返工，21.1% 返工 1–2 次，121 条被丢掉。随机猜测 25%。

数学。输入是三元组 $(I,A,T)$。准确率

$$
\mathrm{Acc}_{\mathrm{Omni}}
=\frac{1}{1142}\sum_{i=1}^{1142}
\mathbf{1}[\hat y_i=y_i]
$$

消融协议再定义 $\mathrm{Acc}(A,T)$ 和 $\mathrm{Acc}(I,T)$。若 $\mathrm{Acc}(I,A,T)\approx\mathrm{Acc}(I,T)$，模型没用音频；两边都接近随机，则可能只是不会跟指令。单位仍是准确率，题型是缺一不可的三模态题，和 C1、C2 的准确率不可减。

公开数字。OmniBench Table 3 / Qwen2.5-Omni Table 8：Gemini-1.5-Pro 总体 42.91%，去图 27.93%，去声 26.09%。Qwen2.5-Omni-7B 总体 56.13%，语音 / 事件 / 音乐 = 55.25 / 60.00 / 52.83。人类评测员 63.19%（Fleiss' Kappa 0.421），人类专家 74.03%。多数开源 Omni 模型刚过随机或卡在指令跟随。用转写代替音频时，双模态 VLM 往往比原生三模态开源模型好看，说明“把声音变成字再做题”和“直接听”不是同一协议。

代码落点。评测匹配选项字母。音频转写和图像配文是近似协议，必须在协议卡上单列，不能和原生 $(I,A,T)$ 混报。OmniInstruct 训练集约 84580 条，用来适应三模态上下文，不是本课要训的模型。

验证。C3 测的是三模态合读。它不测一小时视频的证书长度，不测 cookie 是否删除，不测夹爪。把 56.13% 和 MMMU 59.2% 平均成“理解 57.7%”，会把“必须听见”洗掉。Gemini 在 OmniBench 上 42.91%，在 Video-MME 仅帧上 75.0%：同一个系列名，两类账，禁止说“Gemini 理解分是这两个的平均”。

任务分类要把“看见物体”和“听完再推断情节”拆开。Table 4 里许多模型在 Object Identification 上远高于 Plot Inference：Video-SALMONN 物体描述 62.56%、情节推断 25.74%；Gemini-1.5-Pro 物体 62.56%、情节 32.91%、计数 13.33%。总体 42.91% 会让物体识别替计数和情节说话。音频类型也一样：开源模型常偏语音、音乐更差；人类评测员在声音事件上 75.85%，明显高于语音 58.71%。模型和人对“什么算难”的排序可以反过来。协议卡要能写 `audio_type=music` 或 `task=count`。只报 Avg，C3 仍然兑水。

近似协议是 C3 最容易被偷偷换单位的地方。给 VLM 喂人工转写，InternVL-2-40B 可以到 54.29%，Claude-3.5-Sonnet 59.37%（图+转写设定）。给 ALM 喂图像配文，Qwen2-Audio-7B-Instruct 40.72%。这些数字回答的是“如果声音已经变成字，模型能不能把字和图合读”，不是“模型听见了没有”。原生 $(I,A,T)$ 和近似 $(I,A',T)$ 必须分列。Qwen2.5-Omni-7B 的 56.13% 写在原生列；把 Claude 的转写设定 59.37% 和它减出“开源 Omni 已经接近闭源”，比较的是两种协议。本课把它写成单位错误的近亲：输入已经不是同一件事。

人类基线也要带口径。普通评测员 63.19%，专家 74.03%。作者写明时间限制、非母语、音乐知识缺口会压低人类分。你不得把 63.19% 写成“人类上限”，也不得把模型 56.13% 写成“接近人类专家”。专家行和评测员行是两行。

### 5.6 C4 OSWorld：计算机执行成功率

为什么需要。选择题永远不会改掉真实电脑上的文件。GUI 接地命中（第 32 课的 ScreenSpot 一类）也不等于任务完成：点中了登录按钮，密码没填，脚本仍判失败。OSWorld 把评测放进可执行的真实操作系统。

怎么运转。Xie et al., arXiv:2404.07972。环境是虚拟机里的 Ubuntu / Windows / macOS，观察可以是截图、无障碍树或两者，动作是 pyautogui 键鼠代码，另加 WAIT / FAIL / DONE。任务形式化成 POMDP，奖励在终局由执行脚本给出 0/1（或小于 1 的部分分）。基准含 369 项 Ubuntu 任务：单应用 268（72.6%），跨应用工作流 101（27.4%），不可行任务 30（8.1%），另有 43 项 Windows 补充任务因版权需自行激活。302 种初始状态，134 个独特评价函数。人类完成中位时间 111.94 秒，准确率 72.36%；对照 WebArena 抽样 100 题中位 35.38 秒、准确率 88%。

数学。任务 $i$ 终态 $s_T$，脚本 $R_i(s_T)\in[0,1]$。总体成功率

$$
\mathrm{SR}=\frac{1}{369}\sum_{i=1}^{369}R_i(s_T)
$$

按应用域再拆：OS、Office、Daily、Professional、Workflow。论文 Table 5 显示，智能体跨域方差远大于人类：人类各域都在 70%–75%，GPT-4 无障碍树在 OS 上 20.83%、Office 3.58%、Workflow 2.97%、总体 12.24%。把总体 12.24% 当成“电脑使用能力”而不拆 Workflow，会让最容易的 CLI 任务替跨应用工作流说话。这和第 31 课 LIBERO 宏平均掩盖 Long 是同一句纪律，只是换了身体。

公开数字只引 Table 5。人类总体 72.36%。GPT-4 无障碍树总体 12.24%，是文中最好的模型数字之一。纯截图 GPT-4V 5.26%、GPT-4o 5.03%。工作流子集上，最好的基线大约 6.57%（GPT-4V + Set-of-Mark）。实验默认最多 15 步。后继工作（第 32 课已引的 OS-Atlas、UI-TARS）会报更高的 OSWorld 分数，引用时必须写步数限制和观察接口；那些数字仍是 C4，不能因为变大了就改类。

代码落点。每个例子有初始配置（下载文件、打开软件、调窗口）和评价脚本（读 cookie、比表格、查无障碍树）。仓库目标是可复现的执行式成功，不是演示轨迹匹配。不可行任务上，正确预测 FAIL 才得分：这和“乱点到时间用尽”不是同一协议。

验证。C4 测计算机执行。OSWorld 人类 72.36% 对 GPT-4 12.24% 可以比，因为同类、同任务集、同执行式评价。它们不能和 LIBERO 76.5% 比：一个改的是 Ubuntu 里的文件和 GUI 状态，一个改的是仿真桌面上的物体位姿。CPU 里 `osworld_not_comparable_to_libero` 必须为真。第 32 课已经提醒：ScreenSpot 点中框不是 OSWorld 任务成功；本课把这句话收成类标签：接地命中若要记账，另开探针账，不要塞进 C4 的 SR。

观察接口是 C4 的协议字段，不是小技巧。Table 5 把无障碍树、纯截图、截图+树、Set-of-Mark 分成四块。GPT-4 在树上 12.24%，GPT-4V 纯截图 5.26%，GPT-4V 加树 12.17%。同一模型家族，观察一换，数字可以差一倍。SoM 对 GPT-4V 总体 11.77%，对部分模型反而下降：作者归因于桌面分辨率高、单元格极多，框噪声抵消了编号的帮助。第 32 课把 SoM 当接地接口；在 OSWorld 里它还是观察协议。引用 12.24% 必须写“无障碍树、GPT-4、15 步”。写成“GPT-4 在电脑上 12%”而不写观察，字段不全。

最大步数同样改协议。原文启发式上限 15 步。后继 UI-TARS 报 OSWorld 50 步 24.6、15 步 22.7（第 32 课已引）。24.6 和 12.24% 不能直接减出“我们提升了 12 个点”，除非任务集、不可行题处理、观察接口和步数对齐。不可行 30 题（8.1%）上，正确输出 FAIL 才得分；把超时乱点写成成功，会虚高。跨应用 101 题是专门给“会点一个软件不会串两个软件”留的桶：GPT-4 工作流 2.97%，人类 73.27%。总体 12.24% 把工作流埋掉，和第 31 课把 Long 埋进 76.5% 同一错误函数，只是身体从夹爪换成了窗口。

初始态也要声明。OSWorld 大量任务从“软件已经打开、文件已经在桌面上”的中间态起步，不是从刚开机的空桌面起步。这和 LIBERO 锁示范种子、CALVIN 中性复位是同一类协议字段。缺初始态描述的 C4 数字，不可与另一篇 OSWorld 数字比，尽管两类标签相同。`may_compare` 的第三项 $\mathcal{P}(m_a)\simeq\mathcal{P}(m_b)$ 在这里生效：同类是必要条件，不是充分条件。

### 5.7 C5 LIBERO：仿真操作，不是真机

为什么需要。VLA 论文最常被写成真机的数字，恰恰来自仿真套件平均。第 31 课已经把四套件拆开。本课只多做一件事：给这整本账贴上 C5，并规定 C5 与“真机能力”互斥。

怎么运转。沿用第 31 课已打开的 LIBERO（arXiv:2306.03310）与 OpenVLA Appendix E Table 12。四个套件 Spatial / Object / Goal / Long，每套件 10 个任务，OpenVLA 设定每套件 500 trials × 3 seeds，独立 LoRA fine-tune，第三视角，过滤失败示范。四点：84.7%、88.4%、79.2%、53.7%，宏平均 76.5%。OFT Table I 在加动作块、连续 L1、腕部相机之后把平均做到 97.1%，Long 94.5%，仍然写着 fine-tune。CALVIN 的五步链 0.08% 也是仿真操作，但协议是长程组合，不能和 LIBERO 单套件平均兑在一起。C5 内部仍要按第 31 课再拆：套件、初始态、谓词、是否细调。

数学。套件宏平均

$$
\bar p=\frac{1}{4}\sum_{s}\hat p_s
$$

本课夹具沿用 $0.847+0.884+0.792+0.537$ 得 $0.765$，Spatial 减 Long 大于 0.3。标签函数额外规定：

$$
c(\text{LIBERO macro})\neq \texttt{real\_robot}
$$

任何把 76.5% 或 97.1% 填进真机格的映射，`claim_is_legal` 为假。

代码落点。成功判定是仿真器对 PDDL 谓词的校验。真机成功判定是实验员量表或真实传感器，函数不同。Lab 里把印着 76.5% 的卡片拖进“真机能力”，卡片和桶变成红色。这是本课交互实验的硬验收，不是装饰。

验证。C5 测仿真操作成功率。它不是 C4，也不是真机。OpenVLA 作者自己写：预训练全是真机数据、零仿真数据，fine-tune 到 LIBERO 的增益解释不了真机 Franka。76.5% 不能解释成“真机政策在仿真里也一样强”。本课把这句话升级成类间禁则。

C5 内部的再拆不能省略，否则互斥标签会给人“进了 C5 就可以平均”的错觉。OpenVLA-OFT Table I：同一 OpenVLA 骨干，加并行解码和动作块后平均 90.2%，再加连续 L1 到 95.3%，再加腕部相机到 97.1%；表内 $\pi_0$（fine-tuned）94.2%，$\pi_0+$FAST（fine-tuned）85.5% 且 Long 只有 60.2%。这些格子可以在“同一张 LIBERO 表、都写了 fine-tune、每套件 500 trials”的前提下比排序。它们仍然不能和 OFT 在 ALOHA 上“平均高 15 个绝对点”相减，因为那是真机、双臂、另一套量表。本课的类标签把 ALOHA 那一行排除在 C5 之外；它属于真机行，必须 $N$、任务名、量表和 C5 分开写。CALVIN 五步 0.08% 留在 C5，但 split 必须是 `LH-MTLC-5`，不能和 LIBERO-Object 88.4% 兑成“仿真 44%”。谓词分叉（接触 / 放置 / 保持）是第 31 课的类内纪律，本课夹具不再重算那三条，只要求协议卡上能指向它们。

### 5.8 C6 SIMPLER：排序相关，不是成功率

为什么需要。有人会说：“我们不报真机，我们报 SIMPLER，所以已经 sim-to-real。” SIMPLER 自己的目标函数不是复制成功率，是相对排序相关。

怎么运转。沿用第 31 课已打开的 SIMPLER（arXiv:2405.05941）Table I。Google Robot 上六个开源 checkpoint：Visual Matching 平均 Pearson $r=0.924$、MMRV $=0.056$；Variant Aggregation $r=0.778$；用验证集动作 MSE 排序只有 $r=0.308$。单位是相关系数和排位违背，分母是政策集合，不是试验次数。

数学。第 31 课已给出 RankViolation 与 MMRV。本课只加一条分类：

$$
\mathrm{unit}(r)= \texttt{pearson\_r}
\neq \texttt{success\_rate}
$$

把 0.924 写进成功率列，或把 $r$ 乘 100 写成 92.4% 能力，属于单位错误。C6 可以和另一份同样任务、同样视觉协议、同样政策集合上的 $r$ 比较；不能和 LIBERO 76.5% 减，不能和 OSWorld 12.24% 减，不能填进真机能力。

验证。合格写法：“SIMPLER Visual Matching、Google Robot，六个 checkpoint 的仿真排序与真机排序平均 $r=0.924$（Table I）。该数字不表示仿真成功率等于真机成功率。”错误写法：“SIMPLER 92%，真机约 92%。”后一句在 SIMPLER 论文自己的目标函数下就不成立。CPU 里 `simpler_r_rejected_as_success_rate` 必须为真。

Visual Matching 的合成公式必须出现在 C6 协议卡上，否则 $r$ 没有视觉域。

$$
I'=M\odot I_{\mathrm{sim}}+(1-M)\odot I_{\mathrm{real}}
$$

只调抽屉、只调手臂、只做绿幕，MMRV 都不下降；三件一起做，MMRV 从 0.087 降到 0.050（第 31 课已引 Table III）。C6 的 split 至少要能区分 VisMatch 和 VarAgg：后者平均 $r=0.778$，Drawer 上只有 0.486。把 0.924 和 0.778 平均成“SIMPLER 0.85”，又是类内兑水。机体也要分列：Google Robot 和 WidowX 不能混成一个 SIMPLER 成功率，它们甚至不是成功率。validation MSE 的 $r=0.308$ 是负对照：模仿学习的动作误差低，不能替代任务级仿真评测，和第 01 课“loss 能降不等于复现完成”同构。若有人把 0.308 和 0.924 画在同一张“我们的 sim-to-real 曲线”上当两种方法，必须写清一个是验证集 MSE 排序、一个是 Visual Matching 任务成功率排序，单位看似都是 $r$，协议不是同一个 $\mathcal{P}$。

### 5.9 第 23 课探针横切六类：准确率不是命中

为什么需要。六类解决“这是哪本账”。第 23 课解决“即便在同一本理解账里，答对也不等于看对位置”。两类错误会叠：先把 MMMU 和 Video-MME 兑在一起，再把兑出来的准确率当成 grounding。

怎么运转。在 C1 上，指代、OCR 区域、左右、计数、POPE 仍然要分列。MMMU 的微观准确率没有框。Video-MME 的四选一没有时间定位框。OmniBench 有图像与音频理由字段，但主指标仍是选项字母。OSWorld 的成功脚本有时读界面树，那是状态检查，不是 IoU。LIBERO 的谓词是物体关系，不是“模型看了哪块像素”。

数学。沿用第 23 课：

$$
\mathrm{Hit}_{0.5}=\mathbf{1}[\mathrm{IoU}\ge 0.5],
\quad
\mathrm{Hallu}=\frac{\#\{\text{负例且答有}\}}{\#\{\text{负例}\}}
$$

$\mathrm{Acc}_{\mathrm{MMMU}}$ 与 $\mathrm{Hit}_{0.5}$、$\mathrm{Hallu}$ 可以同时为高、同时为低、一高一低。列联表四格必须分开。CPU 夹具把幻觉率钉在 $3/4$，Yes 比例 $5/6$，MMMU 的 0.557 不能冒充其中任何一个。

验证。报告若只有 C1 准确率，接地和幻觉两格留空。空格可见，比填一个“视觉很好”诚实。第 08 课动态分辨率带来的 OCR 上涨，仍然不能直接写成 grounding 上涨：那是另一课的边界，本课只提醒它也不得写入六类总平均。

横切关系写成一张小表，避免六类把探针挤掉。

| 探针（第 23 课） | 能挂在哪一类下面 | 不能被哪一类的主指标代替 |
|---|---|---|
| IoU / Hit_0.5 | C1 的指代表达子桶；C4 的点击落点检查 | MMMU 微观准确率；OSWorld 任务 SR |
| POPE 幻觉率 | C1 存在题；C2 若问“视频里有没有 X” | Yes 比例；配文观感 |
| OCR 区域命中 | C1 文档图；C4 界面文字 | 生成里碰巧出现该字符串 |
| 左右 / 计数 | C1 空间题；C2 计数题型 | 语言先验猜“常见是两个” |

C4 的脚本有时会检查界面文字是否变成目标值，那是状态命中，不是 OCR 区域命中：改对了单元格内容但模型从来没“看见”表头，脚本仍可能给 1。第 23 课的区域列在 C4 里仍然可以空。空着写 `unspecified`，不要自动填 OSWorld SR。

### 5.10 第 01 课分桶纪律：同一类内部还要再拆

为什么需要。互斥六类防止类间兑水。类内仍会兑水。第 01 课已经禁止只报 WER 总平均、要求按 speaker 分桶；禁止把 mini 英文无视觉的 recipe 和发布权重的中英视觉能力差写成复现误差。

怎么运转。每一类内部继续分桶：

- C1：学科、难度、图像类型、验证 / 测试。Tech & Eng. 41.7% 和 Humanities 76.3% 不能兑成“GPT-4V 已经会学科图”。
- C2：短 / 中 / 长，有无字幕、有无音频。长视频 67.4% 不能藏进总体 75.0%。
- C3：语音 / 事件 / 音乐，以及去图 / 去声消融。音乐 52.83% 不能藏进 56.13%。
- C4：OS / Office / Daily / Professional / Workflow，观察是树还是截图，最大步数。Workflow 6.57% 不能藏进 12.24%。
- C5：四套件、是否 fine-tune、谓词、初始态。Long 53.7% 不能藏进 76.5%。
- C6：VisMatch / VarAgg / 机体。Drawer 上 VarAgg 的 $r=0.486$ 不能藏进平均 0.924。

数学。类内宏平均 $\bar p_c=\frac{1}{|B_c|}\sum_{b\in B_c}\hat p_b$ 可以报，但必须同时列出 $B_c$ 每一桶。只报 $\bar p_c$ 时，本课把它降级为草稿，和第 01 课“只记录总 loss”同等处理。

验证。Qwen2.5-Omni 技术报告把 MMMU、Video-MME、OmniBench 放进不同小节，这是类间纪律做对了。读者若再把 Table 5 / 7 / 8 三行平均成“Omni 理解分”，类间纪律被读者撕掉。作者拆桶、读者兑桶，账仍然坏。协议卡要写给写报告的人，也要写给做幻灯片的人。

第 01 课还有一条和六类正交的禁则：官方 checkpoint 的评测不是你的训练复现。把它映射过来：你没有跑 10500 道 MMMU test，就不得把 GPT-4V 的 55.7% 写进“本系统 C1”。你可以写“对照：GPT-4V test 55.7%（原文 Table 2）”。对照行和自测行必须两个 `run_id`。Video-MME 的 75.0% 是 Gemini 1.5 Pro 仅帧；你的模型若抽了 8 帧、用了字幕，对照行仍是别人的协议。LIBERO 76.5% 是 OpenVLA 独立 LoRA；你若只评了 50 trials 单 seed，连 C5 内部都不可与 Table 12 比，更不要说填真机。六类标签解决“这是哪本账”，第 01 课解决“这是谁跑出来的”。两问都要答。

### 5.11 沿用第 31 课区间：同类才能比，比的时候还要看 N

为什么需要。分类解决能不能比。区间解决比完能不能下结论。本课不引入新的统计模型，公式与第 31 课夹具同一套。

怎么运转。一次试验仍建模为 Bernoulli，$N$ 次独立，$k$ 次成功。95% Wilson：

$$
\frac{\hat p+\frac{z^{2}}{2N}\pm z\sqrt{\frac{\hat p(1-\hat p)}{N}+\frac{z^{2}}{4N^{2}}}}{1+\frac{z^{2}}{N}},
\quad z=1.96
$$

$N=25$、$k=20$ 时，点估计 0.8，Wilson $[0.608687,0.911395]$。该区间只解释“同一个成功定义下的二项比例”。它不能套在 Pearson $r$ 上，不能套在 MMMU 微观准确率的学科差上（那要用不同的抽样模型），更不能用来给跨类减法制造“显著”一词。

题量数量级对照，只为了看见分母，不是为了横比：

| 记录 | 分母量级 | 单位 |
|---|---|---|
| MMMU test | 10500 题 | 准确率 |
| Video-MME | 2700 题 | 准确率 |
| OmniBench | 1142 题 | 准确率 |
| OSWorld | 369 任务 | 执行成功率 |
| LIBERO 一套件 OpenVLA 设定 | 500×3 | 仿真成功率 |
| 真机教学口径 | 25 | 真机成功率 |
| SIMPLER Table I | 6 个 checkpoint | $r$ |

$N=25$ 的真机 80% 和 $N=10500$ 的 MMMU 55.7% 不能讨论谁更“确定”。一个是小样本执行，一个是大题量试卷。

验证。CPU 把第 31 课的 Wilson 手算再跑一遍，公差 $5\times 10^{-7}$。`may_compare` 在跨类时为假，区间公式不会被拿去给非法差值贴误差条。

题量大并不自动允许跨类。MMMU test 10500 题的标准误，按二项粗估 $\sqrt{0.557\times 0.443/10500}\approx 0.0048$，看起来很窄。这个窄只对 C1 的微观准确率有意义。它不能给 LIBERO 的 76.5% 当误差条，也不能给 OSWorld 的 12.24% 当“已经被大样本推翻”的证据。分母不可借。反过来，真机 $N=25$ 的宽区间也不能拿去否定 Gemini 在 Video-MME 2700 题上的 75.0%：那是另一类、另一单位。本课把“区间只服务已经允许比较的那一对格子”写成硬规则。先过 `may_compare`，再画误差条。

C1–C3 的题不完全是独立 Bernoulli 试验：同一学科、同一视频上的三道题相关。Wilson 在这里只当“若独立会有多宽”的下界警示，和第 31 课伪重复那一节同方向。相关只会让真实不确定度更大，不会更小。所以你更没有理由拿 C1 的窄区间去压 C5 的点估计。需要成对比较方法时，回到[第 17 课](17_grpo_rlvr.md)预注册的 $\Delta_{\mathrm{test}}$，不要在本课发明新的检验。

### 5.12 非法映射表与互斥夹具

为什么需要。口头说“不要横比”挡不住幻灯片。夹具必须能对具体映射返回假。

怎么运转。合法映射是六条记录到六类的双射。非法映射包括：两类共用一个标签；LIBERO 标 `real_robot`；SIMPLER 标 `success_rate`；MMMU 标 C2；Video-MME 标 C3；OSWorld 标 C5；MMMU 标 `grounding_hit`。

数学。令 $f$ 为声称标签。互斥条件：

$$
f\text{ 是双射 }\{m_1,\ldots,m_6\}\to\{C_1,\ldots,C_6\}
$$

碰撞映射把 LIBERO 和 OSWorld 都标成 C4，集合大小变成 5，`assignments_are_mutex` 为假。

验证。CPU 对合法表返回真，对碰撞表返回假，对列出的六条非法声称全部拒绝。Lab 是同一张表的人机版：陷阱格不是第六类，是第七个拒收箱。六类桶填对且陷阱为空，才算通过。

### 5.14 错误报告与合格报告对照

原始材料：MMMU test 55.7%；Video-MME 无字幕 75.0%；OmniBench 56.13%；OSWorld 12.24%；LIBERO 76.5%（fine-tune）；SIMPLER $r=0.924$；真机未测。

不合格：“我们的 Omni 模型多模态能力约 60%–80%，操作接近 SOTA（LIBERO 76.5%，SIMPLER 92%），已经可以部署到电脑和机械臂。”错误叠了五层：跨类平均；LIBERO 当操作 SOTA 且未写 fine-tune；$r$ 当成功率；OSWorld 12.24% 被藏掉；真机空白被填满。

合格：“C1 MMMU test，GPT-4V，55.7%（Table 2），大学静态图文，未做 grounding 探针。C2 Video-MME 仅帧，Gemini 1.5 Pro 75.0%，长视频 67.4%；有字幕总 81.3%，该增益不解释为三模态硬约束。C3 OmniBench，Qwen2.5-Omni-7B 56.13%（Speech 55.25 / Sound 60.00 / Music 52.83）。C4 OSWorld，GPT-4 无障碍树 12.24%，人类 72.36%，Workflow 远低于 OS。C5 LIBERO，OpenVLA 独立 fine-tune 宏平均 76.5%，Long 53.7%，仿真，不是真机。C6 SIMPLER VisMatch $r=0.924$，排序相关。真机未测，空白保留。六列禁止平均，禁止部署声明。”

合格稿更长，因为它把缺测写成缺测。评测的诚实度经常表现在空白格的数量。本课交卷时，空白格必须可见。

### 5.15 七问决策树：拿到一个数字先问什么

把 01、23、31 三课的纪律收成一条可以在五分钟内走完的树。每个节点都是否认式的：答不上来就停，不要往下滑。

1. **这是哪一类？** 答不出 C1–C6，也答不出“六类之外另开新账”（例如 TTS 的 WER、第 01 课的 TTFA、第 23 课的 IoU），该数字停用。
2. **单位是什么？** 准确率、成功率、Pearson $r$、MMRV、Hit、WER 只能填一个。把 $r$ 乘 100 写成百分数，停用。
3. **划分写了没有？** MMMU 要写 val 还是 test；Video-MME 要写短中长和有无字幕；LIBERO 要写哪个套件；OSWorld 要写应用域和步数。只写基准名，停用。
4. **成功定义能否复述？** 选项匹配、脚本 getter、仿真谓词、人工量表，四选一。写了 success 却不能用代码或阈值复述，停用。
5. **$N$ 或题量写了没有？** 真机 $N\le 25$ 时必须附 Wilson；10/10 不得写成 100% 能力。沿用第 31 课，不新造区间。
6. **是否 fine-tune、是否换观察？** LIBERO 76.5% 缺独立 LoRA 脚注即停用。OSWorld 缺树/截图/SoM 即停用。
7. **有没有声称另一类能力？** LIBERO 写进真机、Video-MME 写进三模态硬约束、MMMU 写进接地、SIMPLER 写进成功率，停用并标红。

七问全过，才允许把该数字抄进对照表。抄进去之后，仍然只能和同类、同单位、协议相近的另一条做差。第 01 课的 golden case 分桶对应第 3 问的类内划分；第 23 课的列联表对应第 7 问里 grounding 那一支；第 31 课的 Wilson 和套件拆桶对应第 5 问和第 3 问在执行侧的版本。本课没有发明第四套哲学，只是把三课已经教过的检查票钉在六本账的封面上。

走一遍反例。数字：“我们的 Omni-VLA 在公开评测上平均 70%。”第 1 问失败：没有类。停。改成“LIBERO 平均 70%”。第 3 问：四个套件呢？停。补上 Spatial 80、Long 40、平均 70。第 6 问：fine-tune 了吗？未写，停。补上独立 LoRA。第 7 问：正文下一句是“因此真机可部署”。标红，停。直到真机行单独出现且带 $N$，这句话才能写，而且还要过 Wilson。

### 5.16 合法并排与非法减法的手算对照

用本课六张卡上的公开数字做一次只允许加法练习、不允许能力解释的算术，再对照一次合法减法。

非法：把六个点估计当百分数相加再除以六。

$$
\frac{0.557+0.750+0.5613+0.1224+0.765+0.924}{6}\approx 0.613
$$

0.613 看起来像“中等偏好”。CPU 把它标成 `illegal_six_number_mean`。问题不在算术，在第 6 项是相关系数、第 4 项是 369 个电脑任务的执行成功率、第 5 项是仿真 fine-tune。0.613 没有协议 $\mathcal{P}$，也就没有 $p(\pi,\mathcal{P})$。

合法减法只发生在已经对齐的格子里。例 A：C4 内部，人类 72.36% 减 GPT-4 无障碍树 12.24%，得 60.12 个百分点的差。任务集都是 OSWorld 369，评价都是执行脚本，观察对人类是屏幕、对 GPT-4 是树——观察仍不完全相同，所以合格报告会写“在无障碍树设定下模型落后人类约 60 个点；纯截图设定下落后更多”。例 B：C2 内部，Gemini 1.5 Pro 短视频 81.7% 减长视频 67.4%，得 14.3 个点，协议差在时长桶，必须把 $\Delta t$ 和题型分布写在旁边。例 C：C5 内部，Object 88.4% 减 Long 53.7%，得 34.7 个点，这是第 31 课已经验收过的套件效应。例 D：C1 内部，GPT-4V Humanities 76.3% 减 Tech & Eng. 41.7%，得 34.6 个点，解释必须落在图像类型和推理深度，不能落到“工科数据没吃够所以机器人也会差”——后半句跨到了 C5。

非法减法的典型句式有三句，本课见到就删。句 1：“Video-MME 75% 高于 MMMU 56%，视频模块比学科模块强。”单位都是准确率，类不同。句 2：“LIBERO 76.5% 高于 OSWorld 12.24%，操作比电脑强。”类不同，成功定义不同。句 3：“SIMPLER 0.924 说明仿真已经等于真机 92.4%。”单位不同。Lab 的陷阱格专门打句 2 的变体：把 76.5% 拖进真机。句 3 在 CPU 里用 `simpler_r_rejected_as_success_rate` 打。句 1 用 `mmmu_not_comparable_to_videomme` 打。

### 5.17 教学模拟里的标红是协议检查，不是模型分数

Lab 和 CPU 都不产生新的基准分数。六张卡上的 55.7%、75.0%、56.13%、12.24%、76.5%、0.924 全部来自已打开的原文表。你拖对了，只证明分类函数和拒收规则可执行；你算对了 Wilson，只证明第 31 课的公式还在。把 Lab 通过理解成“我复现了 OpenVLA 76.5%”，属于第 01 课已经禁止过的“把官方评测写成自训复现”。本课把这条禁则从 checkpoint 扩到基准表：抄表可以，抄完必须打类标签；抄表不得当复现。

标红的触发条件写死，避免验收时争论“浅红算不算”。LIBERO 卡的 `id=libero` 且所在桶 `id=real_robot` 时，卡片边框和桶边框使用陷阱色，文案出现“标红：不是真机”。移出陷阱格后红色消失，但预测仍须选“LIBERO 平均最常被误填”。只放对桶、预测选成 MMMU，验收不通过：本课要打的是最常见的跨类记账，不是任意一张卡。勾选“不能横着比”是第三条门禁，对应 CPU 里跨类平均被拒绝。三条同时真，Gate 才过。

CPU 夹具与 Lab 的对应表：

| Lab 行为 | CPU 检查 |
|---|---|
| 六张卡各进一类，不重叠 | `six_class_labels_are_mutex` |
| LIBERO 进真机格 | `libero_macro_rejected_as_real_robot` |
| 把 SIMPLER 卡理解成成功率 | `simpler_r_rejected_as_success_rate` |
| 想用 MMMU 和 Video-MME 做差 | `mmmu_not_comparable_to_videomme` |
| 想用 OSWorld 和 LIBERO 做差 | `osworld_not_comparable_to_libero` |
| 勾选不能总平均 | `cross_class_macro_is_not_a_capability` |

两边必须同方向。Lab 过了而 CPU 某条为假，说明你只记住了颜色，没记住函数。CPU 过了而 Lab 把 LIBERO 留在陷阱格，说明函数会写、手不会拒收。两项都要交。

## 6. 在公开实现中定位这些机制

本课不改 MiniMind-O。机制落在公开基准的题目格式、评价脚本和模型卡的表格结构里。行号会变，认职责，不背行号。

**MMMU**（[仓库](https://github.com/MMMU-Benchmark/MMMU)）。按科目存放交织图文。评测对生成做选项解析和开放题抽取。主榜是零样本测试集 10500。你若只跑验证 900 题，报告必须写 val，不能抄 test 的 55.7%。科目桶、难度桶要能从结果 JSON 里拆出来。

**Video-MME**（[项目页](https://video-mme.github.io/)）。视频、字幕、音频分文件。评测入口要能开关字幕。抽帧数、是否按帧对齐字幕，写进协议卡。不要把有字幕列抄进无字幕列。

**OmniBench**（[项目页](https://m-a-p.ai/OmniBench)）。样本含图像、音频、选项、图理由、声理由。质检用过缺模态消融。你复现时若只用转写，必须改标“近似协议”，分数不得写入原生 C3 主列。

**OSWorld**（[项目页](https://os-world.github.io)）。虚拟机快照、任务 config、getter、evaluator。观察是截图还是无障碍树，最大步数，是否 SoM，都改变 $p(\pi,\mathcal{P})$。跨应用任务单独成桶。

**LIBERO / SIMPLER / CALVIN**。定位清单见[第 31 课](31_vla_evaluation.md) 第 6 节。本课只追加：读脚本时看结果写入哪一列标题。标题写 success rate 却引用 SIMPLER 的 $r$，或标题写 real robot 却引用 LIBERO 平均，直接判定位失败。

读任何 Omni 技术报告时再核四件事：图像节、视频节、三模态节、语音生成节是否分开；有没有 OSWorld 或机器人节；有没有把 $r$ 和成功率画在同一坐标轴；有没有 fine-tune 脚注。四项里缺一项，就还没定位到评测，只定位到宣传句。

定位时用一份对照清单，避免把训练循环误认成评测循环。C1 脚本是否在做选项解析，还是在算生成配文的 CIDEr。C2 脚本是否比较字母，是否按帧对齐字幕。C3 脚本喂的是波形还是转写字符串。C4 脚本是否在虚拟机终态上跑 getter，还是在对演示轨迹做动作匹配。C5 脚本返回的是谓词合取还是动作 MSE。C6 脚本输出的列名是 `pearson` 还是 `success`。六条里认错一条，类标签就会跟着错：把动作 MSE 当 C5，或把转写设定当原生 C3，是实现层最常见的串账。

Qwen2.5-Omni 仓库与报告的对应关系值得单独看一眼。报告 Table 5 的 MMMU 是 val 59.2，不是 test 55.7 那种 GPT-4V 口径；Table 7 的 Video-MME 无字幕 64.3 必须和 Gemini 的 75.0 分列，因为模型不同、抽帧也可能不同；Table 8 的 OmniBench 56.13 与 Gemini 42.91 同表，这一行才是 C3 内部可排序的格子。把三张表的第一列数字抽出来平均，定位就算失败。TTS 的 seed-tts-eval 在 Table 9，单位是 WER，分母是读音内容，进第 01 课语音内容账。你在仓库里搜到 `omni_score` 这种键，应当改成六个键，而不是给它补一个权重。

## 7. 数据与协议 recipe

本课的“数据”是评测记录，不是训练语料。recipe 是协议卡模板。复制下面这张表，一条数字一行。

| 字段 | 填写说明 | 非法例 |
|---|---|---|
| record_id | 稳定短名 | `omni_score` |
| class_id | C1–C6 之一 | `general` |
| benchmark | 论文名 | `内部集` 且无说明 |
| split | test / val / 短中长 / 套件 | 空白 |
| modalities | 实际喂给模型的模态 | 写了音频但评测没喂 |
| unit | accuracy / success_rate / pearson_r / … | `%` 且把 $r$ 乘了 100 |
| n | 题量或 trials | 只写百分比 |
| fine_tune | true / false / 未公开 | 把 FT 写成零样本 |
| value | 点估计 | 区间当点估计 |
| forbidden | 本行不得声称的能力 | 空白却在正文声称真机 |

六行填完之后，再加一行真机。真机行的 class 不在 C1–C6，本课只允许 `real_robot` 出现在这一行。LIBERO 行的 forbidden 必须包含 `real_robot`。SIMPLER 行的 forbidden 必须包含 `success_rate`。

推荐配置：先填表，再画柱。没有表的柱状图，本课视为未完成交付。教学模拟的六张卡已经填好公开数字，你的作业是把它们抄进自己的表，并补上“未测”行，而不是再发明第七个百分数。

一张空卡的合法填法示范如下，供对照。`record_id=libero_openvla_macro`，`class_id=C5_sim_manip`，`benchmark=LIBERO`，`split=four_suite_macro_ft`，`modalities=third_person_rgb`，`unit=success_rate`，`n=6000`（500 trials × 3 seeds × 4 套件的数量级），`fine_tune=true`，`value=0.765`，`forbidden=real_robot`。旁边必须另有四行套件点：Spatial 0.847、Object 0.884、Goal 0.792、Long 0.537。缺四行就只有宏平均，第 01 课和第 31 课都会判未完成。SIMPLER 那一行的示范：`unit=pearson_r`，`n=6`，`split=google_robot_vismatch`，`forbidden=success_rate`。两行示范抄进自己的表，比再写一段“我们很重视评测”有用。

若你要给 MiniMind-O 基线做对照，C1–C6 多数格子应写 `unspecified` 或 `out_of_scope`。mini recipe 无视觉正式评测，C1 不能填 55.7%；没有视频训练，C2 不能填 75.0%；没有三模态题本，C3 不能填 56.13%；没有虚拟机代理，C4 不能填 12.24%；没有机械臂政策，C5 和真机都空。空表是诚实的基线。拿 GPT-4V 的 55.7% 填进 MiniMind-O 的 C1，属于第 01 课禁止的官方评测冒充自训。

## 8. 按依赖顺序执行实验

实验不训练模型。顺序从便宜到贵。

**Step 1：跑互斥夹具。** 导入 `lesson_47.run()`，确认全部 `checks` 为真。重点看：六类双射、LIBERO 拒收真机、SIMPLER 拒收成功率、三对 `may_compare` 为假、Wilson 与第 31 课一致、POPE 幻觉率不是 MMMU 准确率。失败则先改夹具理解，不要改公开数字。

**Step 2：浏览器分桶。** 打开本课 Lab。先在四个选项里预测哪张卡最常被填进真机能力。再把六张卡拖进桶，或先点卡再点桶。把 LIBERO 平均拖进真机能力时，卡和桶必须变红。全部放对、预测选 LIBERO、勾选“不能横着比”后，验收通过。此步是教学模拟。

建议故意先把 LIBERO 卡放进陷阱格一次，确认标红文案出现，再拖回仿真操作。验收要的不是“我从没犯过错”，是“犯了这类错时系统拒绝入账”。揭晓之后六张卡下方会给出测什么、不测什么。把这些句子抄进协议卡的 `forbidden` 列，不要只截一张全绿的桶。预测选错时，即使桶放对了也不通过：本课要你事先知道哪一类最容易被写成真机，而不是对着已经标绿的格子倒推。

**Step 3：手写六行协议卡。** 用第 7 节模板，把六条公开数字抄成六行，真机行留空。禁止把 Lab 的“通过”写成 76.5% 被你复现。六行写完后做一次自检：每一行的 `forbidden` 非空；C5 行含 `real_robot`；C6 行含 `success_rate`；C1 行含接地或视频；C2 行含三模态硬约束；C3 行含电脑或抓取；C4 行含仿真抓取。自检失败就还没交付，哪怕 Lab 已经全绿。

**Step 4（可选，有 GPU）：** 只跑一个 C1 子集，例如 MMMU val 里一个科目 30 题，greedy。报告写科目名、题量、解码配置。不得把 30 题的点估计标成 Table 2 的 55.7%。

**Step 5（可选，有虚拟机）：** OSWorld 单任务，例如清 cookie。记录观察接口和步数。不得把单任务 0/1 写成 Table 5 的 12.24%。

没有 Step 4 和 Step 5，本课仍可交付。有了它们，也仍然不能横着比。可选步骤的报告模板要预先写好，避免跑完之后改口径。Step 4 的标题必须是“C1 子集，科目 X，N=30，greedy，checkpoint 名”，不得写成“我们的 MMMU”。Step 5 的标题必须是“C4 单任务，清 cookie，观察=截图，最大步数=15”，不得写成“我们的 OSWorld”。两条标题里都要出现类标签。缺类标签的真实评测，比没有真实评测更糟，因为它会混进夹具数字里。预算也要事先写：Step 4 约一张 24GB 卡、数十分钟；Step 5 需要能跑虚拟机的机器、单任务数分钟到一刻钟。超时或 OOM 记失败模式，不要改成“改抽 8 题重报”。看过结果再改 $N$，属于[第 17 课](17_grpo_rlvr.md)和第 31 课已经禁止的事后改公式。本课沿用那条禁则，不因为这是分类课就放松。

## 9. 评测与测量

本课要测的不是模型，是记账是否合法。

测量对象：

- 标签函数是否为双射；
- 非法声称是否全部为假；
- Lab 中陷阱格是否标红；
- 同类比较时 Wilson 公式是否与第 31 课一致。

不测量：

- 任何真实 VLM 的 MMMU 分数；
- 任何真实代理的 OSWorld 分数；
- 任何真实政策的 LIBERO 分数。

测量记录本身也要分桶。CPU 的 `metrics` 里六条点估计只是夹具常量，用来核对标签函数，不得拷进模型卡。Lab 的 `placements` 是分类结果，单位是桶名，不是百分数。若进度系统保存了 completion payload，里面的 `liberoInTrap` 是布尔，表示有没有触发标红，不是 LIBERO 成功率。三类对象（夹具常量、分类结果、标红事件）写进同一份 `result.json` 时必须带类型字段，避免以后回看时把 0.765 当成你测出来的。第 01 课要求每个指标可追溯到 case；本课要求每个数字可追溯到类。两句话合在一起，才是完整的账本索引。

若你额外跑了真实评测，测量纪律回到对应类的原文：C1 用微观准确率并拆科目；C2 拆时长和字幕；C3 做缺模态消融；C4 拆应用域；C5 拆套件并写 fine-tune；C6 写 VisMatch 或 VarAgg。真实评测的数字另起 `run_id`，不要覆盖夹具 `metrics`。

## 11. 根据症状定位失败环节

调试时从最便宜、最可观测的一层开始查。比如总表很好看，先查类标签，别急着重训模型。

| 症状 | 可能原因 | 诊断 | 修复 |
|---|---|---|---|
| 一张表六个百分数还有总平均 | 把不同单位兑在一起 | 查 `unit` 列是否混有 $r$ | 删总平均，改并排 |
| LIBERO 76.5% 写在真机节 | 类标签被覆盖 | 对照 Table 12 是否 fine-tune、是否仿真 | 移回 C5，真机留空 |
| SIMPLER 写成 92.4% 成功率 | 把 $r$ 乘了 100 | 回 Table I 看列名是 Pearson $r$ | 改回 $r=0.924$，单位 pearson_r |
| MMMU 高就说视频强 | C1 冒充 C2 | 查有没有 Video-MME 短中长 | 分列，或声明未测 C2 |
| 有字幕 Video-MME 当 Omni | 把可选增益当硬约束 | 对照 OmniBench 质检：缺模态必须答错 | 写入 C2 消融，不写入 C3 主列 |
| OSWorld 减 LIBERO | C4 与 C5 做差 | `may_compare` 应为假 | 删除差值句 |
| 答对了宣称已接地 | 用 C1 代替第 23 课 | 查有无 IoU / POPE 列 | 空出 grounding 格 |
| Lab 不通过但自认放对 | LIBERO 仍在陷阱格 | 看红色边框 | 拖回仿真操作 |

| val 和 test 兑在一起 | 划分字段空 | 对照 MMMU Table 2 两列 | 分列，或只保留自己跑过的那一列 |

## 13. 前沿对照与改造方向

**公开方案。** 同一问题，已经公开的系统其实在报告结构上有对、有错，本课只引用课程里已有或本课已打开的文献。Qwen2.5-Omni 技术报告（arXiv:2503.20215）把评测按「图像到文本」「视频（无音频）到文本」「混合模态到文本」「任意模态到语音」分节：MMMU val 59.2% 放在大学题目，Video-MME 无字幕 64.3%、有字幕 72.4% 放在视频，OmniBench 56.13% 放在混合模态，seed-tts-eval WER 另开生成表。第 01 课已经指出这是按输入输出模态拆桶。拆节是对的。错发生在下游读者把三节理解数字兑成一个 Omni 均分，或把 56.13% 读成电脑代理。OSWorld 原文把人类 72.36% 和模型 12.24% 放在同一任务集上，并按应用域拆开，这是 C4 内部纪律做对了；它没有、也不该去报 LIBERO。OpenVLA / OFT 在仿真表和真机表之间分了 Appendix 与正文，第 31 课已要求引用时写套件和 fine-tune。SIMPLER 把 $r$ 和 MMRV 当主指标，作者自己写目标不是数字孪生。这些公开方案的共同点：好的报告靠分节和脚注，不好的引用靠一张柱。

Moshi（arXiv:2410.00037，第 01 课已引）把 codec 质量、文本能力、语音问答分开，延迟单独报。那是 Omni 语音线的拆桶，对应本课第 01 课账，不要塞进 C1–C6 的理解 / 执行六类里平均。六类没有覆盖语音生成 WER，缺测就留空。[第 17 课](17_grpo_rlvr.md) 的可验证奖励和第 23 课的 POPE 探针给的是能执行的判定，本课六类里 C4、C5 已经是执行式 0/1，C1–C3 仍是选择题。不要把“有了 OmniBench”理解成“已经有视觉侧 verifier”。选择题的字母匹配比 IoU 松，比脚本 getter 更松。想在理解侧做 RLVR，仍然要回到第 23 课的探针，而不是把 C1 准确率当奖励。

**差距。** 规模差：你没有 10500 道 MMMU 测试题的评测预算，也没有 OSWorld 全量 369 任务的虚拟机机时，也没有 LIBERO 500×4 的 VLA 推理。机制差：互斥标签、协议卡字段、陷阱格标红、同类才做差，不依赖模型大小。本课夹具用六条固定记录就能复现“跨类平均无意义”和“LIBERO 不是真机”。不能复现的是 55.7%、12.24%、0.924 这些原文表值本身——它们已经是别人的评测，不是你的训练结果。

**动手改造清单。**

1. **日志禁则。** 改动位置：任何把多个基准分数 `mean()` 后写入 `omni_score` 的脚本，改成先写 `class_id` 再按类落盘。预算：0，只改日志。预期：六类键同时存在，不再出现 `omni_score`。失败判定：仍能 grep 到跨类平均。
2. **陷阱格回归。** 改动位置：结果校验器，增加 `forbidden` 字段。LIBERO 行若 `claimed_capability == real_robot` 则非零退出。预算：CPU。预期：故意写错的夹具被拒绝，和 Lab 标红同方向。失败判定：错标签仍能生成 HTML 报告。
3. **同类区间。** 改动位置：只对 C4 / C5 / 真机这种二项成功率调用 Wilson；对 C6 禁止调用。预算：无训练。预期：$N=25$、$k=20$ 与第 31 课区间一致；对 $r=0.924$ 走 Wilson 的分支不存在。失败判定：相关系数被画上 Wilson 误差条。
4. **字幕开关不得改类。** 改动位置：Video-MME 评测配置，`use_subtitle` 只写进 C2 的 split 字段，不把 run 改标为 C3。预算：若无视频评测，用 Lab 的 Video-MME 卡说明“有字幕仍是 C2”。预期：类标签稳定。失败判定：加字幕后 class_id 变成 tri_modal。

**顺手复现。** 论文结论“宏平均掩盖 Long”（OpenVLA Table 12：76.5% vs Long 53.7%）对应 CPU 的 `libero_macro_matches_four_suites`，预期同方向。论文结论“SIMPLER 主指标是 $r$ 不是成功率”对应 `simpler_r_rejected_as_success_rate`。论文结论“OSWorld 远低于人类”对应把 12.24% 和 72.36% 留在 C4 内部，不搬到 C5。论文结论“OmniBench 去模态会掉点”（Gemini 42.91% 到约 27%）在本课缩小版里不能复现数值，只能复现纪律：没有缺模态消融就禁止写三模态同时。若有人在 Lab 里看到 76.5% 就写“接近真机 80%”，判失败——C5 与真机类不同，且真机 $N=25$ 的 Wilson 下界只有约 0.61。

改造实验的失败判定要能被本课夹具触发。实验 1 用六个数的算术平均就能失败。实验 2 用 `real_robot` 声称就能失败。实验 3 用第 31 课序列就能失败。实验 4 用 Video-MME 卡的类标签就能失败。四条都不必等 GPU。

规模上追不上的部分写清楚，避免用机制通过去暗示表值被复现。MMMU test 10500 题的推理、Video-MME 长视频抽帧、OSWorld 369 项虚拟机、LIBERO 每套件 500 trials，都是钱和时间。机制上可以追上的部分也写清楚：类标签、forbidden 字段、`may_compare`、陷阱格标红、Wilson 只用于二项成功率。报告里把能验收的机制和不能验收的规模分成两段。有人在 Lab 里把六张卡放对，就在标题写“复现六类 SOTA”，判失败——本课没有 SOTA，只有分类。

## 14. 论文与必读材料

按“理解三类、执行三类、报告结构”顺序读。每篇材料对应一个能在协议卡或 CPU 夹具里验证的问题。

### 14.1 理解三类

- [MMMU](https://arxiv.org/abs/2311.16502)：读 §3 统计、Table 1、Table 2、错误分析 §5。带着问题：11550 题里验证 900 和测试 10500 能不能混报？GPT-4V 测试 55.7% 和摘要 56% 是否同一划分？专家 88.6% 是验证集还是测试集？读完写出：C1 不覆盖视频和音频。HTML：[v4](https://arxiv.org/html/2311.16502v4)。项目页：[mmmu-benchmark.github.io](https://mmmu-benchmark.github.io/)。
- [Video-MME](https://arxiv.org/abs/2405.21075)：读 Table 1 时长、Table 4 无字幕/有字幕、Table 5 加音频按域分解。带着问题：900 视频与 2700 题如何对应？长视频无字幕 67.4% 为什么不能藏进总体 75.0%？字幕 +6.2 和音频 +4.3 是不是硬约束？读完写出：C2 的可选模态增益 ≠ C3。HTML：[v3](https://arxiv.org/html/2405.21075v3)。项目页：[video-mme.github.io](https://video-mme.github.io/)。
- [OmniBench](https://arxiv.org/abs/2409.15272)：读 §3 标注方案、Table 1、Table 3、去模态消融。带着问题：1142 题如何保证缺图或缺声就答不对？Gemini 42.91% 去图去声掉到哪？Qwen2.5-Omni-7B 56.13% 的三列音频类型是多少？读完写出人类专家 74.03% 仍高于现有模型。HTML：[v6](https://arxiv.org/html/2409.15272v6)。项目页：[m-a-p.ai/OmniBench](https://m-a-p.ai/OmniBench)。

### 14.2 执行三类

- [OSWorld](https://arxiv.org/abs/2404.07972)：读 §2 环境、§3 统计、Table 5。带着问题：369 项里工作流占多少？人类 72.36% 和最好模型 12.24% 的观察接口分别是什么？Workflow 6.57% 能否代表总体？读完把 C4 写成执行成功率，不要写成试卷。HTML：[v2](https://arxiv.org/html/2404.07972v2)。项目页：[os-world.github.io](https://os-world.github.io)。
- [LIBERO](https://arxiv.org/abs/2306.03310) 与 [OpenVLA](https://arxiv.org/abs/2406.09246) Appendix E Table 12：带着问题仍是第 31 课那句：76.5% 是不是零样本？答案：不是。本课追加：它的类是 C5，禁止迁到真机。HTML：LIBERO [v2](https://arxiv.org/html/2306.03310v2)，OpenVLA [v3](https://arxiv.org/html/2406.09246v3)。
- [SIMPLER](https://arxiv.org/abs/2405.05941)：读 Table I。带着问题：$r=0.924$ 的分母是政策还是 trials？VisMatch 和 VarAgg 能否混成一个 sim-to-real 百分数？读完把该行单位写成 pearson_r。HTML：[v1](https://arxiv.org/html/2405.05941v1)。
- [CALVIN](https://arxiv.org/abs/2112.03227)：不必新学，复习第 31 课 Fig. 8：短程 53.9%、五步 0.08%。本课把它留在 C5 内部的长程子桶，不单开第七类，也不和 LIBERO 平均兑。

### 14.3 报告结构（拆桶有没有做对）

- [Qwen2.5-Omni 技术报告](https://arxiv.org/abs/2503.20215)：读 §5.1.3–5.1.5 与 Table 5 / 7 / 8。带着问题：作者有没有把 MMMU、Video-MME、OmniBench 放进同一小节平均？没有。读者能不能仍然把 59.2、64.3、56.13 兑成一个数？能，所以本课的禁则写给读者和做幻灯片的人。TTS 表不要进六类平均。第 01 课已用这份报告当拆桶样例，本课不重讲 TMRoPE 或 Talker。读 Table 8 时再抄三列音频类型：55.25 / 60.00 / 52.83，确认总体 56.13 不是某一列冒充的。读 Table 7 时写下有字幕 72.4 相对无字幕 64.3 的增益，并在笔记里标明：该增益仍是 C2，不得改标 C3。
- 第 31 课论文节里的 OpenVLA-OFT 与 $\pi_0$ 表：带着问题：97.1% 和 94.2% 为什么可以在 C5 内部比排序，却仍然进不了真机格？答案写在观察（腕部相机）、fine-tune、仿真器三行。把这两行抄进本课协议卡当 C5 的合法对照，真机格继续空。
- [第 01 课](01_baseline_reproduction.md) 第 13 节与第 19 节：带着问题：golden case 分桶和本课六类是什么关系？答案：01 是类内与复现纪律，47 是类间互斥。两层都要。

- [第 31 课](31_vla_evaluation.md)：带着问题：本课 C5 / C6 与 31 课四桶如何衔接？31 课的四桶全在执行侧；本课把理解侧三本账补齐，并把“真机”从可填的第四桶改成必须单独留空的陷阱，除非你真的做了真机。

读完材料回头看：模型一行权重都不必改，评测却已经从“一个 Omni 百分数”变成六本互斥的账。同一张幻灯片上的 76.5% 和 0.924，差的不是模型突然变强变弱，是单位和协议。你现在应该能拿着任意一篇 Omni 或 VLA 的总表，在五分钟内给每个格子打上 C1–C6 或“未覆盖”，并决定 LIBERO 那一格能不能进真机节——不能。

把这条检查写进实验报告第一页，比把六个数抄进标题更有用。读者应能独立复述三句：六类互斥；LIBERO 平均不是真机；SIMPLER 的 $r$ 不是成功率。能复述这三句，CPU 十三条检查为真，Lab 预测选中 LIBERO 且陷阱格最终为空，本课就收工。交互实验还要留下一次标红记录或书面说明“理解拖进真机必须标红”。三项齐了，再去碰公开评测脚本也不迟。公开脚本只能检验同一套标签在真实输出 JSON 上是否还能对上，不能回头否定夹具里已经核对过的互斥规则。标签是协议口径，榜上的百分数是别人的推理口径，两套数字不要写进同一格。

下一课规格指向语音打断和手臂重规划是否共用状态表；那是运行时，不是把六类分数再平均一次。本课停在记账：六类评测数字不能横着比。
