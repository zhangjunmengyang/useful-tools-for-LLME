# 第 53 课：给多模态智能体加上跨会话记忆

> 类型：reason-agent 高级，跨会话 payload 与字节上限<br>
> 建议周期：阅读约 60 分钟；浏览器红蓝杯子实验约 10 分钟；CPU 三条记录数分钟<br>
> 硬件：无 GPU 可完成本课阅读、教学模拟与 CPU 机制实验。对照 LoCoMo、MIRIX、M3-Agent 的公开流水线需要各论文自己的推理卡，本课不要求加载这些权重<br>
> 产物：跨会话记录 schema、三条记录的字节上限、过期删像素留摘要的协议。不是家用机器人，不声称复现 MemoryBank 或 MIRIX 的表内分数<br>
> 独立性：需要[第 14 课](14_long_context_curriculum.md)的窗口概念、[第 39 课](39_long_horizon_memory.md)的子目标栈、[第 45 课](45_multimodal_retrieve.md)的检索层。本课不改 MiniMind-O 源码，不重做 YaRN，不重做 Recall@k，不重做 push / pop

## 1. 跨会话记忆该存像素还是存摘要

昨天助手看见桌上有一只红杯子，把对话写进上下文，晚上进程退出。今天你打开同一套系统，问“杯子是什么颜色”。世界已经换成蓝杯子。窗口里的 token 不在了。[第 14 课](14_long_context_curriculum.md)把“记得住”写成 Transformer 内部的事：把 `max_position_embeddings` 拉到 131072，用 YaRN 把 RoPE 外推到 128K，再用证据删除检查远处片段还在不在注意力里。那一课的记忆对象是窗口长度 $T$，单位是 token。一场半小时对话缺的是 $T$。关会话之后，$T$ 变成 0。

[第 39 课](39_long_horizon_memory.md)把长程失败写成子目标栈。栈深 $k$ 的单位是步骤。四步任务的第二步失败后，窗口回放会把已经打开的抽屉再拉一次，pop 只重试失败步。那一课的记忆对象活在**一轮任务**里。任务结束、仿真复位、进程退出，栈也清空。隔天再来拿杯子，没有栈顶可以 pop。

[第 45 课](45_multimodal_retrieve.md)把长视频写成三层索引：字幕、中间特征、像素。查询先选层，未入 Top-k 的第 47 分钟对阅读器等于不存在。那一课的对象是**一条还在磁盘上的带子**。带子没关，索引可以重建。本课的对象是已经关掉的会话：图、框、句子必须在关闭时写成外部记录，否则明天没有带子可检索。

三课各管一个对象。$T$ 是注意力能看见多远。$k$ 是还剩几件没提交的事。检索层是哪一段画面有资格进阅读器。本课多一个对象：跨会话记录 $r$，单位是字节。$r$ 里可以放昨日原图、一个空间框，或一句话摘要。选错 payload，今天的阅读器要么读到过期的“红色”，要么在加载三条原图时打穿字节上限。

类比到此结束。类比失效处：人可以隔夜还记得杯子换了颜色，是因为视网膜在今天重新看了一眼，并且海马体允许改写旧痕迹。系统若把昨日摘要当成不可变事实，今天的蓝杯子进不了记录。系统若把每张原图都留下，账单按 $H \times W \times 3$ 涨，三条教学尺寸的图就会超过本课的 16384 字节上限。PMMC（Sun 等，arXiv:2608.00962）把这件事写进引言：基于 caption 的仓库省空间，但会永久丢掉 caption 时没写进去的视觉属性。去掉原图访问之后，他们在更偏视觉的 Mem-Gallery 上 Harmonized Judge 下降 4.9 分。本课把同一条裂缝收成可回放的夹具：昨日红、今日蓝、三条记录、一个上限。

还可以用厨房里的第二只杯子把“实体”钉死。左边红杯换成蓝杯，是同一个 `desk_cup` 的属性更新。右边又放上一只绿杯，是新的 `entity_id`。摘要若写成“桌上有杯子”，两条变化都会被同一句话吞掉。框若只有一个，阅读器无法知道问的是左边还是右边。像素若两张都留，账单翻倍。本课夹具只放一只杯子，是为了让颜色更新和字节上限同时可触发，不被“几只杯子”分走注意力。改造实验若要加第二只，必须先加 `entity_id`，再谈颜色。缺实体键的多物体仓库，检索会把绿杯的像素安到红杯的摘要上。M3-Agent 用脸和声纹的全局编号来避免这种张冠李戴；本课用字符串键做同一件事的缩小版。

硬件上，读完加 CPU 实验不需要 GPU。若要接 MIRIX 应用或 M3-Agent 权重做 Step 6，再准备对应论文的推理卡。没有这张卡，跳过 Step 6 仍可完成最低交付。软件上只需要 Python 3.10 标准库和能打开本课页面的浏览器。不要为了本课新装向量数据库。FAISS 在 MemoryBank 里的角色课文已经讲清，CPU 实验不跑它。LangChain 在 SiliconFriend 里负责检索装配，本课同样不引入。教学字典用 Python 列表就够三条记录。列表顺序就是写入序，过期器靠 `day` 和该顺序排序。换成真正的数据库之后，排序键必须显式建索引，不能依赖“刚好插入顺序还在”。插入顺序在并发写入里会丢。夹具是单线程，所以没暴露这个问题；并发改造时先加测试：两条 `day` 相同的记录，过期顺序必须与主键一致。

要改的模块是会话关闭时的写入器，以及超限时的过期器。不是 RoPE，不是子目标栈，不是长视频的选层器。验证改对了的标准有两条，都必须能在夹具里复现：只读首条摘要会把颜色答成红；三条原图的字节之和大于上限。混合策略在今日写入时改写同一实体的摘要，并按写入日从旧到新丢掉像素槽，摘要和框留下。浏览器 Lab 和 CPU 实验都是教学夹具。它们证明协议可复核，不能写成 LoCoMo 的人类 87.9，也不能写成 MIRIX 的 85.4%。

本课只用一次“不是 / 而是”来钉死边界：隔天能用的不是加长后的注意力窗口，而是会话关闭时落盘、次日仍能按字节上限取回的那条记录。后面只写 schema、公式和失败判定。

本课术语：

| 术语 | 简要解释 |
|---|---|
| 会话 / session | 一次连续交互，有开始和关闭。关闭后窗口与 KV cache 丢弃 |
| 跨会话记录 | 关闭时写入外部存储、次日仍在的一条记忆，字段分列 |
| payload | 记录里实际保存的内容：原图像素、空间框、或一句话摘要 |
| 像素槽 | 按 $H \times W \times C_{\mathrm{ch}}$ 计的原图或裁剪图 |
| 框槽 | 物体的轴对齐框，本课按 4 个 int32、16 字节计 |
| 摘要槽 | 一句话自然语言，按 UTF-8 字节计 |
| 字节上限 $B_{\max}$ | 全部记录的字节和不得超过的硬限制，本课教学值 16384 |
| 过期 | 超限时删像素槽，摘要和框必须留下 |
| 实体改写 | 同一 `entity_id` 在新观察到来时更新摘要，禁止只追加、不覆盖 |
| 首写冻结 | 摘要只在第一次看见时写入，之后不再改，本课用它制造错误颜色 |
| LoCoMo | 超长多会话对话基准，含图像分享，最长 35 个会话 |
| 虚拟上下文 | MemGPT 把 LLM 窗口当内存、外部库当磁盘的分页办法 |

## 2. 本课解决的问题

到第 45 课为止，课程里已经有三种“记得住”。窗口记得当前前缀里的 token。栈记得这一轮还没提交的步骤。检索层记得长带子上哪一段有资格被看见。缺的是第四种：进程已经退出、任务已经结束、视频文件也不在当前阅读器里时，系统凭什么回答“杯子是什么颜色”。常见实现有三条错路。

第一条错路：把昨日整段对话继续拼进第 14 课那种窗口。LoCoMo（Maharana 等，arXiv:2402.17753）把这种长度写成数字：50 段对话，平均 304.9 轮、19.3 个会话、9209.2 个 token，时间跨度几个月，最长 35 个会话。相对 Multi-Session Chat 的平均 4 个会话、1225.9 个 token，大约是 9 倍 token、4 倍会话。GPT-4-turbo 在 4096 上下文上的问答整体分数是 32.4，人类是 87.9。加长上下文能改善事实题，但在对抗题上 gpt-3.5-turbo-16k 会落到 2.1%，比短上下文的 GPT-4-turbo 低 83%。窗口不是隔夜仓库。

第二条错路：只存一句话。“桌上有一只红色杯子。”便宜，检索也快。MemoryBank（Zhong 等，arXiv:2305.10250）的日摘要和全局摘要就是这一层。LoCoMo 的会话摘要检索 Recall@10 可以到 90.7，问答 F1 却只有 31.5，因为摘要把颜色、时间、是谁说的压没了。今日杯子换蓝，昨日那句还在，答案就是红。

第三条错路：把每张原图都留下。像素保留了今日的蓝色，也保留了昨日的红色、便签、桌布。三条 64×64×3 的教学图已经是 $3 \times 12288 = 36864$ 字节，超过本课 16384 的上限。MIRIX（Wang 与 Chen，arXiv:2507.07957）在 ScreenshotVQA 上把这件事写成产品数字：SigLIP 基线要保留 2K–4K 原图，存储到 19.88–22.55 GB；他们自己的 sqlite 只要约 20 MB，相对 RAG 准确率高 35%，存储少 99.9%。省下来的前提是**不要把原图像素当唯一 payload**。本课不复现那 99.9%，只复现“三条原图会超上限”这一方向。

本课因此固定四个可证伪命题。它们是协议命题，不是模型命题。协议命题可以用 CPU 回放证伪；模型命题需要权重、截屏和真人对话，本课不做。

1. 存在三条记录，全部带 $64 \times 64 \times 3$ 像素时，字节和大于 $B_{\max}=16384$。
2. 过期按写入日从旧到新删像素，摘要和框的字段仍在，过期后字节和 $\le B_{\max}$。
3. 只读实体的首条摘要，颜色答案为 `red`，与今日真值 `blue` 不一致。
4. 今日写入时改写同一 `entity_id` 的摘要，并只保留装得下的新图，答案为 `blue` 且不超限。

四条都通过，只能说明 schema 和过期器被写成了可回放的函数。它们不能说明 SiliconFriend 在 194 道探测题上的 0.716 可以搬到你的客服机器人，也不能说明 M3-Agent 在 M3-Bench-robot 上的 30.7 等于家里的杯子识别已经可用。把四条抄进实验记录时，每条后面跟一个本课夹具数字：37209、12633、`red`、`blue`。数字和命题绑在一起，别人才能复核。只交四句口号，等于没做第 53 课。

出现以下任一情况时，不得把结果标成可用的跨会话记忆：

- 只有一段“长期记忆”散文，没有分列的摘要 / 框 / 像素字段；
- 用 token 下标或栈深 $k$ 冒充字节；
- 过期之后摘要字符串变空或变短；
- 今日写入后阅读器仍按最小 `day` 取颜色；
- 把 GPT-4o 演示视频里“还记得你昨天说过”的流畅程度，换算成本课颜色成立；
- 把 MovieChat 处理一万帧写成已经解决隔夜原图。

把这张清单和前几课的失败清单对齐，避免“本课新发明一套红线”。[第 14 课](14_long_context_curriculum.md)禁止只报能吃进 128K。[第 39 课](39_long_horizon_memory.md)禁止把加大 $T$ 当成失败恢复。[第 45 课](45_multimodal_retrieve.md)禁止把错误层的完整答案当成看见了目标段。本课往这三条后面加第四条：禁止把昨日摘要当成今日像素。四条同时成立，隔夜再来才算接到了同一张可审计的记录上。缺第四条时，前三条可以各自通过，联合演示仍会在“杯子换色”这一下翻掉。

本课明确不解决的问题：不训新的视觉语言模型；不实现 FAISS 或 sqlite 以外的教学字典；不比较离散动作 token 与流匹配；不把第 45 课的三层召回再做一遍；不把第 39 课的 pop 当成隔夜记忆；不重做第 14 课的 YaRN 与证据删除。第 08 课已经说明动态分辨率会改变进模型的 tile 数，那是**当前会话**的视觉账单。本课的像素槽是**关闭之后还占磁盘**的账单，两笔账不要加在同一行。

失败条件预先写死：

- 把 128K 窗口或 35 个会话的 LoCoMo 长度写成已经解决跨会话记忆；
- 只报生成是否流畅，不报记录字节和颜色对错；
- 把 ASR 命中或字幕命中写成看见了今日杯子；
- 过期时连摘要一起删掉，却写成“释放了预算”；
- 首条摘要不改写，却把答红当成“记忆很好”；
- 把第 39 课的栈操作、第 45 课的选层当成隔夜仓库。

把失败写成可观察的日志，比写成口号有用。一次不合格的运行至少应留下：会话编号、`entity_id`、三条 payload 的字节、是否超限、颜色答案、真值。缺 `entity_id` 时，别人无法判断你是追加了一条新杯子，还是改写了旧杯子。缺字节时，颜色答对也不能证明账单合法。本课把这两项写成和[第 01 课](01_baseline_reproduction.md)的 mask 统计同类的必留字段。

还可以用一条时间线把四次读写钉在同一只杯子上。$t=0$ 打开会话，看见红杯子，窗口里有图。$t=t_{\mathrm{close},0}$ 写入 `cup_day0`，像素、框、摘要三槽都满。$t=1$ 新会话开始，窗口空，若此时提问且只加载摘要，答案为红。随后摄像头给出蓝杯子，写入 `cup_day1`。若加载器按词重叠取“杯子”，可能同时取出两条。阅读规则必须指定 `max(day)`。最后跑过期，昨日像素清掉。谁把 $t=1$ 提问时的答红写成“模型幻觉”，请他先出示加载列表里有没有 `cup_day1`。没有这条记录，是写入失败。有记录却答红，是覆盖失败。列表超限被拒，是账单失败。三种失败的修复完全不同，不能共用“再训一版 VLM”。

LoCoMo 的图像分享链路把同一裂缝写在真实数据里。智能体先用语言模型生成 caption 和关键词，再用网页搜索配图，对端用 BLIP-2 再生成一句反应侧 caption，两句 caption 都进长时记忆。问答实验把原图换成这些 caption。作者承认个人相册里的长期外观一致性不在数据里。本课的红变蓝就是那种一致性：同一 `entity_id`，外观变了。配图搜索配到的“红色杯子”库存图，会把错误外观写进仓库。教学夹具不联网，就是为了不让搜索引擎把颜色纠正或污染。CPU 实验禁止读磁盘上的真实 JPEG，只用 $H \times W \times 3$ 的整数账单。

## 3. 开始前需要准备什么

本课没有 MiniMind-O 训练步骤。开始前把上游事实和本课约定分开写进实验记录。

**上游事实（打开过的页面，不是口口相传）：**

- MemoryBank：[arXiv:2305.10250](https://arxiv.org/abs/2305.10250)，HTML：[v3](https://arxiv.org/html/2305.10250v3)。记忆库存对话、日事件摘要和用户画像；检索用双塔加 FAISS；更新用简化的艾宾浩斯曲线 $R=e^{-t/S}$，$S$ 初次为 1，被召回则 $S \leftarrow S+1$ 且 $t \leftarrow 0$。定量集：10 天、15 个虚拟用户、194 道探测题（中英各 97）。表 2 英文：SiliconFriend ChatGPT 检索 0.763、正确率 0.716、连贯 0.912；ChatGLM 检索 0.809、正确率 0.438。开源模型另用 38k 心理对话、LoRA rank 16、3 个 epoch、一张 A100。
- MemGPT：[arXiv:2310.08560](https://arxiv.org/abs/2310.08560)。主上下文当内存，recall / archival 当磁盘。提示 token 超过底层窗口的约 70% 时插入 memory pressure 警告；到 100% 强制换页，并对挤出的消息做递归摘要。评测含扩展后的 Multi-Session Chat，以及嵌套键值检索；作者写明 MemGPT 是唯一能在嵌套层数超过 2 时仍稳定完成该任务的方法。
- Generative Agents：[arXiv:2304.03442](https://arxiv.org/abs/2304.03442)。记忆流是自然语言对象列表，每条含描述、创建时间、最近访问时间。检索按近因、重要度、相关度三项归一化后等权求和。25 个智能体、两个游戏日，用记忆流核对“情人节派对”和“市长竞选”有没有被编造。
- LoCoMo：[arXiv:2402.17753](https://arxiv.org/abs/2402.17753)，HTML：[v1](https://arxiv.org/html/2402.17753v1)。50 段对话；表 1：平均 304.9 轮、19.3 会话、9209.2 token，跨几个月，多模态。人工编辑约 15% 的轮次，删除或替换约 19% 的图像。人类问答 87.9；长上下文和 RAG 相对基座有 22–66% 的相对改善，仍落后人类约 56%，时间推理落后约 73%。局限节写明：网图可用 caption 替换，除非需要 OCR。
- LongMemEval：[arXiv:2410.10813](https://arxiv.org/abs/2410.10813)。500 道题，测五项能力：信息抽取、跨会话推理、时间推理、知识更新、拒答。商业聊天助手和长上下文 LLM 在持续交互上准确率下降约 30%。作者把设计拆成 indexing / retrieval / reading 三阶段。
- MA-LMM：[arXiv:2404.05726](https://arxiv.org/abs/2404.05726)。在**一条视频内部**用记忆库在线累加历史帧，Q-Former 每帧 32 个 token，Breakfast 93.0、COIN 93.2。这是第 45 课的亲戚，不是本课的隔夜仓库。

## 4. 完成后应具备的能力

一个可用的自检办法：把别人的“长期记忆”架构图遮住产品名，只留方框和箭头。你应能判断哪些方框在会话关闭后还在，哪些只是当前窗口；像素、框、摘要有没有分列；超限时扔的是哪一列；新观察进来时覆盖的是哪一个 `entity_id`。缺分列时，演示可以很流畅，审计过不了。

完成后，拿到任意“隔天还记得吗”的实现或论文图，应能做以下检查：

1. 标出会话边界：哪一刻窗口被丢弃，哪一刻外部记录必须已经写完。
2. 画出一条记录的字段：`entity_id`、`day`、摘要、框、像素、各字段字节。
3. 手算 $B(r)=B_{\mathrm{hdr}}+B_{\mathrm{sum}}+B_{\mathrm{box}}+B_{\mathrm{pix}}$，三条全留像素时与 $B_{\max}$ 比大小。
4. 写出过期规则：只删像素，留下摘要和框；按写入日从旧到新。
5. 指出首写冻结为何会把昨日红带进今日答案。
6. 指出今日必须改写同一实体，而不是再插一条互相矛盾的摘要。
7. 对照 LoCoMo 表 1：304.9 轮、19.3 会话、9209.2 token、最长 35 会话。
8. 对照 MemoryBank 表 2 的检索准确率和正确率，并写明语言与模型名。
9. 对照 PMMC：caption 会丢掉没写进句子的视觉属性；去掉原图访问，Mem-Gallery 降 4.9 分。
10. 在 Lab 里先提交预测，再看到摘要答红、原图像素超预算。

把第 10 条再拆成可对外说的三句限制，避免验收会上被追问时改口。第一句：本课证明协议，不证明识别。杯子颜色是夹具字段，没有物体检测，也没有色相直方图。第二句：本课证明落盘，不证明在线。昨日和今日可以按 `day` 注入，不必在你的笔记本上跑 7B 写入器。第三句：本课证明账单，不证明下一次仍能答对没见过的杯子。混合策略在第三条记录之后仍然可能超限，那是 $H$、$W$、$B_{\max}$ 的事，把边长再加大就会看见，不要在本课用“永远答蓝”当 Gate。Lab 的 Gate 亮着只表示先预测、摘要错色、像素超限。杯壁画成蓝色，只是画面上的旁证。同事若追问“真实杯子呢”，回答回到这三句，不要现场加识别准确率。识别准确率属于第 23 课的格子命中，本课没有格子。色卡、光照、杯壁反光都可能让真实系统把蓝看成紫，那是视觉问题。本课只保证：即便识别器完美，选错 payload 仍会答红或超限。识别器不完美，只会让第三条命题更难，不会取消前两条。把识别错误和 payload 错误写在同一行里，第二天无法决定该改摄像头还是该改过期器。分列之后，摄像头问题走第 23 课的格子命中，过期器问题留在本课的字节上限这一列。

## 5. 原理：边造边讲

难点不在向量数据库品牌，在承诺的范围：会话关闭时到底写下了什么，次日加载时还剩什么，超限时先扔什么，新观察到来时改写谁。下面按同一节奏展开：为什么需要、怎么运转、精确定义、在哪核对、怎么证明做对了。

### 5.1 会话边界：窗口结束的地方，记录必须开始

一次会话 $s$ 是半开区间 $[t_{\mathrm{open}}, t_{\mathrm{close}})$。区间内，模型读的是长度为 $T$ 的窗口，加上第 39 课那种栈，加上第 45 课那种当次检索结果。$t_{\mathrm{close}}$ 之后这三样都可以为零。若 $t_{\mathrm{close}}$ 没有对应一次 `flush`，次日的阅读器没有合法输入。

MemGPT 把这次 flush 写成操作系统分页。主上下文是物理内存，容量记作 $C$。当提示长度 $L \ge 0.7C$ 时插入警告，让模型自己调用 `recall_storage.search` 或 `archival_storage.insert`；当 $L \ge C$ 时强制换页，并对挤出的 FIFO 消息做递归摘要。警告阈值 70% 来自论文正文，不是本课发明。本课不实现函数调用循环，只借用一条纪律：接近上限时必须先写外部，不能指望窗口自己过夜。

LongMemEval 把同一纪律拆成三阶段：indexing（写什么）、retrieval（取什么）、reading（读什么）。500 道题覆盖信息抽取、跨会话推理、时间推理、知识更新、拒答。商业助手和长上下文模型在持续交互上掉大约 30 个点。掉点发生在知识更新这一项时，和本课的红变蓝是同一类错误：旧值还在，新值没覆盖。

验证：CPU 夹具里每条记录都有 `day`。`day=0` 的两条在昨日关闭时写入，`day=1` 的杯子在今日关闭前写入。缺 `day` 的实现，过期顺序无法复核。

### 5.2 一条记录的 schema

记录 $r$ 至少含：

- `id`：稳定主键；
- `entity_id`：世界里的对象，本课有 `desk_cup` 与 `desk_note`；
- `day`：写入日，整数；
- `summary`：字符串；
- `box`：可选，$(x_1,y_1,x_2,y_2)$ 或 $(x,y,w,h)$；
- `pixels`：可选，长度为 $H \times W \times C_{\mathrm{ch}}$ 的字节数组。

Generative Agents 的记忆流对象是 `(description, created_at, last_accessed_at)`。那是纯文本流，没有像素槽。MIRIX 把文本拆成六类：Core 常驻人设，Episodic 带时间戳的事件，Semantic 概念，Procedural 步骤，Resource 文档，Knowledge Vault 逐字敏感信息。本课不实现六类路由，只要求**同一条记录内部**把摘要、框、像素分列。混在一个 `blob` 里，过期器无法只删像素。

字节定义：

$$
B(r)=B_{\mathrm{hdr}}+B_{\mathrm{sum}}(r)+B_{\mathrm{box}}(r)+B_{\mathrm{pix}}(r)
$$

其中 $B_{\mathrm{hdr}}=64$，$B_{\mathrm{box}}=16$ 若有框否则为 $0$，$B_{\mathrm{sum}}=\mathrm{utf8}(r.\mathrm{summary})$，

$$
B_{\mathrm{pix}}=
\begin{cases}
H \cdot W \cdot C_{\mathrm{ch}}, & r \text{ 仍持有像素}\\
0, & \text{否则}
\end{cases}
$$

夹具 $H=W=64$，$C_{\mathrm{ch}}=3$，故 $B_{\mathrm{pix}}=12288$。昨日杯子摘要 36 字节，于是一条满配记录

$$
B(\texttt{cup\_day0})=64+36+16+12288=12404
$$

便签句 33 字节，满配 $12401$。今日杯子与昨日杯子同长，$12404$。仓库总账

$$
B_{\mathrm{store}}=\sum_{r \in \mathcal{M}} B(r)
$$

合法当且仅当 $B_{\mathrm{store}} \le B_{\max}$。三条满配 $12404+12401+12404=37209>16384$。这里的数字以 UTF-8 实数为准，CPU 实验按 `len(s.encode("utf-8"))` 打印，不要手抄成 12400 却不核。

验证：`record_bytes` 必须等于四段之和。改摘要多一个句号，字节必须加 3（UTF-8 的 `。` 是三字节），不得加 1。中文标点的三字节是本课最容易和 `len(s)` 打架的地方。Python 里 `len("。")` 为 1，`len("。".encode("utf-8"))` 为 3。仓库若按字符数限额，16384 个汉字会远超 16384 字节。本课上限的单位写死为字节。JSON 若以 UTF-8 落盘，磁盘占用接近 `encode` 的结果再加结构括号。夹具不把括号计进 $B_{\mathrm{hdr}}$ 以外，表头 64 已经按“够放 id、entity、day 和一个小校验和”估，不按真实 JSON 展开。谁把真实 sqlite 行大小写成 64，请他 `hexdump` 一行再回来改 $B_{\mathrm{hdr}}$。改了表头，必须重算 12404 和 37209，Gate 数字跟着变。

id 的稳定性也要写进 schema 说明。`cup_day0` 是教学主键，真实系统常用哈希：`hash(entity_id, day, camera_id)`。哈希碰撞会让今日蓝覆盖到另一只杯子上。本课两条实体 `desk_cup` 与 `desk_note`，主键不含内容字符串，避免摘要改词导致 id 漂移。漂移的表现是过期后摘要列表对不上 `SUMMARIES` 原句，CPU 第二条检查会失败。那不是过期器坏了，是你把 id 绑在了文本上。

### 5.3 像素、框、摘要各保住什么

三个 payload 不是精细度滑条，是三种失败模式。

像素保住今日的蓝色、杯柄高光、桌上反光。[第 08 课](08_dynamic_vision.md)已经说明分辨率决定 tile 数；[第 10 课](10_video_token_reduction.md)说明进模型之后还可以再压 token。本课的像素槽发生在进模型之前、关会话之后。它的代价是磁盘和次日加载预算，不是注意力 FLOPs。三条 $64 \times 64$ 图在夹具里就会超限。真实 2K 截屏更贵：MIRIX 写明 Gemini 基线要把图缩到 $256 \times 256$ 才能塞进长上下文，SigLIP 基线按原分辨率计到 22.55 GB。本课禁止把 22.55 GB 写进 Gate，只借用“原图贵”。

压缩格式会改变 $B_{\mathrm{pix}}$ 的数字，不改变“原图贵”这个方向。JPEG 在平滑桌面上可能把 12288 压到两千字节以下，红杯和蓝杯的色块仍然分得开；在强纹理桌布上可能压不动，还会在块边界引入伪色。夹具故意用未压缩 RGB，是为了让 $H \times W \times 3$ 可手算。接入真实编码器时，必须把 `codec` 字段写进记录，并在笔记里固定质量参数。质量参数若按日漂移，昨日 37209 和今日 37209 就不可比。这和第 01 课禁止混用 ASR 版本是同一条纪律，只是对象从转写器换成了图像编码器。

颜色在像素槽里的表示也要能说清楚。夹具不存真正的 RGB 数组，只存“这条记录的 `color` 字段”。教学上把 `color` 当成从像素读出来的oracle，避免在 CPU 里写一个假的直方图。真实系统要用视觉编码器或规则：例如杯壁区域的平均色相。平均色相在红蓝之间通常分得开，在橙与红之间会打架。本课验收只用红对蓝，不把细色差写进 Gate。细色差交给第 23 课那种格子探针，本课只要求 payload 选择会不会把颜色整类弄丢。

框保住位置，丢掉外观。[第 23 课](23_grounding_ocr_spatial.md)的 grounding 命中用预测框与真值 IoU；[第 32 课](32_gui_agent_grounding.md)的 Set-of-Mark 把可点区域标成数字。本课的框槽只有 16 字节，次日可以知道“杯子大约在桌面中央”，不能知道它是红还是蓝。查询若是颜色，框策略和空策略一样失败。查询若是“杯子还在不在原来那一侧”，框比摘要更合适。Lab 不把框当成能答对颜色的策略，避免把位置题和颜色题混在一格。

摘要保住可检索的句子，丢掉没写进去的属性。MemoryBank 的日摘要提示词是 “Summarize the events and key information”。LoCoMo 把对话压成 session summary 再检索，Recall 很高，问答 F1 接近不检索的 29.9。作者的解释是转换过程丢失信息。本课把丢失写成颜色：首条摘要含“红”，今日世界是蓝，答案跟随摘要。

PMMC 把三种需要拆开：事实题可能只需要文本，实体题需要图文绑定，视觉细节题需要原图像素，时间或多跳题需要若干条互相链接的记忆。本课的红蓝杯子是视觉细节题。用事实题的仓库去答视觉细节题，必然答红。

### 5.4 过期：删像素，留摘要

MemoryBank 用 $R=e^{-t/S}$ 决定一条文本记忆还在不在。$t$ 是上次学习或召回以来的时间，$S$ 是强度。召回一次，$S$ 加 1，$t$ 归零。那是**文本项**的遗忘。本课的过期更硬：字节超了就必须扔。扔的顺序有三种常见错误。

FIFO 整条删除：连摘要也扔。次日既没有图，也没有“曾经有过一只杯子”。账单漂亮，实体消失。

按余弦合并相邻帧：这是 MovieChat / MA-LMM 在**一条视频内部**做的事。MA-LMM 的 Memory Bank Compression 对相邻最像的 token 取平均，长度相对视频帧数保持常数。它服务的是在线看长视频，查询不进入打分。本课的三条记录来自两个自然日和一张便签，不是相邻视频帧。禁止把 MBC 抄进跨会话过期器。

本课采用第三条：只把 `has_pixels` 置假，摘要和框不动。排序键是 `(day, 写入顺序)`。循环直到 $B_{\mathrm{store}} \le B_{\max}$ 或没有像素可删。夹具里昨日杯子和昨日便签的像素先走，今日杯子的像素留下。于是

$$
B_{\mathrm{hybrid}}=B(\texttt{cup\_day1 满配})+B(\texttt{cup\_day0 无图})+B(\texttt{note 无图})
$$

CPU 实验要求这个值 $\le 16384$，并且过期后仍能读到三句摘要原文。

MemGPT 的 70% / 100% 是窗口压力，不是磁盘压力。两边都要有阈值，不要共用一个数字。本课磁盘阈值就是 $B_{\max}$。窗口阈值本课不实现，留给已经读过第 14 课的人自己写进笔记：次日加载时，把摘要放进窗口，像素只加载仍持有 `has_pixels` 的那几张。

### 5.5 实体改写：同一杯子，隔天换色

设实体 $e=\texttt{desk_cup}$。昨日观察给出颜色 $c_0=\mathrm{red}$，今日观察给出 $c_1=\mathrm{blue}$。查询时刻 $t_q$ 在今日会话内。正确的阅读证据必须含有 $c_1$。

首写冻结：

$$
\hat{c}=\mathrm{color}(r_{\mathrm{first}}),\quad r_{\mathrm{first}}=\min\{r:r.\mathrm{entity}=e\}
$$

$r_{\mathrm{first}}$ 是昨日那条，$\hat{c}=\mathrm{red}$。这是 MemoryBank 只追加日摘要、不声明覆盖规则时会发生的事，也是 LongMemEval 的 knowledge update 项在测的事。

追加不覆盖：仓库里同时有“红色杯子”和“蓝色杯子”，检索若按近因以外的词重叠，可能仍命中“红”。LoCoMo 的时间题是最难的一类，相对人类落后约 73%。本课不把时间推理做成完整基准，只要求 `max(day)` 那条优先。

改写：

$$
r^\star=\arg\max_{r:\ r.\mathrm{entity}=e} r.\mathrm{day},\quad \hat{c}=\mathrm{color}(r^\star)
$$

混合策略在写入今日记录之后执行这一行，再跑过期。答案为蓝，且 $B_{\mathrm{store}}\le B_{\max}$。

Generative Agents 的检索分是

$$
\mathrm{score}(m)=\mathrm{recency}(m)+\mathrm{importance}(m)+\mathrm{relevance}(m)
$$

三项先归一化，原文默认等权。近因是上次访问以来的指数衰减。若今日蓝杯子的记录还没被访问，近因可能低于昨日反复讨论过的红杯子。这是“记忆很好”却答错颜色的另一种机制：检索分不等于新近观察。本课 CPU 不实现三项加权，Lab 也不展示重要性。笔记里要写明：若你在系统里用了 Park 等人的打分，必须给“同一实体的最新观察”一个覆盖近因的规则，否则红杯子会因为被聊过很多次而压过蓝杯子。

### 5.6 三条记录的逐步账单

把夹具展开成可手算的表，避免只记住“大约三万六”。表头一律 64。框一律 16。像素一律 12288。摘要按 UTF-8。

| 记录 | day | 摘要字节 | 满配 $B(r)$ | 过期后像素 | 过期后 $B(r)$ |
|---|---|---|---|---|---|
| cup_day0 | 0 | 36 | 12404 | 无 | 116 |
| note_day0 | 0 | 33 | 12401 | 无 | 113 |
| cup_day1 | 1 | 36 | 12404 | 有 | 12404 |

过期前总和 37209。过期后 $116+113+12404=12633$。CPU 的 `expired_store_bytes` 必须印出 12633。若你改了摘要标点，先重算这一行，再改断言。$B_{\max}=16384$，过期后余量 $16384-12633=3751$，不够再塞一张 64×64 图，够再塞大约三十句同等长度的摘要。这就是“删像素留摘要”的定量含义：腾出来的是整张图的 12288，不是几个 token。

加载规则也按这张表写死。摘要策略：只物化三句文本，颜色从 `cup_day0` 读出红。像素策略：试图物化三张图，37209>16384，返回 `budget_exceeded`，颜色列记为非法，不得填红或蓝。混合策略：物化今日图加三句文本，12633≤16384，颜色从 `cup_day1` 读出蓝。三列答案并排：红 / 超限 / 蓝。缺任何一列，验收不算过。

边长变化时，只改像素那一列。边长 32：$32\times32\times3=3072$，满配一条 $64+36+16+3072=3188$，三条约 9564，低于 16384，像素策略不再爆。边长 96：$96\times96\times3=27648$，单张已超上限，混合策略也会拒答。Lab 的滑条就是用来造出这两端。默认 64 落在“三条爆、一条不爆”的区间，对应 CPU 夹具。

### 5.7 裁剪图是第四档，不是框的别名

产品和论文里还常出现裁剪（crop：按框从原图切出一块再存）。它看起来像框和像素的折中，字段上必须单独开槽。框是 16 字节的坐标，不含外观。裁剪是一块更小的 RGB，字节是 $h_{\mathrm{crop}} \times w_{\mathrm{crop}} \times 3$。杯子若占 64×64 图的四分之一，裁剪大约 3072 字节，三条裁剪可能重新低于上限，颜色也还在。这会让人误以为“存框就够了”。框答不对颜色；裁剪才可能。Lab 故意不提供裁剪滑条，免得验收条件从“原图像素爆预算”被偷换成“小裁剪不爆”。

写入器若自动裁剪，必须在日志里写 `payload=crop` 以及 $h_{\mathrm{crop}},w_{\mathrm{crop}}$。PMMC 的程序内核里有 raw-image materialization 和 image–text expansion，就是在查询时才把原图或局部图物化，巩固期只存索引和程序。本课夹具更朴素：像素要么整张在，要么不在。谁在报告里写“我们存了框所以看见了蓝色”，把裁剪和框的字节差算一遍。差为 0，就还是框；差接近 $h_{\mathrm{crop}} w_{\mathrm{crop}} \times 3$，才是裁剪。

[第 08 课](08_dynamic_vision.md)的 tile 是当前会话进模型的切片，按分辨率动态变多变少。跨会话裁剪是关会话后留下的小图，张数由实体数决定，不由当前显示器分辨率决定。两笔账单的自变量不同。把 tile 数抄进 $B_{\mathrm{pix}}$，单位就回到了 token。本课禁止。

### 5.8 冲突、投票和不可撤回的旧句

同一 `entity_id` 在两天给出相反属性时，仓库里会短暂同时存在 $c_0$ 与 $c_1$。M3-Agent 用节点权重投票：反复激活的边压过偶发错误的边。人脸和声音的错误绑定会在后续片段里被多数票纠正。本课的颜色冲突更简单：以最大 `day` 为准，不按出现次数。红杯子若被聊了十轮，蓝杯子只被看了一眼，次数投票会把今日观察压掉。那是 Generative Agents 近因加重要度的变体失败。家用场景里，“刚刚看见”应压过“以前常说”。

旧句不可从审计日志里抹掉。昨日摘要“红色杯子”在改写之后仍应能按 `id=cup_day0` 读出。过期器只清像素，不改字符串。这和第 48 课规格里“已播 PCM 不能 undo”同构：已经对用户发生过的话是历史。今日答案跟新记录，昨日记录留作追溯。有人把改写实现成 `UPDATE summary SET text=...` 且不留旧行，颜色可能对，事故无法回放。CPU 夹具因此保留三条记录对象，改写只发生在阅读函数的选择规则里，不发生在销毁昨日字符串上。混合策略的 `answer_hybrid` 读的是 `max(day)` 那一行的摘要，昨日那一行仍在 `expired` 列表里。

Knowledge Vault 类字段另算。MIRIX 把地址、密钥放进 Vault，标灵敏度，高灵敏度默认不进入闲聊检索。杯子颜色不是密钥，但“用户家里的布局图”可能是。本课不实现权限位，笔记里要留一格：过期删像素不等于对外公开摘要。摘要仍可能含地址。评测集若把地址写进 caption，删像素解决不了泄漏。

### 5.9 和窗口、栈、检索层的对象表

把四个对象写进同一张表，避免验收会上改口。

| 对象 | 课 | 单位 | 活在哪 | 失败时看见什么 |
|---|---|---|---|---|
| 窗口 $T$ | 14 | token | 当前前缀 | 远处证据删掉后仍敢答 |
| 栈深 $k$ | 39 | 步骤 | 一轮任务 | 已打开的抽屉被再拉一次 |
| 检索层 $\ell$ | 45 | 片段 | 一条长带子 | 第 47 分钟不在 Top-k |
| 记录 $r$ | 53 | 字节 | 会话关闭之后 | 答红或三条原图超限 |

第 45 课的像素层和第 53 课的像素槽同名不同源。前者是“当前这条带子上按帧建索引”，查询还在，带子还在。后者是“昨日那张图过夜后还占多少字节”。把第 45 课的密采样 60 帧抄进本课的 $B_{\mathrm{pix}}$，单位就错了。第 45 课按 token 向阅读器收费，本课按字节向仓库收费。Gate 数字分别是 4096 token 和 16384 字节，不要互相冒充。

第 39 课的提交表也不是隔夜仓库。提交表记得“抽屉已经打开”，服务的是当前这条五步链。隔天桌子被收拾过，抽屉状态要重新看图，不能 pop。本课的 `entity_id` 可以跨天，栈深不能跨天。

第 14 课的证据删除仍有用，但对象变了。那里删除的是窗口里的一段 token，合格模型应改口“无法判断”。这里删除的是像素槽，合格系统应还能根据摘要知道“曾经有杯子”，并在颜色题上承认摘要可能过期，或者去看今日仍持有像素的那张图。把答红写成“无法判断”的反面，才算用对了证据删除的精神。

### 5.10 阅读器输入契约

写入和过期都对了，还可能在送进语言模型时把字段又焊死。阅读器输入必须是一张显式表，而不是“把仓库 dump 进 prompt”。本课要求每次查询至少送四行：

1. `entity_id` 与 `day`；
2. 摘要原文，不得改写后再送；
3. 框的四元组或空；
4. 像素槽状态：`present` 或 `expired`，若 `present` 则附上 $H,W$。

语言模型若只看见摘要，它没有权利声称看见了图。M3-Agent 把人脸节点的 `type` 标成 image，声音标成 audio，文本标成 text，检索工具可以按模态过滤。本课缩小成布尔 `has_pixels`。日志里 `has_pixels=false` 却输出“从图中可见杯壁是蓝色”，记为非法看见。第 16 课要求偏好优化必须真的看见媒体；本课要求颜色判断必须真的看见今日像素或今日改写过的摘要。两条纪律同构，媒体对象从一张当前图换成了一条隔夜记录。

送进窗口的 token 数和仓库字节是两笔账。摘要 36 字节进 UTF-8 字符串，进 tokenizer 之后可能是十几个 token，也可能因中英文混合变成别的数。本课 Gate 不看 token。有人用第 14 课的 4096 或第 45 课的 4096 来卡本课加载，属于拿阅读器预算冒充仓库上限。允许的做法是：仓库先按 16384 字节过滤，过滤后再把仍 `present` 的图送进阅读器，阅读器可以再用第 45 课的 token 预算做第二次裁剪。两次裁剪的顺序不能反。先按 token 丢掉今日图、再抱怨仓库超限，责任在阅读器，不在过期器。

MemGPT 的 FIFO 队列是阅读器侧的窗口，archival 是仓库。70% 警告发生在 FIFO，不发生在 archival。本课 $B_{\max}$ 发生在仓库。实现若把昨日摘要反复复制进 FIFO，窗口会满，仓库未必满。复制不是记忆，是泄漏。CPU 夹具里每条 `id` 只出现一次，禁止在过期后再 append 一条内容相同的新纪录来“刷新近因”。刷新近因应改 `last_access`，本课为了少一个字段，用 `day` 代替。加 `last_access` 是合法改造，但不得用它覆盖 `day`：访问昨日红杯子十次，不能让它在颜色题上赢过今日蓝杯子。

### 5.11 公式汇总页

把本课真正要手算的式子收在一页，便于实验笔记对照。

记录字节：

$$
B(r)=64+\mathrm{utf8}(r.\mathrm{summary})+16\cdot\mathbb{1}_{\mathrm{box}}+12288\cdot\mathbb{1}_{\mathrm{pix}}
$$

仓库合法：

$$
\sum_r B(r)\le 16384
$$

过期算子 $\mathrm{Expire}$：按 `(day, 写入序)` 升序，将 $\mathbb{1}_{\mathrm{pix}}$ 置 0，直到合法或没有像素。摘要字符串不变。

颜色阅读：

$$
\hat{c}(e)=
\begin{cases}
\mathrm{color}(r_{\min\mathrm{day}}), & \text{首写冻结}\\
\mathrm{color}(r_{\max\mathrm{day}}), & \text{改写}\\
\texttt{budget\_exceeded}, & \text{像素策略且}\sum B(r)>16384
\end{cases}
$$

夹具真值 $c^\star=\mathrm{blue}$。通过条件：冻结路 $\hat{c}=\mathrm{red}$，像素路超限，改写路 $\hat{c}=\mathrm{blue}$ 且过期后 $\sum B=12633$。

艾宾浩斯文本强度只作为对照，不进入 Gate：

$$
R=e^{-t/S}
$$

$S$ 初值 1，召回则 $S\leftarrow S+1$，$t\leftarrow 0$。它决定一条**文本**还在不在 MemoryBank 里，不决定一张图还占多少字节。把 $R$ 当作 $B_{\mathrm{pix}}$ 的折扣，单位错误。

## 6. 在公开实现中定位这些机制

本课没有 MiniMind-O 源码落点。对照按“写什么、扔什么、改写谁”三条看公开系统。读仓库时先搜 `flush`、`archive`、`summary`、`image`、`evict` 这些函数名，再决定它属于哪一课。搜到 `yarn` 或 `max_position_embeddings`，那是第 14 课。搜到 `pop` 和 `subgoal`，那是第 39 课。搜到 `recall@` 和视频分钟，那是第 45 课。搜到 `session_id` 加图像 blob 加日摘要，才轮到本课。四个关键词同时出现时，画一张对象表，不要把一个 git 仓库当成四课都已完成。

公开实现里还有一种假跨会话：把昨日对话存进 Redis，次日原样拼回 prompt。这只是把窗口搬到了磁盘上，payload 仍然是整段 token，没有分列，没有 $B_{\mathrm{pix}}$，也没有实体覆盖。LoCoMo 的长上下文臂已经证明：整段拼回去会在对抗题上乱说话。本课不把 Redis 当过期器。过期器必须能单独关掉像素列。Redis 里如果存的是 JSON 且 JSON 已经分列，那只是存储引擎换了，协议仍按本课的 $B(r)$ 算。引擎品牌不进 Gate。

**MemoryBank / SiliconFriend。** 仓库分三层文本：逐轮对话、日摘要、画像。检索是 DPR 式双塔，编码器可换成 MiniLM（英文）或 Text2vec（中文）。更新是 $R=e^{-t/S}$。表 2 说明检索准确率可以高于正确率：ChatGLM 英文检索 0.809，正确率只有 0.438。记性找到了，阅读器仍可能写错。本课把阅读器错误收成颜色：摘要被找到，颜色仍是红。心理对话 LoRA 是共情，不是记忆协议，不要把 38k 样本写成跨会话 payload 的证据。

**MemGPT / 后来的 Letta。** 主上下文分系统指令、working context、FIFO 对话。外部是 recall（全部历史消息）和 archival（任意文档）。70% 警告、100% 强制换页、递归摘要。嵌套 KV 超过 2 层时，作者报告只有 MemGPT 能稳定完成。这证明分页能做多跳查找，不证明分页知道该存像素还是摘要。working context 的人设块接近 MIRIX 的 Core；FIFO 接近 Episodic 的原始日志。图像在原文评测里不是一等公民。

**Generative Agents。** 记忆流全是自然语言。反思在累计重要度超过阈值时触发，把低层观察合成高层句子。这是摘要生成器，不是像素槽。作者在局限里写了 memory hacking：一段精心构造的对话可以说服智能体相信从未发生的事。跨会话系统若允许用户用一句话改写 Core，红杯子可以在没有新图的情况下变成蓝杯子。本课夹具禁止在没有 `day=1` 观察时改颜色。

**LoCoMo 流水线。** 每个说话人有人设、时间事件图、短时摘要、长时 observation。图像用 icrawler 按关键词下载，反应侧用 BLIP-2 生成 caption，caption 也写入长时记忆。问答和事件摘要实验把图像换成 caption。局限节承认：网图没有个人相册里的长期外观一致性，除 OCR 外用 caption 替换损失不大。这句话是本课的反例来源。红变蓝是外观变化，caption 若写成“一只杯子”就丢了颜色；若写成“红色杯子”又会首写冻结。LoCoMo 测的是超长对话理解，不是物体换色。数字可以引用，任务不能冒充。

**MA-LMM / MovieChat。** 视频内部记忆库。Q-Former 交叉注意里用视觉记忆当 K/V；查询记忆库存每一步的 learned query。压缩用相邻相似合并，不是按查询 Top-k。Breakfast / COIN 的 93.0 / 93.2 是长视频分类，不是隔夜问答。写相关工作时按“查询是否进入排序、会话是否关闭”归类。两者都是否，就不是本课。

**M3-Agent。** 在线处理视听流，生成情景记忆和语义记忆，存进实体中心的多模态图。人脸和声纹有独立节点，语义记忆负责声明 `<voice_i>` 与 `<face_j>` 是同一个人，用权重投票解决冲突。控制过程多轮检索，最多 5 轮。去掉语义记忆，robot / web / VideoMME-long 分别掉 17.1 / 19.2 / 13.1 个点。这套系统仍主要活在**一条长视频或一段连续任务**里，M3-Bench-robot 平均 2039.9 秒，不是 19.3 个跨日会话。本课借用它的两点：实体中心、语义与像素分列。不借用它的 RL 控制头，也不把 30.7 写成杯子颜色准确率。

**MIRIX。** 六类加 Meta Memory Manager。ScreenshotVQA 强迫系统在一个月的截屏上回答“我那天看了什么”。现成的 Mem0 / Letta 作者认为无法直接吃下这么多图。RAG 基线用 SigLIP 取 Top-50 再交给 Gemini；长上下文基线把图缩到 $256 \times 256$、最多大约 3600 张。MIRIX 不存原图，只存 sqlite 里抽出来的结构化字段，约 20 MB。这是“删像素留摘要”的产品级版本。代价也写在论文里：Resource Memory 才放文档全文，Core 超 90% 要改写。本课的 16384 字节是教学上限，对应他们 90% 改写阈值的精神：先有容量数字，再有扔什么的规则。

**PMMC。** 巩固期用 Questioner 生成未来可能的问题，Planner 编译取证程序，Doubter 真正执行一遍，通过的才进 Question Bank。查询时不再现场规划，只路由到冻结程序；失败则回退到多模态 RAG。去掉 raw-image access，视觉更重的 Mem-Gallery 掉 4.9 分。这是本课 Lab 的文献版：颜色题必须能物化原图或改写后的视觉字段，否则摘要仓库会看起来很自信。MEMLENS 原有 789 题，去掉 90 道拒答剩 699；Mem-Gallery 原有 1711 题，去掉冲突检测 81 和拒答 184 剩 1446。本课不引用被 HTML 转置打乱的逐模型格子，只引用正文宏平均 49.9 对最强基线 46.7。编译期 Questioner 的预算 $b=8$ 个前瞻问题、Planner–Doubter 最多两轮修订、程序最多八个算子，这些是他们的超参，不是本课 Gate。

**Mem0 与扁平事实库。** MIRIX 把 Mem0 写成把用户输入蒸馏成扁平事实、角色接近 Letta 的 archival。本课打开的是 MIRIX 对它的转述，Mem0 原文（arXiv:2504.19413）的表内分数未在本课逐格核对，禁止把 85.4% 记到 Mem0 头上。扁平事实库的机制风险可以直接说：没有 `pixels` 字段，颜色只能靠句子；没有 `day` 覆盖规则，旧事实和新事实并列。这和首写冻结是同一类 bug，不依赖 Mem0 的任何准确率。

**A-Mem。** MIRIX 对照里把 A-Mem 写成 Zettelkasten 式笔记加嵌入链接。本课不核它的 LoCoMo 分。笔记图能表达“杯子 属于 桌子”，不能默认表达“颜色 于 day=1 变为蓝”。缺时间戳的边，多跳很强，更新很弱。

定位时只抄你打开的句子。Qwen2.5-Omni 的 Thinker–Talker、TMRoPE、2 秒交错，服务的是当前会话的音视频对齐，其技术报告未公开跨会话记录 API。Moshi 是语音双工，与隔夜杯子无关。把这些系统画成一张“写 / 扔 / 改写”清单时，空格必须留空，不许用想象填。MemoryBank 的扔是文本强度；MemGPT 的扔是窗口换页；MA-LMM 的扔是相邻帧合并；MIRIX 的扔是不存原图；PMMC 的扔是查询时不物化未选中的程序。本课的扔是 `has_pixels=False`。五套扔法不能共用一个函数名 `evict()`。

## 7. 数据与记忆 recipe

跨会话系统的“数据”不是另一份 SFT parquet，是**写入策略**。recipe 要写清四件事：何时写、写哪一层、何时扔、何时改写。

**何时写。** 会话关闭是硬点。MemGPT 另有软点：70% 压力。MIRIX 的截屏应用每 1.5 秒拍一张，相似度 $>0.99$ 则丢弃，攒够 20 张唯一图就触发更新，大约每 60 秒一次。本课教学路径只保留硬点：`t_close` 必须 `flush`。软点可以当作改造实验，不能当成已经实现。

**写哪一层。** 给每条观察打一个最小模态集合。颜色、文字、细纹理进入像素槽或裁剪图。左右、大小、可点区域进入框槽。可检索的事实进入摘要槽。LoCoMo 把图像 caption 写入长时记忆，等于只走摘要槽；他们自己说除 OCR 外损失不大，那是因为网图没有“同一只杯子隔天换色”。家用场景不要抄这条假设。

**何时扔。** 先定 $B_{\max}$，再定扔的字段。本课扔像素。MemoryBank 按 $R=e^{-t/S}$ 扔整条文本。两种可以同时存在：文本用强度，图像用字节。禁止用强度去扔图像却不报释放了多少字节。

**何时改写。** `entity_id` 相同且新观察包含被查询属性时，覆盖摘要里的该属性，不要追加一句相反的话。LongMemEval 把 knowledge update 单列，就是因为追加型仓库会在“用户后来改口”上失败。杯子换色是视觉版的改口。

训练侧若你真的要微调写入器，预算单独记账。MemoryBank 的 LoRA rank 16、3 epoch、A100，训的是共情风格，不是过期器。M3-Agent 的 memorization 用 10752 条 30 秒片段做 SFT，control 用 DAPO，奖励是 GPT-4o 评判对则为 1 否则为 0。那是规模问题。本课机制问题是：SFT 之后，关会话时的 JSON 是否仍分列 `summary` / `box` / `pixels`。缺字段的 checkpoint 不算本课成功。Control 侧最多 5 轮检索、每轮 `search_clip` 返回 top-2，这些超参可以抄进笔记，不能抄进本课 Gate。Gate 只认颜色和字节。

合成对话可以当探测题生成器。MemoryBank 用 ChatGPT 扮演 15 个用户写 10 天对话，再人工写 194 题。LoCoMo 用事件图加人工修订，标注者改了约 15% 的轮次。本课允许你用 10 条自写对话当探测，不允许把自写对话的正确率写成 0.716。自写题必须标注：问的是颜色、位置还是存在性。颜色题不得用框策略通过。位置题不得因摘要含“红”而通过。存在性题在过期删像素之后仍应能靠摘要答“有过杯子”。三类题混成一个准确率，等于把第 31 课警告过的短程长程横着平均又做了一遍。

写入批次大小也要单独写。MIRIX 截屏路径攒 20 张唯一图再更新，用 Gemini 的 Cloud URL 流式上传，端到端延迟从 GPT-4 直接传图的约 50 秒降到 5 秒以下。这是工程数字，其技术报告式论文没有把 50 秒和 5 秒写成可复现表格的同一列条件，本课只借用“更新是批的，不是每帧都写完字段”。教学路径按会话关闭写一次。若你改成每分钟写一次，必须同时改 $B_{\max}$，否则一天 5886 张截屏会把像素槽打爆。ScreenshotVQA 第一位学生单日 5886 张，正是这种批量和上限的冲突来源。

## 8. 按依赖顺序执行实验

主路径无 GPU。顺序固定，后一步以前一步的字段名为前提。

### Step 0: 冻结三条夹具记录

打开 CPU 模块，确认 `SUMMARIES` 三句与 `TRUE_COLOR="blue"` 未被改成“都是红”。打印每条的 UTF-8 长度。昨日杯子必须是 39。改字之后，先更新笔记里的 $B(\texttt{cup\_day0})$，再跑后面的和。

```bash
python3 -c "from learn_omni_experiments.lessons.lesson_53 import SUMMARIES, utf8_bytes; print({k: utf8_bytes(v) for k, v in SUMMARIES.items()})"
```

### Step 1: 手算满配账单

对每条记录算 $64+B_{\mathrm{sum}}+16+12288$。三条相加，确认大于 16384。这一步不允许看 `run()` 的现成 `full_store_bytes`。算完再跑实验，对一下 `metrics["full_store_bytes"]`。对不上，先查 UTF-8，再查有没有漏框。

### Step 2: 跑过期

调用 `expire_pixels_keep_summaries`。断言：`has_pixels` 的真值个数小于 3；三句摘要字符串与输入完全相同；过期后字节 $\le 16384$。昨日两条的 `has_pixels` 必须为假，今日杯子必须为真。若今日也被删，说明排序键不是 `day`，或上限被改小到一张 64×64 图都装不下。

### Step 3: 三种答案

`answer_summary_only` 必须返回 `"red"`。`answer_pixel_only` 必须返回 `"budget_exceeded"`。`answer_hybrid` 必须返回 `"blue"`。三条和真值 `"blue"` 写在同一张表的四列里，不要把 `"budget_exceeded"` 记成颜色。

过期后的 12633 要拆开看：今日图 12404，两句无图像摘要 116+113=229。加载时若有人把昨日像素“顺便”再读回来，账单会跳回 37209，混合策略名存实亡。实现上过期必须写进持久化字段，不能只在本次进程的内存里置假。重启后 `has_pixels` 仍为假，才叫跨会话过期。

### Step 4: 浏览器先预测再揭晓

打开 `Lesson53SessionMemoryLab`。默认边长 64、额外记录 1、上限 16384。先选预测“只存摘要会答错颜色；只存原图像素会超预算”，再点揭晓。揭晓前不得从指标区读到答案或字节。Gate 要求摘要答红且像素超限同时成立。若你把上限拉到 49152，像素策略不再超限，Gate 保持红色，这是预期，把上限调回去。

### Step 5: 扫边长与上限（可选）

边长 32 时一张图 $32\times32\times3=3072$ 字节，三条满配可能低于 16384，像素策略不再爆预算。边长 96 时一张图 27648，已经单独超过上限，混合策略也会拒答。把这两点记成“参数组合必须能触发验收”，不要记成模型能力。

### Step 6: 文献对照（可选，有卡再做）

若有能跑 Gemini 或 7B VLM 的卡，用昨日红杯图、今日蓝杯图各一张，比较“只把昨日 caption 放进提示”和“把今日原图放进提示”。预期：前路答红或含“红”，后路答蓝。样本少于 25 只发逐例表。禁止把 2 张图的结果写成 MIRIX 的 +35%。

通过最低交付之后，允许加一条可选记录：把边长从 32 扫到 96、上限从 8192 扫到 49152，画出像素策略的 $B_{\mathrm{store}}(H)$ 何时穿过 $B_{\max}$。预期 $H=64$、三条记录时已经穿过；$H=32$ 时可能在 16384 之下。这条曲线给自己看，不写进对外的“论文复现”。

出现以下任一情况，实验无效：揭晓前能看到答红；把 Lab 的蓝色写成 LoCoMo 人类 87.9；把超预算写成视觉编码器坏了；把第 45 课的 4096 token 当成本课 16384 字节；过期后摘要原文与 `SUMMARIES` 不一致仍标通过。

CPU 跑通后应能直接读到这些 `metrics` 字段：`full_store_bytes=37209`，`expired_store_bytes=12633`，`expired_pixel_count=1`，`summary_only_answer=red`，`pixel_only_answer=budget_exceeded`，`hybrid_answer=blue`。字段名以模块为准。自己重写过期器时，只要这六个数还在，就没有改题。少一个字段，等于少一条可复核命题。

## 9. 评测与测量

跨会话记忆至少要分四列报，禁止合成一个“记忆分”。

| 列 | 测什么 | 本课夹具 | 公开数字只能对照不能顶替 |
|---|---|---|---|
| 账单 | $B_{\mathrm{store}}$ 与 $B_{\max}$ | 满配 37209，过期后 12633 | MIRIX sqlite ~20 MB vs SigLIP 22.55 GB |
| 颜色 | 属性是否跟随最新观察 | 摘要红、混合蓝 | PMMC 去原图 Mem-Gallery −4.9 |
| 召回 | 相关记录有没有被取到 | 三句摘要过期后仍在 | MemoryBank 表 2 检索 0.763 / 0.809 |
| 阅读 | 取到之后有没有用对 | 检索高仍可能答红 | ChatGLM 检索 0.809 对正确率 0.438 |

LoCoMo 还拆了 single-hop、multi-hop、temporal、open-domain、adversarial。时间题和对抗题最伤长上下文。本课不把五类做成题库，但报告里要声明：颜色题属于 knowledge update，不属于 single-hop 事实查找。把答蓝写成“检索成功”是错列。

LongMemEval 的拒答是第五项。摘要仓库在没看见今日杯子时，合格行为是“我只记得昨天是红的，今天没看过”，而不是编一个确定的蓝。夹具里的摘要策略答红，是错误的确定，不是拒答。两者不要兑成一个准确率。

M3-Bench 的题型（多证据、多跳、跨模态、人物、常识）服务的是长视频智能体。人物理解依赖实体中心图，和本课 `entity_id` 同构，但视频还没关。引用 30.7 时必须写 M3-Bench-robot、相对哪一个 hybrid 基线。缺一项就删掉该数字。

测量时的时间轴也要分列。写入时延是 `flush` 的墙钟，查询时延是路由加物化。PMMC 把编译成本摊到 $n$ 次未来查询上：

$$
\overline{C}_{\mathrm{PMMC}}(n)=\frac{C_{\mathrm{compile}}}{n}+C_{\mathrm{online}}
$$

他们在 Qwen3.5-9B 上报告：相对 M3-Agent 与 M2A，写时开销大约两次查询就能摊平；相对 Native MM-RAG 约十二次；相对 Caption-Text RAG 约十八次。本课不测这两笔延迟，避免用笔记本上的 `time.time()` 冒充他们的千 token 账单。能抄的只有公式形状：有一笔巩固期成本，必须靠多次查询回收。一天只问一次颜色的杯子助手，PMMC 的编译可能比直接存三句摘要更贵。本课混合策略没有编译期 LLM，回收问题不存在，代价是不会预判“明天会问颜色”。两种成本模型不要写进同一格。

拒答要单列。LongMemEval 把 abstention 列为五项之一。摘要策略在本课夹具里答红，是假确定。像素策略返回 `budget_exceeded`，是真拒答。混合策略答蓝，是真确定。把假确定和真拒答平均成一个 F1，会让“经常超限的像素仓库”看起来比“总是答红的摘要仓库”更差，而在颜色题上前者至少没有说谎。报告里分成三行：正确确定、错误确定、拒答。LoCoMo 的对抗题期望模型识别不可答；长上下文 16k 在这类题上掉到 2.1%。跨会话系统同样会被问“我从没买过的杯子是什么颜色”。仓库里没有 `desk_cup` 时，应拒答，不应引用昨日红。CPU 夹具没有第四条“不存在的实体”记录，改造实验第 3 条的 FIFO 删除可以拿来造拒答：整条删掉昨日杯子后，若阅读器还输出红，就是在凭空说话。

## 10. 根据症状定位失败环节

| 症状 | 先查 | 不要先做 |
|---|---|---|
| 今日答红 | 摘要是否首写冻结，`max(day)` 有没有参与 | 加窗口到 128K |
| 三条图就 OOM 或拒答 | $H \times W \times 3$ 与 $B_{\max}$ | 换更大的 VLM |
| 过期后连“有过杯子”也不知道 | 是否整条 FIFO 删除 | 加大 $S$ |
| 检索分很高，颜色仍错 | 近因是否偏向旧的高频红杯子 | 微调编码器 |
| 框很准，颜色仍错 | 查询是不是外观题 | 加密框的 IoU 阈值 |
| 答蓝但日志没有今日像素 | 是否只是语言模型猜常见颜色 | 加温度 |
| 栈 pop 之后仍答红 | 第 39 课的栈不含隔夜记录 | 在本课里改 $R_{\max}$ |
| 选了中间层仍答红 | 第 45 课的带子不是昨日会话 | 重训 CLIP |
| 截屏系统 20 MB 却答不出颜色 | Resource / 像素槽有没有今日图 | 把 20 MB 当成已经看见 |

再补一组和公式直接相关的症状。$B_{\mathrm{store}}$ 永远小于 $B_{\max}$：检查像素槽是不是被写成了 0，或 $H$ 被改成 1。$B_{\mathrm{store}}$ 永远大于上限且过期不降：检查 `has_pixels` 有没有真正置假。摘要 UTF-8 长度随中文标点跳动：检查是不是用了 `len(s)` 当字节。混合策略答红：检查改写是不是插入了第二条记录却仍按 `min(day)` 读。这些检查只需要打印三行记录和一行总和，不需要再下 LoCoMo。

第 07 课的 `CONTINUE` / `PAUSE` / `REPLAN` 在跨会话里也有对应物：沿用昨日摘要是 CONTINUE，超限先不加载像素是 PAUSE，改写实体并丢掉旧图是 REPLAN。不要把语音路由代码抄过来，只借用状态名，见[第 07 课](07_full_duplex_routing.md)。已经写入磁盘的错误摘要相当于已经播放的 PCM：过期器可以不再加载它的像素，不能假装那句话没写过。审计日志里昨日“红色杯子”仍应在，今日答案跟 `max(day)`。

## 11. 交付物

- 一份公式页：$B(r)$、$B_{\mathrm{store}} \le B_{\max}$、过期只清像素、$\hat c = \mathrm{color}(r^\star)$、$r^\star$ 取同一实体的最大 `day`；
- CPU 实验 `lesson_53.py` 的 `checks` 全通过记录；
- 交互实验状态：预测选项、边长、额外记录、上限、摘要答红、像素超预算、混合答蓝；
- 一张对照表：MemoryBank / MemGPT / LoCoMo / MIRIX / M3-Agent / PMMC / MA-LMM 各改窗口、栈、检索层还是跨会话 payload，数字带来源；
- 明确声明：未复现 SiliconFriend 0.716、MIRIX 85.4、M3-Agent 30.7。

交付物不要求检索延迟漂亮。要求能从一次错误颜色反推：读的是哪一条记录、`day` 是多少、像素槽还在不在、字节有没有超过 16384。这一条和第 01 课的 trace 纪律同类，只是对象从 codec 编号换成了跨会话 payload。做不到反推的实验，即使生成文本流畅，也不算本课交付。交付检查可以缩成三问：payload 选了哪一种，昨日红有没有被今日蓝覆盖，三条原图有没有超过上限。三问都答得出，公式页和 Lab 记录才有地方挂。三问答不出，后面的文献表只是装饰。把这三问抄进实验笔记的页眉，每次改边长或改上限都重答一遍。页眉还要记下当天使用的摘要原文哈希，免得两天之后分不清“红色杯子”来自哪一次改词。哈希缺失的对照表，下一节评测一律视为无效。有效的对照表至少能让别人按哈希把同一三句摘要和同一套 $H,W$ 重新跑出 37209 和 12633。做不到这一条，就还没有完成最低交付。

对照表的列名也要冻住，避免和文献表抢格子。推荐七列：系统名、对象（窗口 / 栈 / 检索层 / 记录）、payload 分列与否、过期删什么、覆盖键、公开数字、本课是否复现。MemoryBank 填记录、文本三层、按 $R=e^{-t/S}$ 扔文本、无 `day` 覆盖、表 2 的 0.716、不复现。MemGPT 填窗口加外部库、文本、100% 换页、working context 改写、嵌套 KV 超过 2 层、不复现。LoCoMo 填评测、caption 可替换图、无、事件图、87.9、不复现。MIRIX 填记录、六类、不存原图、Core 90%、+35% / 85.4%、不复现。PMMC 填记录加程序、可物化原图、巩固期编译、路由阈值 0.60、49.9、不复现。本课夹具填记录、三槽、删像素、`max(day)`、37209 / 12633 / 红 / 蓝、复现的是这一行。七列缺“本课是否复现”，数字就会回流到标题。

## 12. 前沿对照与改造方向

**公开方案。** 同一问题，2023–2026 年的公开系统分成五条路。文本分层：MemoryBank 的对话 / 日摘要 / 画像，MemGPT 的 working / recall / archival，MIRIX 的六类。分页操作系统：MemGPT 的 70% / 100% 与递归摘要。超长对话评测：LoCoMo 的 35 会话与 LongMemEval 的五项能力。多模态实体图：M3-Agent 的人脸–声音节点加语义记忆。巩固期编译：PMMC 把“以后可能问什么”提前算成可执行程序。五条路都没有取消 payload 选择。Qwen2.5-Omni / Qwen3-Omni 的公开技术报告未给出与本课同构的跨会话像素槽 API。Moshi 是语音全双工，与隔夜杯子无关。不要把 Omni 的听说话写成已经会在明天认出杯子换了颜色。

LoCoMo 的一条负结果要单独对照，避免把它误写成“摘要检索已经够了”。会话摘要的 Recall@10 可以到 90.7，问答整体 F1 只有 31.5，接近不检索的 29.9。observation（对说话人生活的断言）在 top-5 时整体 F1 41.4，时间题 41.9，明显好于摘要。对话原文 top-25 的整体 F1 是 35.8，时间题只有 26.2。摘要路 Recall 最高，时间题却更差。本课的混合策略对应 observation 加有上限的原图，不对应 session summary。谁把 90.7 的召回写成颜色已经对，列又混了。

基座对照再抄一组，避免只记住人类 87.9。Mistral-Instruct-7B 在 8K 窗口上整体 10.2；Llama-2-Chat-70B 在 4096 上 19.7 / 14.4（表 2 第二列被 HTML 折行，引用时以你打开的 PDF 为准，本课正文因此只采用作者在第 6.1 节用句子写出的 GPT-4-turbo 整体 32.4 对人类 87.9，以及长上下文对抗题 2.1%）。不确定的格子不写。能确定的机制是：截断窗口会丢跨会话证据；拉长窗口会在对抗题上乱说话；检索 observation 比检索摘要更利于时间题。本课夹具把“乱说话”收成答红，把“丢证据”收成超限拒答。

ScreenshotVQA 三位学生的题量和截屏量也值得单独列，避免把 35% 当成单点。第一位一天 5886 张、11 题；第二位 20 天 18178 张、21 题；第三位一个月以上 5349 张、55 题。题不是均匀分布在时间上的。一天打满 5886 张时，像素仓库的压力来自频次；一个月 5349 张时，压力来自跨度。本课三条记录模拟的是跨度：两个自然日加一张便签。频次要用 Lab 的“额外旧记录”滑条去造。额外记录从 1 加到 4，满配张数从 3 到 6。边长 64 时六张 $6\times12404=74424$，远远超过 16384。这是 ScreenshotVQA 第一位学生那种单日洪峰的缩小版。不要把滑条最大值写成 18178。

MIRIX 相对长上下文的关键证据是：把一个月截屏塞进 Gemini 时必须缩到 $256 \times 256$，准确率接近 0 到 0.25；结构化记忆约 20 MB，整体更高。本课把这笔账写成删像素：缩分辨率是另一种丢外观，结构化字段若不含颜色，仍会答红。谁把 20 MB 写成“已经看见原图”，请他出示今日像素槽是否非空。

PMMC 相对固定 RAG 的关键证据是：去掉 raw-image access，Mem-Gallery 掉 4.9 分，MEMLENS 只掉 2.3 分。视觉更重的基准对原图更敏感。本课 Lab 的红蓝杯子属于 Mem-Gallery 那一侧。Caption-Text RAG 在他们的表里可以很强，仍不能代替原图访问。本课不引用表 1 里被 HTML 转置打乱的逐模型格子，只引用摘要和正文里的 49.9 对 46.7、以及消融表的 4.9。

**差距。** 规模差距：一个月截屏、50 段人工修订对话、500 道 LongMemEval、M3-Bench 的 1020 段视频、H100 上的 PMMC 编译，钱能堆。机制差距：记录分列、字节上限、过期只删像素、同一实体按 `day` 覆盖，本课能做。评测差距：LoCoMo 人类 87.9 和本课一只杯子之间的洞，不是再调一个 UTF-8 长度能填的；那是多会话、多跳、时间、对抗、图像分享，交给第 47 课已经铺过的评测总表去登记，不要在本课用玩具颜色冒充。

规模与机制再拆一次，避免验收会上被问“为何不直接上 MIRIX”。MIRIX 的 99.9% 存储下降来自不存 2K–4K 原图，改存 sqlite 字段；本课 37209 到 12633 来自丢掉两张 64×64 图。方向相同，差了三个数量级，而且 MIRIX 的字段里不一定还有可逆的颜色通道。M3-Agent 的 −17.1 来自去掉语义记忆，本课没有训练语义头，不能说“我们复现了 −17.1”。PMMC 的 4.9 分来自去掉原图访问，本课用答红来模拟同一方向。能声称的只有方向。谁把数量级或百分点抄进夹具标题，规模与机制又焊死了。

Qwen 系 Omni 的差距单独写。Qwen2.5-Omni 报告了 Thinker 出文本、Talker 消费隐表征、音频 16 kHz、TMRoPE、2 秒交错、seed-tts-eval 的 WER 1.42% / 2.33% / 6.54%。这些数字全部属于当前会话的听说话。跨会话杯子颜色其技术报告未公开。把 WER 填进本课 Gate，列错。Qwen3-Omni 同样未给出像素槽 API。对照它们时只问一句：关会话之后，外部存储的 schema 在哪一节。没有这一节，就还是窗口模型加产品侧的聊天记录，不是本课的记录 $r$。

**改造实验。**

1. 把 CPU 夹具的今日摘要改成“杯子还在桌上。”不含颜色字。预算：改一个字符串，数分钟。预期：混合策略不再答蓝，必须走像素槽才能对。失败：不含“蓝”仍返 `blue`。
2. 在 Lab 里把边长固定为 64，扫描上限从 8192 到 49152，记录像素策略何时不再超限。预算：拖滑条，不训练。预期：上限越过 $37209$ 之后，像素策略突然答蓝。失败：答案与上限无关。
3. 给过期器加一条非法对照：FIFO 整条删除昨日杯子。预算：在 CPU 实验里加十行。预期：摘要列表变短，颜色题若再读首条会变成便签或未知。失败：整条删除后摘要计数仍为 3。
4. 若有 1×24GB：用同一对红/蓝杯图，比较“只注入昨日 caption”“只注入昨日原图”“注入今日原图”。预算：单卡若干小时，20 对图。预期：前两路答红或拒答，第三路答蓝，且前两路的加载字节低于第三路。失败：三路答案完全一致且字节相同。样本不够 25 只发逐例表。

**顺手复现映射。** LoCoMo 摘要高召回低 F1 对应本课首写冻结：句子能被搜到，属性已经过期。PMMC 去原图掉点对应 Lab 的像素槽：颜色题没有图就失败。MemoryBank 表 2 检索高于正确率对应“找到了昨日记录仍答错”。MIRIX 的 99.9% 存储下降对应过期删像素，方向相同，数量级不同。LongMemEval 的 knowledge update 对应 `day=1` 必须覆盖 `day=0`。这些映射全部是方向性的。谁把 85.4% 写进自己的三记录玩具报告，就算评测造假。

改造实验的失败判定再补两条公共规则。任何一次 GPU 推理都要保存：权重哈希、写入的 payload 类型、`entity_id`、字节、颜色输出。缺哈希或缺 payload 名的结果不能进对照表。任何一次声称“混合更好”的比较，必须在同一上限、同一对红蓝图、同一查询上完成；换了 caption 模型就不能把差值记在过期器上。

## 13. 论文与必读材料

阅读时带着括号里的问题。数字以你打开的版本为准；本课引用的是下面列出的版本。

1. MemoryBank: Enhancing Large Language Models with Long-Term Memory（arXiv:2305.10250，Zhong 等）。带着问题读：对话、日摘要、画像三层各存什么？$R=e^{-t/S}$ 里 $S$ 何时加一？表 2 中 ChatGPT 与 ChatGLM 的检索准确率和正确率为何一高一低？
2. MemGPT: Towards LLMs as Operating Systems（arXiv:2310.08560，Packer 等）。带着问题读：主上下文、recall、archival 如何对应内存和磁盘？70% 与 100% 各触发什么？嵌套 KV 超过 2 层时作者声称谁能完成？
3. Generative Agents: Interactive Simulacra of Human Behavior（arXiv:2304.03442，Park 等）。带着问题读：记忆流对象有哪些字段？近因、重要度、相关度如何合成？memory hacking 在局限里指什么？
4. Evaluating Very Long-Term Conversational Memory of LLM Agents（arXiv:2402.17753，Maharana 等）。带着问题读：表 1 的 304.9 / 19.3 / 9209.2 相对 MSC 放大了多少？人类 87.9 对照哪一列模型？为何 session summary 的高召回没有变成高 F1？图像换成 caption 的前提是什么？
5. LongMemEval: Benchmarking Chat Assistants on Long-Term Interactive Memory（arXiv:2410.10813，Wu 等）。带着问题读：五项能力分别是什么？约 30% 的掉点发生在哪类持续交互？indexing / retrieval / reading 三阶段本课各对应哪条协议？
6. MA-LMM: Memory-Augmented Large Multimodal Model for Long-Term Video Understanding（arXiv:2404.05726，He 等）。带着问题读：视觉记忆库和查询记忆库谁进交叉注意、谁进自注意？MBC 合并的是相邻帧还是按查询排序？为何它不能当隔夜仓库？
7. MIRIX: Multi-Agent Memory System for LLM-Based Agents（arXiv:2507.07957，Wang 与 Chen）。带着问题读：六类记忆各保什么？ScreenshotVQA 的 35% 与 99.9% 对照的是哪两个基线？Core 90% 改写和本课 $B_{\max}$ 有何同构？
8. Seeing, Listening, Remembering, and Reasoning: A Multimodal Agent with Long-Term Memory（arXiv:2508.09736，Long 等）。带着问题读：情景记忆和语义记忆各写什么？去掉语义记忆的 −17.1 / −19.2 / −13.1 出现在哪些基准？实体图如何把人脸和声音绑在一起？
9. PMMC: Prospective Multimodal Memory Compilation for Long-Term LVLM Agents（arXiv:2608.00962，Sun 等）。带着问题读：Questioner / Planner / Doubter 谁在巩固期跑、谁不许在查询时跑？去掉 raw-image access 为何 Mem-Gallery 比 MEMLENS 掉得更多？49.9 对 46.7 是哪一种平均？

[第 20 课](20_unified_understanding_generation.md)讨论的是图像理解与生成能否共享骨干。本课共享的是记录接口，不是 flow matching 的速度场。下一课规格指向合成数据该补分布还是只加条数。本课的写入器只要求在关会话时把字段写全，不要提前把 MimicGen 的轨迹混合写进来。本课停在这里：跨会话先选定 payload；只留摘要会把昨日的红写进今日答案，只留原图会打穿字节上限。窗口、栈、检索层、调度，都还在别的课里。若你现在就把“记忆”理解成“模型已经看过所有历史图”，回到第 8 节的四列指标，把账单和颜色再读一遍。机制成立，能力边界仍然很窄。把这条边界写进实验报告的第一页，比把 85.4 抄进标题更有用。读者应能在读完本课后独立复述：会话关闭后窗口不是仓库；摘要会冻结昨日属性；像素按 $H \times W \times 3$ 收费；过期必须留下摘要；同一实体按最大 `day` 覆盖。能复述这五句，并且 CPU 实验八条检查为真，本课就收工。交互实验还要留下一次先预测后揭晓的记录，证明你没有对着已经显示的答红去选预测。三项齐了，再去碰公开仓库也不迟。公开仓库只能检验同一套 payload 选择在真实多会话上是否还分得开，不能回头否定玩具里已经核对过的那套字节公式和过期顺序。答题流畅是生成口径，玩具字节和颜色是协议口径，两套数字不要写进同一格。把协议口径写进报告第一页的人，才有资格在第二页讨论 85.4 和 30.7 为什么比玩具难。第一页都写不清 37209 从哪来，第二页的文献只是装饰。
