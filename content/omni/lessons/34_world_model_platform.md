# 第 34 课：世界模型当数据引擎还是当控制器

> 内容：世界基础模型当合成数据源，还是当滚动执行的预测器<br>
> 建议周期：阅读约 75 分钟；CPU 实验数分钟<br>
> 硬件：无 GPU 可读完全文并跑 CPU 机制实验；复现 Cosmos / Genie 论文规模需要多机多卡与大规模视频<br>
> 产物：物体 ID 计数器、重力符号探针、数据引擎 / 控制器两张门禁表、文献数字表

## 1. 世界模型当数据引擎还是当控制器

第 33 课问的是预测对象：未来像素，还是未来表征。本课换一个更靠后的问题：就算你已经能预测，这份预测拿去干什么。NVIDIA 的 Cosmos 把世界基础模型（world foundation model, WFM：用视频学习物理世界下一步会怎样的通用模型）写成平台，主用法是先预训练一个通才，再后训练成相机可控、操作或驾驶专用的生成器，给别人当合成数据。V-JEPA 2 的动作条件后训练（V-JEPA 2-AC）则把预测器接进规划，在两间实验室的 Franka 上做零样本抓放。Genie 从无标签视频里学出潜伏动作，人可以逐步“玩”生成环境，也可以拿潜伏动作去标专家视频。三件事都叫世界模型，评价标准不是同一张表。

要改的模块是评价协议，不是再训一个视频生成器。数据引擎看两件事：生成视频的保真，以及物理违规率。控制器看另一件事：用预测选动作之后，真实世界里的滚动执行误差。Cosmos 自己在 Limitations 里写明，当前模型包括他们在内，还不能当可靠的物理世界仿真器；他们观察到的问题包括缺少物体永久性（object permanence：被挡住或短暂离开视野的物体，下一帧还应在）、接触丰富动力学不准、指令跟随不稳定，以及生成视频的真实感并不总遵守重力、光照和流体。本课把这两类失败写成可执行探针：跨帧物体 ID 计数器，以及自由下落的速度增量符号。浏览器教具用落下的方块加水平动作，夹具保证你会看到物体消失或重力方向错误。CPU 实验核对手算。两类数字都不得写成真机成功率。Lab 揭晓前左右两屏走同一条干净积分，就是为了让你先下预测、后看探针，而不是对着已经消失的方块补理由。CPU 实验没有界面，所以它把干净、消失、翻转三条轨迹同时算完，用 `checks` 代替揭晓按钮。两条路径测的是同一对公式，只是一个要你先说话，一个要机器先对账。

用一段 8 帧、3 个方块的具体过程，把两种产品钉在同一条时间轴上。$t=0$ 时三个 ID 都在画面上方，竖直速度为 0。$t=1$ 时你给它们一个水平速度 $a_x$。数据引擎要交出的是 $t=2$ 到 $t=7$ 的视频：每个 ID 还应在，$\Delta v_y$ 应与 $g$ 同号，水平位移应随 $a_x$ 变大。控制器要交出的是一个动作：根据预测的落点，决定 $a_x$ 往左还是往右，然后在真实积分里看离目标 $x=1$ 有多远。若生成器在 $t=4$ 把 ID 2 吃掉，数据引擎应拒收这段视频；若预测器把 $g$ 取反，控制器选到的符号会反，真实落点会跑到目标对面。Lab 的夹具就是把这两件事强制做出来。你若在 $t=7$ 只截一张“看起来在往下掉”的图，两种失败都可以藏进去：消失发生在中间帧，重力反号发生在速度列，单张图都看不见。

把这条 8 帧再拆成必须记录的六个字段，写进实验笔记就不会和观感混淆。$t_{\mathrm{cond}}$ 是条件帧结束的时刻；$t_{\mathrm{act}}$ 是动作注入的时刻；$t_{\mathrm{miss}}$ 是某个 ID 第一次从集合里消失的时刻；$t_{\mathrm{alarm}}$ 是 $\Delta v_y$ 第一次反号的时刻；$t_{\mathrm{eval}}$ 是计算捕捉误差的最后一帧；$t_{\mathrm{report}}$ 是你决定把数字写进哪张表的时刻。本课只要求 $t_{\mathrm{miss}}$ 和 $t_{\mathrm{alarm}}$ 能从日志里读出来，以及 $t_{\mathrm{report}}$ 不得早于你填完两张门禁表。$t_{\mathrm{cond}}$ 过短时加速度估不准，那是 Cosmos 表 20 里 1 帧条件 IoU 更低的原因。这里先留下六个名字，避免把“第 4 帧很好看”误当成“第 4 帧 ID 还在”。好看是像素距离，ID 是集合差，加速度是速度差。三件事可以同时成立，也可以只成立一件。只成立一件时，对外只能报那一件。

本课术语：

| 术语 | 简要解释 |
|---|---|
| 世界基础模型 / WFM | 用大规模视频预训练、再后训练到具体身体上的通用世界模型 |
| 数据引擎 | 生成物理视频或轨迹，给政策、视觉或操作模型当训练数据 |
| 控制器 | 用世界模型的预测来选动作，再在真实或仿真环境里执行 |
| 物体永久性 | 已出现的物体不应无故消失或凭空出现 |
| 重力符号探针 | 自由下落时 $\Delta v_y$ 必须与真重力同号，否则报警 |
| 动作条件视频 | 下一帧同时依赖过去观察和当前扰动 $c_t$ |
| 潜伏动作 | 没有动作标签时，从相邻帧差里学出的离散控制码 |
| Mixture-of-Transformers / MoT | Cosmos 3 里推理塔和生成塔分参数、在注意力处会合 |
| Physics-IQ | 用真实物理续拍当参照，给生成续帧打 0 到 100 分的基准 |

第 20 课的图像生成是单张图的速度场，见[第 20 课](20_unified_understanding_generation.md)，不是逐步可玩的世界。第 09 课处理视频时间轴，见[第 09 课](09_native_video.md)，不管物体会不会消失。第 31 课禁止把仿真成功率横着写成真机能力，见[第 31 课](31_vla_evaluation.md)；本课把这条纪律接到世界模型的两种用法上。

## 2. 本课解决的问题

看起来像物理的视频，有三条常见出路。一条是当数据：把生成片段写进别人的训练集。一条是当仿真器：让政策在模型里试动作，再挑一条执行。一条是当交互环境：人逐步输入动作，看下一帧。Cosmos 1 的论文把前两条都写进了“Future Cosmos”，同时声明该文没有给出把 WFM 接到政策评估、政策初始化、强化学习、模型预测控制上的实验结果。它实际交付的是预训练 WFM、后训练样例、tokenizer 和护栏。Genie 交付的是可玩环境和潜伏动作。V-JEPA 2-AC 交付的是规划。把三条出路的数字抄进同一格，就是在说“视频好看等于会控臂”。

Current Cosmos 和 Future Cosmos 的分界，值得单独抄一遍。第 2.2 节画出来的平台包括：视频整理管线、因果 tokenizer、预训练 WFM、后训练样例、护栏。第 2.1 节的 Future Cosmos 则是政策评估、政策初始化、政策训练、规划、合成数据。合成数据是唯一一条已经用后训练样例部分兑现的出路：相机条件、指令条件操作、多机位驾驶，都是在生成视频。政策评估和规划在该文没有实验。Cosmos 3 把政策列进了表 1 的后训练变体，那是另一篇报告、另一套数字，不能回溯改写 2501.03575 的“该文没有实证”。读平台论文时，先问“这一节的虚线是愿望还是表格”。愿望可以列，表格才能进本课的禁止合并表。

后训练样例本身也要按产品形态再拆。相机条件模型让用户在生成世界里移动视点，它更接近可导航的数据引擎，不是机械臂控制器。指令条件操作模型预测未来视频是否与语言指令一致，人工评的是视频质量维度，不是夹爪是否合上。驾驶多机位模型给驾驶智能体提供视觉，仍是数据。只有当你把预测接进动作选择、并且在真实或独立仿真器里执行，才进入控制器表。Cosmos 3 的前向动力学、逆向动力学、政策三种加噪模式，就是在同一骨干上切换这张表。加噪模式变了，成功谓词必须跟着变。用前向动力学的视觉 IoU 去给政策打分，等于用数据引擎的尺子量控制器。

本课同时卡住三个互相依赖的问题。

第一，预测方程写的是什么。Cosmos 把 WFM 写成 $\hat x_{t+1}=\mathcal{W}(x_{0:t},c_t)$。$x_{0:t}$ 是 RGB 视频，$c_t$ 可以是动作、随机扰动或文本。扩散家族用连续 token 去噪；自回归家族用离散 token 按顺序预测。Cosmos 3 再把语言、图像、视频、音频、动作收进同一套 MoT，按输入输出配置切换成视觉语言模型、视频生成器或世界-动作模型。Genie 没有真值动作，用 $|A|=8$ 的向量量化码本当潜伏动作。方程右边的条件变了，左边仍是未来观察。不要把条件种类不同的模型，当成已经解决了同一件控制问题。

第二，物理违规怎样变成门禁，而不是观后感。Cosmos 1 用 PhysX 和 Isaac Sim 做了八类刚体场景：自由落体、斜坡、U 形坡、稳定堆叠、不稳定堆叠、多米诺、跷跷板、陀螺，共 800 段 1080p、100 帧、四机位视频。定量结果写在表 20，用 PSNR、SSIM、DreamSim 和平均 IoU。他们随后明确写出，刚体仿真已经够用来抓失败：物体不永久性（自发出现和消失）、形变、不可信运动学、违反重力。Limitations 再次承认缺少物体永久性和重力等基本物理。这些句子可以引用。该节没有给出“物体消失百分之几、重力反号百分之几”的表，本课就不编。教学上把消失写成 ID 集合差，把重力写成 $\operatorname{sign}(\Delta v_y)$。

第三，数据引擎的好分数，为什么不能给控制器用。表 20 里 Cosmos-Predict1-7B-Video2World 在“prompt + 9 帧”条件下 PSNR 21.06、平均 IoU 0.592，高于 1 帧条件的 17.34 和 0.332。更大的 14B 在同一表上并未全面更好。作者的观察是：更大模型画面更好看，各 WFM 在物理符合度上同样吃力。Physics-IQ 上 Cosmos3-Super 的图像到视频直出分是 43.8，加 WMReward 和 best-of-N 到 48.9；视频到视频直出 59.7，加 rerank 到 63.4。这些是生成续帧和真实物理续拍的接近程度，不是 Franka 上的抓取成功率。Cosmos 3 后训练政策在表 1 的 Policy: Robot 一列，Nano 为 39.7（星号表示后训练变体），对照 $\pi_{0.5}$ 的 28.1。那一列才接近控制器。把 48.9 和 39.7 相减，没有物理意义。

失败条件预先写死：

- 只报 FVD、PSNR 或人工“看起来像”，不报物体 ID 丢失和重力符号；
- 把 Cosmos Limitations 里承认的失败，改写成已经解决；
- 把表 20 的 IoU 或 Physics-IQ 的 43.8 写成真机抓取；
- 把 Genie 可玩平台跳跃，写成已经会控机械臂；
- 把教学 Lab 的捕捉误差写成 V-JEPA 2 或 Cosmos 3 的机器人数字。

## 3. 开始前需要准备什么

本课不依赖 MiniMind-O 的训练脚本。需要的是第 09 课那种“视频有时间轴”的直觉，以及第 33 课“像素重建和表征预测损失不同”的对照。没有读过第 33 课也可以往下走，但遇到“画面清楚、杯子却消失”时，不要在本课里重做 JEPA。本课假定预测器已经存在，问它的产品形态。

开始前把笔记本分成两栏。左栏只抄打开过的论文句：模型名、表号、条件帧数、Physics-IQ 分、失败模式的原文措辞。右栏写本课约定：坐标系 $y$ 向下为正、$g>0$ 时 $\Delta v_y>0$、Lab 固定 8 帧 3 个物体、生成路夹具丢掉 2 号、控制路夹具把预测重力取反。左栏可以对外引用，右栏只能当教学夹具。有人把 Lab 里 2 号消失写成“复现了 Cosmos 表 20 的 IoU”，属于把右栏抄进左栏。

硬件上，读完加 CPU 实验不需要 GPU。若要跑 Cosmos-Predict1 或 Cosmos 3 的公开权重，再准备能放下对应生成模型的显存；其技术报告未把“单卡就能逐步交互”写成可复现的最低配置。Genie 选择不发布权重、训练数据和样例。没有这些卡，跳过可选的公开权重步骤仍可完成最低交付。软件上只需要 Python 3.10 标准库和能打开本课页面的浏览器。不要为了本课新装 Isaac Sim 或 PhysX，八类刚体场景只在课文里引用。

**上游事实（打开原文核对过）：**

- Cosmos World Foundation Model Platform（arXiv:2501.03575，NVIDIA，v3 2025-07-09）。权重与代码入口 [NVIDIA Cosmos-Predict1](https://github.com/nvidia-cosmos/cosmos-predict1)，NVIDIA Open Model License；

- V-JEPA 2（arXiv:2506.09985）只作为控制器对照：互联网视频超过 100 万小时，Droid 上不到 62 小时无标签机器人视频做动作条件后训练，两间实验室 Franka 零样本抓放，无任务特定奖励。像素对表征的机制留给第 33 课。

**课程约定：**

- 浏览器里的左右两屏是教学模拟，轨迹由匀加速公式算出来，不是 Cosmos 或 Genie 的前向输出；
- CPU 实验只证明 ID 计数器和符号探针可复核，不证明 Physics-IQ 或真机；
- $y$ 向下为正，与教具屏幕坐标一致。机器人相机若 $y$ 向上，必须在探针之前写清外参，不能假装“重力方向”是通用的。

若只想核对公式，准备 Python 3.10 和本仓库 `experiments/` 即可。CPU 实验不读网、不写文件、不用 NumPy，跑完只在内存里留下一个字典。不要为了“看起来更像生成模型”去加随机采样；本课要的是可复核，不是抽卡。

## 4. 完成后应具备的能力

1. 写出 $\hat x_{t+1}=\mathcal{W}(x_{0:t},c_t)$，并指出 $c_t$ 可以是文本、相机、末端，或 Genie 的潜伏动作。
2. 把数据引擎的门禁写成保真加物理违规率，把控制器的门禁写成真实世界滚动执行误差，拒绝两张表横着减。
3. 实现跨帧物体 ID 计数器 $D=\sum_t|\mathcal{I}_t\setminus\mathcal{I}_{t+1}|$，在“物体不该离开画面”的夹具上 $D>0$ 即失败。
4. 对自由下落写出 $\Delta v_{y,t}=v_{y,t+1}-v_{y,t}$，要求 $\operatorname{sign}(\Delta v_{y,t})=\operatorname{sign}(g)$，取反后探针必须报警。
5. 按 Cosmos 1 原文区分扩散 WFM 与自回归 WFM，并指出表 20 并不支持“更大一定更懂物理”。
6. 说出 Cosmos 3 的 MoT 里自回归子序列因果、扩散子序列可看全体条件，以及动作三种生成模式：前向动力学、逆向动力学、联合视频-动作。
7. 说出 Genie 的三件套：视频 tokenizer、潜伏动作模型、动力学模型，以及 16 帧记忆和约 1 FPS 的限制。

读完第 4 节，用这段自检，不通过就先别进公式。桌上有一个方块正在下落，你给它一个水平速度。你应能指出：数据引擎要问的是“下一帧方块还在不在、加速度方向对不对”；控制器要问的是“我按预测去推，真实世界里会不会推到目标点”。若你只能写出“生成一段很像的视频”，还没有拆开用途。若你写出了抓取成功率，却说不出 ID 集合和 $\Delta v_y$，门禁还没落地。这段自检不计入 CPU 实验，但能避免后面把损失写在错误的变量上。

再补一条更硬的自检。给你两段 8 帧日志，一段 $D=1$、$A_t$ 全假，一段 $D=0$、$A_t$ 有真。你应能立刻说出：第一段应被数据引擎拒收，因为它丢了物体；第二段若拿去选动作，真实世界的竖直运动会和预测相反。两段的 PSNR 都可以很高。PSNR 高不是通行证。若你需要看画面才能判断该拒收哪一段，说明计数器和符号还没变成你的第一反应，公式还停在阅读状态。把两段日志打印成 ID 表和 $v_y$ 列，不看像素，只看这两列做判定，判定应与看视频一致。不一致时，先查 ID 是否每帧重编号，再查 $y$ 轴方向。

## 5. 原理：边造边讲

六个机制按同一节奏：为什么需要、怎么运转、精确定义、公开实现落在哪、怎么证明做对了。本课没有 MiniMind 源码，代码落点写在各小节末尾的公开仓库与本课夹具里。

### 5.1 同一套预测，两种产品

世界模型的训练目标通常是：给定过去，生成未来。产品经理随后会问两个不同的问题。数据引擎问：这段未来能不能当别人的训练数据。控制器问：我能不能根据这段未来选一个动作，真去执行。Cosmos 1 的第 2.1 节把 WFM 的可能用途列成政策评估、政策初始化、政策训练、规划或模型预测控制、合成数据。紧接着写：该文没有给出把 Cosmos WFM 用到这些用途上的实证结果。读到这里就应停下来，把“平台论文列出的用途”和“该文实际测过的东西”分成两行。实际测过的，是视频生成、三维一致性、物理符合度、以及相机 / 操作 / 驾驶后训练样例。

两种产品对错误的容忍不一样。数据引擎可以丢掉坏片段，只要过滤器能抓住物体消失和重力反号。控制器没有这个奢侈：动作一旦下发，杯子会倒，夹爪会夹空。第 30 课处理过执行窗口和过期动作，见[第 30 课](30_closed_loop_control.md)。本课在那条时间轴上再加一条物理门禁：窗口里的预测如果已经丢掉物体或把重力弄反，过期与否都不是主因。

类比可以走到这里：数据引擎像摄影棚，拍得不像就重拍；控制器像把样片直接当成夜航图。类比失效处：摄影棚的废片不会砸到手上，夜航图错了会。Cosmos 把护栏做成输入拦截和输出拦截，防的是有害内容，不是防重力反号。物理探针要另做。

验证：拿同一段落下的方块，写两列指标。左列 PSNR 或 IoU，右列捕捉误差。缺任何一列，都不得声称“这个世界模型能用了”。

把用途写成训练时能落地的字段，比画框图更不容易糊弄。一条数据引擎样本至少包含：条件观察、扰动、生成视频、物体 ID 轨迹、是否触发永久性和重力探针。一条控制器样本至少包含：观察、候选动作、模型预测的下一状态、真实世界执行后的状态、任务成功谓词。两边对齐的字段只有三列：观察、扰动、下一状态。保真分数和成功谓词各自留在产品列。你若在表格里只看到“video, score”，请把它拆开，直到探针和成功谓词单独成列。拆不开的日志，不要拿去宣称平台已经跑通。

### 5.2 Cosmos 1：扩散一条路，自回归一条路

Cosmos 把预训练拆成两个可扩展家族，都用 Transformer。扩散 WFM 先做 Text2World，再微调成 Video2World：未来视频同时依赖过去视频和文本扰动。连续 token 来自 Cosmos-Tokenize1-CV$8\times8\times8$-720p。自回归 WFM 先做“只看过去视频预测未来”的 4B / 12B，再通过交叉注意力注入 T5 文本，得到 5B / 13B 的 Video2World。离散 token 来自 Cosmos-Tokenize1-DV$8\times16\times16$-720p。tokenizer 都是时间因果的：当前帧的 token 不看未来。因果设计让图像和视频可以共用一个网络，也更接近真实身体所处的时间方向。

预训练数据来自约 2000 万小时原始视频，整理出约 $10^8$ 段 2 到 60 秒的片段。类别比例写在第 3.1 节：驾驶 11%、手部与操作 16%、人体活动 10%、空间与导航 16%、第一人称 8%、自然动态 20%、动态相机 8%、合成渲染 4%、其他 7%。过滤管线包含镜头切分、运动、观感、叠加字幕和语义去重。去重大约去掉 30% 训练数据。这些数字说明 WFM 的上限首先被数据管线卡住，而不是被“再加几层注意力”卡住。本课不重做切分算法，只要求你引用时写清是原始小时还是可用片段。

扩散和自回归在后训练时的脾气不同。Cosmos 1 的结论段写：三维一致性和机器人视频上，扩散目前生成质量更好，也更容易接相机位姿、末端位置、驾驶轨迹、多机位。自回归则被寄希望于继承语言模型权重，以及将来更快的推理。表 18 给自回归家族单独报了一类失败：物体从画面下方意外冒出来。评估集是 100 个 Physical AI 输入。图像条件（单帧）下 Cosmos-Predict1-4B 失败率 15%，5B-Video2World 为 7%，12B 为 2%，13B-Video2World 为 3%；99 帧视频条件下都低于 2%，13B 为 0%。这是“出现”，和消失同属永久性家族，但统计口径是人工检查这 100 个输入，不是八类刚体场景的自动 IoU。引用时写清表号和条件。

tokenizer 的压缩比决定探针能不能看见物体。连续 tokenizer 把视频映成向量，给扩散去噪；离散 tokenizer 把视频映成整数，给自回归做交叉熵。Cosmos Tokenizer 用因果时间卷积和因果时间注意力，第一枚时间 token 对应第一帧，所以单张图可以当成 $T=0$ 的视频。离散侧采用 FSQ，连续侧采用普通自编码器，论文写明训练时不使用 VAE 的 KL 先验或 VQ 的 commitment 损失。对物理探针而言，压缩过度的直接后果是：小物体在 token 网格里只占半格，消失和形变在重建里看起来一样糊。表 20 的物体级 IoU 依赖你还能从预测视频里抠出物体；若 tokenizer 已经把两个方块并成一块纹理，计数器会少报 $D$。本课夹具不经过 tokenizer，ID 是显式整数，就是为了把“模型失败”和“编码失败”暂时拆开。你若在公开权重上做 Step 3，先看重建视频里三个方块是不是还分得开，再谈 $D$。分不开时，失败记在 tokenizer，不记在 WFM。

自回归那条“从下方冒出来”的失败，和重力符号有亲缘、但不是同一探针。重力探针看的是已存在物体的 $\Delta v_y$ 是否与 $g$ 同号。从下方冒出来是新 ID 进入集合，属于出现，不是消失，也不是已有物体的加速度。计数器 $D$ 用的是集合差 $\mathcal{I}_t\setminus\mathcal{I}_{t+1}$，只抓消失。若要抓出现，应另计 $|\mathcal{I}_{t+1}\setminus\mathcal{I}_t|$。表 18 的人工检查把“从下方出现”当成腐败，本课教学夹具没有实现出现计数，避免和 $D$ 混名。你在报告里如果看到新物体，另开一列 $B$（birth），不要写进 $D$。Limitations 把出现和消失都叫物体不永久性；统计时仍要分开，否则你无法知道过滤器该丢“少了一个”还是“多了一个”。

代码落点：公开实现在 `nvidia-cosmos/cosmos-predict1`。教学夹具不调用该仓库。你若本地拉权重，先核对模型卡上的条件帧数，再谈 PSNR。

验证：列出四行。扩散 7B Video2World、扩散 14B、自回归 4B、自回归 13B。每一行写条件（1 帧还是 9 帧 / 99 帧）、表 20 或表 18 的数字、以及“本行能不能当成控制器门禁”。表 20 不能，表 18 也不能。它们都是生成质量或人工腐败率。

### 5.3 物体 ID 计数器和重力符号

物理符合度需要一个不依赖“看起来像”的定义。Cosmos 用仿真出的参考视频和 WFM 预测视频对比。表 20 的像素级是 PSNR / SSIM，特征级是 DreamSim，物体级是平均 IoU，统计长度 33 帧，因为这是自回归变体当时支持的最大长度。7B Video2World 在 9 帧条件下四项为 21.06、0.691、0.859、0.592；1 帧条件下 17.34、0.538、0.836、0.332。条件变长，一阶和二阶量（速度、加速度）更好估，IoU 上升，这符合直觉。作者同时写：结果并不表明更大模型在物理符合度上更好；更大模型画面更好，各 WFM 同样在物理上吃力。

八类刚体场景的目的写得很具体，不是“随便做点物理”。自由落体测重力与碰撞；斜坡测重力与转动惯量；U 形坡测势能与动能转换；稳定堆叠测平衡力；不稳定堆叠测重力与碰撞导致的倒塌；多米诺测动量传递；跷跷板测力矩；陀螺测角动量与进动。每类随机化物体数量、尺寸、纹理、形状和背景，四台静止相机，总共 800 段 1080p、100 帧。物体从第一帧起全部可见，为的是避免“存在性含糊”：如果第一帧就看不见，后面出现不能算凭空诞生。本课夹具继承这条：三个 ID 在第 0 帧全部在场。WFM 条件是 9 帧加一条关注运动学状态的提示，然后对比后续帧。图 20 用斜坡、U 形坡、不稳定堆叠三组示例，把仿真参考和 Cosmos-Predict1-7B-Video2World 的滚动并排。定性失败写在表 20 之后那一段，原文列举：物体不永久性（自发出现和消失）、形变、不可信运动学、违反重力。Limitations 再次写：缺少物体永久性，生成视频的真实感并不总遵守重力、光照和流体。本课只把这两句变成计数器，不补百分比。作者还写：所有 WFM 在物理符合度上同样吃力，需要更好的数据整理和模型设计；他们打算以后加入更复杂场景、提高照片真实感以缩小仿真到真实的间隙，并改进评测指标。这些句子是规划，不是本课已经交付的过滤器。

设第 $t$ 帧仍在画面内、且按仿真不应离开的物体 ID 集合为 $\mathcal{I}_t$。丢失计数

$$
D=\sum_{t=0}^{T-2}\lvert\mathcal{I}_t\setminus\mathcal{I}_{t+1}\rvert
$$

在“自由落体、相机静止、物体一直在画面里”的夹具上，健康滚动必须 $D=0$。$D\ge 1$ 就是永久性探针。被遮挡后应还在的物体，若你有分割 ID，同样可以进 $\mathcal{I}_t$；本课 CPU 实验没有遮挡，避免把遮挡误报成消失。

重力用速度增量，不用“是不是往下掉了一点”。位置往下掉可能只是初速度，符号探针要看加速度。取 $y$ 向下为正，$g>0$。无竖直动作的自由下落：

$$
v_{y,t+1}=v_{y,t}+g\Delta t,\qquad
\Delta v_{y,t}=v_{y,t+1}-v_{y,t}
$$

探针

$$
A_t=\mathbf{1}\bigl[\operatorname{sign}(\Delta v_{y,t})\neq\operatorname{sign}(g)\bigr]
$$

$g$ 取反后，$A_t$ 必须为真。$\Delta v_{y,t}=0$ 在有重力的夹具里也视为异常，因为自由落体不应当完全没有加速度。水平动作 $a_x$ 只改 $v_x$：

$$
v_{x,t+1}=v_{x,t}+a_{x,t},\qquad
\Delta x_t=x_{t+1}-x_t=v_{x,t+1}\Delta t
$$

$\lvert\Delta x_t\rvert$ 在有动作时应大于无动作。这就是大纲里的“动作条件视频的帧差”。它不证明模型懂摩擦，只证明动作进了状态，而不是进了字幕。

驾驶后训练有另一段容易被误抄的句子：20 段生成视频、157 个物体，标注者未发现任何“两个物体错误融合成一个被跟踪实体”的物理不可能情形，作者用来支持驾驶视频的物理一致性和物体永久性。这是后训练驾驶模型上、针对跟踪融合的人工检查，样本是 20 段视频，不是八类刚体、也不是 Limitations 里的总声明。本课允许你引用 0/157，但必须写清设置。禁止用它覆盖 Limitations。

操作后训练的人工偏好是另一张表。指令条件视频预测上，10 名评估者、23 个测试回合，Cosmos-Predict1-7B-Video2World-Sample-Instruction 相对 VideoLDM-Instruction 的总体偏好为 78.3% 对 13.0%。评估维度包括指令跟随、物体永久性、真实性、总体。正文给出的可抄数字是总体偏好，没有把物体永久性单独写成百分数。不要把 78.3% 说成永久性命中率。

把 CPU 实验里的数字在纸上走一遍，避免把代码当成黑盒。约定 $\Delta t=0.1$、$g=9.8$、三个物体从 $y=0.4$ 静止释放，第 1 个间隔施加 $a_x=1.5$。无动作时水平位移均值为 0；有动作时，从第 2 帧起 $v_x=1.5$，此后每步 $\Delta x=0.15$，8 帧里有动作的 7 段间隔平均绝对值约为 0.129，严格大于 0。干净滚动每帧 3 个 ID，$D=0$。从第 4 帧删掉 ID 2 之后，只有一个间隔的集合差为 1，故 $D=1$，且第 4 帧到第 7 帧都看不到 ID 2。$v_y$ 每步增加 $0.98$，符号与 $g$ 相同，报警次数 0。把 $g$ 改成 $-9.8$ 再积分，ID 仍是 3 个，$D=0$，但 $\Delta v_y$ 每步为负，7 个间隔全部报警。捕捉目标设在 $x=1$。用正 $g$ 选出的 $a_x=+1.5$，真实世界终点误差约 0.10；用负 $g$ 选出的 $a_x=-1.5$，终点误差约 1.90。这组数字只属于夹具，用来证明：消失计数器和符号探针正交（翻转不丢 ID，丢 ID 不把幸存物体的重力弄反），以及控制器若信了反号重力，真实误差会变大。不要把 0.10 和 1.90 写进 Cosmos 的表。

验证：CPU 实验必须同时出现四件事。干净滚动 $D=0$ 且 $A_t$ 全假；丢掉 ID 后 $D\ge 1$；把 $g$ 取反后 $A_t$ 有真；水平动作增大 $\lvert\Delta x\rvert$。缺任何一件，探针就还只是观后感。再用第五件事卡住控制器：反号重力选出来的动作，真实捕捉误差必须更大。第五件不通过，你只证明了生成路的过滤器，还没有证明控制路不能用自评打分。

### 5.4 Cosmos 3：同一套 MoT 里的五种模态

Cosmos 3 把“理解”和“生成”收进一个网络。输入可以是语言、图像、视频、音频、动作；输出按任务切换。作者的主张是：理解需要推未来和动作后果，生成需要一份紧凑的世界与身体表示，拆成 VLM、视频生成器、VLA 再缝起来会浪费。本课关心的不是口号，是 token 怎么排、动作怎么写、评测分几列。

token 序列分成两段。前段是自回归子序列，放语言，以及给理解用的 ViT 视觉 token，走因果注意力，行为像普通视觉语言模型。后段是扩散子序列，放 VAE 视觉 token、音频 token、动作 token，训练时加噪，推理时迭代去噪。Cosmos 3 写明语言用 next-token，其他模态用迭代去噪，生成目标在实现里是流匹配的速度。每一层有两套参数：推理塔处理前段，生成塔处理后段，只在注意力处会合：

$$
\mathbf{O}_{\mathrm{AR}}=\operatorname{Attn}_{\mathrm{causal}}(\mathbf{Q}_{\mathrm{AR}},\mathbf{K}_{\mathrm{AR}},\mathbf{V}_{\mathrm{AR}})
$$

$$
\mathbf{O}_{\mathrm{DM}}=\operatorname{Attn}_{\mathrm{full}}(\mathbf{Q}_{\mathrm{DM}},[\mathbf{K}_{\mathrm{AR}};\mathbf{K}_{\mathrm{DM}}],[\mathbf{V}_{\mathrm{AR}};\mathbf{V}_{\mathrm{DM}}])
$$

自回归 token 不根据扩散 token 更新，条件通路保持因果。这和 Janus 那种理解/生成分家不是同一张图，也和第 20 课的共享 residual adapter 不是同一套实验。不要把 MoT 说成“已经统一了一切身体”。

动作被写成引起世界状态变化的因果变量。相邻视频 token 之间的动作 $a_t$ 表示从 $v_{t-1}$ 到 $v_t$ 的转移。身体各异，Cosmos 3 把控制收成共享几何件：主体位姿、效应器位姿、抓取状态。相邻 $SE(3)$ 位姿写成相对变换 $\Delta\mathbf{T}_t=\mathbf{T}_{t-1}^{-1}\mathbf{T}_t$，旋转用 6D 表示，OpenCV 约定。抓取状态不取差分，直接编码当前开合或指尖。域特定的输入输出投影把不同长度的动作向量映到共享隐藏维，骨干仍是 MoT。三种生成模式靠“哪些 token 干净、哪些加噪”切换：前向动力学用干净动作去噪视觉；逆向动力学用干净视觉去噪动作；政策模式两者一起去噪。表 1 里 FD: Robot 一列 Super 后训练为 26.0，对照 Ctrl-World 的 23.0；Policy: Robot 一列 Nano 后训练为 39.7，Super 该格为空，对照 $\pi_{0.5}$ 的 28.1。空格的含义是该变体在报告里没有这项能力或没有这项数字，不要自行填。

Physics-IQ 被 Cosmos 3 用来专门测物理符合。396 个真实场景、三个固定机位、五类物理（固体、流体、光学、热、磁）。图像到视频给一帧切换点；视频到视频给 3 秒条件、预测接下来 5 秒。分数按空间重叠、时间对齐、幅度加权空间一致、像素误差，相对真实对真实的上界归一化到 0 到 100。Super 直出 I2V 43.8、V2V 59.7。这仍然是生成续帧对真实续拍的接近程度。作者在图像到视频后训练一节写，I2V 会探测物理定律、物体永久性和场景几何，并给具身规划当预测机制。探测不是已经过关。Reasoner 的监督里收了 VideoPhy-2：约 3400 段以动作为中心的视频、200 种动作、1 到 5 分，标注覆盖守恒、重力、碰撞、时间因果和空间约束。那是给理解塔打物理常识分，不是给生成塔发永久性证书。

代码落点：`github.com/nvidia/cosmos` 与 Hugging Face 上的 Cosmos 3 集合。教学夹具仍然不调用。你若复现表 13，必须写清是 I2V 还是 V2V，是否 WMReward+BoN，以及 prompt 是否经过改写器。Cosmos 3 对所有自动和人工基准都用 Claude-Opus-4.6 把提示改成训练分布里的结构化格式。不写改写器，数字不可比。

位置编码把不同模态的时间对齐到同一物理轴。Cosmos 3 在 3D MRoPE 上加了绝对时间调制：视频、音频、动作的采样率不同，不能共用“token 下标加一等于同一段物理时间”。他们定义每秒时间步 TPS，视频 TPS 是帧率除以 VAE 的时间压缩 4，24 FPS 时 $\mathrm{TPS}_{\mathrm{base}}=6$；音频约 25；动作等于自身采样频率。时间下标每次加一，实际增量是 $\delta t=\mathrm{TPS}_{\mathrm{base}}/\mathrm{TPS}$。对探针的含义是：$\Delta t$ 必须用物理秒，不能用 token 下标差。本课夹具的 $\Delta t=0.1$ 是物理步长。你若把 Cosmos 3 的视频 token 间隔当成 1 秒，重力加速度会错一个数量级，符号探针仍可能碰巧通过，大小全错。本课不要求实现 MRoPE，但要求在自己的日志里写清 $\Delta t$ 的单位。

模型尺度写在表 2：Edge 4B、Nano 16B、Super 64B，双塔各从预训练视觉语言模型初始化。本课不比较三档谁更懂重力，Cosmos 1 表 20 已经警告过“更大不一定更懂物理”。Cosmos 3 的 Physics-IQ 上 Super 高于 Nano（I2V 43.8 对 40.2，V2V 59.7 对 50.2），这是另一张表、另一种条件，不能用来改写表 20 的结论，也不能用来宣布 Super 已经是可靠仿真器。43.8 距离 100 仍有一半以上的缺口，作者也没有把该缺口解释成“只差规模”。

验证：画一条落下的方块，分别标成前向动力学（动作已知、预测视频）、逆向动力学（视频已知、预测动作）、政策（两者都预测）。三行的干净/加噪模式必须不同。把三行都报成“成功率”，门禁就塌了。

### 5.5 Genie：没有动作标签时，动作从哪来

Cosmos 的 $c_t$ 常常来自文本、相机或机器人记录。互联网视频通常没有这些标签。Genie 的问题是：能不能只靠视频，学出一个逐步可控的环境。答案分三件套。视频 tokenizer 把 $T$ 帧压成离散 token。潜伏动作模型（LAM）看 $x_{1:t}$ 和 $x_{t+1}$，输出 $\tilde a_t$，再用一个只在训练时存在的解码器去重建 $x_{t+1}$。为了让人玩得动，码本大小限制为 $|A|=8$。动力学模型是 MaskGIT 式的 ST-Transformer，根据过去的视频 token 和潜伏动作预测下一帧 token。推理时 LAM 丢掉，改由用户选 0 到 7 的整数。作者观察到，同一整数的含义在不同提示图上大致稳定，学映射就像学一只新手柄。

主模型按论文摘要是 11B。训练细节写：tokenizer 约 2 亿参数，码本 1024；LAM 约 3 亿，patch 16，8 个潜伏动作；动力学 101 亿，batch 512，12.5 万步，256 块 TPUv5p；三件合计约 107 亿参数，9420 亿 token。序列长度 16 帧、10 FPS。平台跳跃数据从公开互联网游戏视频滤出约 3 万小时，680 万段 16 秒、160×90 的片段。另训一个 25 亿参数的机器人视频模型，数据来自 RT-1 和相关机器人视频，训练时不用动作标签，测试 FVD 为 82.7。可控性另用 $\Delta_t\mathrm{PSNR}$：用从真值推断的潜伏动作生成，对比用随机潜伏动作生成，看谁更接近真值帧，$t=4$。LAM 若改吃 token 而不吃像素，可控性下降，所以最终 LAM 吃原图像。

缩放实验把动力学从 4000 万做到 27 亿，训练损失随规模下降；batch 从 128 加到 448，2.3B 模型同样下降。最终他们把这条曲线用到 101 亿动力学。缩放改善的是训练损失和视频保真，论文没有声称缩放单独修好了物体永久性或重力。网站演示另训了一个把 token 映到 360p 的更大解码器，参数另计。本课引用 11B 时，指的是摘要口径的基础世界模型，不是 360p 解码器。推理用 25 步 MaskGIT、温度 2。温度和步数影响观感，不进入 $D$ 和 $A_t$ 的定义。有人把温度调低当成“更懂物理”，属于把采样参数写成物理门禁。门禁必须在固定采样协议下算；改温度就要重跑探针，不能沿用旧的 $D$。

Genie 也把潜伏动作接到智能体上：冻结 LAM，给未见过的专家视频打潜伏动作标签，再学一个从观察预测潜伏动作的政策，最后用少量带真值动作的数据把潜伏动作映回真实动作。CoinRun 上，大约 200 条专家样本就能达到有真值动作的行为克隆上界。这是“控制器”用法的一个窄证据：潜伏动作在平台跳跃上可迁移。它不是机械臂数字。论文自己把限制写在结论：会幻出不真实的未来；记忆只有 16 帧，长程一致性困难；交互大约 1 FPS。权重未发布。

推理时的逐步循环值得按帧写死，否则“可玩”会变成“一次生成整段视频”。用户先给一张提示图 $x_1$，tokenizer 得到 $z_1$，再选一个整数 $a_1\in\{0,\ldots,7\}$，动力学模型预测 $z_2$，解码回 $x_2$，然后重复。论文写可以用真值视频推断出的潜伏动作来重建原视频，也可以改动作来生成新轨迹。ST-Transformer 的空间注意力在单帧的 $H\times W$ 个 token 上，时间注意力在同一空间位置的 $T$ 步上，代价对帧数近似线性，这是他们能做 16 帧交互的工程理由。线性并不等于足够：记忆仍截断在 16 帧。落下的方块若在第 17 帧才碰到地面，Genie 必须丢掉早期帧，落地接触就可能不在窗口里。Cosmos 1 表 20 用 33 帧统计，已经比 16 帧长；两套数字不能比“谁更会落地”，因为窗口定义不同。

无标签学动作的代价是：手柄键义要人重新发现，且不保证对应物理上的力。平台跳跃里同一个潜伏动作在不同提示图上“人物左移”，这是作者的定性观察。机器人视频模型上，他们展示同一潜伏动作五次对应下、上、左这类语义。这仍然是生成一致性，不是力传感器读数。本课 $a_x$ 有明确牛顿含义，是夹具特权。把 Lab 的 $a_x$ 说成 Genie 的码本编号，属于把有标签动作和潜伏动作并成一句。

和 Cosmos 对读时，只抓住一件事。Genie 证明动作标签不是学习逐步控制的前提。Cosmos 3 仍然把动作当成一等模态，并用 $SE(3)$ 差分去对齐身体。两条路可以同时存在。本课 Lab 的水平动作 $a_x$ 是有标签的教学动作，用来让帧差可手算；它不声称复现了 $|A|=8$ 的无监督码本。

验证：写三列。tokenizer 输入输出、LAM 的码本大小、动力学是否逐步条件于动作。缺 LAM 那一列，Genie 就退化成普通视频模型。Table 1 把普通视频模型标成视频级可控，世界模型标成帧级可控且需要动作，Genie 标成只靠视频却仍帧级可控。引用这张表时不要改格。

把 8 帧夹具画成一张可打印的表，ID 用整数，速度用两位小数。你自己跑 CPU 实验时，应用这张表的结构去核对，而不是只看 `True`。

| 帧 | 在场 ID | $v_y$ 符号 | $D$ 增量 | $A_t$ |
|---|---|---|---|---|
| 0 | 1,2,3 | 0 | 无 | 无 |
| 1 | 1,2,3 | 正 | 0 | 假 |
| 2 | 1,2,3 | 正 | 0 | 假 |
| 3 | 1,2,3 | 正 | 0 | 假 |
| 4 干净 | 1,2,3 | 正 | 0 | 假 |

第 4 帧三行必须同时存在于你的笔记里。只抄“第 4 帧”而不写条件，数字会互相覆盖。Lab 揭晓后，生成路走“4 消失”这一行，控制路走“4 翻转 $g$”这一行。两行都触发探针，但触发的不是同一列。验收只要求至少一列触发，同时要求你预测对了是哪一种产品形态在触发。预测选对、探针没响，夹具坏了；探针响了、预测选成“两条路都干净”，你在对着已经发生的失败说没发生。两种都不通过。

Cosmos 3 在附录里放出 SDG-PhyxSim，用 Isaac Sim 和 PhysX 做了十类场景家族，其中 `objects_falling` 针对自由落体与弹跳沉降，`rolling_ramp_obstruct` 和 `obstruction` 明确把物体永久性列为要练习的现象。发布规模写明 76489 次独立仿真、多数 5 秒 150 帧、`ball_mixer` 为 8 秒 240 帧，1920 乘 1080、30 FPS，四机位，并带每物体速度与质心位移。这是他们给生成器准备的合成物理数据，不是“模型已经通过永久性考试”的证书。本课夹具只有 8 帧 3 个方块，不允许把 76489 抄进自己的实验记录当样本量。你能学的是：他们把永久性做成可回放的场景文件和分割颜色索引；你至少要把 ID 写成稳定整数。没有稳定 ID，再多仿真次数也只是更多糊视频。分割颜色索引在他们的 NPZ 里当物体主键；本课用整数 1、2、3 做同一件事。主键一变，$D$ 就失去意义，过滤器会把换色当成新生，把换色前的物体当成消失。所以 recipe 里要冻结 ID 的分配规则，和冻结重力坐标方向是同一级约定。写进数据卡的第一行，不要只写在某次会议的口头备注里。口头备注不会跟着数据集走，换一台机器后竖直轴方向和编号起点都会漂，探针就会对同一段视频给出相反的结论。

### 5.6 两张门禁表，禁止合并

现在可以把评价写成两张互不合并的表。

数据引擎门禁：

| 量 | 定义 | 通过 |
|---|---|---|
| $D$ | 跨帧丢失的物体 ID 数 | 0 |
| $\sum A_t$ | 自由下落符号报警次数 | 0 |
| PSNR / IoU / Physics-IQ | 生成与参照的接近程度 | 只在同条件、同改写器下比 |
| FVD | 视频分布距离 | 不代替 $D$ 和 $A_t$ |

控制器门禁：

| 量 | 定义 | 通过 |
|---|---|---|
| 滚动执行误差 | 真实世界里末端或物体相对目标的距离 | 低于预先写死的阈值 |
| 成功谓词 | 接触、抬起、放置是否成立 | 与第 31 课同一套拆层 |
| 模型自评误差 | 在预测世界里算的距离 | 不得单独上报 |

把模型自评误差当成成功，是本课 Lab 故意做出来的陷阱。控制路把预测重力取反之后，模型在自己的世界里仍可能“接到”目标，真实世界里方块继续往下掉，捕捉误差变大。CPU 实验把这件事写成：用 $\operatorname{sign}(g)$ 选动作，比用 $\operatorname{sign}(-g)$ 选动作，在真实世界里更接近 $x=1$。V-JEPA 2-AC 的合法写法是：不到 62 小时 Droid 无标签视频后训练，两间实验室 Franka，图像目标规划，无任务特定奖励。不要把这句话扩成任意房间任意物体。也不要用本课 8 帧方块去复述那两间实验室。

第 17 课的可验证奖励要求成功定义能被程序判定，见[第 17 课](17_grpo_rlvr.md)。世界模型当控制器时，成功谓词仍要能被程序判定。PSNR 上升不是可验证的抓取奖励。物体 ID 丢失可以当负奖励的硬门，但那是数据过滤，不是真机成功。

验证：任意对外表格出现“成功率”三字，后面必须跟：环境（真机 / 仿真 / 教学夹具）、是否用世界模型滚动、成功谓词、样本量。缺一项，数字作废。

## 6. 数据与训练 recipe

世界模型的 recipe 按产品拆，不要写成“再堆视频”。

**数据引擎桶。** Cosmos 1 的预训练吃的是切分、过滤、去重之后的短片段，加 VLM 每 256 帧一条描述。后训练吃的是目标身体上的“提示-视频”对，提示可以是动作指令、轨迹或语言。论文强调预训练提供基础，后训练数据可以小得多。驾驶后训练要多机位；操作后训练要指令或动作条件；相机后训练要位姿。缺条件字段的视频，只能当无条件生成，不能当动作条件数据引擎。Genie 的平台跳跃桶是 3 万小时、无动作标签；机器人桶同样丢掉动作标签，只当视频。你若要做数据引擎，必须另有一条过滤器：跑 ID 计数器和重力符号，触发则丢弃或降权。Cosmos 原文把“从数据里去掉物理上不可能的视频”写成未来工作，本课教学 recipe 把这条提前写成硬门，不是声称他们已经做了。

**控制器桶。** 需要观察、动作、下一观察，最好还有成功谓词。V-JEPA 2-AC 用 Droid 无标签视频学动作条件预测，规划时给图像目标。Cosmos 3 在 DROID 上后训练世界-动作模型，表 1 用星号标出后训练变体。控制器桶的动作必须能在真实身体上执行。Genie 的潜伏动作要经过“潜伏到真实”的小映射才能下发；CoinRun 上这个映射用了带真值动作的小数据。没有映射的潜伏动作，只能当可玩环境，不能当机械臂指令。

**建议的教学规模混合（不是论文规模）：**

| 桶 | 内容 | 损失或门禁 | 占比起点 |
|---|---|---|---|
| A | 落下的方块、无消失、重力符号正确 | 帧差 $L_2$，$D=0$，$\sum A_t=0$ | 0.5 |
| B | 人为丢掉 ID 或 $g$ 取反的负例 | 探针必须报警，不进入引擎桶 | 0.2 |
| C | 用预测选水平动作，在真实积分里评分 | 捕捉误差，不用自评误差 | 0.3 |

禁止用本表的占比去改写 Cosmos 的 $10^8$ 片段或 Genie 的 3 万小时。$\alpha$ 采样和第 26 课一样：按小时数会让自然风景淹没操作。教学上 A 与 C 都要见到，否则你会只做生成、假装会控。

桶 B 的负例不要写成自由文本标签。消失写成整数 $D$，重力写成布尔 $A_t$。有人用一条“这段视频物理不对”的句子当唯一监督，探针就被藏进语言模型的形容词里，计数器没有标签。桶 C 若只有生成视频没有真实积分，先补积分再入库。用模型自己的下一帧去给自己打分，自评误差会系统性偏低。

每个 epoch 结束打印四行：A 的 $D$ 和 $\sum A_t$，B 的探针触发率，C 的真实捕捉误差，以及把 C 的动作放到 A 的干净世界上的误差。最后一行是跨产品探针。若 A 很好、C 很差，你训出的是数据引擎，不是控制器。CPU 实验的翻转重力动作保证这一行和干净动作拉开。

后训练三条样例对应三种条件字段，写进 recipe 才不会把“微调了”当成“什么都能生成”。相机条件：提示是相机位姿，输出是可导航视频，检查三维一致性和视点是否跟手，不检查夹爪。指令条件操作：提示是语言指令，输出是未来操作视频，检查指令跟随和人工偏好，物体永久性只是四个维度之一，且正文没给该维度单独百分数。驾驶多机位：提示包含轨迹或多视点，输出是多相机视频，0/157 只覆盖跟踪融合这一种不可能情形。三条都是数据引擎。若有人声称“后训练之后就可以控臂”，问他动作是否进入 $\mathcal{W}$ 的条件、成功谓词是否在真机上算。两个答案都是否，就还停在数据引擎。

Cosmos 3 的生成后训练还加了一条针对弱点的检索：用智能体工作流找出模型弱点，再从预训练集里取针对性例子，并混入约 1000 条人工精选视频和约 2 万段合成片段（约占总 token 的 6%），同时保留 20% 的 T2I token 以免语义跑偏。I2V 后训练目标分辨率 480p、189 帧，约合 24 FPS 下 8 秒。8 秒已经长过 Genie 的 1.6 秒窗口（16 帧 10 FPS），仍短过很多操作回合。本课 8 帧夹具更短。窗口长度必须写进协议卡：你测的是 0.8 秒下落，还是 8 秒操作，还是 5 秒 Physics-IQ 续帧。不写窗口，IoU 和捕捉误差都会被时间截断悄悄改掉。

许可与污染：Genie 不发布数据。Cosmos 3 释放了部分合成数据和评测基准，使用前读 OpenMDW-1.1。教学夹具不使用真实人脸或驾驶 identifiability 数据。Cosmos 1 的护栏是 Aegis 加关键词拦截输入、安全分类器和脸部模糊拦截输出，与物理探针无关，不要把护栏通过写成物理通过。

把 Cosmos 3 的 Reasoner 数据和 Generator 数据再切一刀，避免把问答样本算进世界模拟预算。Reasoner 约 2420 万样本：预训练 2200 万，监督微调 220 万，微调里视频-文本约占 50%。Generator 吃的是重建目标下的图像、视频、音频、动作，而不是选择题。混在同一个“多模态样本数”里，会把 OCR 算进自由落体。写自己的混合表时，理解样本和生成样本要分列。只报“一共多少百万”会把 DocVQA 算进重力预算。

Reasoner 监督微调里还有一块专门的物理可信判断：Cosmos HUE 的 1.35 万条人工问答，以及 VideoPhy-2 的 1 到 5 分。这块训练的是“看出视频像不像物理”的理解塔，不是“生成时不丢物体”的生成塔。两个塔在 MoT 里会合，但不共享同一组标签。理解塔会判断重力，不保证生成塔遵守重力。本课探针打在生成结果和滚动执行上，不打在选择题准确率上。有人把理解塔的物理问答分当成生成已经懂重力，属于把 Reasoner 列抄进 Generator 列。表 1 把理解列和生成列分开写，就是为了阻止这种抄法。选择题分数进不了 $D$，也进不了滚动执行误差。

## 7. 按依赖顺序执行实验

实验分三层。第一层必须在无 GPU 时通过。第二层是浏览器教具。第三层只有在你真的加载公开世界模型时才跑，数字要带条件帧数和是否改写器。

### Step 1: CPU 机制实验

在 `experiments/` 下核对隔离脚本（本课不改 `registry.py`，编排者接入后再改成 `run.py run 34`）：

```bash
PYTHONPATH=src python3 -c "from learn_omni_experiments.lessons.lesson_34 import run; print(all(run()['checks'].values()))"
```

预期打印 `True`。失败时看 `checks` 里哪一条是 `False`：干净 ID、丢失计数器、重力翻转报警、干净自由落体 $\Delta v_y$、动作增大水平帧差、翻转重力选出的动作偏离捕捉、翻转不丢 ID、丢 ID 不把幸存物体的重力弄反。

### Step 2: 浏览器落下的方块

打开本课页面的 Lab。三个方块从上往下掉，目标点画在地面。先在四个选项里选一句关于“生成路 / 控制路”的预测，再把水平动作 $|a_x|$ 拉到至少 0.04，按“揭晓探针”。生成视频模式下，动作之后 2 号物体会被夹具丢掉，$D\ge 1$。用作控制器时，预测重力取反，符号探针触发；模型自评捕捉误差和真实世界捕捉误差会分叉。教具标题写明教学模拟。

教具内部的计算可以手工复核。真实世界：

$$
v_{y,t+1}=v_{y,t}+g\Delta t,\qquad g>0
$$

生成路在第 4 帧及之后从 $\mathcal{I}_t$ 里删掉 ID 2。控制路的预测器用 $-g$ 积分，所以 $\operatorname{sign}(\Delta v_y)$ 与真值相反。水平动作只加在第 2 帧的 $v_x$ 上。揭晓前左右两屏都走干净积分，避免先看见消失再选答案。改用途、改 $a_x$ 会清掉揭晓。

建议的操作顺序：用途先放到生成视频，$a_x$ 放到 0.08，选预测，揭晓，记下丢失 ID；再把用途切到控制器，再揭晓，确认重力报警，并对比自评误差和真实误差。中途改预测会清空揭晓，防止先看数字再选答案。

教具的左右两屏不要理解成“左真右假”的审美对照。左屏在揭晓后显示夹具处理后的真实世界滚动：生成路会少一块，控制路仍有三块但那是真实重力。右屏显示世界模型自己的预测：生成路按正 $g$ 积分所以仍有三块（模型未必知道自己丢掉了真实 ID），控制路按负 $g$ 积分所以方块往上走。丢失 ID 计数读左屏的集合差；重力符号报警读右屏预测轨迹的 $\Delta v_y$。两列数字来源不同，不能要求它们同时在同一屏上出现。这是产品形态在界面上的对应：数据引擎检查生成结果相对真实世界丢了什么，控制器检查预测器内部的物理是否自洽、以及拿它选动作后真实世界怎么走。

把水平动作幅度拉到 0.04 以上，是为了让动作条件帧差可见。$a_x=0$ 时水平位移为 0，你仍能触发生成路的消失（夹具不依赖动作幅度），但大纲要求“给落下的方块加动作”。验收把幅度写成硬门，避免有人只切用途、不碰动作滑条就通过。加大 $a_x$ 不能修好 $D$ 和 $A_t$，第四个预测选项就是为这个误解准备的。第四个选项“自评误差小就是真机能力”对应第 5.6 节的陷阱。两个错误选项都要能说清为什么错，而不能只记住正确选项的编号。

### Step 3: 可选，公开世界模型的单段探针

只在有 GPU 且你接受“这不是课程最低交付”时进行。选 Cosmos-Predict1 的 Video2World 公开权重，条件用 9 帧真实下落或斜坡，提示写清物体数量。人工数下一帧里物体是不是还在，加速度方向是否明显反了。样本数小于 25 时不要报成功率，只报逐例。评测纪律见第 31 课。Genie 没有公开权重，不要假装本地复现了 11B。

### Step 4: 不要做的事

不要把 Lab 的丢失 ID 写成 Cosmos 表 20 的 IoU。不要把 Physics-IQ 43.8 写成抓取。不要在 CPU 实验通过后声称“世界模型已经能当仿真器”。不要用 FVD 下降代替 $D$ 和 $A_t$。

## 8. 评测与测量

生成、物理探针、滚动执行是三张表。混用就是第 31 课反对过的“横着比成功率”。

**三维一致性不是物理探针。** Cosmos 1 第 5.3.1 节用 RealEstate10K 的 500 段静态场景测多视几何：Sampson 误差和相机位姿估计成功率，再加新视点合成。静态场景刻意去掉物体运动，为的是让现有多视工具用得上。它测的是“生成视频是不是某个三维世界的投影”，不是“下落是否遵守 $g$”。一段视频可以三维一致却把杯子举到天花板上，也可以重力对却在转场时换一间房间。本课 $D$ 和 $A_t$ 不管相机，Sampson 误差不管加速度。引用 Cosmos 时不要把 5.3.1 和 5.3.2 并成“物理都过了”。

**生成保真。** FVD、PSNR、SSIM、DreamSim。Cosmos 1 表 20 必须带模型名和条件帧。Cosmos 3 的 PAIBench-G 把质量分和领域分各一半：Overall $=0.5\times$ Quality $+0.5\times$ Domain。Super 的文本到视频 Overall 80.0，图像到视频 82.8。这些分包含帧一致、运动平滑、美学、视文对齐，以及 VLM 评判的领域正确。它们包含物理，但不孤立物理。PAIBench-G 有 1044 对图像-文本提示，六个领域：Human 299、Autonomous Vehicle 239、Common Sense 174、Robotics 107、Physics 107、Industry 107。Physics 只是六分之一，而且领域分由 VLM 当裁判做二元判定。把 Overall 80.0 说成“物理 80 分”，属于把六桶平均写成单桶。RBench 测具身任务场景里的任务正确和物理可信，Nano 的图像到视频为 58.4%。它比 PAIBench-G 更靠近身体，仍是生成视频评分，不是真机执行。

**物理符合。** Cosmos 1 用八类刚体加表 20，再用文字承认消失和违反重力。自回归另报表 18 的“从下方冒出来”。Cosmos 3 用 Physics-IQ 把物理当成唯一轴，I2V / V2V 分列，是否 BoN 分列。Human 评测 Cosmos HUE 用 1000 段生成视频上的 1.35 万条人工问答，覆盖视觉完整、时间稳定、几何、解剖、运动可信和物理常识，答案是是 / 否 / 不清。人工评测用来抓自动指标漏掉的长尾失败，不是用来给控制器发证书。

**滚动执行。** V-JEPA 2-AC：不到 62 小时、两间实验室、图像目标、无任务奖励。Cosmos 3 表 1 的 Policy: Robot 和 FD: Robot。Genie 的 CoinRun 200 条专家样本。教学夹具的捕捉误差。四行不能减。

**本课最低测量。**

课程通过只看机制，不看是否跑通 11B 或 64B。

## 10. 根据症状定位失败环节

| 症状 | 先查 | 不要先做 |
|---|---|---|
| 画面清楚，物体突然没了 | $D$ 是否在中间帧跳变，分割 ID 是否换了 | 加分辨率 |
| 画面清楚，物体从下方冒出来 | 是否落到表 18 那类自回归腐败，条件是 1 帧还是 99 帧 | 换成更大扩散模型就宣称已修复 |
| 往上飞或失重 | $\operatorname{sign}(\Delta v_y)$ 与 $g$，坐标是否把 $y$ 向上当成正 | 加文本提示“遵守重力” |
| PSNR 升、IoU 不动 | 纹理拟合了、物体框在漂 | 只报 PSNR |
| Physics-IQ 升、抓取不动 | 你在测续帧，不是测执行 | 把 43.8 写进机器人表 |
| 自评捕捉误差很小、真世界很大 | 是否在用模型自己的重力积分给自己打分 | 下调学习率 |
| 动作加大，水平帧差不变 | $a_x$ 有没有进状态，还是只进了 caption | 换 tokenizer |
| Genie 可玩、机械臂不动 | 潜伏动作有没有映到真实动作 | 宣称通用控制器 |
| 驾驶 0/157、刚体仍失败 | 后训练域是否被当成预训练通才 | 用驾驶数字覆盖 Limitations |
| 护栏通过、杯子消失 | 护栏管的是有害内容 | 把安全分类器当物理仿真器 |

第 01 课的 trace 纪律在这里变成：任意一段生成或滚动，都要能回放到条件帧、扰动、$D$、$A_t$ 和成功谓词，见[第 01 课](01_baseline_reproduction.md)。做不到回放的实验，即使 FVD 下降，也不算本课交付。

再补一组和本课公式直接相关的症状。$D$ 永远是 0：检查 ID 是不是每帧重新编号，计数器若用位置聚类而不是稳定 ID，消失会被当成新物体。$A_t$ 永远为假：几乎总是拿 $\Delta y$ 的符号当成 $\Delta v_y$，匀速下落会骗过位置探针、骗不过速度探针。$A_t$ 永远为真：$\Delta t$ 取成 0，或把像素坐标的整数截断当成速度。捕捉误差对 $a_x$ 无感：动作加在了错误的物体 ID 上，或加在了已经消失的 2 号上。这些检查都只需要打印每帧 ID 表和 $v_y$ 列，不需要再下 2000 万小时视频。

## 12. 前沿对照与改造方向

**公开方案。** 同一问题，2024-2026 年的公开系统分成三条产品线。Cosmos 1 把 WFM 做成预训练加后训练的平台，扩散与自回归并列，明确承认还不能当可靠物理仿真器，并把物体永久性和重力写进失败模式。Cosmos 3 用 MoT 把语言、图像、视频、音频、动作收进一个骨干，按配置切换理解、生成和世界-动作；生成评测走 PAIBench-G、RBench、Physics-IQ 和人工 HUE，政策数字走后训练变体。Genie 从无标签视频学逐步可玩环境，用 $|A|=8$ 的潜伏动作代替真值手柄，并展示了把潜伏动作映回 CoinRun 真值动作的窄路径。V-JEPA 2-AC 用不到 62 小时无标签机器人视频把表征预测器变成规划器，两间实验室零样本抓放。第 20 课讨论的 Show-o / Janus 是图像理解与生成，不是逐步世界。Qwen2.5-Omni / Qwen3-Omni 的公开技术报告以听、说、看为主，未把 Cosmos 那种物理探针或 Genie 那种潜伏动作写成预训练目标。其技术报告未公开“与 Cosmos 共用物体 ID 计数器”这一设定。Moshi 是语音全双工，与本课重力符号无关。不要把 Omni 的语音能力写成已经会仿真下落。

规模能堆的部分也要说具体。Cosmos 1 从 2000 万小时收到约 1 亿片段，靠镜头切分、运动过滤、去重。Genie 从更长的互联网游戏视频收到 3 万小时平台跳跃。Cosmos 3 的生成后训练还加了针对性合成数据和人工精选视频。三条流水线都是“先放大再狠滤”。缩小实验没有资格模仿过滤规模，但可以模仿纪律：写入数据引擎桶之前必须有一条可执行的探针，哪怕只是 $D=0$ 和 $\sum A_t=0$。没有探针函数的视频目录，不算 recipe。探针函数要返回原因码，例如 `missing_id`、`gravity_sign`、`zero_accel`。只返回布尔值，以后你无法统计是消失多还是反号多，也就无法决定下一步该修 tokenizer 还是该修条件帧。

**差距。** 规模差距：千万小时视频、11B 到 64B、TPU / GPU 集群，钱能堆。机制差距：两种产品形态、ID 计数器、重力符号、动作帧差、禁止合并表，本课能做。评测差距：Physics-IQ 直出 43.8 距离“可靠仿真器”仍远，Limitations 没有被表 13 撤销；那是数据、接触、长程记忆，交给后续课。Genie 的 16 帧和 1 FPS 也不是本课玩具能填的。

接触丰富动力学被 Cosmos 写进 Limitations，本课探针故意没覆盖。方块夹具没有摩擦、没有碰撞冲量、没有夹爪与物体的多点接触。$D$ 和 $A_t$ 通过，只说明物体还在、自由落体方向对。杯子沿桌面滑、被夹爪挤扁、液体洒出，都不会响。改造实验 2 用形变提醒你：还有一类失败既不是消失也不是反号。谁把本课通过理解成“物理已经过关”，等于把 Limitations 里剩下的接触、光照、流体一并删掉。下一课从深度和接触继续往下问，本课不提前兑现。

长程记忆同样不在本课公式里。Genie 承认 16 帧不够；Cosmos 1 自回归表 20 统计到 33 帧；Cosmos 3 的 I2V 后训练到约 8 秒。操作任务常常比 8 秒长。第 39 课才会处理子目标栈。本课的 8 帧只用来让 $D$ 和 $A_t$ 能手算。你若需要 30 秒的厨房任务，不要把 8 帧捕捉误差外推。外推属于把夹具时间写成任务时间，和第 31 课把 LIBERO 平均写成真机同类。

**改造实验。**

1. 把 CPU 实验的 $D$ 从“下一帧集合差”改成“允许离开画面底部再计消失”。只改集合定义，数据仍是 8 帧 3 物体。预算：CPU 数分钟。预期：物体落到 $y$ 上界后 $D$ 不再增加；人为在半空删掉 ID 时 $D$ 仍增加。失败：$D$ 与是否落地无关。
2. 在 Lab 里加第三种缺陷：形变（把方块宽高比拉到 3:1）但不丢 ID、不反重力。预算：改渲染，不训练。预期：数据引擎可以另设形变门禁；当前 $D$ 和 $A_t$ 保持通过，说明两探针不覆盖形变。失败：形变被 $D$ 误报成消失。
3. 给控制器加候选动作 $\{+a_x,-a_x,0\}$，用预测世界打分再在真实世界执行。预算：CPU 一小时级的网格搜索。预期：预测器用 $-g$ 时选到的动作，真实捕捉误差大于用 $+g$ 的。失败：两种重力选出的动作相同，或真实误差与所选动作无关。
4. 若有能跑 Cosmos-Predict1-7B-Video2World 的显存：用 9 帧真实下落作条件，生成 8 帧，人工数物体。预算：单卡若干小时推理，不微调。预期：至少能标出“是否丢失物体”的逐例表。失败：把 FVD 或一张好看的截图当成永久性已通过。样本不够 25 时只发逐例表。

**顺手复现映射。** Cosmos 5.3.2“刚体仿真能抓到消失和违反重力”对应本课夹具：生成路必须 $D\ge 1$，控制路必须 $A_t$ 为真。表 20“更多条件帧能抬 IoU、更大模型不保证更懂物理”在教学规模只能看到“给满 8 帧初值再积分，比只给 1 帧乱猜加速度更稳”，看不到 21.06。方向可复现，绝对值不能。Genie“潜伏动作让随机动作和推断动作的续帧拉开”对应 $\Delta_t\mathrm{PSNR}$ 的思想：本课用有无 $a_x$ 的 $\lvert\Delta x\rvert$ 差来做最小版本。V-JEPA 2-AC“用预测选动作”对应翻转重力选错符号那一条。这些映射全部是方向性的。谁把 43.8 或 39.7 写进自己的 8 帧玩具报告，就算评测造假。

改造实验的失败判定再补两条公共规则。任何一次 GPU 推理都要保存：权重哈希、条件帧数、提示原文、是否经过改写器、逐帧 ID 表。缺哈希的结果不能进对照表。任何一次声称“控制器更好”的比较，必须在同一观察、同一成功谓词、真实世界执行上完成；只在预测世界里打分就不能把差值记在政策上。

## 13. 论文与必读材料

阅读时带着括号里的问题。数字以你打开的版本为准；本课引用的是下面列出的版本。

1. Cosmos World Foundation Model Platform for Physical AI（arXiv:2501.03575，NVIDIA，v3）。带着问题读：WFM 的定义式 $\mathcal{W}(x_{0:t},c_t)$ 里 $c_t$ 可以是什么？第 2.1 节列出的用途哪些没有实证？表 20 的 9 帧与 1 帧差在哪，为什么作者说更大不一定更懂物理？5.3.2 如何描述物体不永久性和违反重力？Limitations 那一段还加了哪些失败？表 18 的 15% 测的是消失还是从下方出现？
2. Cosmos 3: Omnimodal World Models for Physical AI（arXiv:2606.02800，NVIDIA，v4）。带着问题读：MoT 里自回归子序列和扩散子序列怎样分参数、怎样会合？动作三种生成模式各把哪些 token 加噪？表 13 的 I2V 43.8 和 V2V 59.7 能不能写成抓取？表 1 里带星号的 39.7 和 26.0 是什么变体？I2V 后训练一节把物体永久性写成能力还是写成要探测的问题？
3. Genie: Generative Interactive Environments（arXiv:2402.15391，Bruce 等）。带着问题读：三件套各干什么，为什么推理时丢掉 LAM？$|A|=8$ 的理由是什么？3 万小时和 16 帧、10 FPS、约 1 FPS 分别限制什么？机器人 FVD 82.7 用了动作标签没有？CoinRun 200 条样本证明的是可玩性还是机械臂？为什么不发布权重？
4. V-JEPA 2（arXiv:2506.09985）。带着问题读：不到 62 小时之后，模型被当成数据引擎还是规划器？零样本的条件写了哪些（新实验室、无任务奖励、图像目标）？本课不得把该文的表征损失推导重做一遍，那是第 33 课的作业。摘要写预训练用超过 100 万小时互联网视频和图像；本课只借它的产品形态，不借它的 Something-Something 或 Epic-Kitchens 分数来给 Cosmos 打分。那些是理解与预测基准，不是本课的 $D$。

读这四篇时共用一张问题卡，避免每篇单独看完又并到同一格。问题卡四列：这篇把世界模型当成什么产品、它承认了哪些失败、它报了哪张评测表、那张表能不能当控制器门禁。Cosmos 1 的答案是平台与数据引擎为主、承认永久性和重力、表 20 与表 18、不能。Cosmos 3 的答案是通才骨干加后训练政策、I2V 把永久性写成要探测的问题、Physics-IQ 与表 1 政策列、政策列可以靠近控制器但 Physics-IQ 不能。Genie 的答案是可玩环境加潜伏动作、承认幻象与 16 帧与 1 FPS、FVD 与 $\Delta_t\mathrm{PSNR}$ 与 CoinRun、CoinRun 不是机械臂。V-JEPA 2-AC 的答案是规划器、摘要把限制写在零样本条件里、真机抓放声明、可以进控制器表但必须带 62 小时和两间实验室。四行填完，禁止合并表就已经在你本子上了，不必等第 8 节的印刷表。印刷表只是把同一纪律写成可抄的一行。

第 24 课把动作接进视觉语言模型，见[第 24 课](24_vlm_to_vla.md)；本课的动作是世界模型的条件，不一定是 VLA 词表里的 token。第 28 课的流匹配出的是动作块，见[第 28 课](28_flow_matching_vla.md)；Cosmos 3 生成塔的流匹配出的是视觉或动作 token 的去噪轨迹，不要把两套速度场抄成一个符号。下一课规格指向缺了深度的抓取。本课停在这里：世界模型可以当数据引擎，也可以当控制器；两件事要用物体 ID 和重力符号分开验收，并且任何教学数字都不能冒充真机。读者应能在读完本课后独立复述：预测方程是 $\mathcal{W}(x_{0:t},c_t)$，数据引擎拒收 $D>0$ 或重力反号的片段，控制器用真实世界滚动误差，Cosmos 自己承认永久性与重力仍会失败。能复述这三句，并且 CPU 实验八条检查为真，本课就收工。交互实验还要留下一次先预测后揭晓的记录，证明你没有对着已经显示的消失方块去选答案。三项齐了，再去碰公开权重也不迟。公开权重只能检验同一套探针在真实生成视频上是否还能报警，不能回头否定玩具里已经核对过的集合差和符号函数。报警是过滤口径，真机成功是执行口径，两套数字不要写进同一格。
