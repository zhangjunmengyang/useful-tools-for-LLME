# 第 43 课：分开语音转写和语音指令跟随

> 内容：音频进 LLM 后的两类交叉熵、任务过拟合与语音指令跟随评测<br>
> 建议周期：阅读约 65 分钟；CPU 实验数分钟<br>
> 硬件：无 GPU 可读完全文并跑 CPU 机制实验；复现论文规模需要多卡与大规模语音指令数据<br>
> 产物：两类 loss mask 对照、转写对而指令错的夹具、文献数字表

## 1. 听懂指令和转写声音差在哪一层

同一段波形可以当两份作业。一份作业是：把嘴里的字原样写成文本，这是自动语音识别（ASR，automatic speech recognition：听写）。另一份作业是：把嘴里的字当成对模型的命令，去改日程、做算术、解释背景里的键盘声，这是语音指令跟随（speech instruction following：听懂并执行）。两份作业共用音频编码器和语言模型，不共用监督区间。

第 03 课和第 04 课已经处理过声音怎么变成离散编号、Talker 怎么按 delay schedule 吐多路码本，见[第 03 课](03_audio_codec.md)和[第 04 课](04_multicodebook_talker.md)。那些课管的是可重建、可预测的声学 token。本课不再拆 RVQ，也不再排 delay。这里的音频编码器输出只当作条件：给语言模型看的连续帧，默认不进交叉熵。要改的是文本侧那张 0/1 表：哪些位置的预测错误算数。

差在哪一层，可以先用一句口语指令钉死。有人对着麦克风说：“把三加五的结果乘以二，只回答数字。”转写对了，得到的字符串几乎等于这句话。指令对了，得到的字符串应是 `16`。模型完全可以在第一份作业上 WER（词错误率）低于 2%，同时在第二份作业上把原句复读出来。Qwen2-Audio（arXiv:2407.10759）把 Librispeech test-clean 做到 1.6%、test-other 做到 3.6%；同一篇技术报告没有给出它在把文本基准念成语音之后的 MMLU 数字。Qwen2.5-Omni（arXiv:2503.20215）表 4 补了这张对照：把大约 90% 适合口述的文本题转成语音后，Qwen2-Audio 的 MMLU 只有 33.2，GSM8K 只有 18.4；同规模文本模型 Qwen2-7B 是 69.3 和 82.3；Qwen2.5-Omni-7B 是 65.6 和 85.4。转写层已经很强的系统，指令层可以几乎不会做题。

SALMONN（arXiv:2310.13289，ICLR 2024；课程大纲里曾写 2310.09478，打开后是 MiniGPT-4，本课按 Qwen2-Audio 引用的 Tang 等原文核对）把这件事写成训练事故：指令微调之后，模型遇到没见过的跨模态题，会假装收到了“请转写”或“请做音频描述”，输出短而确定的听写。论文把这种现象叫做 task over-fitting（任务过拟合：条件语言模型被听写这类高确定目标拽歪）。激活微调 12 步之后，讲故事的跟随率从 0.00 升到 1.00，LibriSpeech test-clean 的 WER 仍停在 2.1%。转写层几乎没动，指令层突然能跟。

本课要造的不是新的 codec，是一张能把两层拆开的账本。验证改对了的标准有两条，都必须能在无 GPU 时复核：同一条序列上，ASR 交叉熵的有效 token 集合与指令跟随交叉熵的有效 token 集合不相等；浏览器教具里必须出现“转写对、指令错”的一例。CPU 实验证明 mask 公式可手算，不证明 AIR-Bench 或 VoiceBench 的分数。

把“差在哪一层”说死之后，还要能指出它不覆盖什么。它不覆盖 codec 码率、Talker 多码本和 delay schedule，那些是第 03–04 课。它不覆盖全双工谁先开口，那是第 06–07 课。它不覆盖把回复再读成波形的 seed-tts WER，那是 Qwen2.5-Omni 的生成评测。它覆盖的只有：同一段用户语音、两张文本 mask、两套参考、两列指标。谁在这四个对象之外加进“通用听觉智能”之类的空话，就把范围重新抄一遍。

MiniMind-O 的 SenseVoice 在第 01 课里是冻结的听写器。若你把 SenseVoice 的转写直接当 Thinker 的用户文本，系统默认走级联。级联可以把 WER 做得很好，同时把键盘声丢掉。本课提供的替代是：音频帧进 LLM，损失写在执行文本上。两条路径可以并存于同一产品，但不能共用一张验收表。

本课术语：

| 术语 | 简要解释 |
|---|---|
| ASR / 转写 | 把语音变成文字，监督是听写文本 |
| 语音指令跟随 | 把语音当成命令，监督是助手应当执行后的回复 |
| loss mask | 标出哪些位置参与交叉熵的 0/1 表；提示、音频帧、padding 通常为 0 |
| 有效 token 集合 | mask 为 1、label 不是 `-100` 的位置集合 |
| 音频分析模式 | Qwen2-Audio 里用语音或文本去分析一段声音、音乐或混合音频 |
| 语音闲聊模式 | 同一模型把整段用户音频当成对话轮次，不必另写系统提示来切模式 |
| 任务过拟合 | 训练任务里听写占比过高时，零样本指令被模型当成听写来回答 |
| 激活微调 | SALMONN 用少量长而多样的回答，把被听写拽歪的条件分布拉回来 |
| 窗口级 Q-Former | 把变长音频按窗切片，每窗用可学习 query 压成若干文本侧 token |
| VoiceBench | 用口述指令测助手能力的基准，不是 WER 基准 |

若你已经做过第 01 课，loss mask 的写法应当还记得：只对助手目标算账，见[第 01 课](01_baseline_reproduction.md)。第 15 课把同一规则用到多模态联合 SFT：媒体占位符只提供条件，见[第 15 课](15_joint_multimodal_sft.md)。本课把这条规则再切一刀：助手目标里，“听写出来的字”和“执行之后该说的字”仍是两段，不能因为都出现在 assistant 角色里就进同一张 mask。

## 2. 本课解决的问题

把一段用户语音送进大语言模型之后，训练脚本几乎总会打印一个叫 `loss` 的标量。这个标量下降，只说明被 mask 选中的那些位置更好预测了。它没有告诉你选中的是听写，还是命令的回复。

本课同时卡住三个问题。

第一，条件在哪、目标在哪。Whisper 类编码器把 16 kHz 波形变成帧。Qwen2-Audio 把原始波形做成 128 通道梅尔谱，窗长 25 ms、跳步 10 ms，再加步长为 2 的池化，于是编码器每一帧大约对应 40 ms 原声。这些帧进语言模型之前是条件，不是要预测的离散听写。若有人把编码器帧也标进文本交叉熵，数字会看起来很大、梯度会冲向错误的空间。正确的默认：音频帧的 label 全是 `-100`。

第二，同一段助手文本里，哪一段才该学。听写样本的助手侧是转写。指令样本的助手侧是动作、答案、确认码、对背景声的解释。两段字符串可以共享词表、共享 softmax，但 mask 区间必须能分开画。SALMONN 的失败形态恰好是：指令样本的 $P(\mathbf{Y}\mid\mathbf{X})$ 仍峰值在转写上，于是即使用户写了“根据这段声音写故事”，模型仍输出短听写。

第三，评测数字测的是哪一层。WER、CER、BLEU 测转写和翻译。AIR-Bench chat、VoiceBench、把 MMLU / GSM8K 念成语音之后的准确率，测指令跟随。Qwen2-Audio 在 VocalSound 上准确率 0.9392，在 AIR-Bench chat 的 speech / sound / music / mixed 四维上得到 7.18 / 6.99 / 6.79 / 6.77，超过 SALMONN 的 6.16 / 6.28 / 5.95 / 6.08 和 Gemini-1.5-pro 的 6.97 / 5.49 / 5.06 / 5.27。这些是指令侧数字。把它和 Librispeech 1.6% 横着写成“音频全能”，会把两层糊回去。

三个问题必须一起验收。只改编码器、仍对转写算损失，得到的是更强的听写器。只换指令数据、mask 仍盖住转写跨度，模型会继续复读。只报 WER、不报口述 MMLU 或 VoiceBench，账本上指令层是空的。

和第 03–04 课的边界写在这里：本课可以使用“音频编码器输出帧率”这种接口数字，例如 Qwen2-Audio 的约 40 ms/帧、SALMONN 双编码器的 50 Hz，用来数条件 token。本课不比较 Mimi / EnCodec / DAC，不推导残差量化，不排列 Talker 的多码本时延。和第 07 课的边界：全双工路由管的是说话时要不要继续听，见[第 07 课](07_full_duplex_routing.md)；本课的样本默认是回合制，一条语音进、一段文本出。和第 16 课的边界：Qwen2-Audio 用了 DPO（直接偏好优化），公式按原文抄在后文，用来说明偏好对仍然落在助手回复上；本课不重做参考模型与 $\beta$ 的推导。

失败条件预先写死：

- 只报 WER 下降，声称“已经会听指令”；
- 把助手角色里出现的转写文本，和执行后的回复写进同一张有效集合，还不声明这是污染实验；
- 把 SALMONN 激活微调之前的模型，在讲故事、语音问答上的失败，写成“编码器听不清”；
- 用 Qwen2-Audio 的 Librispeech 数字，代替 Qwen2.5-Omni 表 4 的口述答题数字；
- 在教具里找不到“转写对、指令错”的参数组合，却宣称两层已经分开。

## 3. 开始前需要准备什么

本课不依赖 MiniMind-O 的训练脚本，也不需要重训 Whisper。需要的是第 01 课那种“只对助手目标算账”的直觉，以及能把一条序列画成角色跨度的耐心。没有读过第 03–04 课也可以往下走：把音频编码器当成一个冻结的帧生成器即可。读过的人注意：不要把本课的帧和 Mimi 的 8 路编号当成同一种东西。

开始前把笔记本分成两栏。左栏只抄打开过的论文句：采样率、窗长、参数量、表号、WER、AIR-Bench、口述 MMLU。右栏写本课约定：教学序列长度 20，音频帧 6 个，转写跨度 5 个 token，指令跨度 3 个 token，忽略索引 `-100`，Lab 里的回复是规则算出来的，不是 Qwen 权重的前向输出。左栏数字可以对外引用，右栏数字只能当夹具。有人把 Lab 里 `16` 写成“复现了 Qwen2.5-Omni 的 GSM8K 85.4”，属于把右栏抄进左栏。

**上游事实（打开原文核对过）：**

- Qwen2-Audio：Qwen Team，arXiv:2407.10759，仓库 [github.com/QwenLM/Qwen2-Audio](https://github.com/QwenLM/Qwen2-Audio)；音频编码器从 Whisper-large-v3 初始化，语言模型用 Qwen-7B，总参数 8.2B；Hugging Face 类名 `Qwen2AudioForConditionalGeneration`，权重 `Qwen/Qwen2-Audio-7B` 与 `Qwen/Qwen2-Audio-7B-Instruct`；
- SALMONN：Tang 等，arXiv:2310.13289，ICLR 2024，仓库 [github.com/bytedance/SALMONN](https://github.com/bytedance/SALMONN)；Whisper-Large-v2 编码器 + BEATs + Vicuna-13B，可训练部分约 33M，约占全模型 0.24%；
- Qwen2.5-Omni：Qwen Team，arXiv:2503.20215，仓库 [github.com/QwenLM/Qwen2.5-Omni](https://github.com/QwenLM/Qwen2.5-Omni)；音频编码器沿用 Qwen2-Audio 的设定，Thinker 出文本，Talker 出语音 token，本课只读 Thinker 侧的语音指令跟随数字。

**课程约定：**

- 浏览器实验是教学模拟，数字由 mask 规则和配方表算出来；
- CPU 实验不读网、不写文件、不用 NumPy，跑完只在内存里留下一个字典；
- 引用 SALMONN 时使用 2310.13289，不使用误指向 MiniGPT-4 的 2310.09478；
- 本课主路径不训练 7B / 13B。若要跑公开权重做 Step 3，再准备能放下对应 checkpoint 的显存。没有这张卡，跳过 Step 3 仍可完成最低交付。

软件上只需要 Python 3.10 标准库和能打开本课页面的浏览器。不要为了本课新装 Kaldi、Whisper 推理栈或语音合成器。口述 MMLU 那种评测在论文里已经做完，本课只引用表，不重跑。

Qwen2-Audio 的三阶段也要按层来读。预训用自然语言提示喂 ASR、翻译、描述、分类，有效集合大多是听写、译文或短标签。SFT 才把分析和闲聊写成对话回复。DPO 再在回复里挑更好的。若只跑预训就去聊天，得到的是会听写的基座，对应 `Qwen/Qwen2-Audio-7B` 而不是 `Qwen2-Audio-7B-Instruct`。Lab 的听写预训配方对应这一误用。Instruct 权重并不保证你自己的 SFT 脚本 mask 画对：仍可以把助手全文标成 1。权重名字不能代替集合打印。

## 4. 完成后应具备的能力

完成后，拿到任意“音频进、文本出”的训练日志，你应能完成以下检查：

1. 画出一条序列：音频帧、用户提示、助手回复，并标出哪些位置的 label 是 `-100`；
2. 在同一条含转写跨度和指令跨度的序列上，写出 $M_{\mathrm{asr}}$ 与 $M_{\mathrm{if}}$，证明两个集合不相等；
3. 解释为什么只报 WER 不能代替语音指令跟随；
4. 用 SALMONN 的公式说明：无指令时的 $P(\mathbf{Y}\mid\mathbf{X})$ 若被听写霸占，有指令时模型仍会听写；
5. 对照 Qwen2-Audio 的两种交互：分析一段声音，和把声音当成对话，并且指出论文写明不靠系统提示切换；
6. 对照 Qwen2.5-Omni 表 4：口述指令和文本指令的差距，以及 Qwen2-Audio 在同一张表上的缺口；
7. 在教具里构造转写对、指令错的一例，并说出它对应哪一种错误 mask 或错误配方；
8. 根据“复读用户原话 / 算术只做了加法 / 混合音频只吐出问句”三类症状，判断失败在编码器、mask、数据配比还是评测层。

“算术只做了加法”值得单独记一笔。模型输出 `8` 而不是 `16`，转写层和指令层都没有完全失败：它听见了“三加五”，也试图执行，只是丢掉了“乘以二”。这是部分执行。Lab 的听写预训配方不会产出 `8`，它会复读整句；若你在自己的真模型探针里看到 `8`，不要把它填进“转写对、指令错”的复读格子，另开一格叫部分执行。Qwen2-Audio 口述 GSM8K 18.4 里混有复读、乱答和部分执行，论文没有拆开这三类，技术报告未公开该明细。本课夹具把复读和部分执行分开，避免你用一个格子吞掉两种机制。

拿到一条失败样例时，追查顺序固定，不要先改学习率。

1. 打印该样本 tokenize 之后的 `input_ids`、`labels`、`M_asr`、`M_if`。若两张 mask 的有效集合相等，问题在 collator，不在模型。
2. 把音频帧数和论文接口对照：10 秒应在 250 帧量级（Qwen2-Audio 40 ms）或 500 帧量级（SALMONN 50 Hz 拼接前）。差一个数量级，先查重采样是不是 16 kHz。
3. 把模型输出同时对转写参考和执行参考打分。只对其中一个打分，等于拒绝本课。
4. 若转写对、执行复读，对照 SALMONN 无激活；查指令样本比例和 $P(\mathbf{Y}\mid\mathbf{X})$ 是否仍由听写主导。
5. 若转写错、执行对，少见，先怀疑评测脚本把执行参考抄进了转写列。
6. 若两列都错，才轮到编码器、解码参数和数据损坏。

这条顺序与第 01 课“先证明 mask，再调学习率”同构，只是 mask 从一张变成两张。把顺序写进实验记录，复盘时才能知道自己跳过了哪一步。

## 5. 原理：边造边讲

七个机制。每个按同一节奏：为什么需要、怎么运转、精确定义、在公开实现里落在哪、怎么证明做对了。它们合起来只回答一句：听懂和转写差在监督区间和评测协议，不差在“有没有把声音送进 LLM”。

Qwen2-Audio 图 2 把三阶段画成预训、SFT、DPO。预训阶段的自然语言提示看起来已经像指令，容易让人以为这一阶段已经在训跟随。提示的作用是告诉模型当前样本要产出听写、译文还是描述，目标仍是那些短文本。SFT 才把目标换成对话回复。DPO 的 $\boldsymbol{y}_w$ 若来自 SFT 同一分布，优化的是回复质量，不是把 WER 再降半个点。读图时把三个箭头旁的目标文本各抄一句，不要只抄阶段名称。Qwen2.5-Omni 的 Thinker 后训同样走 ChatML 对话，音频对话只是其中一桶；若这一桶被做成“用户音频、助手听写”，ChatML 外壳也救不了指令层。

### 5.1 同一段波形，两条监督区间

先把一条训练样本摊开。教学序列长度 $T=20$，位置从 $0$ 计到 $19$。前 6 个位置是音频编码器帧，记作 $a_{0:5}$。位置 6 是用户角色标记。位置 7–9 是文本提示，例如“按语音做事”或“转写这段音频”。位置 10 是助手角色标记。位置 11–15 是这句话的转写：“明天八点开会”被切成 5 个文本 token。位置 16–18 是执行后的回复，例如“已约 08:00”的 3 个 token。位置 19 是结束符，本课约定不进损失。

真实系统里，转写样本往往根本没有 16–18 这一段；指令样本往往没有把转写写进助手回复。教学序列故意把两段都放进同一条，是为了让两张 mask 有机会被画错。能画错，才能证明你画对了。

音频帧只提供条件。Qwen2-Audio 的训练目标写成：在音频表示和已经出现的文本条件下，最大化下一个**文本** token 的概率

$$
\mathcal{P}_\theta\!\left(x_t \mid \boldsymbol{x}_{<t},\,\mathrm{Encoder}_\phi(\boldsymbol{a})\right)
$$

公式里的 $x_t$ 属于文本词表，不属于梅尔谱。SALMONN 把 Whisper 与 BEATs 的 50 Hz 帧在特征维拼接，再经窗口级 Q-Former 变成文本侧 token，送进 Vicuna；这些增强音频 token 同样是条件。Qwen2.5-Omni 的 Thinker 沿用 Qwen2-Audio 的音频前端，把每帧时间 id 对应 40 ms。三种实现都没有要求你对音频帧做文本交叉熵。

角色标记和用户提示默认也不进损失。第 01 课已经说明：把用户问题算进 loss，模型会学模仿提问。语音场景里这件事更糟，因为用户问题可能就是那句要执行的命令。若命令本身进了损失，模型有一条合法的捷径：把命令复读一遍，损失照样下降。

把这 20 个位置写成可打印的表。`A*` 是音频帧，`P*` 是提示 token，`T*` 是听写，`I*` 是执行回复。`y` 列给出本课夹具使用的整数 id，便于和 CPU 实验对表。

真实 10 秒语音按 Qwen2-Audio 的 40 ms/帧大约 250 个条件位置，提示和回复仍是几十个文本 token。教学表把音频压成 6 帧，只为了让你能用眼睛扫完全表。压缩的是条件长度，不是监督逻辑：条件再长，也不该进 $M$。

帧数还可以从公式倒推。设 hop 为 $10$ ms，池化步长为 $2$，则每帧对应 $20$ ms 的 hop 堆积，论文取“大约 40 ms”。$T_{\mathrm{sec}}$ 秒音频的编码器帧数约为 $T_{\mathrm{sec}}/0.04$。SALMONN 的 Whisper 与 BEATs 都是 50 Hz，拼接后仍是 50 帧/秒；窗口 $L=17$ 时，文本侧 token 数约为 $\lceil 50 T_{\mathrm{sec}}/17\rceil\times N$。$N=1$、$T_{\mathrm{sec}}=30$ 时，$\lceil 1500/17\rceil=89$，论文写约 88，差在是否丢弃最后一窗的 padding。无论 88 还是 89，这些位置的 label 仍应是 $-100$。有人按“token 越多监督越强”把它们写进损失，等于要求语言模型预测 Q-Former 的连续查询结果，目标空间都错了。

于是一条序列上至少能画出四个区间：音频条件、提示条件、转写目标、指令目标。后两个区间才允许 mask 为 1，而且通常不同时为 1。纯 ASR 样本在真实数据里没有 $I_{0:2}$ 这一段，整段助手就是 $T_{0:4}$；纯闲聊样本没有把 $T_{0:4}$ 写进助手。教学表把两段都留下，是故意给错误 mask 留空位。能画错，才能证明你画对了。

### 5.2 ASR 交叉熵和指令跟随交叉熵

记忽略索引为 $-100$，与 PyTorch `CrossEntropyLoss` 一致。位置 $t$ 的标签 $y_t$ 要么是真实 token id，要么是 $-100$。有效集合

$$
M=\{t:y_t\neq -100\}
$$

文本交叉熵为

$$
\mathcal{L}(M)=-\frac{1}{|M|}\sum_{t\in M}\log p_\theta(y_t\mid y_{<t},\,\mathrm{Enc}(\boldsymbol{a}))
$$

ASR 样本把 $M$ 取成转写跨度 $M_{\mathrm{asr}}$。指令样本把 $M$ 取成助手执行跨度 $M_{\mathrm{if}}$。本课夹具里

$$
M_{\mathrm{asr}}=\{11,12,13,14,15\},\qquad M_{\mathrm{if}}=\{16,17,18\}
$$

立刻得到三条可核对事实：

1. $M_{\mathrm{asr}}\neq M_{\mathrm{if}}$；
2. $M_{\mathrm{asr}}\cap M_{\mathrm{if}}=\emptyset$；
3. $|M_{\mathrm{asr}}|=5\neq 3=|M_{\mathrm{if}}|$。

音频位置 $\{0,1,2,3,4,5\}$ 与提示位置 $\{6,7,8,9,10\}$ 对两张 mask 都是 $0$。谁若把 $M_{\mathrm{asr}}\cup M_{\mathrm{if}}$ 当成“助手都该学”，有效集合变成 8 个位置，梯度会同时拉听写和执行。听写更短、更确定、在数据里往往更多，于是共享层被听写主导。这就是 SALMONN 说的 intrinsic conditional LM（内在条件语言模型）偏向转写。

手算一条“只会复读”的模型。假设在 $M_{\mathrm{asr}}$ 上正确 token 的概率恒为 $0.80$，在 $M_{\mathrm{if}}$ 上正确 token 的概率恒为 $0.15$。则

$$
\mathcal{L}_{\mathrm{asr}}=-\log 0.80\approx 0.22314,\qquad
\mathcal{L}_{\mathrm{if}}=-\log 0.15\approx 1.89712
$$

同一组 logits，换一张 mask，损失可以差一个数量级。训练日志如果只打印 `loss=0.22`，你不知道自己看的是哪一张表。CPU 实验会输出这两个数，允许误差只来自浮点。

污染实验把标签在 $M_{\mathrm{asr}}\cup M_{\mathrm{if}}$ 上都填上真值，再拿复读模型去算。5 个高概率位置和 3 个低概率位置平均之后，污染损失介于两者之间，看起来“还行”。这正是最危险的状态：标量不报警，指令层已经坏了。

再把手算从“恒定概率”推进到一次真实的 softmax。词表只留 4 个 id：`31, 32, 41, 42`。在位置 16（本该预测 $I_0=41$）上，复读模型的 logits 为

$$
z(31)=2.4,\quad z(32)=2.1,\quad z(41)=0.4,\quad z(42)=0.2
$$

减最大值 $2.4$ 后指数和为 $1+e^{-0.3}+e^{-2.0}+e^{-2.2}\approx 1.870$。正确 token 的概率

$$
p(41)=\frac{e^{-2.0}}{1.870}\approx 0.0724,\qquad -\log p(41)\approx 2.625
$$

在位置 11（本该预测 $T_0=31$）上，把 31 和 41 对调，得到 $p(31)\approx 0.0724$ 的镜像，$-\log p(31)$ 同样约 $2.625$ 吗？不对。复读模型在听写位置会把 31 放在 $2.4$，于是 $p(31)\approx 1/1.870\times 1 \approx 0.535$，$-\log p(31)\approx 0.626$。同一套网络，换位置后损失可以差四倍。CPU 实验用固定概率 $0.80$ 与 $0.15$ 是为了让验收数字不依赖词表排列；你自己排表时，必须先写清该位置的正确 id，再算 softmax。不要拿位置 16 的分布去解释位置 11 的损失。

Qwen2-Audio 在监督微调之后还做 DPO。原文公式为

$$
\mathcal{L}_{\mathrm{DPO}}(\mathcal{P}_\theta,\mathcal{P}_{\mathrm{ref}})
=
-\mathbb{E}_{(\boldsymbol{x},\boldsymbol{y}_w,\boldsymbol{y}_l)\sim\mathcal{D}}
\Bigl[\log\sigma\bigl(
\beta\log\frac{\mathcal{P}_\theta(\boldsymbol{y}_w\mid\boldsymbol{x})}{\mathcal{P}_{\mathrm{ref}}(\boldsymbol{y}_w\mid\boldsymbol{x})}
-
\beta\log\frac{\mathcal{P}_\theta(\boldsymbol{y}_l\mid\boldsymbol{x})}{\mathcal{P}_{\mathrm{ref}}(\boldsymbol{y}_l\mid\boldsymbol{x})}
\bigr)\Bigr]
$$

三元组是 $(\boldsymbol{x},\boldsymbol{y}_w,\boldsymbol{y}_l)$：$\boldsymbol{x}$ 含输入音频，$\boldsymbol{y}_w$ 是更好的回复，$\boldsymbol{y}_l$ 是更差的回复。偏好对仍然落在助手回复上。若 $\boldsymbol{y}_w$ 收集成“更流畅的听写”，DPO 会把指令层再往听写推一把。论文写 DPO 优化的是 factuality 和 desired behavior，没有把 $\boldsymbol{y}_w$ 定义成更低的 WER。引用时不要把 DPO 写成“又训了一轮 ASR”。

偏好对的构造还决定了“期望行为”是哪一层。若标注员看到复读用户原话的回复就标成 $\boldsymbol{y}_l$，看到只输出确认码的回复就标成 $\boldsymbol{y}_w$，DPO 在推指令层。若标注员按“有没有把每个字听写对”打分，DPO 在推转写层。Qwen2-Audio 没有公开这对数据的来源表，技术报告未公开该细节。能确定的只有：损失仍写在 $\mathcal{P}_\theta(\boldsymbol{y}\mid\boldsymbol{x})$ 的回复侧，音频仍在 $\boldsymbol{x}$ 里当条件。第 16 课讲过的参考模型冻结、$\beta$ 过大会把更新压没，本课直接沿用，不再推导。

### 5.3 任务过拟合：转写对了，指令没跟

SALMONN 把训练分成三阶段。预训用大量 ASR 和音频描述，让窗口级 Q-Former 和 LoRA 学会听写与事件描述。指令微调再混进翻译、情感、重叠语音、说话人验证、语音问答等。到这一步，level 1（训练见过的任务）已经能打：无激活时 LibriSpeech / GigaSpeech 的 WER 为 $(2.1, 4.9, 9.1)$，En2Zh BLEU4 为 34.4。level 2 和 level 3（训练没见过的跨模态题）几乎跟不住：口语问答 SQQA 准确率 0.19、跟随率 0.29；讲故事跟随率 0.00；语音与背景声共推理 SAC 准确率 0.02、跟随率 0.04。

论文用贝叶斯公式解释。测试时生成 $\hat{\mathbf{Y}}=\arg\max_{\mathbf{Y}}P_{\boldsymbol{\Lambda}}(\mathbf{Y}\mid\mathbf{X},\mathbf{I})$。写成

$$
P_{\boldsymbol{\Lambda}}(\mathbf{Y}\mid\mathbf{X},\mathbf{I})
=
P_{\boldsymbol{\Lambda}}(\mathbf{Y}\mid\mathbf{X})\cdot
\frac{P_{\boldsymbol{\Lambda}}(\mathbf{I}\mid\mathbf{Y},\mathbf{X})}{P_{\boldsymbol{\Lambda}}(\mathbf{I}\mid\mathbf{X})}
$$

指令微调见过的回复偏短、偏确定，尤其是 ASR 和 AAC。于是无指令的 $P_{\boldsymbol{\Lambda}}(\mathbf{Y}\mid\mathbf{X})$ 峰值就在听写上。新指令 $\mathbf{I}'$ 再怎么写“写一个故事”，只要内在分布把故事的 $\mathbf{Y}$ 压得很低，乘上似然之后仍然赢不过听写。这与“编码器没听清”无关：听写 WER 已经接近 Whisper 参考值 2.2 / 5.1 / 9.2。

他们还做了一个无需第三阶段的探针：把 LoRA 缩放因子从训练时的 4.0 降到大约 2.0。跨模态推理突然出现，音素错误率等听写指标同时变差。这说明听写偏好部分写在 LoRA 里。激活微调的做法是：用缩小后的 LoRA 生成 12 个基于音频的故事，再对原模型做 12 步 teacher forcing。激活之后，SQQA 跟随率 0.98，讲故事跟随率 1.00，SAC 跟随率 0.73；ASR 变为 $(2.1, 4.9, 10.0)$，test-clean 与 test-other 没动，GigaSpeech 略升。听写层基本保住，指令层被唤醒。

对照实验同样锋利。用长听写文本去做所谓激活，SQQA 跟随率仍是 0.28 量级，故事跟随率仍是 0.00。只用文本、不看音频去训故事，也激不活。必须动到 $P(\mathbf{Y}\mid\mathbf{X},\mathbf{I})$，而不是 $P(\mathbf{Y}\mid\mathbf{T}_x,\mathbf{I})$。本课的污染 mask 实验是这件事的缩小版：把听写跨度留在指令样本的损失里，等于继续强化 $P(\mathbf{Y}\mid\mathbf{X})$ 的听写峰。

窗口级 Q-Former 是 SALMONN 能把听写做好的结构原因，也是它容易过拟合听写的结构原因。图像版 Q-Former 用固定 $N$ 个 query 看整张图，输出长度与图的边长无关。音频长度变化几个数量级，固定 $N$ 会把 30 秒语音压成和 1 秒语音同样多的 token，时间分辨率不够做 ASR。SALMONN 把拼接特征 $\mathbf{Z}$ 切成窗

$$
\mathbf{Z}=\mathrm{Concat}(\mathrm{Encoder}_{\mathrm{whisper}}(\mathbf{X}),\mathrm{Encoder}_{\mathrm{beats}}(\mathbf{X}))
$$

再对每个窗独立跑 Q-Former：

$$
\mathbf{H}_l=\mathrm{Q\text{-}Former}(\mathbf{Q},\mathbf{Z}_l),\qquad l=1,\ldots,\lceil T/L\rceil
$$

输出长度随音频变长。$N=1$ 时每窗只出一个文本侧 token，对齐被强制成单调的：第 $l$ 个 token 主要看见第 $l$ 窗。这对 ASR 有利，因为听写本身就是沿时间展开的符号串。代价是：预训一旦以 ASR 为主，这些按时间排好的 token 会和听写符号形成很强的互信息，$P(\mathbf{Y}\mid\mathbf{X})$ 更容易塌到转写。激活微调几乎不动编码器，只改 Q-Former 与 LoRA，正是在动这条互信息，而不是重做声学前端。

LoRA 缩放因子写成 $\frac{\alpha}{r}BA$，SALMONN 取 $r=8$、$\alpha=4.0$。测试时把 $\alpha$ 减半，相当于把已经学到的跨模态适配幅度砍掉一半，Vicuna 原有的长文本生成重新露出来，所以会讲故事，听写变差。这不是可上线的推理技巧，论文也没有把它当作部署开关。它只证明：听写偏好和生成多样性在同一组低秩矩阵里打架。激活微调用 12 个故事、12 步，把打架的结果写回权重，使跟随率上升而 test-clean 的 2.1% 不动。表 4 还比较了只调 LoRA、同时调 Q-Former、用长问答代替故事：故事优于长问答（SAC 0.50 对 0.34，重复率 0.1% 对 4.6%）；只调 LoRA 也能把 SQQA 跟随率拉到 0.96，但 SAC 只有 0.65。写实验记录时要抄清“动了哪些模块”，不要只写“做了激活”。

### 5.4 自然语言提示，以及两种交互不必切系统提示

Qwen-Audio 用层级标签区分任务。Qwen2-Audio 改成自然语言提示，并扩大数据量，目的是缩小预训和后训的缝。预训目标仍是式 (1) 那种下一文本 token，但提示不再是特殊标签栈。论文认为这样更利于泛化和指令跟随。

后训明确写了两种人类交互，并且写明：两种模式联合训练，用户使用时不必靠系统提示切换。

音频分析：用户丢给模型一段语音、声音、音乐或混合音频，指令可以是文本，也可以嵌在音频里。模型要自己切开“哪一段是命令、哪一段是被分析的内容”。论文给的例子是：先有键盘声，再有一句口语“这是什么声音？”，期望直接回答“这是键盘声”。若模型只会转写，助手回复会变成“这是什么声音”，分析失败，转写可以仍然正确。

语音闲聊：用户把模型当成语音对话代理，整段音频就是这一轮用户话。此时转写成文不是目标，目标是下一轮助手文本。同一套权重要覆盖两种用法，靠的是数据里两种回复都出现过，而不是推理时改 `system`。

这对 mask 的含义是：分析样本的 $M_{\mathrm{if}}$ 落在对声音的解释上；闲聊样本的 $M_{\mathrm{if}}$ 落在对话回复上；纯 ASR 样本的 $M_{\mathrm{asr}}$ 落在听写上。三种样本可以共享编码器，不能共享一张“助手全文都算”的表。Qwen2-Audio 还强调：一段音频里可以同时有环境声、多人说话和一句语音命令，模型应直接理解命令并回应。这要求有效目标是命令的回应，不是把整段混响都写成字。

公开推理接口与这个设计一致。`Qwen/Qwen2-Audio-7B` 的示例提示是把音频占位符和一句英文 caption 指令拼在一起；`Qwen2-Audio-7B-Instruct` 走对话消息。训练时若你自己拼数据，不要把占位符 `<|AUDIO|>` 写进 $M$。它和图像 token 一样，是条件。

把键盘例子按时间切开，两层的差别会变成一张日程表。设 0–2 秒是敲击声，2–4 秒是口语“这是什么声音”。编码器在 40 ms 粒度上大约 100 帧。分析任务的助手目标是“键盘敲击声”这类解释；闲聊任务若用户整段都在提问，助手目标是回答；ASR 任务的助手目标是“这是什么声音”。同一 100 帧条件，三种 $M$ 落在三段完全不同的文本上。Qwen2-Audio 图 10 还展示混合音频分析：多人说话、环境声和命令叠在一起。论文没有公开这条样例的 token 级 mask，技术报告未公开该细节。能确定的是：若你把整段混音的听写当作指令样本的目标，模型会学会“把所有声源写成字”，而不是“找出命令并执行”。

两种模式联合训练还有一个评测后果：你不能靠“有没有文本提示”来判断该用哪张参考。用户可能只丢音频。模型必须从音频内部判断这是分析还是闲聊。Lab 里因此给每句语音同时准备转写参考和执行参考，揭晓时两列都显示。配方决定哪一列会错，语音本身不变。这与“换一句更好听的录音就能让指令变对”相反。录音可以完全清晰，指令列仍然复读。

### 5.5 语音指令跟随和文本指令跟随之间的缺口

Qwen2.5-Omni 把“听懂”定义成：口述指令的成绩应当接近同一套题的文本成绩。表 4 把若干纯文本基准里大约 90% 适合口述的题目转成语音，然后让 Qwen2-Audio 和 Qwen2.5-Omni 听语音，让 Qwen2-7B 读文本。

|---|---|---|---|
| MMLU | 69.3 | 33.2 | 65.6 |
| CEval | 78.4 | 38.6 | 61.1 |
| IFEval | 53.3 | 15.6 | 41.7 |
| GSM8K | 82.3 | 18.4 | 85.4 |
| Math23K | 92.3 | 23.0 | 87.1 |
| Math401 | 75.5 | 20.4 | 62.2 |

读这张表时不要做三件错事。第一，不要把 85.4 写成“比文本还强所以语音编码器更懂数学”。论文没有提供该子集上的置信区间，也没有声称语音输入严格超过文本。第二，不要把 Qwen2-Audio 的 18.4 写成“它听不清题面”。它的 Librispeech test-clean 是 1.6%，听写层足够把题面写下来；缺的是把题面当指令来解题。第三，不要忽略 IFEval：Qwen2.5-Omni 41.7 对文本 53.3 仍有缺口。格式约束、否定句、多约束指令，口述之后更难。本课 Lab 里的“只回答数字”“不要回读”就是这类约束的玩具版。

VoiceBench 从另一侧量同一层。Qwen2.5-Omni-7B 平均 74.12，Qwen2-Audio 平均 55.35。分项里 OpenBookQA 81.10 对 49.45，IFEval 52.87 对 26.33。这些题目要求的是按口述要求答题，不是把口述写下来。

Qwen2.5-Omni 的 ASR 并没有全面超过 Qwen2-Audio。表 2 里 Qwen2.5-Omni-7B 的 Librispeech 是 1.6 / 3.5 / 1.8 / 3.4，test-clean 比 Qwen2-Audio 的 1.6 还略差（Omni 为 1.8）。指令层变强不能用“听写更好了”解释。差在后训目标、数据里指令回复的比例，以及 Thinker 是否真的在优化答题文本。Talker、流式 DiT、TMRoPE 的视频交织，本课不展开；那些是生成日程和双工的问题，分别属于第 04 课和第 42 课的范围。本课只借用一句架构事实：Thinker 负责文本，语音指令跟随的损失在 Thinker 的文本头上。

表 4 其余几行用来防止只盯着 GSM8K。CEval 口述 61.1 对文本 78.4，缺口比 MMLU 更大。Math401 62.2 对 75.5，口述之后选择题式的符号运算掉点。IFEval 41.7 对 53.3，说明“按格式输出”在语音条件下更脆。Qwen2-Audio 在这三行是 38.6 / 20.4 / 15.6，缺口不能用“中文 ASR 不行”一笔带过：它的 Aishell2 已经到 3.0 左右，Fleurs-zh 零样本 7.5。题面大概率听得到，步骤做不出来。VoiceBench 的 IFEval 分项把同一现象换成助手基准：52.87 对 26.33。本课 Lab 的“只回答数字”“不要回读我说的话”就是把 IFEval 收成一条可触发的约束。违反约束时，转写列仍可全对。

Qwen2.5-Omni 在 MMAU 上的音频推理平均 65.60，Qwen2-Audio 为 49.20，Gemini-Pro-V1.5 为 54.90。MMAU 分 sound / music / speech。speech 子集 59.76 对 Qwen2-Audio 的 42.04，差距和口述 MMLU 同方向。推理题的参考不是听写。若有人用 MMAU 的 speech 子集去“证明 ASR 更好”，就把第三层评测偷换成了第一层。

Thinker 的文本损失与 Talker 的语音 token 损失在 Qwen2.5-Omni 里是分开的头。本课的 $M_{\mathrm{if}}$ 只允许出现在 Thinker 文本上。把确认码 `7K` 再交给 Talker 读出声，那是生成日程，验收时只看文本是否为 `7K`。seed-tts-eval 上 Qwen2.5-Omni-7B RL 的 test-zh WER 1.42，是合成语音的内容一致性，不是用户语音的 ASR，更不是指令跟随。三张 WER 表（听用户、听自己、听 TTS 评测集）名字相同，对象不同。

### 5.7 推理时没有教练：复读是一条合法的续写

训练用 teacher forcing：算位置 $t$ 的损失时，前缀是真值。若 $M=M_{\mathrm{if}}$，模型在位置 16 看到的历史是音频加提示，目标是 `41`。推理时没有真值前缀，第一步若采样到听写词 `31`，后续会沿着听写句子走下去。暴露偏差（exposure bias：训练时看真值历史，推理时看自己的输出）在纯文本里就存在；语音指令里它有一条特别便宜的通道：用户说过的字已经在音频条件里，复读它们的条件概率天然不低。SALMONN 的 $P(\mathbf{Y}\mid\mathbf{X})$ 峰值在听写上，就是这条通道被训厚了。

因此“转写对、指令错”在推理时比在训练损失上更常见。训练损失可以只在 $M_{\mathrm{if}}$ 上很低，解码温度一高，模型仍跳回听写。Lab 的听写预训配方把这条通道写成规则：执行头直接复制转写参考。污染 mask 配方更阴险：训练时两条通道都有梯度，解码时听写通道因为更短、更确定而先被采样到。指令 SFT 配方把听写通道从助手目标里删掉，执行头才输出 `16`。

约束句把通道堵得更死。“只回答数字”要求第一步就不能进听写词表的常用字。IFEval 口述成绩低于文本，部分来自这种第一步。Qwen2.5-Omni 的 GSM8K 口述 85.4 说明它在数学题上迈出了第一步；同一行 IFEval 41.7 说明约束题还没有同样稳。不要用 GSM8K 一行代替 IFEval 一行。Lab 会议句同时有“不要回读”和“只回确认码”，两条约束缺一就会在执行列看到整句礼貌复述。

把三条教学语音的参考写成固定表，避免评测时改参考。

| 语音 | 转写参考 | 执行参考 | 听写预训时的执行输出 |
|---|---|---|---|
| 算术约束 | 把三加五的结果乘以二，只回答数字 | 16 | 把三加五的结果乘以二，只回答数字 |
| 改会议 | 把会议室改到下午三点，不要回读我说的话，只回确认码 7K | 7K | 把会议室改到下午三点，不要回读我说的话，只回确认码 7K |
| 键盘问句 | 这是什么声音 | 键盘敲击声 | 这是什么声音 |

第三行是唯一转写参考短于执行参考的例子。若有人用“更长短语就是指令”当启发式，这一行会判反。长度不是层。键盘句的执行参考四个字，转写参考五个字，谁更长取决于分词，不取决于任务。

### 5.6 为什么 WER 不能给指令层代言

WER 的定义针对听写：

$$
\mathrm{WER}=\frac{S+D+I}{N}
$$

$S,D,I$ 是相对参考转写的替换、删除、插入，$N$ 是参考词数。参考是“把三加五的结果乘以二，只回答数字”时，模型输出 `16` 的 WER 接近 100%。参考是 `16` 时，模型输出整句原话的 WER 同样很差。同一段模型输出，换一张参考，WER 可以从接近 0 跳到接近 1。所以 WER 不是模型属性，是“输出对哪张参考”的属性。

指令层该用的参考是执行后的回复。数学题的参考是数字或带推导的答案；改会议的参考是确认码或结构化动作；混合音频的参考是对声音的解释。AIR-Bench chat 用 GPT-4 按 speech / sound / music / mixed 四维打 0–10 分，Qwen2-Audio 明确写：他们发现不少旧 SLU / SER 测试集很难反映真实交互，所以主要看 AIR-Bench。Qwen2.5-Omni 则同时保留 ASR 表和口述答题表。两张表并列，才叫把两层都测了。

级联系统“先 ASR 再文本 LLM”会把错误传播写进指令层。SALMONN 在未训练过的 En2De / En2Ja 上超过 Whisper+Vicuna 的级联参考（BLEU4 18.6 / 22.7 对 16.5 / 15.6，激活后），用来支持端到端能保住韵律等非字面信息。本课不把这句话扩展成“级联已经过时”。它只说明：即便级联的 ASR WER 很低，指令层仍可能因为错误传播或信息丢掉而失败；端到端也仍可能因为 mask 被听写霸占而失败。两种失败都要单独测。

级联还有一种本课必须点名的假成功。先把“把三加五的结果乘以二，只回答数字”听写成文，再送给文本 LLM，文本 LLM 输出 `16`。端到端模型复读原句。表面上级联赢了。把同一管道接到键盘例子上：ASR 输出“这是什么声音”，文本 LLM 没有键盘声可听，只能空答或幻觉。端到端若 mask 画对，可以直接说“键盘敲击声”。假成功来自“命令本身就是一句完整的文本题”；真失败出现在“命令必须看见听写丢掉的声学事件”。Qwen2-Audio 把分析和闲聊放进同一权重，正是为了覆盖第二种。评测集里没有混合音频，就测不出这种假成功。

SALMONN 的 level 3 把第二种做成 SAC：口语问题嵌在音频里，证据在背景声或音乐中。无激活时准确率 0.02、跟随率 0.04，几乎等于不会做；激活后 0.50 / 0.73。参考系统 Whisper+Vicuna 在 SAC 上没有给出可引用的参考值，表 2 该格为空白。不要补一个“级联肯定能做”的数字。空白就是空白。本课 Lab 的键盘句是 SAC 的缩小版：转写参考是问句，执行参考是声源名。配方为听写预训时，执行列应吐出问句。

## 6. 在公开实现中定位这些机制

本课没有 MiniMind-O 源码可改。机制落在三份公开实现里。读代码时只追 mask、提示和评测，不追 codec 解码器。

**Qwen2-Audio。** 官方仓库是训练与演示入口。Transformers 文档里的推理类是 `Qwen2AudioForConditionalGeneration`，处理器 `AutoProcessor`。基座示例把

```text
<|audio_bos|><|AUDIO|><|audio_eos|>Generate the caption in English:
```

和波形一起送进处理器。Instruct 示例把多轮消息交给 chat template，音频作为内容块而不是文本子串。自己做 SFT 时，应对齐这套模板之后再画 mask：`<|AUDIO|>`、role 标记、用户侧文本全部 `-100`；助手侧再按样本类型选择 $M_{\mathrm{asr}}$ 或 $M_{\mathrm{if}}$。论文写明音频前处理：16 kHz、128 通道梅尔、25 ms 窗、10 ms 跳步、池化步长 2。核对特征长度时，用“约 40 ms 一帧”估：10 秒音频大约 250 帧条件 token，这些帧不应出现在 `labels != -100` 的计数里。

**SALMONN。** 仓库实现双编码器拼接、窗口级 Q-Former 和 Vicuna 上的 LoRA。论文超参：$N=1$ 个可学习 query，窗长 $L=17$ 帧，约 0.33 秒一窗，30 秒音频约 88 个文本侧 token；LoRA rank 8、缩放 4.0；只更新 Q-Former 与 LoRA。读训练脚本时核对三件事：预训是否以 ASR + AAC 为主；指令微调的任务表是否与论文表 1 一致（约 4400 小时、约 230 万条）；激活阶段是否真的只用少量长回复。若有人把激活数据换成更长的听写，对照论文表 4，那不应被叫做激活。

**Qwen2.5-Omni。** 仓库与 `Qwen/Qwen2.5-Omni-7B` 提供 Thinker–Talker 的推理入口。本课只打开 Thinker 的文本损失与语音指令评测。音频编码器与 Qwen2-Audio 同源：16 kHz、128 通道梅尔、40 ms 一帧。流式侧把音频编码器改成约 2 秒一块的块内注意力，这是为了预填充和首包延迟，不是为了改 WER。不要在本课把它写成“指令跟随的关键发明”。指令跟随的证据在表 3、表 4 和 VoiceBench，不在块大小。

块内注意力对 mask 有一个间接影响：2 秒一块时，长音频被切成若干条件块，块与块之间的编码器不再做全序列自注意。条件变了，目标还是文本。有人把块边界当成损失边界，在每块末尾插一个假的听写 token，等于把流式工程写进监督。论文没有这样写。块是编码器的感受野限制，label 仍然只在助手文本上。本课 CPU 实验没有块，因为 $T=20$ 里只有 6 个音频位置。真系统打印帧数时，按块加总应等于整段帧数，缺块或重块先查切分，再查损失。

三份实现共同的体检命令是打印三类计数：音频条件 token 数、文本条件 token 数、有效目标 token 数。有效目标还要再拆成听写与指令。缺这一拆，`num_valid_tokens` 再漂亮也没有本课的信息。

建议在 collator 出口处打这样一份 JSON，字段名可改，语义不能并：

```json
{
  "sample_id": "chat_000017",
  "task": "chat",
  "n_audio_cond": 250,
  "n_text_cond": 12,
  "n_asr_valid": 0,
  "n_if_valid": 3,
  "n_label_not_minus_100": 3,
  "asr_positions": [],
  "if_positions": [262, 263, 264]
}
```

断言必须有三条：`n_label_not_minus_100 == n_asr_valid + n_if_valid`；`task=="chat"` 时 `n_asr_valid==0`；`asr_positions` 与 `if_positions` 的集合不相等（聊天样本里前者为空、后者非空，已经不相等；ASR 样本反过来）。若你的框架把 `-100` 以外的 id 都算进一个 `num_valid`，把这条拆开重写。第 01 课的 trace 纪律在这里具体化为“有效集合可打印”。

Qwen2-Audio 的 Instruct 对话还允许用户消息里同时出现文本和音频。此时文本可能是“请分析”，音频可能是一段会议录音。$M_{\mathrm{if}}$ 落在分析结论上，会议录音的听写可以另存一列供人工抽查，但不进损失。基座模型的 caption 提示则是 ASR / AAC 近亲：$M_{\mathrm{asr}}$ 或描述跨度才合法。两套模板混用时，最常见的 bug 是 Instruct 样本误用了基座的 caption 损失，于是闲聊被训成描述。打印 `task` 字段就是为了抓住这种混用。

SALMONN 仓库里 LoRA 缩放若暴露成推理参数，不要在验收里扫它来“提高跟随率”。论文图 3 把那条曲线当作存在性证明：缩放降到约 2.0 时 emergent 能力突然出现，听写同时变差。部署应使用激活后的权重，而不是现场打折。本课 Lab 的 `lora-discount` 配方只模拟这条曲线的方向：转写列开始出现替换错误，执行列变得能跟但啰嗦。它不是第三种可上线 recipe。

## 7. 数据与训练 recipe

公开论文的数据量只作引用，不作本课必须复现的预算。SALMONN 预训：LibriSpeech 960 小时加 GigaSpeech-M 1000 小时做 ASR，WavCaps / AudioCaps / Clotho 做音频描述（WavCaps 去掉长于 180 秒的片段）。指令微调表 1 合计约 4400 小时、约 230 万条，覆盖 ASR、En2Zh、AAC、音素、情感、音乐描述、重叠语音、说话人验证、性别、三类问答。激活只用 12 个故事、12 步。Qwen2-Audio 用图 3 展示预训小时数，正文没有把每一类任务的小时数写成可抄的整数表；技术报告未公开该明细时，不要编。Qwen2.5-Omni 第二阶段写了约 8000 亿图像视频相关 token、3000 亿音频相关 token、1000 亿带音频视频 token，以及文本语料；后训使用 ChatML，含纯文本、视觉、音频和混合对话。这些数字说明指令数据是单独一笔预算，不是 ASR 语料的副产品。

三篇论文的接口可以压成一张对照表，只放正文出现过的数字，方便以后引用时回查表号。

| 项 | SALMONN | Qwen2-Audio | Qwen2.5-Omni-7B |
|---|---|---|---|
| 音频前端 | Whisper-Large-v2 + BEATs，50 Hz | Whisper-large-v3，约 40 ms/帧 | 沿用 Qwen2-Audio |
| 连接 | 窗口 Q-Former，$N=1$，$L=17$ | 编码器帧直接进 LLM | 同左，另有 TMRoPE 时间 id |
| 语言模型 | Vicuna-13B 冻结 + LoRA | Qwen-7B，总 8.2B | Qwen2.5 Thinker |
| 可训练比例 | 约 33M，0.24% | 编码器与 LLM 均可训（报告未逐层公开冻结表） | 多阶段解冻，见原文第 3 节 |
| 听写例 | LS 2.1 / 4.9 | LS 1.6 / 3.6 | LS 1.8 / 3.4 |
| 指令例 | 激活后 Story FR 1.00 | AIR-Bench 7.18 / 6.99 / 6.79 / 6.77 | 口述 MMLU 65.6，VoiceBench 74.12 |
| 模式切换 | 文本指令 | 分析与闲聊联合训，无系统提示切换 | ChatML 多模态对话 |

“编码器与 LLM 均可训”这一格，Qwen2-Audio 原文写 $\theta$ 与 $\phi$ 都是可训练参数，没有给出类似 SALMONN 的 0.24% 冻结表。技术报告未公开该冻结明细时，不要写成“全部解冻”或“全部冻结”。能写进左栏的只有公式 (1) 里两个参数符号都出现。

表的最后一行决定推理时你要不要手动改 `system`。SALMONN 靠提示词区分任务，提示写错就会触发过拟合出听写。Qwen2-Audio 声明不必为分析和闲聊准备两套系统提示。产品若仍在网关里写死“你是转写器”，等于在推理侧把 $M_{\mathrm{asr}}$ 又缝回去。本课不评测网关，但诊断表里“解码前缀泄漏转写”包含这种缝法。

Whisper-large-v3 在本课里只当编码器初始化，不当完整 ASR 系统。Radford 等的 Whisper 用弱监督多任务训练，编码器输出确实同时含语音内容和部分背景信息，SALMONN 引用 Gong 等 Whisper-AT 来支持“噪声也在特征里”。Qwen2-Audio 把它升级到 large-v3，并加 128 通道梅尔。这些事实解释为什么同一前端既能做听写也能做分析：特征里本来就有非字面信息。它们不能解释为什么 SFT 之后仍会复读。复读是文本头和 mask 的问题。有人看见 Whisper 初始化就说“这个模型本质是 ASR”，等于把初始化当成了监督。初始化提供条件空间，监督决定在这个空间上预测什么。

BEATs 那一路更极端。它为非语音事件做迭代自监督，SALMONN 用它补 Whisper 不擅长的音频事件。拼接后的 $\mathbf{Z}$ 同时看见字面和事件。若指令样本的目标仍是听写，BEATs 的梯度会被浪费在“把事件特征映射成空听写”。激活微调能叫醒讲故事，部分因为故事目标允许使用事件特征。键盘句的执行参考“键盘敲击声”必须能从 BEATs 或 Whisper 的噪声通道里读出来；只开 ASR 头读不出来。本课 Lab 没有真的 BEATs，只是用规则把分析任务的执行列写成声源名。真模型探针时，关掉 BEATs 再跑键盘句，若执行列崩溃、算术句不变，就可以把失败分到非语音编码器，而不是 mask。SALMONN 的消融没有把这一刀写成可引用的表，技术报告未公开该明细。你自己的缩小实验可以做，论文数字不能编。

Qwen2-Audio 没有 BEATs，单编码器仍能在 VocalSound 上到 0.9392、AIR-Bench sound 到 6.99。单编码器路线把事件和语音塞进同一 Whisper 族特征。本课不裁决双编码器是否必要。验收只要求：事件类指令的有效集合仍是解释文本，不是事件标签的听写。类别名当目标时，那是分类，应另开计数器，见第 9 节。

本课教学 recipe 只承认四种样本，字段必须能画出 mask。

| 样本类型 | 音频里有什么 | 用户侧文本 | 助手目标 | 有效集合 |
|---|---|---|---|---|
| 纯 ASR | 读稿语音 | “转写这段音频” | 听写 | $M_{\mathrm{asr}}$ |
| 语音闲聊 | 用户命令 | 可空 | 执行后的回复 | $M_{\mathrm{if}}$ |
| 音频分析 | 环境声或混合声，命令可嵌在音频里 | 可选文本问题 | 对声音的解释或回答 | $M_{\mathrm{if}}$ |
| 污染对照 | 与闲聊相同 | 与闲聊相同 | 听写拼接回复 | $M_{\mathrm{asr}}\cup M_{\mathrm{if}}$（故意错误） |

最小合法字段：

| 字段 | 要求 |
|---|---|
| `id` | 稳定主键 |
| `audio_path` 与采样率 | 16 kHz 或写明重采样 |
| `transcript` | 字面听写，可空仅当样本声明不是 ASR |
| `instruction_text` | 文本提示；语音闲聊可空 |
| `assistant_target` | 该样本真正要学的回复 |
| `task` | `asr` / `chat` / `analysis` / `contaminated` |
| `mask_span` | 在 tokenize 之后写入的闭区间，能复原 $M$ |

`assistant_target` 不得默认等于 `transcript`。闲聊样本里 `transcript` 仍建议保留，供评测层单独算 WER，但不进入训练 label。分析样本里，若音频同时包含问句和环境声，`transcript` 只覆盖口语问句，`assistant_target` 覆盖对声音的回答。Qwen2-Audio 的键盘例子按这一行写。

配比是 recipe 的另一半。SALMONN 预训几乎全是听写和描述，所以必须靠激活把 $P(\mathbf{Y}\mid\mathbf{X})$ 拉回来。Qwen2-Audio 强调 SFT 数据的质量、数量和复杂度，再加 DPO。教学上从听写:指令 $=4:1$ 起，盯住两列指标：ASR 的 WER，指令的精确匹配或 GSM8K 式数字准确率。只降 WER 就加指令样本，不要先加学习率。按条数抽样时，一条 30 秒分析音频的条件 token 远多于一条短闲聊；第 15 课的 token 配平在这里同样适用。本课 CPU 实验不抽样，只固定一条长度为 20 的序列。

许可与泄漏：LibriSpeech、CoVoST2、AIR-Bench 引用的 Fisher / SpokenWOZ / IEMOCAP / Common Voice / Clotho / MusicCaps / AudioCaps，评测前要确认训练排除列表。Qwen2-Audio 写明评测集从训练中严格剔除。你若微调开源音频语言模型，先读对应卡片，不要把 AIR-Bench 的源音频混进 SFT。

SALMONN 表 1 的小时数还可以用来估计“听写霸占”有多严重。ASR 两项合计约 1180 小时、约 48 万条；SQA 又用 LibriSpeech 960 小时生成问答，本质上仍在同一批语音上。真正的闲聊式长回复，要等到激活阶段的 12 个故事。指令微调名义上有约 230 万条，里面音素识别 28 万、说话人验证 52 万，目标都是短而确定的标签。短标签和听写一样，会把 $P(\mathbf{Y}\mid\mathbf{X})$ 推向低熵。激活之所以便宜，是因为它专门对抗这种低熵，而不是再堆 100 万条 ASR。

教学混合若要看见同一方向，不必上百万条。下面这张表只用于本课缩小实验，禁止拿去改写论文小时数。

| 桶 | 目标层 | 起点条数占比 | 损失 |
|---|---|---|---|
| A 读稿听写 | $M_{\mathrm{asr}}$ | 0.50 | $\mathcal{L}_{\mathrm{asr}}$ |
| B 语音闲聊 / 约束执行 | $M_{\mathrm{if}}$ | 0.30 | $\mathcal{L}_{\mathrm{if}}$ |
| C 混合音频分析 | $M_{\mathrm{if}}$ | 0.15 | $\mathcal{L}_{\mathrm{if}}$ |
| D 污染对照 | $M_{\mathrm{asr}}\cup M_{\mathrm{if}}$ | 0.05 | 只作反事实，正式训练必须为 0 |

桶 D 永远不应进入“发布权重”的配比。它存在于课程里，是为了让你能复现“转写对、指令错”。正式训练把它留在 0，评测时再用同一批语音跑一遍“假如 mask 画错”的反事实，损失数字会介于 $\mathcal{L}_{\mathrm{asr}}$ 与 $\mathcal{L}_{\mathrm{if}}$ 之间。CPU 实验的 `contaminated_ce` 就是这个夹具。

token 配平按第 15 课的口径。设桶 A 平均 40 个有效听写 token，桶 B 平均 8 个执行 token。条数各半时，听写 token 占 $40/(40+8)\approx 0.83$。优化器看到的世界仍是听写。要让两层有效 token 接近，桶 B 的条数需要大约 5 倍于桶 A，或对 $\mathcal{L}_{\mathrm{if}}$ 乘上相应权重。权重是最后一招：先打印两层的有效 token 计数。Qwen2-Audio 没有公开这一计数，技术报告未公开该细节。你自己的缩小实验必须打出这两列。

合成口语指令时，约束要写进 `assistant_target`，不要只写进 `instruction_text`。例如用户说“只回答数字”，目标就应是 `16`，而不是“好的，三加五等于八，乘以二等于十六”。IFEval 类失败常常来自目标写得太客气。Qwen2.5-Omni 表 4 的 IFEval 口述 41.7，已经说明客气回复在语音条件下更难被压住。Lab 的会议句把目标收成 `7K`，就是把客气话从监督里删掉。

## 8. 按依赖顺序执行实验

实验分三层。第一层必须在无 GPU 时通过。第二层是浏览器教具。第三层只有在你真的加载公开权重时才跑，数字要带模型名和是否 Instruct。

### Step 1: CPU 机制实验

在 `experiments/` 下核对隔离脚本（本课不改 `registry.py`，编排者接入后再改成总入口）：

```bash
PYTHONPATH=src python3 -c "from learn_omni_experiments.lessons.lesson_43 import run; print(all(run()['checks'].values()))"
```

预期打印 `True`。失败时看 `checks` 里哪一条是 `False`：两集合是否不相等、是否不相交、音频与提示是否都排除、复读模型是否低 ASR 损失高指令损失、污染集合是否为真超集、有效计数是否不等。

手算应能对上 `metrics` 里的这两个损失。$-\log 0.80$ 与 $-\log 0.15$ 用任意科学计算器即可。若你的实现先对整段序列做平均再乘 mask，会把条件位置的 0 算进分母，数字会对不上。必须先筛 $t\in M$，再平均。

### Step 2: 对照手算整条序列

把第 5.1 节的 20 个位置抄成三行：`role`、`label`、`mask_asr` / `mask_if`。确认：

- 位置 0–5 的 label 均为 `-100`；
- 位置 11–15 仅在 ASR 表上为 1；
- 位置 16–18 仅在指令表上为 1；
- 两张表的 1 的个数是 5 和 3。

再构造一组“复读”logits：在转写位置把正确 token 的 logit 设高，在指令位置把听写词的 logit 设高、把正确动作词设低。分别用两张 mask 算 $\mathcal{L}$。指令损失必须明显高于 ASR 损失。这一步不过，不要进教具：教具只是把同一规则换成可点选的句子。

CPU 实验还会返回污染集合的大小。正确关系是

$$
M_{\mathrm{asr}}\cup M_{\mathrm{if}}
\supsetneq
M_{\mathrm{asr}},
\qquad
M_{\mathrm{asr}}\cup M_{\mathrm{if}}
\supsetneq
M_{\mathrm{if}}
$$

元素个数 $8=5+3$。若你的实现把结束符也标进污染集合，个数会变成 9，`checks` 应失败。结束符是否进损失属于另一条约定：本课夹具规定位置 19 为 `-100`，与“只对内容 token 算账”一致。公开训练脚本有时把 `<eos>` 算进去，那是他们的约定，写入笔记左栏时要抄原文，不要和右栏的 8 混用。

复读模型在 $M_{\mathrm{asr}}$ 上的平均损失是 $-\log 0.80$，在 $M_{\mathrm{if}}$ 上是 $-\log 0.15$，在污染集合上是 5 个听写项与 3 个执行项的加权平均：

$$
\mathcal{L}_{\mathrm{mix}}=\frac{5(-\log 0.80)+3(-\log 0.15)}{8}\approx 0.8509
$$

这个数看起来“正常”，因为它被听写项拉低了。这就是为什么只盯标量会漏掉指令层。CPU 实验把三个损失都写进 `metrics`，验收时比较的是不等式 $\mathcal{L}_{\mathrm{asr}}<\mathcal{L}_{\mathrm{mix}}<\mathcal{L}_{\mathrm{if}}$，不是某一个绝对值是否小于 1。

把 8 个有效位置的单项损失列成表，复读模型在听写位置用 $p=0.80$，在执行位置用 $p=0.15$：

| $t$ | 属于 | $p(y_t)$ | $-\log p$ |
|---|---|---|---|
| 11 | $M_{\mathrm{asr}}$ | 0.80 | 0.22314 |
| 12 | $M_{\mathrm{asr}}$ | 0.80 | 0.22314 |
| 13 | $M_{\mathrm{asr}}$ | 0.80 | 0.22314 |
| 14 | $M_{\mathrm{asr}}$ | 0.80 | 0.22314 |
| 15 | $M_{\mathrm{asr}}$ | 0.80 | 0.22314 |
| 16 | $M_{\mathrm{if}}$ | 0.15 | 1.89712 |
| 17 | $M_{\mathrm{if}}$ | 0.15 | 1.89712 |
| 18 | $M_{\mathrm{if}}$ | 0.15 | 1.89712 |

五行平均就是 $\mathcal{L}_{\mathrm{asr}}$，三行平均就是 $\mathcal{L}_{\mathrm{if}}$，八行平均就是 $\mathcal{L}_{\mathrm{mix}}$。表比标量难造假：若有人把位置 16 的 $p$ 改成 0.80 却仍声称这是复读模型，表会自相矛盾。CPU 实验的概率是写死的常量，不允许随机。你若改概率，必须同时改 `checks` 里的不等式阈值，并在笔记右栏声明这是另一套夹具。

指令 SFT 模型把表下三行的 $p$ 改成 0.80，上五行保持 0.80，两条损失都会低。这是“两层都对”的训练态，对应 Lab 的指令 SFT 配方。它不能取消“必须先构造转写对、指令错”的验收：验收要的是你能制造失败，不是只能看到成功。SALMONN 无激活的权重就是失败态；有激活的权重才是成功态。只提交成功态，等于没证明你理解失败来自哪张 mask。

### Step 3: 浏览器教具

打开本课页面的 Lab。同一句语音会同时走转写头和指令头。先在四个选项里选一句预测：两边都对 / 转写对指令错 / 转写错指令对 / 两边都错。未选预测时不能揭晓。揭晓后才显示两头输出、两张有效集合和两条交叉熵。

验收必须触发“转写对、指令错”。配方选“只做听写预训”或“污染 mask”，任务选“执行指令”，三句语音里任意一句都应出现：听写与参考一致，执行回复变成复读、只做了加法、或只吐出问句。把配方改成“指令 SFT”之后，同一句语音的执行头应变成 `16`、`7K` 或“键盘敲击声”。教具标题写明教学模拟。

建议顺序：配方先放听写预训，选“转写对、指令错”，揭晓转写列和执行列；再换污染 mask，确认有效集合变成两段的并；然后换指令 SFT，确认指令损失下降且回复变成执行结果。中途改预测或改旋钮会清空揭晓，防止先看数字再选答案。

教具内部用规则，不用网络。听写预训：转写输出等于转写参考，执行输出等于转写参考。污染 mask：转写输出仍对，执行输出变成转写参考加一个被截断的动作碎片，有效集合显示为两段的并。指令 SFT：两列都等于各自参考，有效集合只含执行跨度。LoRA 打折：转写参考里替换一个词，执行输出能跟但带一句多余的礼貌前缀。四条规则都能在纸上复述。揭晓后的交叉熵来自第 8 节的 $-\log 0.80$ 与 $-\log 0.15$，不是模型前向。若页面数字和手算差一个数量级，先查你有没有把自然对数看成以 10 为底。

三句语音的设计意图不同。算术句测约束：执行参考是单个数字，任何复读都立刻可见。会议句测否定：执行参考是确认码，礼貌复述会同时违反“不要回读”和“只回确认码”。键盘句测分析：转写参考是问句，执行参考是声源，级联假成功会在这一句上露出。Gate 不要求三句都点一遍，但要求至少一句触发转写对、指令错。建议三句都看，因为三种失败在诊断表里对应不同行。

预测选项与配方的合法对应也写死，避免“随便选一个也能过”。听写预训加执行任务，揭晓后应是转写对、指令错；你若预测“两边都对”，揭晓仍显示失败态，Gate 只在你确实触发了该失败态后变绿，预测对错另外记录。课程要的是看见失败，不是考你猜配方。预测的作用是强迫你在看数字前先站队，防止把输出当标准答案倒推机制。

### Step 4: 可选，公开权重的双协议探针

仅当你已经能加载 `Qwen2-Audio-7B-Instruct` 或 `Qwen2.5-Omni-7B` 时才做。固定三条本地语音，与教具同一文案：算术约束、改会议加“不要回读”、键盘声加问句。每条语音问两次，提示分别是“转写这段音频”和“按语音指令回答”。记录：转写是否与参考一致；执行是否遵守约束。此步失败只说明权重、解码或预处理有问题，不能回写 Step 1 的集合不等式。不要把三条样本的成功率写成论文数字。

Qwen2.5-Omni 若同时出声，关掉 Talker 或忽略波形，只看 Thinker 文本。本课不评测语音合成的 WER。

### Step 5: 写实验记录

记录序列原文、两张 mask、两条损失、教具配方、是否找到转写对指令错。任何数字必须能从序列重新算出来。建议表格：

| 项 | ASR mask | 指令 mask | 污染 mask |
|---|---|---|---|
| 有效位置 | 11–15 | 16–18 | 11–18 |
| 有效个数 | 5 | 3 | 8 |
| 复读模型损失 | $\approx 0.223$ | $\approx 1.897$ | 介于两者之间 |
| 教具对应配方 | 听写预训 | 指令 SFT | 污染 mask |

互动实验通过后，把页面上的两段输出和两个集合抄进同一张表。集合必须和上表同位置。若页面在“指令 SFT”下仍显示复读，说明揭晓时配方旋钮还停在听写预训。

Gemini-1.5-pro 在 AIR-Bench 上因安全策略少返回约 1/5 样本，Qwen2-Audio 论文写了这条限制。SALMONN 自己的 level 2/3 用跟随率 FR：激活前讲故事 FR 为 0.00，激活后为 1.00。FR 测的是“有没有按指令的类型来答”，不是故事写得好不好。论文对 Story 的 diversity 只统计不同词的个数，并声明这不代表质量。

测量协议卡建议至少四列：输入模态（语音 / 文本）、目标层（转写 / 指令）、参考文本、指标。缺一列，就把 WER 和 GSM8K 写进同一格了。第 47 课会把六类评测横着比的禁令写得更完整；本课先把音频内部的两层拆开。

CoVoST2 的 BLEU 属于转写层的近亲：语音到文本翻译。Qwen2-Audio 在 en-de / de-en / en-zh / zh-en 上为 29.9 / 35.2 / 45.2 / 24.4，高于 SALMONN 在论文表 2 里给出的 18.6 / — / 33.1 / —。翻译的参考是目标语言句子，不是源语言听写，但它仍然要求“把语音里的命题写出来”，不要求“按命题去改日程”。不要把 BLEU 上升写成 VoiceBench 上升。情感识别 MELD 准确率 Qwen2-Audio 0.553、Qwen2.5-Omni 0.570、SALMONN 激活后 0.69（IEMOCAP Session 5，不同测试集，不能横着比出“谁更会共情”）。VocalSound 上 Qwen2-Audio 与 Qwen2.5-Omni 都是 0.939 量级，这是分类，参考是类别名。分类对了，仍可能不会执行“听到咳嗽就暂停会议”这种指令。把分类头接到指令样本上当辅助损失是允许的，但辅助损失的有效集合是类别 token，与 $M_{\mathrm{if}}$ 仍然不是同一个集合。CPU 实验不覆盖辅助头，课文只要求你在自己的脚本里给辅助头另开计数器。

AIR-Bench 的 GPT-4 打分范围 0–10，四维分开报。Qwen2-Audio 在 music 上从 Qwen-Audio 的 5.52 拉到 6.79，这一跳与 Librispeech 无关。Mixed-Audio 6.77 对 Gemini-1.5-pro 的 5.27，对应的是键盘例子那种叠音，正是本课分析样本要测的层。引用时抄四维，不要只抄平均值再宣称全面领先。Gemini 少返回约 1/5 样本，分母不同，论文自己写了，转述时不能删。

口述子集的星号也要进协议卡。Qwen2.5-Omni 表 4 写 approximately 90% of text instructions suitable for speech。剩下约 10% 可能含公式、表格或不宜上口的符号。你自己用 TTS 生成口述题时，同样要有剔除规则，否则分母里会留下合成失败的题目，口述准确率被无声或乱码拉垮，看起来像指令层崩溃，其实是数据管道。本课不提供 TTS。协议卡上写“未跑 TTS”即可。

## 11. 根据症状定位失败环节

| 症状 | 先查 | 不要先做 |
|---|---|---|
| WER 很低，口述 GSM8K 接近随机 | 指令样本比例、 $M_{\mathrm{if}}$ 是否其实盖在听写上 | 换更大的音频编码器 |
| 一问“写故事”就输出短听写 | SALMONN 式任务过拟合；$P(\mathbf{Y}\mid\mathbf{X})$ 是否被 ASR 霸占 | 降 ASR 学习率 |
| 混合音频只复述问句，不解释键盘声 | 分析样本的目标是不是写成了问句转写 | 加更多 Librispeech |
| 算术题输出整句原话，约束“只回答数字”被忽略 | IFEval 类约束数据是否存在；解码是否带了 ASR 提示 | 调温度 |
| 算术只做了加法，得到 8 而不是 16 | 指令层部分执行，仍不是转写失败 | 报 WER |
| 训练 `loss` 很低，两张 mask 打印出来却是同一段 | collator 把助手全文标成 1 | 加大 batch |
| 有效 token 计数接近序列长度 | 音频帧或提示被算进损失 | 改连接器 |
| LoRA 缩放减半后会讲故事，听写变差 | 听写写进了 LoRA；考虑激活微调而不是直接部署缩小版 | 认定编码器坏了 |
| 文本 MMLU 正常，口述 MMLU 掉一截 | 语音指令数据与 Thinker 文本头，不是 Talker | 重训 codec |
| 级联 ASR+LLM 答题对，端到端复读 | 端到端 mask / 任务配比 | 宣称级联永远更好 |
| AIR-Bench 高，VoiceBench IFEval 低 | 约束跟随与闲聊不是同一分布 | 用 AIR-Bench 四维平均代替一切 |

定位时始终带两列输出。只有转写列、没有执行列，表格本身就是故障。

同一症状还可以按“训练看得到、推理看不到”再拆一刀。训练日志里 $\mathcal{L}_{\mathrm{if}}$ 已经很低，推理却复读：先查解码前缀有没有泄漏转写，再查 temperature / top-p 是否把概率质量还给了听写词。训练日志里 $\mathcal{L}_{\mathrm{if}}$ 一直高：先查 $M_{\mathrm{if}}$ 是不是空集，再查目标文本是否其实等于 `transcript`。空集的典型原因是 collator 把整段助手标成 `-100`，只留下音频条件；此时总损失可能来自别的任务，看起来在降。CPU 实验把空 mask 当成非法：`|M_{\mathrm{if}}|=3`，不能为 0。

还有一种“两列都对、验收仍应失败”的假象：执行参考被写成了转写。会议句若把执行参考改成整句原话，听写预训配方会显示两边都对。Gate 要求的是转写对、指令错，这条假象过不了，因为执行列与转写列字符串相等，教具会把它判成“没有指令层”。写自己的评测脚本时，加一条断言：执行参考不得等于转写参考。键盘句、算术句、会议句都满足。

硬件侧的误判也很常见。有人看见 7B 放不进 12 GB 卡，就说“本课做不了”。本课主路径是 CPU 集合实验加浏览器教具。放不进卡只影响 Step 4。Step 4 失败不得回写 Step 1。Qwen2.5-Omni 官方还提供低显存示例目录，那是推理工程，不是指令跟随机制。不要把 OOM 写成 mask 错误。

- 若做了 Step 4，三条双协议探针的原始解码文本。

不要交付：新的 codec 排名、Talker 延迟曲线、把三条本地样本写成“复现了 85.4”。

实验记录的文件名建议带日期和 git commit，不要叫 `final.xlsx`。两列指标分两个工作表或两个 JSON 字段：`asr` 与 `instruction`。字段里至少有参考文本、模型输出、指标名、指标值、mask 有效个数。缺 mask 有效个数的记录，一个月后无法证明当时集合不相等。CPU 实验的返回字典已经按这个最小字段排好，抄它即可，不必另发明格式。

若你要把本课接进 MiniMind-O 的联合 SFT，只改 `labels` 的构造函数，不要新开一套音频编码器。SenseVoice 仍然可以并行跑，当作转写列的对照系统：同一条用户语音，SenseVoice 给出 WER，Thinker 给出执行文本。两列日志并排，才叫把第 01 课的 trace 用到了指令层。禁止把 SenseVoice 的字符串写进 Thinker 的 `labels` 又声称这是端到端指令跟随。那是级联，级联可以是产品选择，不能冒充本课机制。第 02 课的 connector 若把音频帧投进 Thinker，投影层的参数计入可训练计数，仍不计入有效目标集合。投影是条件通路上的矩阵，不是 mask 上的 1。connector 训得好，只说明音频帧能被读懂；读懂之后预测听写还是预测执行，仍由 $M$ 决定。第 02 课比较三种 connector，本课不重做那场消融。把 connector 换成 Perceiver 或 Q-Former，两张 mask 的集合不等式必须仍然成立，否则你只是换了一条更贵的复读通路。读完[第 02 课](02_multimodal_connector.md)的人容易把“对齐到 LLM 词嵌入维”当成已经会听指令。对齐只解决条件能不能被注意力看见。看见之后算哪一段的交叉熵，是本课的题目。两课的验收互不替代：connector 消融过了，仍要交两张 mask 的集合不等式。把这件事写进第 02 课笔记的页边：投影 $W$ 改变的是条件，不改变 $M_{\mathrm{asr}}$ 与 $M_{\mathrm{if}}$ 是否相等。页边不写新数字，只写这一句判断，避免和论文表混在一起。判断对了，connector 的消融数字仍然只属于第 02 课。本课页边不抄那些消融表，也不改那些实验的预算。

## 13. 前沿对照与改造方向

**公开方案。** 2023–2025 年把“听写”做成“听懂”，至少有三条能打开原文的路。SALMONN 用双编码器覆盖语音与非语音，用窗口级 Q-Former 保住时间分辨率，再用 12 步激活把被听写拽走的指令能力拉回来。Qwen2-Audio 取消层级标签、把分析和闲聊联合训练、加 DPO，AIR-Bench chat 四维超过当时可比的 LALM 和 Gemini-1.5-pro（后者样本因安全策略减少约 1/5）。Qwen2.5-Omni 把同一音频前端接到 Thinker，并拿出口述与文本对照：MMLU 65.6 对 69.3，GSM8K 85.4 对 82.3，同时 VoiceBench 平均 74.12。三条路都没有把“换一个更好的 RVQ”写成指令跟随的主因。

**差距。** 本课缩小版和论文的差距，规模项是：没有 230 万条指令、没有 8.2B 权重、没有 AIR-Bench 全量评测。机制项是：有没有两张 mask、会不会构造转写对指令错、评测协议是否分层。规模用钱可以补；机制补不上，钱会把复读训得更稳。Qwen2.5-Omni 相对 Qwen2-Audio 的口述 MMLU 差距（65.6 对 33.2）是机制加数据，不是 40 ms 帧变成了 39 ms。

**动手改造清单。**

1. **换 mask，不换编码器。** 在任一开源音频语言模型的 SFT 脚本里，把指令样本的 label 改成只覆盖执行跨度。预算：1 张 24 GB 卡，1 千到 1 万条自造闲聊即可看见趋势。预期：同一批语音上，复读率下降，WER 变化小于指令精确匹配的变化。失败判定：执行回复仍等于 `transcript`，或有效 token 计数几乎等于整段助手文本。
2. **听写:指令配比扫描。** 固定总步数，扫 $4:1$、$1:1$、$1:4$。预算：与上一项同卡，三种配比各几千步。预期：指令比例上升时，口述算术准确率上升；4:1 时 WER 最好但复读最多。失败判定：三列指标同升同降，分不出两层。
3. **SALMONN 式 12 步激活。** 先把模型训到会听写、不会讲故事，再用 12 条长回复做激活。预算：CPU 可先在本课夹具上改配方；真模型用 13B 加 LoRA 时约一张 24–48 GB 卡、可忽略的步数。预期：跟随率上升，test-clean WER 变动小于 0.5 个点（SALMONN 是 2.1 对 2.1）。失败判定：用长听写当激活数据也能“成功”，或 WER 崩了才换来跟随。
4. **口述与文本同一题集。** 把 50 道短数学或约束题各做文本版和 TTS 版。预算：推理即可，不必训练。预期：文本准确率明显高于听写型模型的口述准确率；指令 SFT 之后两者靠近，类似表 4 的方向。失败判定：口述准确率用 WER 代替，或 TTS 失败的题目没从分母里剔除。

**顺手复现映射。** 论文结论“听写好不等于会跟指令”对应本课教具的听写预训配方，预期能复现同方向：转写对、执行复读。论文结论“少量长回复可激活跟随、听写几乎不动”对应配方从听写预训切到指令 SFT，预期执行头从复读变成 `16` / `7K`，转写头仍对。论文结论“Qwen2-Audio 的 AIR-Bench 高于 SALMONN”本课不能复现，只允许引用表 2。不要把教具里的交叉熵差值写成 AIR-Bench 的 7.18。

改造实验的失败判定要写进预注册，避免事后把 WER 当挡箭牌。实验 1 若复读率下降但有效 token 计数仍等于助手全文，说明你可能把礼貌前缀也标进了 $M_{\mathrm{if}}$，下降来自“少说废话”而不是“学会执行”。实验 2 若三列同升同降，先检查是不是同一条损失被复制进了两个记录器。实验 3 若听写崩了才换来跟随，对照 SALMONN 图 2：激活曲线应在 ASR 几乎水平时让 FR 上升。实验 4 若口述准确率用 WER 代替，直接判失败，不必看数字大小。

预算数字是上限，不是门槛。没有 24 GB 卡时，实验 1–3 都可以停在本课 CPU 夹具和教具：改 mask 看集合，改配方看复读，改 12 步故事看跟随列是否从复读变成执行。真模型上的卡时属于“若要复现论文规模”。主路径通过不依赖那些卡时。Qwen2-Audio 预训练小时数的图 3、Qwen2.5-Omni 的 3000 亿音频 token，只说明公开方案花了多少数据，不说明你必须花同样多才能理解两张 mask 不相等。

## 14. 论文与必读材料

1. [Qwen2-Audio Technical Report](https://arxiv.org/abs/2407.10759)（Chu 等，2407.10759）。带着什么问题读：自然语言提示替换层级标签之后，预训目标有没有变成指令跟随？两种交互如何做到不用系统提示切换？表 2 里哪些数字是 ASR，哪些是 AIR-Bench？DPO 的三元组 $\boldsymbol{y}_w,\boldsymbol{y}_l$ 是回复还是听写？
2. [SALMONN](https://arxiv.org/abs/2310.13289)（Tang 等，2310.13289，ICLR 2024）。带着什么问题读：窗口级 Q-Former 为什么能保住时间分辨率？任务过拟合的贝叶斯分解里，被听写霸占的是哪一项？激活微调 12 步之后，哪些 level 1 指标几乎不动、哪些 FR 从 0 附近跳起？长听写和纯文本故事为什么激不活？
3. [Qwen2.5-Omni Technical Report](https://arxiv.org/abs/2503.20215)（Qwen Team，2503.20215）。带着什么问题读：表 4 的星号是什么子集？口述 MMLU 65.6 与 Qwen2-Audio 33.2 的差，能否用表 2 的 WER 解释？VoiceBench 平均 74.12 测的是哪一层？Thinker 文本头和 Talker 语音头，哪一个才是本课损失该写的地方？

补充对照（本课不要求精读全文，引用前已打开摘要或表格）：Qwen-Audio（2311.07919）提供层级标签基线；Whisper（Radford 等，ICML 2023）提供编码器初始化与 ASR 参考 WER；AIR-Bench（Yang 等，ACL 2024）提供指令侧打分协议；VoiceBench（2410.17196）提供口述助手基准。课程大纲误写的 2310.09478 是 MiniGPT-4，不要当作 SALMONN 来引。

读这三篇时建议按“同一句语音、两张表”做笔记，而不是按模型名做笔记。第一张表只收听写：Librispeech、Aishell2、Fleurs、GigaSpeech、Common Voice。第二张表只收指令：AIR-Bench chat、VoiceBench、口述 MMLU / GSM8K / IFEval、SALMONN 的 FR。任何数字进笔记前先问属于哪一张。进错表的数字，后文引用一律作废。Qwen2.5-Omni 的 seed-tts WER、Talker NMOS、OmniBench 多模态平均，分别属于生成层和视听混合层，本课第三张表可以列标题，但不要写进前两张的验收。OmniBench 平均 56.13% 证明混合模态理解，不证明语音指令跟随已经等于文本；表 4 才是本课要的对照。
