# 第 36 课：把导航底盘和手臂动作分成两套词表

> 类型：spatial-body 单元，导航底盘与手臂动作空间<br>
> 建议周期：阅读约 65 分钟；CPU 实验数分钟；浏览器教具先预测再揭晓<br>
> 硬件：主路径无 GPU；复现 RT-1 需要原文中的 13 台移动操作器，复现 NaVILA-8B 需要原文中的多卡训练，均非本课验收<br>
> 产物：两套不重叠词表、路点非法索引夹具、丢掉地图后的分叉失败记录

## 1. 手臂动作和底盘动作为什么不是同一张词表

第 [24](24_vlm_to_vla.md) 课把动作接进视觉语言模型：7 维末端位姿每维切成 $B$ 个箱子，箱子编号加上语言词表长度，变成和文字同一套 next-token。那一课的对象是夹爪中心的位置、姿态和开合。厨房里的真实指令很少停在桌面局部。人说「去厨房把杯子拿来」时，机器人先要让轮子或腿把底座挪到台面附近，再让手臂伸过去。前一段的可执行对象是底盘速度或拓扑路点，后一段才是第 24 课的 7 维。把两段写进同一张均匀分箱表，看起来省事，解码时会把「停车」读成「手腕抬到半程」，或把「台面节点 3」读成「夹爪开度 3/255」。

本课改的是动作词表的分区，不是再训一个视觉塔。输入侧的投影、冻结编码器和动态分辨率仍沿用第 [22](22_standard_vlm_recipe.md) 课和第 [08](08_dynamic_vision.md) 课。第 35 课规格处理的是缺深度时抓取在哪一步失败，本课假定局部台面已经能看见杯子，问的是「走到那张台面」和「抓住杯子」要不要共用整数编号。要验证的只有三件事：底盘 $(v,\omega)$ 与手臂动作是否共享 bin 边界；两套词表拼接后的偏移是否重叠；丢掉地图之后，路点政策与速度政策是否以不同方式失败。

为什么必须先切开词表，而不是把底盘 $(x,y,\mathrm{yaw})$ 直接接在 7 维后面当成第 8–10 维？因为后一种写法在 RT-1 的实现里确实出现过，而且论文把它和三模式开关绑在一起。RT-1（arXiv:2212.06817）的动作是 7 维臂、3 维底盘，外加一个离散维在「控臂 / 控底盘 / 结束回合」之间切换。每一维仍切成 256 个 bin，但同一时刻只有一套身体在听。教学缩小版把这件事写得更硬：手臂切片和底盘切片在整数轴上不许相交；路点索引再单独占一段，合法范围跟着地图节点数 $N$ 走。$N=0$ 时，任何旧节点号都是非法索引。速度政策没有节点表，丢掉地图后 token 仍落在底盘切片里，电机会撞墙或转圈。两种失败必须能被同一套开关分别触发，否则你会把「模型坏了」写成「词表越界」，或反过来。

会写 `go to the kitchen and pick up the cup` 不等于底盘和手臂已经接在同一套条件生成里。把一个导航栈挂在 VLA 外面，可以得到能走动的系统，但那不是本课的验收。本课的最小承诺是：两套身体的整数编号能画在同一条数轴上且不相交；丢掉地图时，路点解码失败和速度解码成功可以同时被测量。交互实验是浏览器里的受控模拟，页面标明「教学模拟，不是模型输出」。CPU 实验无网络、无 GPU、无文件副作用，证明的是偏移和非法索引，不是真机成功率。

用手算把这件事钉死。设语言词表占 $[0,32)$，手臂按第 24 课占用 $[32,88)$。若有人图省事，把底盘 $v$ 也从 32 起编，那么 $v=0.4$ 在手臂 $x$ 箱边上的编号是 37，与示例向量的 $x$ 维 token 完全相同。解码器看到 37，不知道该当成「末端向前 0.4」还是「前进 0.4」。电机层若把同一个整数同时送给腕部和轮子，杯子还没抓住，底座已经挪了。这不是训练不够，是词表合同没签。本课后面所有公式都在防止这个合同漏洞：先分身体，再分箱，再检查 $N$。

第 [29](29_dual_system_vla.md) 课的快慢双系统也在分身体，但分的是「规划通路 / 控制通路」，不是「轮子 / 手臂」。本课的模式维可以塞进慢系统的输出，也可以塞进快系统的执行开关；无论塞哪一层，整数段都必须分开。不要用双系统的术语来逃避偏移检查。偏移是词表事实，双系统是调度事实，两者同时成立时才允许在报告里并排出现。

移动操作器把「走」和「抓」放在同一台机器上，并不自动把它们放进同一张 softmax 表。厨房工作台离起始点只有几米时，示教里底盘位移很小，模型可以靠手臂 bin 混过训练损失；评测一旦把杯子放到隔壁房间，损失上看不见的底盘错误才会出现。这就是为什么本课一定要把「走到台面」做成单独一拍，而不是在 7 维后面悄悄加两维指望网络自己学会何时用它们。不加分拍、不加模式、不加合法性，多出来的维只是更大的噪声。RT-1 用 13 台机器人、17 个月、13 万回合才把这套噪声压下去，并且仍然需要模式维。缩小版没有这批数据，只能靠词表合同，不能靠规模硬扛。

教室里可以用一句更短的话检查自己有没有把两套词表分开。问：停车时 $v=0$ 的 token 是多少？答 88。再问：夹爪全开时的 token 是多少？答 87，因为夹爪是手臂第 6 维（从 0 计），起点 $32+6\times 8=80$，全开是右端点 bin 7，token $80+7=87$。88 是底盘切片的第一个 id，87 是手臂切片的最后一个 id。两者相邻但不重叠，这就是合同签好的样子。若有人把夹爪区间也写成 $[-1,1]$，全开不再落在 87，对账失败。若有人让 $v=0$ 占用 32，停车和手臂 $x$ 的最左箱撞车。这两问不需要跑模型，上课前就能问。Lab 的公式栏把切片写在左上角，揭晓前就可以先对这两问，揭晓后再看失败模式。顺序不能反：先看失败模式再回头编切片，总能为任何数字找到借口。停车的完整底盘 token 是两维：`[88, 100]`，因为 $\omega=0$ 落在 $[-1.5,1.5]$ 的中位箱子 4，$88+8+4=100$。只背 88 不够，漏掉角速度维会在直行时埋下漂移。Lab 揭晓速度政策时必须同时读 $v$ 和 $\omega$ 两个 id。路点政策没有这两个 id，只有 110。看见 110 还去问 $\omega$ 是多少，说明仍然把路点当成了速度。两种身体的读数方式不一样，问错问题本身就是没切开词表。把这两问写进实验记录的「课前自测」栏：答错不准开始 Lab。自测通过只说明切片记得住，还不说明丢掉地图后的失败已经分叉，Gate 仍要揭晓两次探针。切片记忆和失败分叉是两道门，少一道都叫未完成。课前自测还可以加第三问：模式 token 105 出现时，手臂 7 个 id 应不应该进损失？答案是不应该。答「应该，反正联合 softmax 能分清」的人，还没把第 5.3 节的泄漏读进去。三问全对，才打开浏览器教具。第四问可选：路点 110 在 $N=6$ 时是不是合法？是。$N=0$ 时还是不是？不是。这一问专门挡「切片里有号就等于图上有点」的混读。预留切片长度和当前图的节点数是两个量，混成一个量就会把非法索引看成合法停车。CPU 夹具因此同时检查 $i=3,N=0$ 和 $i=0,N=0$，防止有人把越界 clip 成回起点。

第十一幕「第三维与全身」里，第 35 课规格把深度接进抓取，本课把底盘接进词表，第 37 课规格才会把灵巧手和人形的维数抬上去。现在若把 20 维手指或全身力矩写进作业，超出本课范围。依赖写的是 24 与 35：没有 7 维分箱，本课的「另一套词表」没有对照；没有深度失败的印象，容易把「走不到台面」和「夹爪在错误深度闭合」混成一个成功率。第 35 课的 Markdown 若尚未入库，先按第 24 课的 7 维夹具完成本课 CPU 实验，把深度失败留在实验记录的「非本课」栏。

本课术语：

| 术语 | 简要解释 |
|---|---|
| 底盘动作 | 移动底座的命令，常见是平面速度 $(v,\omega)$，或 RT-1 的 $(x,y,\mathrm{yaw})$ |
| 路点 | 拓扑图上的一个节点，通常对应一张历史图像或一个可停位置 |
| 拓扑图 | 节点加可通行边，不要求度量地图上的每一格都可定位 |
| 词表偏移 | 一套整数编号的起点，用来避免和文字或其他身体撞车 |
| bin 边界 | 每个动作维度从最小值到最大值切成 $B$ 段的端点 |
| 三模式开关 | RT-1 里在控臂、控底盘、结束回合之间二选一的离散维 |
| 非法索引 | 路点号 $i$ 满足 $i<0$ 或 $i\ge N$，无法在当前图上解码 |
| 非完整约束 | 轮式底盘不能任意侧移，状态常用 $(x,y,\theta)$，输入是 $(v,\omega)$ |
| VLN | 视觉–语言导航：按自然语言在未见过的环境里走动 |
| 中层语言动作 | NaVILA / NaVid 那种「前进 75 cm」「左转 30°」，再交给低层跟踪 |

## 2. 本课解决的问题

当前系统（第 21–32 课铺好的 VLM 与 VLA，以及第 24 课的 7 维分箱）可以在桌面局部吐出末端位移。桌面局部解决不了「杯子在另一个房间」。第 [32](32_gui_agent_grounding.md) 课比较的是屏幕点击和机械臂在图像平面上的二维接地，那是同一张图里的点；本课是两种执行器、两种合法整数集合。第 [30](30_closed_loop_control.md) 课处理控制频率和开环窗口，本课不重做 $H/f$，只借用「底盘命令的时间尺度往往比手指慢」这一事实。第 [07](07_full_duplex_routing.md) 课的 PAUSE 可以丢掉音频缓冲再重说；底盘一旦转过墙角，物理状态不能 undo。本课不把力安全切断提前写完，那是第 40 课规格。本课只把失败记在词表和解码层。

「去厨房把杯子拿来」至少要拆成两个子目标：

1. **走到台面。** 可执行对象是底盘。表示可以是连续速度 $(v,\omega)$，可以是 RT-1 那种 3 维底盘 bin，也可以是拓扑图上的节点索引。
2. **抓住杯子。** 可执行对象是手臂。表示沿用第 24 课的 7 维均匀分箱，本课不再比较 L1、分块或 DCT，那些是第 [25](25_action_tokenization.md) 课的对象。

两段的失败模式事先写清：

| 子目标 | 丢掉地图时 | 词表是否仍合法 | 身体上能看见什么 |
|---|---|---|---|
| 路点走到台面 | 节点表长度为 0 | 否，旧 $i$ 变成非法索引 | 底盘停在原地 |
| 速度走到台面 | 没有全局目标 | 是，$(v,\omega)$ 仍在底盘切片 | 撞墙或转圈 |
| 抓住杯子 | 不查路点表 | 是，7 维仍在手臂切片 | 若人已经把底座放到台前，局部抓取仍可解码 |

出现以下任一情况，不得把作业标记为「已经接上导航动作」：

- 底盘速度使用手臂 $x$ 的 $[-1,1]$ 箱边，导致 $v=0$ 落进中位格子；
- 手臂 token 和底盘 token 在整数轴上相交，解码时把夹爪开度读成角速度；
- 丢掉地图后，路点政策仍报告「合法节点 3」，或速度政策报告「非法索引」；
- 两种政策的失败被写成同一句话，例如「都不能走了」；
- 把 LM-Nav 的路点搜索、NaVid 的中层语言动作、RT-1 的 3 维底盘 bin 说成同一个方法。

下一课规格才升高维数。本课把「两套词表」做完，并且只做这件事。

和相邻课的分工再钉一次，避免写报告时把深度、表示、评测塞进来凑字数。第 24 课验收的是「动作能不能成为 token」；本课验收的是「两种身体的 token 能不能分家」。第 25 课验收的是同一身体上 bin / L1 / 分块 / DCT 的重建；本课固定用均匀分箱，不为底盘另开 FAST。第 26 课处理异构机器人数据混合；本课只在 RT-1 混 Kuka 的段落里提醒「迁移的是技能先验，不是箱边」。第 27 课处理自回归串行延迟；本课 7 个手臂 token 加 2 个底盘 token 的串行深度留给那一课。第 31 课处理 LIBERO / SIMPLER 的拆层评测；本课的 97% 和 54.0 只允许带表号出现，不允许平均成「导航成功率」。第 32 课的二维接地可以把「台面在图像哪一格」和「按钮在截图哪一格」写成同一套 $[0,1]^2$，仍然解决不了轮子怎么走过去。谁在本课交付物里贴上一张 SoM 热图，视为跑题。

「去厨房把杯子拿来」在语言里是一句。在执行里最少是两段身体、两套整数、两种失败。把这句话压缩成一个 7 维向量，等于假设厨房只有一张桌子、底座已经贴在桌沿。该假设在第 24 课的俯视桌面里成立，在本课的俯视房间里不成立。实验记录首页用一句话声明：本课样本是否包含底盘位移。声明为否的数据集，不准用来验收非法索引。

## 3. 开始前需要准备什么

本课不训练 MiniMind-O，也不要求 GPU。需要第 [01](01_baseline_reproduction.md) 课的记录习惯，加上一套能手算的手臂向量和底盘向量。

**上游事实（来自已打开的论文页，不是本课约定）：**

- RT-1 在 17 个月里用 13 台 Everyday Robots 收集约 13 万条回合；Table 1 合计 744 条指令；模型 35M 参数，控制频率 3 Hz；每维动作均匀切成 256 个 bin。动作包括臂的 7 维、底盘的 3 维 $(x,y,\mathrm{yaw})$，以及三模式开关。视觉侧：6 帧 $300\times 300$，EfficientNet-B3 出 $9\times 9\times 512$，展平为 81 个视觉 token，TokenLearner 压到每帧 8 个，6 帧共 48 个。训练指令成功率 97%，未见指令 76%，干扰物 83%，背景 59%。长程任务接到 SayCan 框架，论文写可执行多达 50 段。
- LM-Nav（arXiv:2207.04429）用 GPT-3 抽路标、CLIP 接地、ViNG 做视觉导航，不对目标环境微调。20 条指令、合计超过 6 km，论文写 85% 的实验能按指令完成，目标最远约 800 m。系统依赖预先建好的拓扑图。
- ViNT（arXiv:2306.14846）31M 参数，图像目标导航，预测到目标的动力学距离和 $H=5$ 步相对路点，部署约 4 Hz。训练数据超过 100 小时、8 种平台。长程靠在线图加扩散子目标。
- NaVid（arXiv:2402.15852）只吃单目 RGB 视频，输出 `FORWARD` / `TURN-LEFT` / `TURN-RIGHT` / `STOP` 及距离或角度。R2R-CE Val-Unseen：NE 5.47、SR 37.4、SPL 35.9。真机约 200 条指令、约 66% 成功率。训练约 24 张 A100、28 小时，共 672 GPU hours。路点预测变体被原文消融判定为极难学习。
- NaVILA（arXiv:2412.04453）两级：VLA 先出中层语言，例如「前进 75 cm」，再映射到 $\{0.5\,\mathrm{m\,s^{-1}},\,\pi/6\,\mathrm{rad\,s^{-1}},\,-\pi/6\,\mathrm{rad\,s^{-1}},\,0\}$ 交给视觉运动 RL。R2R-CE Val-Unseen：NE 5.22、OS 62.5、SR 54.0、SPL 49.0。真机 25 条指令成功率 88%。VLN-CE-Isaac 上 Go2 有视觉 50.2% SR，盲政策 36.2%。8B 推理约 1 FPS（RTX 4090）。
- Mobility VLA（arXiv:2407.07775）在 $836\,\mathrm{m}^2$ 办公环境：长上下文 VLM 在导览视频里找目标帧，低层用 COLMAP 拓扑图出路点 $(\Delta x,\Delta y,\Delta\theta)$。真机 Table 2：推理无关 80%、需推理 80%、小物体 40%、多模态 85% 端到端成功率；找到目标后低层到达 100%。仿真里让 VLM 直接出路点动作：成功率 0%，每步 $25.90\pm 8.36$ s；目标索引加拓扑图：90%，每步 $0.19\pm 0.047$ s。高一层 Table 3 的目标帧命中：推理无关 95%、需推理 86%、小物体 42%、多模态 90%。

**本课约定：**

- 教学分箱取 $B=8$，语言词表占位 $V_{\text{text}}=32$。手臂 7 维区间与第 24 课相同：前六维 $[-1,1]$，夹爪 $[0,1]$。底盘教学用单车 $(v,\omega)$，$v\in[0,1.5]$，$\omega\in[-1.5,1.5]$，不是 RT-1 的 3 维 $(x,y,\mathrm{yaw})$。
- 模式占 3 个 id：控臂、控底盘、结束。路点占 6 个 id，台面节点编号为 3。
- 交互实验是浏览器里的受控模拟。CPU 实验无网络、无 GPU、无文件副作用。编排者登记之后可用下面命令跑；登记前可直接调用 `lesson_36.run()`。

```bash
python3 run.py run 36
```

```bash
python3 run.py check 36
```

没有移动底盘也能完成本课。缺的是真机导航成功率，不是偏移公式。

建议把第 24 课 CPU 的示例向量原样抄过来当手臂夹具，本课不再改它。这样两课的手臂 token 可以对账：若第 36 课手臂示例不再是 `[37, 43, 52, 60, 66, 79, 82]`，说明有人动了 `ARM_DIMS` 或 `TEXT_VOCAB`。底盘夹具是新的，对账对象是本课自己的 `base_tokens` 与 `lost_map_velocity_tokens`。两套对账各算各的，不要把 90 拿去和第 24 课的 37 比大小。

建议准备一张纸，左栏抄 $z^{\mathrm{arm}}$ 和 $z^{\mathrm{base}}$ 的起点，右栏抄「$N=0$ 时 $i=3$ 非法」。Lab 揭晓时只看右栏有没有被违反：速度政策若出现非法索引，或路点政策在 $N=0$ 时仍显示合法，左栏公式再对也算本课失败。CPU 实验只看左栏加合法性谓词：箱边、偏移、非法索引、单车撞墙。两边分开过，再写第 10 节的验收勾选。把 Lab 的格子路径粘进 CPU 的 `metrics` 没有意义，两边的几何单位不同。

若从第 01–20 课跳进本课，需要接受两句前置而不展开：图像已经被编成一串视觉 token；7 维末端可以均匀分箱并加偏移。本课的新内容是第二套身体和路点合法性，不是再讲一遍 FiLM-EfficientNet。已经读过第 24 课的人，可以把手臂编码器当成库函数，本课实验文件仍然重新实现了一份，是为了让本课能独立跑，不是为了改第 24 课的公式。两份实现的手臂示例 token 必须相同；不同就先停下来对 `ARM_DIMS`。

## 4. 完成后应具备的能力

1. 把厨房指令切成走到台面和抓杯子，并指出每一段的执行器和合法整数集合。
2. 写出单车运动学 $\dot x=v\cos\theta,\ \dot y=v\sin\theta,\ \dot\theta=\omega$，说明它和手臂 7 维末端位移不是同一组物理量。
3. 写出底盘与手臂各自的箱宽 $\Delta_d=(a_d^{\max}-a_d^{\min})/B$，证明 $\Delta_v\neq\Delta_x$、$\Delta_\omega\neq\Delta_{\mathrm{yaw}}$。
4. 写出拼接偏移 $z^{\mathrm{base}}_k=V_{\text{text}}+D_{\mathrm{arm}}B+kB+b_k$，检查与文本、手臂、模式、路点都不重叠。
5. 解释 RT-1 的 7+3+1：3 维底盘 bin 仍按 256 切，但三模式开关保证同一时刻只有一套身体生效。
6. 写出路点合法条件 $0\le i<N$；在 $N=0$ 时把任意旧 $i$ 判为非法索引。
7. 对照 LM-Nav / Mobility VLA 的图搜索与 NaVid / NaVILA 的中层语言或速度，不把它们写成同一套词表。
8. 在 Lab 里先提交「失败模式不同」的预测，再分别揭晓路点丢地图与速度丢地图。
9. 在报告里把「上游事实 / 本课约定 / 本次测量」分成三栏，不把教学 $B=8$ 写回 RT-1 的 256。

第 8 条是为了防止对着揭晓后的数字事后编故事。第 9 条是第 01 课复现纪律在导航词表上的翻版。

完成后还应能拒绝两种常见的假完成。第一种：把底盘 3 维接到手臂 7 维后面，报告「词表增加了 768 个 token」（$3\times 256$），但不做模式维，每一步都同时改 10 维。真机上这会让走路时的手臂保持变成高方差监督。第二种：用一个技能名 `navigate_and_pick` 覆盖整句指令，低层黑盒执行，报告里只有字符串没有 $i$ 也没有 $(v,\omega)$。技能名可以存在，但本课的 CPU 和 Lab 都不把技能名当作通过条件。通过条件永远落在整数段和合法性谓词上。

若你已经会手算第 24 课的 7 维偏移，本课新增的计算量很小：多两次除法得到 $\Delta_v$ 和 $\Delta_\omega$，多一次加法得到 `BASE_START`，多一次比较得到 `legal`。难的是解释。解释必须能对着 Lab 的两种失败分别说出「这一次坏在图，这一次坏在物理」。说不出差别的人，手算对了也还没完成本课。

## 5. 原理：边造边讲

每个机制按同一节奏：为什么需要、怎么运转、精确定义、在公开实现里落在哪、怎么证明做对了。

### 5.1 同一句指令切成两种身体

直觉：你自己去厨房拿杯子时，腿和手并不是同一套肌肉指令。腿负责「别撞门、别在走廊转圈」，手负责「对准杯口、合拢」。机器人把这套分工写成两个可学习的输出头，或同一头上的两段词表。

机制：把指令 $u$ 分解为子目标序列 $(g_1,g_2)$。$g_1=$ 走到台面，$g_2=$ 抓住杯子。策略 $\pi$ 在每个时刻先选身体 $m\in\{\mathrm{arm},\mathrm{base},\mathrm{terminate}\}$，再从对应词表里取动作。教学 Lab 把 $g_1,g_2$ 做成下拉框，避免模型自己切分带来的额外失败。论文系统里，切分可以来自 SayCan 式技能名，也可以来自 VLA 自己的模式维。

数学：记手臂动作为 $a^{\mathrm{arm}}\in\mathbb{R}^{7}$，底盘动作为 $a^{\mathrm{base}}=(v,\omega)$，路点为整数 $i\in\mathbb{Z}$。同一时刻的可执行命令是三选一：

$$
a_t=
\begin{cases}
a^{\mathrm{arm}}_t, & m_t=\mathrm{arm}\\
a^{\mathrm{base}}_t, & m_t=\mathrm{base}\\
\varnothing, & m_t=\mathrm{terminate}
\end{cases}
$$

路点政策在 $m_t=\mathrm{base}$ 时不直接出 $(v,\omega)$，而出 $i_t$，再由跟踪器把 $i_t$ 变成速度。这是表示层的分叉，不是「多两个输入通道」。

代码落点：CPU 模块 `encode_mode` 把 $\{0,1,2\}$ 映到 $[104,107)$。Lab 在抓杯子时强制 $m=0$，走到台面时强制 $m=1$。不要在本课实现一个从自然语言切分子目标的分类器。

验证：抓杯子阶段的 token 必须全部落在 $[32,88)$；走到台面的路点 token 必须落在 $[107,113)$；速度 token 必须落在 $[88,104)$。任一交叉即失败。

### 5.2 底盘速度与手臂不共享 bin 边界

直觉：夹爪开合在 $[0,1]$ 里有物理意义，线速度 $0$ 表示停车，不是「半开夹爪」。若两维共用 $[-1,1]$ 的 8 个箱子，停车速度会掉进第 4 号箱子，反量化得到一个非零中点，底盘会慢慢爬。

机制：均匀分箱的格子宽度由该维自己的 $[a^{\min},a^{\max}]$ 决定。手臂 $x$ 教学区间 $[-1,1]$，$B=8$，箱宽 $0.25$。底盘 $v$ 教学区间 $[0,1.5]$，箱宽 $0.1875$。同一数值 $0.4$ 在两维上不是同一个 bin。CPU 实验里 $v=0.4$ 的正确 bin 是 2，若误用手臂 $x$ 的箱边则变成 5。

数学：对维度 $d$，

$$
b_d=\mathrm{clip}\left(\left\lfloor\frac{a_d-a_d^{\min}}{\Delta_d}\right\rfloor,0,B-1\right),\qquad
\Delta_d=\frac{a_d^{\max}-a_d^{\min}}{B}
$$

左闭右开，右端点单独映射到 $B-1$。反量化用格心：

$$
\hat a_d=a_d^{\min}+(b_d+0.5)\Delta_d
$$

重建误差上界 $\lvert a_d-\hat a_d\rvert\le\Delta_d/2$，前提是 $a_d$ 已 clip 进 $[a^{\min},a^{\max}]$。若把 $v=1.2$ 送进手臂 $x$ 的 $[-1,1]$，它会先被 clip 到 $1$，再落到最后一格，格心 $0.875$，系统以为底盘已经饱和，实际上 $1.2$ 在底盘自己的区间里还不是最后一格。CPU 检查 `shared_arm_bins_clip_fast_base` 就是这件事。

单车运动学把 $(v,\omega)$ 积成位姿：

$$
\dot x=v\cos\theta,\qquad
\dot y=v\sin\theta,\qquad
\dot\theta=\omega
$$

手臂 7 维没有这组非完整约束。侧向速度在理想差速轮上不可独立命令；RT-1 的底盘 $y$ 维是否真正侧移，其技术报告未把控制器细节写成可复现的公式，本课不编。教学缩小版只用 $(v,\omega)$，避免假装 3 维底盘和 7 维手臂可以逐维对齐。

再把 $v=0$ 单独算一遍。停车在底盘区间 $[0,1.5]$ 上是左端点，正确 bin 为 0，格心 $0.09375$，这是量化噪声，不是指令。若误用手臂 $x$ 的 $[-1,1]$，$v=0$ 落在

$$
\left\lfloor\frac{0-(-1)}{0.25}\right\rfloor=4
$$

格心为 $0$。看起来「中点是零」像碰巧对了，其实这只对对称区间成立。角速度 $\omega=0$ 在 $[-1.5,1.5]$ 上同样是中点，误用 $[-1,1]$ 也会碰巧得到中点。线速度没有负号、区间不对称，碰巧消失。本课把 $v$ 的区间故意写成从 0 起，就是为了让共享箱边在停车这一档上暴露。真机若允许后退，$v$ 可以改成 $[-v_{\max},v_{\max}]$，那时必须同时改 $\Delta_v$，不能继续抄手臂的 $[-1,1]$。

RT-1 的底盘是 3 维 $(x,y,\mathrm{yaw})$，每维仍 256 bin。论文没有在正文给出这三维的米制上下界。其技术报告未公开该细节。因此本课不把 256 个底盘 bin 换算成米每秒，也不声称教学 $[0,1.5]$ 对应 Everyday Robots 的最大速度。教学区间只为了让 $\Delta_v=0.1875$ 能口算。把真机固件里的 $\mathrm{m\,s^{-1}}$ 未经仿射变换塞进 $[0,1.5]$，属于单位错误。

代码落点：`BASE_DIMS` 与 `ARM_DIMS` 分开声明。禁止写一个全局 `LOW, HIGH = -1, 1` 给所有维。

验证：`arm_x_bin_width != base_v_bin_width`，且 `shared_bin_v_index != proper_v_index`。把两处宽度改成相等再跑，检查必须失败。

### 5.3 两套词表拼接时的偏移

直觉：文字、手臂、底盘、模式、路点都要变成非负整数。唯一安全的做法是分段，像内存里的互不覆盖的缓冲区。

机制：令 $D_{\mathrm{arm}}=7$，$D_{\mathrm{base}}=2$，$M=3$，$N=6$，$B=8$，$V_{\text{text}}=32$。

$$
\begin{aligned}
z^{\mathrm{arm}}_d &= V_{\text{text}}+dB+b_d\\
z^{\mathrm{base}}_k &= V_{\text{text}}+D_{\mathrm{arm}}B+kB+b_k\\
z^{\mathrm{mode}} &= V_{\text{text}}+D_{\mathrm{arm}}B+D_{\mathrm{base}}B+m\\
z^{\mathrm{wp}} &= V_{\text{text}}+D_{\mathrm{arm}}B+D_{\mathrm{base}}B+M+i
\end{aligned}
$$

教学数字：手臂 $[32,88)$，底盘 $[88,104)$，模式 $[104,107)$，路点 $[107,113)$。第 24 课示例向量 $(0.4,-0.2,0.0,0.1,-0.5,0.8,0.3)$ 仍编码为 `[37, 43, 52, 60, 66, 79, 82]`，因为手臂切片没动。底盘示例 $(v,\omega)=(0.4,0.3)$ 编码为 `[90, 100]`。

损失与第 24 课相同，只是有效类别变了。对动作位置 $t\in M_a$：

$$
\mathcal{L}=-\frac{1}{\lvert M_a\rvert}\sum_{t\in M_a}\log p(z_t\mid z_{<t})
$$

mask 必须按身体来。控臂步只监督手臂 7 个 id；控底盘步只监督底盘或路点；模式维每步都可以监督。把底盘步的手臂位置也标成有效 label，模型会在走路时更新夹爪词表，这是泄漏，不是多任务。

Gato（第 24 课已引，arXiv:2205.06175）把连续值 μ-law 后 1024 bin，再偏移到 `[32000, 33024)`。它证明的是「连续控制和文本可以靠偏移共存」，没有证明手臂和底盘该共用箱边。本课的偏移是身体之间的，不是文本与控制之间的。两件事可以同时成立：与文本不重叠，且身体之间也不重叠。

联合 softmax 会把泄漏带到另一套身体上。设词表是文本、手臂、底盘拼成的一整段，对一个文本 label 做交叉熵时，配分函数

$$
Z=\sum_{z\in\mathcal{V}_{\text{text}}\cup\mathcal{V}_{\text{arm}}\cup\mathcal{V}_{\text{base}}}e^{s_z}
$$

仍包含手臂行和底盘行。第 24 课已经证明：独立语言头时动作行梯度为 0，联合 softmax 时动作行梯度非 0。本课多了一段底盘。若一步的 label 是路点 110，而 softmax 开在整段 $[0,113)$ 上，手臂行同样会收到非零梯度。训练「走到台面」时夹爪词表被更新，走路示教里的手臂保持姿态会被轻微改写。修复有两种，本课 CPU 不实现，但报告里必须写明你选了哪一种：

1. 分头：手臂、底盘、模式、路点各一个 softmax，互不进入对方的 $Z$。
2. 分步 mask：联合 softmax 仍开在整段上，但执行时只取当前模式对应切片的 argmax，并且非当前切片的 label 为 `-100`。梯度仍会经 $Z$ 漏出，需要靠数据里「走路时手臂几乎不动」去对冲。

RT-1 用的是每维一个 256 路分类头，维与维之间本来就不是一个联合 softmax。教学缩小版为了手算偏移，把各维的 bin 排成一段连续 id，看起来像一个大词表。不要把「排成一段」理解成「必须联合 softmax」。偏移是编号合同，损失图是另一张合同。

代码落点：`ARM_START, BASE_START, MODE_START, WAYPOINT_START` 四个常数。`ranges_overlap` 必须对每对切片返回假。

验证：`concatenated_slices_cover_without_gap` 要求从 32 到 107 的整数被手臂、底盘、模式恰好覆盖，路点再往后接 6 个。出现空洞或重叠都失败。

### 5.4 RT-1 的导航子集与三模式开关

直觉：Everyday Robots 的移动操作器同时有臂和底座。若每一步同时改 7+3 维，示教里大量「走路时手臂该保持」的样本会变成噪声；若完全分开两个模型，长程厨房任务又要在模型外切技能。RT-1 的折中是：同一套 Transformer 出全部离散动作，再用一个离散维声明「现在听哪一套」。

机制：论文第 5.1 节原文：动作包括臂运动 7 个变量 $(x,y,z,\mathrm{roll},\mathrm{pitch},\mathrm{yaw},\mathrm{gripper})$，底盘运动 3 个变量 $(x,y,\mathrm{yaw})$，以及在控臂、控底盘、结束回合之间切换的离散变量。每一维映射到 256 个均匀 bin。模型吃 6 帧历史，3 Hz 出动作，直到 `terminate` 或步数用尽。这不是「导航专用 VLA」，是操作数据集里的导航子集：技能表以 pick / place / drawer 为主，底盘用于走近柜台和抽屉。长程厨房指令由 SayCan 把高层指令拆成约 10 步、论文称可多达 50 段的技能序列，RT-1 充当低层。

数学：设 $B=256$。RT-1 每步产出 11 个离散符号（7+3+1）。教学缩小版把 3 维底盘收成 2 维 $(v,\omega)$，把模式从「256 格里只用 3 格」收成 3 个专用 id。两种写法的共同约束是：模式 $m$ 决定哪些切片进入执行器。

$$
\mathrm{execute}(z)=
\begin{cases}
\mathrm{decode\_arm}(z^{\mathrm{arm}}), & m=\mathrm{arm}\\
\mathrm{decode\_base}(z^{\mathrm{base}})\ \text{或}\ \mathrm{track}(i), & m=\mathrm{base}\\
\mathrm{stop}, & m=\mathrm{terminate}
\end{cases}
$$

未选中的切片即使被 softmax 赋了概率，控制器也必须忽略。否则「控臂」步里底盘 bin 的噪声会让底座抖动。

代码落点：公开页面 [robotics-transformer1.github.io](https://robotics-transformer1.github.io/) 与论文 Fig. 3。本课不依赖未核过的仓库文件名。搜 `256`、`base`、`terminate` 三个词，核对自己的实现有没有漏掉模式维。

验证：CPU 的 `mode_arm, mode_base, mode_terminate` 必须是 104、105、106。Lab 抓杯子时模式 token 为 104，走到台面时为 105。把模式和路点做在同一段 id，检查应失败。

RT-1 的成功数字不能当成「底盘词表已经够用」。97% 是训练指令上的操作成功率，评测环境是办公厨房柜台，不是 VLN-CE 那种跨房间连续导航。本课引用这些数字，只为了说明：同一模型里底盘维已经存在，并且用模式维和手臂分开执行。跨房间泛化要看后面几篇导航专用论文。

把 RT-1 的推理约束也写进实验记录，避免和教学 8 bin 缠在一起。论文要求控制频率至少 3 Hz，给定系统里其它延迟后，模型推理预算小于 100 ms。TokenLearner 把每帧 81 个视觉 token 压到 8 个，加速约 2.4 倍；重叠窗口上复用视觉 token 再加速约 1.7 倍。这些数字回答的是「为什么 35M 的 Transformer 跑得动移动操作器」，不回答「底盘和手臂该不该共用箱边」。本课 CPU 在纯 Python 里跑完，没有 100 ms 预算，不准把 `run()` 的墙钟时间写成 3 Hz 复现。

数据多样性方面，RT-1 还做过两件和导航词表有关、但本课不实现的事。其一，加入仿真物体后，真实物体上的训练指令性能几乎不掉，仅仿真中见过的物体在真实世界的 pick 从 23% 升到 87%。其二，混入 Kuka IIWA 的 QT-Opt 成功回合 20.9 万条之后，原教室评测只降约 2%，在 Everyday Robots 上的箱拣评测从 22% 升到 39%；只用 Kuka 数据在 Everyday Robots 上评箱拣是 0%。这两段说明「另一台机器人的抓取数据」可以改善移动操作器在相似场景里的抓取，没有说明 Kuka 的动作维和 Everyday Robots 的底盘维可以共用箱边。跨身体迁移改的是视觉特征和技能先验，不是把 $v$ 和夹爪开合编成同一个整数。

SayCan 把高层指令拆成技能序列，RT-1 充当低层。技能名「走到桌子」在 SayCan 里是一个离散选项，在 RT-1 里会展开成一串底盘 bin。本课 Lab 的「走到台面」对应后一种展开之后的表示，不对应技能名本身。技能名属于第 24 课的通路 C；底盘 bin 和路点 id 属于本课。报告里如果写「我输出了 walk_to_counter」，还要再写一行：这个名字在执行时被展开成路点 3，还是展开成 $(v,\omega)$，还是交给未在本课实现的低层政策。缺这一行，技能名会把两套词表重新藏起来。

### 5.5 路点索引不是速度

直觉：速度说的是「现在这一拍怎么转」；路点说的是「下一站是图上哪一张照片」。前者在丢掉全局地图后仍能乱走，后者在图消失后连合法输出都没有。

机制：拓扑图 $\mathcal{G}=(V,E)$，$N=\lvert V\rvert$。每个节点通常存一张图像，边权是可达性或 ViNG / ViNT 估出的时间距离。LM-Nav 的目标是找一条经过语言路标的 walk。Mobility VLA 的高层只出目标帧索引 $g$，底层每步在图上做最短路，把下一节点相对位姿写成 $(\Delta x,\Delta y,\Delta\theta)$。两种系统的「动作词表」在高层都是节点编号，不是 $(v,\omega)$ 的 bin。

数学：路点政策输出 $i\in\mathbb{Z}$。合法当且仅当

$$
0\le i<N
$$

编码 $z^{\mathrm{wp}}=V_{\mathrm{wp}}+i$，其中 $V_{\mathrm{wp}}=\texttt{WAYPOINT\_START}$。解码时若 $N=0$ 或 $i\notin[0,N)$，返回 `illegal`，不调用跟踪器。速度政策没有这条谓词：只要 $(v,\omega)$ 落在各自区间内，token 就合法。

ViNT 的相对路点是另一条路。它预测 $H=5$ 步的相对位移，再用机器人自己的跟踪器去跟踪。这仍是度量空间里的短程目标，不是 LM-Nav 那种「节点 17」。不要把 $H$ 步相对路点和拓扑节点索引写成同一个符号 $i$。本课 CPU 实验里的路点是拓扑索引；Lab 里速度政策的路径点只是可视化，不进入词表。

NaVid 明确对比过「直接出路点」：附录与消融把 waypoint 变体换成连续位置和朝向，结果是 VLM 极难学习导航技能。NaVILA 选择中层语言而不是低层关节，理由写在引言：VLM 主要在自然语言上预训练，把推理写成「右转 30 度」比写成 12 维关节更容易保住泛化。这些原文选择说明：路点、中层语言、低层速度是三种词表，不能因为都叫 navigation 就共用一套 bin。

LM-Nav 把「哪一个节点对应这句话里的路标」写成检索问题。对节点图像 $v$ 和路标文本 $\ell$，CLIP 给出

$$
P(v\mid\ell)=\frac{\exp\mathrm{CLIP}(v,\ell)}{\sum_{v'\in V}\exp\mathrm{CLIP}(v',\ell)}
$$

搜索的得分还要扣掉边的时间距离。论文公式 (3) 写成

$$
R(\bar v,\bar t)=\sum_{i=1}^{n}\mathrm{CLIP}(v_{t_i},\ell_i)-\alpha\sum_{j}D(v_j,v_{j+1}),\qquad\alpha=-\log\gamma
$$

动态规划 $Q(i,v)$ 是「已经匹配完前 $i$ 个路标、当前停在节点 $v$」的最大得分。算法每匹配一个路标就做一次 Dijkstra 式松弛。本课 CPU 不实现 CLIP 和 Dijkstra，只保留这件事的终点：匹配结果是一个节点下标 $i$，合法范围是当前 $V$ 的大小。$V$ 被删空时，$P(v\mid\ell)$ 的分母是 0，搜索没有定义，任何缓存的 $i$ 都必须判非法。这和 softmax 数值溢出不是一类 bug。

Mobility VLA 的高层甚至不输出 walk，只输出导览视频里的帧号 $g$。底层用当前观察在图上定位到 $v_s$，再对 $v_s$ 与 $v_g$ 跑最短路，把路径上下一个顶点相对机器人位姿写成 $(\Delta x,\Delta y,\Delta\theta)$。帧号 $g$ 合法的前提是导览还在：离线 COLMAP 已经为每一帧准备好了顶点。导览被拿掉，$g$ 指向的那一帧没有顶点，底层的 Dijkstra 没有终点。教学里把这件事收缩成 $N=0$。不要在缩小版里模拟 948 帧和 PnP；要模拟的是「终点不在图上」这个谓词。

ViNT 的 $H=5$ 相对路点坐在度量空间里：输出的是未来若干拍的相对位移，再用 PD 跟踪。部署频率约 4 Hz。长程时它仍然建图，节点是观察，边是模型预测的可达性；探索时用扩散模型提议图像子目标，再用 ViNT 估距离。短程相对路点在丢掉全局图之后仍可尝试执行，失败更像本课的速度政策：输出合法，身体还在动。长程图搜索在丢掉图之后更像路点政策：没有节点可走。写 ViNT 时必须声明评测的是哪一段。

代码落点：`encode_waypoint(node_id, n_nodes)` 返回 `(token, legal)`。`legal` 不得只检查 token 是否落在 `[107,113)`：那是「id 落在预留切片」，不是「当前图上存在该节点」。预留切片长度为 6，是本课约定的上限；真实图的 $N$ 可以更小。$N=0$ 时切片还在，节点不在。

验证：地图接通，$i=3$，$N=6$，token 110，合法。地图关掉，$N=0$，仍吐出 110，`legal=False`。只看 token 相等会误判成功。

### 5.6 丢掉地图之后的两种失败

直觉：关掉地图像是关上了走廊的灯。认照片走路的人会说「我不知道 3 号门在哪」，站着不动。只看脚下一步的人会继续迈步，然后转圈或撞墙。两种人都失败了，口供不同。

机制：Lab 的「地图」开关把 $N$ 从 6 打到 0，并隐藏节点标记。路点政策没有替代目标，输出缓存里的台面号 3。速度政策改用局部启发式：教学里写死 $(v,\omega)=(1.1,1.45)$，单车积分后会转过 $\pi/2$ 并越出 $[0,1]^2$ 的房间。CPU 用同一组数字，便于两边对照。

数学：非法索引事件

$$
\mathrm{Illegal}(i,N)=\mathbf{1}[N=0\ \lor\ i<0\ \lor\ i\ge N]
$$

速度失败事件（教学房间）

$$
\mathrm{CrashOrSpin}=\mathbf{1}[\text{撞墙}]\lor\mathbf{1}[\lvert\Delta\theta\rvert>\pi/2]
$$

本课要求 $\mathrm{Illegal}=1$ 且速度 token 合法且 $\mathrm{CrashOrSpin}=1$。丢掉地图之后，路点政策停在非法索引，速度政策带着合法 token 去撞墙或转圈。

LM-Nav 的 GPS-Nav 消融提供真机对照：去掉视觉导航模型、改用 GPS 距离加直线控制器后，系统频繁撞树、路缘和墙。那是「速度或直线指令在没有可通行性模型时的失败」，不是非法索引。Mobility VLA 的对照更硬：Gemini 1.5 Pro 直接出路点动作时端到端成功率 0%，几乎总是输出前进；接上拓扑图后仿真 90%。0% 来自「VLM 不会把图像变成可执行相对位姿」，不是来自 $N=0$。写报告时把三种失败分开：非法索引（本课 CPU）、无地图乱走（本课 Lab 速度）、有地图但高层直接控速失败（Mobility VLA Table 5）。

单车积分在 CPU 里从 $(x,y,\theta)=(0.25,0.25,0)$ 起步，$v=1.1$，$\omega=1.45$，$\Delta t=0.6$，房间是 $[0,1]^2$。第一步 $x\leftarrow 0.25+1.1\times 0.6=0.91$，$\theta\leftarrow 0.87$。第二步 $x$ 越过 1，判定撞墙。两步转过的角度 $1.74>\pi/2$，同时满足转圈。这组数字和词表无关：就算把 $(1.1,1.45)$ 编对成 `[93, 103]`，积分仍会出界。把步长改小到永远停在房间里，`lost_map_collided` 会变假，速度失败就只剩转圈；本课允许「撞墙或转圈」二选一出现，但 CPU 夹具两者都触发，避免有人只检查角度。

Lab 里的转圈路径是格子序列，最后一格落在隔墙 $(4,1)$ 上，用来让俯视图看见碰撞。格子坐标和 CPU 的连续单车不是同一套单位。对照时对的是失败类型，不是米制轨迹。谁把 Lab 的格子数写进 CPU `metrics`，属于把教具几何当成物理仿真。

预测必须在揭晓之前提交。四个选项里只有「路点非法索引、速度合法但撞墙或转圈」能通过。选「两者同样报非法」的人，脑子里还把导航失败当成词表越界；选「两者仍能走到台面」的人，还没把地图当成路点政策的运行时依赖。Gate 还要求两次探针都点过：只看速度撞墙、没看到 $N=0$，会漏掉非法索引；只看非法索引、没看到电机仍在动，会以为关掉地图等于所有政策冻结。

代码落点：Lab 必须先选预测再揭晓。正确预测是 `split`。只揭晓当前随意设置不算过 Gate；必须分别点「揭晓路点丢地图」和「揭晓速度丢地图」。

验证：`map_off_failures_differ` 为真。若把速度政策在丢地图时也改成返回非法索引，检查应变假。那是把两种失败焊死成一种，教具就废了。

### 5.7 导航专用 VLA 怎样处理这套分叉

直觉：操作 VLA 把桌面当成工作空间；导航 VLA 把建筑当成工作空间。后者要么带一张图，要么把历史视频当成记忆，要么把语言当中层接口。

机制：把已打开的五篇导航相关工作按「动作写在哪一层」排成表。

| 系统 | 高层输出 | 低层输出 | 是否要预先建图 | 丢掉图时最像本课哪条失败 |
|---|---|---|---|---|
| RT-1 导航子集 | 无独立高层 | 3 维底盘 bin + 模式 | 否 | 速度类：仍出合法 bin，可能走错 |
| LM-Nav | 路标序列 + 图上 walk | ViNG 图像目标政策 | 是，先遍历建图 | 路点类：图不在则无法规划 |
| ViNT | 图像子目标 / 图搜索 | $H=5$ 相对路点 | 长程要图，短程可不要 | 混合：短程像速度，长程像路点 |
| NaVid | 语言动作 + 数量 | 前进 / 转向 / 停 | 否 | 速度类：无图仍可乱走 |
| NaVILA | 中层语言 | 速度指令 + 12 维关节 | 否 | 速度类；避障在运动政策 |
| Mobility VLA | 导览视频中的目标帧 | 拓扑路点 $(\Delta x,\Delta y,\Delta\theta)$ | 是，离线 COLMAP | 路点类；直接让 VLM 出路点则 0% |

NaVid 的 R2R-CE 数字低于使用全景、深度、里程计和仿真器预训练路点预测器的方法（例如 ETPNav SR 57.0），但高于同设定的 RGB-only Seq2Seq / CMA（SR 0.0 / 5.0）。它要证明的是：不靠地图也能把 VLN 写成 VLM 的 next-token。NaVILA 在同一基准上 SR 54.0、SPL 49.0，并且把低层换成腿足运动政策，才能上楼梯和碎石。Mobility VLA 不和 R2R-CE 比，它的任务是 MINT：导览视频加多模态指令，例如举着塑料箱问「这个该还到哪」。任务不同，词表不同，成功率不能横着减。

数据侧也在分叉。NaVid 用 510k 导航样本加 763k 网络数据。NaVILA 把 YouTube 观光视频经 MASt3R 估计位姿，做成连续环境下的轨迹–指令对，并和 R2R-CE / RxR-CE、ScanQA、通用 VQA 混合。LM-Nav 宣称不需要语言标注的机器人数据。RT-1 的 13 万回合是人类示教，指令是技能动词加名词。本课缩小版不收集这些数据，只要求你能指出：路点政策的监督是节点 id，速度政策的监督是 $(v,\omega)$ 或中层语言，手臂政策的监督是 7 维 bin。三种 label 不能写进同一列却共用一个 `action7` 字段。

NaVid 的动作解析用正则表达式，在 VLN-CE Val-Unseen R2R 上抽取有效动作的成功率为 100%。这句话很硬：语言动作作为词表，首先要保证「模型吐出的字符串能被控制器认领」。本课缩小版没有字符串，只有整数；对应的验收是：路点 token 要么合法要么显式非法，不允许静默 clip 到 $[0,N-1]$。静默 clip 会把 $i=3,N=0$ 变成 $i=0$，机器人走向起点，看起来像「还在走」，日志里没有越界。真机上这比直接停住更难查。

NaVid 还把历史帧和当前帧用不同数量的视觉 token 编码：当前帧 64 个 instruction-agnostic token，历史帧每帧 4 个，再加一个 instruction-queried token。这是观察压缩，不是动作词表。不要把 64 抄进本课的 $B$。它要解决的是「视频进 VLM 太长」，本课要解决的是「轮子和手臂的整数撞车」。两个 64 如果出现在同一张草稿纸上，先写清单位：一个是视觉 token 数，一个是 bin 数。

NaVILA 在 R2R-CE 上超过不使用仿真器预训练路点预测器的方法，论文写成功率相对先前方法提高超过 17 个百分点（相对「不靠仿真器路点预测器」那一组）。它用单目 RGB 做到接近部分全景+深度+里程计系统。真机 25 条指令、每条重复三次，覆盖 Workspace / Home / Outdoor，简单与复杂指令分开报。消融显示去掉人类观光视频后，户外简单指令成功率从 1.00 掉到 0.00。这些数字说明中层语言动作可以迁移身体（同一 VLA 接到 Go2、H1、Booster T1），前提是低层运动政策按身体替换。词表分叉发生在「中层语言 / 低层关节」之间，比本课的「手臂 bin / 底盘 bin」更高一层。本课不实现 12 维关节，但要能指出：替换低层政策时，中层词表可以不动；替换中层词表时，手臂 7 维也不应被迫重编。

Mobility VLA 的用户指令分四类：推理无关、需要推理、小物体、多模态。小物体端到端只有 40%，论文归因于导览分辨率。多模态 85% 依赖图像指令本身，把图像改成 caption 后命中率明显下降（附录 Table 7：多模态导览加图像指令 0.90，文本化指令显著更低）。对本课的启发是：路点政策的「节点」可以来自语言，也可以来自当前相机里的物体。节点来源变了，合法条件仍然是「图上有没有这个顶点」，不会变成手臂 bin。

代码落点：本课没有实现 CLIP 检索或 COLMAP。公开实现的阅读入口写在第 6 节。缩小版只实现偏移、合法性和两种失败。

验证：书面表填完六行，Lab 的两种失败能对上「路点类 / 速度类」两列。把 NaVILA 填进「必须建图」是错的；把 Mobility VLA 填进「RGB-only 无图」也是错的。

### 5.8 教学数字和论文数字如何共存

直觉：教学 $B=8$ 是为了口算。论文 $B=256$ 是为了真机。混在一句里，下次改教学常数会把论文一并改掉。

机制：三栏记录。上游事实抄第 3 节已经打开的数字。本课约定抄本节四个起点：32、88、104、107。本次测量抄 CPU `metrics` 和 Lab token。

数学：论文箱宽与教学箱宽的比，对同一物理区间是 $256/8=32$。本课底盘区间和 RT-1 底盘区间并不相同，这个 32 不能用来换算真机米每秒。只在手臂前六维 $[-1,1]$ 的无量纲教学空间里，它表示「论文格子比教学细 32 倍」。

验证：实验记录出现「RT-1 用 8 个 bin」或「本课 256 bin」即为失败。Gate 通过不自动等于记录合格。

### 5.9 完整手算一条厨房回合

把「去厨房把杯子拿来」写成两拍，所有整数都应能在纸上复现。

第一拍，走到台面，路点政策，地图接通。模式 $m=1$，token $104+1=105$。节点 $i=3$，$N=6$，路点 token $107+3=110$。手臂 7 个位置的 label 为 `-100`。执行器只跟踪节点 3，不读夹爪。Lab 在这一拍画出从起点到台面的格子路径。

第二拍，抓杯子。模式 $m=0$，token 104。手臂示例若仍用第 24 课向量，token 为 `[37, 43, 52, 60, 66, 79, 82]`。底盘与路点 label 为 `-100`。执行器只动臂。地图在这一拍即使被关掉，也不产生非法索引，因为没有查询 $i$。

再把第一拍的地图关掉，其它不变。模式仍是 105，政策仍吐出 110，但 $N=0$，`legal=False`，跟踪器不得启动，机器人留在起点。同一时刻若误切到速度政策，token 变成 `[93, 103]`，合法，积分后撞墙。两拍对照写进实验记录后，才允许声称「我理解了厨房任务的切分」。只交第二拍的 7 维 token，等于把本课做成第 24 课的复印件。

时间尺度也写在同一张纸上。RT-1 3 Hz 出一步离散动作；ViNT 约 4 Hz 出 $H=5$ 的相对路点；NaVid 每步约 1.2 到 1.5 秒才给出一个语言动作；NaVILA 的 VLA 约 1 FPS，运动政策按控制周期跑。本课 Lab 没有时钟，揭晓是瞬时的。报告里若出现「本课复现了 3 Hz」，把这句话划掉，改成「本课复现了 3 Hz 系统里的词表分区，没有复现它的控制频率」。第 [30](30_closed_loop_control.md) 课已经处理开环窗口 $H/f$；导航里 $f$ 往往更低，本课只借用「底盘命令比手指慢」这一观察，不把 $H$ 当验收。

最后把终止符单独记账。RT-1 的 terminate 是模式维上的一个离散值，不是夹爪全开，也不是 $v=0$。教学用模式 id 106 表示结束。Lab 的 idle 手臂向量夹爪为 1，只表示「这一拍不抓」，不表示回合结束。若把「夹爪=1」兼当作结束，走到台面途中任何保持姿态都会被控制器理解成关机。写数据时宁可多一个模式 id，也不要复用夹爪开度。

把第一拍的整数排成一行，便于对照 CPU `metrics`：

`[105, 110]`

含义：模式=底盘，路点=台面。地图接通时执行器把 110 解码为节点 3，跟踪器输出一组 $(v,\omega)$ 或相对位姿，那些低层速度不再进入词表。地图关掉时 110 仍出现在模型输出里，但 `legal=False`，执行器输出 $(0,0)$。注意：模型输出非法 id 和执行器输出零速度是两层。日志必须两行都有。只有零速度、没有非法标志，会把「图丢了」记成「政策选择停车」，下一轮数据收集会把这种停车当成正样本。

第二拍：

`[104, 37, 43, 52, 60, 66, 79, 82]`

含义：模式=手臂，随后 7 个手臂 token。若你的实现把 7 维并成一个联合类别而不是 7 个独立头，id 就不再是这串数，本课 CPU 约定作废，必须在记录里重写编码器。本课选择 7 个独立编号，是为了和第 24 课逐维分箱对齐，不是声称 RT-1 用一个 7 维联合 softmax。RT-1 是每维一个 256 路头。对齐的是「维与维分开」，不是「头的个数写成 7 还是 11」。

## 7. 数据与训练 recipe

本课不采集 13 万回合，也不爬 YouTube 观光视频。recipe 分论文层和教学层。

**论文数据（只引用原文）。** RT-1：教室厨房示教，技能见表 1。LM-Nav：目标环境先人工或自动遍历，得到图像节点，无语言标注。ViNT：现成异构导航轨迹，超过 100 小时。NaVid：Habitat 里 R2R-CE 的 oracle 与 DAgger 非 oracle，加指令反推和视频问答。NaVILA：R2R-CE / RxR-CE、EnvDrop 增广、ScanQA、通用 VQA、YouTube 轨迹。Mobility VLA：手柄或手机导览视频，可选旁白；办公环境约 16 分钟、1 Hz 共 948 帧。

**教学缩小版。** 一条样本必须声明身体字段，不能所有行都叫 `action7`。

| 字段 | 类型 | 含义 |
|---|---|---|
| `episode_id` | 字符串 | 稳定主键 |
| `phase` | `nav` / `grasp` | 走到台面或抓杯子 |
| `map_available` | 布尔 | 是否提供节点表 |
| `n_nodes` | 整数 | 当前图的 $N$，丢地图为 0 |
| `instruction` | 字符串 | 与评测逐字相同 |
| `mode` | `arm` / `base` / `terminate` | 三模式 |
| `action7` | 长度 7 或空 | 仅 `grasp` 填写 |
| `base_vw` | 长度 2 或空 | 仅速度政策填写 |
| `waypoint` | 整数或空 | 仅路点政策填写 |
| `legal` | 布尔 | 路点是否满足 $0\le i<N$ |
| `tokens` | 整数数组 | 编码结果 |

三个桶：

| 桶 | 设定 | 用途 |
|---|---|---|
| G | 地图接通，路点政策，走到台面 | $i=3$ 合法，token 110 |
| L | 地图关掉，路点政策 | $N=0$，$i=3$ 非法 |
| V | 地图关掉，速度政策 | token 在 $[88,104)$，积分后撞墙或转圈 |

混合比建议 G:L:V:抓取 = 2:2:2:2。L 太少，非法索引探针方差大；没有 V，会把所有导航失败都写成越界。抓取样本的 `waypoint` 必须为空，`legal` 必须为真（不查图不算非法）。

预处理：先 clip 再分箱。路点 id 写成 `int32`，不要先转成 float 再 round。$N$ 与节点表哈希和 checkpoint 放在一起。换了环境却沿用旧 $N$，属于静默改词表。

训练预算（缩小版，CPU 可完成机制）：

| 档 | 样本 | 目的 |
|---|---|---|
| 过拟合 | 16 条固定 G+L+V+抓取 | 编码准确率 1.0，L 桶 `legal=False` |
| 标准 | 512 条 | 跑丢地图探针 |
| 负对照 | 把 L 桶的 `n_nodes` 改回 6 但关掉可视化 | 模型若仍报非法，说明它在看开关而不是 $N$ |

负对照是为了防止 Lab 的「地图关掉」被实现成一个与 $N$ 无关的布尔捷径。真正的谓词是 $N$，不是复选框。

示教里两种身体的时间对齐要单独记账。走到台面的片段里，手臂示教应接近保持姿态：夹爪开度几乎不变，末端位移接近 0。若这一段仍用第 24 课那种「伸向杯子」的 7 维向量当 label，模型会在走廊里挥臂。抓杯子的片段里，底盘示教应接近停车：$v=0$，$\omega=0$，或模式直接切到 `arm`。RT-1 用模式维避免同时监督两套身体；教学数据若没有模式维，至少要用 mask 把另一套身体从损失里拿掉。检查方法：在 G 桶样本上统计手臂 label 有效个数，应为 0；在抓取样本上统计底盘或路点 label 有效个数，应为 0。两个计数同时非零，说明你在用一条样本训练两种身体的同步动作。本课不禁止真机上的「边走边伸手」，但那是另一套标注协议，需要同时给出合法的手臂向量和底盘向量，并且两者的箱边仍然分开。没有这份协议就不要把同步动作写进缩小版。

坐标系再写一次。路点 $(c,r)$ 是 Lab 俯视格子，原点在网格左上，单位是格。单车 $(x,y)$ 是 CPU 房间，原点在房间角落，单位是无量纲长度。手臂 7 维是桌面局部，原点在夹爪工作空间，$[-1,1]$ 无量纲。三套坐标不许互相代入 bin 公式。谁用格子列号 $c=5$ 去填手臂 $x$ 的分箱，会得到一个看起来很自信的 token，对应的电机目标却指向工作空间外。数据卡上必须有一句话：本条样本的动作向量属于哪一套坐标。

## 8. 按依赖顺序执行实验

顺序锁死。偏移没过，不准看 Lab「成功率」；Lab 没提交预测，不准写失败模式结论；单车积分没撞墙也没转圈，不准声称速度政策已经失败。

### Step 1：CPU 偏移、箱边、非法索引

运行本课实验模块。期望 `checks` 全为真，并记录：`arm_start=32`、`base_start=88`、`mode_start=104`、`waypoint_start=107`、手臂示例 token `[37, 43, 52, 60, 66, 79, 82]`、底盘示例 `[90, 100]`、丢地图路点 token 110 且 `map_off_waypoint_legal=False`、丢地图速度 token `[93, 103]` 仍在底盘切片、`lost_map_collided=True`。

任一条失败时停。常见原因：底盘沿用 $[-1,1]$；路点合法性只检查切片；单车步长太小没碰到墙；把模式和路点做成一段。

手算：$v=0.4$，$\Delta_v=1.5/8=0.1875$，$\lfloor 0.4/0.1875\rfloor=2$，token $88+2=90$。$\omega=0.3$，$\Delta_\omega=3/8=0.375$，$\lfloor(0.3-(-1.5))/0.375\rfloor=\lfloor 4.8\rfloor=4$，token $88+8+4=100$。误用手臂 $x$ 箱边时 $v=0.4$ 的 bin 是 $\lfloor(0.4-(-1))/0.25\rfloor=5$。

丢地图速度 $(1.1,1.45)$：$v$ 的 bin 为 $\lfloor 1.1/0.1875\rfloor=\lfloor 5.866\rfloor=5$，token $88+5=93$。$\omega$ 的 bin 为 $\lfloor(1.45-(-1.5))/0.375\rfloor=\lfloor 7.866\rfloor=7$，因为 $1.45$ 仍小于 $1.5$，尚未触发右端点规则，token $88+8+7=103$。若有人把 $1.45$ 四舍五入成 $1.5$，会提前掉进最后一格，token 仍是 103，但理由错了：最后一格应当留给 $\omega\ge 1.5$。边界测试要用 $\omega=1.5$ 和 $\omega=1.5-10^{-12}$ 分成两行，左闭右开必须在角速度上同样成立。

### Step 2：浏览器教具，先预测再揭晓

打开 `Lesson36NavActionLab`。预测题：走到台面时关掉地图，路点政策和速度政策会怎样失败。正确项是「路点政策输出非法节点索引；速度政策仍输出合法 $(v,\omega)$，但会撞墙或转圈」。

然后必须点两次探针：「揭晓路点丢地图」「揭晓速度丢地图」。只揭晓当前随意设置不算通过。抓杯子阶段应显示手臂 token，路点索引为「未使用」。地图关掉时节点标记应变淡，但不能把杯子也删掉：杯子是物体，不是地图节点。

### Step 3：把厨房任务写成两行 label

取序列概念：`[img] 去 厨房 拿 杯子` 之后，走到台面的一步是 `mode=base` 加路点或 $(v,\omega)$；抓杯子的一步是 `mode=arm` 加 7 个 $z$。写出每一步哪些位置不是 `-100`。两行的非 `-100` 计数必须不同。这是第 01 课 mask 纪律在身体维上的延伸。

一张最小对照表可以这样填。条件 token 一律 `-100`，只列出动作位置。

| 拍 | 模式 label | 手臂 7 个 label | 底盘 2 个 label | 路点 label | 有效个数 |
|---|---|---|---|---|---|
| 走到台面、路点、有图 | 105 | 全 `-100` | 全 `-100` | 110 | 2 |
| 走到台面、路点、无图 | 105 | 全 `-100` | 全 `-100` | 110（非法，仍可作负例） | 2 或 0 |
| 走到台面、速度、无图 | 105 | 全 `-100` | 93, 103 | `-100` | 3 |
| 抓杯子 | 104 | 37…82 | 全 `-100` | `-100` | 8 |

无图路点这一行要事先约定：非法输出要不要进损失。进损失，模型学会「没图时不要预测 3」；不进损失，模型对 $N=0$ 无监督，推理时仍可能吐 3，靠执行器挡下。本课 CPU 走后一种：非法是执行期谓词，不是训练期把 label 改成 `-100`。Lab 对应执行期。谁在训练里把非法样本的路点 label 改成 0，等于教模型「没图就回起点」，和非法索引探针冲突。约定写在数据卡上，不允许事后改。

### Step 4：负对照，禁止把 $N$ 写死

在 L 桶把 `n_nodes` 改回 6，图像仍是「看不见节点」。若实现只看「地图开关」布尔而不看 $N$，合法标志会错。修复办法是：合法性函数只接收 `(i, N)`，不接收 `mapOn`。Lab 的复选框只能改 $N$ 和可视化。

### Step 5：对照表，数字来自揭晓

| 设置 | 路点索引 | 速度 token | 失败模式 |
|---|---|---|---|
| 走到台面、路点、地图开 | 3 / 6 合法 | 未使用 | 无 |
| 走到台面、路点、地图关 | 3 / 0 非法 | 未使用 | 非法索引 |
| 走到台面、速度、地图开 | 未使用 | 合法底盘切片 | 无 |
| 走到台面、速度、地图关 | 未使用 | `[93, 103]` | 撞墙或转圈 |
| 抓杯子、任意政策、地图关 | 未使用 | 未使用 | 无（手臂切片） |

表中速度丢地图的 token 以 CPU `lost_map_velocity_tokens` 为准。Lab 使用同一组 $(1.1,1.45)$。若你改了 `LOST_MAP_VELOCITY`，两处一起改，并在记录里标注约定变更。

### Step 6：记录三栏

上游事实抄 256、97%、85%、37.4、54.0、88%、0%、90%。本课约定抄 $B=8$ 与四个起点。本次测量抄本次运行。禁止用本次测量覆盖上游事实。

## 9. 评测与测量

主指标是机制指标，不是 R2R-CE 成功率。

| 指标 | 定义 | 通过 |
|---|---|---|
| 箱边分离 | $\Delta_x\neq\Delta_v$，$\Delta_{\mathrm{yaw}}\neq\Delta_\omega$ | 两处都成立 |
| 偏移合法性 | 手臂、底盘、模式、路点两两不相交 | 集合相等 |
| 共享箱边探针 | $v=1.2$ 误用手臂箱边时落到最后一格 | 必须发生 |
| 路点合法 | $N=6,i=3$ | token 110 且合法 |
| 路点非法 | $N=0,i=3$ | token 110 且非法 |
| 速度仍合法 | 丢地图后 $(1.1,1.45)$ 的 token 在 $[88,104)$ | 必须成立 |
| 失败分叉 | 非法索引与撞墙或转圈同时出现 | 必须同时 |
| Lab 预测 | 先选 `split` 再揭晓两次探针 | Gate 通过 |

不要把 Lab 里机器人圆点碰到灰色格子写成真机碰撞。教具里的墙是 CSS 背景，token 合法只说明整数落在底盘切片。

若引用论文数字，带表号或节号：RT-1 Table 2 的 97 / 76 / 83 / 59；NaVid Table I 的 SR 37.4；NaVILA Table I 的 SR 54.0；Mobility VLA Table 5 的 0% 与 90%。横着减这些数没有意义，成功定义不同。第 [31](31_vla_evaluation.md) 课的评测纪律在这里继续有效：仿真成功率不能直接当成真机能力。

SPL、NE、nDTW 是 VLN 的标准量，本课 CPU 一个都不算。原因：缩小版没有目标坐标的米制真值，也没有路径长度。Lab 的格子路径不能冒充 SPL。若你额外写了一个仿真器去算 SPL，把它标成「超出本课，不计入 Gate」。本课通过条件停在词表与合法性，是为了让没有仿真器的人也能完成高级课。有仿真器的人仍然必须先过词表，再谈 SPL。顺序反了，会出现「SPL 还行、路点 id 和手臂 id 重叠」这种无法维修的系统。

## 11. 根据症状定位失败环节

| 症状 | 先查 | 不要先做 |
|---|---|---|
| $v=0$ 反量化后底盘仍爬 | 是否共用手臂 $[-1,1]$ 箱边 | 加大学习率 |
| 走路时夹爪乱开 | mask 是否在底盘步监督了手臂 id | 改视觉编码器 |
| 丢地图后路点仍显示合法 | 合法性是否只看切片而不看 $N$ | 加节点数到 256 |
| 丢地图后速度也报非法 | 是否把两种失败焊成一个 `if not map` | 重训 VLM |
| 路点 token 落在 37 | 偏移是否漏了 $D_{\mathrm{arm}}B$ | 怀疑 tokenizer 坏了 |
| Lab 一揭晓两种政策都停在原地 | 速度路径是否被写成空数组 | 改预测选项 |
| 与第 24 课示例 token 对不上 | `ARM_DIMS` 是否被改 | 改 RT-1 的 256 |
| 引用了未打开论文的成功率 | 第 3 节上游事实表 | 用记忆补齐 |

调试时打印四件事：$N$、$i$、`legal`、token 列表。缺 $N$ 的日志无法区分「切片预留了 6 个号」和「当前图有 6 个点」。

再补一张「看起来像导航、其实是手臂」的表，避免和第 24、25、32 课抢症状。

| 你看见的现象 | 可能属于 | 本课该不该收 |
|---|---|---|
| 7 维 token 与文字 id 重叠 | 第 24 课偏移 | 否，先回 24 |
| $B=2$ 时高频来回消失 | 第 25 课量化 | 否，本课不改 $B$ 的重建课 |
| 答案对、点击格子错 | 第 23 / 32 课接地 | 否 |
| 夹爪在错误深度闭合 | 第 35 课规格 | 否 |
| 走路时夹爪 token 落在 37 | 本课身体切片 | 是 |
| $N=0$ 仍显示节点 3 合法 | 本课合法性谓词 | 是 |
| 无图时底盘转圈，token 仍在 $[88,104)$ | 本课失败分叉 | 是 |
| 语音 PAUSE 后物体回到原位 | 第 07 课对照 | 否，底盘不能 undo |

第 07 课的 PAUSE 丢掉的是音频缓冲，重说一遍可以覆盖上一次的词。底盘转过门之后，门框相对机器人的角度已经变了，重放上一个 chunk 不会把门转回来。本课不实现力门限，只要求：非法索引时不得调用跟踪器，以免「解码失败」变成「继续用上一拍速度」。实现上这是一行 `if not legal: v, omega = 0.0, 0.0`。漏了这行，路点政策在 $N=0$ 时会退化成速度政策，两种失败重新焊死。

还有一种更隐蔽的退化：合法性谓词写成 `0 <= i < max(N, 1)`。$N=0$ 时 `max(N,1)=1`，$i=0$ 变成合法，机器人被送到预留切片的 0 号节点。教学图的 0 号是起点，看起来像「安全回起点」，日志里没有非法。真机上 0 号可能是充电座、楼梯口或地图文件里的垃圾节点。本课把 $N=0$ 的任意 $i$ 都判非法，就是为了禁止这种「好心 clip」。CPU 的 `map_off_waypoint_is_illegal` 在 $i=3$ 上检查；你自己加一条 $i=0,N=0$ 也应非法。只测 $i=3$ 不够，因为有人会写 `if i>=N: i=0`。

速度政策的隐蔽退化是把撞墙写成 `terminate`。撞墙之后模式仍应是底盘，token 仍在 $[88,104)$，只是积分越出房间。若把碰撞接到模式 106，失败模式会从「合法但危险的速度」变成「回合结束」，和路点非法在日志里都显示为停止。本课要求停止的原因可区分：非法索引、碰撞、转圈、terminate。四种原因用四个字段，不要共用一个 `stopped=True`。

Lab 记录至少包括：预测选项的原文、路点丢地图时的 `i / N`、速度丢地图时的 token 串、抓杯子时的手臂 token 是否落在 $[32,88)$。缺预测原文的记录视为未完成第 8 条能力。揭晓之后改预测再截图，视为未完成 Gate。浏览器会把进度写进 `useCompletionGate` 的 payload，其中 `failuresDiffer` 必须为真。交作业时把 payload 里的 `waypointIndex`、`nNodesLost`、`velocityFail` 抄进记录，不要凭记忆重填。

## 13. 前沿对照与改造方向

### 13.1 公开方案

同一问题在 2022–2024 年至少分成三条工程路线。

第一条，操作模型里附带底盘维。RT-1 把 3 维底盘和 7 维手臂放进同一套 256 bin，用模式维分时执行。它证明移动操作器可以在一个 Transformer 里同时走路和抓取，评测主体仍是柜台技能，不是跨房间 VLN。

第二条，拓扑图加预训练模型。LM-Nav 把语言、视觉接地和视觉导航拆成三个冻结模型。ViNT 把短程相对路点做成可跨身体预训练的基础模型，长程再挂图。Mobility VLA 把长上下文 VLM 用在「找导览视频里的哪一帧」，执行仍交给图。Table 5 说明：2024 年 6 月查询的 Gemini 1.5 Pro 还不能把同一套图像直接变成可部署的逐步路点。

第三条，把导航写成 VLM 的语言动作，尽量不建图。NaVid 输出带数量的前进与转向；NaVILA 把同一思想接到腿足，并明确写成两级时间尺度：VLA 低频出中层命令，运动政策实时避障。NaVILA 还把中层语言映射到固定速度集合，这是「语言词表」和「底盘词表」之间的一张薄表，不是 256 bin。

本课缩小版三条都只保留机制：模式维对应第一条；非法索引对应第二条；丢地图后合法 $(v,\omega)$ 乱走对应第三条。

2024 年之后还有把多种导航任务塞进同一个视频 VLA 的工作，例如 Uni-NaVid 在摘要里自称统一多种具身导航。本课检索到了它的 arXiv:2412.06224 条目，但没有打开 HTML 核对动作空间和表内数字，因此不引用其成功率，也不把它的架构写进对照表。需要用它时，先打开页面再补一行。同样的纪律适用于任何只在综述里露过面的名字。课程允许、并且要求使用检索工具；检索到标题不等于已经核对数字。

把三条路线画成决策：你有没有一张可以查询的节点表？有，则高层最小输出是节点或帧索引，合法性跟着 $N$ 走，丢掉表就应得到非法索引。没有，则高层最小输出是速度、相对路点或中层语言，丢掉表之后输出仍可解码，失败转到碰撞、转圈或走错房间。RT-1 介于两者之间：没有 VLN 意义下的节点表，但有模式维把底盘 bin 从手臂 bin 里隔开。本课 Lab 的地图开关模拟的是第一种的运行时依赖；速度政策模拟的是第二种的物理失败。两套开关都要按过，决策树才算被走过。

### 13.2 缩小版和前沿的差距

规模差距：教学 $B=8$ 对论文 $B=256$；6 个路点对 Mobility VLA 的 948 帧导览；单房间 CSS 格子对 $836\,\mathrm{m}^2$ 办公室和户外郊区。这些用数据和场地可以缩，公式不用改。

机制差距：教学路点号写死为 3，不是 CLIP 检索出来的。教学速度丢地图的 $(1.1,1.45)$ 是夹具，不是学到的启发式。NaVILA 的 12 维关节跟踪、ViNT 的扩散子目标、LM-Nav 的动态规划 $Q(i,v)$，缩小版都没有。缺它们属于机制未实现。NaVid 训练 672 GPU hours、NaVILA 8B 在 4090 上约 1 FPS，属于规模。不要用「我没有 8B」当借口，跳过 $N=0$ 的合法性谓词。

NaVILA 的中层到速度映射可以写成一张字典，而不是分箱。设语言动作 $w\in\{\text{forward},\text{left},\text{right},\text{stop}\}$，数量 $q$ 是厘米或角度。论文把类型先投到固定速度，再按数量决定持续时间：

$$
(v,\omega,T)=
\begin{cases}
(0.5,0,q/0.5), & w=\text{forward},\ q\text{ 以米计}\\
(0,\pi/6,q/(\pi/6)), & w=\text{left}\\
(0,-\pi/6,q/(\pi/6)), & w=\text{right}\\
(0,0,0), & w=\text{stop}
\end{cases}
$$

这张字典的输出仍是 $(v,\omega)$，本课速度词表可以对它再分箱；字典本身不是 256 bin。合并两层时常见错误是：把「75 cm」里的 75 当成路点号，或当成手臂 $x$ 的 bin。75 在教学手臂 $[-1,1]$ 上甚至越界。中层语言的数字是物理量，必须先经字典变成速度，再经箱边变成 id。跳过字典的系统，看起来像 VLA，执行时会把厘米写进无量纲箱子。

ViNT 把相对路点按机器人最大速度归一化，部署时用机体自己的跟踪器还原。这是「跨身体共享动作表示」的另一种做法：共享的是无量纲相对位移，不是共享箱边。本课底盘教学区间 $[0,1.5]$ 没有按最大速度归一化到 $[-1,1]$，就是为了避免和手臂区间看起来一样。看起来一样的区间最容易被复制粘贴进同一个 `LOW, HIGH`。若你要做跨身体底盘，先写归一化，再写分箱，两行都出现在数据卡上。

### 13.3 动手改造清单

四个实验都在本课的编码函数和 Lab 政策上改，不新开 8B 训练。

1. **把底盘改回 RT-1 的 3 维 $(x,y,\mathrm{yaw})$。** 改 `BASE_DIMS` 长度为 3，重算 `BASE_START` 之后所有起点。预算：CPU 数秒。预期：路点起点后移 8 个 id；手臂示例 token 不变。失败判定：手臂 token 跟着变，说明偏移公式写死了 88。
2. **把 $N$ 从 6 改到 1 和 0。** $N=1$ 时只有起点合法，$i=3$ 应非法。预算：CPU 数秒。预期：非法条件随 $N$ 变，不随复选框文案变。失败判定：$N=1$ 且 $i=0$ 被判非法。
3. **给速度政策加一个可通行性掩码。** 在单车积分里，若下一步进入墙则把 $v$ 置 0、$\omega$ 保持，得到「纯转圈、不撞墙」的失败。预算：改十行。预期：`collided=False` 且 `heading_travel>\pi/2`，失败模式仍与非法索引不同。失败判定：把 $v=0$ 写成 terminate 模式。
4. **把中层语言动作做成正则解析。** 输入 `"move forward 75cm"`，输出 $(v=0.5,\,T=1.5\,\mathrm{s})$，对照 NaVILA 的固定速度集合。预算：一页脚本。预期：解析失败时不写进底盘 bin，而写进文本错误。失败判定：把这句话的 token id 当成路点号 75。

改造实验的记录格式与第 01 课相同：改了哪几个常数、预期哪一条 `checks` 仍为真、哪一条必须被你同步改掉。例如把底盘改成 3 维之后，`concatenated_slices_cover_without_gap` 的右端点会从 107 变成 115，路点起点后移。若测试仍断言 `waypoint_start==107`，那是测试没改，不是编码器错。论文数字 256、3 Hz、88%、0% 在任何改造里都禁止被改写。改造只动本课约定栏。

### 13.4 顺手复现

| 论文结论 | 缩小版对应 | 能否看到同方向趋势 |
|---|---|---|
| RT-1：底盘与手臂分维，模式分时 | 四个切片 + 模式 id | 能；256 bin 与 3 Hz 不能复现 |

## 14. 论文与必读材料

1. [RT-1](https://arxiv.org/abs/2212.06817)（arXiv:2212.06817）。带着什么问题读：7+3+1 维各自切多少 bin？三模式开关在执行时如何避免另一套身体抖动？3 Hz、35M、TokenLearner 的 81→8 与本课教学 8 bin 各是哪一层的数字。读完应能说明它为什么是「操作模型里的导航子集」，不是 VLN 专用系统。
2. [LM-Nav](https://arxiv.org/abs/2207.04429)（arXiv:2207.04429）。带着什么问题读：三个预训练模型各干什么？目标函数 (2) 里路标似然和可通行性如何相乘？20 条指令、6 km、85% 写在哪一节。没有图、没有 ViNG 时失败像本课哪一条。
3. [ViNT](https://arxiv.org/abs/2306.14846)（arXiv:2306.14846）。带着什么问题读：图像目标为什么被选作可跨数据集的预训练任务？$H=5$ 的相对路点和拓扑节点索引差在哪？4 Hz 跟踪器属于哪一层。不要把扩散子目标写成 RT-1 的 bin。
4. [NaVid](https://arxiv.org/abs/2402.15852)（arXiv:2402.15852）。带着什么问题读：观测里明确排除了什么（地图、里程计、深度）？语言动作的四个类型和数量参数如何解析？Table I 的 SR 37.4 与 RGB-CMA 的 5.0 差在哪。路点变体消融说了什么。
5. [NaVILA](https://arxiv.org/abs/2412.04453)（arXiv:2412.04453）。带着什么问题读：为什么不让 VLA 直接出低层关节？中层语言怎样变成 $\{0.5,\pi/6,-\pi/6,0\}$？Table I 的 54.0 与真机 88% 各自的评测协议。VLN-CE-Isaac 上视觉相对盲政策的 14 个百分点用在哪句结论里。
6. [Mobility VLA](https://arxiv.org/abs/2407.07775)（arXiv:2407.07775）。带着什么问题读：MINT 的输入是什么？高层输出为什么是帧索引而不是 $(v,\omega)$？Table 2 与 Table 5 的成功率分别测量哪一层。直接 VLM 控路点的 0% 能否当作「长上下文已经会导航」。

读完应能用一句话把本课收住：手臂 7 维、底盘速度、路点索引可以出现在同一条因果模型里，但必须占用互不覆盖的整数段；丢掉地图时，路点段会变成非法 id，速度段仍会驱动电机。下一课规格才把维数从平行夹爪抬到灵巧手和人形，本课的偏移公式在维数升高后仍然先分身体、再分箱。

阅读顺序建议：先 RT-1 §5.1（分箱、模式、3 Hz），再 LM-Nav §4（图、路标、搜索），再 Mobility VLA §4 与 Table 5（长上下文仍然要图），再 NaVid §III–IV 与 Table I（无图的语言动作），再 NaVILA §II 与 Table I（中层语言加腿足），最后 ViNT §3–4（相对路点作为可预训练的短程接口）。这个顺序按「动作写在哪一层」从操作子集走到必须建图，再走到故意不建图。倒着读容易一开始就陷进 8B 和 YouTube 管线，把 $N=0$ 的谓词挤掉。

每篇只交三句笔记：底盘动作进入模型的位置（bin / 节点 id / 中层语言 / 相对路点）；丢掉地图或去掉图模块时失败像哪一类；一条你核对过的数字及其表号或节号。数字没有表号或节号的，不要写入交付物。论文 PDF 很大，允许只精读指定节；指定节之外的附录数字，未打开就不引用。

补充阅读时保持同一条纪律。ViNG、GNM、NoMaD 被 ViNT 和 LM-Nav 引用，本课没有单独打开它们的 HTML，不写它们的成功率。ETPNav、BEVBert、HNR 出现在 NaVILA Table I 的对照列，本课只借用该表里已经核对过的 NaVILA 自己的 NE / OS / SR / SPL，不把对照方法的架构写成「本课也实现了」。Gemini 1.5 Pro 的 1M token 上下文写在 Mobility VLA Table 4 的讨论里，用来解释为什么 1 FPS 的导览能塞进高层；它不是本课的词表常数。GPT-4V 在 0.2 FPS 导览上的推理无关命中 60%，同一表里 Gemini 1.5 Pro 为 95%，1 FPS 时 GPT-4V 超出 token 限制。这些数字属于「长上下文能不能看见整栋楼」，属于 Mobility VLA 的高层，不属于手臂 bin。抄进本课 `BINS` 的人，等于把上下文长度和动作箱数当成同一个 $B$。

若后续公开了新的导航 VLA，引用前仍须打开摘要或 HTML。模型名、arXiv 号、成功率三项缺一，就只写「未核对，不引用」。本课已经打开的六篇足够支撑词表分叉：RT-1 给出同一模型里的底盘维和模式维，LM-Nav 与 Mobility VLA 给出图上的节点编号，NaVid 与 NaVILA 给出无图的中层语言或速度，ViNT 给出短程相对路点如何再接到图上。六篇的并集是一张分层图，不是一张更大的均匀分箱表。
