# 第 52 课：让多模态模型在看见图之后调用工具

> 内容：看图后的通用工具调用、JSON schema 门、发票进位夹具<br>
> 建议周期：阅读约 70 分钟；CPU 实验数分钟<br>
> 硬件：无 GPU 可读完全文并跑 CPU 机制实验；复现 LLaVA-Plus / GPT4Tools 规模需要多卡与视觉工具链<br>
> 产物：工具目录与必填字段、发票三列账本、schema 拒绝日志、文献数字表

## 1. 看见图以后何时该调用工具而不是直接答

一张发票摆在眼前。三行印刷金额是 18.90、26.50、15.80，问税前小计。视觉语言模型把三个数字读进上下文，下一句却写出 51.20。数字是对的，加法错了：45.40 加 15.80 时，个位 5+5 加上从十分位来的进位 1 得到 11，应当再向十位进 1，模型把这一位丢掉，十位写成 5，答案少了整整 10 元。同一组被读对的数字交给计算器，得到 61.20。失败发生在「看见之后、出数之前」。本课改的就是这一段：模型何时必须把已经看见的东西写成工具参数，交给外部执行器，再把观察写回回答。

第 32 课把屏幕点击和机械臂末端写成同一套 $[0,1]^2$ 接地，见[第 32 课](32_gui_agent_grounding.md)。那一课的动作是点哪里、抓哪里，执行器是键鼠或关节。本课的动作是调用计算器、裁剪、深度、搜索。点「提交」和调用 `calculator(expression=...)` 看起来都像「出手」，目录完全不同。把本课做成 GUI 代理，等于把发票小计重新画成一次点击。

第 44 课问版面：合计字符串 32.00 对了，框若盖在表头「金额」上，版面命中仍为假，见[第 44 课](44_document_layout.md)。本课假定单元格已经对，数字已经进上下文，问的是这些数字要不要再送进计算器。第 44 课的失败是框；本课的失败是进位。同一张发票可以两边都测，必须两个 run ID。

第 45 课问长视频先检索哪一层，工具参数只能指向已召回的时间戳和框，见[第 45 课](45_multimodal_retrieve.md)。那一课的搜索是选层、召回、精读。本课的 `search` 是查图外知识：税率条款、品牌规格、过期公告。把本课的搜索写成「再扫一小时像素」，层又混了。

要改的模块是工具目录、调用格式和执行门，不是视觉编码器，也不是 GUI 头。验证改对了的标准有两条，都必须能在教学模拟里复现：印刷数字被读对时，直接答得到 51.20，调用计算器得到 61.20；缺 `expression` 的计算器调用、缺框的裁剪调用不得进入执行。CPU 实验再核对同一套数字和同一张 schema。

把「通用工具」说死之后，还要能指出它不覆盖什么。它不覆盖把 click / type / scroll 训成空间接地，那是第 32 课。它不覆盖把字段字符串和单元格框拆开，那是第 44 课。它不覆盖一小时带子先建哪一层索引，那是第 45 课。它覆盖的只有：一张已经在上下文里的图、一句要精确计算或局部放大或读深度或查外部事实的问题、一个带 JSON schema 的工具目录、一次可拒绝的执行。谁在这四个对象之外写成「智能体已经完成」，就把范围重新抄一遍。

本课术语：

| 术语 | 简要解释 |
|---|---|
| 工具调用 | 模型输出工具名和参数，交给外部执行器，再把返回值读回上下文 |
| 工具目录 | 当前允许的名字、用途和 JSON schema，不在目录里的名字必须拒绝 |
| Schema 门 | 检查必填键、类型和几何约束，不通过则 `Valid=0`，不得执行 |
| 观察 | 合法执行留下的返回值；被拒绝的调用没有观察，只有拒绝原因 |
| 计算器 | 对已抽出的表达式做精确算术，不负责读图 |
| 裁剪 | 按框切出子图再编码，用来看小字、小物体、局部结构 |
| 深度 | 在图像平面上的点 $(u,v)$ 查询相对深度，本课不把它写成抓取闭合 |
| 搜索 | 用自然语言查询图外文档或网页，不是第 45 课的检索层 |
| 心算 | 模型用 next-token 自己做加减乘除，进位、小数位、括号都可能错 |

[第 23 课](23_grounding_ocr_spatial.md)已经要求：答对不等于看对位置。本课再加一条：看对数字不等于算对小计。Lab 把发票印在左侧，揭晓前你先选「看见了数字、心算错、工具对」这一类诊断，再看 OCR、心算和计算器三列。CPU 实验用整数分当单位，避免浮点争辩。

可以用同一张发票把四类工具钉在不同问题上。税前小计：该调计算器。右下角一行 6 磅的脚注税率：该先裁剪再 OCR。货架上「哪盒更靠后」：该调深度。这款咖啡豆今年是否召回：图上没有公告，该调搜索。四问共用一张图，工具名不能互换。拿裁剪去加三个小数，拿计算器去找脚注，拿搜索去量前后，都会留下「调用了工具但问题没被那把工具碰到」的日志。本课验收盯的是名字、参数和返回值是否对得上那一问，不盯「工具链很长」。

四问和四工具的对照先写成表，后面所有夹具都按这张表选名字：

| 问题 | 看见了什么仍不够 | 该调用 | 必填参数 | 直接答的典型错法 |
|---|---|---|---|---|
| 税前小计多少 | 三行金额 | `calculator` | `expression` | 漏十位进位，写出 51.20 |
| 脚注税率是多少 | 整页发票 | `crop` | `image_id` 与框 | 把页眉「税率」旁的空白读成 0 |
| 哪盒更靠后 | 两个包装的二维位置 | `depth` | `image_id` 与 $(u,v)$ | 把「左边」说成「更远」 |
| 这款豆今年召回了吗 | 袋上的品牌字 | `search` | `query` | 用训练语料编一个年份 |

表里每一行都满足「图像已经在上下文里」。缺的是执行，不是看见。谁把第四行改成「在一小时巡检录像里找红色阀门」，请回到[第 45 课](45_multimodal_retrieve.md)。谁把第一行改成「点屏幕上的合计按钮」，请回到[第 32 课](32_gui_agent_grounding.md)。谁把第一行改成「32.00 对但框在表头」，请回到[第 44 课](44_document_layout.md)。本课的四行都不碰那些对象。

## 2. 本课解决的问题

当前系统（按[第 22 课](22_standard_vlm_recipe.md)训出的视觉语言模型，或 MiniMind-O 这种把图接到 Thinker 的 Omni）默认把「看见图」当成「可以开始生成最终答案」。生成头擅长把上下文里的数字抄进句子，不擅长十进制进位，也不擅长承认「这一点的深度我没有」。直接答的失败会被流畅的中文盖住。GPT4Tools（Yang 等，arXiv:2305.18752）把这件事拆成三截成功：Thought 决定要不要调，Action 选对名字，Arguments 填对参数；三者乘在一起才叫 SR。Vicuna-13B 只靠提示时 SR 为 12.4，微调后 seen-tool SR 为 94.1，GPT-3.5 提示为 84.8（原文 Table 2）。数字说的是「调用格式可以学会」，没有说「看见图就会算术」。

本课要同时回答三个互相卡住的问题。

第一，何时必须调用。算术、局部细节、度量几何、图外事实，这四类在权重里没有可靠实现。ToRA（Gou 等，arXiv:2309.17452）把自然语言推理和程序执行交错：ToRA-Code-34B 在 MATH 上 50.8，GPT-4 的思维链为 42.5，GPT-4 写程序为 51.8（原文 Table 2）。视觉这边更硬：发票数字已经在图里，模型仍会把 61.20 写成 51.20。V*（Wu 与 Xie，arXiv:2312.14135）证明高分辨率细节经常不在全局编码器里，需要按目标搜索再裁。看见了整张图，不等于看见了该看的那一块。

第二，调用怎样才算合法。一次调用写成 $c=(n,a)$，$n$ 是名字，$a$ 是参数对象。目录 $\mathcal{N}$ 给每个 $n$ 一张 schema $S_n$，必填键集合为 $R_n$。合法性是合取，不是「模型很有信心」：

$$
\mathrm{Valid}(c)=\mathbf{1}[n\in\mathcal{N}]\cdot\mathbf{1}[R_n\subseteq\mathrm{dom}(a)]\cdot\mathbf{1}[\mathrm{Type}(a;S_n)=1]\cdot\mathbf{1}[\mathrm{Cons}(a;S_n)=1]
$$

只有 $\mathrm{Valid}(c)=1$ 才允许 $\mathrm{Exec}(c)=T_n(a)$。否则 $\mathrm{Exec}(c)=\bot$，观察槽为空，拒绝原因必须留下。缺 `expression` 的计算器、缺 `x0` 的裁剪、$(u,v)$ 落到单位正方形外的深度、名字叫 `click_submit` 的 GUI 动作，在本课全部是 $\bot$。第 32 课的点击可以是合法 GUI 动作，对本课目录来说它不在 $\mathcal{N}$ 里。

第三，观察如何写回回答。LLaVA-Plus（Liu 等，arXiv:2311.05437）把对话从「Human 图+问 / Assistant 答」扩成：Assistant 先写 `skill_use`，Human 再回 `skill_result`，Assistant 最后写给用户看的 `value`。训练损失只落在模型该写的那些 token 上。规划器全程看见原图，这是它相对 Visual ChatGPT、MM-REACT、GPT4Tools 的分界：后三者的分配器是纯语言模型，图像只在工具被点名之后才出现。本课的缩小版不训 7B，但账本同构：没有 `skill_result`，就不得把最终 `value` 写成「已经算过」。

这三个问题不能分开买。只会喊「用计算器」、表达式是空字符串，执行器不该跑。只会填参数、名字是 `click_submit`，本课不该当成成功。只会合法执行、不把 61.20 写进最终回答，用户仍看到 51.20。所以验收必须同时碰到进位和缺参。缺任何一条，都可以用「我接了一个工具 API」交差，那不是这课要的东西。

和第 32 课的边界：屏幕点击是空间接地，本课工具是带 schema 的外部模块。和第 44 课的边界：版面命中管字段是否来自正确单元格，本课管单元格里的数字要不要再计算。和第 45 课的边界：检索层决定哪一段视频有资格进入阅读器，本课的搜索查的是图外文本。和第 17 课的边界：GRPO 需要可验证奖励，见[第 17 课](17_grpo_rlvr.md)；本课的可验证对象是 schema 与算术，不在这里重做组相对优势。

失败条件预先写死：

- 只报最终小计字符串，不报 OCR 列、心算列、工具列；
- 把 GUI 点击命中写成通用工具成功；
- 把第 45 课的召回@k 写成 `search` 命中；
- 缺必填参数仍去执行，再用「模型自己补全了」辩护；
- 声称「看见图就会算」，却造不出心算 51.20、工具 61.20 这一对。

把失败写成可观察的日志，比写成口号有用。一次不合格的运行至少应留下：查询原文、OCR 读到的数字列表、是否发出调用、调用名、参数对象、`Valid`、拒绝原因、执行结果、最终回答。缺「是否发出调用」时，别人无法判断是心算错还是工具错。缺「拒绝原因」时，空参数会被解释成工具坏了。本课把这两项写成和[第 01 课](01_baseline_reproduction.md)的 mask 统计同类的必留字段。训练侧的总 loss 在这里几乎帮不上忙：模型可以学会抄工具名，同时把 `arguments` 留空。阅读器训得越强，越会把 51.20 写成「约六十元」这种听起来负责的句子。那句话没有经过执行器，不能当收银记录。

还可以用一条时间线把四类工具的代价钉死。设一张 1024 边的发票，查询 1 条。直接答：一次前向，账单最低，进位无担保。调计算器：OCR 之后一次常数时间求值。调裁剪：按框再编码一次子图，视觉 token 随框面积涨。调深度：一次单点或单图前向，得到相对深度。调搜索：一次外部往返，延迟和噪声都不在视觉编码器里。四条路径的正确条件和账单不同。本课验收盯「该调的那条有没有被合法调用」，是因为那一笔直接决定 51.20 会不会变成 61.20。谁把四条路径都跑一遍再挑一个好看的数字，请他出示调用日志。没有日志，就还是直接答。

## 3. 开始前需要准备什么

本课不依赖 MiniMind-O 的训练脚本。需要的是第 23 课那种「字符串对不等于区域对」的直觉，以及第 32、44、45 课「同一张图可以问三种完全不同的问题」的接口意识。没有读过那三课也可以往下走，但遇到「点对了按钮却算错小计」「字段对了却加错行」「检索对了却把搜索当像素扫描」时，要回到那三课，而不是在本课里重做接地、版面或选层。

开始前把笔记本分成两栏。左栏只抄打开过的论文句：表号、SR、MATH 准确率、V*Bench、工具条数。右栏写本课约定：三行金额 18.90 / 26.50 / 15.80，真值 61.20，心算漏十位进位得到 51.20，OCR 清晰度阈值 0.6，裁剪框与深度点都在 $[0,1]^2$，目录只有 `calculator` / `crop` / `depth` / `search`。左栏数字可以对外引用，右栏数字只能当教学夹具。有人把 Lab 里的 51.20 写成「复现了 ToRA 的 MATH 50.8」，属于把右栏抄进左栏。

**上游事实（打开原文核对过）：**

- Visual ChatGPT，arXiv:2303.04671：用提示把视觉基础模型接到 ChatGPT，公开仓库 [microsoft/visual-chatgpt](https://github.com/microsoft/visual-chatgpt)；
- HuggingGPT，arXiv:2303.17580：规划、选模型、执行、汇总四段；
- MM-REACT，arXiv:2303.11381：ChatGPT 分配视觉专家；LLaVA-Plus 原文 Table 5 给出它在自建工具台上 grounding 30.2、OCR 77.3；
- ViperGPT，arXiv:2303.08128：Codex 生成 Python，API 含 `find` / `compute_depth` / `simple_query`；GQA test-dev 零样本 48.1，BLIP-2 为 44.7；OK-VQA 零样本 51.9；
- VisProg，arXiv:2211.11559：无需任务训练的视觉程序，CVPR 2023；
- GPT4Tools，arXiv:2305.18752：71K 指令，23 个训练工具加 8 个未见工具；Vicuna-13B seen SR 94.1，unseen 90.6；目录里含 Predict Depth On Image、Crop the Given Object；
- LLaVA-Plus，arXiv:2311.05437：LMM 当规划器；In-the-Wild 从 LLaVA 的 57.1 到 69.5；SEED-Bench 从 44.45 到 55.01；自建工具台 All Tools 82.3 对 LLaVA 的 58.7；7B 与全部工具可在 80GB 卡上加载；
- V*，arXiv:2312.14135：SEAL + V* 搜索，V*Bench 总体 75.39，无搜索的同结构 45.02；
- Visual Sketchpad，arXiv:2406.09403：数学任务平均 +12.7 个百分点，视觉任务 +8.6；GPT-4o+Sketchpad 在 V*Bench 80.3、BLINK spatial 83.9；
- ToRA，arXiv:2309.17452：ToRA-Code-34B 的 MATH 50.8；交错格式相对纯程序、纯思维链都更好；
- Chameleon，arXiv:2304.09842：GPT-4 规划器在 ScienceQA 86.54，TabMWP 98.78；
- CogCoM，arXiv:2402.04236：六种操作 OCR / Grounding / Counting / Calculate / CropZoomIn / Line，自动 70K 加人工数学 7K；
- Qwen2.5-VL，arXiv:2502.13923：报告写明可做视觉代理、工具使用、电脑与手机操作。电脑与手机操作归第 32 课；本课只借用「看图后可以调用工具」这一句，不抄 OSWorld 数字。

**课程约定：**

- 浏览器里的发票是教学模拟，数字由进位规则和 OCR 阈值算出来，不是 LLaVA-Plus 或 GPT-4V 的前向输出；
- CPU 实验只证明公式可复核，不证明 CORD、DocVQA、MathVista 成功率；
- 金额用整数分存储，18.90 记为 1890，求和后再除以 100。报告对外仍写元；
- 产出目录约定为 `artifacts/lesson52/`。CPU 实验在编排者注册后可用下面这条命令写入该目录；注册前可直接调用 `lesson_52.run()` 复核。

```bash
python3 run.py run 52
```

只读本课、不训模型时，仍需交：schema 手算、教学发票「看见了数字、心算错、工具对」一则、拒绝日志空表。这条支线标记为 `protocol-only`，不能写成「复现了 LLaVA-Plus」。

硬件上，读完加 CPU 实验不需要 GPU。若要接开源视觉语言模型做 Step 3，再准备能放下 7B 的显存。没有这张卡，跳过 Step 3 仍可完成最低交付。软件上只需要 Python 3.10 标准库和能打开本课页面的浏览器。不要为了本课新装检测器、深度网络或搜索引擎。MiDaS、Grounding DINO、CLIP 检索的角色在课文里讲清即可，CPU 实验不跑它们。

## 4. 完成后应具备的能力

完成后，拿到任意「看见图却答错」的样例，你应能完成以下检查：

1. 指出失败落在感知、决策、schema、执行、写回中的哪一截；
2. 写出 $c=(n,a)$ 和 $\mathrm{Valid}(c)$，并列出 $R_n$；
3. 把发票小计拆成 OCR 列、心算列、工具列，标出进位误差是 10.00 元；
4. 对缺参调用给出拒绝原因，且执行计数为 0；
5. 说明裁剪和深度的参数为什么必须落在 $[0,1]^2$；
6. 把 `search` 从图内检索层里拆出来；
7. 对照 LLaVA-Plus 与 GPT4Tools：规划器看不看原图；
8. 形成后续课统一的工具日志字段，而不是只存最终句子；
9. 从一段模型自由文本里拆出 JSON 调用，说明围栏、内心独白和参数对象哪一层丢了键；
10. 在关掉执行器的对照里，指出「仍写出 61.20」是观察槽被语言头污染。

## 5. 原理：边造边讲

四个机制，每个按同一节奏：为什么需要、怎么运转、精确定义、公开实现落在哪、怎么证明做对了。

### 5.1 决策：看见之后仍可能必须停笔

直觉。人看发票时，眼睛已经扫过 18.90，手仍会打开计算器。模型的生成头没有十进制状态机。它把「十八点九零」编码成 token，用的是语言共现，不是进位链。ToRA 原文把三种格式画在 Figure 2：只写理由、只写程序、理由和程序交错。视觉课多一种更糟的格式：只看图，然后直接把数字当已经加过。

机制。给定图像 $I$ 和问题 $q$，模型先得到感知结果 $P=\mathrm{Perceive}(I)$，例如行金额列表、框、点。决策头输出 $d\in\{\mathrm{ANSWER},\mathrm{CALL}\}$。若 $d=\mathrm{ANSWER}$，最终回答 $\hat y$ 完全由 $P$ 和参数记忆生成。若 $d=\mathrm{CALL}$，再写 $c=(n,a)$。教学夹具里，小计问题的正确 $d$ 永远是 $\mathrm{CALL}$，因为 $P$ 只保证数字被抄对，不保证加法。脚注税率问题的正确 $d$ 也是 $\mathrm{CALL}$，名字换成 `crop`。货架前后是 `depth`。召回公告是 `search`。「这是不是一张发票」可以 $\mathrm{ANSWER}$，因为不需要精确算术。

数学。把心算写成对 OCR 数字的带噪声求和。本课固定噪声为漏掉 $10^{k}$ 元进位：

$$
\hat s_{\mathrm{mental}}=\sum_{i} \tilde x_i - 10^{k},\qquad k=1
$$

其中 $\tilde x_i$ 是 OCR 读到的第 $i$ 行。印刷真值 $x=(18.90,26.50,15.80)$，$s^{\star}=61.20$。当 $\tilde x=x$ 时，$\hat s_{\mathrm{mental}}=51.20$。计算器是

$$
\hat s_{\mathrm{tool}}=\sum_{i}\tilde x_i
$$

三列诊断：

$$
\begin{aligned}
\mathrm{Saw}&=\mathbf{1}[\tilde x=x],\\
\mathrm{MentalWrong}&=\mathbf{1}[|\hat s_{\mathrm{mental}}-s^{\star}|>0],\\
\mathrm{ToolRight}&=\mathbf{1}[|\hat s_{\mathrm{tool}}-s^{\star}|=0].
\end{aligned}
$$

本课必须造出 $\mathrm{Saw}=1,\mathrm{MentalWrong}=1,\mathrm{ToolRight}=1$。OCR 把 15.80 读成 15.08 时，$\hat s_{\mathrm{tool}}=60.48$，工具也对不了。那是感知失败，不要记成「计算器坏了」。

公开实现。GPT4Tools 的 Thought 字段对应 $d$：负样本专门教「这次不要调工具」。原文 Table 3：没有图像内容时 SR 36.9，加上图像条件 81.6，再加上下文样本 91.6，再加负样本 94.1。LLaVA-Plus 把空 `Action` 列表当成 $\mathrm{ANSWER}$。ViperGPT 没有显式 $d$，它总是生成一段 Python；逻辑和算术在解释器里，感知在模块里。三种写法都承认：看见图不等于最终数字已经存在。

验证。Lab 默认 OCR 清晰度为 1、路径为计算器。揭晓前必须先选诊断。选「心算对、工具多余」不能过门，因为夹具里心算永远减 10。CPU 实验用分：1890+2650+1580=6120，减去 1000 得到 5120。不要用二进制浮点去比 0.1。

进位为什么是 10 元，值得用手算钉死。先把 18.90+26.50 写成 45.40，这一步即使心算也常对，因为它没有向十位进 1。再加 15.80：

$$
\begin{aligned}
\text{百分位}&: 0+0=0,\\
\text{十分位}&: 4+8=12,\ \text{写 }2,\ \text{进 }1,\\
\text{个位}&: 5+5+1=11,\ \text{写 }1,\ \text{进 }1,\\
\text{十位}&: 4+1=5,\ \text{若漏掉个位来的进位则停在 }5.
\end{aligned}
$$

正确十位是 $4+1+1=6$，得到 61.20。漏进位得到 51.20。误差恰好 10.00，不是「大约算错」。谁把 51.20 解释成「模型四舍五入了」，请他指出哪一条舍入规则会从 61.20 跳到 51.20。没有这样的规则。这是进位链断了。语言头把「四十五」和「十五」拼在一起时，十位 token 的统计更接近「五十」而不是「六十」，于是 5 被写出来。计算器没有这套统计，它只看见 1890+2650+1580。

决策头还要能拒绝不该调的工具。问「这是不是发票」，$d=\mathrm{ANSWER}$ 即可，硬调 `search` 会引入网页噪声。问小计却调 `depth`，执行器可能返回 0.73 这种相对深度，写进回答就变成「大约 0.73 元」。合法性 $\mathrm{Valid}(c)$ 不管名字是否问对了问题。问对问题是决策的责任，填对参数是 schema 的责任。两层都记日志。只有 schema 通过、问题仍牛头不对马嘴时，应把失败记在 $d$ 和 $n$ 上，不要记在执行器上。

### 5.2 Schema 门：缺参数不得执行

直觉。给收银员一张没有金额的计算器指令，他不会按随机键。给深度网络一个 $v=1.4$ 的点，它也不该悄悄夹紧到 1.0 再返回一个看起来合理的数。夹紧会把非法调用变成合法观察，日志里再也找不到谁写错了参数。

机制。执行器前插入纯函数 $\mathrm{Validate}$。它不读图像，不调用网络，只读目录和 $c$。返回记录必须包含：`ok`、`missing`、`type_errors`、`constraint_errors`、`executed`、`result`、`reject_reason`。`executed` 为真当且仅当 `ok` 为真。`result` 在拒绝时必须是空。这一条和「模型稍后会补参数」冲突：补参数是再发一次调用，不是把这一次改成成功。

数学。$R_{\mathrm{calculator}}=\{\texttt{expression}\}$，且 `expression` 必须是非空字符串。$R_{\mathrm{crop}}=\{\texttt{image\_id},x_0,y_0,x_1,y_1\}$，框约束

$$
0\le x_0<x_1\le 1,\qquad 0\le y_0<y_1\le 1.
$$

$R_{\mathrm{depth}}=\{\texttt{image\_id},u,v\}$，点约束 $(u,v)\in[0,1]^2$。$R_{\mathrm{search}}=\{\texttt{query}\}$。目录外的 $n$ 直接 `unknown_tool`。GPT4Tools 把 Arguments 成功写成 $\mathrm{SR}_{args}$，整体

$$
\mathrm{SR}=\frac{1}{N}\sum_{i=1}^{N}\mathbf{1}(\tau_i)\cdot\mathbf{1}(\alpha_i)\cdot\mathbf{1}(\eta_i>0.5)
$$

其中 $\tau_i$ 是 Thought，$\alpha_i$ 是工具名，$\eta_i$ 是参数匹配（文本用 BLEU，路径用后缀）。本课缩小版把 $\eta_i>0.5$ 改成精确匹配加几何约束，因为夹具没有必要引入 BLEU。谁把 BLEU 0.51 的表达式当成已经加对，进位误差会被平均掉。

公开实现。OpenAI 兼容的工具描述用 JSON Schema 写 `parameters.properties` 与 `required`。这是行业接口，不是一篇需要编造的论文。LLaVA-Plus Table 1 的 `API_name` / `API_params` 与此同构。ViperGPT 用 Python 签名和 docstring 当 API，解释器在缺参时抛 `TypeError`，效果也是不得执行。HuggingGPT 把「选哪个 Hugging Face 模型」放在规划之后、执行之前，选错模型等于本课的 `unknown_tool` 或名字错。

验证。CPU 实验固定六类拒绝：空 `arguments` 的计算器、把 61.2 当成 `expression` 的类型错误、只有 `image_id` 的裁剪、`x1<x0` 的框、`v=1.4` 的深度、名字 `click_submit`。全部 `executed is False` 且 `result is None`。合法计算器只接受目录内表达式 `18.90+26.50+15.80`，返回 61.20。不要在 CPU 里 `eval` 任意字符串。

JSON Schema 在本课的最小形状如下。它不是要你实现完整的 Draft 2020-12 校验器，只要求这四个字段能被手写检查：

```json
{
  "name": "calculator",
  "description": "Evaluate an arithmetic expression over extracted numbers.",
  "parameters": {
    "type": "object",
    "properties": {
      "expression": { "type": "string" }
    },
    "required": ["expression"]
  }
}
```

`required` 缺了，执行器会把空对象当成合法调用。`type` 写成 number，模型就会直接把 61.20 当参数塞进来，计算器不再看到加号。`description` 不参与 $\mathrm{Valid}$，它只给规划器当文档；不要把描述相似度当成参数已经填对。裁剪的 schema 必须把五个键都列为 required，不能只写「给一个框」这种自然语言。深度的 $u,v$ 若允许缺省，缺省值往往会变成图像中心，货架前后问题会全部塌到同一点。搜索的 `query` 若允许空字符串，执行器会去搜空查询，返回首页噪声，模型再把噪声写成「已检索」。四张 schema 的 required 集合，就是本课目录的合同。改合同必须升版本号，不能在同一 run ID 里把 `x0` 改成可选。

约束 $\mathrm{Cons}$ 和类型 $\mathrm{Type}$ 要分开记账。`x0` 是字符串 `"0.2"` 时，这是类型失败，还没有轮到几何。`x0=0.7,x1=0.3` 是类型通过、约束失败。把两类失败都写成 `bad_args`，排错时会去改执行器。日志里应出现 `type_error` 或 `constraint_error`。unknown_tool 是第三类：名字根本不在 $\mathcal{N}$。三类拒绝的 `executed` 都是假，`reject_reason` 必须不同。CPU 实验对这三类各放一条夹具，就是为了禁止合并。

把一轮合法调用和一轮缺参调用写成可回放的伪记录，比只谈公式清楚。合法小计：

1. 感知写出 `ocr_list = [18.90, 26.50, 15.80]`；
2. 决策写出 `decision = CALL`，`name = calculator`，`arguments = {expression: "18.90+26.50+15.80"}`；
3. schema 检查 `required` 齐、类型是字符串、表达式在目录内，`Valid = 1`；
4. 执行器返回 `61.20`，观察槽写入该数；
5. 最终 `value` 引用观察槽，用户看见 61.20。

缺参小计：

1. 感知同样写出三个数字；
2. 决策写出 `name = calculator`，`arguments = {}`；
3. schema 得到 `missing = ["expression"]`，`Valid = 0`，`executed = 0`，`result` 为空；
4. 系统把拒绝原因回给模型，这一轮没有观察；
5. 模型若此时直接写 51.20，日志必须显示「拒绝之后仍用语言头出数」。允许的下一动作是 REPLAN：补上 `expression` 再调一次。不允许的下一动作是把拒绝记录改成 `executed = 1`。

两段记录的差别只在第 3 步。感知相同，问题相同，差一个键，收银结果差 10 元。这就是为什么缺参不得执行要写进最低交付，而不能写成「提示词里已经告诉模型要填 expression 了」。提示词不是门。门是 `Validate` 这个不读图像的纯函数。

多轮补参时，每一轮都是一条新的 $c$。第一轮 $\bot$，第二轮 $T_n(a)$。不要在同一条记录上把 `arguments` 改写后再把 `executed` 翻成真。那会让回放无法指出哪一次生成缺了键。LLaVA-Plus 的对话正好支持这种多轮：`skill_use` 失败后，下一轮再写一次 `skill_use`。本课 CPU 不做多轮采样，只冻结「缺参的那一条不得执行」。Lab 也不做多轮，它用路径开关模拟「这一轮调不调」。谁要看补参，去改造实验里加第三轮，不要改最低交付的夹具。

### 5.3 计算器：把进位从语言头里搬出去

直觉。语言头可以背九九表的片段，仍会在小数进位上跳档。PAL（Gao 等，arXiv:2211.10435）和 ToRA 把计算交给解释器。视觉课多一步：表达式里的数字必须来自图，不能来自语言先验。18.90 若其实是 18.60，计算器会诚实加出另一个错的数。所以计算器成功的前提是 OCR 列已经亮绿灯。

机制。感知模块输出行金额。规划器把它们排成表达式字符串，而不是自己加。执行器只做有理数加法。写回时，最终 `value` 必须引用观察槽里的 61.20，不能再改口成「大约六十」。ToRA 的失败分析里，推理错误占 38%，图理解占 21%，不恰当工具 10%，语法与运行时错误各 9%（原文 Table 4）。发票夹具把「图理解」收成 OCR 列，把「不恰当工具」收成直接答，把「语法」收成缺参。不要用一个总准确率把三列平均掉。

数学。金额用整数分 $c_i=100x_i$，避免 IEEE 浮点。真值 $C^{\star}=\sum c_i=6120$。心算 $C_{\mathrm{mental}}=C^{\star}-1000$。工具 $C_{\mathrm{tool}}=C^{\star}$。对外显示 $C/100$。验收不等式：

$$
\mathrm{Saw}=1 \;\wedge\; C_{\mathrm{mental}}=5120 \;\wedge\; C_{\mathrm{tool}}=6120.
$$

公开实现。Toolformer（Schick 等，arXiv:2302.04761）给 GPT-J 6B 接计算器、问答、搜索、翻译、日历，是文本工具，不看图。GPT4Tools 在视觉目录里没有单独的「加法器」，但有 Answer Question About The Image；把算术交给另一个视觉问答模型，进位问题会换一个外壳回来。ViperGPT 用 Python 的 `/` 和 `len` 做公平分配，Figure 1 的 muffin 例子是「先数再除」，解释器负责除法。本课只保留加法，是为了把进位暴露成 10 元，而不是把故事写成代码生成竞赛。

验证。Lab 在 OCR 清晰时展示心算 51.20、工具 61.20。路径若仍是直接答，最终回答停在 51.20，门不开。必须切到调用计算器。这不是为了难为人，是为了禁止「我知道该调工具」却还用语言头出数。

表达式从哪来，要单独写死。合法来源只有 OCR 列里的数字，按行序用 `+` 连接。禁止来源有三种。语言先验：模型记得「套餐大概六十」，写出 `60`。邻行污染：把单价 18.90 写成数量 3 再乘。表头污染：把「金额」右边的空白读成 0。三种都会让 $\mathrm{Saw}=0$ 或表达式不再等于印刷行。CPU 实验把合法表达式冻成 `18.90+26.50+15.80`，其它字符串一律 `expression_not_in_catalog`。看起来苛刻，实际是在模拟「执行器不负责猜你想加谁」。生产系统可以换一套更宽的解析器，但必须另开 schema 版本，并在日志里留下被接受的表达式原文。没有原文，61.20 无法审计。

Chameleon 在 TabMWP 上把程序执行器和表格工具放进同一条规划。GPT-4 规划器达到 98.78，比当时最佳公开结果高 17.0 个百分点，比 GPT-4 思维链高 7.97（原文 Table 4 一段）。表格数学是计算器类工具最干净的对照：格子里的数要算，不要背。本课发票是单列表格的最小版本。不要把 98.78 写进自己的三行夹具。方向可以迁移：规划器点名 Program Executor，执行器输出精确数，最终答案引用该数。谁在 TabMWP 上关掉执行器只留思维链，分数会掉一截；谁在本课关掉计算器只留心算，51.20 就会出现。两件事同构，分母不同。

税行是小计夹具里故意不放进去的陷阱。若发票底部还印着「税额 4.90 / 含税合计 66.10」，查询若是「税前小计」，表达式不得把 4.90 加进去。加进去会得到 66.10，OCR 仍可能全部读对，$\mathrm{Saw}=1$，工具也对了「含税合计」，但对错了问题。这是决策把 $n$ 选对了、把加数选错了。日志必须留下表达式原文，才能把 66.10 从「计算器坏了」里救出来。本课最低交付不印税行，就是为了把进位和加错行拆开。谁在 Lab 里私自加税行，门禁数字会变，不得再声称造出了 51.20 对 61.20。要练加错行，另开夹具，另开 run ID，把查询写成「含税合计」，真值改成 66.10。不要在同一张表上同时验收两问。

观察写回上下文时，执行器返回的 61.20 应作为不可训练的前缀出现在下一轮输入里。模型接着生成的 token 才是 `value`。若把 61.20 和 `value` 拼成同一段可训练文本，损失会鼓励模型抄数字，也会鼓励模型在没有观察时凭记忆写 61.20。推理时执行器一旦拒绝，记忆里的 61.20 仍会被抄出，表 A 就会出现「工具列为空、最终误差为零」的碰巧写对。训练 recipe 里把 `observation` 的 label 设为 `-100`，就是堵住这条抄数捷径。验证方法很简单：把执行器关掉，再跑同一条样本，最终 `value` 不得再等于 61.20。若仍相等，观察槽被语言头污染了。这一条和[第 16 课](16_multimodal_preference_optimization.md)「必须看见媒体」同构：那里看不见图像不能当偏好对，这里看不见观察不能当已经算过。

### 5.4 裁剪：全局编码器看不清的地方要再看一次

直觉。CLIP 一类编码器常在 224 或 336 边长上工作。发票脚注、货架最上层的标价、远处的牌照，都会在这一步被平均掉。[第 08 课](08_dynamic_vision.md)用动态分辨率和 tile 提高上限；那是编码器预算。本课的裁剪是工具：模型先指出框，再把子图送回编码器。V* 把这件事叫做视觉搜索。Visual Sketchpad 把框、线、标记画在草稿上，再基于草稿推理。CogCoM 把 CropZoomIn 收成六种操作之一。

机制。`crop` 的参数是 `image_id` 和归一化框。执行器按框切片，可选放大，再编码。观察是新图像句柄，不是一句「我已经放大」。缺框时不得用整图顶上，否则裁剪退化成第二次全局前向，账单涨了，细节仍不在。V*Bench 平均分辨率 2246×1582，属性 115 题、空间 76 题。无搜索的 Vicuna-7B 总体 45.02，换成 Grounding DINO 填工作记忆是 62.30，OWL-ViT 是 62.82，V* 搜索是 75.39（原文 Table 2）。检测器当工具有用，仍低于带启发式的搜索。本课不实现 A* 式搜索，只要求：框缺失则 $\bot$。

数学。子图像素域

$$
I_{\mathrm{crop}}=I[y_0H:y_1H,\, x_0W:x_1W]
$$

面积比 $(x_1-x_0)(y_1-y_0)$。教学上，面积比小于阈值 $\tau_A$ 的目标，全局前向的 $\mathrm{Saw}$ 视为 0，必须裁剪。$\tau_A$ 由夹具指定，不要写成「人眼觉得小」。

公开实现。GPT4Tools 的 Crop the Given Object 输入是图像路径加物体名，由检测器找框。ViperGPT 的 `crop(left, lower, right, upper)` 直接吃坐标。LLaVA-Plus 的检测/分割技能返回框和 mask，后续技能吃这些几何。三者都把几何当成参数，而不是靠下一句「左下角」的语言指代。语言指代会和第 23 课的左右幻觉搅在一起。

验证。CPU 实验拒绝缺四个坐标的调用，拒绝 `x1<=x0`。合法裁剪返回宽高，证明执行器看见了框。不要在 CPU 里读真实像素。

裁剪和动态分辨率不要合并成一个消融。第 08 课的 tile 是编码器在训练和推理时对整图做的预算分配，查询还没进来。本课的裁剪是查询进来之后，规划器指出「脚注在右下」。没有查询时，tile 仍可能把脚注分到一个小格子里；有查询但不裁，格子里的字仍可能小于编码器的有效分辨率。两个旋钮都转，必须两个 run ID。只开 tile、不记 `crop` 调用，不能写「我做了视觉搜索」。只调 `crop`、框却是整图 $[0,1]^2$，调用日志是绿的，细节账单和直接答一样。验收要看框面积比，不只看工具名是否出现。

V* 的搜索长度对照也很值得抄进笔记。原文 Table 3 把随机深度优先、随机广度优先、顺序扫描和带线索的 V* 放在一起，V* 平均步数更短；COCO-Search18 上与人类注视热图引导的步数接近（原文 Table 4，V* 2.52 对人类热图 2.80 一档的对照）。本课不要求复现搜索长度。它提醒：裁剪若没有优先级，就会退化成把图切成四块穷举。穷举能提高 $\mathrm{Saw}$，账单按块数线性涨，和第 45 课像素层打穿阅读预算是同一类事故。本课目录只有一次 `crop`，是故意把「会不会叫裁剪」和「会不会聪明地搜」拆开。后者是 V* 的课题，前者才是 schema 课题。

### 5.5 深度：点上的几何不是下一句形容词

直觉。「后面那盒」在语言里是介词，在几何里是相对深度。ViperGPT 把 `compute_depth()` 做成 `ImagePatch` 的方法，用 MiDaS 返回中值相对深度，用来比较远近，而不是生成「似乎更远」这种副词。GPT4Tools 从 Visual ChatGPT 继承 Predict Depth On Image，并把它留在 23 个训练工具里。第 35 课用深度服务抓取闭合，见[第 35 课](35_spatial_depth_vla.md)。本课停在查询接口：给点，得标量。不要把夹爪宽度写进来。

机制。参数 $(u,v)$ 落在单位正方形。执行器返回相对深度 $z$。比较两个物体时，应调两次 `depth`，或一次返回两个点，schema 必须写明。用语言头直接输出「左边更深」，会和第 23 课的左右颠倒叠在一起，无法拆开。

数学。教学夹具用

$$
z(u,v)=0.25+0.5v
$$

让「更靠下的点」更深，只为了让 CPU 实验可复核。真实 MiDaS 的标度、位移、是否度量深度，其在 ViperGPT 论文里只作为模块名字出现，本课不编米为单位的误差。

公开实现。Visual Sketchpad 在 BLINK spatial 上到 83.9，靠的是草稿上的几何标记，不一定调用深度网络。Chameleon 的工具箱含视觉模型和 Python，规划器决定要不要上哪一种。Qwen2.5-VL 技术报告强调定位和文档，没有给出与本课同构的 `depth(u,v)` 表；其技术报告未公开该细节。不要把「擅长定位」抄成本课已经测过深度工具。

验证。`v=1.4` 必须拒绝。合法 `(0.4, 0.8)` 返回 0.65。谁把越界点夹紧到 1.0 再返回 0.75，就是在伪造观察。

相对深度不能当抓取距离。第 35 课要的是能把末端送到接触附近的度量或至少经过手眼标定的量。本课的 $z$ 只用来比较同一张图上两个点谁更大。没有外参、没有尺度，把 0.65 写成 65 厘米，是单位犯罪。日志字段应叫 `relative_depth`，不要叫 `meters`。比较货架前后时，两次调用必须共用同一张深度图、同一标定。换一张图再比 0.65 和 0.40，没有意义。CPU 夹具用 $0.25+0.5v$，是为了让「v 更大则 z 更大」可手算，不是为了声明真实场景里下边一定更远。透视会把这个夹具推翻。推翻之后要换真深度模块，不要改 schema 的点约束。点约束只管参数合法，不管物理。

### 5.6 搜索：图外事实进不了像素

直觉。包装袋上没有今年的召回公告。语言头会根据训练语料编一个年份。搜索工具把查询送到外部索引，观察才是网页或文档片段。这和第 45 课的中间层余弦不是同一个对象。第 45 课的对象是这段视频里有没有红色阀门。本课的对象是图外有没有一条可引用的文本。LLaVA-Plus 把 CLIP Retrieval 接到 InfoSeek，训练集约 4087 条（原文 Table 2）。那是外部知识技能，不是像素检索层。

机制。`search` 的必填键是 `query`。执行器返回命中列表。写回时必须能指出命中文本，不能只说「我搜过了」。空查询、目录外的 `web_browse_click` 都是拒绝。第 32 课若要真的点搜索结果，那是 GUI 接地，应换课、换目录。

数学。本课不引入 Recall@k。搜索成功的最低定义是：`executed=1` 且返回结构含 `hits` 与原始 `query`。相关性评价交给引用，不交给本课 CPU。把 Recall@k 写进本课，会和第 45 课抢公式。

公开实现。HuggingGPT 的模型选择会按任务类型和下载量取 Top-K Hugging Face 模型，那是「选执行器」，仍不是视频检索层。Chameleon 在 ScienceQA 上用 Knowledge Retrieval 和 Bing Search，GPT-4 规划器 86.54，比当时最佳少样本高 11.37 个百分点。这些数字测的是科学问答，不是本课发票。它们只证明：规划器会为图外知识单独点名一种工具。

验证。CPU 实验对缺 `query` 的调用 `executed is False`。合法搜索返回 `hits=3`，仅为结构夹具。不要把 3 写成真实网页数量。

搜索的查询必须能从当前问题生成，且不得把整张图的 caption 当查询。caption 会把「咖啡店发票」送进索引，命中商户简介，召回公告仍不在。正确查询是「某品牌咖啡豆 召回 2024」这种可核对字符串。LLaVA-Plus 的检索技能建立在 InfoSeek 上，问的是视觉信息寻求，答案往往在维基一类外部页，不在像素里。本课若借用这条技能，日志要留下 query 原文和命中 URL。没有 URL，不能写「已搜索」。第 45 课的字幕层会把对讲词当命中；本课的搜索若只回一段和包装袋颜色很像的广告语，应记硬负例，不要记成功。两个「搜」字，一个在时间轴上找片段，一个在知识库里找文档。实验笔记的页眉写明是哪一个。

HuggingGPT 的四段里，和本课 schema 最像的是「选模型」与「执行」。规划把用户请求拆成子任务，选择段按功能描述和下载量挑 Hugging Face 权重，执行段真正跑推理，汇总段把各模态结果写成回复。它没有在论文摘要里给出必须抄的准确率表；正文用 passing rate、rationality、success rate 三套指标。本课不引用未打开核对的表内数字。能用的是协议：选择发生在执行之前，选不到模型就不应假装已经看见分割 mask。这和 `unknown_tool` 同构。把 Hugging Face 下载量最高的分割模型硬塞给发票小计，等于本课把 `depth` 塞给加法。日志应显示名字被拒绝或至少显示名字与问题类型不匹配。本课缩小版用固定四名目录，不做下载量排序，避免把「流行」写成「正确」。

### 5.7 在公开实现中定位这些机制

没有 MiniMind-O 源码可改时，把落点写在公开系统的接口上。

Visual ChatGPT / GPT4Tools：提示词里的工具说明书对应目录；Thought / Action / Action Input / Observation 对应决策、名字、参数、观察。负样本对应 $d=\mathrm{ANSWER}$。代码入口见 GPT4Tools 仓库的指令模板，不是 MiniMind 的 `omni_dataset.py`。

LLaVA-Plus：`skill_use` 与 `skill_result` 插在原 LLaVA 对话中间。FastChat 的 web server、model worker、controller 负责把工具和 7B 规划器跑在同一张 80GB 卡上。All Tools 变体在训练和评测时把几乎全部理解类工具跑一遍，Fly 变体只跑相关工具。本课缩小版采用 Fly 语义：没被点名的工具不得执行。

ViperGPT：`ImagePatch` 的方法签名就是 schema。Codex 只看见签名和 docstring，看不见 MiDaS 实现。这一点要学：规划器不该依赖执行器内部张量。GQA 48.1、OK-VQA 51.9、RefCOCO 零样本 72.0 是执行之后的任务分，不是 schema 分。本课 CPU 不追求这些分。

V* / SEAL：VQA LLM 列出缺失目标，搜索模型往 Visual Working Memory 里填裁剪块和坐标。工作记忆的四个槽（问题、全局图、已搜目标、位置）对应本课观察槽的结构化版本。

CogCoM：操作集合写在论文第 2 节，数据流水线用 GPT-4 当语言标注、Grounding DINO 与 PaddleOCR 当视觉标注，70K 自动样本的正路径成功率 0.3555。它强调操作可以内化进权重，不一定每次都走外部进程。本课仍走外部执行器，是为了让缺参可拒绝。内化之后，缺参会变成「模型自己脑补一个框」，日志更难写。

Qwen2.5-VL：技术报告把视觉代理、工具使用、电脑与手机操作写在同一段能力列表里。电脑与手机操作是第 32 课的 GUI。本课读报告时只抽取「工具使用」四个字，不把 ScreenSpot 数字搬过来。Qwen2-VL（arXiv:2409.12191）同样以定位和文档见长，本课不重抄 72B 表。

Moshi、Qwen2.5-Omni、Qwen3-Omni 的公开技术报告未给出与本课同构的四工具 schema。不要把 Omni 的听说话写成已经会拒绝缺参的发票调用。

ReAct（Yao 等，arXiv:2210.03629）给了 Thought / Action / Observation 的文本格式，GPT4Tools 和 LLaVA-Plus 都显式引用。本课把 Action 从自由文本收成 JSON 对象，就是为了让 `missing` 可机读。自由文本里写「用计算器算一下那些数」，执行器无法知道 $R_n$ 缺了哪一个键。

VisProg 与 ViperGPT 的差别也要能指出来。VisProg 生成模块化视觉程序，不训练任务专用网络；ViperGPT 直接生成可执行 Python，逻辑、循环、数学都交给解释器。本课不生成程序，只生成一次或几次 JSON 调用。程序更强，也更容易在缺参时被 Python 异常打穿。JSON schema 把异常提前变成 `Valid=0`。教学上先过 schema，再谈是否升级到代码生成。谁一上来就 `eval` 模型写的 Python，本课的拒绝日志会消失。CPU 实验因此禁止通用 `eval`。

写回协议也要落在公开接口上。LLaVA-Plus 服务阶段只把 `value` 展示给用户，把 `thoughts` 和 `actions` 藏起来，调试时才展开。本课教学刚好相反：必须展开。收银员对账时不能只看「合计六十一元二角」这句人话，必须能看见调用 JSON 和观察槽。产品演示可以藏，课程验收不能藏。谁把「用户体验要藏工具痕迹」写成「日志也可以不存」，第 9 节的五问就没地方挂。FastChat 的 model worker 把工具和规划器放在同一进程里，本课的缩小版把 `Validate` 和四类执行做成无副作用函数，就是为了在没有 80GB 卡时仍能回放。回放不需要 worker，只需要那条记录。

观察槽的写入规则再抄一遍。只有 `executed=1` 的返回值可以进槽。拒绝原因进的是另一列 `reject_reason`，不要和观察混在一个字符串里。混在一起之后，模型会把 `"missing: expression"` 读成一句新的用户话，再编一个 51.20。LLaVA-Plus 把工具结果放在 Human 角色里，看起来奇怪，其实是在模拟「世界回了一次话」。本课 CPU 没有角色标签，用显式字段代替。字段名固定为 `observation` 与 `reject_reason`。不要发明 `feedback` 这种会和产品文案撞车的名字。

## 6. 数据与训练 recipe

工具调用不是多喂一些 caption 就会出现的。公开路线有三条，数据字段不同，不能混在一个 loss 里当同一列。

提示链。Visual ChatGPT、MM-REACT、HuggingGPT、ViperGPT、VisProg、Chameleon 不训规划器，或只训很薄的胶水。数据是工具说明书、少样本示范、API docstring。优点是接入新工具快。GPT4Tools Table 2 显示：Vicuna-13B 零样本 SR 12.4，说明只靠提示、模型又不够大时，Thought 和 Action 会对不上。LLaVA-Plus 把「测试时才塞工具结果」的 LLaVA 变体做成消融：COCO 全部分从 81.2 掉到 59.1，In-the-Wild 从 57.1 掉到 47.5（原文 Table 4）。结论：不会用工具的模型，测试时硬塞专家输出，会把它打乱。

指令微调。GPT4Tools 用 ChatGPT 在图像内容（caption+框）条件下生成指令，过滤后约 41K，再扩成 71.4K 训练对，其中 35.7K 真的用工具。负样本来自普通对话，防止永远 `Thought=Yes`。上下文样本切断动作链、拼多轮。评测集人工核对：验证 1170 条、测试 652 条。LLaVA-Plus 把工具数据与 LLaVA-158K 拼在一起，并把 158K 改成统一的 thoughts / actions / value，否则模型会不会调工具。理解类 81K 用于报基准数字，全量用于演示。

交错推理。ToRA-Corpus 16K 条，覆盖 GSM8k 训练题的 98.2% 和 MATH 的 83.1%，交错理由、程序、执行输出。再做 output space shaping：采样合法轨迹、用教师模型修补非法轨迹，最后每题最多再留 4 条，合并到 69K。去掉 shaping，ToRA-Code-7B 的 MATH 从 44.6 降到 40.2；再去掉理由只留程序，降到 36.8（原文 Table 3）。视觉课对应的 shaping 是：同一张发票既要有「调计算器得 61.20」的正例，也要有「问这是不是发票、Action 为空」的负例，还要有「第一次缺 expression、第二次补全」的多轮。只有正例时，模型会在任何问题上都调计算器。

本课最小字段：

| 字段 | 含义 | 缺了会怎样 |
|---|---|---|
| `image_id` | 哪一张图 | 裁剪和深度无法指向对象 |
| `question` | 用户原话 | 无法判断该不该调 |
| `ocr_list` | 读到的数字 | 无法拆 Saw |
| `decision` | ANSWER 或 CALL | 无法判断是心算还是工具 |
| `call.name` | 工具名 | 无法做目录检查 |
| `call.arguments` | 参数对象 | 无法做缺参检查 |
| `valid` | schema 结果 | 非法执行会被当成工具成功 |
| `observation` | 返回值或空 | 最终答案无法引用 |
| `answer` | 给用户的话 | 无法核对是否写回 61.20 |

配比建议（课程约定，不是论文数字）：正例小计调用 40%，负例「描述图像不调工具」30%，缺参后纠正 15%，裁剪/深度/搜索各约 5%。不要在小计正例里混入 GUI 点击。点击属于另一张表。

训练目标仍是自回归 CE，但 mask 必须盖住不该学的部分。LLaVA-Plus 只在绿色子序列上算损失：`skill_use` 和最终 `value`，不在 `skill_result` 上算，因为观察来自工具。本课同样：`observation` 的 token 若由执行器写入，label 应为 `-100`。把 61.20 当语言模型自己「生成」的数字来训，执行器会被跳过。推理时执行器一旦拒绝，模型仍会把记忆里的 61.20 写出来，造成「没执行却有观察」。这和[第 01 课](01_baseline_reproduction.md)把用户问题算进 loss 是同一类 mask 错误。

规模对照只写打开过的句子。GPT4Tools 在 13B 上 LoRA，秩 16，三轮，学习率 $3\times 10^{-4}$，batch 512，最大长度 2048（原文 Appendix Table 12）。LLaVA-Plus 报数字时用 81K 理解数据；演示系统用全量技能数据，含生成、编辑、组合。ToRA 用全局 batch 128、三轮、默认学习率 $2\times 10^{-5}$，34B/70B 用 $1\times 10^{-5}$。这些超参不能直接搬到 MiniMind-O 26M 上。26M 规划器写 JSON 的能力很弱，本课最低交付因此是 schema 与进位夹具，而不是「在 26M 上微调出 94.1 SR」。谁把 Vicuna-13B 的 94.1 写成 MiniMind 的预期，就是把左栏抄进右栏。

负例要真的负。GPT4Tools 的负样本来自已有对话数据，转成 Thought=No、Action 为空。如果负例仍在问「小计多少」，模型会学到「看见发票就拒绝计算器」。本课负例应问「这张票是不是午餐收据」「店名是什么」「有几行」，答案在语言头能力范围内。正例问「税前小计」。两类问题共用同一张图，只有 `decision` 不同。这是图像条件下的负例，不是随机句子。原文 Table 3 显示负例把 SR 从 91.6 送到 94.1，增益来自 Thought，不是来自更会填参数。本课若只做正例，Lab 里的「直接答」路径会消失，门禁就无法要求用户主动切到计算器。

一条最小正例在记录里长什么样，写出来以免各人发明字段。下面不是模型输出，是课程约定的 JSON 形状：

```json
{
  "image_id": "invoice-52",
  "question": "税前小计是多少？",
  "ocr_list": [18.9, 26.5, 15.8],
  "decision": "CALL",
  "call": {
    "name": "calculator",
    "arguments": {"expression": "18.90+26.50+15.80"}
  },
  "valid": true,
  "observation": 61.2,
  "reject_reason": "",
  "answer": "61.20"
}
```

对应的缺参负向记录把 `arguments` 改成 `{}`，`valid` 改成 false，`observation` 改成 null，`reject_reason` 改成 `missing_required`，`answer` 若仍是 51.20，这条样本只能当「拒绝后仍心算」的反例，不能当正例。训练时如果把反例的 `answer` 也当成要模仿的 token，模型会学会在缺参之后输出 51.20。正确做法是：缺参样本的可训练片段停在下一次 `call` 之前，或者把 `answer` 标成「需要补 expression」，不要标成一个金额。GPT4Tools 的负样本停在 Thought=No，没有金额，就是这个原因。

组合技能不要进最低交付的训练集。LLaVA-Plus Table 2 里「Mix of Detection, Segmentation, Tagging, Caption」有 37431 条，那是演示系统用的组合。本课四工具若一开始就训组合，缺参会变成「四个名字里缺一个也继续跑」。先把单工具的 `required` 跑绿，再谈组合。组合的 schema 是新的 $n$，例如 `crop_then_ocr`，它有自己的 $R_n$，不能靠两个旧 schema 自动拼接。自动拼接会让 `missing` 列表算错。

## 7. 按依赖顺序执行实验

执行顺序固定：先手算进位和 schema，再跑 CPU，再打开 Lab 先预测后揭晓，最后如果有 GPU，才把同一套日志接到开源权重上。

**Step 0：手算进位。** 18.90+26.50=45.40。45.40+15.80：十分位 4+8=12 写 2 进 1；个位 5+5+1=11 写 1 进 1；十位 4+1+1=6，得 61.20。漏掉个位向十位的进位，得 51.20。把 51.20 和 61.20 写进笔记，禁止用计算器「先看答案再反推进位」。

**Step 1：手写四张 schema。** 列出每个工具的 $R_n$ 和约束。用空对象、缺键、类型错误、越界点各举一例，标出 `reject_reason`。不要执行。

**Step 2：CPU 夹具。** 运行 `lesson_52.run()`，确认 `checks` 全为真。重点看三条：`constructed_saw_digits_mental_wrong_tool_right`、`missing_calculator_expression_does_not_execute`、`unknown_tool_and_missing_search_rejected`。

**Step 3：浏览器 Lab。** 印刷金额始终可见。先选「看见了数字、心算错、工具对」，OCR 清晰度保持在 0.6 以上，路径选调用计算器，再点揭晓。门通过的条件是这三件同时成立，揭晓前不得看到 51.20 / 61.20。把清晰度拉低，确认沙拉变成 15.08、工具也错，这一对照用来理解 $\mathrm{Saw}=0$。不要在低清晰度下强行过门。

**Step 4（可选，需 GPU）：** 同一张教学发票问开源 7B。记录是否发出工具调用、参数是否缺、最终数字。样本少于 25 只发逐例表，不准平均成「成功率」。不得把 Lab 的 61.20 写进这一列。

出现以下任一情况，实验无效：揭晓前能看到心算或工具数字；把 51.20 写成真实模型的 MATH 分数；缺参仍执行；把点击屏幕写成 `calculator` 成功。

通过最低交付之后，允许加一条可选记录：把 OCR 清晰度从 0 扫到 1，画出 $\mathrm{Saw}$、$\hat s_{\mathrm{tool}}$。预期在 0.6 处跳变。这条曲线给自己看，不写进对外的「论文复现」。

Step 0 的进位手算必须留下竖式，不能只写「等于 61.20」。竖式是本课和[第 01 课](01_baseline_reproduction.md) trace 同构的东西：别人按你的竖式应能得到同一位的进位。若竖式里十分位没有写「进 1」，后面的 51.20 就变成了魔术数字。Step 1 的 schema 手写必须含拒绝原因字符串，且与 CPU 实验里的 `reject_reason` 词表一致：`unknown_tool`、`arguments_not_object`、`missing_required`、`type_error`、`constraint_error`、`expression_not_in_catalog`。自己发明 `bad` 这种词，日志将无法和夹具对齐。Step 2 若有一条 check 为假，先看是不是改了金额常量，再看是不是允许了 `eval`。不要先调学习率。本课没有学习率。

解析模型输出时还有一层工程失败，值得单独做一次。模型常常把调用包在 Markdown 围栏里，前面再写一句「我来算一下」。执行器若对整段字符串做 JSON 解析，会得到 `arguments_not_object` 或直接抛错。正确顺序是：先切出围栏内文本，再 `json.loads`，再送进 `Validate`。切围栏失败应记 `parse_error`，不要记 `unknown_tool`。两类失败的修复不同：前者改解析器，后者改目录或微调。本课 CPU 不测解析器，因为夹具直接喂字典。GPU 可选 Step 4 必须测：把模型原文和解析后的对象一起存。只存解析后的对象，围栏失败会被当成模型不会调工具。只存原文，schema 门无法自动跑。两份都要。

Step 3 的操作顺序也是协议。先预测、再改滑条、再揭晓，允许。先揭晓、再改预测，不允许：`ran` 会在改预测时被 Lab 清掉，这是有意的。先揭晓、记住 51.20、刷新页面再选「心算错」，属于对着答案填空。课程无法从技术上禁止刷新，实验笔记必须自己写「揭晓前的选项」。没有这一行，Lab 截图不算交付。Step 4 的逐例表至少含：权重哈希、是否发出调用、`Valid`、最终数字、与 61.20 是否相等。缺哈希的 GPU 数字，和缺 mask 统计的 loss 一样，不能进对照表。

## 8. 评测与测量

评测分三张表，禁止横着平均。

表 A 诊断列。$\mathrm{Saw}$、$\mathrm{MentalWrong}$、$\mathrm{ToolRight}$、最终 $|\hat y-s^{\star}|$。本课主门是第一行三列同时为 1，且路径为 CALL。只报 $|\hat y-s^{\star}|$ 会把「没看见但碰巧写对」算进去。

表 B schema 列。合法执行率、缺参拒绝率、类型错误拒绝率、目录外拒绝率。四者分母不同。缺参拒绝率的分母是缺参样本，不是全部样本。GPT4Tools 的 $\mathrm{SR}_t$、$\mathrm{SR}_{act}$、$\mathrm{SR}_{args}$、$\mathrm{SR}$ 是同一 $N$ 上的四个分子，本课可以对照，但不要把 BLEU 阈值 0.5 悄悄换成精确匹配还不改名。

表 C 任务列。这是论文表，可选。LLaVA-Plus 的 LLaVA-Bench、SEED-Bench、MM-Vet、VisIT-Bench Elo 1203 对 LLaVA 13B 的 1095（原文 Table 7，截止日期 2023-09-27）。V*Bench 75.39。ToRA MATH 50.8。Chameleon ScienceQA 86.54。它们证明公开系统「接了工具会涨点」，不构成本课最低交付。没有表 A、表 B，表 C 只是装饰。

和文档基准的关系再写死一次。Donut 在 DocVQA 测试集 ANLS 67.5（第 44 课已引 Table 3）。那是抽字符串。本课在字符串已经对的前提下测加法。两列可以同一张发票，必须两个指标名。MM-Vet 的 Math 子项，LLaVA-Plus-7B 为 7.7，LLaVA-7B 为 8.1（原文 Table 6，作者自己的复跑）。工具不一定涨数学。本课因此不用 MM-Vet Math 当主门，用进位夹具当主门。

表 A 的四列要能复原竖式。$\mathrm{Saw}=1$ 意味着 OCR 列表等于 $(18.90,26.50,15.80)$。$\mathrm{MentalWrong}=1$ 意味着心算是 51.20 而不是别的错法。若心算写成 62.20，误差来源变成「多加了 1」，不再是本课固定的十位进位，夹具失败原因变了，不能再宣称造出了指定案例。$\mathrm{ToolRight}=1$ 意味着执行器输出 61.20，且 `executed=1`。若模型没调用、自己写出 61.20，表 A 的工具列必须为 0，最终误差可以为 0。这就是「碰巧写对」。表 A 存在的意义就是抓住它。表 B 的拒绝率必须在注入故障之后再测。合法集上拒绝率为 0 不说明门在工作；缺参集上拒绝率不为 1 才说明门坏了。GPT4Tools 把三类成功乘在同一个 $N$ 上，是因为他们的评测集每条都有完整标注。本课 CPU 把合法与非法分成不同夹具，乘积会误导。分母写清楚。表 C 若要抄 LLaVA-Plus 的 VisIT-Bench Elo，必须抄截止日期和「#matches」：1203 分来自 678 场，LLaVA 13B 的 1095 来自 5420 场（原文 Table 7）。场次差一个数量级，Elo 不能当本课主门。抄表时连场次一起抄。

| 症状 | 先查 | 不要先做 |

| 最终 51.20，OCR 列表正确 | 是否发出 calculator 调用 | 换更大的视觉编码器 |

| 深度值总是 0.75 | $(u,v)$ 是否被夹紧到中心 | 换 MiDaS 权重 |

| 字段 32.00 对、框在表头 | 这是第 44 课版面失败 | 调计算器 |

再补一组和公式直接相关的症状。$\mathrm{Valid}$ 永远为 1：检查是不是把 `required` 写成了空列表。$\mathrm{Valid}$ 永远为 0：检查目录名是否与模型输出的字符串差一个空格。心算误差不是 10.00：检查是不是另一位进位，或把税也加进去了。工具结果与真值相等但 `executed` 为假：观察槽被语言头污染。这些检查只需要打印调用记录，不需要再下数据集。

第 07 课的 CONTINUE / PAUSE / REPLAN 在工具里也有对应物：观察已够用是 CONTINUE，schema 拒绝是 PAUSE，换工具名或补参数是 REPLAN。不要把语音路由代码抄过来，只借用状态名，见[第 07 课](07_full_duplex_routing.md)。

症状表还可以按日志字段反查。缺 `ocr_list`：无法谈 $\mathrm{Saw}$，先补感知记录，不要调学习率。缺 `call.name`：无法谈目录，先看决策头是否输出了 JSON。`name` 有、`arguments` 不是对象：走 `arguments_not_object`，检查模型是不是把参数写成了自然语言句子。`arguments` 是对象、缺键：走 `missing_required`，检查 schema 与提示词是否一致。键都在、类型错：走 `type_error`，检查是不是把数字当字符串。类型对、框反向：走 `constraint_error`，检查归一化原点是不是左上。全部合法、结果错：才轮到执行器或 OCR。跳层排错会把 MiDaS 卸了又装，而真正的失败在 `v=1.4`。把这张反查表抄进实验笔记页眉，比事后写「感觉工具不稳」要有用。

## 12. 前沿对照与改造方向

**公开方案。** 同一问题，2023–2025 年的公开系统分成四条路。提示链：Visual ChatGPT、MM-REACT、HuggingGPT 用大语言模型当分配器，图像往往晚到。程序合成：VisProg 与 ViperGPT 把查询编译成模块图或 Python，深度、裁剪、计数变成函数调用。指令微调：GPT4Tools 教开源语言模型写出 Thought / Action；LLaVA-Plus 进一步让规划器全程看图，技能库含检测、分割、OCR、CLIP 检索、扩散生成与组合技能。交错与内化：ToRA 把理由和程序交错；CogCoM 把 CropZoomIn、Calculate 等操作内化；Visual Sketchpad 把草稿留在像素里。Qwen2.5-VL 把工具使用和电脑手机代理写进同一份报告，后一半归第 32 课。四条路都没有取消 schema 门，也没有宣布看见图就会进位。

LLaVA-Plus 相对 GPT4Tools 的关键证据是规划器模态。原文 Table 3：GPT4Tools 的分配器是 LLM，LLaVA-Plus 是 LMM。Table 4 里 GPT4Tools 在 LLaVA-Bench In-the-Wild 全部分 40.7，LLaVA-Plus Fly 59.1，All Tools 69.5。同一套「会调视觉工具」的故事，看不看原图差一截。本课缩小版没有 7B，但日志里要留下「决策时图像是否仍在上下文」。决策时只剩 caption，就回到了 GPT4Tools 那一列。

V* 相对「换一个更高分辨率编码器」的证据是：LLaVA-1.5 用 336 边长，属性题上涨，总体仍远低于带搜索的 75.39。分辨率是第 08 课的旋钮。搜索是本课裁剪工具的旋钮。两个旋钮都转，必须两个 run ID。

ToRA 相对纯思维链、纯程序的证据是 Figure 4：在 LLaMA-2 上交错格式比只要理由高 29.0 个百分点，比只要程序高 6.7；GPT-4 上分别高 19.1 和 9.8。发票课对应的不是 29 个百分点，是 51.20 对 61.20。方向相同：算术不要放在语言头里。

**差距。** 规模差距：71K 指令、158K 视觉指令、80GB 卡、A100 上 6 秒一次搜索、GPT-4 当教师，钱能堆。机制差距：四名目录、`Valid` 合取、进位 10 元、缺参 $\bot$、三列诊断，本课能做。评测差距：MATH 50.8、V*Bench 75.39、VisIT-Bench Elo 1203 和本课三行发票之间的洞，不是再写一个 JSON 能填的；那是真实题型、真实工具噪声、真实延迟，交给以后的评测总表，不在本课用玩具分数冒充。

**改造实验。**

1. 把 CPU 夹具的沙拉金额改成 15.08，印刷真值仍为 61.20。预算：CPU 数分钟。预期：$\mathrm{Saw}=0$，$\mathrm{ToolRight}=0$，缺参拒绝仍全真。失败：工具仍等于 61.20，或缺参开始执行。
2. 在 Lab 里只改路径、保持 OCR=1，记录直接答与调用计算器的最终数字。预算：两次揭晓。预期：51.20 对 61.20。失败：两路数字相同。
3. 给 `crop` 增加面积比字段，拒绝面积比大于 0.9 的「假裁剪」。预算：在 CPU 里加两行约束。预期：整图框被拒绝，脚注小框通过。失败：两种框都通过。
4. 若有 1×24GB：在一个 7B 视觉语言模型上对同一张发票比较「禁止工具」和「只开计算器」。预算：单卡若干小时，20 张扫描件。预期：禁止工具时至少出现一例进位错误，开计算器后该例数字改为与 `decimal` 求和一致。失败：两路答案完全一致且都没有调用日志。样本不够 25 只发逐例表。

**顺手复现映射。** GPT4Tools 的 12.4 到 94.1 对应本课「不训调用格式时 Thought 与 Action 对不齐」；用缺参夹具模拟对不齐。LLaVA-Plus 测试时硬塞工具结果掉点，对应本课「观察槽污染」：没有 `executed` 却有 61.20。V* 的 45.02 到 75.39 对应裁剪前后 $\mathrm{Saw}$ 的变化，本课用面积比阈值模拟，不复现 2246 边长。ToRA 去掉程序后 MATH 下降，对应关掉计算器后 51.20 出现。这些映射全部是方向性的。谁把 50.8% 写进自己的三行发票报告，就算评测造假。

改造实验的失败判定再补两条公共规则。任何一次 GPU 推理都要保存：权重哈希、OCR 列表、调用 JSON、`Valid`、观察、原始输出。缺哈希或缺 `Valid` 的结果不能进对照表。任何一次声称「计算器更好」的比较，必须在同一 OCR、同一张发票、同一解码温度上完成；换了 OCR 引擎就不能把差值记在计算器上。

公开方案里还有一条容易抄错的分界。CogCoM 把操作内化，推理时可以不依赖外部进程，用户仍能从生成的操作名和框反查错误。内化提高了速度，降低了 schema 的强制力：模型可以写出 `CropZoomIn` 却不真的切像素。本课最低交付走外挂执行器，就是为了让「没切」可观测。若你要做改造实验 5（可选）：把 `crop` 改成只生成框坐标、不再切片，看最终 OCR 是否仍失败。预算：改执行器十行。预期：脚注仍读错，$\mathrm{Saw}=0$。失败：不切片却读对，说明答案来自语言先验，应回到第 23 课涂黑探针，而不是留在本课。这条可选实验专门用来抓住「工具名出现了、像素没变」。日志里若没有新的 `image_id`，裁剪就等于没发生。

Qwen2.5-VL 的电脑与手机代理不要写进改造清单第 4 条。那会把本课拖进 OSWorld。第 4 条只允许计算器。若有人坚持要测 GUI，另开第 32 课的 run ID，本课对照表不收。Omni 报告未公开四工具 schema，改造清单因此也不写「在 Qwen2.5-Omni 上打开计算器」。写了就无法验收。可写的是：在任意开源 VLM 外包一层本课目录，规划器仍用该 VLM 的文字输出解析 JSON。外包层的 schema 代码属于本课，VLM 权重属于它自己的论文。

规模和机制的分界再用发票说一次。把 Vicuna-13B 换成 70B，心算仍可能漏进位，因为进位不是参数量能自动长出来的状态机。把 OCR 从 EasyOCR 换成更强的文档模型，51.20 仍可能出现，因为读对和加对是两列。把搜索引擎从关键词换成稠密检索，小计问题仍不该走搜索。钱能堆的是：更大的规划器把 JSON 写对、更稳的 OCR 让 $\mathrm{Saw}=1$、更低的工具延迟。钱堆不出来的是：缺 `expression` 仍然执行、把 GUI 点击记进本课 SR、把 61.20 当语言记忆。后三件是本课要改的协议。前三件是你以后有卡再做的工程。报告第一页只许出现协议是否成立。工程数字可以放附录，但附录不能回写协议。有人用 70B 直接答对了这张三行发票，只说明这张夹具对那次解码不够难，不说明协议可以拆掉。换一行 19.99 × 3 的进位，语言头往往又会掉下来。夹具要能换金额常量而不改 schema。常量写在 CPU 文件顶部，就是为了让你换。换完之后，心算误差仍应是 $10^{k}$ 元这一档，而不是随便一个差。随便一个差无法证明漏的是进位。

课程停在「看见图之后的工具门」，还有两件明确不教。一件是工具结果怎样变成可验证奖励再送进 GRPO，那是第 17 课的对象，本课只提供 `Valid` 和算术相等这两个可验证量，不组相对优势。另一件是跨会话把这张发票的原图或摘要存到第二天，那是第 53 课规格里的对象。本课观察槽在这一轮结束时即可丢弃。丢弃不等于没有日志：日志要进 `artifacts/lesson52/`，观察槽不必进下一轮上下文。有人把整张发票像素塞进下一轮「以免忘记数字」，那是在用上下文预算逃避计算器。预算会涨，进位不会因此变得可靠。该调工具时调工具，该记日志时记日志，两件事不要合成一次「把图再喂一遍」。

[第 20 课](20_unified_understanding_generation.md)讨论的是图像理解与生成能否共享骨干。本课共享的是工具目录接口，不是 flow matching 的速度场。LLaVA-Plus 的生成技能（Stable Diffusion、InstructPix2Pix）属于那条生成轴，本课目录故意不收图像生成，避免和第 20、49 课抢题。下一课规格指向跨会话记忆该存像素还是存摘要。本课的观察槽只活在这一轮调用里，不要提前把跨天的原图缓存写进来。本课停在这里：看见图之后，该调的工具必须带着合法参数被执行；缺参数的调用不得进入执行；直接答会把进位错误写进下一句。检索层、版面框、屏幕点击，都还在别的课里。把这三句抄进实验报告页眉，和 51.20 / 61.20 放在同一行。页眉能读，夹具就能复跑；页眉只写「工具学习成功」，夹具就已经被叙事吃掉了。复跑时金额常量可以换，schema 的 `required` 不能悄悄变空。变空等于拆掉门再宣称门还在。谁把 `required` 改空却仍沿用本课 run ID，验收作废，必须新开一次。新开时在笔记里写明改了哪一个键，以及为什么旧夹具不能覆盖。覆盖不了的原因通常是：旧夹具的拒绝词表没有这条路径。词表没有的路径，数字再漂亮也不属于本课已经核过的协议。若你现在就把「会用工具」理解成「会点按钮」或「会检索视频」，回到第 8 节的三张表，把表 A 和表 B 再读一遍。机制成立，能力边界仍然很窄。把这条边界写进实验报告的第一页，比把 MATH 50.8 抄进标题更有用。读者应能在读完本课后独立复述：看见数字仍可能漏进位，计算器只对 OCR 负责，裁剪没有框就是假看，深度越界必须拒绝，搜索不是选层。能复述这五句，并且 CPU 实验检查为真，本课就收工。五句缺任何一句，说明还把「看见」和「执行」焊在了一起。焊在一起的系统，演示可以很流畅，对账时会把 51.20 当成已经算过。拆开之后，演示可能多一次拒绝，对账才能指出缺的是哪一个键。课程要的是后一种。前一种留给产品视频，不要写进本课交付。交付看的是 51.20 被拦在语言头之外、61.20 来自观察槽。两数都在，且缺参记录的 `executed` 仍是假，这一课才算写完。数字对得上竖式，拒绝原因对得上词表，才叫可复核，不叫看起来像会用工具。看起来像，不能过门。过门要的是可回放的三列和拒绝日志，不是流畅的中文小计句。必须留下记录。交互实验还要留下一次先预测后揭晓的记录，证明你没有对着已经显示的 51.20 去选答案。三项齐了，再去碰公开仓库也不迟。公开仓库只能检验同一套 schema 在真实工具噪声上是否还分得开，不能回头否定玩具里已经核对过的那套进位和拒绝规则。答题准确率是生成口径，玩具三列诊断是工具口径，两套数字不要写进同一格。
