# 第 27 课：实现并诊断自回归 VLA

> 内容：动作词表、串行解码延迟、并行 L1 与 LIBERO 套件拆桶<br>
> 建议周期：4–6 天阅读与机制实验；论文规模训练另计<br>
> 硬件：CPU 完成本课实验与浏览器 Lab；复现 OpenVLA 预训练约 64×A100、14 天；LoRA 微调约 1×A100；OFT 微调约 8×A100/H100<br>
> 产物：可核的 CE / L1 mask 实验、延迟对照记录、按套件拆开的 LIBERO 读数表

## 1. 自回归 VLA 的词表和串行延迟

第 25 课比较过离散分箱、连续回归和动作分块，第 26 课处理过异构机体数据不能按条数直接倒进同一个 batch。本课把这两件事接到一个能跑的模型上：视觉语言模型（VLM：输入图像和文字、输出文字的模型）被改成视觉语言动作模型（VLA：同一套主干还要输出机械臂动作）。公开可复现的代表是 OpenVLA：7B 参数，骨干来自 Prismatic VLM，视觉侧把 SigLIP 和 DINOv2 的特征拼在一起，语言侧是 Llama 2，训练数据是 Open X-Embodiment 里筛过的约 97 万条真实机器人示教。

它解决的工程问题很具体。机械臂一步动作通常是 7 个数：末端位置 3 维、姿态 3 维、夹爪 1 维。语言模型只会写词表里的整数编号。OpenVLA 的做法是把每个连续维均匀切成 256 档（bin：把一段连续区间切成等宽格子，格子编号当类别），再把这 256 个编号写进 Llama 词表最不常用的尾部 256 个位置。训练时，图像和语言指令当条件，模型按 next-token 交叉熵（CE：预测下一个编号、用负对数概率当损失）逐维吐出这 7 个动作 token。teacher forcing（训练时永远把正确答案前缀喂回去，不管模型自己刚才猜错没有）让这 7 步可以在一条序列上并行算 loss；推理时没有标准答案，必须真的一步一步跑解码器。

延迟账单从这里开始。记一次解码器前向的时间为 $\Delta t$，前缀（视觉 token 加语言 token）还要另付一次。H=1、只出当前步的 7 维时，串行步数是 7；若一次要出未来 $H$ 步，串行步数变成 $7H$。OpenVLA-OFT 论文表 II 在一块 NVIDIA A100 上、输入 224×224 图像和一条 LIBERO 指令，测得原版自回归 OpenVLA 动作吞吐 4.2 Hz、延迟 0.2396 秒。论文正文还写过，单步动作在 A100 上大约 0.33 秒。无论取哪一条实测，数 Hz 的控制频率对 25–50 Hz 的双臂平台都不够用。

OpenVLA-OFT 把三件事捆在一起改：并行解码（一次前向出全部动作维，注意力改双向）、动作 chunk（一次出 $H$ 步）、连续动作加 L1 回归。同一张表 II 上，并行加 $H=8$ 的连续 L1 吞吐到 109.7 Hz，相对 4.2 Hz 大约 26 倍；再加腕部相机和本体感觉后仍有 71.4 Hz。成功率不能只报平均。OpenVLA 论文附录 E 表 12 与 OFT 表 I 都给出四套件：微调 OpenVLA 在 LIBERO-Spatial 84.7%、LIBERO-Object 88.4%、LIBERO-Goal 79.2%、LIBERO-Long 53.7%，四套件平均 76.5%。OFT 在第三人称图像、腕部相机、本体感觉、过滤失败示教的设定下，四套件平均 97.1%，其中 LIBERO-Long 是 94.5%，不是 97%。97% 是四套件各自微调后的仿真平均数，不是“通用操作已经做完”。

和 MiniMind-O 的关系也要说清，避免有人把本课当成第 01 课的续训。MiniMind-O 的可训主体约 26M，视觉是冻结的 SigLIP2，输出是文本与 8 路语音编号，见 [第 01 课](01_baseline_reproduction.md)。OpenVLA 的可训主体约 7B，视觉在 VLA 阶段解冻，输出是 7 个动作编号或一段连续动作。两套系统共享的只有“把非文本模态投进因果语言模型”这一形状，不共享词表、不共享损失位置、不共享控制频率。本课的 CPU 实验因此重新实现了一份动作 mask，没有去改 MiniMind-O 的 9 路布局。

本课术语：

| 术语 | 简要解释 |
|---|---|
| VLA | 视觉语言动作模型：VLM 主干直接预测机器人动作 |
| Prismatic | OpenVLA 用的开源 VLM 骨干，视觉编码器加投影加 Llama |
| SigLIP / DINOv2 | 两个预训练视觉编码器；前者偏语义，后者偏空间细节 |
| 动作 token | 把一维连续动作分箱后写入语言词表的整数编号 |
| teacher forcing | 训练时下一步的输入永远是标准答案，不是模型自己的采样 |
| 串行解码 | 推理时必须等上一个 token 出来才能算下一个，步数等于动作 token 数 |
| 并行解码 | 空的动作槽一起进解码器，一次前向出全部维 |
| action chunk | 一次预测未来 $H$ 步动作，执行完或执行前 $k$ 步再重新查询 |
| L1 回归 | 对连续动作预测值与真值的绝对差取平均 |
| LoRA | 低秩适配：只训练两个瘦矩阵去近似满秩更新，省显存 |
| LIBERO | 仿真操作基准，本课只用 Spatial / Object / Goal / Long 四套件 |

页面机制图按双视觉、词表覆盖、串行 CE 与并行 L1 三条路径画。浏览器 Lab 是受控教学模拟：延迟条和玩具成功率由公式计算，不得写成 OpenVLA 权重的输出。CPU 实验只核形状和 loss mask。

把延迟账单摊开成一张能手算的表。取教学数 $t_{\text{prefix}}=50\,\text{ms}$（视觉编码加语言前缀，可缓存）、$t_{\text{decode}}=27\,\text{ms}$（一次动作 token 或一次并行动作头）。H=1 串行：

$$
t=50+7\times 27=239\,\text{ms}
$$

对应吞吐约 $1000/239\approx 4.2$ 次动作每秒，与 OFT 表 II 的 4.2 Hz 同量级。H=1 并行：前缀仍付 50 ms，动作头一次付 27 ms，合计 77 ms。H=8 串行变成 $50+56\times 27=1562\,\text{ms}$，已经掉到 1 Hz 以下；H=8 并行只让注意力序列略变长，OFT 实测延迟从 0.0629 秒升到 0.0735 秒，吞吐却因一次吐 8 步而到 108.8 Hz。Lab 用同一套分解，方便你看见“步数”和“吞吐”不是同一个旋钮：并行减的是步数，chunk 乘的是每次吐出的动作个数。两者同时打开，才出现表 II 的 26 倍。

7 维动作本身也要拆开读，避免把“7 个 token”当成一句口号。OpenVLA 预训练和 LIBERO 微调里，这 7 维是末端位置增量 3 维、姿态增量 3 维、夹爪 1 维。ALOHA 上变成 14 维绝对关节角，串行步数若仍按“每维一个 token”会直接翻倍，这是 OFT 把双臂实验完全排除原版自回归基线的原因：3–5 Hz 单臂已经勉强，双臂再串 14 步会掉到实时控制带以下。本课 Lab 保持 $D=7$，CPU 实验也用 7，改造清单里再把 $D=14$ 当作可选压力测试。

## 2. 本课解决的问题

会把动作写成 token，不等于已经有一条可诊断的训练和推理链路。缺了任何一环，LIBERO 数字和延迟数字会对不上：

1. 视觉特征从哪两个编码器来、怎么拼、投影后几个 token 进 Llama；
2. 256 档动作编号覆盖词表的哪一段，语言 token 会不会被挤掉；
3. 训练 CE 的 mask 是否只盖动作位置，prompt、padding 是否为 `-100`；
4. 推理串行步数到底是 7 还是 $7H$，前缀计算有没有被重复计入；
5. 改成并行和连续 L1 之后，吞吐和各套件成功率分别变多少；
6. 只报四套件平均时，LIBERO-Long 的缺口会不会被藏住。

本课改的模块是动作头和解码日程，不改 MiniMind-O 的音频路径。验证分三层。浏览器 Lab 必须让你先预测“H=1 时串行 7 步是否比并行 1 步慢”，揭晓后串行延迟条更长；把报告方式切到“只报平均”时界面标红。CPU 实验必须让 CE logits 形状为 `[B, T, V]`、L1 预测为 `[B, H, 7]`，并且 prompt / padding 不进 loss。论文数字只从已打开的 OpenVLA、OpenVLA-OFT、Prismatic 页面和斯坦福 SAIL MiniVLA 博文抄表，不横着比不同协议。

出现以下任一情况，本课结论作废：把 97.1% 写成通用操作已解决；把 Libero-90 上 MiniVLA 的 61.4% 和 LIBERO-Long 的 53.7% 加在同一张“SOTA”表里；用 CPU 实验的 CE 标量冒充仿真成功率；声称 MiniVLA 有独立 arXiv 号。

把“本课要改的”和“本课故意不改的”写成边界，避免作业膨胀到第 28–31 课。要改的是：动作如何占用词表、推理有多少次解码、CE 与 L1 的 mask、读表时如何拆套件。不改的是：OpenX 混合指数（第 26 课）、流匹配速度场（第 28 课）、快慢双系统（第 29 课）、开环窗口与重规划（第 30 课）、Wilson 区间与真机 N=25（第 31 课）、MiniMind-O 音频链路（第 01–07 课）、动态分辨率（第 08 课）。第 20 课的图像 flow 只作为“连续生成目标长什么样”的对照，本课动作头仍是 CE 或 L1。

读者完成第 25 课后，应已能说出均匀分箱会丢掉格内精度、chunk 会拉长开环时间。本课把这两句话接到 OpenVLA 的 256 档与 OFT 的 $H=8$。读者完成第 26 课后，应已能说出按条数采样会淹没小机体。本课直接使用 OpenVLA 已经选好的混合物，不再调 $\alpha$。若跳过 25/26，本课 5.3 与 5.6 仍可读，但你会缺少“为什么要怀疑平均成功率”的铺垫；Lab 红标就是为补上这块。

独立性：没有 GPU 可以完成第 4 节列出的能力 1–8 中除可选计时外的全部条目。有 GPU 也不许跳过 CPU 实验：7B 模型的 CE 标量下降，不能证明你的 mask 写对了。mask 错误时 loss 仍可下降，第 01 课已经演示过复制用户输入的失败模式；VLA 对应的失败模式是把视觉 token 也算进动作 CE，模型学会复述指令单词，动作维得不到梯度。

## 5. 原理：边造边讲

七个机制按同一节奏：为什么需要、怎么运转、公式、公开实现落点、怎么验证。

### 5.1 Prismatic 骨干：先有 VLM，再改成 VLA

OpenVLA 不是从随机初始化的 7B Transformer 直接训机器人。它先拿一个已经在图文数据上会看图说话的 VLM，再把输出空间从文字改成动作。这个 VLM 来自 Prismatic。Prismatic 论文把现代 VLM 收成三块：视觉骨干 $V_\omega$ 把图变成 patch 特征；投影 $F_\psi$ 把特征写进语言模型的嵌入维；语言模型 $\mathrm{LM}_\theta$ 做 next-token。训练目标仍是条件语言建模：

$$
\mathcal{L}_{\text{VLM}}=-\log p(\hat{u}_{\text{gen}}\mid x_{\text{img}},u_{\text{prompt}})
$$

“patch-as-token”（把每个图像小块的向量当成一个输入 token）让视觉序列和文字序列可以拼在同一条注意力里，也让后续 VLA 几乎不用改注意力内核。Prismatic 的一个关键实验结论是：在 VQA、定位和幻觉探针上，VLM 训练阶段把视觉编码器解冻会显著掉点，定位任务更明显。所以 Prismatic 默认冻住视觉骨干，只训投影和语言模型。OpenVLA 论文 3.4 节给出相反的 VLA 经验：做动作预测时，解冻视觉编码器是必要的，作者认为冻结的互联网视觉特征不够细，撑不起精确控臂。两篇论文并不打架：图文问答要保住互联网预训练的语义；控臂要看见桌沿、瓶口、夹爪缝。冻还是解冻，取决于监督信号从“说对物体名字”换成了“把夹爪放到厘米级目标”。

投影器在 Prismatic 里是两层 MLP，OpenVLA 沿用。第 02 课比较过 MLP、Perceiver、Q-Former；OpenVLA 走的是最朴素的逐 patch 投影，视觉 token 数等于 patch 数。224×224、ViT patch 14 时，每路编码器大约 256 个 patch。OFT 后来加腕部相机，视觉 token 从 256 加倍到 512，表 II 最后一行吞吐从约 110 Hz 降到 71.4 Hz，延迟 0.112 秒。这是输入变长的账单，不是动作头变慢。

Prismatic 的数据与优化选择也被 OpenVLA 继承了一部分。VLM 用 LLaVA 1.5 混合，大约 558K 字幕样本加 665K 指令样本，外加 ShareGPT 语言安全对话。Prismatic 发现单阶段直接训投影和 LM，可以去掉单独的 projector 对齐阶段，节省约 20–25% 训练，且综合指标不降。图像预处理上他们比较了裁切、letterbox 与直接拉伸，CLIP 上直接拉伸更好。分辨率从 224 升到 336/384 在 VLM 基准上显著涨点，但序列长度按分辨率平方涨、注意力按长度平方涨，这正是 OpenVLA 后来在 VLA 上改回 224 的成本背景。融合视觉把 DINOv2 与 SigLIP 的 patch 特征沿通道拼接，定位和挑战集上约 5–10 个点的收益，参数几乎不增加。OpenVLA 选 Prismatic，图的就是这份空间细节，而不只是“一个 7B VLM”的空壳。

验证：读 Prismatic 时核对其“单阶段训练可去掉 projector-only 预热”和“融合 DINOv2+SigLIP”两条；读 OpenVLA 时核对其“VLA 阶段解冻视觉”。不要把 VLM 阶段的冻结策略抄到 VLA 微调里还以为在复现 OpenVLA。

### 5.2 双视觉：SigLIP 管语义，DINOv2 管空间

只接一个 CLIP 或 SigLIP，对“图里是不是罐头”往往够用，对“罐头离夹爪还有几厘米、开口朝哪”不一定够。Prismatic 4.2 节把 DINOv2 特征与 CLIP/SigLIP 特征按通道拼接（同一 patch 位置、特征维加倍，序列长度不变），发现定位和挑战集上有统计显著提升；DINOv2+SigLIP 是他们试过的最强视觉组合。OpenVLA 图 1 和 3.1 节明确采用这套融合：输入 patch 分别过两个编码器，特征向量通道拼接，再进投影。

记 $p^{\text{sig}}, p^{\text{dino}}\in\mathbb{R}^{L\times h}$，融合为

$$
p_{\text{img}}=\operatorname{concat}_{\text{channel}}(p^{\text{sig}},p^{\text{dino}})\in\mathbb{R}^{L\times 2h}
$$

投影输入维从 $h$ 变成 $2h$，序列长度 $L$ 不变，注意力二次代价不按通道维爆炸。这是“加一路视觉几乎不增加 token 数”的理由。OpenVLA 还比较过 224 与 384 分辨率：384 训练大约慢 3 倍，他们在 BridgeData V2 小规模搜索里没看到收益，最终用 224×224。VLM 基准上提高分辨率常常涨点，VLA 上未必；分辨率账单要按控臂任务重测，不能从 VQA 直接迁移。

两路编码器的预处理必须各自按其预训练来，不能共用一套均值方差。SigLIP 与 DINOv2 的归一化统计不同；强行共用会让其中一路的特征漂到对方从未见过的输入域。OpenVLA / Prismatic 的实现是：同一张 224 图复制两份，各走各的 transform，再在 patch 维对齐后拼接。若一路 center-crop、一路 letterbox，256 个 patch 不再对应同一块物理区域，通道拼接就变成把两张错位的地图钉在一起。本课不要求你复现归一化常数，但代码审查时要看到“两套 transform”。

验证：实现里两路 ViT 输出的 $L$ 必须相等才能按通道拼。$L$ 不一致时先检查输入分辨率和 patch 大小，不要默默插值混过去。Lab 里的遮挡滑条模拟的是空间信息被挡，Spatial / Object 玩具成功率掉得比 Goal 更狠，对应“空间编码器一旦看不见物体，语义指令也救不了夹取”。

### 5.3 词表尾部的 256 个动作编号

语言模型的输出是词表上的分类。连续动作 $a\in\mathbb{R}^{7}$ 要先变成 7 个整数。OpenVLA 3.2 节跟随 RT-2：每一维单独分箱，箱数 $B=256$。箱宽不用训练集的 min/max。OpenVLA 用该维的 1% 和 99% 分位 $q_{0.01},q_{0.99}$，避免离群点把区间拉得过宽、有效分辨率变差：

$$
b_d=\operatorname{clip}\left(\left\lfloor B\cdot\frac{a_d-q_{0.01,d}}{q_{0.99,d}-q_{0.01,d}}\right\rfloor,0,B-1\right)
$$

Llama 词表留给新特殊 token 的坑大约 100 个，装不下 256 档。OpenVLA 再次跟随 RT-2：覆盖词表里最少用到的 256 个编号，对应词表最后 256 个位置。第 $d$ 维箱号 $b_d$ 映射为

$$
z_d = V - B + b_d
$$

其中 $V$ 是原词表大小。7 维动作变成长度 7 的 token 串 $z_{1:7}$。这个设计的代价要写清楚：那 256 个原语言 token 在 VLA 里不再能被生成；若它们本来就极少出现，对控臂影响有限，但不能假装词表是无损扩展。另一种设计是另加 256 个新 embedding，MiniVLA 博文在向量量化动作块时提供了“额外加 token”的选项。OpenVLA 主模型走覆盖，图省事、实现短。

分箱把同一格内的连续差全部抹平。格宽 $\Delta=(q_{0.99}-q_{0.01})/256$。若某维有效区间约 2（归一化到 $[-1,1]$ 后常如此），则 $\Delta\approx 1/128$。夹爪开合若需要比这更细的中间值，CE 无法表达。这是第 25 课量化误差上界在 OpenVLA 里的实例，也是 OFT 改连续 L1 的直接动机。

用手算把一维连续值变成词表编号。设某维 $q_{0.01}=-1$、$q_{0.99}=1$、$B=256$，则箱宽 $\Delta=2/256=1/128$。观测值 $a=0.12$：

$$
b=\operatorname{clip}\left(\left\lfloor 256\cdot\frac{0.12-(-1)}{2}\right\rfloor,0,255\right)=\operatorname{clip}(\lfloor 143.36\rfloor,0,255)=143
$$

若 Llama 词表大小 $V=32000$，覆盖从 $32000-256=31744$ 起，该维 token 为 $31744+143=31887$。相邻连续值 $0.12+\Delta/2$ 仍落在同一箱，CE 视为同一类；再加一点点跨过 144 号箱壁，类别跳 1，CE 立刻按两个不同词来罚。CPU 实验把 $B$ 缩到 8、$V$ 缩到 32，偏移从 24 起，方便打印整张 label。真实 256 档只改这两个常数，形状关系不变。

再给一个会跨箱的反例。同一维 $a=0.0$ 落在箱 128（若 $q_{0.01}=-1,q_{0.99}=1$），$a=\Delta=1/128\approx 0.0078$ 仍在 128 或刚进 129，取决于你对边界取左闭右开还是 `floor`。OpenVLA 用 `floor` 再 `clip`。实现若改成四舍五入，训练与推理各写一套，箱号会系统性偏半格，末端轨迹整体平移。CPU 实验在 $B=8$ 的边界 $e=-1+0.25=-0.75$ 两侧取 $e\pm 10^{-9}$，左箱 0、右箱 1，就是在锁这条离散规则。你应能不看代码、只看公式，指出 `floor` 让边界点归右箱还是左箱：因为 $e$ 恰好使分子/箱宽为整数，$e-10^{-9}$ 向下取整少 1。报告里写清边界归属，比争论“256 够不够”优先。

七维要串成一条因果链。常见顺序是 $x,y,z$，再滚转、俯仰、偏航，最后夹爪。这个顺序一旦在训练集里固定，推理时必须相同，否则第 4 个 token 的条件分布对不上。teacher forcing 时第 5 维看见的是真值第 4 维；推理时看见的是模型自己的第 4 维。第 4 维若落错箱，第 5、6、7 维的条件全偏，这就是曝光偏差（exposure bias：训练输入分布与推理输入分布不一致）。chunk 的自回归展开把这条链拉到 $7H$ 长，偏差有 $H$ 步时间去放大。并行解码切断了“第 $d$ 维依赖第 $d-1$ 维 token”这条链，改成 7 维同时看见同一份视觉语言前缀。OFT 在 LIBERO 上没有观察到并行比串行更差，说明这 7 维在该基准里主要共享同一观测，而不是强依赖“先写对 x 再写 y”。

验证：CPU 实验用 $B=8$ 的玩具词表，把动作编号放到最后 8 格，并断言 prompt 位置的 label 是 `IGNORE`。打印 `ce_action_positions` 应是长度为 7 的连续下标。

### 5.4 串行 CE：训练可并行，推理必须 7 步或 7H 步

训练序列看起来像一条语言样本：视觉 token、任务指令、然后 7 个动作 token。标准因果语言建模对每个位置预测下一个 token。OpenVLA 只在动作 token 上算 CE，图像和指令位置的 label 设为忽略。记有效位置集合为 $M$，则

$$
\mathcal{L}_{\text{CE}}=-\frac{1}{|M|}\sum_{t\in M}\log p(z_t\mid I,\ell,z_{<t})
$$

teacher forcing 意味着位置 $t$ 的输入是真值 $z_{<t}$，不是模型自己的 $\hat{z}_{<t}$。因此训练可以用一条因果 mask 在全部 7 个位置上同时算 loss，GPU 利用率高。这与第 01 课 assistant-only mask 同构：系统提示和用户问题不算账，只对要学的那段输出算账。回看 [第 01 课](01_baseline_reproduction.md) 的公式，把 $M_t$ 换成动作位置即可；回看 [第 02 课](02_multimodal_connector.md) 时，OpenVLA 的投影器对应那里的逐 token MLP，不对应 Perceiver。第 07 课的 CONTINUE / PAUSE / REPLAN 见 [第 07 课](07_full_duplex_routing.md)，本课只借用“生成期间是否还接收新观测”这一句。图像分辨率的动态切片见 [第 08 课](08_dynamic_vision.md)，OpenVLA 不用。连续生成目标的另一种数学见 [第 20 课](20_unified_understanding_generation.md) 的速度场，本课动作仍不是图像 latent。

推理没有真值前缀。生成 $z_1$ 之后才能把它喂回去生成 $z_2$，直到 $z_7$。每一步都是一次解码器前向（视觉前缀可缓存，但动作步之间无法并行）。H=1 时串行步数等于动作维数 $D=7$。若把未来 $H$ 步也展成 token 串，长度变成 $DH=7H$，串行步数同样是 $7H$。OFT 论文 III 节写得很直：chunk 大小为 $K$、维数为 $D$ 时，原版 OpenVLA 需要 $KD$ 次顺序前向；相对 H=1 的 $D$ 次，延迟大约再乘 $K$。所以在自回归公式下，chunk 不但不加速，还会让出动作更慢。这就是“OpenVLA 原公式下 chunk 不划算”的全部数学。

把前缀时间和逐步解码分开写，避免拿 7 去除总延迟后误以为每步都一样贵：

$$
t_{\text{serial}}(H)=t_{\text{prefix}}+7H\cdot t_{\text{decode}}
$$

OFT 表 II 的 0.2396 秒对应 H=1 的整段动作生成，吞吐 4.2 Hz。OpenVLA 论文 3.5 节在 RTX 4090、bfloat16、无编译加速时写过大约 6 Hz、显存约 15 GB。两块卡、两种实现，Hz 不可直接当同一测量。本课 Lab 用 $t_{\text{prefix}}=50\,\text{ms}$、$t_{\text{decode}}=27\,\text{ms}$ 的教学数，使 H=1 串行约 239 ms，与表 II 同量级，但界面已标明教学模拟。

KV 缓存（把已算过的 key/value 留下来，下一步只算新 token）能降低串行每步的常数，减不掉步数本身。视觉前缀 256 个 patch 加几十个语言 token，第一步最贵；之后 6 个动作 token 每步只追加 1 个位置。即便每步 decode 从 27 ms 降到 15 ms，H=1 仍要 7 次启动，H=8 仍要 56 次。编译、speculative decoding（用小模型草稿、大模型验收）可以再削常数，OpenVLA 论文 3.5 节明确写他们测 6 Hz 时没有开这些技巧。本课不把未测量的加速写进结论。

验证：CPU 实验断言 `serial_steps_h1 == 7` 且 `serial_steps_chunk == 7H`。Lab 验收要求你先预测串行 7 步更慢，再看到 H=1 的串行延迟条高于并行 1 步。

### 5.5 LoRA：7B 也能在单卡上适配

满血微调 OpenVLA 在论文 5.2–5.3 节用 8 块 A100、每任务 5–15 小时。对只有一块消费卡、示教只有几十到一百条的人，这不现实。OpenVLA 表 1 比较了若干参数高效策略（在一套略简的骨干上测，视觉只含 SigLIP）：只训最后一层 30.3%；冻视觉 47.0%；sandwich（视觉、嵌入、最后一层）62.1%；LoRA rank=32 为 68.2%，与满血 69.7% 接近，可训参数 97.6M，约占 1.4%，batch 16 时显存 59.7 GB。作者建议默认 rank 32，单卡 A100 上 10–15 小时可适配新任务，相对满血大约 8 倍算力下降。

LoRA 把更新写成两个瘦矩阵：

$$
W'=W+\frac{\alpha}{r}BA,\quad B\in\mathbb{R}^{d\times r},\;A\in\mathbb{R}^{r\times k}
$$

推理时可把 $BA$ 合并回 $W$，不留额外延迟。这与第 18 课 Nemotron LoRA 的代数相同，本课只把它用在 VLA 的线性层上。OFT 后续的 LIBERO 实验同样用 LoRA 微调 OpenVLA，因为下游示教约 500 条，远小于预训练的百万量级。

量化是推理侧的另一刀。OpenVLA 表 2：bfloat16 在 Bridge 代表任务上 71.3%、16.8 GB；int4 为 71.9%、7.0 GB；int8 掉到 58.1%，作者把主因归于 A5000 上 int8 只有约 1.2 Hz，系统动力学相对 5 Hz 采集错位。所以“位数越低越差”不成立，int4 可以又快又省，int8 反而可能因为慢而把控制搞砸。任何量化声明必须同时报 Hz 和任务成功率。

验证：微调日志里可训参数应在 1%–3% 量级（rank 32/64），不应接近 7B。若显存仍按满血 160 GB 涨，说明 LoRA 没有打到线性层，或又把视觉以满精度解冻进了优化器。

把表 1 的显存列当成实现检查表。满血微调 163.3 GB（2 卡 FSDP）、可训 7188M；只训最后一层 51.4 GB、465M 参数但成功率 30.3%，说明“能跑起来”远不够；冻视觉 156.2 GB，几乎没省显存，因为 LLM 仍满血，成功率 47.0% 说明视觉确实要动；sandwich 64.0 GB、914M 参数、62.1%，介于两端；LoRA 32 与 64 成功率同为 68.2%，参数 97.6M 对 195.2M，显存 59.7 GB 对 60.5 GB。rank 从 32 加倍几乎不涨点、不涨显存，所以默认 32。你若在单卡 24 GB 上复现，还要再开量化训练或更小 batch；论文没有声称 24 GB 能满设定跑 LoRA batch 16。本课 CPU 实验不测显存，只保留“可训参数应远小于 7B”这一句作为阅读检查。

### 5.6 OFT：并行、chunk、连续 L1

自回归 CE 的推理瓶颈是 $7H$ 次顺序前向。OFT 第四节把解码改成并行：给解码器填入空的动作嵌入（没有因果依赖的占位），把因果 mask 换成双向注意力，让 7 个位置互相看得见，一次前向写出全部维。chunk 只是把占位从 7 个加到 $7H$ 个。并行步数

$$
N_{\text{parallel}}=1
$$

输出张量形状 $[H,7]$（或再加 batch 维）。表 II：只改并行，吞吐 4.2 Hz 到 15.9 Hz，延迟 0.2396 秒到 0.0629 秒，大约 4 倍，接近 7 次解码合成 1 次、前缀仍在的预期。再加上 $H=8$，延迟略升到 0.0735 秒（文中写约 17%，因为注意力序列变长），吞吐到 108.8 Hz，相对 4.2 Hz 约 26 倍。连续 L1 再加一个 MLP 动作头，吞吐 109.7 Hz、延迟 0.0729 秒，和离散并行几乎一样，头很便宜。

连续动作不再走 softmax 词表。最后一层 hidden 进 MLP，直接出归一化连续值，损失为

$$
\mathcal{L}_{\text{L1}}=\frac{1}{|M|}\sum_{(k,d)\in M}\left|\hat{a}_{k,d}-a_{k,d}\right|
$$

$M$ 是有效动作位置。padding 的未来步、缺失维必须 mask 掉，否则模型会学着预测 0。这和 CE 的 `-100` 是同一纪律，只是损失从分类换成绝对值。OFT 还试过扩散目标、测试 50/10/5/2/1 步。表 II：50 步扩散吞吐仍是 4.2 Hz，延迟 1.9070 秒，LIBERO-Long 91.1%；1 步扩散吞吐 109.4 Hz，但 Long 成功率 0.0%。所以“并行了就一定又快又好”不成立，目标函数和采样步数会把质量归零。L1 的吸引力在于：单次前向、没有扩散步、LIBERO 上与扩散接近（表 I 第三人称设定下 Cont-L1 平均 95.3%，Cont-Diffusion 95.4%）。

表 I 必须按输入和是否过滤示教分块读，不能把三块平均横着比：

| 设定（OFT 表 I） | Spatial | Object | Goal | Long | 平均 |
|---|---|---|---|---|---|
| 第三人称+语言，过滤失败示教，微调 OpenVLA | 84.7 | 88.4 | 79.2 | 53.7 | 76.5 |
| 同上，+并行与 $H=8$ | 91.3 | 92.7 | 90.5 | 86.5 | 90.2 |
| 同上，+连续扩散 | 96.9 | 98.1 | 95.5 | 91.1 | 95.4 |
| 同上，OFT 连续 L1 | 96.2 | 98.3 | 96.2 | 90.7 | 95.3 |
| 第三人称+腕部+本体，过滤，OFT L1 | 97.6 | 98.4 | 97.9 | 94.5 | 97.1 |
| 同上设定，微调 $\pi_0$ | 96.8 | 98.8 | 95.8 | 85.2 | 94.2 |

并行加 chunk 相对原自回归平均绝对提升约 14 个点，Long 从 53.7% 到 86.5%，是四个套件里跳最明显的。连续表示再抬约 5 个点。97.1% 那一行还多了腕部相机和本体感觉，并且仍是每个套件单独微调、每套件 10 任务×50 回合=500 次试验。LIBERO-Long 在这一行是 94.5%，低于 Spatial 的 97.6%。平均再高，Long 也没有消失。

并行实现有三个容易抄错的细节。第一，空动作嵌入不是“把动作真值丢进输入再让模型复制”。输入侧是占位，监督只在输出头。若把真值动作当作输入还算 L1，模型会抄输入，评估时没有真值就会垮。第二，双向注意力只应加在动作槽之间以及动作槽对前缀；语言 token 仍应保持因果，否则指令内部会泄漏未来词，和 VLM 预训练不一致。OFT 文本强调动作并行，没有说把整段语言改成 BERT。第三，chunk 的时间维需要位置信息，否则 8 步输出会坍成同一步的重复。实现可以是可学习的步嵌入，或把步索引加进动作槽。缺这一项时，L1 仍能下降（预测平均值），评估轨迹会发直。

ALOHA 是另一套身体：25 Hz、14 维关节、三相机、双臂，预训练从未见过。OFT+ 在 L1 之外加 FiLM（用语言嵌入缩放平移视觉特征）。表 III：原自回归加额外相机后 1.8 Hz、0.543 秒；OFT+ 在 $H=25$ 时 77.9 Hz、0.321 秒，文中称相对基线约 43 倍吞吐。对照方法含 ACT 84M、Diffusion Policy 157M、RDT-1B、$\pi_0$ 3.3B，它们因体积小或 JAX 实现可以更快；OFT+ 以 7.5B 仍到 77.9 Hz，靠的是单次前向而不是更小的网。去掉 FiLM 后，语言跟随在两个依赖指令的任务上掉到 33%，等于随机选目标。本课不把 ALOHA 分数写进 LIBERO 表，也不把 33% 写成 LIBERO-Goal 的数字。

OFT 附录还做过一次“去掉 OpenX 预训练、直接对 Prismatic VLM 套 OFT 配方”的消融：四套件平均从 97.1% 掉到 91.9%，绝对 5.2 个点（表 XIV：Spatial 97.6 到 94.3，Object 98.4 到 95.2，Goal 97.9 到 91.7，Long 94.5 到 86.5）。并行 L1 并不能让预训练变得可有可无。本课 CPU 实验没有预训练权重，所以它更不能代替这一行消融。

验证：实现并行时检查注意力 mask 是否在动作槽之间双向。仍用因果 mask 的“伪并行”会让后面维看不见前面维的占位，形状对、语义错。L1 必须对 padding 步乘 0。

### 5.7 CE 与 L1 对 bin 边界的敏感度

取一维、箱宽 $\Delta$、$b$ 与 $b+1$ 的边界 $e$。边界左侧 $e-\varepsilon$ 与右侧 $e+\varepsilon$ 的连续差只有 $2\varepsilon$，CE 却把它们当成两个类别。若模型把全部质量放在左类，右类的 CE 是 $-\log p(b+1)$，可以接近很大的正数；L1 只付 $2\varepsilon$。反过来，箱内从左壁走到右壁，连续差接近 $\Delta$，CE 仍视为同一类、损失可为 0。

$$
\mathcal{L}_{\text{CE}}(e-\varepsilon,e+\varepsilon)\gg 2\varepsilon\approx\mathcal{L}_{\text{L1}}(e-\varepsilon,e+\varepsilon)
$$

$$
\mathcal{L}_{\text{CE}}(\text{同箱两端})=0,\quad\mathcal{L}_{\text{L1}}=\Delta
$$

CE 对“跨格”过敏，对“格内误差”失明。控臂时，格内误差是末端差一格宽，夹爪可能已经擦到杯沿；跨格误差有时只是量化抖动。L1 按物理差付钱，更贴近执行。代价是 L1 对多峰示教（同一观测对应两种都合理的动作）会倾向中位数附近，OFT 论文 VIII 节把这一点列为限制：示教真的多峰时，扩散可能更合适。LIBERO 四套件的示教策略相对集中，所以 L1 够用。

CPU 实验在 $B=8$ 的边界两侧取 $e\pm 10^{-9}$，断言两个 bin 编号不同，且把峰值放在左类时 CE 差大于 1，而 L1 差小于 $10^{-8}$。这是边界敏感度的最小可核证明。

用同一个 logits 向量把 CE 差算出来。$B=8$，logits 在左类位置为 4、其余为 0。softmax 后左类概率约 $e^{4}/(e^{4}+7)\approx 0.96$，右类约 $0.0057$。对左类 CE $\approx -\log 0.96\approx 0.041$，对右类 $\approx -\log 0.0057\approx 5.17$，差约 5.13，远大于 1。连续差 $2\times 10^{-9}$ 的 L1 几乎是 0。换一组均匀 logits，CE 差会变小，但类别仍然不同，梯度方向仍指向“把质量搬到另一格”，不会指向“在格内挪一点”。这就是离散头在接近箱壁时的行为：模型与其输出更精确的连续位移，不如把分类改到邻箱。夹爪开合若只有开/关两个物理意义，这个行为可接受；平移若需要毫米级，它会在箱壁附近抖。OFT 把头换成 L1，抖的来源从分类跳格变成回归噪声，通常幅度更小，且可用 chunk 平均掉一部分。

L1 也有失明区：同一观测对应两种相反策略时，绝对值损失的最优解靠近中位数。若一半示教向左绕障碍、一半向右，L1 可能输出“对着障碍走”。OFT 第八节把多峰示教列为限制，并指出扩散可能过拟合差的那一峰。LIBERO 四套件示教策略较集中，所以表 I 里 L1 与扩散平均只差 0.1 个点（95.3% 对 95.4%，第三人称设定）。换到真机厨房里多种绕法并存的数据，这个 0.1 不能拿来当“L1 已经够了”。本课 CPU 实验的动作没有多峰，测不出这件事；报告里要写“未测多峰”。

### 5.8 MiniVLA：参数量不是唯一瓶颈

OpenVLA 7B 在单卡上慢，并不自动推出“必须 7B 才能在仿真里成功”。斯坦福 SAIL 博文把语言骨干换成 Qwen 2.5 0.5B，ViT 仍用 OpenVLA 那套，总参数约 1B，称为 MiniVLA。同一篇博文给出 Prism 224px 的 VQA 对照：Llama 7B 的 VQAv2 78.11、GQA 62.5、TextVQA+OCR 54.70；Qwen 0.5B 为 71.73、56.64、39.8。文字视觉掉得明显，POPE 都是 87.6。然后他们在 Libero-90 上把动作预测训到约 95% token 准确率：OpenVLA 62%，MiniVLA 61.4%。博文原句：没有显著差异。单卡 NVIDIA L40s 上 MiniVLA 推理 12.5 Hz，OpenVLA 5 Hz，约 2.5 倍。

真正拉开 Libero-90 的是输出和输入表示，不是把 7B 加回去。向量量化动作块（VQ h8）把 MiniVLA 推到 77%；再加 history=2 到 82%，加腕部图像到 82.1%。VQ 只做单步（h1）则 62.4%，几乎回到无 chunk。这与 OFT 在 LIBERO-Long 上看到的 chunk 收益同方向：一次预测一段时间，减少逐步误差累积。MiniVLA 仍是自回归 token，用压缩后的 code 缩短串；OFT 用并行加连续值取消串。两条路都在打 $7H$ 这笔账，工具不同。

博文还在 SimplerEnv 四任务上给过 MiniVLA+VQ h8 与 OpenVLA 的对照（Place carrot 44% 对 46%，Place spoon 68% 对 44%，Block stack 70% 对 62%，Pick eggplant 14% 对 66%）。四任务有赢有输，不能写成 1B 全面超过 7B。本课只引用博文表内数字，不为 MiniVLA 编造 arXiv。SimplerEnv 是另一套仿真协议（视觉尽量贴近真实 Bridge 采集），与 LIBERO 四套件、Libero-90 都不可横比。第 31 课会处理协议分层；本课只要你在笔记本里给这三组数字打上不同来源标签。

### 5.9 一条训练样本如何摆 token 和 mask

把前缀、动作、padding 写进同一条长度 $T$ 的序列，是 CE 与 L1 共同的记账面。CPU 实验用 $T=5+7+2=14$：5 个提示位置、7 个动作、2 个 padding。CE 的 label 向量是

```text
[-100, -100, -100, -100, -100, z1, z2, z3, z4, z5, z6, z7, -100, -100]
```

logits 形状 `[B, 14, 32]`，对每个非 `-100` 位置取该行 softmax 后的负对数。有效项数必须等于 $B\times 7$，多出来说明 padding 或提示被算进损失，少了说明某维动作没进监督。teacher forcing 在实现里体现为：位置 $t$ 的输入 token 是真值序列的 $t$，不是模型采样。PyTorch `CrossEntropyLoss(ignore_index=-100)` 与第 01 课相同。

并行 L1 不再占用词表维。动作头输出 `[B, H, 7]`，真值同样形状。CPU 实验令 $H=4$，第二条样本的最后一步 mask 为 0，模拟“这个 chunk 没有第 4 步示教”。有效条目应是 $2\times 4\times 7-7=49$。若你把 mask 忘掉，模型会在 padding 步学输出全零，推理时在短轨迹结尾把胳膊收回原点。这是执行层故障，不是回归比分类差。

因果 mask 与双向 mask 要分开画。CE 训练：位置 $t$ 只能看见 $1\ldots t$。并行训练：动作槽之间全连接，所有动作槽都能看见全部视觉语言前缀。若并行实现里仍留下下三角，后几维等于在看空占位，梯度噪声会变大，形状检查发现不了这个问题。读 OFT 代码时，除了输出头，还要打印注意力 mask 的一块 $7\times 7$ 动作子矩阵，确认全 1。

### 5.10 视觉遮挡、语言捷径与套件拆桶

LIBERO-Goal 的物体和布局固定，变的是指令；LIBERO-Spatial 的物体固定，变的是摆放。若模型几乎不看图、只背“这个套件里常见的那个动作”，Goal 会相对稳，Spatial / Object 会在相机被挡时先垮。Lab 的遮挡滑条按这个方向造夹具：Spatial、Object 的权重更高，Goal 更低。这不是 LIBERO 官方扰动协议，只逼你养成“改视觉输入后必须看分套件表”的习惯。

只报平均的危害可以用 OpenVLA 表 12 直接算。四套件 84.7、88.4、79.2、53.7，平均 76.5。把 Long 藏进平均之后，读者看到的是“约四分之三成功”，看不到长程只有约一半。OFT 把平均拉到 97.1 时，Long 是 94.5，缺口缩小了，没有消失。若有人只在幻灯片写 97%，听众会以为长程也 97%。本课 Lab 因此在“只报平均”时强制红标。第 31 课会进一步要求置信区间；本课先做到拆桶。

语言捷径还有一种更硬的负对照：打乱指令文字、保持图像不变。若成功率几乎不动，模型没在用语言。OpenVLA 论文强调多物体场景里的语言接地，OFT+ 在 ALOHA 上加 FiLM 也是因为多相机视觉相关物太多、语言会被淹没。FiLM 公式为 $\hat F=(1+\gamma)\odot F+\beta$，其中 $\gamma,\beta$ 由语言嵌入投影得到，并且作用在每个 ViT 块、对所有 patch 的同一隐维。OFT 写明：若错误地把每个 patch 当独立 feature 去调，语言跟随会变差。LIBERO 主表不用 FiLM。本课不实现 FiLM，只要求你不要把 ALOHA 的 OFT+ 开关抄进 LIBERO 复现命令。

### 5.11 从一张图到七个数：把前向走成可对账的流水

下面用一组具体数字把 5.1–5.7 串起来。数字是教学量级，用来对形状，不是 OpenVLA 某次真实前向的日志。

输入：一张 224×224 第三人称图，指令 12 个文本 token。SigLIP 与 DINOv2 各输出 $L=256$、$h=1024$ 的 patch 表。通道拼接得 $[256,2048]$。两层 MLP 把 2048 投到 Llama 隐维 4096，得到 256 个视觉 token。文本 12 个，前缀长度 268。自回归 H=1 时再追加已生成的动作 token，最多加 6 个历史动作（正在生成第 7 维时）。并行 H=8 时追加 $8\times 7=56$ 个空动作槽，前缀加动作槽长度 324。OFT 表 II 加腕部相机后视觉 token 变 512，前缀约 524，吞吐从 109.7 Hz 降到 71.4 Hz，长度账单在注意力里可见。

自回归 CE 的输出头是词表分类，logits `[1, 1, V]` 逐步产生，或训练时 `[1, 7, V]` 一次对齐 7 个真值。取 $V=32000$，有效类别只有最后 256 格。训练 mask 把前 268 个前缀标成 `-100`，只留 7 个动作位置。设这 7 个真值箱号为 $(143, 90, 200, 128, 10, 180, 255)$，对应 token $(31887, 31834, 31944, 31872, 31754, 31924, 31999)$。若模型在第 3 维把质量分给 199 号箱，CE 对该位置罚 $-\log p(200)$；即便 199 与 200 在连续空间只差一格，分类损失也不看格宽。

并行 L1 的输出头是 `[1, 8, 7]`。真值是 8 步、每步 7 维、已按分位归一化到大约 $[-1,1]$。第 3 步第 1 维真值 0.12、预测 0.20，该格贡献 $0.08$。八步平均后得到标量损失。没有词表，也没有“第 3 步必须等第 2 步 token 出来”。推理一次前向写出 56 个数，执行完 8 步再查询。OFT 发现整段执行再查询，比中途重规划更稳，也更快。这是开环窗口换吞吐的交易，第 30 课再把它放进物体被挪走的场景。

延迟对照把同一前缀时间留下。设 $t_{\text{prefix}}=50\,\text{ms}$ 含两路 ViT 与 268 个前缀的注意力，$t_{\text{decode}}=27\,\text{ms}$。串行 H=1：239 ms。并行 H=1：77 ms。串行 H=8：1562 ms。并行 H=8：按表 II 的 17% 拉伸约 80–90 ms 量级，实测 73.5 ms。Lab 的条形图就是这四行。你必须先猜串行 7 步更长，再看条，避免用事后的 239>77 倒填预测。

成功率对照必须换纸。机制实验通过，只说明张量对；LIBERO-Long 53.7% 或 94.5% 是另一张纸上的伯努利计数。把 239 ms 和 97.1% 写在同一句里当因果，本课视为报告错误：延迟来自表 II，97.1% 来自表 I 第三块，中间隔着腕部相机、过滤示教和每个套件单独微调。

### 5.12 OpenVLA 在真机微调里证明了什么、没证明什么

OpenVLA 主文 5.2 节把同一套 7B 权重微调到 Franka-Tabletop（5 Hz）和 Franka-DROID（15 Hz），每任务 10–150 条示教，共 7 个任务、129 次评估回合。结论方向是：窄任务、单指令时，从零训练的 Diffusion Policy 仍然平滑、精确；指令多样、多物体需要语言接地时，OpenX 预训练的 OpenVLA 更稳；OpenVLA（scratch）即直接在 Prismatic VLM 上微调、不经 OpenX，语言接地变差。这支持“百万级机器人预训练有用”，不支持“自回归 7B 已经是所有操作的默认解”。作者自己写 Dexterity 仍不如 Diffusion Policy 的动作块平滑，并把 chunk 与时间平滑列为后续（后来 OFT 做了）。

表 1 的 LoRA 对比要连着读“测在哪些 Franka-Tabletop 任务、33 次回合”。68.2% 对 69.7% 不是 LIBERO 数字，更不是 97.1%。量化表 2 测在 8 个 Bridge 代表任务、每种精度 80 回合：int4 与 bfloat16 相当，int8 因 1.2 Hz 拖垮动力学。把表 1 和表 2 的成功率接到 LIBERO 表 I，属于张冠李戴。

Google Robot 与 WidowX 上的 29 任务 out-of-the-box 评测，是预训练通用性，不是本课的微调诊断主线。本课需要它的唯一结论：7B 开源 VLA 可以在部分真机任务上接近或超过 55B 闭源 RT-2-X，语义泛化仍可能落后，且成功率通常低于 90%。OpenVLA 第 6 节自己把“可靠性仍然不够高”写成限制。97.1% 出现在一年后的仿真微调论文里，不能用来改写 2024 年这篇真机段落。

## 6. 在公开实现中定位这些机制

本课没有 MiniMind-O 源码可改。对照公开仓库时，按前向顺序找，不要从训练脚本倒推“应该有的文件名”。

OpenVLA 推理入口在 HuggingFace 包装类 `OpenVLAForActionPrediction`（模块路径 `prismatic.extern.hf.modeling_prismatic`，配置类 `OpenVLAConfig`）。读这个类时核四件事：图像是否被两路视觉编码器处理；投影输出是否与语言 embedding 拼接；`predict_action` 是否循环 7 次 decode；解出的 token 是否减掉词表偏移后再映射回连续动作。微调走 `vla-scripts/finetune.py`，注释和参数里能看到 LoRA 与量化开关。动作分箱的分位统计必须来自训练集，而不是对称的 $[-1,1]$ 硬编码，否则 $q_{0.01}$ 与 $q_{0.99}$ 对不上论文 3.2 节。

OFT 仓库 `moojink/openvla-oft` 与项目页 [openvla-oft.github.io](https://openvla-oft.github.io) 对应论文第四节的实现差异：动作槽占位、双向 mask、MLP 动作头、chunk 维、$H=8$ 或 ALOHA 的 $H=25$。若一份“OFT”实现仍在循环 7 次 `generate`，它只是换了损失名字。FiLM 只出现在 ALOHA 的 OFT+，LIBERO 主结果不用它；不要给 LIBERO 复现误加 FiLM 还当官方设定。

MiniVLA 仓库 `Stanford-ILIAD/openvla-mini`。先确认语言骨干是 Qwen 2.5 0.5B 还是误装了 7B Llama；再看动作是 256 档还是 VQ code。博文里的 61.4% 是无 VQ chunk 的 Libero-90；82% 含 VQ 与历史帧。复现时把开关写进报告，否则两个数字会被当成矛盾。

Prismatic 训练代码在 `TRI-ML/prismatic-vlms`。它证明 VLM 阶段冻视觉、单阶段训练、融合视觉。OpenVLA 在此之上改数据与动作头。两仓不要混成一份“Prismatic-VLA”。

读权重时同时记下精度：bfloat16 约 15–17 GB，int4 约 7 GB（OpenVLA 表 2）。OFT 项目页 FAQ 写过 LIBERO 单图推理大约 15.9 GB。显存对不上时先查 batch 和是否又把视觉 encoder 以训练模式加载，再怀疑模型下错。

建议的阅读顺序固定为五次打开，每次只核一张清单，避免在仓库里无目标滚动。

1. 打开 `modeling_prismatic.py` 里的 `OpenVLAForActionPrediction`。记下 `forward` 是否返回动作 logits 还是语言 logits；`predict_action` 循环次数是否写死为 7；detokenize 是否先减词表偏移再按分位反量化。若循环次数随 `action_dim` 变化，双臂 14 维会自动变慢，这是机制，不是 bug。
2. 打开分箱与分位统计。确认 $q_{0.01}$、$q_{0.99}$ 来自训练集扫描，而不是对称区间硬编码。OpenVLA 3.2 节把这一点写成相对 RT-2 min/max 的改动。若你用 $[-1,1]$ 当全体机体的分位，夹爪 0/1 会浪费大量箱子，位置维会被压到过宽的格子里。
3. 打开 `vla-scripts/finetune.py`。记下 LoRA rank、目标模块列表、学习率、是否解冻视觉。OpenVLA 表 1 表明冻视觉会掉到 47.0%。一份“只训 LLM、冻 ViT”的脚本不是在复现他们的推荐适配。
4. 打开 OFT 仓库中改 mask 与动作头的 diff。并行的最小证据是：动作槽输入为可学习或零占位；注意力子矩阵在动作维上双向；输出从 `lm_head` 换成 MLP。chunk 的最小证据是动作槽数量等于 $K\times D$，而不是 $D$。
5. 打开 MiniVLA 配置。确认 `qwen2.5-0.5b` 与 `dinosiglip-224px` 同时存在。只有语言骨干缩小、动作仍是 7 个 256 档 token 时，对应博文 61.4% 那一行；VQ h8 是另一行。

远程推理服务器是 OpenVLA 论文 3.5 节的工程产物：机器人本机可以没有 15 GB 显卡，动作从工作站流过来。延迟账单要加上网络往返。表 II 在 A100 本地测，不含这项。本课 Lab 也不含网络。真机部署若走远程，必须把往返加进 $t_{\text{prefix}}$，否则会低估开环窗口是否够用。第 30 课专门处理延迟进入控制回路；本课只要求你不要把“模型 Hz”和“末端 Hz”写成同一个数。

一份对照清单，用来在 code review 时五分钟内否决错误 PR：

| 检查项 | 通过 | 否决 |
|---|---|---|
| 动作维数 | 7（LIBERO/OpenVLA 预训练）或明确的 14（ALOHA） | 写死 7 却加载双臂数据 |
| 词表映射 | `token = V - 256 + bin` | 占用 `<unk>` 或随机 256 格 |
| 分位 | 训练集 1% / 99% | 全局 min/max 或对称 $[-1,1]$ 冒充全体机体 |
| 训练 mask | 仅动作位置 | 视觉或指令 token 进 CE |
| 推理循环 | 7 或 $7H$ 次，或并行 1 次 | 训练用并行、推理偷偷变回 7 次且不声明 |
| 注意力 | 串行因果；并行时动作槽双向 | 并行仍下三角 |
| 损失 | 离散 CE 或连续 L1，不混在同一输出头 | 对 softmax 概率做 L1 |
| chunk 执行 | 与训练 $H$ 一致 | 训练 8、推理 1 且无位置嵌入 |
| 评测表 | 四套件分列 | 只有平均 97% |
| MiniVLA 引用 | SAIL 博文 URL | 伪造 arXiv:XXXX.XXXXX |

表中“对 softmax 概率做 L1”是真实出现过的混合错误：有人把 256 类的概率向量当成连续动作。概率在单纯形上，L1 对它没有末端位移的单位。CPU 实验把两种损失分成两套张量，正是为了让这种混合无法通过形状检查。

## 7. 数据与训练 recipe

OpenVLA 预训练数据来自 Open X-Embodiment，经两轮整理：只要带第三人称相机、单臂末端控制的操作数据，再按 Octo 的混合权重平衡机体与场景。论文写最终约 97 万条轨迹。DROID 曾以 10% 权重加入，动作 token 准确率一直偏低，最后三分之一训练被拿掉。第 26 课讨论的 $\alpha$ 混合在这里是已经选定的上游事实，本课不重做混合搜索。

动作空间在预训练里是相对末端位姿加夹爪，低频（论文讨论里写常见 3–10 Hz）。LIBERO 微调用仿真 Franka、增量末端动作；ALOHA 微调用 25 Hz 绝对关节角、14 维。同一套 7B 权重能被 OFT 接到 ALOHA，说明微调配方可以跨动作定义，不说明零样本已经会折衣服。

LIBERO 四套件在 OpenVLA 附录 E 和 OFT 第五节定义一致，各 10 个任务、每任务 50 条人工示教：

| 套件 | 测什么 |
|---|---|
| LIBERO-Spatial | 物体集合固定，布局变，测空间关系 |
| LIBERO-Object | 布局固定，物体变，测物体类别 |
| LIBERO-Goal | 物体与布局固定，目标指令变，测任务语义 |
| LIBERO-Long（LIBERO-10） | 长程，物体、布局、任务都更多样 |

OpenVLA 附录 E 对训练数据做了四项修改，OFT 跟随“过滤失败示教”这一条并在表 I 分块标注：示教重放到 256×256 以免把 128 图硬放大；去掉近零的 no-op，否则单步高容量策略会学会在原地冻结；第三人称图旋转 180° 以匹配他们硬件上的颠倒渲染；只留成功轨迹。报告里必须写“modified / filtered”还是原始未过滤。表 I 中间块是未过滤加腕部相机，OFT 平均 94.5%，与过滤加腕部的 97.1% 不是同一行。

预训练超参（OpenVLA 3.4–3.5）：学习率 $2\times 10^{-5}$，与 Prismatic VLM 相同，无 warmup 收益；图像 224；一直训到动作 token 准确率超过 95%，最终 27 个 epoch；64×A100、14 天、batch 2048。OFT 的 LIBERO 微调（附录超参表）：8×A100 或 H100 80 GB，学习率 $5\times 10^{-4}$，50K–150K step，非扩散方法；扩散要 100K–250K。chunk $K=8$，执行完整 chunk 再查询。这些数字只描述原论文预算，不是本课 CPU 实验的运行时间。

本课 CPU 数据是手写的 7 维向量，分位数固定为 $[-1,1]$，箱数 8。它只负责 mask 与形状，不含 LIBERO 轨迹。

OpenVLA 在 BridgeData V2 上做过小规模骨干搜索，再放大到全量 OpenX，这是 3.4 节的工作方式。他们比较过 IDEFICS-1、LLaVA、Prismatic：多物体语言接地任务上 LLaVA 比 IDEFICS-1 高约 35 个点，Prismatic 再比 LLaVA 大约高 10 个点，作者把差额归到融合视觉。本课不要求复现这场搜索，但写报告时不能把“换一个 VLM 骨干”说成无关改动。视觉融合一旦拿掉，空间题先掉，和 Prismatic 4.2 节方向一致。

学习率 $2\times 10^{-5}$ 扫过多个数量级后被选中，与 VLM 预训练相同。VLA 与 VLM 还有一个相反点：VLM 常常 1–2 个 epoch 就够，OpenVLA 要 27 个 epoch，并且真实机器人表现随着动作 token 准确率爬过 95% 还在涨。这解释了为何“看一眼 CE 已经 1.0 以下就停”会欠拟合。准确率 95% 仍允许每 20 个动作 token 错 1 个；7 维一步里错 1 维，夹爪或高度就可能失败。所以预训练的停止条件是任务相关的 token 准确率，不是文本 CE 的观感。

OFT 微调学习率 $5\times 10^{-4}$ 比预训练高一个数量级，配合 LoRA 与小示教集。扩散变体要更多 step 才收敛，表 I 因此给扩散 100K–250K、非扩散 50K–150K。若有人用 50K 扩散和 150K L1 比成功率，收敛步数不公平。本课引用表 I 时默认作者已按“每条方法取最好 checkpoint、每 50K 测一次”的规则，不把该规则改写成你的 CPU 实验。

LIBERO 图像处理的 180° 旋转只属于 OpenVLA/OFT 自己的硬件观察：仿真器在他们机器上返回倒图。换渲染器的人若照抄旋转，等于把训练集和测试集一齐转错。这是“论文附录里的实现细节不是物理定律”的例子。过滤 no-op 则更接近算法：单步高容量模型会模仿“什么都不做”，评估时在某状态冻住。并行 L1 加 chunk 之后，冻住的表现会换一种形式：整段 chunk 输出近零。mask 与 no-op 过滤要一起看。

## 8. 按依赖顺序执行实验

实验顺序锁死：先公式和 mask，再浏览器对照，最后才允许碰公开权重。倒过来会把环境错误当成算法结论。

### Step 0: 核 CE 与 L1 的形状、mask、边界

在 `experiments/` 下运行本课 CPU 实验（编排者注册后）：

```bash
python3 run.py run 27
```

`checks` 必须全为真：CE logits `[B, T, V]`；prompt 与 padding 为 `IGNORE`；有效动作 token 数等于 7；串行深度 7 与 $7H$；L1 预测 `[B, H, 7]`；padding 时间步 mask 为 0；bin 边界两侧类别不同且 L1 差接近 0。任一条假，先改实验代码或你对 mask 的理解，不要开始调 Lab 滑条。

### Step 1: 浏览器里先预测再揭晓延迟

打开本课 Lab。先在底部三选一：H=1 时串行 7 步 CE 与并行 1 步 L1 谁延迟更高。不选不能运行。运行后看四条延迟条：当前配置、对照配置、固定的串行 7 步、固定的并行 1 步。验收要求串行 7 步条长于并行 1 步条。教学公式保证该不等式；若你的预测是“并行更慢”或“相同”，反馈会要求改预测。

### Step 2: 切 chunk 与遮挡，观察玩具成功率

H 在 1/4/8 切换。串行步数显示为 $7H$，并行保持 1。遮挡 0/35%/70%。这是教学夹具：Long 的玩具成功率低于另外三套，遮挡主要打 Spatial/Object。不要把 Lab 百分比抄进论文笔记。

### Step 3: 触发“只报平均”的红色警告

把“成功率怎么报”切到“只报平均”。界面必须变红，并写明 Long 被藏进平均数。再切回“拆开四套件”才能通过 Gate。这一步对应本课误区：76.5% 或 97.1% 都不能单独当结论。

### Step 4: 可选，公开权重上的单步计时

仅在有 GPU 且已按官方许可证下载权重时进行。用 `OpenVLAForActionPrediction` 对一张 224 图和一条固定指令计时 100 次，分别记录 H=1 自回归与（若加载 OFT 权重）并行 chunk。报告卡型号、精度、是否编译。不要把一次测量写成表 II。表 II 的条件是 A100、100 次查询、指定那句 LIBERO 指令。

失败判定：Step 0 有假 checks；Step 1 未先预测；只报平均却无红标；用 Lab 数字给 OpenVLA 排名。

Step 0 的 8 条 checks 对应本课公式，不是装饰。`ce_logits_shape_is_batch_seq_vocab` 锁住分类头仍走词表维；若你已经改成 L1 还保留这条，应该拆成两个实验臂，不要在同一组 logits 上既算 CE 又算 L1。`ce_loss_mask_skips_prompt_and_padding` 锁住 $M$ 的定义。`ce_counts_seven_action_tokens` 防止 7 维里某维被写成 padding。`serial_depth_is_seven_or_seven_h` 把推理步数从训练并行里拆出来。`l1_pred_shape_is_batch_chunk_dim` 锁住 $[B,H,7]$。`l1_mask_drops_padded_timestep` 锁住短轨迹。两条边界 checks 锁住 5.7 节的不等式。改实验代码时只许加新 checks，不许为了变绿而删旧 checks。

Step 1–3 在浏览器里完成，状态应能被 `useCompletionGate` 写回。预测选项必须在运行前选定；运行后改预测会清掉揭晓，防止先看条再选答案。H 与遮挡改动也会清掉揭晓，因为玩具成功率是这些旋钮的函数。红标与拆套件是报告纪律，与延迟预测分开：即使延迟已经看对，只留平均列仍不能过 Gate。

若你走 Step 4，计时协议抄表 II：同一张图、同一条指令、预热后再统计 100 次。报告均值和极值。第一次前向常含编译或权重加载，必须丢掉。吞吐按“每秒动作步”计：并行 $H=8$ 的一次前向算 8 步。若按“每秒查询次数”计，会把 26 倍说成 4 倍，和表 II 对不上。

Lab 内部公式与论文表 II 的关系也要写在笔记里，免得有人把教学条当成复现。Lab 固定 $t_{\text{prefix}}=50$、$t_{\text{decode}}=27$，串行 H=1 得到 239 ms，有意贴近 0.2396 秒，但并行 H=1 的 77 ms 并不等于表 II 的 62.9 ms，H=8 的拉伸也不等于 0.0735 秒。Gate 只检查不等式 $t_{\text{serial}}(H=1)>t_{\text{parallel}}(H=1)$，以及平均报告的红标。玩具成功率的基数是 0.72/0.78/0.70/0.41 与 0.86/0.89/0.84/0.62，刻意避开 84.7/88.4/79.2/53.7，以免截图被贴进论文笔记。遮挡按 0/0.35/0.70 三档，权重 Spatial 0.52、Object 0.48、Goal 0.22、Long 0.34，只为让 Spatial/Object 先掉。改这些常数等于改夹具，改完必须在报告里声明“非默认 Lab”。

完成 Gate 的推荐操作顺序：预测选“串行 7 步更高”，再运行（默认在只报平均，应立即看到红标），再确认最下面两条 H=1 延迟条串行更长，再把报告方式改成拆开四套件，最后拖遮挡和 H，观察 Long 与 Spatial 的分化。顺序反了也能过，只要四个条件同时成立；推荐顺序只是减少迷失。

## 9. 评测与测量

评测对象分三类，指标不得混用。

**机制核验（本课必须过）。** CE / L1 的 shape、mask、串行深度、边界敏感度。通过标准是 CPU 实验 `checks` 全真。它不测量任务成功。

**延迟与吞吐。** 定义要与 OFT 表 II 一致：latency 是生成一个动作或一个 chunk 的墙钟时间；throughput 是每秒产生的动作维时间步数量（chunk 为 8 则一次前向计 8 个动作）。A100 上他们查询 100 次，输入 224×224 与指令 “pick up the alphabet soup and place it in the basket”。抄表时连同硬件和输入写上。OpenVLA 论文的 6 Hz 是 4090、H=1、bfloat16，另一行数字。

**LIBERO 成功率。** 套件名、是否微调、输入相机、示教是否过滤、试验次数必须同时出现。OpenVLA 表 12：三随机种子、每套件 500 次，Spatial 84.7±0.9%、Object 88.4±0.8%、Goal 79.2±1.0%、Long 53.7±1.3%、平均 76.5±0.6%。OFT 表 I 写明 OpenVLA 变体每套件 500 次（10×50）。97.1% 是过滤示教、腕部+本体+第三人称、OFT L1 那一行的四套件平均。$\pi_0$ 在同一块是 94.2%，其 Long 为 85.2%。平均赢不等于每个套件赢。

**Libero-90 与真机。** MiniVLA 博文的 62% / 61.4% / 77% / 82% 属于 Libero-90，不是上述四套件。OpenVLA 主文 Bridge 与 Google Robot 的 29 任务、相对 RT-2-X 的 +16.5 个点，属于真机跨机体评测，样本量和任务定义都不同。第 31 课会专门拆仿真与真机；本课能做的是拒绝把这些行剪贴成一张总表。

测量时若只给平均成功率，按本课规定视为报告缺陷，相当于 Lab 红标。补救是加四列套件，再加一列设定脚注。

样本量要能回算。OFT 表 I 写 10 任务×50 回合=500。OpenVLA 表 12 写三种子、每套件 500 次并给标准误。500 次伯努利试验、成功率 0.537 时，正态标准误会在 $\sqrt{0.537\times 0.463/500}\approx 0.022$ 量级，论文给的 ±1.3% 还含任务间差异与多种子。本课不要求你在报告里重算 Wilson 区间（那是第 31 课的作业），但要求你看见 ± 时不要把它抄成“误差可以忽略”。N=25 的真机评测更宽，本课不引用未打开页面的真机百分比。

吞吐和成功率必须配对出现。表 II 把扩散的 Long 成功率写在同一张效率表里：50 步 91.1%、10 步 91.0%、5 步 90.0%、2 步 85.7%、1 步 0.0%。只报 109.4 Hz 会让人以为 1 步扩散可用。L1 行 109.7 Hz 配的是表 I 里 H=8 连续 L1 的 Long 90.7%（第三人称设定）或加输入后的 94.5%。抄 Hz 时带上对应成功率，抄成功率时带上能否实时。

OpenVLA 主文相对 RT-2-X 的 +16.5 个点，统计口径是 WidowX 与 Google Robot 上 29 个任务，不是 LIBERO。RT-2-X 是 55B 闭源。写“7B 超过 55B”必须跟上任务集合和开闭源条件。语义泛化那一类 RT-2-X 仍更好，OpenVLA 论文图 2 自己画了。本课不把这 16.5 个点写进 LIBERO 表。

## 10. 验收条件

书面报告同时满足：

1. 给出 $N_{\text{serial}}=7$ 或 $7H$、$N_{\text{parallel}}=1$，并说明 teacher forcing 不减少推理步数。
2. 词表覆盖写明最后 256 格、分位 $q_{0.01}$–$q_{0.99}$、每维 256 档。
3. CPU 实验 8 条 checks 为真，并附 `result.json`。
4. Lab：预测为“串行 7 步更高”；揭晓后 H=1 串行延迟大于并行；出现过只报平均的红标；最终按套件展示。
5. LIBERO 数字带表号和套件名。引用 97.1% 时写清 OFT 表 I 第三块设定，并列出 Long 94.5%。
6. MiniVLA 只引用 SAIL 博文，无伪造 arXiv。
7. 未把 97% 平均成功率写成通用操作已解决。

缺第 7 条，前面六条再完整也判不合格。

第 5 条要防一种精致的含糊：正文写了 97.1%，脚注写“LIBERO”，但既没有 Spatial/Object/Goal/Long，也没有“过滤失败示教、腕部相机、每套件 500 次”。这种写法在本课按未拆套件处理，与 Lab 红标同罪。正确的最小句子是：“OFT 表 I 第三块，第三人称加腕部加本体感觉、过滤失败示教、四套件各自微调，Spatial 97.6%、Object 98.4%、Goal 97.9%、Long 94.5%，平均 97.1%，每套件 500 次试验。” 句子长，是因为信息不能丢。第 6 条的最小句子是：“MiniVLA 见斯坦福 SAIL 博文，无 arXiv；Libero-90 上 1B 为 61.4%，对照 7B 的 62%；该基准不是 LIBERO-Long。”

第 1 条的反例：只写“并行更快”。没有 $N_{\text{serial}}$ 与 $N_{\text{parallel}}$，无法判断你是否把前缀时间算进了每一步。第 3 条的反例：贴一段 loss 下降曲线，没有 `checks` 字典。第 4 条的反例：截图只有并行延迟条，没有 H=1 串行对照，Gate 的不等式无从核。验收人应能在十分钟内按这七条打勾，不需要重训 7B。

可选加分（不加也不判失败）：在公开权重上记录一次 7 步墙钟，硬件与精度写清；把 $D=14$ 的串行深度手算进报告；为 FiLM 写明“仅 ALOHA OFT+”。加分项若数字无来源，改为扣分。

## 11. 根据症状定位失败环节

| 症状 | 先查 | 不是什么 |
|---|---|---|
| 推理约 4 Hz，训练 CE 却很快下降 | 是否在用自回归 7 步 decode；有无把训练并行误当成推理并行 | 不一定是数据差 |
| chunk 之后更慢 | 是否仍在串行吐 $7H$ 个 token | 不是 chunk 理论失效 |
| 形状是 `[B,7]` 但末端抖动像台阶 | 仍在走 256 档 CE；检查 bin 边界 | 不一定缺数据 |
| L1 loss 正常，padding 步输出恒 0 且被执行 | mask 没盖住无效时间步 | 不是 L1 比 CE 差 |
| 平均成功率高、长程任务崩 | 只报了平均；打开 LIBERO-Long | 不是“模型已经通用” |
| 加遮挡后 Spatial 掉、Goal 几乎不掉 | 语言捷径：没看见物体仍在背指令 | 需要负对照，不是单纯加数据 |
| LoRA 显存仍上 160 GB | 适配器没挂上线性层，或视觉以满精度进优化器 | 不是 rank 32 太小 |
| int8 成功率掉、int4 不掉 | 先看 Hz 是否把控制频率打穿 | 不是“8 bit 一定更准” |
| MiniVLA Libero-90 只有 61% | 是否没开 VQ chunk / 多图 | 不是 1B 一定失败 |
| 复现 LIBERO 远低于 84.7% | 示教是否过滤 no-op 和失败轨迹；图是否旋转 | 不是 OpenVLA 数字造假 |

遮挡负对照要单独记：Lab 里提高遮挡若四套件一起掉，空间和语义都在用视觉；若只有 Goal 几乎不动，模型可能在背套件先验。公开权重上做同类实验需要真的挡相机，不能用 Lab 公式代替。

训练 CE 已经低于 0.1、动作 token 准确率 99%，评估仍在抓空：先看推理是否用了采样温度。训练是 teacher forcing 的 argmax 监督，推理若 top-p 采样，7 步里任何一步抽到邻箱都会让后续维条件偏移。OpenVLA 默认动作解码接近贪心。接着核对控制频率是否匹配示教：4090 上 6 Hz、采集若是 5 Hz，错位不大；若把同一权重接到 25 Hz 而未改 OFT，动作会在两次查询之间被控制器插值或重复，表现像发粘。然后再看 no-op：准确率高可能来自大量近零动作被拟合，过滤 no-op 之前的 checkpoint 会在评估时停住。

并行 L1 训练损失很低、评估抖动大：检查双向 mask 是否只在训练打开、推理关掉。训练看见未来动作槽、推理变回因果，分布会偏。OFT 的设定是训练和推理都并行、都双向。另一常见错误是 chunk 在训练为 8、推理改为 1，动作头的位置嵌入对不上。

LoRA 合并进基座后成功率掉：合并时 $\alpha/r$ 缩放遗漏，或视觉编码器的 LoRA 没合并。OpenVLA 表 1 的 68.2% 是未量化、rank 32。合并后应与未合并推理逐元素对 hidden，再上机械臂。

MiniVLA 在 Libero-90 复现成 40%：先对动作 token 准确率。博文的 61.4% 对应约 95% token 准确率。准确率 80% 就停，7 维里平均一步错超过一维，仿真成功率没有理由靠近 60%。再查是否误用 LIBERO-Long 的评测脚本去报 Libero-90。

## 13. 前沿对照与改造方向

**公开方案。** 2024–2025 年把“VLM 吐动作”做成可下载权重的，OpenVLA 是自回归离散路线的基准。OFT 证明：在同一 7B 上，解码日程和动作表示比再堆参数更先碰到墙。表 I 里 $\pi_0$ 用流匹配，同一块过滤设定平均 94.2%、Long 85.2%，低于 OFT L1 的 97.1% / 94.5%；这不能外推成“L1 永远压过流匹配”，只说明在 LIBERO 这套示教和输入下，OFT 配方有效。FAST（OFT 相关工作里引用）把动作块压成更短的离散串，自回归加速约 2–13 倍，但文中举例 chunk 间仍可能有约 750 ms 空隙。MiniVLA 把语言骨干降到 0.5B，Libero-90 与 7B 持平，再用 VQ chunk 和多图把 61.4% 拉到约 82%。第 28 课将改用流匹配一次生成连续动作块，本课不实现速度场。

**差距。** 规模差距：OpenVLA 预训练 21500 A100 小时，本课 CPU 实验几毫秒。钱能缩小的是拟合容量和真机多样性，不能自动改掉串行 7 步。机制差距：因果 mask 对动作槽、离散 CE 对 bin 边界、只报平均对 Long 套件，这三件在缩小设置里就能复现方向。MiniVLA 说明 7B 不是 Libero-90 的必要条件；OFT 说明 26 倍吞吐主要来自取消 $7H$ 串，而不是换更大的 LLM。

公开方案里还有一条容易被滑过去的限制：OFT 把扩散的测试步数降到 1 时，LIBERO-Long 成功率为 0.0%，尽管吞吐已经和 L1 一样到 109.4 Hz。这说明“并行 + chunk”只提供了把多步动作一次写出来的槽位，槽位里填什么目标函数仍然决定能不能用。L1 填的是可在单次前向里求的绝对值；扩散填的是需要沿时间反推的噪声，步数不够时槽位里是未完成的噪声。本课不实现扩散，但改造实验若有人把 CPU 玩具改成“一次输出加噪声的 7 维”，必须同时声明反推步数，否则会重演表 II 中 $T_{\text{test}}=1$ 那一行的 0.0%。

顺手复现映射如下。

| 论文结论 | 缩小版对应 | 预期 |
|---|---|---|
| 自回归 7 步慢于并行 1 步（OFT 表 II） | Lab H=1 两条延迟条；CPU `serial_steps` | 同方向不等式，数值不等于 0.2396 秒 |
| chunk 把吞吐大约乘 $H$（并行之后） | Lab 把 H 从 1 调到 8 | 并行吞吐上升，串行深度变成 56 |
| 连续 L1 对箱壁不跳类别 | CPU 边界 checks | CE 跳、L1 几乎为 0 |
| 平均成功率掩盖 Long | Lab 只报平均红标 | 必须切到四套件 |
| 7B 不是 Libero-90 的唯一条件 | 阅读 MiniVLA 博文表 | 不在 CPU 上复现 61.4% |
| 去掉 OpenX 预训练掉 5.2 点（OFT 表 XIV） | 无缩小版 | 只记录，不声称已复现 |

表中“无缩小版”的行禁止用 Lab 数字填空。

与 Qwen2.5-Omni、Moshi 的对照只能停在架构口号之外。那些系统的公开技术报告讨论的是语音与视频时钟，没有给出 OpenVLA 同设定的 LIBERO 四套件表。本课因此不引用它们的操作成功率。能引用的是第 02 课已经讲过的投影器形状、第 01 课的 mask、第 20 课的“连续生成目标可以不是分类”。再往外的数字，没有打开的页面就不要写。

改造实验的失败判定要写得比“loss 没降”更硬。实验 1 失败：`serial_steps` 仍等于 7 而 `ACTION_DIM` 已改 14。实验 2 失败：B=2 的重建曲线被说成“更平滑”，实际是高频被量化削掉。实验 3 失败：CSV 只有 `avg` 列还在摘要里写 SOTA。实验 4 失败：计时包含第一次冷启动，或把 4090 的 6 Hz 写进“表 II 复现”。四条失败都是协议错误，不是模型太弱。预算方面，实验 1–3 在笔记本 CPU 上应在一分钟内结束；实验 4 的时间瓶颈是下载 7B 权重，下载失败就停在实验 3，不要用随机初始化的 7B 前向冒充 OpenVLA 延迟。

若后续课程已经写好，第 28 课会把 $a\in\mathbb{R}^{H\times d}$ 换成流匹配积分；第 29 课会把慢 VLM 与快动作专家拆开；第 30 课会把本课的 $t_{\text{serial}}$ 放进 $H/f$ 的开环窗口不等式。本课停在“会诊断自回归 VLA 的词表和串行延迟”，不预支那些公式的验收。学完应能在白板上写出 $N=7$ 或 $7H$、画出 mask、并拒绝一张只有 97% 的幻灯片。写不出这三件事，就还没完成本课。辅导时可以让对方只做三道口头题：H=8 的串行步数是多少；CE 的 `-100` 盖在哪；OFT 表 I 里 97.1% 对应的 Long 是多少。三题全对，再看 Lab Gate。三题里把 97.1 说成通用操作，当场退回第 2 节。H=8 的答案必须是 56 而不是 8：8 是 chunk 长度，串行仍按维数展开。`-100` 必须覆盖视觉与指令，不能只盖 padding。Long 的答案必须是 94.5% 并带上表 I 第三块。三道题对应延迟、mask、读表，覆盖本课三条主线。口试可以再追问一句：并行之后 chunk 为何不再让延迟乘 8。合格回答是一次前向吐出 $H$ 步，注意力只略变长，OFT 测得约 17% 而不是 8 倍。再追问 26 倍从哪来：4.2 Hz 到 108.8 Hz 是并行把 7 次合成 1 次，再乘上 $H=8$ 次动作一次性入账。只会说“因为并行”而不提 chunk，算半对。

**改造实验。**

1. 在 CPU 实验里把 `ACTION_DIM` 改成 14 模拟双臂，比较 `serial_steps=14H` 与 `parallel_steps=1`。预算：本地 Python，分钟级。预期：串行深度加倍，L1 形状变成 `[B,H,14]`，mask 纪律不变。失败：并行实现仍循环 14 次却声称 OFT。
2. 把 CE 的 $B$ 从 8 改到 2，再对一条高频来回的一维示教算重建误差。预算：同一脚本。预期：B=2 时来回运动被抹成台阶，L1 仍跟踪幅度。失败：有人把 CE 训练 loss 下降当成重建变好。
3. 在 Lab 等价的表格里强制输出四套件，禁止提交只有平均列的 CSV。预算：无训练。预期：Long 列会阻止“97% 已解决”的句子。失败：平均列单独标成 SOTA。
4. 若有 1×24 GB，加载公开 OpenVLA 权重，对同一张图分别跑 7 步自回归与（若有 OFT checkpoint）一次并行。预算：下载权重加数分钟推理。预期：串行墙钟明显高于并行，方向与表 II 一致，绝对值随卡变化。失败：把 4090 的 Hz 写进“复现表 II”。

**缩小版能复现的方向。** 论文结论“并行降低延迟、chunk 抬吞吐、连续 L1 对边界更平滑、平均成功率掩盖 Long”，在本课 Lab 与 CPU 实验里都能看到同方向趋势。论文结论“97.1% 与 26×”依赖 7B、LIBERO 仿真器和 A100，缩小版不能复现数值，只能复现不等式 $t_{\text{serial}}(H=1)>t_{\text{parallel}}(H=1)$ 以及“必须拆套件”。

相对第 20 课：那里的 flow matching 作用在图像 latent 上，目标是重建像素；本课的连续动作仍用 L1，还没有速度场。不要把 OFT 的 MLP 头叫成 flow。$\pi_0$ 的 94.2% 出现在 OFT 表 I，是为了对照，细节留给第 28 课。相对第 07 课：语音双工的 CONTINUE / PAUSE / REPLAN 与本课“生成 7 个 token 期间收不收新图像”同构，但时钟不同。本课不实现音频路由。相对第 08 课：OpenVLA 固定 224×224，没有动态 tile。把 M-RoPE 和动态切片接到 VLA 上是改造，不是 OpenVLA 复现。

下一课把动作块改成流匹配：不再占用词表尾部逐步分类，从噪声积出 $a\in\mathbb{R}^{H\times d}$。本课交付的 mask 纪律和套件拆桶仍然要用。

## 14. 论文与必读材料
