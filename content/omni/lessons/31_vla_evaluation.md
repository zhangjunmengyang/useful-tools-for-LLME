# 第 31 课：设计可拆层的 VLA 评测

> 类型：VLA 高级，评测协议与统计口径，不改模型结构<br>
> 建议周期：阅读约 70 分钟；浏览器三种协议实验约 10 分钟；CPU 区间实验数分钟<br>
> 硬件：无 GPU 可完成本课阅读、教学模拟与 CPU 机制实验。复现 LIBERO / SIMPLER 论文规模推理需要能加载 7B 级 VLA 的单卡；真机评测另需对应机械臂与固定外参相机<br>
> 产物：一张评测协议卡（套件桶、初始态种子、视觉域、指令、成功谓词、样本量与区间）、三种协议排序记录、Wilson / 正态区间手算<br>
> 独立性：依赖第 27 或第 28 课的 VLA 背景；评测纪律对照 [第 01 课](01_baseline_reproduction.md)。本课不改 MiniMind-O 源码。无 GPU 时不要根据 CPU 数字报告真实成功率

## 1. 仿真成功率为何不能直接当成真机能力

第 24 课把动作接进视觉语言模型，第 27 课把自回归 VLA 跑到能在仿真里出可用成功率，第 28 课用流匹配一次生成一段连续动作，第 29 课把慢规划与快控臂拆成两个时钟，第 30 课把频率、分块和延迟放进控制回路。到这里，系统能在仿真器里抓住杯子、拉开抽屉、把物体放进篮子。于是报告里出现一个很诱人的百分数：LIBERO 平均 97%、真机 80%、SIMPLER 上和真机“相关”。四个数字并排印在一张幻灯片上，听起来像同一把尺子量出来的能力。

它们不是同一把尺子。

仿真成功率是：在某个物理引擎、某套相机、某个 reset 分布、某条成功谓词下，政策在 $N$ 次试验里得到 $k$ 次真。真机成功率是：在真实摩擦、真实曝光、真实桌布、真实人手摆放的物体上，用另一套 $N$ 做同样的计数。SIMPLER 的视觉 gap 测排序一致性：仿真里政策 A 比政策 B 高，这件事能不能在真机上保持。CALVIN 的长程数字测的是五条语言指令能否连着完成，第一步失败后面全部记零。把这四类数字横着减、横着平均、横着写成 SOTA，等于把百米成绩、马拉松成绩、天气预报准确率和跑道风速写进同一列。

类比到此结束。类比失效处：体育成绩至少还共享“时间”这个单位；VLA 评测连单位都不共享。LIBERO 的 1 次成功，是 robosuite 里一组谓词（predicate：关于物体开合、相对位置的逻辑原子，例如 `In(A,B)`）全部为真；CALVIN 的 1 次成功，是桌面状态相对初始帧越过几何阈值；SIMPLER 的 1 次成功，是 Google Robot 或 WidowX 的任务脚本判定抓取或抽屉到位；真机的 1 次成功，常常是实验员按事前写好的量表打勾。四套判定函数不可代数相加。

本课改的是评测协议，不是再训一个 7B 政策。要验证的结果很具体：同一政策在固定初始态、初始态随机、加 distractor（干扰物：场景里多出来的、任务没点名的物体）三种协议上，成功率必须按这个顺序下降；N=25、成功率 0.8 的 Wilson 区间必须算出来给读者看；报告里出现 OpenVLA / OFT / $\pi_0$ 的表内数字时，必须写套件名和是否 fine-tune（在目标套件或目标机器人上继续训练）。浏览器 Lab 和 CPU 实验都是教学夹具，不能代替 LIBERO 的 500 trials，也不能代替一次真机。夹具的通过条件写得很窄：排序对、区间对、谓词能分叉。通过只说明你读懂了协议，不说明桌上的杯子会被抓住。这一点要写进实验记录的第一页，免得以后回看时把 Lab 的 86% 当成模型成绩。

本课术语：

| 术语 | 简要解释 |
|---|---|
| 成功率 | $k/N$：N 次独立试验里判定为成功的比例；没有协议，这个比例没有意义 |
| 套件（task suite） | 一组共享某种分布偏移的任务，例如 LIBERO-Spatial 只改空间关系 |
| 初始态种子 | reset 时物体位姿、机器人关节、抽屉开合的随机源；锁住才能复现同一次试验 |
| 视觉域 | 政策实际看到的像素从哪来：仿真网格、绿幕叠真实背景、还是真机相机 |
| distractor | 任务指令没提到、但会出现在画面里的物体，专门用来拆“见物就抓”的捷径 |
| 成功谓词 | 把一条轨迹判成 0/1 的函数：接触、放入区域、保持若干步是三种不同函数 |
| 点估计 | $\hat p=k/N$，一个数字，不含不确定性 |
| Wilson 区间 | 对二项比例构造的近似置信区间，在 $\hat p$ 靠近 0 或 1、$N$ 较小时比正态近似稳 |
| MMRV | SIMPLER 提出的 Mean Maximum Rank Violation：仿真排错名次时，按真机分差加权 |
| Visual Matching | SIMPLER 缩小视觉 gap 的协议：真实背景绿幕 + 前景纹理对齐 |
| Variant Aggregation | SIMPLER 的另一协议：把视觉随机化后的多个变体成功率聚合起来 |
| fine-tune | 在目标套件或目标机器人的示范上继续训练；和“出厂直接评”不是同一数字 |

## 2. 本课解决的问题

当前课程里的 VLA 叙事到第 30 课为止，默认“政策能跑、数字能报”。缺的是把数字拆开的纪律。[第 01 课](01_baseline_reproduction.md) 已经要求 golden case 分桶、禁止把官方 checkpoint 的评测写成自己训练复现；[第 17 课](17_grpo_rlvr.md) 已经要求在看数据前登记 $\Delta_{\text{test}}$、$\delta_{\min}$ 和置信区间算法。机器人评测把这两条纪律同时放大：试验贵、成功定义有歧义、仿真和真机的像素分布差一个视觉域。

本课因此固定四个可证伪命题：

1. 存在至少两种任务套件（或两种协议），使得同一政策的成功率差超过该样本量下 Wilson 区间半宽，因而“平均成功率”不能代表每一桶。
2. 同一政策在固定初始态上的成功率，严格高于初始态随机，再严格高于加 distractor；排序由协议造成，不由更换权重造成。
3. $N=25$、$\hat p=0.8$ 时，95% Wilson 区间宽度约为 0.30，不能把 0.8 读成“接近解决”。
4. 一份 sim-to-real 声明如果只写仿真成功率、不写视觉域（Visual Matching / Variant Aggregation / 原始仿真网格 / 真机相机），则声明无效。

四条都通过，只能说明评测被写成了可审计协议。它们不能说明 OpenVLA-OFT 的 97.1% 可以搬到你的机械臂，也不能说明 SIMPLER 上 Pearson $r=0.924$ 等于仿真成功率等于真机成功率。

本课明确不解决的问题：不训新的 VLA；不实现 robosuite 或 SAPIEN 仿真器；不比较离散 token 与 flow matching 的生成质量（那是第 25、27、28 课）；不把屏幕点击当成机械臂（那是第 32 课）。本课只引入协议。

和相邻课的边界再钉死一次，避免抢题。第 27 课关心词表、串行步数和 LIBERO 上“能用的”成功率从哪来，本课接管这些数字的读法：76.5% 必须拆套件，97.1% 必须写 fine-tune 和腕部相机。第 28 课关心动作块上的速度场，本课不管积分步数对不对，只问评测时开环执行了几步。第 29 课关心两个时钟，本课把规划失败和动作失败记成不同谓词，不实现双时钟。第 30 课关心延迟大于开环窗会抓空，本课把那种失败记进协议卡的时钟字段，不重做传送带实验。第 01 课和第 17 课提供分桶与预注册区间，本课把它们从文本生成搬到夹爪。

- OpenVLA：[arXiv:2406.09246](https://arxiv.org/abs/2406.09246)，HTML：[arXiv HTML v3](https://arxiv.org/html/2406.09246v3)。7B，970k 真机示范。LIBERO 数字在 Appendix E Table 12，是 fine-tune 之后的。

需要会的前置技能：二项分布的点估计；Python 列表求和；第 01 课“分桶再平均”的口径；第 27 或第 28 课“政策输出动作”的直观含义。不要求会训 7B，不要求有机械臂。

统计直觉只需到这一层：$N$ 次独立抛硬币，正面比例的波动大约是 $\sqrt{p(1-p)/N}$。$p=0.8$、$N=25$ 时约 0.08，乘 1.96 得到半宽 0.16。不必先学 Bootstrap 也能完成本课；若已学第 17 课的分层 Bootstrap，把它留给“两个方法成对比较 $\Delta$”的场合，单方法的 $k/N$ 仍用 Wilson。两种区间不要混在同一格子里。

硬件记录也要分开写。读课文和跑 CPU：笔记本即可。跑 Lab：现代浏览器。复现 LIBERO 500 trials：能加载 OpenVLA 7B 的单卡，推理精度 bfloat16 约 16.8 GB（OpenVLA Table 2），int4 可压到 7.0 GB，Bridge 任务上 int4 与 bfloat16 的成功率在误差条内（71.9% 对 71.3%，80 rollouts / 方法）。那是推理显存事实，不是评测协议。真机：对应机械臂、固定相机、能锁定曝光。没有真机就不要填真机格子。

## 4. 完成后应具备的能力

完成后，拿到任意 VLA 论文的“成功率”列，应能做以下检查：

1. 指出该数字属于四类中的哪一类：LIBERO 套件、SIMPLER 视觉域相关、CALVIN 长程链、真机小样本；拒绝把它们减成一个“提升了 X 个点”。
2. 写出协议卡：套件或任务名、reset 种子是否锁定、相机与纹理是否随机化、指令是否改写、成功谓词是接触、放置还是保持。
3. 对给定 $k$、$N$ 计算 $\hat p$、正态近似区间和 Wilson 区间，并判断区间是否覆盖 0.5。
4. 对照 OpenVLA Table 12：四套件独立 fine-tune，Spatial 84.7%、Object 88.4%、Goal 79.2%、Long 53.7%，宏平均 76.5%。
5. 对照 OpenVLA-OFT Table I：同一 OpenVLA 骨干、OFT fine-tune、加腕部相机后四套件平均 97.1%；表内 $\pi_0$（fine-tuned）为 94.2%。
6. 对照 SIMPLER Table I：Google Robot 上 Visual Matching 平均 Pearson $r=0.924$、MMRV $=0.056$，目标是排序相关，不是 1:1 复制成功率。
7. 对照 CALVIN Fig. 8：MCIL 在 D 到 D、静态 RGB 上短程 53.9%，五步链 0.08%。
8. 在三种协议 Lab 里先提交排序预测，再看数字；把“固定初始态最高、加 distractor 最低”写成协议效应，而不是模型排行榜。
9. 看到 10/10 或 5/5 时先算 Wilson，拒绝宽度为 0 的正态区间。
10. 引用任何公开百分数时，能在 30 秒内指出表号、套件、是否 fine-tune；指不出就从讲稿里删掉该数。

## 5. 原理：边造边讲

八个机制，每个按同一节奏：为什么需要、怎么运转、精确定义、在公开实现里落在哪、怎么证明做对了。本课没有 MiniMind-O 源码可改，代码落点改到 LIBERO / CALVIN / SIMPLER / OpenVLA 评测脚本里那些“判定 0/1 的函数”。

### 5.1 四种不能横着比的数字

为什么需要。VLA 论文喜欢一张总表。总表有阅读价值，也是错误的主要来源：读者会把“仿真高”读成“真机强”，把“平均高”读成“长程也高”，把“和真机相关”读成“仿真成功率可以当真机成功率用”。

怎么运转。先按测量对象分四桶，再决定能不能做差。

| 桶 | 测什么 | 典型数字（必须带出处） | 不能当成什么 |
|---|---|---|---|
| LIBERO 四套件 | 仿真桌面上的空间 / 物体 / 目标 / 长程 | OpenVLA fine-tune：平均 76.5%；OFT fine-tune：平均 97.1% | 真机能力；未经 fine-tune 的出厂能力 |
| SIMPLER 视觉 gap | 仿真排序与真机排序是否一致 | VisMatch 平均 Pearson $r=0.924$ | 某个政策的绝对成功率 |
| CALVIN 长程 | 五条未见指令能否连着完成 | MCIL 短程 53.9%，五步 0.08% | 单步抓取能力；LIBERO-Long 的替代 |
| 真机小样本 | 真实机器人、真实桌子上的 0/1 | OpenVLA Google Robot 每任务 5 次；Bridge 每任务 10 次；OFT ALOHA 每任务 10–24 次 | 仿真 500 trials 的等价物 |

数学。若只关心“两个数字能不能减”，最低条件是：同一任务集合、同一 reset 分布、同一观察、同一成功谓词、同一 $N$ 的数量级。四桶里任意一条不同，差值没有因果解释。更硬的版本是：令政策 $\pi$ 在协议 $\mathcal{P}$ 下的期望成功率为 $p(\pi,\mathcal{P})$。报告必须估计的是 $p(\pi,\mathcal{P})$，不是某个与 $\mathcal{P}$ 无关的“能力标量”$\theta(\pi)$。

验证。拿 OFT Table I 自己做一次横向拒绝：OpenVLA-OFT 在 LIBERO-Long 上 94.5%（fine-tune，500 trials/套件），$\pi_0$（fine-tuned）在 LIBERO-Long 上 85.2%，$\pi_0+$FAST（fine-tuned）在 LIBERO-Long 上 60.2%。三个数字可以在“同一张 LIBERO 表、都写了 fine-tune”的前提下比较排序；它们仍然不能和 OFT 在 ALOHA 上“平均高 15 个绝对点”那句话相减，因为那是真机、双臂、25 Hz、另一套量表。

### 5.2 任务套件拆桶

为什么需要。LIBERO 原文（Liu et al., 2023）不是为“报一个 VLA 平均成功率”设计的。它要回答终身学习里不同类型的知识能不能迁：空间关系、物体概念、任务目标，以及三者缠在一起。后来的 OpenVLA / OFT 把它改成四套件上的行为克隆评测。这个改用途是合法的，前提是你还按套件拆，而不是只报宏平均。

怎么运转。四个套件的构造在 LIBERO §4.2：

- LIBERO-Spatial：10 个任务。物体集合相同，要放的碗相对其他物体的空间关系不同。测的是陈述性空间知识。
- LIBERO-Object：10 个任务。场景布局类似，要抓的物体换了。测的是物体概念。
- LIBERO-Goal：10 个任务。物体和布局固定，语言目标换了。测的是程序性动作知识。
- LIBERO-100 拆成 LIBERO-90（预训练用）和 LIBERO-Long（10 个长程任务）。OpenVLA 附录把 LIBERO-Long 也叫 LIBERO-10。

每个任务配 50 条人类遥操作示范。原文用行为克隆训练单任务政策，再跑终身学习算法。OpenVLA Appendix E 改成：每个套件独立 LoRA fine-tune，第三视角图像，滤掉失败示范和近零动作，每套件 500 trials、三个随机种子。

数学。套件 $s$ 的成功率

$$
\hat p_s=\frac{1}{|\mathcal{T}_s|N}\sum_{t\in\mathcal{T}_s}\sum_{i=1}^{N}\mathbf{1}[\text{success}(\pi,t,i)]
$$

宏平均 $\bar p=\frac{1}{4}\sum_s\hat p_s$。OpenVLA Table 12 的实现里 $|\mathcal{T}_s|=10$、$N=50$，再对 3 个 seed 取平均，所以每个格子背后是 1500 次试验。宏平均把 Long 的 53.7% 和 Object 的 88.4% 兑成 76.5%。差 30 个点的两桶，兑完看起来像“还不错”。

代码落点。LIBERO 用 PDDL 描述初始分布 $\mu_0$ 和目标 $g$。目标是谓词合取：`Open(X)`、`TurnOff(X)`、`On(A,B)`、`In(A,B)`。仿真在所有谓词为真时终止。OpenVLA 评测没有改这套谓词，改的是训练数据过滤：Spatial 500 条里去掉 68 条失败示范，Object 46，Goal 72，Long 121。引用 76.5% 时，这是“fine-tune + 过滤失败示范 + 只看第三视角”之后的数字。

验证。CPU 实验把 Table 12 四个点写成夹具：宏平均必须等于 0.765，Spatial 减 Long 必须大于 0.3。只要你只报 76.5%，检查失败。OFT Table I 把同一拆法用在更强的 fine-tune 配方上：OpenVLA（fine-tuned）仍是 84.7 / 88.4 / 79.2 / 53.7；加上并行解码和动作块之后 Long 从 53.7% 升到 86.5%；再加连续 L1 到 90.7%；再加腕部相机到 94.5%。平均从 76.5% 走到 97.1%，主要贡献之一是 Long 被动作块救起来。若只报 97.1%，读者看不见这件事。

套件拆桶还有一层“排序”信息，OpenVLA Table 12 专门报了 Rank。Diffusion Policy 在 Object 上排第 1（92.5%），在 Spatial / Goal / Long 上排第 3。OpenVLA fine-tune 在 Spatial 和 Long 上排第 1，在 Object 上排第 2。平均成功率 OpenVLA 76.5% 对 Diffusion 72.4%，差距不大；平均排名 1.5 对 2.5，差距更清楚。作者写明：平均排名比未归一化的平均成功率更适合选默认方法，因为套件难度不同。本课沿用这条：跨套件比较方法时，同时报每桶排名。只报平均，等于让最容易的 Object 桶替 Long 说话。

LIBERO 原文的终身学习指标是 FWT、NBT、AUC，不是单次 BC 成功率。VLA 论文改用途之后，FWT 那些格子被丢掉了。这不一定错，但必须声明“我们评的是套件内模仿，不是持续学习”。若有人把 OpenVLA 的 76.5% 写进“终身学习 SOTA”，那是张冠李戴：权重在每个套件上独立 fine-tune，根本没有跨任务的遗忘曲线。

### 5.3 初始状态种子

为什么需要。示范教的是“从这些摆放开始怎么做”。评测如果总从示范里见过的那几个位姿 reset，政策可以背住一条轨迹，不必看当前杯子在哪。CALVIN 把这个问题写成协议：长程评测把机器人复位到中性姿态，切断“初始姿态暗示任务”的相关。LIBERO 每个任务有自己的 $\mu_0$。真机实验如果每次都把杯子放回胶带画的圈，报出来的是固定初始态协议。

怎么运转。一次试验的生成过程是：抽种子 $s$，从 $\mu_0$ 采样物体位姿 $x_0$，政策从 $x_0$ 开始 rollout。固定初始态协议把 $s$ 锁成示范种子或评测集里的少数几个；随机初始态协议在允许范围内重采样。Lab 里的“随机半径”就是 $\mu_0$ 的支撑大小。

数学。令 $p(x_0)$ 为 reset 分布。固定协议估计的是 $p(\pi\mid x_0=x^\star)$，随机协议估计的是 $\mathbb{E}_{x_0\sim p}[p(\pi\mid x_0)]$。由全期望公式，后者是前者在 $x_0$ 上的平均。若政策在 $x^\star$ 上过拟合，两个量可以差出几十个点，而权重完全相同。

代码落点。CALVIN 的 MTLC 把仿真器 reset 到一条未见示范的第一帧，以保证指令在该状态下可行，每任务 10 次不同起始态。LH-MTLC 另外把机器人复位到中性位置，并过滤不可行、循环、相似的五步链，得到 1000 条唯一指令链。LIBERO 的 $\mu_0$ 写在 PDDL 里，包含物体类别、摆放和初始开合。SIMPLER 为了和真机配对，还要把仿真相机位姿调到与真机初始夹爪、桌沿对齐。

验证。Lab 夹具冻结政策，只改 reset。固定初始态的成功次数必须严格多于随机初始态。若你把半径旋到最小仍看不到差距，夹具失败。真实评测里，若论文没写 reset 是锁种子还是重采样，该成功率不可复现，也不可与另一篇比。

### 5.4 相机、纹理与视觉域

为什么需要。政策吃的是像素。仿真网格的桌布、灯光、金属臂反光，和真实实验室不是一个分布。SIMPLER 把这件事命名为 real-to-sim visual gap（真机到仿真的视觉差距：同一政策在仿真观察和真机观察下行为不一致）。他们的关键判断是：仿真不必是数字孪生，只要相对排序和真机相关。

怎么运转。SIMPLER 给了两条路。

Visual Matching。用真机评测视频的第一帧，抠掉机器人和前景物体，得到背景 $I_{\text{real}}$；仿真里用分割掩码 $M$ 取出可交互前景 $I_{\text{sim}}$；合成观察

$$
I'=M\odot I_{\text{sim}}+(1-M)\odot I_{\text{real}}
$$

对纹理差距大的物体，把真实纹理投影回仿真网格；对机械臂，从真实视频取若干颜色再平均，减轻运动中反光变化。Table III 的消融写得很绝：只调抽屉、只调手臂、只做绿幕，MMRV 都不下降；绿幕、抽屉、手臂一起做，MMRV 从 0.087 降到 0.050，真机-仿真成功率差从 0.272 降到 0.136。视觉域必须整场一致，不能只修一半。

Variant Aggregation。不缩小 gap，而把背景、灯光、桌布、干扰物随机化成多个变体，再把成功率聚合。灵感来自 domain randomization，但用在评测端：用一簇仿真域去逼近“真机可能的变化”。

数学。SIMPLER 要的不是 $R_{\mathcal{S}}\approx R_{\text{real}}$，而是 $\mathrm{corr}(R_{\mathcal{S}},R_{\text{real}})$ 高，以及 MMRV 低。Pearson $r$ 只看线性相关；政策挤在很窄的真机分数带里时，$r$ 会被噪声打飞。MMRV 把排错名次的代价写成真机分差：

$$
\mathrm{RankViolation}(i,j)=|R_i-R_j|\cdot\mathbf{1}[(R_{\mathcal{S},i}<R_{\mathcal{S},j})\neq(R_i<R_j)]
$$

$$
\mathrm{MMRV}(R,R_{\mathcal{S}})=\frac{1}{N}\sum_{i=1}^{N}\max_j\mathrm{RankViolation}(i,j)
$$

代码落点。SIMPLER 开源环境覆盖 Google Robot（RT 系列）和 WidowX BridgeData V2，Gym 接口，SAPIEN 默认，Isaac Sim 可复现。Google Robot 仿真结果对四种手臂/夹爪颜色取平均；WidowX 手臂一直是黑色，跳过这一步。Octo 的扩散头非确定性，仿真成功率对三个 seed 取平均。

验证。Table I：六个开源 checkpoint 在 Google Robot 三组任务上，用 validation MSE 排序的平均 Pearson $r$ 只有 0.308、MMRV 0.375；VarAgg 把 $r$ 抬到 0.778；VisMatch 到 0.924，MMRV 0.056。Pick Coke Can 上 VisMatch 的 $r=0.976$，Drawer 上 0.942，Move Near 上 0.855。论文还测了分布偏移：相机位姿和桌布纹理对政策伤害大，灯光和 distractor 相对小；实心新桌色平均掉 4%，带图案的新桌布掉 25%，仿真里对应是 2% 和 24%。Octo-Base 对仿真手臂纹理敏感（Visual Matching 下未调手臂 0%，调了一种到 29.3%），真机用包装纸改手臂颜色后同一趋势还在。这些数字全部绑定视觉域描述。缺视觉域的 sim-to-real 句，本课视为未完成声明。

WidowX / BridgeData V2 是第二条机体。SIMPLER Fig. 5 写：除一个任务外，政策排序都被仿真排对；MMRV 与 $r$ 按任务估计再平均。Google Robot 和 WidowX 不能混成一个“SIMPLER 成功率”。机体不同、相机不同、任务不同，只共享“配对仿真”这个方法。OpenVLA 出厂评测也是两条机体分开报，摘要的 +16.5% 是 29 任务上的绝对成功率差，仍然要回到 Fig. 2 / Fig. 3 看 WidowX 与 Google Robot 各自的柱。WidowX 上 OpenVLA 明显超过 RT-2-X，Google Robot 上两者接近；语义泛化那一桶 RT-2-X 更高，作者归因于更大规模的互联网共训。拆桶之后，“7B 打败 55B”这句话只在部分桶成立。本课要求引用 +16.5% 时写“29 任务、WidowX+Google Robot、出厂、相对 RT-2-X”。缺机体名，就和缺套件名一样，数字停用。

物理参数 gap 的敏感性在 SIMPLER §VI-D：可乐罐质量和夹爪摩擦、抽屉关节摩擦在合理范围内变动，成功率可有不超过 15% 的移动，但 MMRV 仍低、$r$ 仍高。作者据此认为：对刚体操作，物理参数不必精确到数字孪生，视觉域和控制域更关键。这条结论有边界：Limitations 写明当前环境以刚体为主，软体、阴影、运动相机上的绿幕都不成立。把 SIMPLER 的 $r=0.924$ 写成“仿真已经等于真机”，越出了作者自己划的刚体操作边界。

控制 gap 是另一轴。SIMPLER 用离线示范轨迹做系统辨识，调仿真 PD 参数，让开环回放的末端轨迹贴住真机。Table II：SysID 后控制损失 0.131、MMRV 0.031；乱设刚度则 MMRV 升到 0.07–0.10。视觉域和动力学域要一起写，不能只说“我们用了仿真”。

### 5.5 语言指令改写

为什么需要。第 23 课已经证明：答对选择题不等于看见了位置。VLA 上的对应物是：场景已经唯一决定任务时，改错指令动作仍不变。LIBERO-Goal 和机理研究里的 `libero_goal` 就是专门给“必须读指令”留的桶。CALVIN 测试指令不在训练集里，是同一任务的未见说法。

怎么运转。评测指令集合 $\mathcal{L}_{\text{test}}$ 与训练指令集合 $\mathcal{L}_{\text{train}}$ 的关系要写进协议：

- 原句重放：$\mathcal{L}_{\text{test}}=\mathcal{L}_{\text{train}}$，测的是记忆。
- 改写：同任务、近义句，测的是语言接地。
- 目标替换：物体和布局不变、动词或宾语变了，测的是 LIBERO-Goal 那种程序性跟随。
- 空指令 / 错指令：负对照。若成功率几乎不变，政策在走视觉捷径。

CALVIN 用 MiniLM 把句子编成 384 维向量，词表 30522；crowd-sourced 指令 400 余条覆盖 34 个任务，但只标注了约 1% 的交互数据。测试句是未见措辞。Fig. 4 给出同任务的多种说法，例如 open drawer 对应 “grasp the handle of the drawer and open it” 和 “go open the drawer”。

数学。令 $p(\pi\mid \ell,x_0)$ 为指令 $\ell$ 下的成功概率。语言敏感度可以写成

$$
\Delta_{\text{lang}}=\mathbb{E}[p(\pi\mid \ell_{\text{true}},x_0)-p(\pi\mid \ell_{\text{wrong}},x_0)]
$$

$\Delta_{\text{lang}}\approx 0$ 且场景多目标时，政策没有用语言；$\Delta_{\text{lang}}\approx 0$ 且场景只有一个可抓物体时，测不到语言，那是任务设计的问题，不要写成“模型不需要语言”。OFT 在 ALOHA 上用 FiLM 加强语言：去掉 FiLM 后，两个依赖语言的任务上跟随率掉到 33%，等于在三个选项里随机选。这条消融说明：同一套动作头，语言通道可以被视觉捷径短路。

验证。写协议卡时必须填：测试指令是否在训练集出现过；有没有错指令对照；多目标场景里改宾语是否改变抓取对象。CALVIN 还观察到政策有时能做积木操作，但分不清红蓝——MiniLM 把含 red / blue 的句子嵌得很近。语言编码器本身会制造评测噪声，这也要记。

语言评测还有一种假阴性：任务场景里只有一个可操作物体，改错指令也无法失败，因为政策没有第二种合法动作。LIBERO-Object 在同一布局里换物体，就是为了避免这种假阴性。LIBERO-Goal 在同一物体布局里换目标，测的是动词和技能，不是识物。把 Object 上的高分解释成“语言很好”，会和 Goal 上的掉点打架。OFT Table I 里 OpenVLA-OFT 的 Object 98.4%、Goal 97.9%，两者都高，这时才有资格说语言和识物都过关；OpenVLA fine-tune 的 Object 88.4%、Goal 79.2%，Goal 更差，说明“会认物体”不等于“会听动词”。拆桶的用处就是把这两句话分开写。

指令改写的工作量也要记账。CALVIN 用程序化状态检测给 1% 的交互窗口打语言标，其余窗口只有目标图像条件。MCIL 能从大量无语言 play 里学控制，再靠少量成对句子迁移。评测却几乎全是语言条件。训练时语言稀疏、测试时语言密集，这是另一条分布偏移。协议卡的“语言”格要写训练标注比例。1% 和 100% 不是同一协议。OFT 引用 MDT 时特意并列了 2% 语言标注和 100% 语言标注两行：Spatial 从 78.5% 到 95.2%，Object 从 87.5% 到 97.8%。语言监督密度会改数字。引用 MDT 必须写标注比例，否则两行会被兑成一个“MDT 大约 90%”。

### 5.6 成功定义：接触、放置、保持

为什么需要。“成功”看起来像 0/1，其实是函数选择。接触一下杯子、把杯子放进圈、放进圈后夹爪松开并保持两秒，三条轨迹的物理意义不同，对政策的要求也不同。把接触当放置，成功率会虚高；把保持当接触，成功率会虚低。两者都不是“模型变了”。

怎么运转。CALVIN Fig. 6 把 34 个任务的判定写成几何阈值，本课只摘几条，说明谓词有多具体：

- 积木旋转：绕 z 轴转过 60°，且绕 x/y 不超过 30°。
- 积木平移：向左或向右移动超过 10 cm，两帧都保持桌面接触。
- 滑门：至少移动 12 cm。
- 抽屉：推进或拉出至少 10 cm。
- 从桌面举起：夹爪先不接触物体，再举到至少 5 cm。
- 放入滑柜/抽屉：第一帧物体必须被夹爪提起。
- 推入抽屉：第一帧物体接触桌面。
- 堆叠：最终帧积木不得与夹爪接触。
- 灯：开关拨到对应位置。

LIBERO 用谓词合取，仿真器在全部为真时结束。真机实验常用人工量表：OFT 在 ALOHA 上“用预定量表给部分完成打分”，衣服折叠、舀配料、放进锅是不同栏目。部分分和 0/1 成功率又不是一个量。

数学。三条谓词：

$$
S_{\text{contact}}=\mathbf{1}[\min_t d(g_t,o_t)\le \tau_{\text{touch}}]
$$

$$
S_{\text{place}}=\mathbf{1}[\lVert x_T-x^\star\rVert\le r\ \wedge\ \text{gripper open}]
$$

$$
S_{\text{hold}}=\mathbf{1}\Big[\sum_{t=T-H}^{T}S_{\text{place}}(t)\ge H\Big]
$$

一般有 $S_{\text{hold}}\Rightarrow S_{\text{place}}\Rightarrow S_{\text{contact}}$ 不成立的方向：接触不必放置，放置不必保持。CPU 夹具构造一条“碰到了但没放到圈里、夹爪也没张开”的轨迹：接触为真，放置与保持为假。真机上对应的典型录像是：夹爪碰到杯子沿，杯子移动了两厘米，任务员已经伸手去扶。若谓词只检测接触，这次会记成功，而杯子并不在盘子上。OFT 在 ALOHA 上改用部分完成量表，就是承认 0/1 装不下折叠衣服这种多步接触。部分分和 0/1 必须分列：不要把 70% 的量表分换算成 70% 的成功率再去和 LIBERO 的 97.1% 比。量表分的分母是栏目条数，成功率的分母是试验次数，单位又一次不同。

验证。协议卡上的成功定义必须能用代码或几何阈值复述。若论文只写“success rate”而不写阈值、是否要求松开夹爪、是否要求保持，该列数字不可与另一篇比。CALVIN 的长程协议还规定：当前子任务按环境状态指示器成功后，才把政策条件切到下一句指令。第一步失败，后面四步根本没有机会，五步成功率会接近 0。这是组合失败，不是每一步都只有 0.08% 的独立成功率。

### 5.7 样本量与置信区间

为什么需要。真机一次试验要几分钟到十几分钟，还要人重置桌子。于是 $N$ 经常是 5、10、25。仿真可以跑 500。把 20/25=80% 和 400/500=80% 写成同样的 80%，是本课最具体的统计错误。

怎么运转。一次试验的成功与否建模为 Bernoulli($p$)，$N$ 次独立试验 $k\sim\mathrm{Binomial}(N,p)$，点估计 $\hat p=k/N$。95% 区间常用两种。

正态近似（Wald）：

$$
\hat p\pm z_{1-\alpha/2}\sqrt{\frac{\hat p(1-\hat p)}{N}}
$$

其中 $z_{0.975}=1.96$。它在 $\hat p$ 靠近 0 或 1、或 $N$ 很小时会给出宽度为 0 的假精确，或越出 $[0,1]$。

Wilson 区间：

$$
\frac{\hat p+\frac{z^{2}}{2N}\pm z\sqrt{\frac{\hat p(1-\hat p)}{N}+\frac{z^{2}}{4N^{2}}}}{1+\frac{z^{2}}{N}}
$$

它把 $z^{2}/N$ 收进中心和宽度，区间落在 $(0,1)$ 内（再裁到端点），对小样本更诚实。

亲手算一遍本课指定的例子。$N=25$，$k=20$，$\hat p=0.8$，$z=1.96$，$z^{2}=3.8416$。

正态：标准误 $\sqrt{0.8\times 0.2/25}=\sqrt{0.0064}=0.08$，半宽 $1.96\times 0.08=0.1568$，区间

$$
[0.6432,\ 0.9568]
$$

宽度 0.3136。下界已经掉到 64%。

Wilson：分母 $1+3.8416/25=1.153664$。中心 $(0.8+3.8416/50)/1.153664=0.876832/1.153664=0.760041$。根号内 $0.0064+3.8416/(4\times 625)=0.00793664$，平方根 $0.089088$。半宽 $1.96\times 0.089088/1.153664=0.151354$。区间

$$
[0.608687,\ 0.911395]
$$

宽度 0.3027。下界大约 61%，上界大约 91%。两个区间都不覆盖 0.5，所以“明显好于抛硬币”在 $N=25$、$\hat p=0.8$ 时还站得住；但“80% 接近解决”完全站不住，因为区间跨过三十个百分点。

对照小样本。$N=5$，$k=4$，$\hat p=0.8$。Wilson $[0.375528,\ 0.963777]$，覆盖 0.5；正态 $[0.449385,\ 1.150615]$，越出 1 并且也覆盖 0.5。五次里成功四次，什么结论都不要下，包括“比随机好”。$N=3$，$k=2$ 同样覆盖 0.5。$N=10$、$k=10$：正态区间宽度恰好是 0，看上去像“100% 已证明”；Wilson 是 $[0.72246,\ 1.0]$，宽度 0.28。十次全成功，只能说明真 $p$ 大概不低于七成，不能写成解决了任务。

[第 17 课](17_grpo_rlvr.md) 用成对分层 bootstrap 给 $\Delta_{\text{test}}$ 做区间，并且要求开训前登记算法。本课的二项 Wilson 是同一纪律的最小版本：评测开始前登记 $N$、区间公式、覆盖概率；看过 $k$ 之后不许改公式。真机若每任务 5 次，标准误本身就有 $\sqrt{p(1-p)/5}$，在 $p=0.5$ 时约为 0.22，两次政策差 10 个点，多数时候是噪声。

代码落点。CPU 实验把上述序列写成夹具，核对手算到 $10^{-6}$。OpenVLA 真机：BridgeData V2 17 个任务 × 10 trials = 170 次/方法；Google Robot 12 个任务 × 5 trials = 60 次/方法。OFT 的 LIBERO 格子是 10 任务 × 50 episodes = 500 次/套件。OFT 的 ALOHA：fold shorts 10，fold shirt 10，scoop 12，put into pot 24。同一篇论文内部，$N$ 已经差一个数量级。跨论文比百分数，必须先比 $N$。

验证。出现以下任一情况，报告里的成功率只能当点估计草稿，不能当结论：

- 只给 $\hat p$，不给 $N$ 和 $k$；
- $N\le 10$ 却宣称优于另一政策，而两者 Wilson 区间重叠；
- $10/10$ 写成 100% 能力；
- 用仿真 500 次的区间宽度去解释真机 10 次的点估计差。

### 5.8 sim-to-real 声明必须带视觉域

为什么需要。SIMPLER 摘要写得很克制：仿真评测可以成为可扩展、可复现、可靠的代理，目标不是完全取代真机。正文 III-A 再写一次：目标是相对表现的相关，若真机上 A 优于 B，仿真里也要保持。缺了视觉域，这句话无法审计——你不知道政策看到的是网格桌布、绿幕真背景，还是随机化后的一簇变体。

怎么运转。一份合格声明至少包含：

1. 仿真器与资产来源（SAPIEN / Isaac，URDF，物体网格）。
2. 视觉协议：原始仿真、Visual Matching、Variant Aggregation，或“未对齐”。
3. 控制协议：是否做了 PD 系统辨识，开环回放误差多大。
4. 配对方式：哪些政策在真机和仿真上用了同一组任务和初始条件。
5. 相关指标：Pearson $r$ 与 MMRV，按任务报，再平均。
6. 失败模式：哪些分布偏移仿真能预测（相机、桌布），哪些不能（软体、阴影，SIMPLER Limitations 已承认绿幕不处理运动相机和阴影）。

数学。给定政策集合 $\{\pi_i\}$，声明的是

$$
\mathrm{MMRV}(R,R_{\mathcal{S}})\le \varepsilon,\quad r(R,R_{\mathcal{S}})\ge \rho
$$

而不是 $R_{\mathcal{S},i}=R_i$。$\varepsilon$ 和 $\rho$ 要事前写。SIMPLER Table I 提供的经验锚是：VisMatch 平均 $r=0.924$、MMRV $=0.056$；validation MSE 的 $r=0.308$ 不能当仿真评测。

验证。本课验收把“只报仿真成功率、声称已经 sim-to-real”判失败。正确写法示例：“在 SIMPLER Visual Matching、Google Robot Pick Coke Can 上，六个 checkpoint 的仿真排序与真机排序 Pearson $r=0.976$（Table I）。该数字不表示仿真成功率等于真机成功率。”错误写法示例：“SIMPLER 80%，因此真机约 80%。”后一句在 SIMPLER 论文自己的目标函数下就不成立。

### 5.9 一张填满的协议卡：把杯子放到盘子上

把前八个机制收成一张能直接贴进实验记录的卡。下面这张卡是教学填写，数字来自公开表或本课夹具，格子里写“未公开”的，禁止补编。

**任务。** 语言指令：`put the cup on the plate`。物体：一个杯子、一个盘子，可选 distractor（瓶子、勺子）。机体：单臂平行夹爪，末端 6D 加夹爪 1 维。

**套件桶。** 若在 LIBERO 里找近邻，它更接近 LIBERO-Object（杯子是哪个）和 LIBERO-Spatial（杯子相对盘子）的混合，不是 LIBERO-Goal（同一桌面换动词）。因此不能把 LIBERO-Goal 的分数当成这个任务的代理。若任务再要求“先拉开抽屉再放杯子”，它开始接近 LIBERO-Long 和 CALVIN 五步链，平均分数更不能用。

**初始态。** 三种协议写成三行，不许合成一行。

| 协议 | reset | 政策权重 | 本课 Lab 夹具角色 |
|---|---|---|---|
| 固定初始态 | 杯子、盘子、关节锁在示范种子 | 冻结 | 上界：允许背轨迹 |
| 初始态随机 | 杯子在半径 $r$ 的圆盘内均匀采样 | 同一冻结权重 | 关掉“背这一摆” |
| 加 distractor | 随机初始态 + $m$ 个未点名物体 | 同一冻结权重 | 再关掉“见物就抓” |

Lab 的夹具保证三行成功率严格递减。真实实验室如果做不到随机摆放，必须在卡上写“仅固定初始态”，并放弃与随机协议论文比高低。

**视觉域。** 四选一，打勾：

1. 原始仿真网格（LIBERO / CALVIN 默认）。
2. SIMPLER Visual Matching：绿幕 $I'=M\odot I_{\text{sim}}+(1-M)\odot I_{\text{real}}$，物体与手臂纹理对齐。
3. SIMPLER Variant Aggregation：背景、灯光、桌布、干扰物多变体再聚合。
4. 真机相机，外参与内参加入记录，曝光与白平衡写入配置 hash。

SIMPLER 在 Google Robot 上 VisMatch 平均 Pearson $r=0.924$，VarAgg 0.778，validation MSE 0.308。选 1 却引用选 2 的 $r$，声明作废。相机位姿和带图案桌布是已知的强偏移：真机上实心新桌色平均掉 4%、图案桌布掉 25%，仿真里 2% 与 24%。协议卡要写清评测时桌布有没有换。

**语言。** 至少准备三句：训练原句、近义改写（`place the mug onto the dish`）、错宾语（`put the bottle on the plate`）。多目标场景里，错宾语必须改变抓取对象，否则语言通道被视觉捷径短路。OFT 在 ALOHA 上去掉 FiLM 之后，两个依赖语言的任务跟随率掉到 33%，等于三个选项随机选。这句话只能写在“语言通道消融”格，不能写进“动作质量”。

**成功谓词。** 三条开关默认全开才记 1，并分别记三个率：

- 接触：夹爪与杯子表面距离 $\le \tau_{\text{touch}}$。
- 放置：杯子中心进入盘子上方半径 $r$ 的圆柱，且夹爪张开。
- 保持：放置条件在最后 $H$ 步持续为真（教学默认 $H=20$ 步）。

CALVIN 对“放入抽屉”要求第一帧物体已被夹起，对“推入抽屉”要求第一帧接触桌面。同是“进抽屉”，谓词不同。CPU 夹具里有一条只满足接触的轨迹，放置与保持为假。若你的日志把这条记成成功，谓词写错了。

**样本量。** 仿真：每协议至少 50 次，能到 500 更好，与 OpenVLA / OFT 的 LIBERO 格子对齐。真机：每协议写清 $N$，本课教学口径 $N=25$。对 $k=20$ 必须同时报点估计 0.8、Wilson $[0.609,0.911]$、正态 $[0.643,0.957]$。$N=5$ 时即使 4 次成功，Wilson 仍覆盖 0.5，结论栏留空。$N=10$ 且 10 次全成功，只许写 Wilson 下界约 0.72，不许写“已解决”。

**禁止事项（印在卡脚）：** 不把本任务的固定初始态成功率与 LIBERO 四套件平均横比；不把 SIMPLER 的 $r$ 填进成功率格；不把 CALVIN 五步链的 0.08% 与单步放置平均；不把 Lab 夹具数字标成 SOTA。

### 5.11 试验独立性、伪重复和区间假设

Wilson 公式默认 $N$ 次试验独立同分布。机器人评测里这件事经常被悄悄破坏。

同一条示范的 reset 连续跑十遍，桌子没变、光照没变、随机种子几乎没变，得到的 10 个 0/1 高度相关。有效样本量接近 1，不是 10。区间会假窄。协议卡要写：每次 reset 是否重采样物体位姿；真机是否由人重新摆放；仿真是否推进了随机源。Lab 的固定初始态协议故意制造相关：它就是“同一摆放重复 $N$ 次”。那个 0.86 的点估计描述的是条件成功概率 $p(\pi\mid x_0=x^\star)$，Wilson 仍按独立公式去画，只为了让你看见 $N$ 的影响，不能拿去当无条件 $p(\pi)$ 的区间。随机初始态协议才更接近公式假设。

真机还有操作员相关：同一个人摆杯子会越摆越标准，后面几次成功率上升，不是政策变好。预注册“每人每任务摆放次数上限”和“试验顺序随机化”。OpenVLA 写明 A/B 评测、同一组初始状态，就是为了挡住操作员漂移。若你的真机评测没有 A/B，两个方法的差可能来自下午的桌子比上午整齐。

伪重复的另一种形式是：把一条长程链的五个子任务拆开平均。CALVIN 的 LH-MTLC 规定当前句失败则后面不计。若你改成五句各自独立 reset，测的是短程 MTLC，数字会从 0.08% 跳回 50% 量级，看起来像方法突破。协议卡必须写“链”还是“句”。

区间还有一条边界：政策在评测中途被改了权重、或换了解码温度、或换了动作块长度，样本就不是同一个 $p$。OFT Table II 里扩散变体把测试步数从 50 减到 1，Long 从 91.1% 掉到 0%。把这些格子平均成“扩散政策 80%”，$p$ 已经换了。本课要求：一个格子对应一组冻结的推理超参。

独立同分布被破坏时，Wilson 仍然可以当“若独立会有多宽”的下界警示：相关只会让真实不确定度更大。所以 $N=25$ 已经很宽的时候，相关样本下结论更不成立，没有“相关了所以更准”这回事。

### 5.12 错误报告与合格报告对照

下面两段是同一组原始计数写出来的报告。左边不合格，右边合格。原始计数：LIBERO-Long，$k=268$，$N=500$，fine-tune，第三视角；真机放置杯子，$k=20$，$N=25$，固定初始态，无 distractor。

不合格：“我们的模型在操作上达到 80%–90% 成功率，接近 SOTA（LIBERO 97%，真机 80%），已经可以部署。”四个错误叠在一起：把 Long 的 53.6% 藏进从未出现的 97%；把 $N=25$ 的 80% 写成部署门槛；把两种协议兑成一个区间；SOTA 没有对手和套件。

合格：“LIBERO-Long、OpenVLA 式过滤示范、第三视角、本实验室 fine-tune checkpoint，500 trials，点估计 53.6%，Wilson 95% 约 $[0.492,0.579]$（作者未给官方区间，此为二项补算）。真机放置杯子、固定初始态、无 distractor、$N=25$、$k=20$，点估计 0.80，Wilson $[0.609,0.911]$。两者协议不同，不比较高低，也不声称可部署。未测随机初始态和 distractor。未做 SIMPLER 配对，不做 sim-to-real 声明。”

合格稿更长，因为它把缺测的格子写成缺测。评测的诚实度经常表现在空白格的数量，不表现在填满的百分数数量。本课交卷时，空白格必须可见。

把这条对照再落到 OFT 摘要上。摘要可以写 76.5% 到 97.1%，因为它立刻补了“四套件平均”和 fine-tune，并且后文 Table I 把四格摊开。读者侧的纪律是：看到摘要的 97.1% 之后必须翻到 Long 的 94.5% 和观察条件（腕部相机）。只转推摘要一句，等于把协议撕掉。

## 6. 在公开实现中定位这些机制

本课不改 MiniMind-O。机制落在公开基准和 VLA 评测脚本里。行号会变，认函数职责，不背行号。

**LIBERO**（[仓库](https://github.com/Lifelong-Robot-Learning/LIBERO)）。任务生成管道从 Ego4D 抽行为模板，再写 PDDL 的物体、$\mu_0$ 和目标合取。成功判定是仿真器对谓词的校验，不是网络打分。四个套件的任务列表在文档和 `libero/libero/benchmark` 一类目录里按 Spatial / Object / Goal / 100 分开。VLA 论文若把 LIBERO 当独立 fine-tune 的多任务测试，已经不是原文的 ER / EWC / PackNet 终身学习协议；报告里要写“我们用 LIBERO 套件做多任务 BC 评测，不做终身学习”。

**CALVIN**（项目页 [calvin.cs.uni-freiburg.de](http://calvin.cs.uni-freiburg.de)）。环境用 PyBullet，7 自由度 Franka，30 Hz。观察可以是固定相机和夹爪相机的 RGB-D、触觉、本体感受。任务完成按 Fig. 6 的状态差检测，可当稀疏奖励。评测入口把 MTLC 和 LH-MTLC 分开：前者 34 任务 × 10 rollout，后者 1000 条五步链，中性复位。MCIL 基线的表就是 Fig. 8，短程和长程必须分列。

**SIMPLER**（[simpler-env.github.io](https://simpler-env.github.io)）。环境一行 import，Gym 接口。Visual Matching 的绿幕合成、纹理烘焙、SysID 的模拟退火，在论文 §IV 和附录 C。评测脚本对 Google Robot 和 WidowX 分开，RT-1 / RT-1-X / Octo 的推理代码随仓库提供。不要把 SIMPLER 的成功率列直接抄进“我们的方法 SOTA”；仓库的目标函数是配对相关。

**OpenVLA 评测**。真机出厂评测在 WidowX 与 Google Robot，A/B、同一组初始状态。LIBERO 在 Appendix E：重放示范、提高分辨率到 256、旋转 180°（作者硬件上图像颠倒）、过滤 no-op 和失败示范、只用第三视角、每套件独立 LoRA。OFT 在此之上改并行解码、动作块 $K=8$、连续 L1，并可加腕部相机和本体感受。两篇论文的 LIBERO 数字都是 fine-tune，不是 970k OpenX 预训练的零样本。

定位时用一张清单：成功函数返回的是不是 0/1；reset 是否读种子；观察是否经过绿幕；指令字符串从哪张表来；结果是按套件写还是先平均。五项里缺一项，就还没定位到评测，只定位到训练脚本。

读脚本时再核四件具体的事，避免把训练循环误认成评测循环。

1. **试验计数器。** OpenVLA 附录写每套件 500 trials、三个 seed，合计 1500。若你本地跑出来 50 次就停，点估计方差会对不上 Table 12 的标准误（例如 OpenVLA fine-tune 的 Spatial $84.7\pm 0.9\%$）。标准误大约 $0.009$，反推有效样本量与 1500 次二项相符量级。自己复现时先对上 $N$，再对 $\hat p$。
2. **失败示范过滤。** 附录列出 Spatial 去掉 68/500、Object 46、Goal 72、Long 121。过滤发生在训练，评测仍用官方初始构型。若有人用未过滤的 50 条/任务去 fine-tune，不能把结果写进 Table 12 那一行。OFT Table I 把“过滤 / 未过滤”分成上下两块，就是怕这一混。
3. **图像朝向。** OpenVLA 在训练和测试都把第三视角转 180°，因为作者硬件上 LIBERO 图像颠倒。这是视觉域的一部分。换机器若不转，等于给政策送倒立桌子，成功率崩了先查这一行，再查模型。
4. **动作块与开环。** OFT 在 LIBERO 上 $K=8$，整块执行再重规划。Table II 把吞吐从 OpenVLA 的 4.2 Hz 写到加动作块后的 108.8 Hz，Long 从 53.7% 到 86.5%。评测脚本如果逐步重规划、训练却整块执行，协议又裂了。第 30 课管延迟与开环窗，本课只要你在评测卡上写 $K$ 和是否整块执行。

SIMPLER 脚本里另有两处容易漏。Google Robot 要对四种手臂/夹爪颜色平均，漏掉平均等于只评了一种视觉域。Octo 要对三个扩散 seed 平均，漏掉平均等于把采样噪声写进方法差。论文 VI-A 把这两条写成协议，不是实现细节。

CALVIN 的状态指示器按两帧之间的环境状态差判定任务，所以离线数据也能自动打标。评测时 LH-MTLC 只有当前句的指示器变真，才把语言条件切到下一句。若实现成“五句一起喂进去、最后看桌子”，测的就不是论文的五步链。MCIL 基线在 D 到 D 静态 RGB 上五步 0.08%，这个 0.08% 是 1000 条链里大约 1 条走完，不是每一步独立 0.08%。

## 7. 数据与评测 recipe

评测数据不是训练数据。协议卡把它们分开写。

**LIBERO 评测 recipe（OpenVLA / OFT 实际用的，不是终身学习原文）：**

- 套件：Spatial / Object / Goal / Long，各 10 任务。
- 示范：每任务 50 条人类遥操作；OpenVLA 过滤失败条后，四套件分别剩 432、454、428、379 量级（500 减 68/46/72/121）。
- 观察：OpenVLA 主结果只用第三视角；OFT 主结果（97.1% 那一行）加腕部相机，本体感受可选。
- 训练：每个套件独立 fine-tune，不是四个套件一个头平均。
- 试验：每套件 500 次（OFT Table I 说明 10 × 50）；OpenVLA Table 12 再对 3 个 seed 平均。
- 成功：环境谓词，未改 CALVIN 那种几何阈值列表，但也不等于“接触即可”。

**CALVIN 评测 recipe：**

- 环境组合：D 到 D；A,B,C,D 到 D；A,B,C 到 D（零样本房间）。
- 传感器组合：静态 RGB 是基线；可加夹爪、深度、触觉。
- 短程：34 任务 × 10，未见指令措辞。
- 长程：1000 条五步链，中性复位，当前句成功才切下一句。
- 数据：约 24 小时 play，约 2.4M 步，语言标注约 1%。

Fig. 8 把传感器和环境组合摊成十二行，本课要求至少抄三行进笔记，避免只记住 53.9% 一个数。静态 RGB、D 到 D：短程 53.9%，五步 0.08%。静态加夹爪 RGB、D 到 D：短程 51.8%，五步仍是 0.08%。静态 RGB-D 加夹爪 RGB-D、D 到 D：短程 46.1%，五步 0。零样本 A,B,C 到 D、静态 RGB：短程 38.6%，五步 0。加传感器没有自动抬长程，零样本房间会压短程。任何“我们用了深度所以更强”的句子，必须能在这张表里找到对应行；找不到就说明那是另一套协议，不能借用 MCIL 基线当对照。

**SIMPLER 评测 recipe：**

- 机体：Google Robot、WidowX。
- 视觉：VisMatch 或 VarAgg，必须二选一写明。
- 控制：SysID 后的 PD。
- 政策：RT-1 不同训练阶段、RT-1-X、RT-2-X、Octo-Base / Small。
- 指标：任务成功率用于画配对图；协议质量用 MMRV 和 Pearson $r$。

**真机 recipe（只能按论文写到的做）：**

- OpenVLA 出厂：WidowX 170 rollouts / 方法，Google Robot 60 rollouts / 方法。
- OpenVLA fine-tune：Franka-Tabletop 与 Franka-DROID，示范 10–150 条，比较 Diffusion Policy 从头训与 Octo fine-tune。
- OFT ALOHA：25 Hz，四任务，试验次数 10 / 10 / 12 / 24，量表含部分分；和 $\pi_0$、RDT-1B 的比较明确写了“用各自默认 recipe fine-tune”。
- $\pi_0$ 原论文：预训练约 10,000 小时机器人数据加 OXE，评测含直接提示、人给语言、高层 VLM 语言、以及 fine-tune 新技能；洗衣折叠等真机任务。动作专家约 3 亿参数，骨干 PaliGemma 3B，合计约 3.3B；控制频率写到 50 Hz，积分 10 步。后训练“最简单任务约 5 小时、最复杂 100 小时以上”，和 LIBERO 每任务 50 条示范不是同一预算。LIBERO 四套件不是该文主表；若引用 94.2%，出处是 OFT Table I 的 $\pi_0$（fine-tuned）行。

配比原则：仿真试验可以多，用来拆桶和做消融；真机试验必须少而配对，用来校准排序。不许用仿真 $N$ 的区间去给真机点估计贴上“显著”二字。

训练数据与评测数据的边界再写三条，避免“用评测任务的示范训完再报该任务”。

1. **套件内泄漏。** LIBERO 每套件 10 任务 × 50 条示范。OpenVLA / OFT 是套件内 fine-tune 再在同套件评测，测的是“在这些任务的示范上适配得怎么样”，不是零样本迁移。Table 12 标题写 fine-tuned，摘要里 76.5% 也必须跟着 fine-tune 走。若实验是 9 个任务训练、第 10 个任务评测，那是另一张表，论文没给这个数就不要编。
2. **房间泄漏。** CALVIN 的 A,B,C 到 D 才是零样本房间。D 到 D 是同房间新指令措辞。两者短程可以差十几个点（53.9% 对 38.6%，静态 RGB）。只报较高的那个，等于把零样本格留空。
3. **真机示范泄漏。** OFT 的 put-into-pot 用 300 条训练、24 次评测，其中 12 次分布内、12 次分布外。把 24 次平均成一个数，会把分布外那一半洗掉。协议卡要分两格写。scoop 任务 15 条/配料 × 3 配料，评测 4 次/配料，语言跟随必须按配料拆，不能只报总舀入成功率。

许可与缺失：LIBERO、CALVIN、SIMPLER 的任务资产跟随各自仓库许可证。Open X-Embodiment 各子集许可证不同，第 26 课处理混合，本课评测不重新混合数据。缺原始评测种子文件时，写“无法逐 trial 复现，只能对到套件均值”。不要用自己重新采样的 50 次去“打假”论文的 500 次，除非你先证明 reset 分布与官方相同。

协议卡可以用一份固定字段的 YAML 存档，方便和 checkpoint 一起做 hash。下面是教学模板，值来自“假想的杯子放置、固定初始态、真机、N=25”，不是任何论文结果：

## 8. 按依赖顺序执行实验

本课实验不训练。顺序是：先手算区间，再跑 CPU 夹具，再在浏览器里交排序预测，最后（可选）读论文表核对套件。

### Step 1: 手算 N=25、k=20

用纸或计算器按 5.7 节算出正态 $[0.6432,0.9568]$ 和 Wilson $[0.608687,0.911395]$。把中间量 $z^{2}$、分母、中心、半宽写进笔记。不要先看 CPU 输出再抄。建议按这个顺序写：

1. $N=25$，$k=20$，$\hat p=20/25=0.8$。
2. $z=1.96$，$z^{2}=3.8416$。
3. 正态标准误 $\sqrt{0.16/25}=0.08$，半宽 $0.1568$，区间 $[0.6432,0.9568]$。
4. Wilson 分母 $1+3.8416/25=1.153664$。
5. 中心 $0.876832/1.153664=0.760041$。
6. 根号内 $0.00793664$，平方根 $0.089088$，半宽 $0.151354$。
7. 区间 $[0.608687,0.911395]$，宽度 $0.3027$，不覆盖 0.5。
8. 另算 $N=5$、$k=4$，确认 Wilson 覆盖 0.5。
9. 另算 $N=10$、$k=10$，确认正态宽度为 0、Wilson 下界约 0.72。

九步都写在纸上之后，再进 Step 2 对 CPU。CPU 与手算差过 $5\times 10^{-6}$，先查自己的 $z^{2}$ 有没有四舍五入错，再查代码。本课实验把 $z$ 钉死为 1.96，不用更长的 1.959964。

### Step 2: 跑 CPU 夹具

在 `experiments/` 目录：

```bash
python3 -c "from learn_omni_experiments.lessons.lesson_31 import run; import json; print(json.dumps(run()['checks'], ensure_ascii=False, indent=2))"
```

登记进仓库 runner 之后改用：

```bash
python3 run.py run 31
```

`checks` 必须全为 True。重点看：N=5 覆盖 0.5；N=25 不覆盖 0.5；10/10 的正态宽度为 0；四套件宏平均掩盖 Long；接触与放置在同一轨迹上不一致。

### Step 3: 浏览器三种协议

打开本课 Lab。开始时成功率格子是“待揭晓”。先选排序，建议先写在纸上再点。再调随机半径、distractor 个数、$N$，点“揭晓三种协议”。夹具保证固定初始态最高、加 distractor 最低。勾选“不会把单一成功率标成 SOTA”。把三组 $k/N$ 和 Wilson 区间抄进笔记，观察 $N$ 从 8 拖到 50 时区间如何变窄。

### Step 4: 对照论文表（可选，无 GPU）

打开 OFT Table I 和 OpenVLA Table 12。逐行抄：方法名、是否 scratch / fine-tune、观察是否含腕部相机、是否过滤失败示范、四套件分列、平均。任何一行缺“是否 fine-tune”，从你的对照表里删掉。打开 SIMPLER Table I，抄 VisMatch / VarAgg / MSE 三行的 $r$ 和 MMRV。打开 CALVIN Fig. 8，抄 D 到 D 静态 RGB 的短程和五步。四张表不许合并成一个“SOTA 列”。

### Step 5: 写协议卡

用第 5.9 节与第 9 节的模板填一次“假想的杯子放置评测”。即使你没有机器人，也要填满每个空，把不知道的格子写成“未公开”而不是编一个数。三行协议（固定 / 随机 / distractor）都要有，即使后两行你填“本实验室做不到，故不声称泛化”。

### Step 6: 拒绝一次虚假合并

拿四列数字做一次反面练习，写进笔记后划掉：$(0.971 + 0.924 + 0.539 + 0.80)/4$。这四个输入分别是 OFT 的 LIBERO 平均、SIMPLER 的 Pearson $r$、CALVIN 短程、真机教学口径 0.8。单位不同，平均没有定义。划掉之后，改写成四行独立结论，每行带出处。这一步不算数学，算肌肉记忆：合并欲出现时先问单位。

四行独立结论的最低写法如下，可直接粘贴再填空：

1. LIBERO：方法 ____，fine-tune ____，观察 ____，Spatial/Object/Goal/Long = ____，平均 ____，每套件 $N$ = ____，出处 ____。
2. SIMPLER：机体 ____，视觉协议 ____，Pearson $r$ = ____，MMRV = ____，配对政策名单 ____，出处 ____。此行无政策成功率。
3. CALVIN：方法 ____，环境组合 ____，传感器 ____，MTLC = ____，LH-MTLC 五步 = ____，出处 ____。
4. 真机：机体 ____，任务 ____，是否 fine-tune ____，$N$ = ____，$k$ = ____，$\hat p$ = ____，区间 ____，成功谓词 ____，出处 ____。

四行都填得出，Step 6 才算过。缺行就标明缺测，不要用另一行的数字顶上。

## 9. 评测与测量

主指标不是“平均成功率”，是“带协议的成功率向量”。一次合格报告至少输出：

| 字段 | 例子 |
|---|---|
| 套件或任务 | LIBERO-Long，10 任务 |
| 是否 fine-tune | 是，该套件示范上 LoRA |
| 观察 | 第三视角 + 腕部相机 |
| reset | 官方初始构型，不锁单一示范种子 |
| 视觉域 | 仿真网格（非 SIMPLER VisMatch） |
| 指令 | 套件自带英文，未见改写 |
| 成功谓词 | 环境 `success` 标志 |
| $N$ | 500 / 套件 |
| $k$ 或 $\hat p$ | Long 94.5%（OFT Table I，OpenVLA-OFT） |
| 区间 | 若按二项粗算，Wilson 半宽约 2 个点；论文未报该区间，笔记里标“作者未给” |

辅助指标：

- 套件差：Spatial 减 Long。OpenVLA fine-tune 是 31 个点；OFT 加腕部后是 3.1 个点。差变小说明长程被救，不是平均自己变魔法。
- 协议差：固定初始态减 distractor。Lab 夹具里必须为正。
- 语言差：对指令减错指令。OFT 去 FiLM 后跟随率 33%。
- 相关：SIMPLER 的 $r$ 与 MMRV。只在配对真机-仿真时填写。
- 长程链：CALVIN 的 1/2/3/4/5 步成功率必须分列。MCIL 最好一行是 48.9%、12.9%、2.6%、0.5%、0.08%（D 到 D 静态 RGB 的 LH-MTLC）。

测量时同时记下时钟：控制频率、动作块长度、是否开环执行整块。第 30 课的延迟会改变成功率，但本课不把延迟写进主指标，以免和协议效应缠在一起。若论文的仿真评测用开环块、真机评测用逐步重规划，又多了一层不能横比的理由。

[第 07 课](07_full_duplex_routing.md) 的对照：语音里 `CONTINUE / PAUSE / REPLAN` 是生成中途的控制动作；评测里对应的是“这条试验继续算、作废重来、还是改写指令再跑”。作废重来若不写入协议，实验员会在失败时悄悄再试一次，成功率被人工抬高。本课要求每次 reset 都消耗一个种子，失败就是失败。

把测量结果写成向量时，推荐固定顺序，免得表格列漂移：

$$
\mathbf{m}=(\hat p_{\text{Spatial}},\hat p_{\text{Object}},\hat p_{\text{Goal}},\hat p_{\text{Long}},\hat p_{\text{fixed}},\hat p_{\text{rand}},\hat p_{\text{distract}},r_{\text{VisMatch}},\hat p_{\text{chain-5}})
$$

九个量可以缺测，缺测就留空，不许用平均去填。宏平均若要报，只能作为第十个派生量，并且在脚注写 $\bar p=\frac14\sum_{s}\hat p_s$。SIMPLER 的 $r$ 进不了 $\hat p$ 那几个槽。CALVIN 的五步成功率只进最后一个槽。真机固定初始态进 $\hat p_{\text{fixed}}$，不要覆盖 $\hat p_{\text{Long}}$。

对 $N=500$、$\hat p=0.971$ 这种仿真格子，Wilson 半宽大约 1.5 个点，点估计已经比较稳，拆桶的意义大于报区间。对 $N=25$、$\hat p=0.8$，区间宽度约 30 个点，报区间的意义大于报点估计。两种格子的“主数字”不同：仿真主报套件向量，真机主报点估计加区间。把仿真的稳拿去给真机的点估计当置信，是类型错误。

## 10. 验收条件

协议层（本课交卷）同时满足：

1. CPU `checks` 全为 True，其中必须包含：N=25、k=20 的 Wilson 与手算一致；N=5 覆盖 0.5；N=25 不覆盖 0.5；10/10 正态宽度为 0 且 Wilson 宽度大于 0.2；四套件宏平均掩盖 Long；接触谓词与放置谓词在同一轨迹上不一致。
2. Lab：提交预测；预测为“固定初始态 > 初始态随机 > 加 distractor”；揭晓后该排序成立；勾选非 SOTA 声明。界面不得出现把单一数字标成 SOTA 的导出文案。
3. 笔记里 OpenVLA、OFT、$\pi_0$ 的数字都能指回表号，并写套件名和是否 fine-tune。CALVIN 的 53.9% 必须标短程 MTLC，0.08% 必须标五步链。SIMPLER 的 0.924 必须标 Visual Matching 平均 Pearson $r$，不得写成成功率。
4. 协议卡五个空（套件、种子、视觉域、指令、谓词）无空白。不知道的写“其技术报告未公开该细节”。

出现以下任一情况，不得标记为“评测已诚实”：

- 只报 LIBERO 平均 97.1%，不报四套件，不报 fine-tune；
- 把 SIMPLER 的 $r$ 或 MMRV 当成政策成功率；
- 把 CALVIN 短程 53.9% 和五步 0.08% 平均成一个“CALVIN 分数”；
- 真机 $N\le 10$ 的点估计不带区间，却宣称超过另一方法；
- 用 Lab 或 CPU 数字当作 LIBERO / 真机结果；
- sim-to-real 句不写 Visual Matching 或 Variant Aggregation。

## 11. 根据症状定位失败环节

| 症状 | 先查 | 不要先做 |
|---|---|---|
| 平均很高、一拆套件 Long 很差 | 是否把宏平均当能力；动作块 $H$ 是否太短 | 再堆预训练数据 |
| 固定摆放接近满分、换位置就掉 | reset 是否锁示范种子；视觉是否看当前物体 | 换更大 LLM |
| 加一个瓶子政策去抓瓶子 | 指令是否进入政策；有没有错指令对照 | 把成功率平均进总表 |
| 仿真远高于真机 | 视觉域是不是原始网格；SysID 做了没有 | 宣称已经 sim-to-real |
| 仿真远低于真机 | 绿幕掩码有没有把夹爪切掉；纹理是否只修了物体没修手臂 | 立刻换仿真器 |
| 10/10 写成已解决 | 算 Wilson；看区间下界 | 写进摘要第一句 |
| 两个方法差 8 个点、$N=5$ | 区间是否重叠 | 做 t 检验凑 p 值 |
| 接触率高、任务仍失败 | 谓词是不是只检测碰撞 | 加接触奖励充数 |
| 长程第一步还行、五步接近 0 | 是否在测组合而不是单技能；中性复位有没有切断姿态捷径 | 用 LIBERO-Object 代替 CALVIN |
| 论文数字对不上 Table 12 | 是否用了腕部相机；是否过滤失败示范；是否 3 个 seed | 改成功阈值凑数 |
| OFT 97.1% 被写成 OpenVLA 出厂 | 是否 fine-tune；观察是否第三视角 only | 把 970k OpenX 当作 LIBERO 训练 |

第 01 课的对照：trace 不能改变 logits。本课的对照：改协议必须改变数字，改权重才能叫“政策变了”。若三种协议成功率几乎一样，不是政策鲁棒，是夹具没把捷径关掉，或成功谓词太松（例如任何接触都算成功）。

再补六条现场口令，写进实验值班表：

1. 数字出现时先问“套件、fine-tune、$N$、谓词、视觉域”五件事，答不上来就先不记进总表。
2. 真机失败时拍一张结束帧，标出谓词卡在接触、放置还是保持。没有结束帧的失败，事后无法审计。
3. 仿真崩溃（夹爪插入几何体、物体飞出）单独计 `crash`，不要并进失败。崩溃率突然升高，优先查物理时间步和碰撞网格，再查政策。
4. 改了指令字符串必须改试验 ID，不能在同一 ID 下覆盖。CALVIN 测试句本就不在训练集，覆盖会把未见措辞测没。
5. 换相机后先跑固定初始态协议，确认像素分布变了、成功率变了，再跑随机协议。否则你分不清是相机坏了还是政策差了。
6. 任何“接近 SOTA”的句子，后面必须跟对手名字、套件、是否 fine-tune。缺一项就删句。本课 Lab 的横幅已经把这条印在界面上。

值班表看起来琐碎，它对应的是第 01 课的 golden case：固定输入、固定判定、固定记录。机器人多了物理和视觉两层噪声，记录必须更厚，不是更薄。

交付物的对照表建议用固定列名，避免每人一套缩写：`paper`、`table`、`method`、`finetune`、`suite_or_task`、`n_trials`、`p_hat`、`interval`、`visual_domain`、`success_predicate`。`interval` 作者没给就填 `not_reported`，你自己补算就填 `wilson_posthoc`，两者不要混成“论文区间”。`finetune` 只许 `yes` / `no` / `scratch` / `unknown`，不许留空。`visual_domain` 在 LIBERO 格子填 `raw_sim`，在 SIMPLER 格子填 `vis_match` 或 `var_agg`，在真机格子填 `real_camera`。填完之后按 `suite_or_task` 排序，不要按 `p_hat` 排序——按成功率排序会诱使你把四类数字重新排成一张榜。

下一课看屏幕上的“身体”：点击和机械臂是否共享空间接地。评测纪律原样带走——OSWorld 上的成功率同样要写清任务集、$N$ 和成功定义，仍然不能和 LIBERO 平均横着比。屏幕上一次点击的成功，通常是“落点落在控件框内”；桌面上一次放置的成功，通常是“物体中心进入目标半径并保持”。两者都可以写成二维接地，第 32 课去讨论损失，本课只提醒：控件框命中率和放置保持率的分母、噪声来源、$N$ 都不同，并排画柱状图之前先写两张协议卡。

若你只做完本课、暂时不进第 32 课，停在这里也完整：手里有协议卡、有手算区间、有三种协议的排序记录、有一张不能合并的四列表。这些已经够用来审一篇 VLA 论文的表，也够用来拒绝自己实验记录里的单一百分数。审表时建议按这个 90 秒流程：先找表注里有没有 fine-tune 和 $N$；再看列名是不是套件而不是一个 Average；再看有没有视觉域或机体名；最后自己用 $k$、$N$ 补一条 Wilson，看作者的排序在区间重叠时还站不站得住。90 秒过不了的表，不要进幻灯片。流程本身不产生新数字，只决定哪些数字有资格出现。把这条流程和协议卡钉在一起，本课的交付才算做到可执行，而不是停在“评测很重要”这种空句上。若 90 秒流程里只有 Average 一列，就回到第 5.2 节把 Spatial / Object / Goal / Long 四格补上；若没有 $N$，就回到第 5.7 节把 Wilson 补上；若没有视觉域，就回到第 5.8 节把 VisMatch / VarAgg / raw / real_camera 四选一补上。三处都补得上，表才有资格进对照；任一处补不上，表只能进“未公开细节”附录，不能进主结论。主结论允许出现的句子只有带协议的那种：哪套件、是否 fine-tune、多少次试验、何种谓词、何种视觉域、点估计多少、区间多少。缺字段的句子越短，越像口号，越要删。本课正文按汉字计数落在一万八千以上，篇幅用在机制、公式、协议和文献格子上，就是为了让那句短口号没有落脚处。读完若只能背 97.1% 一个数，等于没读；读完若能指出 97.1% 是 OpenVLA-OFT 在 LIBERO 四套件上 fine-tune、加腕部相机、每套件 500 trials 的宏平均，并且能立刻补上 Long 的 94.5% 和 $\pi_0$ fine-tune 的 94.2%，这课才算落地。三个数来自同一张 OFT Table I，却仍然不能拿去和 SIMPLER 的 0.924 或真机 $N=25$ 的 0.80 做加减。加减之前先问单位：套件成功率、排序相关系数、小样本真机成功率，三套单位碰在一起只会得到没有物理意义的算术。本课从头到尾都在挡这件事。挡住之后，剩下的才是可以拿去复现、拿去打假、拿去写进下一课对照表的格子。

## 13. 前沿对照与改造方向

**公开方案。** 2024–2025 年公开 VLA 把评测拆成至少三条线。规模越大，拆得越开，因为单一百分数已经装不下。OpenVLA 把出厂真机（WidowX / Google Robot，相对 RT-2-X 的 +16.5% 写在 29 个任务上）和 fine-tune 真机（Franka）和仿真 LIBERO（Appendix E）分成三节，没有把 76.5% 写进摘要当出厂能力。OFT 把 LIBERO 和 ALOHA 分成 §V 和 §VI，摘要里 76.5% 到 97.1% 明确是四套件平均且来自 fine-tune，ALOHA 的“最多 15 个绝对点”明确是相对 $\pi_0$、RDT-1B、Diffusion Policy、ACT 的平均任务完成度，试验次数只有 10–24。$\pi_0$ 原论文几乎不靠 LIBERO 说话，主场是真机洗衣、收拾桌子、装箱，以及出厂提示 / 人给语言 / 高层 VLM / fine-tune 四条评测轴。SIMPLER 把“仿真能不能当代理”本身当成研究对象，指标是 $r$ 和 MMRV。CALVIN 把短程与五步链分列，MCIL 基线在长程上接近失败，给后来的方法留了空间。这些方案的共同点是：数字旁边跟着协议。

Qwen2.5-Omni 与 Moshi 的评测拆桶在 [第 01 课](01_baseline_reproduction.md) 前沿节已经对照过：按输入输出模态分，不把听感和 WER 兑成一个 Omni 分数。本课把同一纪律迁到动作：按套件、视觉域、长程深度、$N$ 分，不把仿真和真机兑成一个 VLA 分数。机制相同，对象从 codec 换成夹爪。

[第 17 课](17_grpo_rlvr.md) 的对照是统计预注册：$\Delta_{\text{test}}$ 与 $\delta_{\min}$ 必须在看数据前写入。机器人评测把同一规则用在更贵的试验上。OFT 的 ALOHA 每任务 10–24 次，OpenVLA 的 Google Robot 每任务 5 次，两者都不够支撑“显著优于”这类句子，除非区间或配对检验事先写好。公开论文多数只报点估计，读的人要自己补区间，这是读者侧的纪律，不是作者已经做完的手续。

SIMPLER 还把“用验证集动作 MSE 选 checkpoint”做成负对照：平均 $r=0.308$。模仿学习里 loss 低不等于任务成功，和 [第 01 课](01_baseline_reproduction.md) “loss 能降不等于复现完成”同构。VLA 评测脚本如果只盯动作 L1 或 CE，本课把它归为未完成评测。

**差距。** 规模差：你没有 970k 轨迹，也没有 ALOHA，也没有 SIMPLER 那种配对真机预算。机制差：拆桶、谓词、区间、视觉域声明不依赖模型大小。OpenVLA-OFT 的 97.1% 是规模加配方加观察加过滤示范之后的仿真数；本课夹具用几十次试验就能复现“协议一变排序就变”和“N 太小区间覆盖 0.5”。不能复现的是 97.1% 本身，也不能复现 Pearson $r=0.924$，因为没有配对真机。

机制上可以追上的部分写清楚。套件分列、成功谓词分叉、Wilson 公式、协议卡字段，这些在 CPU 和浏览器里就能验收。规模上追不上的部分也写清楚：500 trials × 4 套件的 GPU 推理、ALOHA 双臂 25 Hz、Google Robot 真机 60 rollouts。报告里把能验收的机制和不能验收的规模分成两段，避免用机制实验的通过去暗示规模数字被复现。

**动手改造清单。**

1. **套件分列回归。** 改动位置：任何把 LIBERO 四套件先平均再写入日志的脚本，改成先写四格再写宏平均。训练预算：0，只跑已有 checkpoint 的评测；若没有 GPU，用本课 CPU 夹具的四个点代替，并在报告标明“夹具不是评测”。预期：Long 明显低于 Object。失败判定：四格与平均的差小于 2 个点，说明日志仍在先平均。
2. **谓词消融。** 改动位置：成功函数，把接触、放置、保持做成三个开关，不改政策。预算：CPU 即可，用录好的轨迹回放。预期：同一批轨迹上接触率最高、保持率最低。失败判定：三开关输出完全相同，说明谓词没有真正分叉。
3. **N 与区间预注册。** 改动位置：评测配置文件，开跑前写入 $N$、Wilson、$z=1.96$；跑完禁止改公式。预算：无训练。预期：$N=25$、$\hat p=0.8$ 时宽度约 0.30；$N=5$ 覆盖 0.5。失败判定：报告只剩点估计，或 $N$ 是看过结果后改的。
4. **视觉域标注。** 改动位置：仿真观察预处理，显式分支 raw / vis-match / var-agg，日志里写分支名。预算：若无 SIMPLER 环境，用 Lab 的 distractor 开关代替“视觉域变了”这一条，并标明教学模拟。预期：分支名出现在每一条成功率旁边。失败判定：日志里只有一个百分数，没有视觉域字段。

**顺手复现。** 论文结论“宏平均会掩盖 Long”（OpenVLA Table 12：76.5% vs Long 53.7%）在缩小版里对应 CPU 夹具的 `four_suite_average_hides_long_horizon_drop`，预期同方向。论文结论“小样本区间很宽”对应 N=25 手算，预期同方向。论文结论“10/10 的正态区间是假精确”对应 CPU 的 `perfect_ten_normal_width_is_zero`。论文结论“接触不等于放置”对应 `contact_place_hold_disagree_on_touch_only_trial`。论文结论“仿真相对排序可与真机相关”（SIMPLER $r=0.924$）在本课缩小版里不能复现数值，只能复现纪律：没有配对真机就禁止写 sim-to-real。若有人在 Lab 里看到固定初始态 86% 就写“接近 OFT 的 97.1%”，判失败——两个数字的协议、$N$、政策都不同。

改造实验的失败判定要能被本课夹具触发，避免写成无法执行的愿望。实验 1 用四个固定点就能失败（只报平均）。实验 2 用 CPU 那条只接触的轨迹就能失败（三谓词相同）。实验 3 用 N=5 序列就能失败（区间不覆盖 0.5 却下了结论）。实验 4 用 Lab 的 distractor 开关就能失败（日志没有视觉域字段）。四条都不必等 GPU。有 GPU 之后，把实验 1 换成真正的 LIBERO 四套件推理，预算大约是加载 7B 后每套件 500 次前向；失败判定不变：Long 仍须单独成列。

### 14.1 评测对象

- [CALVIN](https://arxiv.org/abs/2112.03227)：读 §III 环境、34 任务阈值、MTLC / LH-MTLC，以及 Fig. 8。带着问题：短程 53.9% 和五步 0.08% 共用同一套 MCIL 权重，差在哪一层协议？读完写出中性复位、未见指令、五步组合各自关掉了什么捷径。HTML：[v4](https://arxiv.org/html/2112.03227v4)。
- [LIBERO](https://arxiv.org/abs/2306.03310)：读 §4.2 四个套件和 PDDL 谓词。带着问题：Spatial / Object / Goal 分别转移哪种知识？VLA 论文把它们平均成一个数时，原文的研究问题还在不在？原文还比较了 ER、EWC、PackNet 与顺序 fine-tune，并发现顺序 fine-tune 的前向迁移可以优于那些终身学习算法。OpenVLA 后来只用了套件上的独立 BC fine-tune，等于把终身学习问题撤掉，只留任务分布。读的时候把“基准原问题”和“VLA 用法”分成两段笔记。HTML：[v2](https://arxiv.org/html/2306.03310v2)。项目页：[libero-project.github.io](https://libero-project.github.io)。
- CALVIN 项目页 [calvin.cs.uni-freiburg.de](http://calvin.cs.uni-freiburg.de) 与 SIMPLER 项目页 [simpler-env.github.io](https://simpler-env.github.io)：对照仓库 README 的评测入口。带着问题：一条命令默认跑的是短程还是长程、VisMatch 还是 VarAgg？默认值写进协议卡，不要假设自己知道。

### 14.2 视觉域与真机代理

- [SIMPLER](https://arxiv.org/abs/2405.05941)：读 §III 相关目标、§IV 控制 gap 与视觉 gap、Table I / II / III、Fig. 6 分布偏移。带着问题：Visual Matching 和 Variant Aggregation 各假设了什么？为什么 validation MSE 不能替仿真评测？读完把 Table I 的 $r$ 与 MMRV 抄进协议卡的“相关”栏，不要抄进“成功率”栏。HTML：[v1](https://arxiv.org/html/2405.05941v1)。项目页：[simpler-env.github.io](https://simpler-env.github.io)。

### 14.3 政策表内数字（必须写套件和 fine-tune）

- [OpenVLA](https://arxiv.org/abs/2406.09246)：读 §5.1 出厂真机（29 任务、相对 RT-2-X +16.5%，WidowX 170 / Google 60 rollouts）和 Appendix E Table 12。带着问题：Table 12 的 84.7 / 88.4 / 79.2 / 53.7 / 76.5 是不是零样本？答案：不是，是各套件独立 LoRA fine-tune，500 trials × 3 seeds，还过滤了失败示范。HTML：[v3](https://arxiv.org/html/2406.09246v3)。
- [OpenVLA-OFT](https://arxiv.org/abs/2502.19645)：读 Table I 和 Table II。带着问题：97.1% 用了哪些观察、是否过滤示范、每套件多少 trials？$\pi_0$（fine-tuned）94.2% 和 $\pi_0+$FAST（fine-tuned）85.5% 能不能跟 97.1% 比？可以比排序，因为同表、同套件、都写了 fine-tune；不能写成三个模型的出厂能力。ALOHA 的 15 个绝对点是另一张表、另一种 $N$。HTML：[v2](https://arxiv.org/html/2502.19645v2)。
- [$\pi_0$](https://arxiv.org/abs/2410.24164)：读评测设定（出厂提示、人给语言、高层 VLM、fine-tune）和真机任务列表。带着问题：这篇主表是不是 LIBERO？不是。若你要引用 96.8 / 98.8 / 95.8 / 85.2 / 94.2，出处是 OFT Table I 的 $\pi_0$（fine-tuned）行，不是 $\pi_0$ 原论文摘要。再问一次：洗衣折叠那条政策是出厂提示还是后训练？原论文把预训练与后训练分开写，后训练才是“诱导所需行为”的阶段。把后训练成功率写成预训练零样本，属于协议错误。HTML：[v4](https://arxiv.org/html/2410.24164v4)。

读 OpenVLA 时再带一个计算题：Table 12 的 Spatial $84.7\pm 0.9\%$，按二项粗估 $N_{\text{eff}}\approx \hat p(1-\hat p)/\mathrm{SE}^2\approx 0.847\times 0.153/0.009^2\approx 1600$，与 500 trials × 3 seeds 同量级。若有人复现时 SE 大出三倍，先查是不是只跑了单 seed 50 次。读 OFT 时带一个对照题：Table I 里 $\pi_0+$FAST 的 Long 只有 60.2%，平均却有 85.5%。平均把 Long 的坑填了 25 个点。任何“FAST 接近 $\pi_0$”的句子，如果没写 Long，本课视为漏报。

读完材料回头看：政策一行权重都不必改，评测却已经从“一个百分数”变成一张可审计的协议卡。同一政策在三种协议上的排序差异，不是模型能力变了，而是评测把捷径一条条关掉了。你现在应该能拿着任意一篇 VLA 的成功率列，在五分钟内把它拆回套件、视觉域、谓词和 $N$，并决定这列数字能不能进自己的对照表。下一课把这套纪律带到屏幕上的点击：GUI 成功率和桌面抓取成功率，仍然不能横着写成同一种身体智能。
