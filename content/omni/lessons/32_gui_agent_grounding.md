# 第 32 课：统一 GUI 操作与机器人动作

> 内容：GUI 接地、Set-of-Mark / Trace-of-Mark 与跨身体二维动作头<br>
> 建议周期：阅读约 75 分钟；CPU 实验数分钟<br>
> 硬件：无 GPU 可读完全文并跑 CPU 机制实验；复现论文规模需要多卡与大规模截图 / 轨迹<br>
> 产物：共享 $[0,1]^2$ 接地损失、SoM 分类对照、分辨率夹具、文献数字表

## 1. 屏幕点击和机械臂动作有什么共同结构

点“提交”和抓杯子，看起来分属两个行业。一个在浏览器里移动鼠标，一个在桌面上移动夹爪。第 24 课把动作接进视觉语言模型，第 31 课要求仿真成功率不能直接当成真机能力。两边都已经能“看见”和“出手”，但还缺一句更硬的话：出手之前，模型必须在当前画面里指定一个位置。

这个位置可以是屏幕上的像素，也可以是相机图像里的末端投影。共同结构是三段式流水线：先读一张图（截图或俯视），再把语言指令落到图上的空间目标（接地，grounding：根据指令指出该动哪里），最后把该目标翻译成可执行动作（点击、输入、滚动，或末端位移）。前两段在数字世界和物理世界可以共用；第三段的动作语义不能假装相同。

本课把前两段写成同一套训练信号。连续头把目标写成归一化坐标 $\mathbf{u}=(x/W,\,y/H)\in[0,1]^2$，与机械臂在图像平面上的 $xy$ 共用二维回归损失。编号头把可点区域标成 $1,\ldots,K$，对编号做分类。Magma（arXiv:2502.13130）把第一种接口叫做动作接地的 Set-of-Mark（SoM，在可操作物体上叠编号），把时间上的第二种接口叫做 Trace-of-Mark（ToM，把未来运动画成编号轨迹）。它强调：SoM 管“此刻该动哪一块”，ToM 管“接下来这块会怎么走”。UI 截图是离散翻页，论文明确不对 UI 数据使用 ToM。

要改的模块是动作头，不是再训一个全新的视觉塔。验证改对了的标准有两条，都必须能在教学模拟里复现：视觉网格降到 $4\times 4$ 时，连续坐标误差大于 SoM；同一套共享头在玩具 UI 和桌面俯视图上误差都下降。CPU 实验再核对归一化是否落在单位正方形、Magma 式 256 档是否落在 $\{0,\ldots,255\}$、编号是否落在 $\{0,\ldots,K-1\}$。

把“共同结构”说死之后，还要能指出它不覆盖什么。它不覆盖力、摩擦、液体、不可逆损坏，那些是后续安全课。它不覆盖 HTML 特有的隐藏节点和 aria 标签，那些是结构化观察，本课故意不用。它不覆盖语音打断和全双工路由，那是[第 07 课](07_full_duplex_routing.md)的时钟。它覆盖的只有：两张图、一条指令、一个二维目标、一种把目标变成可执行量的写法。谁在这四个对象之外加进“通用智能”之类的空话，就把范围重新抄一遍。

本课术语：

| 术语 | 简要解释 |
|---|---|
| GUI 接地 | 根据指令在截图上指出要点的位置或区域，不经过 HTML / 无障碍树 |
| SoM | 把可操作区域叠上可读编号，模型输出编号而不是原始像素 |
| ToM | 把未来若干帧里同一批标记的位置串成轨迹，当作规划监督 |
| 归一化坐标 | 像素除以宽高，落到 $[0,1]^2$，跨分辨率可比 |
| 分箱 | 把连续坐标切成有限档，便于当 token 预测 |
| 基本动作 | OS-Atlas / UI-TARS 里跨平台共用的 click、type、scroll 等 |
| 6D / 7-DoF | 末端位置加姿态，必要时再加夹爪开合 |
| ScreenSpot | SeeClick 提出的跨手机 / 桌面 / 网页接地基准 |
| 原生 GUI 代理 | UI-TARS 那种只看截图、端到端出键鼠动作的模型，而不是外挂工作流 |

第 08 课已经处理过动态分辨率，见[第 08 课](08_dynamic_vision.md)；那一课管的是 tile 和位置编码，不管“点有没有点对”。第 23 课的探针用来检查答对是否等于看对位置，本课在那条探针上再加“看对之后如何变成动作”。

## 2. 本课解决的问题

GUI 代理的主流失败不是“不会写邮件正文”，而是“知道该点登录，却点到旁边的广告”。SeeClick（arXiv:2401.10935）把这件事命名为 GUI grounding，并给出可操作定义：只根据截图和指令预测点击位置，预测点落在真值框内算命中。机械臂这边的对应失败是：语言头能生成“抓住红色杯子”，末端却走向相邻的碗。两边都是空间接地失败，差别在动作执行器。

本课要同时回答三个互相卡住的问题。

第一，观察接口能否统一。CogAgent（arXiv:2312.08914）证明只喂截图、不喂 HTML，也可以在 Mind2Web 上超过吃清洗后 HTML 的大语言模型。OS-Atlas（arXiv:2410.23218）进一步把 Windows、Linux、macOS、Android、网页的截图收进同一套接地语料。机器人侧 Magma 用同一视觉编码器吃 UI 截图、OXE 操作图和教学视频。结论已经够用：输入都可以是图像。不要把 HTML 树或关节编码器当成统一的前提。

第二，监督信号能否统一。连续坐标对分辨率敏感：视觉格子变粗，格子中心到真值的距离变大。SoM 把目标改成“选几号”，只要编号仍能分开，分类对了就把动作落在物体中心，位置误差可以为 0。Magma 的消融写得很硬：把 UI 和机器人数据直接混在一起、仍预测原始 2D 坐标和 7-DoF，两边都会变差；改成 SoM + ToM 之后，同一组参数才能同时服务数字世界和物理世界。

第三，动作空间在哪一分叉。点击、输入、滚动是离散语义；末端 $xyz$、姿态和夹爪是连续控制量。OS-Atlas 发现“tap”和“click”这种命名冲突会损害多任务微调，于是把跨平台动作收成 click / type / scroll 三个基本动作，其余放进自定义动作。UI-TARS 官方报告（arXiv:2501.12326）给出另一张表：共享 Click、Drag、Scroll、Type、Wait、Finished、CallUser，桌面再加热键和左右键，手机再加长按和系统键。机械臂没有“热键”。二维接地可以共享，完整动作表必须在头之后分叉。

这三个问题不能分开买。只统一观察、仍用 HTML 选元素，桌面应用和实体杯子都进不去。只统一监督、动作名仍冲突，词表会把共享特征撕开。只统一动作名、视觉格子只有 $4\times 4$，连续头会在大格子里晃。所以本课的验收必须同时碰到分辨率和双域：低分辨率暴露接口差异，双域下降暴露参数是否真共享。缺任何一条，都可以用“我训了一个 GUI 模型”或“我训了一个操作模型”交差，那不是这课要的东西。

和第 23 课的边界也在这里。第 23 课问：选择题答对，是否等于看对了格子。本课假定你已经会问这个问题，接着问：看对了格子之后，出手的表示怎么写，才能让屏幕和桌面共享梯度。和第 24 课的边界：第 24 课问动作如何成为 token；本课问二维位置这种动作参数，如何在两种身体上写成同一张表。第 25 课才会比较分箱、连续 $L_1$、分块和压缩。本课固定用 $L_2$ 加 256 档，是为了和 Magma、SeeClick 的公开约定对齐，不是宣布其它表示无效。

失败条件预先写死：

- 只报下游任务成功率，不报接地命中或坐标误差；
- 把 HTML 选择或无障碍树命中，写成视觉接地；
- 把 SoM 提示 GPT-4V 的零样本结果，写成 Magma 那种训练时的 SoM 监督；
- 声称“一个头输出 7-DoF 就等于会点屏幕”，却没有共享的二维损失；
- 在低分辨率设置里连续误差没有大于 SoM，却宣称编号接口对分辨率不敏感。

## 3. 开始前需要准备什么

本课不依赖 MiniMind-O 的训练脚本。需要的是第 23 课那种“看对位置”的直觉，以及第 24 课“动作如何成为可预测对象”的接口意识。没有读过那两课也可以往下走，但遇到“答对了却点错”或“语言对了手臂不动”时，要回到那两课的探针，而不是在本课里重做 VQA。

开始前把笔记本分成两栏。左栏只抄打开过的论文句：分辨率、表号、样本量、动作名。右栏写本课约定：原点在左上、归一化用模型实际看到的 $(W,H)$、$B=256$、SoM 标签与渲染一致、Lab 的 $S$ 只有 4/8/16/32 四档。左栏数字可以对外引用，右栏数字只能当教学夹具。有人把 Lab 里 $4\times 4$ 的误差写成“复现了 CogAgent 不用高分辨率就会掉点”，属于把右栏抄进左栏。硬件上，读完加 CPU 实验不需要 GPU；若要跑 SeeClick 或 OS-Atlas-Base 的公开权重做 Step 3，再准备能放下 7B 视觉语言模型的显存。没有这张卡，跳过 Step 3 仍可完成最低交付。软件上只需要 Python 3.10 标准库和能打开本课页面的浏览器。不要为了本课新装检测器或 CoTracker，ToM 的算法在课文里讲清即可，CPU 实验不跑点跟踪。

**课程约定：**

- 浏览器里的左右双屏是教学模拟，数字由格子中心和编号规则算出来，不是 Magma 或 UI-TARS 的前向输出；
- CPU 实验只证明公式可复核，不证明 OSWorld 或 LIBERO 成功率；

若只想核对公式，准备 Python 3.10 和本仓库 `experiments/` 即可。CPU 实验不读网、不写文件、不用 NumPy，跑完只在内存里留下一个字典。不要为了“看起来更像训练”去加随机种子以外的噪声；本课要的是可复核，不是随机搜索。

## 4. 完成后应具备的能力

1. 把一次点击写成 $\tilde{x}=x/W$、$\tilde{y}=y/H$，并指出 $u=1$ 时分箱必须夹到 $B-1$，否则会越界。
2. 写出 SoM 的分类损失和连续坐标的 $L_2$，说明二者对视觉分辨率为什么不对称。
3. 按 Magma 原文区分 SoM 与 ToM：前者出现在静态图的可操作物体上，后者出现在视频和机器人轨迹里；UI 序列不用 ToM。
4. 对照 CogAgent 的高分辨率交叉注意力、SeeClick 的 ScreenSpot、OS-Atlas 的统一动作空间、UI-TARS 的原生代理，各用一句话说清它们改的是观察、接地、动作表还是推理。
5. 设计一个夹具：低分辨率下连续误差必须大于 SoM；共享头必须在 UI 和桌面两个域同时降误差。
6. 看到“平均成功率 SOTA”时，能追问是 ScreenSpot 的点中框，还是 OSWorld 的任务成功，还是 LIBERO 某个套件的 fine-tune 结果。

读完第 4 节，可以用下面这段自检，不通过就先别进公式。拿一张手机设置页截图和一张桌面俯视，指令都写“打开那个红色的东西”。你应能指出：两张图的观察都是 RGB；接地目标分别是设置页里红色开关的中心，和桌上红色杯子的中心；GUI 动作是 click，桌面动作是靠近并闭合夹爪。若你只能写出“都是点红色”，还没有把动作分叉写出来。若你写出了 click 和 7-DoF，却说不出 $\mathbf{u}$ 怎么从像素算出来，观察和接地还没对齐。这段自检不计入 CPU 实验，但能避免后面把损失写在错误的变量上。

## 5. 原理：边造边讲

五个机制按同一节奏：为什么需要、怎么运转、精确定义、公开实现落在哪、怎么证明做对了。本课没有 MiniMind 源码，代码落点写在各小节末尾的公开仓库与数据字段里。

### 5.1 观察、接地、动作：三段里哪一段能跨身体

人点按钮时，眼睛先找到按钮，手指再按下去。机械臂抓杯子时，相机先看到杯子，控制器再把末端送到接触点。中间那一步都是：在当前画面里指定空间目标。Magma 把模型写成

$$
\mathcal{O}=\pi(\mathcal{I},\texttt{task},\texttt{ctx})=\{o_1^{l},\ldots,o_T^{l}\}
$$

其中 $l\in\{\texttt{verbal},\texttt{spatial}\}$，输出既可以是词，也可以是空间标记。UI 导航时，空间部分是 $(x,y)$ 或框 $(x,y,w,h)$；操作时，空间部分是末端位移，论文写成 6-DoF $(x,y,z,\mathrm{yaw},\mathrm{pitch},\mathrm{roll})$，必要时加一维夹爪。多模态问答则退化成只输出词。

三段流水线里，观察和接地可以共享，动作执行不能。观察共享的证据是：CogAgent、SeeClick、OS-Atlas、UI-TARS 都选择“只看截图”；Magma 进一步把截图、机器人相机帧和教学视频送进同一个 ConvNeXt 编码器。接地共享的证据是 Magma 用同一套 SoM 编号覆盖按钮、末端和人手。动作不能共享的证据是 OS-Atlas 自己都要把“tap / click”合并之后，仍然保留 `open_app`、`drag` 这种平台自定义动作；机械臂没有 Home 键。

类比可以走到这里：编号像给房间里每件可搬的东西贴标签，连续坐标像用卷尺量到墙角的距离。类比失效处：真实 UI 的标签会互相遮挡，Magma 的算法要给编号找一块远离已有框的角；真实机器人还有深度、力和接触，二维接地只覆盖末端在图像上的投影，并不覆盖“有没有抓住”。

验证：给同一条指令“点提交 / 抓杯子”，画出三列：观察（图）、接地（编号或 $[0,1]^2$）、动作（click 或 7-DoF）。缺任何一列，都不得声称“统一了身体”。

把这条流水线写成训练时能落地的字段，比画框图更不容易糊弄。一条 UI 样本至少包含：原始截图尺寸 $(W,H)$、指令文本、目标框或点、动作类型、以及（若用 SoM）渲染后的标记图和编号 $k$。一条桌面样本至少包含：相机图尺寸、指令、末端在图像上的投影点或物体框、以及 7-DoF 里不进入共享头的那几维。两边对齐的字段只有四列：图像、指令、归一化二维目标、可选编号。动作类型、夹爪、热键各自留在域内列。你若在表格里只看到“image, instruction, action_string”，请把它拆开，直到二维目标单独成列。拆不开的数据集，不要送进共享头。

公共字段一旦对齐，batch 构造就变成普通的多任务取样。设一个 batch 里 UI 样本集合为 $\mathcal{B}_{\mathrm{UI}}$、桌面样本为 $\mathcal{B}_{\mathrm{arm}}$，共享参数 $\theta$ 只通过 $\mathbf{u}$ 和 $k$ 两条出路更新：

$$
\theta \leftarrow \theta-\eta\nabla_\theta\Bigl(
\frac{1}{|\mathcal{B}_{\mathrm{UI}}|}\sum_{\mathcal{B}_{\mathrm{UI}}}\mathcal{L}
+
\frac{1}{|\mathcal{B}_{\mathrm{arm}}|}\sum_{\mathcal{B}_{\mathrm{arm}}}\mathcal{L}
\Bigr)
$$

$\mathcal{L}$ 是 $\mathcal{L}_{\mathrm{SoM}}$ 或 $\mathcal{L}_{\mathrm{reg}}$，下一节展开。域特定的动作类型头用自己的学习率或冻结，避免 `Hotkey` 的梯度改写末端 $xy$。Magma 的教训已经写在表 3：动作空间不先对齐，就做上面这个求和，两边都会掉。

### 5.2 连续坐标：归一化、分箱、二维损失

SeeClick 选择把坐标写成自然语言里的两位小数，范围 $[0,1]$，例如 `click (0.49, 0.40)`。它没有新增 1000 个专门的位置 token。CogAgent 沿用 CogVLM 的框格式 $[[x_0,y_0,x_1,y_1]]$，每个量归一化到 $[000,999]$。OS-Atlas-Base-7B 的模型卡写明输出是 $0$–$1000$ 的相对坐标。Magma 的做法是：先按图像高宽归一化，再量化到 256 档。UI-TARS 报告写：对有框的元素取四角平均得到中心点，再输出相对屏幕尺寸的坐标。

本课的教学约定与 SeeClick / Magma 对齐，写成：

$$
\tilde{x}=\frac{x}{W},\quad \tilde{y}=\frac{y}{H},\quad \mathbf{u}=(\tilde{x},\tilde{y})\in[0,1]^2
$$

分箱（Magma 的 $B=256$）：

$$
b_x=\operatorname{clip}\bigl(\lfloor \tilde{x}\,B \rfloor,\,0,\,B-1\bigr)
$$

$\tilde{x}=1$ 时 $\lfloor B \rfloor=B$，必须夹到 $B-1$，否则词表越界。反量化用档中心：

$$
\hat{u}=\frac{b+0.5}{B}
$$

最大量化误差是半档 $1/(2B)$。$B=256$ 时约为 $0.002$。这和视觉分辨率带来的误差不是同一件事：视觉编码器若把图压成 $S\times S$ 个 patch，格子中心误差量级是 $1/(2S)$。$S=4$ 时半格是 $0.125$，比 256 档量化大两个数量级。所以“分箱不够细”很少是低分辨率失败的主因，“格子太大”才是。

连续头的回归损失取二维 $L_2$（也可用 $L_1$，OpenVLA-OFT 走 $L_1$，那是第 25 课的表示问题）：

$$
\mathcal{L}_{\mathrm{reg}}=\lVert \hat{\mathbf{u}}-\mathbf{u}^\star \rVert_2^2
$$

把机械臂末端在图像上的投影写成 $\mathbf{u}^{\mathrm{arm}}$，同一条损失可以对 UI 点击和桌面 $xy$ 求和：

$$
\mathcal{L}_{xy}=\mathcal{L}_{\mathrm{reg}}^{\mathrm{UI}}+\mathcal{L}_{\mathrm{reg}}^{\mathrm{arm}}
$$

$z$、姿态、夹爪不进入 $\mathcal{L}_{xy}$。硬把 7 维塞进二维头，梯度会把“夹爪开合”和“点屏幕”拧在一起，这正是 Magma 消融里“直接混动作空间会掉点”的来源之一。

公开实现落点：SeeClick 附录 A.1 写明点用 $(x,y)$、框用 $(\mathrm{left},\mathrm{top},\mathrm{right},\mathrm{down})$，均为两位小数；Magma 图 3 注记“All coordinates are normalized by image size (height, width) and then quantized into 256 bins.” CPU 实验用 1920×1080 的像素点跑一遍归一化和 256 档，并故意把宽高对调，确认错误归一化会把 $\tilde{x}$ 推出 $(0,1)$。

用手算一遍，避免只记住公式。取 SeeClick 文中的例子风格：屏幕 $W=1920$、$H=1080$，要点 $(x,y)=(941,432)$。

$$
\tilde{x}=\frac{941}{1920}=0.490104,\quad \tilde{y}=\frac{432}{1080}=0.400000
$$

SeeClick 写成两位小数就是 `click (0.49, 0.40)`。Magma 的 256 档：

$$
b_x=\lfloor 0.490104\times 256\rfloor=125,\quad b_y=\lfloor 0.400000\times 256\rfloor=102
$$

档中心反量化：

$$
\hat{x}=\frac{125.5}{256}=0.490234,\quad \hat{y}=\frac{102.5}{256}=0.400391
$$

和真值的差小于半档 $0.001953$。若有人把宽高对调，会得到 $\tilde{x}=941/1080=0.871$，$\tilde{y}=432/1920=0.225$，点会落到完全不同的控件上。再取一个贴边点 $(1919,1079)$：$\tilde{x}=0.999479$，$b_x=255$；取 $(1920,1080)$ 即 $\tilde{x}=\tilde{y}=1$，必须夹到 255，不能输出 256。CPU 实验把 $0$、$1-10^{-12}$、$1$、$-0.25$、$1.25$ 五个输入的档位固定成 $[0,255,255,0,255]$，就是锁这条边界。

CogAgent 的 $[000,999]$ 和 OS-Atlas 的 $0$–$1000$ 是另一套整数接口。换算关系是 $\mathrm{int}(\tilde{x}\times 999)$ 或 $\mathrm{int}(\tilde{x}\times 1000)$，上界约定不同。读权重卡时先看这句话：OS-Atlas-Base-7B 写的是 “normalized to relative coordinates within a 0-1000 range”。你若用 SeeClick 的两位小数去解码 OS-Atlas 的整数，点会挤在左上角。教学代码里只实现一套 $[0,1]$ 加 256 档，其它格式写成显式的线性变换，不要靠“都是相对坐标”混过去。

机械臂的 waypoint 怎样进入这套 $[0,1]^2$，必须写明投影，不能口头说“末端也是 xy”。设相机内参把工作空间点 $\mathbf{p}=(X,Y,Z)$ 投到像素 $(x,y)$。共享头的标签是投影后的 $(\tilde{x},\tilde{y})$，不是 $(X,Y)$ 本身。深度 $Z$ 丢失。若两只杯子在图像上重叠，二维头无法区分远近，这是后半课不能宣称“已经统一 6D”的几何原因。若你只有末端在基座坐标下的 $(X,Y)$、没有相机外参，就不要把 $(X,Y)$ 除以桌面宽度冒充图像归一化。两种“xy”同名不同源。Magma 的 SoM 画在图像上，标签属于图像坐标系。OpenVLA 式 7-DoF token 属于机器人坐标系。本课共享的是前者。实现上若要用后者，先把 7-DoF 的平移分量投到当前相机，得到 $\mathbf{u}^{\mathrm{arm}}$，再进 $\mathcal{L}_{xy}$；投影失败的帧丢掉，不要用上一帧的投影顶上。

连续损失对框和点也要分开。点监督就是 $\mathbf{u}^\star$ 本身。框监督常见两种：用框中心，或要求预测点落在框内（推理指标）但训练仍回归中心。SeeClick 的 click accuracy 是推理指标，不是训练损失。若训练用 $L_2$ 回归中心、评测用点中框，低分辨率下 $L_2$ 可能仍大于 SoM，但点中框准确率双方接近——因为框比点大。写报告时损失和指标必须成对出现。

### 5.3 SoM：从提示 GPT-4V 到训练时的动作接地

原始 SoM 不是动作模型。Yang 等人（arXiv:2310.11441）给 GPT-4V 做视觉提示：用 SEEM / SAM 等分割模型把图切成区域，在区域上叠数字、字母、掩膜或框，得到标记图 $I^{m}$，再问模型。公式是

$$
T^{o}=\mathcal{F}(\mathrm{SoM}(I),T^{i})
$$

关键性质有两条。标记必须“能被模型读出来、能被模型说出来”，所以用数字而不是红圈；标记不能泄漏到用户文本里，论文图 1 注明 no marks are leaked to user text inputs。在 RefCOCOg 的子集上，让 GPT-4V 直接吐坐标只有 25.7；加上 SoM 后 REC 到 86.4，超过若干专门微调的检测器。它解决的是“通用多模态模型说不清位置”，还不是“代理要点哪里”。

Magma 把同一套视觉语言拿来当训练目标。给定图像 $I_t$，先提出 $K$ 个候选区域或点 $\mathcal{P}=\{p_1,\ldots,p_K\}$，把编号叠回去得到 $I_t^{M}$，模型输出

$$
o_t^{\mathrm{mark}}=\texttt{action}_t:\texttt{mark}_t=\pi(\mathcal{I}_t^{M},\texttt{task},\texttt{ctx})
$$

$\texttt{mark}_t$ 是 $\mathcal{M}=\{1:p_1,\ldots,K:p_K\}$ 的子集。对教学规模，取单标记、分类损失：

$$
\mathcal{L}_{\mathrm{SoM}}=-\log p(k^\star\mid I^{M},\mathrm{task},\mathrm{ctx}),\qquad k^\star\in\{0,\ldots,K-1\}
$$

编号从 0 还是从 1 起，必须与渲染一致。Magma 算法 1 用 `str(idx+1)` 渲染，训练标签若从 0 起却忘记减一，损失会稳定下降，点却永远偏一个控件。CPU 实验把错误编号的交叉熵和正确编号比了一遍，前者必须更大。

SoM 对分辨率不敏感的条件是：编号在低分辨率下仍可分辨。若两个按钮落入同一 $4\times 4$ 格子，分类也会混。交互实验把控件放在不同象限，保证 $4\times 4$ 时仍能分开，这样“连续误差更大”才是分辨率效应，而不是编号撞车。原始 SoM 论文也警告：图里已经全是数字时，不要再叠数字。GUI 里图标本身可能含数字，渲染时要避让。

验证：同一张低分辨率图，连续头只能报格子中心，SoM 选对编号后回到物体中心。位置误差的差，就是本课要看见的那条不等式。

把分类损失也写到能手算。设 $K=6$，正确编号是 $0$，logits 为 $(2.4,0.15,0.12,0.08,0.11,0.09)$。减去最大值做 softmax，得到 $p_0\approx 0.664$，

$$
\mathcal{L}_{\mathrm{SoM}}=-\log 0.664\approx 0.410
$$

若标签写成 $3$，同一组 logits 的损失升到约 $2.73$。这就是 CPU 实验里 `off_by_one_som_target_increases_ce` 的数值。它只证明编号范围和交叉熵实现没写反，不证明 6 个真实按钮已经能分开。真要分开，还得看渲染：Magma 算法 1 先画框，再找远离已画框的角放数字，再按文字尺寸开一个 text box。编号互相覆盖时，分类头会稳定地学会“读那个更大的数字”，损失照样降。检查方法是把 $I^{M}$ 存盘，人工看最小两个编号的像素距离，小于字体尺寸就重排。

原始 SoM 论文还比较过标记类型。Flickr30K 子集上，只用数字加掩膜 Recall@1 为 84.4，再加框升到 89.2。GUI 里框几乎总是有的（HTML 或 A11y 能给出），所以 Magma 和 OS-Atlas 叠框加数字是有先例的。自然图上 GPT-4V 能“自己会用编号”，是因为训练语料里有带图注的论文和图表；开源 LLaVA-1.5、MiniGPT-v2 在同一提示下几乎不会读编号。因此：不要假设任意 VLM 加上数字就能当接地模型。SeeClick、OS-Atlas、Magma、UI-TARS 都是在 GUI 数据上继续训过的。

候选区域从哪来，决定 SoM 的上限。UI 可以用 DOM / A11y；自然操作可以用分割或检测；Magma 还写了 OmniParser 只提供检测、不提供局部语义，用于零样本 ScreenSpot。候选漏掉真目标时，分类头再准也点不到。这和原始 SoM 用 GT 掩膜把 RefCOCOg mIoU 从 75.6 抬到 90.1 是同一件事：标记集合的召回率是分类准确率的天花板。缩小实验里我们把 6 个物体都标上，等于假设召回率 1，只比较接口，不比较检测器。

### 5.4 ToM：把未来运动写成可预测的标记轨迹

静态 SoM 只回答“现在动哪一块”。长程操作还要回答“这块接下来往哪走”。Magma 把观察序列从当前帧延到未来 $l$ 帧，取出各标记的未来位置 $\mathcal{T}=\{\mathcal{M}_{t+1},\ldots,\mathcal{M}_{t+l}\}$，在动作和编号之后继续预测轨迹：

$$
o_t^{\mathrm{mark}}=\texttt{action}_t:\texttt{mark}_t:\texttt{trace}_{t+1:t+l}
$$

实现上用 CoTracker 在 $s\times s$ 网格上追点，丢掉平均运动幅度小于 $\epsilon$ 的轨迹，剩下的当作前景。补充材料给出默认 $s=15$、全局运动阈值 $\eta=2$、前景阈值 $\epsilon=2$。教学视频常有相机运动，算法先做单应变换再分类前景。作者在 YouCook2-BB 的 1320 个片段上检查：从人工框出发的轨迹，1 秒后仍落在框内的比例是 0.89。

ToM 相对“预测下一帧像素”的好处，论文写了两条：强迫模型在出手前进看；用少得多的 token 覆盖更长的时间范围，并丢掉背景。它对 UI 不适用：UI 是一串离散截图，按钮不会在像素里连续滑到下一页。表 1 写得很清楚：UI 截图只用 SoM，机器人和教学视频同时用 SoM 和 ToM。

不要把 ToM 写成世界模型。第 33 课才会问预测的是像素还是表征。ToM 预测的是已标记点的二维轨迹，不是未来 RGB，也不是 V-JEPA 式的潜变量。

验证：在一段“手把杯子推向左沿”的玩具轨迹上，SoM 只监督第一帧的杯子编号，ToM 监督后续帧的编号坐标。关掉 ToM 只留 SoM，模型仍能指出杯子，但不能被要求复现那条折线。Magma 表 3 的定量版本是：去掉 SoM+ToM、只混原始动作时，VisualWebBench 的 Act-G 从 71.8 掉到 25.2，SimplerEnv-Bridge 从 35.4 掉到 17.7。

把 ToM 的生成流程按算法 2 拆成可复查的步骤，写进实验笔记。输入是一段 $l$ 帧的短镜头。先用镜头检测切段，再用 CLIP 图文相似度丢掉小于 0.25 的片段。在起始帧铺 $s^2$ 个网格点，跑 CoTracker，得到每条轨迹的未来位置和遮挡标记。若检测出全局运动，用单应 $h_i=\mathcal{H}(M_t,M_{t+i})$ 把后续点变回第一帧坐标系。按相邻帧平均位移是否达到 $\epsilon$ 分成前景和背景，分别做 K-Means，前景簇数随机取 $1$ 到 $\min(5,|\mathcal{M}^f|)$，背景取两倍。最后在第一帧上渲染 SoM，模型要预测留下来的前景轨迹。参数 $s=15$、$\eta=2$、$\epsilon=2$ 来自原文，缩小实验可以改 $s$，但不能把“随便抽 8 个点连线”写成 ToM。

ToM 与第 24 课离散动作 token、第 25 课动作分块的关系要划清。离散 token 预测的是下一时刻的控制量；分块预测的是未来 $H$ 步关节；ToM 预测的是图像上标记的未来坐标。三者都能“看未来”，监督对象不同。Magma 仍然要在机器人数据上预测 7-DoF，ToM 是额外的替代监督，用来消化没有动作标签的视频。没有 7-DoF 标签的 Ego4D 片段，靠 ToM 才能进同一套预训练。这是它能把 2500 万视频样本算进“动作相关语料”的原因。

### 5.5 动作空间：click / type / scroll 对 6D 末端

接地给出位置之后，还要给出动作类型。SeeClick 把动作简化为点击和输入，并借用 AITW 的编号：click 为 4，type 为 3，另有 select、swipe、BACK / HOME / ENTER。它自己承认没有覆盖拖拽和双击。

OS-Atlas 的问题更刺：多数据集微调时，同一物理操作有不同名字。论文量化过：统一动作空间把独特动作类型从 17 个收到 10 个，消掉 tap/click、press_home/home、type/input。基本动作固定为 click、type、scroll；自定义动作包括 `open_app` 和 `drag`，用来表达平台特有能力，也是他们声称 OOD 还能扩展的原因。

UI-TARS 官方报告表 1 给出目前最完整的一张公开表。共享动作：`Click(x,y)`、`Drag(x1,y1,x2,y2)`、`Scroll(x,y,direction)`、`Type(content)`、`Wait()`、`Finished()`、`CallUser()`。桌面追加 `Hotkey(key)`、`LeftDouble(x,y)`、`RightSingle(x,y)`。手机追加 `LongPress(x,y)`、`PressBack()`、`PressHome()`、`PressEnter()`。坐标仍然是点，不是 HTML 元素 id。

机械臂侧，Magma 跟随 OpenVLA：把 7-DoF 写进语言模型几乎用不到的最后 256 个离散 token。二维接地头只应对 $(x,y)$ 或图像平面投影；$z$ 和姿态是另一组头或另一段 token。教学上保持这道缝：共享头输出 $\mathbf{u}\in[0,1]^2$ 和（可选）SoM 编号；机器人配置再把 $\mathbf{u}$ 反投影到工作空间，或把 256 档 token 解成末端增量。

验证：准备两份动作表。一份只有 click/type/scroll，应能描述“打开设置并输入 Wi-Fi 名”。一份 7-DoF，应能描述“把杯子放到盘子上”。找一条两边都需要的指令，例如“把桌面上的按钮点一下”——GUI 里那是 click，真机里那是末端接触。同一条 $\mathcal{L}_{xy}$ 可以训练位置，不能训练“点下去”和“夹住”的力学差异。第 40 课会处理接触力；本课只把缝留清楚。

把分叉写成接口，避免以后有人把 7 维向量直接拼进 click 头。共享头输出

$$
(\hat{\mathbf{u}},\,\hat{k},\,z_{\mathrm{shared}})\in[0,1]^2\times\{0,\ldots,K-1\}\times\mathbb{R}^{d}
$$

GUI 侧再接一个小分类器 $g_{\mathrm{gui}}(z_{\mathrm{shared}})\to\{\mathrm{click},\mathrm{type},\mathrm{scroll},\ldots\}$，需要字符串时另开文本解码。机器人侧再接 $g_{\mathrm{arm}}(z_{\mathrm{shared}},\hat{\mathbf{u}})\to\mathbb{R}^{6}\times[0,1]$，最后一维是夹爪。$\hat{\mathbf{u}}$ 可以当图像平面提示，也可以丢掉只用 $z_{\mathrm{shared}}$；本课验收只要求 $\hat{\mathbf{u}}$ 在两域上都受 $\mathcal{L}_{xy}$ 约束。$g_{\mathrm{gui}}$ 和 $g_{\mathrm{arm}}$ 不共享最后一层。OS-Atlas 的自定义动作等价于 $g_{\mathrm{gui}}$ 的可扩展词表；Magma 的 7-DoF 离散 token 等价于 $g_{\mathrm{arm}}$ 走语言模型词表。两种实现都能满足“二维共享、其余分叉”。

动作历史怎么进上下文，也按域分开记账。SeeClick 用最近 $k=4$ 步动作。UI-TARS 保留全部 thought 与动作，截图只留最近 $N$ 张。机器人在线控制里，历史往往是上一 chunk 的末端轨迹，见第 30 课的分块与延迟。不要把 4 步 GUI 历史和 50 步关节历史塞进同一位置编码而不写明时间单位。共享的是空间头，不是时间尺度。

### 5.6 CogAgent：高分辨率是接地的前置条件

GUI 的字和图标经常只有十几像素。CogAgent 的观察是：224 分辨率已经能表达物体和布局，但看不清字；若把 1120×1120 的图直接送进大解码器，patch 14 时视觉 token 长达 6400，自注意力按长度平方涨。它的结构是：低分辨率 EVA2-CLIP-E（224，沿用 CogVLM 的 4.4B 视觉）走原来的视觉专家自注意力；高分辨率 EVA2-CLIP-L（1120，0.30B）在每一层解码器上做小隐层交叉注意力。交叉注意力隐层 1024、32 头、每头 32 维。论文给出改进后的注意力复杂度

$$
T_{\mathrm{improved}}=O\bigl((L_{I_{\mathrm{lo}}}+L_T)L_{I_{\mathrm{hi}}}H_{\mathrm{cross}}d_{\mathrm{cross}}+(L_{I_{\mathrm{lo}}}+L_T)^2 H_{\mathrm{dec}}d_{\mathrm{dec}}\bigr)
$$

并声明 CogAgent-18B 在 1120 输入上的 FLOPs 不到 CogVLM-17B 默认 490 输入的一半。消融表 5：不做高分辨率交叉、只用 224，ST-VQA 48.0、DocVQA 28.6；224+1120 交叉则到 78.2 和 74.1。GUI 数据 CCS400K：从 Common Crawl 抽 URL，截 40 万张网页，用 Playwright 收可见 DOM 和渲染框，构造 1.4 亿条 REC / REG 问答。框的数字格式是 $[000,999]$。

Mind2Web 上，只看截图的 CogAgent 逐步成功率 overall 58.2，cross-task 62.3、cross-website 54.0、cross-domain 59.4，高于用清洗 HTML 的 LLaMA2-70B（50.1 / 55.8 / 51.6 / 55.7）。AITW 上统一模型 overall 76.88。这些数字说明：分辨率和 GUI 预训练能把“看见小字”变成可测的接地能力。它们不说明 18B 已经能当电脑用户。CogAgent 自己的结论也写了：输出坐标仍不够准，也不能处理多图。

对本课的用处只有一句：共享二维头之前，视觉塔必须有足够的空间带宽。交互实验里把网格从 32 降到 4，就是在玩具里重放这条带宽限制。

训练日程也值得单独记一笔，因为它解释了“高分辨率模块为什么能接到已经训好的低分辨率 VLM 上”。CogAgent 共预训练 6 万步，batch 4608，学习率 $2\times 10^{-5}$。前 2 万步冻结原 VLM，只训新加的高分辨率交叉模块，可训练参数 6.46 亿，约占 3.5%；后 4 万步再解开视觉专家。课程学习顺序是：先易的文字识别和配图说明，再学术文档 OCR，再接地，再网页。多任务对齐阶段 1 万步，batch 1024，全部参数解开，数据包括人工标注的两千余张手机和电脑截图、Mind2Web、AITW，以及一批公开 VQA。对缩小实验的含义是：先把共享二维头接到冻结视觉塔上，确认 $\mathcal{L}_{xy}$ 能降，再考虑解冻 ViT。第 22 课的解冻顺序在 GUI 上同样适用，只是本课不重做三种 connector。

高分辨率交叉注意力的查询来自解码器隐状态，键值来自 6400 个高分辨率 token。它是对低分辨率特征的残差补充，所以低分辨率分支仍然要能看见布局。关掉高分辨率分支，模型还能做粗定位，但小图标会丢。这和本课 $S=4$ 对 $S=32$ 的夹具同构：粗网格保留布局，细网格才够点图标。CogAgent 用真实容量换细网格；教学实验用 $S$ 这个旋钮假装同一件事。

CogAgent 同时报了一批非 GUI 的 VQA，用来声明自己还是通用视觉语言模型。通才设置下 TextVQA 76.1、ST-VQA 80.5、ChartQA 68.4、DocVQA 81.6、MM-Vet 52.8、POPE-adv 85.9。这些数字高于同表里不少通用模型，也高于作为起点的 CogVLM 通才结果。对本课的用处是：GUI 继续预训练不一定必须以牺牲读字为代价。Magma 表 2 也报了 VQAv2 80.0、TextVQA 66.5、POPE 87.4，用来对照“专攻动作的模型往往丢掉 VL”。你的缩小实验如果只训 12 个点，VQA 必然崩，不要用 CogAgent 的 DocVQA 81.6 给自己的玩具头背书。正确的对照是：加 GUI 数据前后，同一条 OCR 探针升还是降。第 23 课的 OCR 探针可以复用，本课不重做。

网页接地任务在 CogAgent 里拆成 REC 和 REG。REC：给定 DOM 元素，回归渲染框。REG：给定截图上的一块区域，生成对应 HTML。两者都在 CCS400K 上大规模出现。SeeClick 的 text2point 更接近 REC 的点版本；point2text 更接近 REG 的短文本版本。Magma 的 SoM 分类可以看成把 REC 的连续框换成离散编号。三条路都在做“语言和区域互指”，损失不同。写相关工作时按损失归类，不要按论文标题归类。

### 5.7 SeeClick 与 ScreenSpot：先测接地，再谈代理

SeeClick 的预备实验发现，现成视觉语言模型在 GUI 上几乎不会点。ScreenSpot 因此被做成第一张跨平台、含图标的接地考卷：600 余张截图、1200 余条指令，覆盖 iOS、Android、macOS、Windows 和网页，并单独统计 Text 与 Icon/Widget。评测口径是 click accuracy：预测点落在真值框内。表 1：MiniGPT-v2 平均 5.7%，Qwen-VL 5.2%，GPT-4V 16.2%，Fuyu 19.5%，CogAgent 47.4%，SeeClick 53.4%。拆开看，SeeClick 手机文字 78.0%、图标 52.0%，桌面文字 72.2%、图标 30.0%，网页文字 55.7%、图标 32.5%。所有模型在图标上都明显弱于文字。这不是装饰性拆桶：图标没有可读字符串，连续坐标和 SoM 都会更难，但 SoM 仍把问题保持为“选几号”，连续头则要在一片扁平像素里吐小数。

SeeClick 的训练数据约 100 万条：网页 text2point 27.1 万、text2bbox 5.4 万，以及反向 OCR；手机 text2point 27.4 万，加 widget captioning 和 UI summarization；再加 LLaVA 的 14.5 万通用指令。骨干是 Qwen-VL，分辨率 448，LoRA 开视觉编码器和语言模型，约 1 个 epoch、10k step，8×A100 约 24 小时，学习率 $3\times 10^{-5}$，全局 batch 64。下游 MiniWob 上，2.8K 轨迹的纯视觉 SeeClick 在 35 个任务上得 67.0，超过用 130 万轨迹的 Pix2Act（64.6），数据量不到其 0.3%；同一 2.8K 上 Qwen-VL 只有 48.4。AITW 按指令划分后 overall 59.3，ClickAcc 66.4，相对 Qwen-VL 的 57.4 / 54.3 主要涨在点击。Mind2Web 纯视觉、不喂 HTML 时，cross-task 逐步成功率从 Qwen-VL 的 13.3 到 25.5，大约翻倍，但仍低于用 HTML 候选的 MindAct（52.0）。作者把差距解释为：从像素吐坐标，比从 HTML 候选里做选择题更难。

ScreenSpot 后来被 OS-Atlas 发现约 11.32% 标注错误，并发布 ScreenSpot-V2。引用 SeeClick 表 1 时，要写明是原版 ScreenSpot；引用 OS-Atlas 表 2 时，写明是他们评的原版还是 V2。本课交互实验不使用 ScreenSpot 图片，只借用“点是否落在目标里”这条口径。

ScreenSpot 的标注协议本身也是一份接地定义。四名计算机专业研究生按平台分工，在日常使用中截图，用框标出常点的可操作区域，再写英文指令，去个人信息。手机和桌面要求选常用应用；网页从 WebArena 的开发、购物、论坛、工具四类站点取样。它刻意不从旧 Android 数据集里抽，以免和 2017 年的 RICO 训练集重叠。评测时各模型用官方推荐提示。CogAgent 用“What steps do I need to take to \<instruction>? (with grounding)”这类官方句，再取输出坐标或框中心。SeeClick 发现自己点预测略优于框，所以主表用点。GPT-4V 按 Yang 等人 2023 的方式提示。这些细节说明：同一张 ScreenSpot，提示词不同数字就会动。本课引用表 1 时跟随 SeeClick 原文设置，不把后来加 planner 的 OS-Atlas 数字写进同一行。

SeeClick 还画过一张“接地变好、下游也变好”的相关图（图 6），并做了统一训练：三个下游任务合在一起略降，MiniWob 67.0 到 64.1，AITW 59.3 到 57.1，Mind2Web 20.9 到 19.5。作者猜测是界面差异太大。这对共享头是警告：UI 内部的手机 / 网页已经会互相干扰，再加机械臂只会更严重。Magma 用 SoM/ToM 换接口，就是在回答这张表。

附录里的误差分析同样有用。SeeClick 把预测点到真值中心的距离做成直方图：错例大多仍落在目标附近。模型“看见了”却不够细。连续头在低分辨率下的格子中心误差，就是这一现象的公式版。提高 $S$、提高输入分辨率、或改成 SoM 选物体，是三条不同的修补，别混成“再多训一会儿”。

### 5.8 OS-Atlas：接地规模和动作表是两件工程

OS-Atlas 把失败原因写成两条：现成视觉语言模型几乎没在 GUI 截图上预训练；各数据集动作名冲突。它的回答也是两条：做跨平台接地数据基础设施；训练时用统一动作空间。

数据方面，网页从 FineWeb URL 爬约 400 万页，渲染整页再切成 1920×1080，过滤 404 和元素扎堆，每页最多保留 10 个元素，得到 160 万张截图、770 万元素。桌面和手机不能靠爬虫：Android 用 AndroidEnv，Linux 用 OSWorld，Windows 和 macOS 在真机上跑，读 A11y 树再 DFS / 随机走。指令接地还用 GPT-4o 给 Mind2Web、AMEX、AITZ 的轨迹标子指令，并显式使用 SoM 提示来标出被操作元素。总计超过 230 万张不重复截图、1300 万 GUI 元素，覆盖五个平台，并补上以往几乎没有的桌面接地。

模型方面，先做接地预训练得到 OS-Atlas-Base，再在 AMEX、AITZ、Mind2Web 上做动作微调。骨干两条：InternVL-2-4B（AnyRes 切块）和 Qwen2-VL-7B（动态视觉 token）。ScreenSpot 标准设置（无 planner）下，OS-Atlas-Base-7B 的文字 / 图标为：手机 93.04 / 72.93，桌面 91.75 / 62.86，网页 90.87 / 74.27，平均 82.47。加 GPT-4o 当 planner 后平均 85.14。消融写了两句对课程有用的话：指称表达数据几乎已够训强接地模型，比指令接地更容易放大；只在网页上预训练，很难迁到桌面和手机，所以桌面 / 手机采集设施不是锦上添花。

OSWorld 上，他们把 GPT-4o 代理的坐标替换成外部接地模块。表 3 给出按应用域划分的成功率：人类 75.00 / 61.70 / 80.85；GPT-4o + OS-Atlas-Base 高于 SeeClick 和原始 SoM 提示，但仍远低于人类。本课引用这条，是为了阻止“接地基准高就等于电脑代理已解决”。

对本课共享头的直接教训：动作表要先合并同义名，再谈跨身体。如果 UI 头输出 `tap`、桌面头输出 `click`、机器人头输出 `move_xy`，共享二维特征也会被词表撕开。

OS-Atlas 的三种使用方式（图 1）也值得写进接口文档。Grounding 模式：只根据指令出坐标，外面再接一个规划器，OSWorld 实验就是 GPT-4o 规划加 OS-Atlas 出点。Action 模式：零样本直接出一步动作，用来测 OOD。Agent 模式：在下游轨迹上再 SFT，变成专用代理。本课的共享二维头对应 Grounding 模式。你若只有 Action 模式的逐步成功率，不能反推接地头已经过关，因为动作类型对了、坐标错了，逐步成功率一样会低。他们的指标拆成 Type、Grounding、SR 三列，就是防止这种混淆。缩小实验至少要同时报动作类型准确率和位置 $L_2$。

数据缩放图（图 3）给出另一条可在玩具里模仿的曲线：接地准确率和 IoU 随数据量上升，IoU 和网页域（元素最多，接近一千万）的斜率更陡。点中框对细误差不敏感，所以他们建议以后用更难的基准和 IoU。本课的连续 $L_2$ 比点中框更接近 IoU 的精神：格子中心即使仍在大按钮里，$L_2$ 也会暴露分辨率不够。

### 5.9 UI-TARS：原生代理把接地嵌进端到端轨迹

UI-TARS 官方报告的立场是：模块化代理框架（感知模型 + 接地脚本 + 提示词工作流）能出演示，但工作流写在人脑子里，换任务就要改提示。原生代理把感知、推理、记忆、动作收进同一组参数。它只看截图，输出类人键鼠。训练 Qwen-2-VL 的 7B 和 72B，约 500 亿 token。

报告列出四项技术，对本课有用的是前两项，后两项说明接地不是全部。

增强感知：用解析工具从网站、应用、操作系统抽元素类型、框、文本，再做元素描述、稠密配图说明、状态变化说明、问答和 SoM 提示。信息密度和 10×10 图标是他们强调的 GUI 特有困难。

统一动作与接地：动作表见 5.5。接地数据把开源集合（含 SeeClick、OS-Atlas 等）收进同一格式。表 2：网页元素 1480 万、手机 250 万、桌面 110 万；多步轨迹网页 6400、手机 14.5 万，桌面开源轨迹为 0，自家标注平均 14.9 步。框取中心点，输出相对坐标。

System-2 推理：从 MINT 和 OmniCorpus 筛教程，粗筛加细筛后约 600 万条高质量 GUI 教程（引言里写爬取 6600 万，过滤后是这 600 万），平均 510 个文本 token、3.3 张图。再给轨迹补 thought：任务分解、长期一致、里程碑、试错、反思。形式是 $(\mathrm{instruction},(o_1,t_1,a_1),\ldots)$。为了省上下文，只把最近 $N$ 张截图送进去，动作和 thought 历史保留。

在线迭代：数百台虚拟机滚轨迹，规则 + VLM 打分 + 人工过滤，再用 DPO 做错误纠正和事后反思。这和[第 17 课](17_grpo_rlvr.md)的可验证奖励是亲戚，但 GUI 的“对错”往往不是单位测试，报告用的是偏好对，不是本课的二维 $L_2$。

数字（全部来自 2501.12326 摘要与正文，不把后续 1.5 / 2 的表混进来）：OSWorld 上 UI-TARS-72B 在 50 步 24.6、15 步 22.7，对照 Claude Computer Use 的 22.0 和 14.9；AndroidWorld 46.6，对照 GPT-4o 的 34.5；VisualWebBench 上 72B 为 82.8，GPT-4o 为 78.5；ScreenSpot Pro 38.1。这些是任务级或专业接地基准，不是本课 CPU 实验能复现的量。

对本课：UI-TARS 选择连续相对坐标而不是强制 SoM 分类，说明两条头都有人走到生产规模。本课不站队“必须 SoM”或“必须回归”，只要求你量过低分辨率下谁更脆，并且承认同一套二维头可以两边用。

感知五项任务可以当作共享头之前的辅助损失。元素描述强迫模型说出类型、外观、相对位置、功能；稠密配图说明强迫它读整页布局；状态变化说明强迫它看两帧之间的差别；问答强迫它做视觉推理；SoM 提示强迫它把元素和空间标记绑在一起。UI-TARS 并没有把 SoM 当成唯一输出，而是当成感知课。Magma 则把 SoM 当成动作输出。两者都用编号，监督位置不同。写实现时要在配置里写明：编号是输入提示、辅助损失，还是动作本身。混用会让你无法解释 ScreenSpot 的数字来自哪一条出路。

推理模式也不要口头化成“模型会思考”。报告列出的可标注模式是任务分解、长期一致、里程碑识别、试错、反思。ActRe 给每一步倒填 thought：已知当前动作 $a_n$，用 VLM 根据前文生成 $t_n$。这是事后解释，不是环境里的搜索。在线阶段才用虚拟机真正试错，再用 DPO 把“错误动作 / 纠正动作”成对喂回去。本课 CPU 实验没有 DPO，不要把 `checks` 通过写成“已经具备 System-2”。若你要在缩小模型里加 thought，先固定动作标签，再倒填一句不超过 40 字的中文理由，检查删除该句后坐标是否不变。坐标变了，说明 thought 泄漏了不该泄漏的位置词，训练会走捷径。

### 5.10 分辨率敏感度：为什么低分辨率时连续头先垮

把视觉编码器看成 $S\times S$ 的占用网格。目标点 $\mathbf{u}^\star$ 被读成所在格的中心 $\mathbf{c}(S)$。连续头哪怕把格子中心到真值的残差学到 0，推理时仍只能看见 $\mathbf{c}(S)$，于是

$$
\varepsilon_{\mathrm{reg}}(S)\ge\lVert \mathbf{c}(S)-\mathbf{u}^\star \rVert_2
$$

$S=4$ 时右端典型是 $0.05$–$0.12$；$S=32$ 时降到百分之几。SoM 若分类正确，动作用的是物体中心 $\mathbf{u}^\star$ 本身，

$$
\varepsilon_{\mathrm{SoM}}=0 \quad \text{（编号正确）}
$$

因此低分辨率夹具是：

$$
\varepsilon_{\mathrm{reg}}(4)>\varepsilon_{\mathrm{SoM}}(4)
$$

这条不等式在编号撞格时会反转，所以实验必须先检查 $4\times 4$ 下每格至多一个标记。CPU 实验用 12 个分散的点，连续头的格子中心 MSE 约为 $1.08\times 10^{-2}$，正确 SoM 的位置 MSE 为 0，同时正确编号的交叉熵约为 0.41、错误编号约为 2.73。交叉熵和 MSE 量纲不同，不能横着比；位置误差可以横着比。

共享头的最小可训练版本不必上 Transformer。设观察为格子中心 $\mathbf{c}$，预测 $\hat{\mathbf{u}}=s\mathbf{c}$，UI 和桌面样本共用同一个 $s$。从 $s=0.55$ 做一步梯度下降，$s$ 升到约 0.68，UI 的 MSE 从 0.120 降到 0.055，桌面从 0.102 降到 0.053。这就是验收句“同一头在 UI 和桌面上都能降低误差”的玩具版。它不证明 8B 模型，只证明损失在两个域上连在同一参数上。

把这条不等式和视觉 patch 对齐。第 08 课的动态分辨率把图切成 tile，每个 tile 再切 patch。设 patch 边长为 $p$ 像素，图像短边缩放到 $H$，则 $S\approx H/p$。CogAgent 低分辨率 $H=224$、$p=14$，得到 $S=16$，半格约 $0.031$；高分辨率 $H=1120$ 得到 $S=80$，半格约 $0.006$。教学实验的 $S=4$ 对应“几乎看不见图标”的极端，半格 $0.125$，连续头不可能靠分箱补回来。$S=32$ 接近“普通 VLM 看桌面”的带宽。Lab 的滑条只提供 4、8、16、32 四档，是为了让不等式在 4 上稳定出现，不是为了模拟 1120 输入。

编号分类的误差来源不同。字体渲染在 $S=4$ 时可能糊成色块，但只要每个色块仍对应唯一编号、且分类头看见的是“哪一块被点亮”而不是 OCR 出数字，理论上仍能选对。Lab 的 SoM 头正是这样实现的：用物体是否独占一格决定会不会混，不真的做 OCR。这和真实 SoM 有差距。真实模型必须读出叠在像素上的字形。CogAgent 强调高分辨率就是为了 OCR。写局限时要写这一句：教学 SoM 在低分辨率下的优势，部分来自“编号以离散 id 的形式直接进头”，真实系统还要付 OCR 成本。CPU 实验不过 OCR，只过分类交叉熵。

### 5.11 把共享头接到现有 VLM 上时要改哪几处

没有 MiniMind 源码时，改公开 VLM 也按同一清单，避免只换数据集不改接口。

视觉输入。GUI 截图和桌面相机都走现成的图像预处理器。记录预处理后的 $(W',H')$，归一化必须用这对尺寸，不能用原图像素尺寸。Qwen2-VL / Qwen2.5-VL 会按动态分辨率改 token 数，见[第 08 课](08_dynamic_vision.md) 的 tile 讨论；解码坐标时要用模型实际看到的网格，而不是显示器分辨率。

坐标解码。若语言模型直接吐 `(0.49, 0.40)` 这样的字符串，解析失败要记为无效样本，不能默认成屏幕中心。若走 256 档 token，词表偏移必须冻结在配置里：OpenVLA 用尾部 256 个 token 表示动作，Magma 对坐标也量化到 256 档，两套 256 不要共用 id 段。CPU 实验的档位是数学上的 $\{0,\ldots,255\}$，不占用真实词表。

损失位置。只在动作 token 上算 $\mathcal{L}_{\mathrm{reg}}$ 或 $\mathcal{L}_{\mathrm{SoM}}$，指令和截图占位 token 的 label 为忽略。这和第 01 课的 assistant-only mask 是同一纪律，见[第 01 课](01_baseline_reproduction.md)。若把整段 thought 也算进回归，模型会学着在句子里抄数字。

双域 batch。每个 step 从 UI 和桌面各抽相等条数，或按第 26 课的 $p_d\propto n_d^{\alpha}$ 并把 $\alpha$ 写进配置。日志里分别记下 $\mathcal{L}_{\mathrm{UI}}$ 和 $\mathcal{L}_{\mathrm{arm}}$。只报平均损失时，大域会把小域的反弹盖掉。

动作词表。启动训练前打印一次 unique action names。出现 `tap` 和 `click` 并存就停。OS-Atlas 把这一步做成预训练之后的微调约束；你在玩具里用一张别名表替换即可。

评测探针。固定 20 个点：10 个 UI、10 个桌面，分辨率 $S=4$ 和 $S=32$ 各跑一遍。通过条件抄第 8 节的表，不要用 MiniWob 分数代替。

这条清单执行完，才能说“共享二维头已经接到模型上”。接上头不等于 Magma，也不等于 UI-TARS。

## 6. 数据与训练 recipe

真实系统不会只喂 12 个点。把公开 recipe 按“观察 / 接地 / 动作 / 推理”四层排列，避免把别人的预训练阶段抄进自己的微调脚本。

**观察层。** CogAgent：合成文字渲染约 8000 万、自然图 OCR 1800 万、学术文档 900 万、视觉接地 4000 万，再加 CCS400K 网页。SeeClick：约 30 万网页（Common Crawl）、公开手机 widget captioning（约 2 万张、4 万控件、10 万描述）和 RICO，混 LLaVA 以保持自然图能力。OS-Atlas：五个平台的指称表达为主，指令接地为辅。Magma：SeeClick + Vision2UI 约 270 万 UI 截图，OXE 97 万条轨迹、940 万图文动作三元组，视频约 2500 万样本（约 400 万镜头一致片段），再加 ShareGPT4V / LLaVA-1.5 / OCR 构成的 82 万 SFT。UI-TARS：感知任务加大规模截图元数据，具体抓取量正文未写成单一总数，其技术报告未把原始截图库存成一个可引用的“共 N 张”。

**接地层。** 任务三元组固定为 $\langle$截图，指令或指称，点或框$\rangle$。SeeClick 同时做 text2point、text2bbox、point2text、bbox2text。OS-Atlas 强调指称表达可放大，网页预训练迁不到桌面。Magma 在所有图像上渲染 SoM，视频和机器人再加 ToM。UI-TARS 对框取中心，输出相对坐标。

**动作层。** 先统一命名，再混轨迹。OS-Atlas 用三份轨迹做动作微调，把其余基准留作零样本 OOD。UI-TARS 把 MM-Mind2Web、GUIAct、AITW、AITZ、AndroidControl、GUI-Odyssey、AMEX 收成一张表。Magma 把 UI 动作写成文本字典，机器人动作写成尾部 256 token。不要在这一层把 7-DoF 和 `Click(x,y)` 直接拼成同一段字符串而不做规范化。

**推理层。** UI-TARS 才把 thought 当成一等公民。CogAgent / SeeClick / OS-Atlas 的主损失仍是下一步动作。若你的缩小实验没有 thought，不要声称复现了 UI-TARS 的 System-2。

**建议的教学规模混合（不是论文规模）：**

| 桶 | 内容 | 损失 | 占比起点 |
|---|---|---|---|
| A | 玩具 UI 点击 | $\mathcal{L}_{\mathrm{SoM}}$ 或 $\mathcal{L}_{\mathrm{reg}}$ | 0.4 |
| B | 玩具桌面 $xy$ | 同一 $\mathcal{L}_{\mathrm{reg}}$ | 0.4 |
| C | 动作类型分类（click/type/scroll） | 交叉熵 | 0.2 |

$\alpha$ 采样和第 26 课一样：按条数会让截图淹没桌面。教学上两域各半。禁止用本表的占比去改写 Magma 的 3900 万样本构成。

桶 C 的标签不要写成自由文本。click / type / scroll 做成三个整数，和 SoM 编号一样检查范围。type 需要字符串时，字符串走独立的语言损失，位置仍由 $\mathbf{u}$ 提供，例如先点中输入框再出字。SeeClick 和 UI-TARS 都把“点哪里”和“写什么”拆开。有人用一条 `type("hello")` 字符串当唯一监督，位置被藏在模型自己想象的插入点里，共享二维头就没有标签了。桶 B 若只有 7-DoF 没有图像投影，先做投影再入库，投影失败就丢弃。不要用关节角冒充 $\tilde{x}$。

每个 epoch 结束打印四行：A 的点中框或 $L_2$，B 的 $L_2$，C 的类型准确率，以及把 A 的头直接评在 B 的图像上的 $L_2$。最后一行是跨域探针。若 A 很好、跨域探针很差，共享只发生在优化器日志里，没有发生在表示里。CPU 实验的共享 $s$ 保证跨域探针和训练域一起降；换成两套 $s$ 各管一域，跨域探针不会降，那条对照值得写进自己的笔记。

许可与污染：ScreenSpot、Mind2Web、OmniAct 被 OS-Atlas 从训练里剔除以免评测泄漏。你若微调开源接地模型，先读他们的排除列表。GUI 截图常含个人信息，SeeClick 写了脱敏；本课玩具 UI 不使用真实截图。

把 Magma 的 3900 万样本按“有没有动作标签”再切一刀，避免把配图说明算成操作数据。ShareGPT4V 和 LLaVA-1.5 的 82 万是言语智能，用来防止空间训练冲掉 VQA。SeeClick / Vision2UI 的 270 万张 UI 有元素框，可以渲染 SoM，是真正的数字世界动作接地。OXE 的 940 万三元组有 7-DoF，是物理世界动作。视频的 2500 万没有 7-DoF，靠 ToM 才进入动作相关桶。写自己的混合表时，这四类要分列。只报“一共多少百万”会把 VQA 样本算进接地预算。

Magma 的对照模型也按这一刀来读。Magma-8B (SFT) 只吃 82 万指令，没有跨域动作。Magma-8B (UI) 和 (OXE) 各吃一边。Magma-8B (ACT) 把 UI 和机器人原始动作拼在一起。Magma-8B (Full) 才加视频并打开 SoM+ToM。表 3 显示 ACT 相对单域并没有双赢：ScreenSpot 总体 56.2，低于只吃 UI 的 57.7；Bridge 17.5，低于只吃 OXE 的 22.2。Full 不加 SoM+ToM 时 Act-G 只有 25.2，加上之后才到 71.8。引用 Magma 时写清是哪一个变体。本课共享 $s$ 头对应 Full 的“同一套二维参数”，对应不了 Full 的 8B 和 3900 万。

空间推理表（表 6）用来防止另一种过度宣称。Magma-8B (Full) 在 VSR 上 65.1，BLINK-val 41.0，部分 SpatialEval 子项高于 LLaVA-1.5。去掉 SoM/ToM 的 Full 变体在若干子项上会掉。这说明替代监督不只服务点击和抓取，也抬了“图里谁在谁左边”这类问题。它仍然不是机器人学里的运动学求解器。BLINK 41.0 离满分很远，GPT-4o 在同一表上是 60.0。本课不把空间问答应对，写成已经会控臂。

零样本 SimplerEnv 的读法也要克制。Magma 强调 OpenVLA 用真机轨迹预训练，迁到仿真有域差；自己因为吃了更多异构数据，对视觉匹配和变体聚合更稳，平均成功率几乎是 OpenVLA 的两倍，并在“把物体放进抽屉”“胡萝卜放到盘子上”这类基线经常为零的任务上仍有成功。图 8 还比较了只吃 OXE 的 Magma(OXE) 和完整预训练：完整版更好，用来支持“从视频和 UI 学到的空间智能帮了操作”。这些是仿真器里的成功，第 31 课的纪律仍然适用：要写视觉域、是否 visual matching、试验次数。正文没有把每个子任务的成功次数写成可引用的整数表，需要该整数时打开原图或附录，不要估算。

UI-TARS 的接地表按平台拆开还有一层含义：桌面开源多步轨迹是 0。桌面代理的多步能力几乎完全依赖自家标注（平均 14.9 步）和在线滚轨迹。你若只下载 SeeClick 的网页元素来训，桌面长程不会自动出现。OS-Atlas 补上桌面接地元素，补的是单步指称，不是长程轨迹。两篇论文合在一起读：元素级数据和轨迹级数据是两种预算。

合成数据时的最小合法字段如下，缺一项就不要写入训练目录。

| 字段 | UI 样本 | 桌面样本 |
|---|---|---|
| 图像路径与 $(W,H)$ | 必填 | 必填 |
| 指令文本 | 必填 | 必填 |
| 目标点或框，像素单位 | 必填 | 必填 |
| 归一化 $\mathbf{u}$ | 由像素当场算，不入库假装已算好 | 同左 |
| SoM 编号与渲染图 | 若走分类头则必填 | 同左 |
| 动作类型 | click/type/scroll 等 | grasp/move 等，不与左列共用字符串 |
| 7-DoF 或夹爪 | 不填 | 可选，不进 $\mathcal{L}_{xy}$ |
| 来源与排除标记 | 是否与 ScreenSpot / Mind2Web 重叠 | 是否与评测集轨迹重叠 |

“当场算归一化”是为了防止有人用 1080P 的 $W,H$ 去除已经裁过的图。CPU 实验每次都从像素重算，就是把这条写成可执行断言。

## 7. 按依赖顺序执行实验

实验分三层。第一层必须在无 GPU 时通过。第二层是浏览器教具。第三层只有在你真的微调开源模型时才跑，数字要带套件名和是否 fine-tune。

### Step 1: CPU 机制实验

在 `experiments/` 下核对隔离脚本（本课不改 `registry.py`，编排者接入后再改成 `run.py run 32`）：

```bash
PYTHONPATH=src python3 -c "from learn_omni_experiments.lessons.lesson_32 import run; print(all(run()['checks'].values()))"
```

预期打印 `True`。失败时看 `checks` 里哪一条是 `False`：单位正方形、256 档边界、编号范围、低分辨率不等式、共享头双域下降、宽高对调、错误编号交叉熵。

### Step 2: 浏览器双屏教具

打开本课页面的 Lab。左屏六个带编号按钮，右屏六个带编号物体。先在四个选项里选一句关于 $4\times 4$ 的预测，再按“揭晓误差”。把训练步拉到至少 4，确认 UI 误差和桌面误差相对 0 步都下降，且 $4\times 4$ 探测行里连续误差大于 SoM。教具标题写明教学模拟。

教具内部的计算可以手工复核，避免把它当成黑盒分数。连续头在训练步 $t$ 的预测是格子中心与真值的插值：

$$
\hat{\mathbf{u}}(t)=\mathbf{c}(S)+(1-0.68^{t})(\mathbf{u}^\star-\mathbf{c}(S))
$$

$t=0$ 时报 $\mathbf{c}(S)$；$t\to\infty$ 时逼近 $\mathbf{u}^\star$，但仍受 $\mathbf{c}(S)$ 在更粗网格上的限制——探测行强制用 $S=4$ 再算一遍，所以即使用户把滑条停在 32，验收用的低分辨率不等式仍然可触发。SoM 头在 $t$ 足够大且该物体独占一格时，直接返回 $\mathbf{u}^\star$，位置误差为 0。若两物体同格，预测在两者之间插值，误差不再为 0。六个 UI 按钮放在四角和上下中点，六个桌面物体放在不同象限，为的是 $S=4$ 时不撞格。你若自己改坐标，先数每个格子里有几个编号。

共享训练不按当前“观察域”开关来。开关只改变你看哪一侧的预测点。梯度始终混用两侧样本。所以会出现：你正盯着左屏，右屏误差也在降。这是验收句“同一头”的字面意思。若改成“只训练当前域”，桌面误差在只看 UI 时不会降，验收应当失败。现在的实现不允许那种作弊。

建议的操作顺序：分辨率先放到 32，训练步放到 0，选预测，揭晓，记下连续 / SoM 两行；再把分辨率拖到 4，再揭晓，确认连续行变大、SoM 行仍接近 0；最后把训练步拖到 4 以上，确认 UI 和桌面两列相对 0 步都下降。中途改预测或改滑条会清空揭晓，防止先看数字再选答案。

### Step 3: 可选，开源接地模型的单步探针

只在有 GPU 且你接受“这不是课程最低交付”时进行。选 SeeClick 或 OS-Atlas-Base 的公开权重，用自己拍的一张英文桌面截图，指令写“click the close button”，记录预测点是否落在关闭按钮框内。样本数小于 25 时不要报成功率，只报逐例命中。评测纪律见第 31 课。

### Step 4: 不要做的事

不要把 Lab 的误差写成 Magma 的 SimplerEnv 数字。不要在 CPU 实验通过后声称“统一身体已经验证”。不要用 HTML 元素 id 冒充视觉坐标。

## 8. 评测与测量

接地和代理是两张表。混用就是第 31 课反对过的“横着比成功率”。

**单步接地。** ScreenSpot：点中框。OS-Atlas 另报 IoU，因为点中框对“点在框边缘”不敏感。UI-TARS 报告了 ScreenSpot Pro（专业高分辨率软件），72B 为 38.1，说明日常 ScreenSpot 变容易之后还要换更难的考卷。本课玩具指标是归一化 $L_2$ 和编号准确率。

**逐步代理。** Mind2Web 报 Ele.Acc、Op.F1、Step SR。SeeClick 纯视觉 cross-task Step SR 25.5；CogAgent 62.3；Magma 微调后 cross-website / cross-task / cross-domain 的 Step SR 为 45.4 / 43.4 / 47.3。AITW 的口径更乱：SeeClick 用指令级划分 overall 59.3，CogAgent 用原划分 overall 76.88，Magma 微调 overall 67.3。不同划分不能减出“谁进步了 10 个点”。

**在线任务。** OSWorld、AndroidWorld 改环境状态，看是否到达目标。UI-TARS-72B：OSWorld 50 步 24.6、15 步 22.7；AndroidWorld 46.6。OS-Atlas 表 3 的人类对照说明这些分数离“能当电脑用户”还很远。

**机器人。** Magma 零样本 SimplerEnv：Google Robot 52.3、Bridge 35.4，对照 OpenVLA 的 31.7 和 14.5。LIBERO 上他们用每任务 10 条轨迹做 few-shot，文中用图报告相对 OpenVLA 更高的平均成功率，没有在正文里写成可抄的单一百分数；需要该数字时打开原图，不要凭记忆写。真机 WidowX 是约 50 条轨迹、每任务 10 次试验的 few-shot，不是大规模真机统计。

**本课最低测量。**

| 量 | 定义 | 通过 |
|---|---|---|
| $\varepsilon_{\mathrm{reg}}(4)$ | $4\times 4$ 格子中心到真值的平均 $L_2$ | 大于 $\varepsilon_{\mathrm{SoM}}(4)$ |
| $\varepsilon_{\mathrm{SoM}}$ | 编号正确则为 0，否则到错误物体中心 | $4\times 4$ 无撞格时应为 0 |
| $\Delta_{\mathrm{UI}}$ | 共享头训练后 UI 的 MSE 变化 | 必须为负 |
| $\Delta_{\mathrm{table}}$ | 桌面 MSE 变化 | 必须为负 |
| 越界率 | 归一化后落在 $[0,1]^2$ 外的比例 | 0 |

## 9. 验收条件

课程通过只看机制，不看是否跑通 18B。

1. 课文第一个 H2 是“屏幕点击和机械臂动作有什么共同结构”，并能用三段流水线解释。
2. CPU 实验八条 `checks` 全为 True。
3. 交互实验：先提交预测“低分辨率下连续坐标误差大于 SoM”，再把共享头训练到至少 4 步，UI 与桌面误差同时下降。
4. 能指出 Magma 原文中 SoM 与 ToM 的分工，以及“UI 不用 ToM”。
5. 能指出至少一处动作空间分叉：例如 UI-TARS 的 `Hotkey` 没有机械臂对应物，或 7-DoF 的夹爪不进入 $\mathcal{L}_{xy}$。
6. 引用 ScreenSpot / Mind2Web / OSWorld 时写了基准名、模型名和设置（是否 planner、是否 fine-tune、步数限制）。

出现以下任一情况，实验无效：揭晓前能看到误差数字；只用 UI 域训练却声称桌面也下降；把 HTML 命中写成视觉接地；把 UI-TARS-2 的数字写进 2501.12326 的表。

通过最低交付之后，允许加一条可选记录：在 $S=8$ 和 $S=16$ 上各报一次 $\varepsilon_{\mathrm{reg}}$ 与 $\varepsilon_{\mathrm{SoM}}$。预期连续误差随 $S$ 上升而下降，SoM 在不撞格时保持接近 0。这条曲线是给自己看的，不写进对外的“论文复现”。若 $S=16$ 时连续误差反而比 $S=8$ 大，先查格子索引是否用了 `floor(u*S)` 在 $u=1$ 时越界，再查 Lab 是否在改分辨率后还缓存着旧预测。交互实验每次改滑条都清掉揭晓，就是为了逼你重新跑一遍，而不是对着过期数字写结论。

## 10. 根据症状定位失败环节

| 症状 | 先查 | 不要先做 |
|---|---|---|
| 损失下降，点总偏一个按钮 | 编号从 0 还是从 1 起，渲染是否 `idx+1` | 加学习率 |
| 归一化后 $x>1$ | 宽高是否对调，原点是否左上 | 换骨干 |
| 低分辨率下 SoM 也差 | 是否两标记同格，数字是否被图标吞掉 | 宣称 SoM 对分辨率免疫 |
| 连续头在 32×32 仍很差 | 监督是中心点还是框角，是否用了 $[0,999]$ 却按 $[0,1]$ 解码 | 立刻上 18B |
| UI 变好、桌面变差 | batch 是否只含截图，共享参数是否被 UI 词表撕开 | 加机器人数据而不改动作名 |
| 桌面 $xy$ 对、$z$ 乱 | $\mathcal{L}_{xy}$ 是否错误地回传到 7-DoF 全体 | 关掉 SoM |
| Mind2Web Ele.Acc 低、Op.F1 高 | 会选动作类型，不会选位置 | 只加 thought 数据 |
| OSWorld 远低于 ScreenSpot | 接地单步好，多步与状态变化差 | 用 ScreenSpot 宣布代理 SOTA |
| 真机碰到杯子却抓空 | 二维接地成功，接触和深度失败 | 在本课里加世界模型 |

第 07 课的 CONTINUE / PAUSE / REPLAN 在 GUI 里也有对应物：点错了是 REPLAN，弹窗等待是 PAUSE。不要把语音路由代码抄过来，只借用状态名，见[第 07 课](07_full_duplex_routing.md)。

再补一组和本课公式直接相关的症状。预测永远是 $(0.5,0.5)$：检查解码器是否在解析失败时回落到画面中心，以及训练标签是否整列写成了 0.5。预测集中在左上角：几乎总是把 $[0,999]$ 或 $[0,1000]$ 的整数当成了 $[0,1]$ 的小数，或用预处理后的小图尺寸去除了原图像素。预测集中在右下：符号反了，或把原点当成左下却按左上渲染。SoM 准确率接近 $1/K$：编号没有进视觉，只进了文本，或渲染用黑色数字叠在深色按钮上，OCR 等于没有。双域损失一条降一条升：学习率对小域过大，或动作字符串未归一导致词表梯度主导。这些检查都只需要打印直方图和三张图，不需要再下数据集。

## 12. 前沿对照与改造方向

**公开方案。** 同一问题，2023–2025 年的公开系统分成四条路。CogAgent 用高分辨率交叉注意力解决“看见小字”，用截图在 Mind2Web 上超过 HTML 代理。SeeClick 把 GUI 接地设成预训练任务，并交出 ScreenSpot。OS-Atlas 把数据规模推到千万级元素，并把动作名冲突收成基本动作加自定义动作。UI-TARS 把模块化框架收成原生端到端模型，动作用于统一表，推理写成 thought，数据用虚拟机迭代。Magma 是唯一公开把 UI 和机器人放进同一预训练、并用 SoM / ToM 当跨域接口的基础模型。它在零样本 ScreenSpot 上手机 60.4 / 58.5、桌面 75.3 / 52.9、网页 69.1 / 52.0，并不处处超过 SeeClick 的手机文字 78.0；它的主张是覆盖全谱任务，而不是在单一 GUI 基准上独占。SimplerEnv 上相对 OpenVLA 的优势（52.3 vs 31.7，35.4 vs 14.5）用来支持“空间智能可以从异构数据迁到操作”，前提是 SoM+ToM 已打开。

Qwen2.5-Omni / Qwen3-Omni 的公开技术报告以听、说、看为主，未把 GUI 点击和 7-DoF 写成与 Magma 同级的预训练目标。其技术报告未公开“与 Magma 共享二维头”这一设定。Moshi 是语音全双工，与本课动作空间无关。不要把 Omni 的语音能力写成已经会点屏幕。Nemotron Omni 的公开 recipe 覆盖文本和视觉后训练，同样没有给出屏幕点击与末端 $xy$ 的联合损失。把这些系统列在这里，是为了划界：能听会说的 Omni 和会动手的 VLA 在第一波课里仍然是两条线，合流放到第 48 课的规格里，本课不提前兑现。

规模能堆的部分也要说具体。OS-Atlas 的网页过滤从 370 万张截图、3700 万元素收到 160 万张、770 万元素，靠的是渲染完整页、去掉 404、限制每页元素数。UI-TARS 的教程从约 6600 万候选收到约 600 万，靠 fastText 粗筛、语言模型细筛、URL 与 LSH 去重。Magma 的视频靠镜头切分和 CLIP 0.25 阈值。三条流水线都是“先放大再狠滤”。缩小实验没有资格模仿过滤规模，但可以模仿纪律：写入训练集之前必须有一条可执行的过滤函数，哪怕只是“编号不撞格”和“$\mathbf{u}$ 在单位正方形内”。没有过滤函数的数据目录，不算 recipe。过滤函数要返回被丢样本的原因码，例如 `out_of_unit_square`、`mark_collision`、`missing_projection`。只返回布尔值，以后你无法统计是投影失败多还是撞格多，也就无法决定下一步该修相机还是该改渲染。

**差距。** 规模差距：百万到千万级截图、OXE 级轨迹、500 亿 token，钱能堆。机制差距：归一化与分箱、SoM 对回归、动作名合并、高分辨率带宽、低分辨率夹具，本课能做。评测差距：OSWorld 24.6 和人类 70+ 之间的洞，不是再训一个玩具头能填的；那是多步、状态、应用内 API 限制，交给后续课。

**改造实验。**

1. 把连续头的两位小数改成 Magma 的 256 档 token，只改动作解码和词表偏移，数据用本课 12 个点加随机抖动到 1 千条。预算：CPU 数分钟。预期：档中心反量化误差不超过半档；把 $B$ 改成 8 时，量化误差必须可见变大。失败：反量化后 $L_2$ 与 $B$ 无关。
2. 在交互实验的 6 个按钮上故意让两个按钮挤进同一 $4\times 4$ 格，比较 SoM 与连续头。预算：改 Lab 坐标，不训练。预期：撞格后 $\varepsilon_{\mathrm{SoM}}$ 不再为 0，不等式可能反转。失败：撞格后 SoM 误差仍报 0。
3. 给共享 $s$ 头加一个不可共享的动作类型嵌入（click vs grasp），只让类型嵌入进入动作分类，不进入 $\mathbf{u}$。预算：CPU 一小时级的小型逻辑回归。预期：位置 MSE 仍双域下降，动作类型准确率可分开统计。失败：去掉类型嵌入后 click 和 grasp 的混淆率不变。
4. 若有 1×24GB：在 OS-Atlas-Base 或 SeeClick 公开权重上，用 100 张自有截图比较“直接回归”和“先用开源检测器画 SoM 再分类”。预算：单卡若干小时推理，不微调。预期：图标密集屏上 SoM 命中不低于回归，文字大按钮上两者接近。失败：两种接口在全部 100 张上误差相同且都不随图标密度变化。样本不够 25 时只发逐例表。

**顺手复现映射。** Magma 表 3“直接混 UI 和机器人动作会掉点，SoM+ToM 才能一起涨”对应本课共享 $s$ 头：把桌面目标改成与 UI 完全不同的尺度且不做归一化，双域 MSE 不能同时降；做归一化后可以。SeeClick 图 6“接地提升与下游代理提升同向”在教学规模只能看到“位置误差降、点击命中升”，看不到 MiniWob 67.0。方向可复现，绝对值不能。

CogAgent 表 5 的高分辨率消融对应 Lab 的 $S$ 滑条：224 对应粗网格，1120 对应细网格。教学实验没有交叉注意力，只保留“格子变细、连续误差下降”这一方向。OS-Atlas 的“只训网页迁不到桌面”对应：若共享头的训练 batch 删掉桌面样本，$\Delta_{\mathrm{table}}$ 不得为负。UI-TARS 的“相对坐标跨设备”对应 CPU 实验的单位正方形断言。这些映射全部是方向性的。谁把 82.47% 写进自己的 12 点玩具报告，就算评测造假。

改造实验的失败判定再补两条公共规则。任何一次 GPU 推理都要保存：权重哈希、预处理后的 $(W',H')$、原始预测字符串、解析后的 $\mathbf{u}$、以及人工框。缺哈希的结果不能进对照表。任何一次声称“SoM 更好”的比较，必须在同一视觉骨干、同一批图、同一指令上完成；换了检测器就不能把差值记在分类头上。

阅读时带着括号里的问题。数字以你打开的版本为准；本课引用的是下面列出的版本。

1. Magma: A Foundation Model for Multimodal AI Agents（arXiv:2502.13130，Yang 等，2025）。带着问题读：SoM 和 ToM 分别监督什么？为什么 UI 不用 ToM？表 3 里去掉 SoM+ToM 之后哪些基准掉得最狠？256 档是对坐标还是对机器人动作 token？（机器人动作另用词表尾部 256 token，不要和坐标分箱混成一句。）
2. Set-of-Mark Prompting Unleashes Extraordinary Visual Grounding in GPT-4V（arXiv:2310.11441，Yang 等，2023）。带着问题读：原始 SoM 是提示还是训练目标？标记为什么必须能被模型“说出来”？GPT-4V 直接吐坐标 25.7 和加 SoM 后 86.4 比的是哪项任务？
3. CogAgent: A Visual Language Model for GUI Agents（arXiv:2312.08914，Hong 等，CVPR 2024）。带着问题读：1120 分辨率如何避免 6400 token 的平方注意力？Mind2Web overall 58.2 的输入是截图还是 HTML？CCS400K 的 REC/REG 与 SeeClick 的 text2point 有何不同？
4. SeeClick: Harnessing GUI Grounding for Advanced Visual GUI Agents（arXiv:2401.10935，Cheng 等，2024）。带着问题读：ScreenSpot 为什么要把 Icon/Widget 单列？click accuracy 如何定义？MiniWob 67.0 用了多少轨迹，和 Pix2Act 比的是哪 35 个任务？
5. OS-ATLAS: A Foundation Action Model for Generalist GUI Agents（arXiv:2410.23218，Wu 等，2024）。带着问题读：1300 万元素是怎么按平台收的？统一动作空间从 17 收到 10 解决了哪些命名冲突？ScreenSpot 11.32% 错误如何影响你引用表 1？
6. UI-TARS: Pioneering Automated GUI Interaction with Native Agents（arXiv:2501.12326，Qin 等，ByteDance Seed，2025）。带着问题读：原生代理和模块化框架的差别写在第 2 节哪一段？表 1 哪些动作是共享的、哪些是桌面或手机特有的？OSWorld 24.6 的步数限制是 50 还是 15？过滤后的教程是 600 万还是引言里的 6600 万？
7. UI-TARS-2 Technical Report（arXiv:2509.02544）与 UI-TARS-1.5 发布页。带着问题读：它们相对 2501.12326 新增了什么（多轮 RL、沙箱、游戏与代码）。本课正文不把这些后发数字写进第 8 节的表。若报告没写的细节，就写“其技术报告未公开该细节”。

第 20 课讨论的是图像理解与生成能否共享骨干，见[第 20 课](20_unified_understanding_generation.md)。本课共享的是动作接地头，不是 flow matching 的速度场。下一课规格已指向世界模型：预测未来帧还是预测表征。本课的 ToM 只是标记轨迹，不要提前把 Cosmos 或 V-JEPA 2 的结论写进来。把 ToM 的二维折线当成世界模型，会在第 33 课里和表征预测的损失对不上账。本课停在这里：屏幕和桌面可以共用一套空间接地；未来像素、三维接触、长程记忆，都还没进这套头。若你现在就把“统一身体”理解成“一个模型已经能当电脑用户和家庭机器人”，回到第 8 节的禁止合并表，把 OSWorld 24.6 和人类对照再读一遍。机制成立，能力边界仍然很窄。把这条边界写进实验报告的第一页，比把 Magma 摘要里的 state-of-the-art 抄进标题更有用。读者应能在读完本课后独立复述：共享的是归一化二维目标，分叉的是动作语义，检验的是低分辨率不等式和双域损失同时下降。能复述这三句，并且 CPU 实验八条检查为真，本课就收工。交互实验还要留下一次先预测后揭晓的记录，证明你没有对着已经显示的误差去选答案。三项齐了，再去碰公开权重也不迟。公开权重只能检验同一套接口在真实截图上是否还能点中框，不能回头否定玩具里已经核对过的那套归一化公式和编号范围。点中框是推理口径，玩具 $L_2$ 是训练口径，两套数字不要写进同一格。
