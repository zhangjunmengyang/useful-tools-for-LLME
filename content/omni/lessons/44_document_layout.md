# 第 44 课：把文档版面从单图 OCR 里拆出来

> 内容：文档阅读顺序、表格单元格、跨页键值与 OCR-free 图像到文本<br>
> 建议周期：2-4 天读完并跑通 CPU 实验；若评开源文档模型，另加 1-2 天<br>
> 硬件：无 GPU 可完成全文与 CPU 夹具；1×24GB 可跑开源小模型发票探针；Donut / Pix2Struct 原预训练为多卡或多 TPU 作业，本课不要求复现<br>
> 产物：内容-框列联表、单元格命中公式页、阅读顺序对照、跨页键值日志、字段 F1 / TED 分列表

## 1. 版面和表格为什么不是单图 OCR

[第 23 课](23_grounding_ocr_spatial.md)已经把单图文字拆成两列：字符串对不对，区域盖没盖住字形。那一课的反例是招牌、菜单行、发票金额被语言模型猜出来，框却落在促销条上。本课把同一纪律从「一块字」扩到「一张有栏、有表、有页的文档」。文档理解（visual document understanding, VDU：从文档图像抽出结构化信息，而不是只生成一段读得通的话）失败时，字符串仍然可以全部正确。表头写着「金额」，合计栏也写着「32.00」，模型输出 32.00，评测脚本若只做子串匹配就会亮绿灯。框如果盖在表头那两个字上，单元格没有被找到。这是版面失败，不是识别失败。

第 23 课的 OCR 命中公式是 $\mathrm{Hit}_{\mathrm{OCR}}=\mathbf{1}[\mathrm{IoU}\ge\tau]\cdot\mathbf{1}[\mathrm{match}(\hat{s},s)]$。本课沿用合取，把对象从「一块字形」换成「一个字段所在的单元格」。字段有名字、有值、有坐标、有页码。表格还有行号和列号。跨页合同时，键在第 1 页、值在第 2 页。这些对象都不出现在单图 OCR 的默认账本里。单图 OCR 问：图上这些字是什么。版面问：这些字属于哪一栏、哪一行、哪一页、哪一个键。

两条公开路线把这件事做成了端到端生成。Donut（Document understanding transformer，[arXiv:2111.15664](https://arxiv.org/abs/2111.15664)）不再调用外部 OCR 引擎，编码器吃整页图像，解码器直接吐出可还原成 JSON 的 token 串。Pix2Struct（[arXiv:2210.03347](https://arxiv.org/abs/2210.03347)）走同一条像素进、文本出的路，预训练任务改成：把网页截图解析成简化 HTML。它们证明「可以不先跑检测+识别」。它们没有取消本课的评测列。生成模型仍可能读对数字、框错栏。本课要造的是把这两列拆开的协议，不是再训一个 1.3B 的截图解析器。

[第 08 课](08_dynamic_vision.md)管分辨率和位置编码：固定 256×256 会糊掉发票小字，动态切片改变的是眼睛被允许看多细。本课假定字形已经可读，要检查的是字段有没有落到正确单元格。08 的负对照是打乱二维坐标后 OCR 桶下跌。本课的负对照是：打乱阅读顺序、把框挪到表头、只给第 1 页。可以同一张发票两边都测，必须两个 run ID，禁止把「动态分辨率加版面」写成一个消融。

交互实验是一张教学发票。你先预测这一问会「内容对且框对」「读对数字但框在表头」「框对但数字错」还是「跨页键值失败」，再看玩具模型的字符串和它实际框住的格子。CPU 实验用固定框手算同一套公式，夹具里故意放进「32.00 对、框在表头」。做完这课你手里会有：一张禁止把字段字符串当成版面的报告模板；阅读顺序和跨页可见性的检查单；以及至少一例书面记录的「读对数字但框在表头」。

本课术语：

| 术语 | 简要解释 |
|---|---|
| 版面（layout） | 文档里标题、栏、表、页眉页脚的空间组织，决定阅读顺序和字段归属 |
| 单元格（cell） | 表格里由行、列交出来的格子，既有字符串也有框 |
| 阅读顺序 | 人眼扫文档的次序，通常先左栏后右栏，不是单纯按像素 $y$ 再 $x$ |
| 栅格扫描（raster） | 按从上到下、从左到右对检测框排序，双栏时会把右栏插入左栏 |
| 键值（key-value） | 「合计」对应「32.00」这类成对字段，键和值可以不在同一行，也可以不在同一页 |
| OCR-free | 推理时不调用外部检测+识别引擎，图像直接映射到文本或 JSON |
| 字段级 F1 | 一个字段字符串必须整段匹配才算抽出，漏一个字符整字段失败 |
| TED 准确率 | 用树编辑距离衡量预测 JSON 和真值 JSON 的结构差 |
| 版面命中 | 内容匹配且框 IoU 过阈值；只有内容对不算版面对 |

## 2. 本课解决的问题

当前系统（以及你按[第 22 课](22_standard_vlm_recipe.md)训出的任何视觉语言模型）若用 DocVQA、TextVQA、普通 VQA 验收，默认口径仍是文字对不对。Donut 在 DocVQA 测试集上的 ANLS 为 67.5，手写子集为 72.1（原文 Table 3）。Pix2Struct-Large 把同一测试集推到 76.6，InfographicVQA 为 40.0（原文 Table 1）。这些数字测的是「问句能否从页面里抽出一段对的文字」，不测「这段文字是不是从被问的那一格来的」。四类失败会被均分盖住：

1. 阅读顺序失败：双栏合同按栅格扫描，右栏金额插进左栏条款中间，JSON 的字段顺序跟着乱。
2. 单元格失败：合计数字对了，框在表头「金额」、邻行单价或页眉发票号上。
3. 结构失败：菜单名、数量、单价被抽出来了，嵌套的 `items[].price` 丢了，拍成一张扁平表。
4. 跨页失败：键在第 1 页，值在第 2 页，只编码第一页时模型用页眉数字顶上。

本课的改造范围只包括评测协议、记录字段和一小段可手算的命中公式。不更换视觉编码器，不重做第 23 课的 POPE 负例，不重训第 08 课的切片器。若你要在真实模型上微调 Donut 或 Pix2Struct，那是第 13 节的改造实验，不是主路径验收。

以下结果不能支持「模型会看版面」：

- 只报 DocVQA ANLS 或字段字符串准确率，没有单元格框、行号、列号或页码；
- OCR 只报「答案出现在整页识别结果里」，没有阅读顺序；
- 把 LayoutLMv3 在 FUNSD 上的 90.29 F1（BASE，原文 Table 1）写成 MiniMind-O 或本课夹具的预期；
- 把第 08 课动态分辨率带来的小字上涨，直接写成版面上涨；
- 把第 23 课「区域盖住字形」当成「单元格盖住字段」，两者的真值框不是同一个对象。

执行顺序固定：先在 CPU 夹具上证明公式可复核，再在教学发票上亲眼看到「读对数字、框在表头」，最后如果有 GPU，才把同一套探针接到开源权重上。没有 GPU 时，前两步已经构成完整交付。

和第 23 课的边界再写死一次。第 23 课的 OCR 对象是一块连续字形，真值往往是外接矩形或 mask。本课对象是字段：`{name, value, box, page, row?, col?}`。同一张发票可以同时进两课，必须两个 run ID。第 23 课涂黑字形看语言先验是否还在；本课把框从合计栏挪到表头，看字符串列是否还亮着。负对照不同，禁止合并。

## 3. 开始前需要准备什么

本课可以在没有 GPU 的机器上读完并跑通 CPU 实验。开始前在实验记录里分开写明上游事实和本课约定。

**上游事实：**

- 第 23 课给出 grounding 命中和 OCR 双列。本课复用 IoU 阈值 $0.5$ 和「字符串对不等于区域对」，不再重讲 POPE、CHAIR、左右参照系。
- 第 08 课若已做过，保留动态分辨率前端。本课所有单元格框都在 encoder 实际看见的像素坐标系里算，不要先把原图缩到糊掉再谈版面失败。
- Donut、Pix2Struct、LayoutLMv3 的数字全部来自已打开的原文表或段落，见第 14 节。
- Qwen2-VL / Qwen2.5-VL 的文档数字已在第 23 课对照原文引用，本课只借用「文档要带框」这一条，不重抄 72B 表。

**课程约定：**

- 教学发票和 CPU 夹具使用固定布局，不代表任何发布模型的成功率。
- IoU 阈值默认 $0.5$，与第 23 课、Kosmos-2 / 多数指代评测一致。改阈值必须单列。
- 内容匹配默认精确匹配。若改用 ANLS，报告必须写「ANLS」，不得和 exact match 混在同一列。
- 产出目录约定为 `artifacts/lesson44/`。CPU 实验在编排者注册后可用下面这条命令写入该目录；注册前可直接调用 `lesson_44.run()` 复核。

```bash
python3 run.py run 44
```

只读本课、不训模型时，仍需交：公式手算、教学发票两则对照（表头假成功 / 两列都过）、列联表空表。这条支线标记为 `protocol-only`，不能写成「复现了 Donut」。

建议花在各节上的时间：第 1–4 节约 40 分钟建立口径；第 5 节机制约 3 小时，公式要手算一遍表头 IoU、字段 F1 和 TED；第 6 节公开实现约 1 小时，打开仓库确认特殊 token；第 7–12 节边跑边写报告约半天；第 13–14 节按「带着什么问题读」打勾。Donut 与 Pix2Struct 必读，LayoutLMv3 用来对照「OCR 依赖路线」，Qwen2.5-VL 的文档 HTML 可按你是否继续做文档系统决定精读深度。没有 GPU 的人到第 12 节就可以停，第 13 节的改造实验标 `deferred`。

笔记本仍分两栏。左栏只抄打开过的论文句：表号、划分、分辨率、卡时。右栏写本课约定：原点左上、$\tau=0.5$、精确匹配、页码从 1 起、Lab 捷径阈值 0.55。左栏可以对外引用，右栏只能当教学夹具。有人把 Lab 里「框在表头」写成「复现了 Donut Figure 8」，属于把右栏抄进左栏。Donut Figure 8 是交叉注意力可视化，没有 IoU 表。

硬件分层写进记录，避免和论文卡时搅在一起。读课文和 CPU 实验：一台笔记本即可，本课夹具无网络、无 GPU、无文件副作用。教学发票在浏览器里跑，标了「教学模拟」。评 2B 级开源文档模型：1×24GB 通常够 greedy 解码加数十张发票，不够从零预训练。Donut 原文预训练 200k step、64 张 A100、batch 196，输入 $2560\times 1920$，解码最大长度 1536。Pix2Struct-Base 在 64 个 TPU 上用 batch 2048 做 270k step 截图解析，Large 在 128 个 TPU 上用 batch 1024 做 170k step。这些是他们的预训练，不是你的作业。

软件只需要 Python 3.10 标准库和能打开本课页面的浏览器。不要为了本课新装 OCR 引擎或表格检测器。主路径证明的是账本，不是检测器 AP。若你已经有 Tesseract 或 PaddleOCR，可以在 Step 6 当对照流水线，必须单列 `pipeline=ocr+parser`，并写引擎版本。Donut 原文 Figure 9 表明 OCR 基线的速度和准确率随引擎剧烈变化；你换一次引擎就要换 run ID，不能把两次 F1 的差写成「本课方法涨了」。

时间分配不要倒过来。有人一上来就去微调 Donut，两天之后才发现评测脚本没有框列，内容准确率 90%、版面命中无法定义。正确顺序是 Step 0 到 Step 2 先占用半天，确认公式和教学发票的表头假成功能被你自己的眼睛看见，再决定要不要烧 GPU。没有这一半天，后面的卡时都是在给错误的分子加数据。

## 4. 完成后应具备的能力

完成后，拿到任意「发票答对了」的样例，你应能完成以下检查：

1. 写出预测框与单元格真值框的 IoU，并按阈值判定框命中；
2. 写出内容匹配，并证明它可以和框命中同时为真或同时拆开；
3. 用合取定义版面命中，构造「读对数字、框在表头」；
4. 把双栏文档的栅格顺序和阅读顺序写成两条 token 序列，并数出逆序对数；
5. 对嵌套 JSON 算字段级 F1 和 TED 准确率，说明拍平结构会掉哪一列；
6. 声明跨页键值的可见页集合，缺值所在页时字段记失败；
7. 指出 Donut 的预训练是按阅读顺序读字，Pix2Struct 的预训练是截图到 HTML，两者都不等于本课的单元格合取；
8. 把第 23 课的 OCR 双列和第 08 课的分辨率桶从本课报告里划出去。

完成能力第 1 到 4 条可以在纸上验收：CPU 实验里表头对合计的 IoU 必须是 $0$，`content_can_hit_while_box_misses` 必须为真，栅格顺序必须是「条款一、32.00、条款二」。第 5、6 条在同一份 `metrics` 里验收：单字符缺失的字段 F1 必须是 $2/3$，只看见第 1 页时合同编号必须是 `None`。第 7 条口头能讲清两条预训练目标即可。漏掉第 3 条（构造表头假成功）等于本课没上。

第 32 课的屏幕点击会复用本课的单元格想法：按钮是另一种格子，点击点必须落在按钮框内，光会读按钮上的字不够。差别是 GUI 的动作还有 type / scroll，文档字段没有这些动作。不要在本课报告里写 ScreenSpot。第 23 课的字形区域是本课单元格的子集：当字段独占一块字且没有表头诱饵时，两课的框重合；当表头和合计同数字时，只有本课能抓住假成功。

和第 17 课的关系只借「可验证判定优先于看起来对」这一句。单元格合取、字段精确匹配、可见页集合，都是可以执行的判定，适合以后接到奖励里。本课不训 GRPO，也不改 verifier 代码。需要时回看[第 17 课](17_grpo_rlvr.md)的 verifier 段落，不要在发票夹具上重做组相对策略优化。

## 5. 原理:边造边讲

九个机制，每个按同一节奏：为什么需要、怎么运转、精确定义、在公开实现哪里、怎么证明做对了。

### 5.1 单图 OCR 的账本缺了字段

单图 OCR 的最小输出是字符串列表，有时附带检测框。流水线通常是：检测文本行，裁块，识别字符，再按几何排序交给下游。Donut 原文 Figure 1 把这条流水线画成检测、识别、解析三截。作者列了三个代价：高质量 OCR 推理贵；换语言或换领域要重训或换引擎；识别错误会传到解析。复杂文字系统（原文举韩文、中文）上，后 OCR 纠错又会再加一块系统。这些是工程理由，用来解释为什么要做 OCR-free。本课还要补一条评测理由：即便三截都对，你仍然可能只拿到「页上有哪些字」，拿不到「字属于哪个字段」。

把一页发票写成三个对象。字符串集合 $S$ 是 OCR 能给出的东西。框集合 $B$ 是检测能给出的东西。字段集合 $F$ 是版面要给出的东西。一个字段 $f\in F$ 至少包含：

$$
f=(\mathrm{key},\,s,\,B,\,\mathrm{page},\,\mathrm{row},\,\mathrm{col})
$$

$\mathrm{key}$ 是「合计」「单价」「合同编号」。$s$ 是值。$B$ 是值所在单元格，不是键所在单元格，也不是列名外接框。$\mathrm{page}$ 从 1 起。表格字段才填 $\mathrm{row}$、$\mathrm{col}$。单图 OCR 默认交出 $(s,B_{\mathrm{glyph}})$，其中 $B_{\mathrm{glyph}}$ 盖住字形。$B_{\mathrm{glyph}}$ 可以和 $B$ 重合，例如合计数字独占一格；也可以远小于 $B$，例如数字只占格子右半；还可以完全不是 $B$，例如模型框住了列名「金额」。第 23 课验收 $B_{\mathrm{glyph}}$。本课验收 $B$。

类比：图书馆能把每页上的字都抄下来，不等于已经编好了目录。类比失效处：目录还有主题词和索书号，本课不要求主题分类；本课只要字段名、值、框、页。RVL-CDIP 那种 16 类文档分类（letter、memo、email 等）是另一张表，Donut 把它也写成 JSON `{"class": "memo"}`，本课主路径不做分类桶。

传统 IE 还多一截序列化。Donut 原文 Table 2 的第一组基线走 BIO 标注：OCR 出字和框，再按几何排成 token 序列，再对每个 token 做命名实体分类，最后把 B/I 片段拼回字段。序列化这一步已经假设阅读顺序正确。顺序错了，BIO 会把右栏金额标进左栏条款的实体里。SPADE 改成在框之间预测关系边，WYVERN 在 OCR 输出上做编码器-解码器生成实体树。Donut 和它们的差别是输入：后两者吃 OCR，Donut 吃像素。评测差别是：BIO 基线默认有框（OCR 框），Donut 默认没有框。用 BIO 基线的框去填本课框列是合法的，必须写 `box_source=ocr_line`。那种框是文本行，不是单元格。行框和单元格框 IoU 常常低于 0.5，即使字符串完全正确。这是流水线路线在本课账本上的系统性偏差，不是模型「不会看表」。

验证：CPU 夹具里合计真值是 `("total","32.00",TOTAL_CELL,1)`。预测 `("total","32.00",AMOUNT_HEADER,1)` 时，字符串列对，字段框列错。`layout_fails_when_box_is_on_header` 必须为真。

### 5.2 阅读顺序：栅格扫描会拆开双栏

解码器按时间步吐 token。预训练如果按错误顺序读字，下游 JSON 的键值对会跟着错位。Donut 的预训练任务写得很硬：在图像上按阅读顺序读出全部文字，基本上是从左上到右下，目标是图像与已读上下文上的下一词交叉熵（原文 §2.3）。「基本上」三个字不能漏。双栏、表格、页眉页脚、竖排、印章，都会让「从左上到右下」不再等于人的阅读顺序。

栅格扫描是最常见的偷懒排序。对每个检测框取左上角 $(x_1,y_1)$，按 $y_1$ 再按 $x_1$ 排序。双栏合同时，左栏第一条和右栏金额可能有接近的 $y_1$，金额会被插到左栏两条条款中间。CPU 夹具用三个框：

- 条款一：$(8,10,40,22)$
- 32.00：$(68,10,92,22)$
- 条款二：$(8,40,40,52)$

栅格顺序是「条款一、32.00、条款二」。阅读顺序是「条款一、条款二、32.00」。逆序对数为 1：只有「32.00」与「条款二」这一对前后颠倒。检查项 `raster_order_is_not_reading_order` 和 `raster_has_one_inversion` 覆盖这两句。

把阅读顺序写成排列。令真值序列为 $r_1,\ldots,r_n$，预测序列为 $\hat{r}$。用 Kendall 逆序数

$$
K(\hat{r},r)
=\bigl|\bigl\{(i,j):i<j,\;\pi(\hat{r}_i)>\pi(\hat{r}_j)\bigr\}\bigr|
$$

其中 $\pi$ 是真值里的位次。$K=0$ 才算顺序对。本课不把 $K$ 折进版面命中的主公式，避免和单元格 IoU 缠在一起。顺序单独成列。表格里还有一种更严的顺序：先按行号，再按列号。行号来自纵坐标聚类，不来自「第几个检测框」。聚类阈值写进协议，默认取行高中位数的一半；改了必须换 run ID。

Donut 用 SynthDoG 生成合成页时，版面是规则随机堆叠的网格，背景来自 ImageNet，纸张纹理来自拍摄的纸，文字来自维基百科，并加了渲染扰动（原文 §2.3 与 Figure 4）。每种语言 50 万张，加上 IIT-CDIP 的 1100 万英文扫描件。合成页的阅读顺序由生成器自己规定，比真实双栏报纸干净。你若只用合成页训阅读顺序，迁移到报纸、杂志、多栏海报时 $K$ 会上升。报告里写清训练顺序是「生成器顺序」还是「人工阅读顺序」。

IIT-CDIP 的伪标签来自商业 OCR，本身带识别噪声。Donut 把这些噪声当成读字目标，等于在学「有错的阅读顺序」。这不是缺陷隐瞒：作者明确写了伪标签来源。你用同一批扫描件做本课单元格真值时，不要直接抄 OCR 框当 $B$。OCR 框是字形行，合计栏可能被切成「32」和「.00」两个框。单元格真值要人工或按表格线合并。用 OCR 行框当单元格真值，IoU 阈值 0.5 会系统性偏严，Hit 被低估。低估本身不可怕，可怕的是你据此宣布「OCR-free 比 OCR 管道高 20 个点」，差值里一半来自真值定义不同。

双栏之外还有一种常见失败：页眉和表体的 $y$ 接近。发票号「No.128」在右上，表头「金额」在它下方不远。栅格扫描会先读发票号再读表头再读第一行金额。问合计时，语言模型看到的上文是「128、金额、24.00、8.00」，「128」和「金额」都会抢答。阅读顺序正确时应先扫表体行、最后到合计栏，页眉单独成段。协议里把页眉、表体、页脚写成三个区，区与区之间禁止栅格混排。区的切分可以用水平投影：对每一行像素统计油墨量 $h(y)$，在 $h(y)$ 低于全页中位数 $1/4$ 的位置切开。切缝写进 `band_id`。切错的典型症状是把合计栏并进最后一行商品。

XY-cut 是比栅格更老的版面切分。先沿空白最多的水平或垂直缝把页面切成块，再对子块递归。它能拆双栏，也会在表格的网格线上误切，把一行切成一堆单字。本课不实现完整 XY-cut。你只需要会做一次对照：同一份双栏页，栅格序列、$K$ 和人工序列并排打印。$K>0$ 时不要进入字段 F1 的主表，先修顺序。顺序错了还报 F1，等于在错误的袋子里数对了几颗豆子。

验证：交互实验把阅读顺序做成开关。栅格扫描且捷径高时，问「打印纸这一行金额」，玩具模型可能输出 32.00 并框住表头：它按像素把列名和合计数字当成同一条扫描带。版面顺序且捷径低时，同一问应落到 24.00 那一格。

### 5.3 单元格命中：内容对且框过线

本课主公式只有一行。预测 $(\hat{s},\hat{B})$，真值 $(s,B)$：

$$
\mathrm{Hit}_{\mathrm{cell}}
=\mathbf{1}[\hat{s}=s]
\cdot
\mathbf{1}\bigl[\mathrm{IoU}(\hat{B},B)\ge\tau\bigr]
$$

默认 $\tau=0.5$。IoU 与第 23 课相同：

$$
\mathrm{IoU}(\hat{B},B)
=\frac{|\hat{B}\cap B|}{|\hat{B}\cup B|}
$$

交集宽高为负时面积记 0。边相贴面积为 0。阈值是闭区间：恰好 $0.5$ 算命中。CPU 实验沿用边长组合使 IoU 恰好为 $0.5$ 的夹具，以及略低于 $0.5$ 的未命中夹具。

合取展开成列联表，四格都要会说话：

|  | 框命中 | 框未命中 |
|---|---|---|
| 内容对 | 真看见字段 | 表头 / 邻行 / 页眉捷径 |
| 内容错 | 看对格子说错值 | 双重失败 |

右上格就是本课验收必须找到的那一例：合计是 32.00，模型也输出 32.00，框在表头「金额」。左下格同样重要：框盖住了合计栏，字符串却是发票号 128。左下格说明「会指格子」不等于「会抄格子里的字」。禁止只交右上格或只交准确率。

手算一遍表头假成功。表头框 $B_H=(70,30,95,42)$，宽 25、高 12、面积 300。合计框 $B_T=(70,80,95,96)$，宽 25、高 16、面积 400。两框无交集，$\mathrm{IoU}=0$，框未命中。$\hat{s}=s=\texttt{32.00}$，内容命中。$\mathrm{Hit}_{\mathrm{cell}}=0$。行内金额 $(70,44,95,56)$ 与合计同样无交，不能拿第一行 24.00 的框冒充合计栏。

若预测框是 $(70,82,95,96)$，与 $B_T$ 的交集高 14、面积 350，并集 400，$\mathrm{IoU}=0.875$，框命中。内容仍对时，单元格命中为 1。略微偏一点不要紧，偏到表头就过不了 $0.5$。

内容匹配的规范化必须预先写死。默认规则：去首尾空白；全角数字转半角；货币符号从字符串里剥掉再比，但要在日志里留 `raw` 和 `norm` 两列。不要在评测时根据模型输出改规则。「￥32.00」和「32.00」在本课默认算匹配；「32」和「32.00」不算，除非协议写了小数位折叠。改规则换 run ID。

框还可以按行带或列带放松，但放松必须单列，不能偷偷改主公式。行带命中定义为：预测框中心的 $y$ 落入真值行带 $[y_{\min},y_{\max}]$，不要求左右也对。列带同理。行带命中适合「只要找对了合计这一行」的诊断，不适合验收。验收仍用单元格 IoU。原因是行带会把合计行上的「币种」格和「金额」格算成同一个成功。本课夹具里合计行只有一个数字格，行带和单元格碰巧重合；真实收据的合计行常常有「合计 / 税额 / 总额」三个数。只报行带，你会把税额当成总额。

点选式变体和第 23 课的点接地是亲戚。模型输出一个点 $p$，命中当且仅当 $p\in B$ 且字符串对。点比框便宜，但点落在表头两个字的墨水上仍算版面失败。不要用「点离数字中心 20 像素以内」这种像素阈值替代「点在单元格内」，除非你把阈值和单元格面积一起写进协议。小格子 20 像素已经出界，大格子 20 像素几乎等于乱点。

再手算一个「几乎碰上」的框，避免把 IoU 写成观感。预测 $(68,76,97,98)$，真值 $B_T=(70,80,95,96)$。交集 $(70,80,95,96)$，面积 $25\times 16=400$。预测面积 $29\times 22=638$，真值 400，并集 $638+400-400=638$，$\mathrm{IoU}=400/638\approx 0.627$，过线。若预测上移到 $(68,50,97,72)$，与 $B_T$ 无交，IoU 为 0。中间那一段「看起来盖住了表格右下」不够。

验证：`content_can_hit_while_box_misses`、`layout_fails_when_content_is_wrong`、`layout_passes_only_when_both_hit` 三条必须同时为真。任一失败，公式实现和课文不一致。

### 5.4 表格：列名是诱饵，行是结构

表格把字段放进二维索引。第 $i$ 行第 $j$ 列的单元格是 $C_{i,j}=(s_{i,j},B_{i,j})$。列名 $h_j$ 通常在第 0 行，例如「项目 / 数量 / 单价 / 金额」。问「合计金额」时，真值不是 $h_{\text{金额}}$，是合计行的金额格，或独立于表体的合计栏。语言模型见过无数「金额」后面跟数字，列名是最便宜的诱饵。

行结构是另一件事。CORD（Consolidated Receipt Dataset）把收据字段收成 30 个唯一字段，带嵌套：`items > item > {name, count, price}`（Donut 原文 §3.1）。训练集 800、验证 100、测试 100。字段级 F1 只问抽出的叶子对不对；TED 还问树还在不在。Donut 在 CORD 上字段 F1 84.1、TED 准确率 90.9，P40 上 1.2 秒/张（原文 Table 2）。同一张表里，LayoutLMv2 的 F1 是 78.9、TED 准确率 82.4，且必须外挂 OCR。数字用来对照「OCR-free 生成也能做嵌套收据」，不要抄进本课夹具的预期。

字段级 F1 的口径来自 Donut 引用的 IE 惯例：字段信息必须出现在真值里；漏一个字符，该字段抽取失败。写成集合：

$$
P=\frac{|\{k:\hat{v}_k=v_k\}|}{|\hat{V}|},\quad
R=\frac{|\{k:\hat{v}_k=v_k\}|}{|V|},\quad
F_1=\frac{2PR}{P+R}
$$

CPU 夹具：真值 `{total: 32.00, date: 2024-01-02, vendor: Acme}`，预测把日期写成 `2024-01-0`。三个字段里两个精确匹配，$P=R=F_1=2/3$。`single_char_miss_drops_field_f1` 必须为真。若你改成基于编辑距离的部分分，那是另一张表，名字里要有 ANLS 或 soft-F1，不能叫字段级 F1。

TED 准确率按 Donut 原文公式：

$$
\mathrm{Acc}_{\mathrm{TED}}
=\max\bigl(0,\;1-\mathrm{TED}(\mathrm{pr},\mathrm{gt})/\mathrm{TED}(\phi,\mathrm{gt})\bigr)
$$

$\phi$ 是空树。$\mathrm{TED}(\phi,\mathrm{gt})$ 等于把真值树从零建起来的代价，本课实现里用节点数近似。预测树与真值树相同则 TED 为 0，准确率为 1。把嵌套 `menu: [{name, price}, …]` 拍成扁平 `{total, name, price}` 之后，键集合和层次都变了，TED 上升，准确率下降。`flattening_structure_lowers_ted_accuracy` 覆盖这一句。Donut 强调 F1 看不到部分重叠，也看不到组与嵌套；所以他们两列都报。本课照抄这个纪律。

行号列号怎么来。有真值单元格时，用单元格中心落入哪一行带来决定行号，不要用「第几个输出 token」。没有行带标注时，先对 $y$ 中心做一维聚类，再在每一行内按 $x$ 排序得到列。聚类失败的典型症状是：把两行合成一行，于是「打印纸 / 24.00」和下一行「装订 / 8.00」交叉配对。日志里保存 `row_id`、`col_id` 以及聚类阈值。交互实验的表是四列三行（含表头），你应能指出「金额」是 $(0,3)$，合计 32.00 不在这张表体里，它是表外字段。

合并单元格和跨行表头是表格里的第三种诱饵。表头「单价 / 金额」有时被画成一个跨两列的大格，下面再分子列。真值协议必须写清：问单价时 $B$ 是子列，不是跨列父格。父格面积大，IoU 容易过 0.5，内容却可能是「单价金额」四个字而不是数字。本课夹具没有跨列父格，所以教学发票不能证明你处理了合并单元格。真实题本里至少放 4 张含合并表头的表，单独成桶 `span-header`。没有这桶就写 `span-deferred`，不要假装表格已经做完。

行对齐还有数值单位。同一列里「12.00」「8」「32.00 元」混用。字段 F1 的精确匹配会把「32.00 元」判失败。若你的业务允许剥单位，剥的规则要在匹配之前执行，并且对真值和预测各做一次，写入 `norm_text`。不要只剥预测不剥真值。CORD 的菜单价和总价字段在不同收据上单位并不统一，Donut 原文用精确字段匹配，所以 84.1 的 F1 已经包含了这类硬匹配代价。你改成软匹配后，禁止和 84.1 写在同一行。

验证：`line_item_is_not_the_total_cell` 为真。第一行 24.00 的框与合计框 IoU 为 0。内容若被问的是合计，行内金额再准也不是命中。

### 5.5 跨页键值：可见页集合是第一约束

多页 PDF 不是把页拼成一张超长图就结束。键「合同编号」印在第 1 页，值「HT-2024-09」印在第 2 页。模型如果只编码第 1 页，正确行为是输出缺失，而不是把发票号 128 填进去。把可见页写成集合 $\mathcal{P}$。字段 $f$ 可解，当且仅当

$$
\mathrm{page}(f_{\mathrm{key}})\in\mathcal{P}
\quad\text{且}\quad
\mathrm{page}(f_{\mathrm{value}})\in\mathcal{P}
$$

任一页不在 $\mathcal{P}$ 里，该字段进入 `page_missing`，不算内容命中，也不算版面命中。不要把缺失写成空字符串再去和真值比编辑距离，那会制造一批假的内容失败。

CPU 夹具：

```text
page 1: 发票号 = 128
page 2: 合同编号 = HT-2024-09
```

只看见 `{1}` 时，查「合同编号」得到 `None`。看见 `{1,2}` 时得到 `HT-2024-09`。第 1 页的发票号在只看第 1 页时仍可解，证明函数没有把整页清空。`page1_only_misses_contract_id` 与 `both_pages_recover_contract_id` 必须同时为真。

跨页还有阅读顺序。有的合同在第 1 页放条款，第 2 页放签字和编号；有的脚注把值指回上一页。本课最小协议不处理「见附件二」这类语言指代，那要另开桶，真值必须能从像素或印刷标记恢复。语言常识（「合同编号长得像 HT- 开头」）不能当跨页真值。

拼页策略写进记录。三种合法做法：每页独立编码再在文本侧拼接字段；把相邻页拼成一张图再编码；对每页做检索，只把可能含值的页送进编码器。第一种要保存页码；第二种要保存拼接缝的坐标偏移，所有框加页内偏移后才能和真值比 IoU；第三种失败时先查召回，再查抽取。第 45 课的规格才把长视频检索当主题。本课只要求：跨页字段的日志里有 `pages_visible`。缺这个字段，跨页准确率作废。

多页编码的预算要写进记录。把 10 页合同全部拼成一张长图，补丁数按页线性涨，Pix2Struct 的序列长度预算会被后面几页挤爆，前面的键反而被降采样糊掉。每页独立编码再在文本侧合并字段，补丁数按页恒定，但跨页注意力消失，模型无法在同一前向里看见「第 1 页的键」和「第 2 页的值」。折中是只把检索到的 2 到 3 页送进编码器，并在每页顶部渲染页码。本课不实现检索。你只要在日志里写清用了哪一种，以及 `pages_visible` 的产生规则是「人工指定」还是「启发式：含键名的页加后一页」。启发式错了，失败记在召回，不记在抽取。

验证：交互实验第 2 页写着合同编号。捷径高时玩具模型输出 128，使用格子是第 1 页发票号。这是跨页键值失败，不是 OCR 失败：128 在第 1 页确实存在。

### 5.6 Donut：图像到 JSON，不经过 OCR 引擎

Donut 的结构是视觉编码器加文本解码器（原文 §2.2）。编码器把 $\mathbf{x}\in\mathbb{R}^{H\times W\times C}$ 映成一组 $d$ 维向量。作者选用 Swin Transformer，层数 $\{2,2,14,2\}$，窗口 10。解码器取公开的多语言 BART（asian-bart-ecjk）的前四层。推理时给一个任务提示，解码器自回归生成 token，再用正则把 `[START_*]` / `[END_*]` 包起来的片段还原成 JSON。缺结束符的字段视为丢失，不尝试补全。

预训练是伪 OCR：按阅读顺序预测下一词，条件是图像和已经读出的上下文。数据是 IIT-CDIP 1100 万扫描件（伪标签来自商业 CLOVA OCR）加上 SynthDoG 合成的中日韩英各 50 万张。200k step，64 张 A100，batch 196，Adam，学习率在 $10^{-5}$ 到 $10^{-4}$ 里选。主分辨率 $2560\times 1920$，解码最大长度 1536。火车票和名片微调改用 $960\times 1280$。这些超参来自原文 §3.2，本课不要求复现。

微调把所有下游任务写成 JSON 预测。分类是 `{"class":"memo"}`。信息抽取是带嵌套的字段树。DocVQA 把问题当作起始提示，解码器吐答案。作者用字段 F1 和 TED 准确率报 IE，用 ANLS 报 DocVQA。CORD / 火车票 / 名片 / 韩文收据四张 IE 表上，Donut 的 F1 分别为 84.1 / 94.1 / 57.8 / 78.6，TED 准确率分别为 90.9 / 98.7 / 84.4 / 88.6（原文 Table 2）。参数按多语言对比口径记为 143M，推理时间在四套数据上为 1.2 / 0.6 / 1.4 / 1.9 秒，测量卡是 P40。OCR 基线还要另计 OCR 子系统的参数和时延，作者写明近期 OCR 模型可超过 80M 参数。

消融对本课有直接用处。原文 Figure 7：预训练任务里，读字比配文更有效；只合成数据对 IE 够用，DocVQA 则需要真实扫描件，作者认为 IIT-CDIP 和 DocVQA 图像分布接近。分辨率升高，CORD 和 DocVQA 都涨，DocVQA 上小字更多，涨得更明显。CORD 在 $1280\times 960$ 时 0.7 秒/张、TED 准确率 91.1，比主设置更快、略高；低资源（80 张）时更大分辨率更稳。编码器对照里 Swin 和 EfficientNetV2 较强，作者选 Swin 是因为 Transformer 更好扩。交叉注意力可视化（Figure 8）显示，即便没有定位监督，解码器在生成某字段时会看对应区域。这一条只说明「有可能从注意力反查框」，不能代替本课的框列：注意力不是因果，第 23 课已经写过局限。

Donut 没有在官方指标里要求你提交单元格 IoU。它的 F1 是字段字符串，TED 是树。你若用 Donut 权重做本课探针，必须自己从交叉注意力或外挂框头得到 $\hat{B}$，否则只能填 `box_missing`。`box_missing` 的行可以进内容列，不能进版面命中的分子。

训练时 Donut 用 teacher forcing：解码器每一步读真值前缀，不读自己上一步的预测（原文 §2.2）。推理没有这条教练，前几个字段错了，后面的 JSON 括号会跟着崩。这和[第 01 课](01_baseline_reproduction.md)写过的 exposure bias 是同一件事，对象从音频编号换成了字段 token。评测时不要把「JSON 解析失败」和「字段值错」混成一个错误码。解析失败进 `struct_fail`，值错进内容列，框错进框列。Donut 原文对结构错误的处理是：缺结束符就丢字段。你的日志要能数出丢了多少字段，否则 TED 的分母会漂。

低资源曲线也值得记一笔。原文 Figure 9 右侧：CORD 只留 80 张训练时，Donut 仍高于对照的 LayoutLMv2；更大输入 $2560\times 1920$ 在 80 张时更稳。作者的解释是端到端少吃 OCR 噪声。本课不能复现这条曲线，但可以复现它的评测纪律：少样本必须写 $N$，必须和满量划分分列，禁止把 80 张上的分数写进「CORD SOTA」句子。火车票字段位置几乎固定、键只出现一次，F1 94.1、TED 98.7，比 CORD 好看，因为结构更浅。用火车票分数宣传「已经会复杂收据」，属于选错桶。

验证：本课 CPU 实验不训 Swin，不调 BART。它只保证：当你已经有字符串和框时，合取公式和 Donut 的字段 F1 / TED 可以同时算，并且可以互相拆开。

### 5.7 Pix2Struct：截图解析比读字更深一层

Pix2Struct 的目标是通用的「视觉上安放的语言」（visually-situated language）：文档、示意图、界面、自然图里的字和版式混在一起（原文 §1）。输入仍是像素，输出仍是 token，和 Donut 同类。作者认为 Donut / Dessurt 的预训练停在表层文字（合成渲染或 OCR 输出），限制了能从无监督数据里搬走的结构。他们改用网页：从 C4 的 URL 另爬页面，不使用 C4 发布的文本，得到 8000 万张 $1024\times 1024$ 视口截图。

截图解析的做法是（原文 §2.3）：压缩 HTML DOM，只留可见节点；节点里只保留文本、图片文件名和 alt-text；再取能放进解码长度的最大子树，并在截图上画出该子树的框。然后做 BART 式信号：遮住子树里 50% 的文本，解码整棵子树。作者把三种经典监督嵌进同一目标：未遮住的部分像 OCR；遮住的部分像带视觉线索的语言建模；alt-text 像有页面上下文的配文。解码长度 128 token，预训练目标最多 1024 字符。

输入表示改了 ViT 的固定缩放。标准 ViT 先把图拉到预设分辨率，会扭曲文档、界面、长图的宽高比，也让微调时改分辨率变麻烦。Pix2Struct 在给定序列长度里，把图放大或缩小，使固定大小的补丁尽可能铺满预算，并用二维绝对位置编码（原文 §2.2）。InfographicVQA 上 Donut 只有 11.6 ANLS，Pix2Struct-Large 到 40.0，作者把 Donut 的惨状部分归因于固定宽高比（原文 §4.4）。

微调时，问句不走单独的文本通道，而是渲染到图像顶部当页眉。带候选框的界面题，把框画在图上。多项选择把选项也写进页眉。作者把它类比成 GPT 以来 NLP 里「把所有输入拼成一段」的做法。本课教学发票没有真的把问句烧进像素，但协议上要明白：Pix2Struct 的「问题」在视觉里，Donut 的「问题」在解码器提示里。混用后处理会把坐标原点搞错。

规模：Base 2.82 亿参数，12+12 层，隐层 768；Large 13 亿，18 层，隐层 1536。两者都先在 BooksCorpus 渲染文本上做 30k step 读字热身，补丁上限 128。随后 Base 在 64 个 TPU、batch 2048 上做 270k step，Large 在 128 个 TPU、batch 1024 上做 170k step，输入补丁 2048，Adafactor，学习率热身到 0.01 再余弦降到 0。预训练验证 BLEU 约 30 / 32。这些数字来自原文 §3.2。

下游 Table 1（单模型、单任务、标准划分）：Pix2Struct-Large 在 ChartQA 放松准确率 58.6（Donut 41.8），AI2D 精确匹配 42.1（Donut 30.8），OCR-VQA 71.3，DocVQA ANLS 76.6（Donut 67.5），InfographicVQA 40.0。界面侧 Widget Captioning CIDEr 136.7、Screen2Words 109.4、RefExp 94.2。自然图 TextCaps CIDEr 95.5，仍低于以海量配文预训练的 GIT2 / PaLI。作者的结论是：截图解析向更多域迁移，配文预训练更帮自然图。Table 2 消融（Base、总 100k step）：完整方法在 DocVQA 验证 67.8；去掉热身 56.2；去掉遮挡 55.7；去掉截图解析、只延长读字 12.2。读线性文本几乎搬不动文档问答。

对本课的含义有三条。第一，预训练目标可以从「读字」升级到「读结构」，HTML 子树就是结构的一种写法。第二，可变分辨率是版面任务的一等公民，长发票、长信息图不能先被拉成正方形。第三，即便预训练已经包含结构，评测仍要单元格合取：HTML 生成对了，框仍可能画在错误节点上。Pix2Struct 官方指标同样不强制单元格 IoU。

热身阶段单独存在是因为直接做截图解析会不稳、学得慢（原文 §2.4）。热身数据是 BooksCorpus 上随机颜色和字体渲染出来的纯文本图，目标就是把字读出来，类似 Dessurt 和简化版 Donut 预训练。30k step 之后再进入网页 HTML。Table 2 显示去掉热身，DocVQA 验证从 67.8 掉到 56.2，Widget Captioning 和 TextCaps 也掉。结论是：先会读字，再读结构。本课主路径不训这两个阶段，但诊断时要按这个顺序排：先查内容列是不是随机乱码（还不会读），再查框列是不是总在表头（会读不会找栏）。两列同时烂，先修分辨率和预处理，不要先加 TED 损失。

问句画在图顶会改变有效分辨率。同一张发票，顶部被问句占去一条，下面的表被挤矮。可变分辨率会重新算补丁网格，框的像素坐标必须在渲染问句之后的那张图上标。先标框再叠问句，IoU 会系统性错位。Donut 没有这个问题，因为它的问句在 token 侧。你若在同一题本上跑两个模型，要存两套框：`box_on_raw` 和 `box_on_rendered`。本课夹具没有渲染问句，所以 CPU 数字不能直接和 Pix2Struct 微调日志对拍。

验证：本课不爬 C4，不渲染 HTML。CPU 夹具用字典树代替 HTML 子树，TED 准确率扮演「结构还在不在」。拍平树之后准确率必须下降，对应 Table 2 里「去掉结构监督就崩」的方向，不是复现 67.8 这个绝对值。

### 5.8 LayoutLMv3：对照一条仍吃 OCR 的路

OCR-free 不是唯一合法路线。LayoutLMv3（[arXiv:2204.08387](https://arxiv.org/abs/2204.08387)）仍然用现成 OCR 取出文字和二维框，再和线性图像补丁一起送进 Transformer。预训练三个损失相加：掩码语言建模（遮 30% 文本，跨度长度服从 $\lambda=3$ 的泊松），掩码图像建模（块状遮约 40% 补丁，目标是离散 VAE 的视觉词），以及词-补丁对齐（判断一个未遮文本词对应的图像补丁有没有被遮）。图像 $224\times 224$，补丁 $16$，196 个补丁。文本最长 512。在 IIT-CDIP 的 1100 万页上预训练，batch 2048，50 万 step。BASE 1.33 亿参数，LARGE 3.68 亿。

原文 Table 1：BASE 在 FUNSD 实体标注 F1 90.29，CORD 96.56，RVL-CDIP 分类 95.44，DocVQA ANLS 78.76。LARGE 为 92.08 / 97.46 / 95.93 / 83.37。FUNSD 只有 199 张表单、149/50 划分，作者提醒他们和 StructuralLM 用的是段级二维位置，和其他词级位置的工作不能直接横比。CORD 他们用官方 800/100/100 划分，并点名 UDoc 论文用了 626/247，分数不可比。这些脚注是评测纪律，本课照收。

图像中心任务上，他们把 LayoutLMv3 当 Cascade R-CNN 的视觉骨干，在 PubLayNet 验证集上做版面检测。PubLayNet 是论文页，五类：text / title / list / table / figure，官方划分约 33.6 万训练、1.1 万验证、1.1 万测试。指标是框的 mAP @ IoU $[0.50:0.95]$。作者报告 overall mAP 95.1，并写 title 类提升明显，因为标题小、常靠文字内容辨认（原文 §3.4）。消融 Table 3：没有图像、只有 MLM 时不能做 PubLayNet；加上线性补丁却不加 MIM，版面检测损失不收敛、mAP 近 0；加上 MIM 后 mAP 94.38；再加 WPA 到 94.43。结论：图像侧没有重构目标时，线性补丁进不了版面检测。

对照写进你的笔记。LayoutLMv3 的 CORD F1 96.56 高于 Donut 的 84.1，但它推理依赖 OCR，输入里已经有字和框。Donut 的 84.1 是从像素直接生成。两列测的不是同一接口。PubLayNet 的 mAP 测的是「标题/表格/图」这类区域类别，不是「合计金额」这种字段。本课的单元格命中更接近字段 IE，不是区域检测。谁把 95.1 mAP 写成「版面命中 95.1」，就是把检测 AP 偷换成字段合取。

验证：本课夹具不调用 OCR。若你外挂 Tesseract 再跑 LayoutLMv3 公开权重，报告第一行写 `pipeline=ocr+layoutlmv3`，第二行写 OCR 引擎名和版本。不要和 Donut 的 `pipeline=pixels-to-json` 横着减 F1。

### 5.9 三套数字：字符串、树、框

到这里可以收成三套必须分列的数字。

1. 内容列：精确匹配或 ANLS。Donut / Pix2Struct / DocVQA 默认活在这一列。
2. 结构列：字段 F1 加 TED 准确率。叶子对了但嵌套丢了，F1 仍可高、TED 会掉。
3. 版面列：$\mathrm{Hit}_{\mathrm{cell}}$，以及阅读顺序的 $K$，以及跨页 `page_missing` 计数。

均分只能在同一列内部算。禁止把 ANLS 0.76 和 Hit 0.40 平均成「综合 0.58」。样本少时（小于 50 张发票）只准写案例和区间，不准写能力百分比。区间算法沿用第 23 课写过的正态近似或 Wilson，第 31 课会系统讲，本课只要你不被 20 张图的 80% 说服自己。

Qwen2-VL（[arXiv:2409.12191](https://arxiv.org/abs/2409.12191)）Table 2：72B / 7B / 2B 的 DocVQA test 为 96.5 / 94.5 / 90.1，InfoVQA 为 84.5 / 76.5 / 65.5。Qwen2.5-VL（[arXiv:2502.13923](https://arxiv.org/abs/2502.13923)）把版面、表格、公式写成带框 HTML，Table 5：72B 的 DocVQA 96.4、InfoVQA 87.3。这些是公开配方已经把文档当一等任务的证据。原文没有把它们拆成「单元格 IoU × 字符串」两列。你引用时必须写任务名和尺寸，不能把 96.5 说成本课版面命中。

记录一条样本至少包含：`doc_id`、`page`、`question`、`pred_text`、`gt_text`、`pred_box`、`gt_box`、`iou`、`content_hit`、`box_hit`、`layout_hit`、`reading_order_id`、`pages_visible`。缺 `pred_box` 时填 `box_missing`。全空的空间字段不能进命中分子。

验证：CPU `metrics` 同时输出 `ocr_content_hit`、`ocr_box_hit`、`ocr_layout_hit`、`field_f1_char_miss`、`ted_accuracy_flat`、`raster_inversions`。缺任何一列，夹具没有覆盖本课。

### 5.10 一张检查单，三种证据

读到这里，机制已经够用来写检查单。每条模型输出先对号入座，再决定进哪一格。

| 探针 | 问什么 | 真值 | 成功 | 假成功 |
|---|---|---|---|---|
| 单元格 | 这个字段的值在哪一格 | 值 + 单元格框 | 两列都过 | 值对、框在表头或邻行 |
| 阅读顺序 | token 按什么次序出 | 人工或生成器顺序 | $K=0$ | 栅格把右栏插入左栏 |
| 结构 | JSON 还是不是树 | 嵌套字段 | TED 准确率高且 F1 高 | F1 高、树被拍平 |
| 跨页 | 键和值是否都看见 | 页码对 + 值对 | 可见页集合覆盖两页 | 用第 1 页发票号顶合同号 |

跨探针规则三条：

1. 同一张发票可以同时进四条探针，分数分列。禁止把三个答案拼成一个「该票通过」。
2. 扰动一次只动一种。挪框只解释单元格；改排序只解释顺序；藏第 2 页只解释跨页。三种一起加，失败了你不知道是哪一条。
3. 教学模拟、CPU 夹具、真实权重是三层证据。模拟证明你懂列联表；夹具证明公式可复核；真实权重证明协议能接到模型上。缺第三层时状态为 `protocol-only`。

从检查单反推 MiniMind-O 现在缺什么。默认视觉路径是冻结 SigLIP2、固定 64 个 patch、MLP connector、文字 next-token，没有文档 JSON 头，没有单元格框头。主路径只能做：用现成文字答案做内容列；若能取出注意力，做第 23 课那种质量分数当框的代用品；用人工框做 IoU。前两件 CPU 和教学发票已经覆盖。加 Donut 式 JSON 解码属于第 13 节改造，不加就不准在报告里写「本系统会输出字段树」。

把 JSON token 还原成单元格框，是 OCR-free 系统最容易漏写的一步。Donut 官方输出是字段字符串，没有框。一条最小还原链是：

1. 在解码到 `[START_total]` 与 `[END_total]` 之间的每一步，取出交叉注意力向量 $\mathbf{a}_t\in\mathbb{R}^{n}$，$n$ 是视觉补丁数。
2. 对这些步做平均，得到 $\bar{\mathbf{a}}$。
3. 把 $\bar{\mathbf{a}}$ 按 Swin 最后一层的空间网格 reshape，再上采样到输入分辨率。
4. 按第 6 节的连通域规则出 $\hat{B}$。

Swin 有 patch merging，最后一层的网格比输入补丁粗。上采样公式必须用 encoder 实际输出的 $H'\times W'$，不要用输入 $H\times W$ 除以 32 的口头约定。打印 `feature_map_hw` 进日志。网格搞错时，所有框会按一个固定比例平移，IoU 整表变差，看起来像「模型不会看版面」。先叠一张网格在原图上目视，确认合计栏中心落在高响应格，再谈百分比。

Pix2Struct 的 HTML 节点如果带包围盒（预训练时作者会在截图上画子树框），微调 DocVQA 时目标往往只是答案字符串，包围盒监督消失。你不能假设微调后的模型仍会吐框。要框，要么自己加节点坐标解码，要么走注意力反查。两条路的 `box_source` 字段分别填 `html_attr` 和 `attn`。混填会使你以为「截图解析自带版面命中」。

## 6. 在公开实现中定位这些机制

本课没有 MiniMind-O 里现成的文档 JSON 头。对照放到公开仓库和本课夹具。读代码时带着两个问题：特殊 token 有没有进词表；评测脚本有没有框列。

Donut 仓库 [https://github.com/clovaai/donut](https://github.com/clovaai/donut)。应对齐：Swin 编码器、BART 前四层解码器、任务提示、`[START_*]` / `[END_*]`、JSON 还原失败时丢字段。推理脚本若只打印字符串，自己补一个注意力到框的后处理，或接受 `box_missing`。输入分辨率是否仍是 $2560\times 1920$ 要打印出来；改分辨率后不要沿用原文 Table 2。

Pix2Struct 说明与权重入口 [https://github.com/google-research/pix2struct](https://github.com/google-research/pix2struct)。应对齐：可变分辨率铺补丁、二维位置、问句渲染在图像顶部、截图解析的 HTML 简化规则。微调 DocVQA 时若你另开文本通道喂问题，就已经不是原文设定。

LayoutLMv3 入口 [https://aka.ms/layoutlmv3](https://aka.ms/layoutlmv3)。应对齐：OCR 文本 + 段级二维框 + 线性补丁，MLM / MIM / WPA。评测 FUNSD / CORD 时确认划分和是否使用官方 OCR 标注。PubLayNet 那条视觉检测链路没有文本嵌入，不要和 CORD 的 F1 写进同一格。

Qwen2.5-VL 仓库与技术报告见第 23 课。文档 Omni-Parsing 若启用，区域来自 HTML 属性。不要再跑一遍外接矩形当唯一真值而不加说明。坐标协议：Qwen2-VL 是 $[0,1000)$，Qwen2.5-VL 是绝对像素，两套权重不要混用同一后处理。

机制图 `lesson44Diagram` 把同一张文档拆成阅读顺序、字段序列、内容判定、框判定，汇到版面命中。读图时按步骤核对：输入是否同时流向编码器和顺序状态；内容节点是否只谈字符串；框节点是否写着阈值 0.5；输出节点是否写着合取。若有人把内容输出直接连到「成功」，那张图就画错了。事实栏四条应对得上原文：Donut 的阅读顺序预训练、单元格合取、Pix2Struct 的截图解析与可变分辨率、字段 F1 对单字符缺失敏感。

本课 CPU 夹具在 `experiments/src/learn_omni_experiments/lessons/lesson_44.py`：`iou`、`content_hit`、`box_hit`、`layout_hit`、`field_f1`、`ted_accuracy`、`raster_order`、`cross_page_lookup`。交互实验在 `web/components/labs/advanced/Lesson44DocumentLayoutLab.tsx`，捷径阈值 $0.55$ 写在模拟函数里，改了必须同步改课文。

从注意力反查框时，固定一层、一个归约。建议用解码器最后一层、对应当前字段 value token 的交叉注意力，对多头取平均，得到与视觉补丁同尺寸的图 $A$。把 $A$ 双线性拉回原图，取质量超过 $\max(A)/2$ 的连通域，外接矩形当 $\hat{B}$。阈值和层号写入协议。换一层必须换 run ID。Donut Figure 8 只是定性图，没有给出这套阈值，所以你写的是本课约定，不是原文数字。连通域若碎成多个，只留面积最大的一块，避免把表头和合计同时框进来再靠并集混过 IoU。

读开源推理脚本时按这个顺序打勾：

1. 图像预处理是否与训练一致。Pix2Struct 会按补丁预算缩放并保持宽高比；你若先把发票压成正方形，长表的行带会变形，单元格 IoU 系统性偏低。
2. 提示在哪一条通道。Donut 在解码器侧，Pix2Struct 在像素侧。
3. JSON / HTML 还原失败怎么记。Donut 丢字段；你若自动补 `null` 再评 F1，分母会变。
4. 框从哪来。注意力反查、外挂检测、模型自己吐坐标，三种来源分列。
5. 多页怎么切。缺 `pages_visible` 的跨页准确率作废。
6. 特殊 token 是否被切成普通子词。`[START_total]` 若变成三个词，字段边界会漂，TED 会假摔。

[第 02 课](02_multimodal_connector.md)比较过 MLP / Resampler / Q-Former。本课不重做那组消融，诊断时要记得：query 压缩会先丢掉窄列和小字。connector 若只留 16 个 query，合计栏可能已经被池化进「右下角一团」。这时注意力质量分数不能当单元格框。要么把 query 的空间位置映射回原图像素再和 $B$ 比 IoU，要么外挂检测器出框，要么承认 `box_missing`。在 16 个槽上假装做了单元格命中，属于协议失败。

## 7. 数据与训练 recipe

主路径不训练大模型。若你要为探针造数据或做第 13 节的小改造，按下面配比记账。数据许可写进报告，不默认任何扫描件可训练。

**评测题本（必须）：**

| 桶 | 每文档最少题 | 真值 | 负对照 |
|---|---|---|---|
| 单元格 / 合计 | 1 个字段 + 框 | 值 + 单元格 | 框改到表头或邻行 |
| 行内金额 | 1 | 该行该列 | 列名、下一行 |
| 阅读顺序 | 1 条序列 | 人工顺序 | 栅格排序 |
| 结构 / 嵌套 | 1 棵字段树 | JSON | 拍平后的叶子袋 |
| 跨页键值 | 1 | 值 + 页码 | 只给第 1 页 |

规模建议：CPU 教学用本课固定发票即够。真实文档探针：每桶至少 30 份才能开始看方向，200 份才接近「可以谈比例」。少于 30 份只准写案例，不准写百分比。CORD 测试集只有 100 张，够看方向，不够按子结构再切十份报均分。

**可选小训练（protocol-sft，非本课验收必需）：**

目标不在追 Donut Table 2。这一阶段只是让小模型多一个「图像到迷你 JSON」的头，便于你看见 $\mathrm{Hit}_{\mathrm{cell}}$ 从全 0 变成非 0。

1. 投影层已按第 22 课对齐；本阶段只训短 JSON，学习率低于指令微调主阶段。
2. 正例：字段名、值、框、页码。负例：表头框配合计值，目标为「该框不是该字段」，比例至少 1:1。没有表头负例，模型会学会看见「金额」就输出数字。
3. 合成发票自己渲染，许可标 CC BY 或内部自用。画布建议 $512\times 720$，表体 2 到 4 行，合计栏与表头「金额」必须同时出现，跨页样本不少于 20%。
4. 不要把 CORD 训练划分写进「零样本 CORD」报告。

**禁止混进 recipe 的东西：**

- 用闭源 VLM 批量造字段框再写成「自研数据」，除非保存操作日志并声明蒸馏；
- 把第 08 课 OCR 配比（文档倾斜）直接拿来当版面配比：文档多只解决读字；
- 只训短答案 DocVQA，却在报告里写「已具备单元格接地」。

合成数据的最低规格。每张票：表头四列、至少两行商品、一个表外合计、一个页眉发票号、一句含相同数字的促销。随机种子写入文件名。jsonl 必须能从种子重建框。没有这一层，改造实验里「Hit 从 0 变成非 0」无法复审。

数字碰撞要单独造。不少于 30% 的票里，页眉发票号、促销满减、某一行金额、合计，四者中至少两处出现同一数字串。没有碰撞，内容列会虚高：模型只要在整页里找到这个数就算对，你测不到表头捷径。碰撞票上，真值框必须标在被问的那一处，其它同数字处标成 `distractor_box`，评测时若 $\hat{B}$ 与干扰框 IoU 更高，记入右上格并写 `notes=same_string_wrong_cell`。

跨页合成的最低规格。第 1 页只放键和页眉数字，第 2 页只放值。禁止在第 1 页重复印值，否则 `page_missing` 探针失效。两页的像素哈希分开存，拼页时记录缝的 $y$ 偏移。偏移写错，第 2 页的框加到第 1 页坐标系里，IoU 会全军覆没，看起来像模型不会读，其实是你的坐标坏了。

## 8. 按依赖顺序执行实验

实验 ID 前缀 `44`。一次只改一种探针或一种输入扰动。教学模拟和 CPU 夹具是必做；真实权重是可选。

### Step 0: 锁定公式与夹具

在 `experiments/` 目录运行本课 CPU 实验（编排者注册后）：

```bash
python3 run.py run 44
```

核对 `checks` 全为真。重点看：`content_can_hit_while_box_misses`、`layout_fails_when_box_is_on_header`、`raster_order_is_not_reading_order`、`page1_only_misses_contract_id`。把 `artifacts/lesson44/result.json` 的 metrics 抄进报告附录。这一步失败，后面所有百分比都没有单位。

### Step 1: 教学发票，先预测再揭晓

打开本课交互实验。默认捷径 0.70、提问「合计金额」、版面顺序。先选预测「读对数字但框在表头」，再揭晓。记录字符串、使用格子、真值格子、IoU、内容命中、版面命中。再把捷径降到 0.40 以下，预测「内容对且框对」，揭晓。两条都勾上，验收才过。可选：点一个你认为模型会框的格子，对照揭晓后的使用格子。

### Step 2: 行内金额与栅格开关

提问改成「打印纸这一行的金额」。阅读顺序切到栅格扫描，捷径保持高。预期：字符串可能变成 32.00，框仍可能在表头。这不是 Gate 硬条件，但报告需要一行，否则阅读顺序桶是空的。再切回版面顺序、低捷径，确认 24.00 落到行内格。

### Step 3: 跨页合同号

提问改成「合同编号」，打开第 2 页看真值，再回到第 1 页。捷径高时预期输出 128、框在发票号。报告写 `pages_visible={1}`。这问也不是 Gate 硬条件，缺了则跨页桶为空。

### Step 4: 手造 20 份真实票的最小探针（无 GPU 可只标不跑模型）

选 20 份扫描件或照片，覆盖：带表头「金额」的收据、双栏条款、至少 4 份两页合同、至少 4 份行数大于 3 的表。每份写：合计字段与框、一行商品字段与框、阅读顺序 token 列表、若有第二页则写跨页键值。即使没有模型输出，题本本身是交付物。有开源文档模型时，用 greedy、温度 0 跑同一题本，填列联表。

20 份的配额再写死，避免全是同一家超市的小票。普通单栏收据 6 份，带表头诱饵且合计与某行同数字 4 份，双栏或多栏 4 份，两页或以上 4 份，含合并表头或竖排印章 2 份。每份冻结 `doc_id`、每一页的像素哈希、拍摄或扫描时的 DPI。改图必须换 id。手机拍照的透视畸变不要在本课里用单应变换「修正」后再和原图框比 IoU；要修，就在标注之前修，并保存修正后的图当唯一真值图。一边修图一边沿用旧框，IoU 会变成在测你的单应而不是模型。

标注单元格时用「值的格子」不是「键加值的大框」。键「合计」在左侧、值在右侧，真值 $B$ 只罩数字。大框容易和表头、整行重叠，IoU 失去分辨力。两人标注同一份票时，若框的 IoU 低于 0.8，该题进 `annot_disagree`，不进主表。本课 20 份做得到双人复核；做不到就由同一人隔天复标一次，两次 IoU 写入日志。

### Step 5: 负对照，一次一个

对 Step 4 的题本做三种扰动，分别存 run ID：

1. 把合计真值框改标注到表头，看内容列是否还亮（这是在测你的评测脚本会不会把框列丢掉）；
2. 按栅格重排 OCR 框再喂给依赖 OCR 的基线，看字段 F1 是否掉；
3. 丢掉第 2 页图像，看跨页字段是否进入 `page_missing`。

第 23 课涂黑的是物体像素；本课丢掉的是页。不要写成同一次消融。

### Step 6: 可选真实权重

若有 1×24GB，拉 Donut 或同等开源文档权重，只跑 Step 4 的题本。报字段 F1、TED（若你能还原树）、$\mathrm{Hit}_{\mathrm{cell}}$、`box_missing` 比例。禁止把原文 CORD 84.1 或 Pix2Struct DocVQA 76.6 写进你的 20 份表。解码必须锁死：greedy、温度 0。温度 0.8 会让 JSON 括号随机断裂，`struct_fail` 会跟着种子跳，字段 F1 不可复现。beam search 只在你明确要报「多个候选树再取 TED 最小」时使用，并写 beam 宽度。日志字段名固定：

```json
{
  "doc_id": "inv-014",
  "page": 1,
  "pages_visible": [1],
  "question": "合计金额是多少？",
  "pred_text": "32.00",
  "gt_text": "32.00",
  "pred_box": [70, 30, 95, 42],
  "gt_box": [70, 80, 95, 96],
  "iou": 0.0,
  "content_hit": true,
  "box_hit": false,
  "layout_hit": false,
  "decoding": "greedy",
  "notes": "框在表头金额"
}
```

`pred_box` 若模型不吐，填 `null` 并把 `box_hit` 留空，`layout_hit` 记 `false`。不要编一个框。

## 9. 评测与测量

所有数字带桶名、样本量、阈值和解码配置。

**必报表：**

1. 列联表：$N$、四格计数、内容准确率、框命中率、$\mathrm{Hit}_{\mathrm{cell}}$。
2. 字段 F1：精确匹配；若另报 ANLS，分列。
3. TED 准确率：写清空树代价是节点数还是官方 TED 实现。
4. 阅读顺序：$K$ 的中位数；双栏子集单独一行。
5. 跨页：`page_missing` 计数、可见页覆盖后的召回。
6. 案例：至少 1 条表头假成功，1 条两列都过，附 `doc_id` 与模型输出原文。

**口径：**

- 单元格：IoU 阈值 0.5，闭区间，解码不出框记 `box_missing`。
- 内容：默认 exact；规范化规则写在 `protocol.md`。
- 结构：F1 与 TED 必须同时出现，缺 TED 则结构桶标记 `structure-deferred`。
- 跨页：分母是「键或值至少有一侧需要第 2 页」的题，不是全部题。
- 小样本：30 份以下只准案例；若坚持写比例，必须同时写区间。$N=20$、$p=0.8$ 时正态近似半宽约 0.18，区间大约盖住 0.62 到 0.98。这个宽度意味着「看起来能用」和「几乎随机」可以落在同一区间。第 23 课已经用同一公式提醒过 VQA 探针，本课原样搬过来，对象换成发票字段。第 31 课会系统讲区间，这里只要你不被 20 张票的百分比说服自己已经会拆表格。

**明确不报成成功的东西：**

- 训练 loss 下降；
- JSON 更漂亮、键名更全；
- 与原文 72B 或 Donut Table 2 对比的「我们接近」；
- 教学模拟里调低捷径后「命中变高」（那是模拟设定）；
- PubLayNet mAP 或 RVL-CDIP 分类准确率冒充单元格命中。

字段 F1 对长度极敏感。真值 `32.00`、预测 `32.0` 在精确匹配下失败。若业务允许小数位折叠，写进协议并另开一列 `F1_soft`，主表仍保留精确匹配。否则你会在「会读数」和「会输出两位小数」之间反复改结论。

把列联表的四格翻译成操作建议，避免报告只堆百分数。右上格大：加表头负例，或在损失里对 $\hat{B}$ 加 GIoU，第 23 课写过 GIoU 在不相交时仍有梯度。左下格大：内容头在抄页眉，把页眉数字从训练目标里拿掉，或在提示里写死「不要抄发票号」。左上格小、右下格大：先回到第 08 课看是不是糊了。四格接近均匀：题本太容易或解码坏了，先打印 10 条原文。

阅读顺序的 $K$ 要按文档类型分层。单栏信件的 $K$ 接近 0 不说明你会拆版面。双栏、三栏、表格、脚注四档分开报中位数。某档 $N<10$ 只写案例。把四档平均成一个 $K$ 会让单栏把双栏洗掉。这和第 23 课「左右题和存在题不能平均成 grounding 均分」是同一纪律。

## 11. 根据症状定位失败环节

| 症状 | 先查 | 不要先做 |
|---|---|---|
| 字符串全对，IoU 全接近 0 | 有没有框头、坐标原点、是否框在表头 | 加学习率 |
| 框对，字符串是发票号 | 内容列是否在抄页眉；提示有没有「合计」 | 换更大视觉塔 |
| 双栏字段交叉配对 | 排序是不是栅格；$K$ 是否大于 0 | 加合成单栏数据 |
| F1 高、TED 低 | JSON 是否被拍平；嵌套键还在不在 | 只报 F1 |
| 跨页全错、单页还行 | `pages_visible`；是不是只编码了第 1 页 | 宣称模型不会读数字 |
| 小字全错、大标题对 | 回到第 08 课分辨率 | 在本课解冻 ViT 来「补版面」 |
| Donut JSON 经常缺 `END` | 最大解码长度、字段是否被截断 | 改 TED 实现 |
| Pix2Struct 长图 ANLS 极低 | 是否先拉成正方形 | 抄 Donut 的固定分辨率 |
| LayoutLMv3 F1 远高于 Donut | 流水线是不是已经吃了 OCR 框 | 横着减出「提升 12 个点」 |
| 注意力在合计栏，字符串仍错 | 注意力不是因果；后处理是否改了数字 | 用注意力单独当成功 |
| 20 张票 80% Hit | $N$ 太小 | 写成能力证明 |
| 中文收据掉、英文 CORD 还行 | 词表和预训练语言 | 用 CORD 英文分代替中文票 |

再补一组和公式直接相关的症状。预测框永远在图像上半：检查是不是总在回归表头行。预测框面积接近整页：IoU 会被大框抬起来，先加「框面积不得超过真值 4 倍」的合法性过滤，过滤前后的 Hit 分列。预测字符串总是 `32.00`：题本是不是合计全是同一个数，换几个 17.50 / 108.00 再测。阅读顺序 $K$ 恒为 0：题本是不是全是单栏，加两份双栏才有诊断价值。

第 07 课的路由状态和第 32 课的点击编号，本课都不重做。文档代理若要点「下载发票」按钮，那是第 32 课的 GUI 接地；本课停在字段被正确框住。不要把点击命中写进单元格表。

坐标单位混用是本课最高频的实现事故。Kosmos-2 式箱子索引、Qwen2-VL 的 $[0,1000)$、Qwen2.5-VL 的像素、本课夹具的 $100\times 140$ 画布，四种数字长得像。还原函数入口写死 `unit=pixel|norm1000|bin32|canvas100`。混用一次，IoU 会系统性偏零或偏一。偏零时你以为模型全错，偏一时你以为全对。两种都比「有的对有的错」更危险，因为你不会去看图。打印 3 个框叠在原图上，是比任何均分都便宜的健全性检查。

## 13. 前沿对照与改造方向

**公开方案。** 同一问题，2022–2025 年的公开系统分成三条路。Donut 把检测、识别、解析收成图像到 JSON，预训练是按阅读顺序读字，IE 上用 F1+TED，DocVQA ANLS 67.5。Pix2Struct 把预训练换成 8000 万网页截图到简化 HTML，补上可变分辨率和把问句画进图像，DocVQA 76.6，并在示意图、界面、信息图上明显超过 Donut。LayoutLMv3 坚持 OCR 文本加二维框加补丁，FUNSD / CORD 的 F1 更高，PubLayNet mAP 95.1，代价是推理仍绑 OCR。Qwen2-VL / Qwen2.5-VL 把文档问答做成通才 VLM 的一等任务，72B 的 DocVQA 在 96 上下，Qwen2.5-VL 还把版面写成带框 HTML。三条路共享本课能学会的事：输出里必须有可核对的字段对象（JSON 键、HTML 节点、单元格框），整页字符串只是其中一列。

Qwen2.5-Omni / Qwen3-Omni 的公开技术报告以听、说、看为主，未把「单元格合取」写成和 Magma 二维头同级的预训练目标。其技术报告未公开跨页键值的可见页协议。Moshi 是语音双工，与本课字段框无关。不要把 Omni 的听写能力写成已经会拆表格。

**差距。** 规模差距：1100 万扫描件、8000 万截图、64 卡 200k step、TPU 上的 270k step，钱能堆。机制差距：合取公式、阅读顺序对照、跨页可见页、表头负例、F1 与 TED 分列，本课能做。评测差距：DocVQA 96 和本课 20 张票之间的洞，不是再训一个玩具头能填的；那是分辨率、语言、模板、手写、印章，交给有数据的人。

缩小版和前沿版差在哪里，要拆开说。Donut 的 Swin-B 加四层 BART、143M、输入两千多像素，本课夹具没有编码器。差的是规模。Donut 把任务写成 JSON、用 F1 和 TED 同时报、缺结束符就丢字段，这些本课夹具都能做。差的不是机制。Pix2Struct 的可变分辨率和问句渲染是机制，本课 Lab 没有做，所以你不能声称「已经复现了截图解析」；你只能声称「理解了为什么固定正方形会伤害长表」。LayoutLMv3 的 WPA 是机制，本课没有实现词-补丁对齐损失，报告里就不要写 WPA 数字。规模能补的，写 `deferred-scale`。机制能补却没补的，写 `deferred-mechanism`。混在一起会变成「我没卡所以没学版面」，那不是事实。

**改造实验。**

1. 在 CPU 夹具上把 $\tau$ 从 0.5 改成 0.75，只改阈值常量。预算：数秒。预期：表头假成功仍然失败；边界 IoU 0.5 的夹具从命中变成未命中。失败：所有 `box_hit` 与 $\tau$ 无关。
2. 给教学发票加一行「折扣 32.00」，与合计同值不同格。预算：改 Lab 坐标，不训练。预期：高捷径时框可能落到折扣行，内容仍对，版面仍失败。失败：同值干扰出现后 `layoutOk` 仍为真且使用格子是合计。
3. 用 200 张自渲染双栏页，只训一个「排序头」：输入框集合，输出阅读排列，损失是逆序数或列表交叉熵。预算：CPU 数小时或 1×12GB 数十分钟。预期：双栏 $K$ 下降；单栏几乎不变。失败：$K$ 与栏数无关。
4. 若有 1×24GB：在 Donut 公开权重上跑 Step 4 的 20 份票，比较「只报字符串」和「用最后一层交叉注意力质量分数当框」。预算：单卡若干小时推理，不微调。预期：表头假成功能被注意力探针抓到至少 3 例。失败：20 份上注意力质量分数与字符串对错完全独立且不随表头/合计位置变化。样本不够 10 时只发逐例表。

**顺手复现映射。** Donut Figure 8「解码字段时看对应区域」对应本课列联表：注意力或框落在合计栏时，内容列才有资格谈版面。方向可在教学发票上看到，绝对值不能。Pix2Struct Table 2「去掉截图解析只剩读字，DocVQA 掉到 12.2」对应 CPU 的拍平树：结构信号拿掉，TED 准确率必须下降。LayoutLMv3 Table 3「没有 MIM，PubLayNet 不收敛」对应：没有图像侧目标就不要报版面检测。这些映射全部是方向性的。谁把 84.1 F1 写进自己的固定发票报告，就算评测造假。

改造实验的失败判定再补两条公共规则。任何一次 GPU 推理都要保存：权重哈希、预处理后的 $(W',H')$、原始生成串、解析后的字段、人工框。缺哈希的结果不能进对照表。任何一次声称「OCR-free 更好」的比较，必须在同一批图、同一套单元格真值上完成；一边用官方 OCR 标注、一边用像素生成，不能把差值记在编码器上。

## 14. 论文与必读材料

阅读时带着括号里的问题。数字以你打开的版本为准；本课引用的是下面列出的版本。

1. OCR-free Document Understanding Transformer（Donut，arXiv:2111.15664，Kim 等，ECCV 2022）。带着问题读：预训练究竟按什么顺序读字？Table 2 的 F1 和 TED 各惩罚什么？DocVQA 67.5 和手写 72.1 为什么要分列？JSON 缺 `END` 时字段怎么处理？64 A100、200k step、$2560\times 1920$ 是预训练还是微调？
2. Pix2Struct: Screenshot Parsing as Pretraining for Visual Language Understanding（arXiv:2210.03347，Lee 等，2023）。带着问题读：截图解析比 Donut 的读字多了哪些监督？为什么要遮 50% 文本？可变分辨率解决了固定 ViT 的哪两个扭曲？Table 1 里 InfographicVQA 11.6 对 40.0 作者如何解释？Table 2 去掉截图解析后 DocVQA 为什么掉到 12.2？问句为什么画在图顶而不是另开文本塔？
3. LayoutLMv3: Pre-training for Document AI with Unified Text and Image Masking（arXiv:2204.08387，Huang 等，ACM MM 2022）。带着问题读：WPA 预测的是什么二进制标签？Table 1 的 CORD 96.56 和 Donut 84.1 能否横比？FUNSD 为什么不能和词级位置的工作直接比？Table 3 里没有 MIM 时 PubLayNet 发生了什么？95.1 mAP 测的是字段还是区域类别？
4. Qwen2-VL（arXiv:2409.12191）与 Qwen2.5-VL（arXiv:2502.13923）的文档表。带着问题读：DocVQA / InfoVQA 有没有拆成单元格 IoU？Qwen2.5-VL 的带框 HTML 和 Donut 的 JSON 差在谁提供区域？坐标是千分尺还是绝对像素？
5. 第 23 课已引的 Kosmos-2、Grounding DINO，只用来复习 IoU 0.5 和「字符串对不等于区域对」，不要在本课重做 REC / POPE。

[第 20 课](20_unified_understanding_generation.md)讨论的是图像理解与生成能否共享骨干。本课共享的是字段账本，不是 flow matching 的速度场。规格里的下一课才把长视频检索哪一层特征当主题。本课停在这里：文档的字已经被第 23 课探针过；现在必须把栏、格、页从那串字里拆出来。读对 32.00 只是内容列。框还在表头上，版面就还没开始。

读完应能独立复述三句。第一句：单元格命中是内容匹配与框 IoU 的合取，两列可以脱钩。第二句：阅读顺序不是按 $y$ 再按 $x$ 的栅格扫描，双栏会把右栏金额插入左栏条款。第三句：跨页键值先检查可见页集合，缺值所在页应记 `page_missing`，不该用第 1 页发票号顶上。能复述这三句，并且 CPU 实验检查为真、教学发票留下先预测后揭晓的记录，本课就收工。公开权重只能检验同一套账本在真实扫描件上是否还能抓住表头假成功，不能回头否定夹具里已经核对过的 IoU、字段 F1 和 TED。字符串列是推理口径，单元格合取是版面口径，两套数字不要写进同一格。

CORD 由 Park 等 2019 发布。Donut 与 LayoutLMv3 都引用它并写明 800/100/100 与 30 个字段。本课没有单独打开 CORD 原文页面，划分、字段数以及收据里的嵌套菜单结构以 Donut §3.1 与 LayoutLMv3 §3.3 为准。DocVQA 的题量以 LayoutLMv3 §3.3 转述的官方划分为准：图像约 10194 / 1286 / 1287，问题约 39463 / 5349 / 5188。你若要引用 DocVQA 原文里未出现在这三篇里的数字，必须先打开 Mathew 等 2021 的页面再写。不确定的数字不写。

Mathew 等那篇 DocVQA 的 arXiv 编号本课没有打开，所以正文不写它的 arXiv。ANLS 的定义以 Donut Table 3 和 Pix2Struct §3.1 的用法为准：基于规范化编辑距离的平均相似度。本课主路径默认仍用精确匹配，ANLS 只作为可选的内容列变体，名字必须写出来。把 ANLS 0.9 写成 $\mathrm{Hit}_{\mathrm{cell}}=0.9$，是把宽容字符串分当成了版面命中。字符串列可以宽容，单元格框列不能跟着宽容：框要么过 IoU 阈值，要么不过。给框也打一个「软 IoU 分」可以进附录，不能替代命中指示函数。附录和主表混用一次，列联表的右上格就会被软分洗掉。本课的教学发票、CPU 夹具、公开论文表，三套数字的职责不同：发票让你看见假成功，夹具让你手算合取，论文表让你知道别人在测哪一列。谁把三套写进同一格，下一课的检索评测也会跟着被带偏。字段找对了，才谈得上检索哪一层特征；字段还在表头上，检索层选得再对也只是把错误字段存进索引。先把栏拆对，再把页交给后面的检索课去处理长文档索引。
