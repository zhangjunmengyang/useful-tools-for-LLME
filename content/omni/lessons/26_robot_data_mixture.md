# 第 26 课：混合异构机器人数据并控制机体捷径

> 内容：跨机体数据混合、动作与相机粗对齐、温度采样与捷径探针<br>
> 建议周期：2–4 天阅读与 CPU 实验；复现论文预训练不在本课主路径<br>
> 硬件：无 GPU 可完成全文、互动实验和 CPU 机制实验；OpenVLA 原文预训练为 64×A100、14 天、21500 A100-hours<br>
> 产物：一份可复核的四域混合物账本、指令打乱与机体 ID 泄漏夹具、缩小版 recipe

## 1. 异构机器人数据为什么不能直接倒进同一个 batch

第 24 课把动作接进视觉语言模型：7 维末端可以分箱，变成和文字同一套 next-token。第 25 课比较了均匀分箱、连续 L1、动作分块和压缩表示。到这一步，单机、单相机、单一动作约定上，训练目标已经说得清。本课换一个更脏的事实：公开机器人数据不是一锅同质汤。Open X-Embodiment（OXE）把许多实验室的操作数据汇成一份仓库；Octo 和 OpenVLA 再从里面挑子集来训通才政策。你若把 tfrecord 文件路径拼进同一个 `DataLoader`，按原始条数随机抽 batch，训练看起来在“用上全部数据”，梯度账本上却几乎只看见最大的那几个域。

本课要改的不是网络结构，是采样器、字段对齐和负对照。改对了的判据有三条，都可以在缩小版里用手算或浏览器教具复核：α=1 时最大域占比过高；给每域条数加上限后小域回升；把机体 ID 泄漏写进输入后，去掉语言准确率几乎不变。这三条对应互动实验的验收，也对应 CPU 实验的 checks。它们不证明真机抓取成功率。

具体到数字。四域条数定为 10000、1000、200、100，总和 11300。按条数抽样，厨房占 $10000/11300\approx 88.5\%$，双臂占 $0.885\%$。batch 大小 256 时，厨房期望 226.5 条，双臂期望 2.3 条。有的 step 里双臂是 0 条，梯度里没有插入、没有第二只手臂、没有那套夹爪符号。模型仍会在日志里打印“看到了四个数据集”，因为文件路径确实列了四个。路径不是频率。频率才进优化器。第 15 课用 token 预算揭穿“每类 8 条并不公平”；本课用域预算揭穿“列表里有这个机体并不公平”。两课的算术相同，单位从模态换成了实验室。

OXE 论文摘要给出的规模是：22 种机器人、21 家机构、527 种技能、160266 项任务。仓库把 60 个既有数据集合并，写成超过 100 万条真实轨迹。图 0 还写了两件对混合致命的事：Franka 在视觉场景多样性上占优，因为 Franka 数据集数量多；轨迹条数上，xArm 和 Google Robot 因少数超大集合而领先。条数多和场景多样不是一回事。按条数采样，你会把梯度交给条数冠军；按“每个数据集一份”采样，你会把梯度交给场景更多、但轨迹更短的实验室。两种做法都叫“用了 OXE”，优化对象完全不同。

RT-X 并没有在 22 种机体上训练。OXE 第 IV-C 节写明：实验用的机器人数据混合物来自 9 种操作臂，来源包括 RT-1、QT-Opt、Bridge、Task Agnostic Robot Play、Jaco Play、Cable Routing、RoboTurk、NYU VINN、Austin VIOLA、Berkeley Autolab UR5、TOTO 和 Language Table。全集后来仍在增长，实验当时这 9 种就是他们用到的全部。Octo 写得更具体：OXE 大约有 150 万条 episode，他们整理出 80 万条、25 个数据集；RT-X 用的是更窄的 35 万条。OpenVLA 训练用 97 万条真实演示，并写明写作时完整 OpenX 已超过 70 个数据集、超过 200 万条轨迹。本课引用规模时必须带论文名字和“用了哪一版子集”。把 22、9、80 万、97 万写在同一行当同一数字，账会糊。

| 来源 | 机体或集合 | 轨迹规模 | 这句话能写什么 |
|---|---|---|---|
| OXE 摘要 / 第 III-A 节 | 22 种机器人，60 个数据集 | 超过 100 万条真实轨迹 | 仓库有多大 |
| OXE 第 IV-C 节 | 9 种操作臂 | 实验当时的混合物 | RT-X 实际吃进模型的数据 |
| Octo | 25 个数据集，评测 9 个平台 | 从约 150 万条里整理 80 万条 | 开源政策的过滤结果 |
| Octo 对 RT-X 的转述 | 更窄的子集 | 35 万条 | 不要把 Octo 的 80 万当成 RT-X 的训练量 |
| OpenVLA | OpenX 子集，跟随 Octo 权重 | 97 万条真实演示 | 7B VLA 的训练量 |
| OpenVLA 写作时的 OpenX | 超过 70 个数据集 | 超过 200 万条轨迹 | 仓库后来长大了，不是 2023 摘要里的同一快照 |

上表每一行的数字都来自对应论文的摘要或指定章节。缺“谁说的”就不能进你的报告。RT-1 自己的 13 万条、13 台机、700+ 指令是单机队，更不能和 OXE 的 100 万条横着比。异构混合的第一步是把这些分母分开。

异构从四个轴同时发生。动作轴：有的集合记末端位姿增量，有的记关节角，有的把同一维写成速度；夹爪有的用 +1 表示张开，有的相反。相机轴：第三人称、腕部、双目、分辨率、相对机体的外参都不共享。语言轴：有的 episode 有自然语言，有的只有目标图像，有的指令是实验室内部模板。场景轴：桌布、灯光、背景墙、物体套装会和机体身份绑死。OXE 第 IV-A 节把观察和动作做成“粗对齐”：选一路规范相机、缩到同一分辨率、把原动作转成 7 维末端（x, y, z, roll, pitch, yaw, 夹爪或它们的速率）。他们明确没有对齐各数据集的坐标轴，也允许同一维表示绝对位置、相对位置或速度。于是同一个 7 维向量，在不同机体上会引起完全不同的运动。模型若看见 Google Robot 的外壳就输出一套厨房动作，看见 WidowX 就输出水槽动作，它甚至不需要读指令。

这就是机体捷径（embodiment shortcut：用机体身份、外观或与身份绑定的视觉统计量预测动作，而不是用语言和当前场景里的物体）。桌布颜色是同一类现象的视觉版：某实验室永远蓝布，另一实验室永远木纹，蓝布几乎只和“把杯子放进水槽”一起出现。按条数混合后，大域的桌布会变成最强的类别特征。第 15 课讲过多模态 joint SFT 里按样本配平不等于按 token 配平；本课的单位换成域。域是按机体、实验室或数据集切开的采样桶。桶的大小可以差两个数量级。本课互动实验用四域计数 10000、1000、200、100，最大域和最小域正好差两个数量级，用来把这条账算清楚。

本课术语：

| 术语 | 简要解释 |
|---|---|
| 机体 / embodiment | 具体机器人及其传感器、动作空间和外观；Google Robot 和 WidowX 是两种机体 |
| 域 / domain | 采样与统计的桶，通常按数据集或机体切；本课四域玩具用厨房、桌面、水槽、双臂 |
| 混合物 / mixture | 每个域进入一个训练 batch 的概率表 |
| 温度 α | 把条数 $n_d$ 抬到 $n_d^\alpha$ 再归一化；α=1 按条数，α=0 对域均匀 |
| 每域上限 / cap | 计算权重前把 $n_d$ 截成 $\min(n_d,C)$，防止超大集合独占 |
| 有效域数 | $D_{\mathrm{eff}}=1/\sum_d p_d^2$，衡量 batch 实际覆盖了多少域 |
| 粗对齐 | 把相机和动作压到同一形状，但不保证坐标轴、单位和语义一致 |
| 机体占位符 | 显式机体 ID token 或可从图像反推的外壳编码，供模型切换逆归一化 |
| 语言噪声 | 缺标注、模板句、同义改写、和动作不对齐的指令 |
| 负对照 | 打乱指令或打乱机体标签后再测准确率，用来抓捷径 |

## 2. 本课解决的问题

把异构机器人数据送进同一个训练循环，要同时处理三件会互相拆台的事。第一件是字段合同：7 维末端、关节角、夹爪符号、相机数量不能直接 `torch.stack`。第二件是采样合同：按条数抽，大域淹没小域；对域均匀抽，小域被反复看见、大域的长尾物体被浪费。第三件是捷径合同：模型可以靠机体 ID、桌布、固定相机外参完成训练损失，推理时换一间厨房就垮。

本课结束时你要能交出一份缩小版混合物，而不是一个 7B 权重。混合物必须写明：每个域的 $n_d$、$p_d$、期望 batch 条数、α、上限 $C$，以及两套负对照的准确率。对照必须能被参数组合触发：α=1 时最大域超过阈值；加 cap 后最小域回升；打开机体 ID 泄漏后，去掉语言准确率几乎不变。

本课可以独立阅读。完成第 24 课能少走弯路，因为动作已经是可预测的目标；第 25 课能说明 256-bin 和连续头如何消化对齐后的 7 维。没有这两课也可以：把动作当成“长度为 7 的向量标签”不影响采样和捷径探针。不要在本课重做分箱边界或 flow matching；那些是第 25 课和[第 20 课](20_unified_understanding_generation.md)的对象。第 20 课的 flow 画的是图像 latent，本课的样本是机体域计数，公式不要混用。第 17 课的可验证奖励可以以后拿来给“指令与动作是否一致”打分，但本课的负对照更早、更便宜：打乱输入就能抓捷径，不必上强化学习。[第 17 课](17_grpo_rlvr.md)的 reward hacking 和本课的桌布捷径是亲戚：你奖励（或监督）了错误的相关，模型就优化那条相关。本课用打乱拆相关，第 17 课用程序判分拆投机，对象不同，诊断习惯相同。你若已经做过第 15 课的 token 账本，可以把那张表的列名从模态改成机体，立刻得到本课 α=1 的那一行；差别只是本课多了 cap 和两套打乱。不要把 15 课的音频 token 过长和本课的厨房轨迹过多写成同一个“数据不平衡”故事而不写单位。单位写错，后面所有 $p_d$ 都在给错误的分母做归一化。本课默认分母是域级轨迹数 11300；有人改成时间步或视觉 token 而不改标题，检查者会按 11300 复算失败。改单位必须同时改表头、改 CPU 实验、改教具，三处一起改，禁止只改一处。本课互动实验、CPU 实验和正文手算表已经锁死同一组 $n_d$，就是为了让这三处无法偷偷分叉。你复制本课去做自己的五域混合物时，先改这三处的计数常量，再谈新的 α。五域的 $D_{\mathrm{eff}}$ 上界是 5，α=0 时取到；若你算出来大于 5，归一化已经坏了，不要继续训练。四域玩具的上界是 4，CPU 实验已经断言 α=0 时恰好取到 4。α=1 时约 1.26，加 cap 后约 3.27，三套数字构成主验收曲线，缺一套就不能说混合物已被控制，更不能带着糊涂账进入第 27 课的词表实验。也不要在本课实现自回归 VLA 的词表替换：那是第 27 课。本课只保证一件事：送进第 27 课的 batch，其域组成和捷径风险是可审计的。

第 27 课会把动作塞进 Llama 词表逐步吐出，延迟往往只有数 Hz。若本课把 88% 的 token 预算继续交给厨房，自回归头会把厨房的 256 箱背得很熟，双臂的箱几乎没有监督。到那时再调 α，你分不清是词表问题还是混合物问题。所以本课必须先单独验收 $p_d$ 和探针。全双工那套 CONTINUE / PAUSE / REPLAN 属于[第 07 课](07_full_duplex_routing.md)的语音时钟，本课不借用；手臂的重规划是第 30 课的控制时钟。本课结束时，系统仍然可以是开环模仿，只要 batch 不是假混合。第 27 课若发现厨房动作 token 的准确率 95%、双臂不到 40%，先回来查本课的 $e_d$，不要先改词表大小。词表决定动作怎么写进序列，混合物决定这种写法有没有监督。两件事的失败症状都是“某机体不会动”，定位顺序必须先混合物、后词表。本课交付物就是那张能让第 27 课点名回查的账本。

同样的顺序适用于第 28 课的流匹配动作块和第 29 课的快慢双系统：动作头可以换，域频率表不能丢。换头之后若小域仍然每 113 步才出现一次，新头也学不会插入。α 和 cap 不是某一类架构的附件，是所有跨机体训练共享的入口检查。本课把它单独做成一课，就是为了避免后面每课都把混合物和结构缠在一起调。

和[第 15 课](15_joint_multimodal_sft.md)的边界：15 课的桶是文本/图像/音频/语音，担心的是 codec token 比文本长几十倍。本课的桶是机体和实验室，担心的是 10000 条厨房轨迹对 100 条双臂装配。两课都用“加权再归一化”，权重的物理含义不同。15 课按 token 预算配平；本课按域预算配平。机器人数据里一条轨迹还会展开成许多时间步，Octo 附录 E 写他们每个训练轨迹最多随机抽 100 步，免得超长 episode 挤满 shuffle buffer。时间步是第三种采样单位。本课主账本按域，必要时再拆到步。

三种单位可以同时出错。域对了、轨迹很长，batch 仍被单条演示占满。轨迹对了、每帧视觉 token 数差十倍，梯度仍被高分辨率相机的集合拿走：这是 15 课的 token 账。本课不把视觉 token 数写进 $p_d$，因为 OXE 粗对齐已经把图像 resize 到同一分辨率，OpenVLA 更锁死 224×224。一旦你在扩展里混入未 resize 的高分辨率腕部视频，必须回到 15 课的 token-balanced，否则 α 只是在错误的单位上做精确除法。写 recipe 时声明当前单位：本课默认“域级轨迹计数”。换单位视为另一份实验，不要改同一张表的列定义。

## 3. 开始前需要准备什么

主路径不下载 OXE，不训练 Octo 或 OpenVLA。需要的是纸、计算器或本课 CPU 实验，以及浏览器里的四域教具。若你有磁盘和兴趣，可以打开 OXE 的 RLDS 字段字典，核对相机键名和动作维，但不把“成功读出一个 tfrecord”当成验收。

**上游事实（来自论文，报告里必须写出处）：**

- OXE 摘要：22 种机器人、21 家机构、527 种技能、160266 项任务；仓库为 60 个数据集、超过 100 万条真实轨迹。项目页：[robotics-transformer-x.github.io](https://robotics-transformer-x.github.io)。
- OXE 实验混合物：9 种操作臂，不是 22 种。动作粗对齐为 7 维末端加 episode 终止；每维 256 箱。推理频率按机体要求，文中写 3–10 Hz。
- Octo：80 万条轨迹、25 个数据集、9 个真实机器人平台、4 家机构评测。Octo-Small 27M，Octo-Base 93M。预训练里约 27% 含腕部相机，约 56% 含语言标注。
- OpenVLA：7B，Llama 2 + SigLIP + DINOv2，97 万条真实演示。混合物大体跟随 Octo，并尝试把 DROID 设为 10%、训练后三分之一去掉。预训练 64×A100、14 天、batch 2048、27 个 epoch。
- RT-1：约 13 万条演示、13 台 Everyday Robots 移动操作臂、超过 700 条语言指令、35M 参数、控制频率 3 Hz。

**本课约定（你定的，不要写进“论文说”）：**

- 四域玩具计数固定为 Google 厨房 10000、Franka 桌面 1000、WidowX 水槽 200、双臂装配 100。
- 每域上限的默认演示值 $C=400$。
- 负对照夹具 8 条样本、4 个机体、每机体 2 条指令。
- CPU 实验和互动实验必须用同一组计数，禁止各写各的 $n_d$。

独立执行时固定：

| 锁定项 | 固定值 |
|---|---|
| 域计数 | 10000 / 1000 / 200 / 100 |
| batch 大小（教具） | 256 |
| α 网格 | 0、0.5、1 |
| 条数上限演示 | 400 |
| 探针 | 完整、去掉语言、打乱指令、打乱机体 ID |

论文规模的硬件只作为对照，不作为本课门槛。OpenVLA：64×A100、14 天、21500 A100-hours、batch 2048、27 epoch、学习率 2e-5。Octo-Base：TPU v4-128、30 万步、batch 2048、约 14 小时；同模型在单张 A5000（24GB）上微调约 5 小时。RT-1 原文在 13 台真实机器人上采集约 17 个月。没有这些机器，仍必须把 $p_d$ 表和八格探针做完。有这些机器，也不允许跳过探针直接报成功率。

若要把缩小版接到真实 RLDS，另开实验记录，写清你实际读到的 episode 数。本课正文不假装已经扫描完整 OXE。

## 4. 完成后应具备的能力

完成后，拿到任意一份“我们在 OXE 上训了通才政策”的声明，你应能完成以下检查：

1. 问清用的是 22 种机体的仓库，还是 9 种操作臂的实验混合物，还是 Octo 的 25 个数据集，还是 OpenVLA 的 97 万条。
2. 写出 $p_d\propto n_d^\alpha$，并算出 α=1、α=0 和加 cap 后的 $p_d$ 与 $D_{\mathrm{eff}}$。
3. 指出 7 维末端粗对齐没有统一坐标轴，解释为何同一向量在两种机体上运动不同。
4. 列出夹爪符号、缺失相机通道、腕部相机缺席如何进入 batch。
5. 设计打乱指令和打乱机体标签两套负对照，并说明哪一种抓语言捷径、哪一种抓 ID 泄漏。
6. 在四域玩具上指出：α=1 时最大域超过 75%；$C=400$ 后最小域从约 0.9% 升到约 9%。
7. 解释为何“去掉语言后准确率几乎不变”是失败，不是鲁棒。
8. 把混合物、α、cap、探针结果写进可复查的 recipe，而不是口头说“我们平衡过了”。

自我检查可以用四道题，答不出就还没学完。第一，$n=(10000,1000,200,100)$ 在 α=1 时最大域是多少，有没有过 75%？第二，$C=400$ 后最小域从多少升到多少，对应 $B=256$ 时期望几条？第三，指令打乱时为什么必须冻住动作标签，只改字符串？第四，OXE 摘要的 22 种机体和 RT-X 实验的 9 种操作臂，哪一个能写进“我们在全集上训练”这句话？四题都对应 checks 或论文原句，不需要 GPU。

## 5. 原理：边造边讲

以下机制按同一节奏：为什么需要、怎么运转、精确定义、公开实现落点、怎么证明做对了。

### 5.1 域是采样单位，条数不是多样性

直觉。10000 条 Google 厨房轨迹和 100 条双臂装配轨迹放进同一个列表再随机打乱，下一个 batch 里厨房大约占 88%。模型大部分更新都在学那间厨房的灯光、桌面和外壳。双臂装配每 113 个样本才出现一次，梯度噪声很大，学不会插入。实验室报告却可以说“训练数据包含双臂”。包含不等于被看见。

机制。记域 $d$ 有 $n_d$ 条轨迹（或步，单位必须在 recipe 里写死）。全体 $N=\sum_d n_d$。按条数均匀抽一条，落到域 $d$ 的概率是 $n_d/N$。若改为“先抽域再抽域内样本”，域概率变成另一张表 $p_d$，域内再按轨迹均匀或按步均匀。OXE、Octo、OpenVLA 实际都是“数据集级混合物”：先按数据集加权，再在数据集内读 RLDS。Octo 图 1 的饼图是每个训练 batch 里各数据集的平均份额，不是磁盘上的条数份额。两者可以差得很远。本课四域里厨房和双臂的条数比是 100:1，按条数抽则约每 113 个样本才见到一次双臂；batch=256 时，多数 step 里双臂要么 0 条要么 2 条，方差本身就会吞掉学习信号。cap 把这个比改成 4:1，方差下降，过采样上升，两端要一起看。

数学。温度混合把域概率写成

$$
p_d=\frac{n_d^{\alpha}}{\sum_j n_j^{\alpha}},\qquad \alpha\in[0,1].
$$

α=1 退回按条数；$α=0$ 时 $n_d^0=1$，于是 $p_d=1/D$，对域均匀。α 在中间时，大域仍多、但不再按线性膨胀。对一次长度为 $B$ 的训练，域 $d$ 的期望样本数

$$
e_d=B\,p_d.
$$

相对“按条数”的过采样倍数

$$
r_d=\frac{p_d}{n_d/N}=\frac{n_d^{\alpha-1}\sum_j n_j}{\sum_j n_j^{\alpha}}.
$$

α=1 时所有 $r_d=1$。α&lt;1 时 $n_d$ 越小 $r_d$ 越大：小域被反复看见。有效域数

$$
D_{\mathrm{eff}}=\frac{1}{\sum_d p_d^{2}}.
$$

四域均匀时 $D_{\mathrm{eff}}=4$。若一个域占 88%、其余瓜分 12%，$D_{\mathrm{eff}}$ 会掉到约 1.26，几乎等于单域训练。

本课四域 $n=(10000,1000,200,100)$，$N=11300$。α=1：

| 域 | $n_d$ | $p_d$ | $B=256$ 的 $e_d$ |
|---|---:|---:|---:|
| Google 厨房 | 10000 | 0.884956 | 226.55 |
| Franka 桌面 | 1000 | 0.088496 | 22.65 |
| WidowX 水槽 | 200 | 0.017699 | 4.53 |
| 双臂装配 | 100 | 0.008850 | 2.27 |

最大域 88.5%，超过 75% 的验收阈值。$D_{\mathrm{eff}}\approx 1.26$。双臂在 256 的 batch 里期望 2.3 条，有的 step 里是 0。

α=0.5 时 $\sqrt{n}\approx(100,31.62,14.14,10)$，归一化后约 $(0.642,0.203,0.091,0.064)$。双臂的 $r_d\approx 7.25$：相对自然频率被放大七倍。α=0 时四域各 0.25，$r_{\text{双臂}}\approx 28.2$，每个 epoch 相当于把 100 条轨迹读 28 遍，过拟合风险立刻变成主矛盾。

代码落点。公开实现里这张表通常是一份 Python 字典或 JSON，而不是模型权重。OpenVLA 附录 A 表 3 列出了训练混合物百分比，例如 Bridge 13.3%、Fractal 12.7%、Kuka 12.7%、DROID 10.0%、BC-Z 7.5%、FMB 7.1%，长尾可到 &lt;0.1%。Octo 附录 C 写采样权重“大体由数据集相对规模决定，再加少量手工调整”，表 III 里三个集合各占 17.0%，最小到 &lt;0.1%。你复现时不要手抄百分比当精确 $n_d$；百分比已经是加权结果。本课 CPU 实验实现的是未加权的 $n_d^\alpha$，用来先把公式钉死。

验证。固定四域计数，断言 α=1 的 $p_d$ 与 $n_d/N$ 一致，α=0 为均匀，$D_{\mathrm{eff}}(α=0)=4$。再断言最大域在 α=1 时大于 0.75。这三条在 `lesson_26.py` 里都是 checks。

温度混合还有一个实现细节：指数运算必须在浮点上做。若有人把 `n ** alpha` 先转成整数再归一化，α=0.5 时 10000 的平方根会被截成 100，和 10000^0.5 的真值相同，但 200 的平方根 14.14 会被截成 14，误差沿长尾放大。CPU 实验用 Python 浮点；你自己写 C++ sampler 时要先测一遍 $p_d$ 是否与手算表一致。

两段抽样和一段抽样也不相等。一段抽样：从长度为 $N$ 的大列表按 $n_d^\alpha$ 复制或拒绝采样。两段抽样：先按 $p_d$ 抽域，再在域内均匀抽一条。α=1 时两者同分布。α≠1 或加了 cap 时，只有两段抽样能精确实现 $p_d$。一段抽样若用“把小域轨迹复制 $r_d$ 份再 shuffle”，$r_d$ 不是整数就会再引入取整误差。本课公式默认两段：先域后样本。

一个 epoch 的定义也必须写死。若 epoch 指“每个域的每条轨迹都见到一次”，那 $p_d$ 无法小于 $n_d/N$，α&lt;1 只能靠多个 epoch 里过采样小域、欠采样大域来实现，大域每条轨迹不是每个 epoch 都出现。若 epoch 指“固定 $T$ 次两段抽样”，小域轨迹会被重复，大域有的轨迹一次都抽不到。OpenVLA 写他们跑了 27 个 epoch，动作 token 准确率要过 95% 才开始像能控臂。那 27 是针对他们已经加权过的混合物，不是针对磁盘条数。你照抄 27 但自己用 α=1 无 cap，等于让厨房再读 27 遍，双臂仍然只是厨房的 1%。报告里要写：epoch 的分母是加权后的期望计数，还是原始 $n_d$。

### 5.2 每域上限：截断条数，而不是截断已经归一化的概率

直觉。有人看见 88% 就说“把最大域的概率 clip 到 40% 再归一化”。clip 后再归一化，40% 会重新胀回去，因为其余域的原始份额太小，分母跟着变小。对 88.5%、8.8%、1.8%、0.9% clip 到 40% 再归一化，最大域仍约 78%。小域几乎不回升。上限必须加在计数或未归一化权重上。

机制。先把有效条数写成 $n_d'=\min(n_d,C)$，再送进温度公式：

$$
p_d=\frac{(n_d')^{\alpha}}{\sum_j (n_j')^{\alpha}}.
$$

$C=400$、α=1 时，四域变成 400、400、200、100，总和 1100。于是 $p=(0.3636,0.3636,0.1818,0.0909)$。最小域从 0.885% 升到 9.09%，大约十倍。厨房和 Franka 被放在同一条起跑线：它们都触及上限，不再靠磁盘上的万级条数抢梯度。WidowX 和双臂因为本身低于 400，保持原条数，相对份额上升。

Octo 的手工规则是同一思想的非公式版。第 III-B 节：删掉没有图像流、不是 delta 末端控制、过于重复、分辨率过低或任务过窄的集合；把剩下的标成“更多样 / 更少样”，多样的加倍；对重复 episode 很多的集合降权。OpenVLA 跟随这张表，并写明 DROID 以 10% 加入后，动作 token 准确率一直偏低，于是在训练最后三分之一去掉 DROID，把它的权重重新分给其余集合。上限、加倍、降权、中途踢出，都是在改 $n_d'$，不是在改网络宽度。

数学。加 cap 后的有效域数用同一条 $D_{\mathrm{eff}}$。四域在 $C=400$、α=1 时 $D_{\mathrm{eff}}\approx 3.32$，从 1.26 抬起来。这不是“数据变多了”，是 batch 内的碰撞熵变大了。过采样倍数对双臂变成 $0.0909/0.00885\approx 10.3$。你必须同时看两个数：小域被看见的频率，以及小域每条轨迹被重复的次数。频率太低学不会；重复太高过拟合。cap 是这两端之间的螺丝。

代码落点。本课实验函数 `cap_counts` 只做 `min(n, C)`。不要把 cap 理解成“每个 batch 最多 C 条来自该域”的硬配额，那是另一种 sampler（带拒绝的 multinomial），实现更重，公式也不同。Octo 还提到 shuffle buffer：小 buffer（2 万）加轨迹级交错会严重伤害零样本；他们把帧级交错提前到解码图像之前，buffer 可到 50 万，并且每条轨迹最多抽 100 步。混合物和 shuffle 质量是两件事。混合物对了、同一条长轨迹连续占满 batch，模型看见的仍是单域。

验证。CPU 实验断言：$C=400$ 后最小域份额比未截断的 α=1 高出至少 0.05，最大域份额下降至少 0.3，$D_{\mathrm{eff}}$ 上升至少 0.5。互动实验把 $C$ 做成滑条：只有当你把 $C$ 降到 400 附近，清单上的“小域回升”才会亮。

### 5.3 动作空间：粗对齐保住形状，保不住语义

直觉。Franka 的 7 个关节角和 WidowX 的末端增量不能逐维平均。就算都叫“x”，一个可能是基座坐标的米，一个可能是腕部坐标的厘米，一个可能是速度。OXE 选择把它们压成同一形状：7 维末端加一个终止维，每维 256 箱。形状对齐之后，监督可以写成同一条交叉熵。语义对齐没有发生。

机制。OXE 第 IV-A 节逐步做了这些事：选一路规范相机；缩到同一分辨率；把原动作转成 7 DoF 末端；离散化前按数据集各自归一化。他们写明不对齐坐标轴，并允许绝对、相对或速度。同一输出向量在不同机体上“去归一化”的规则不同。模型必须从图像里的手臂外形、或从某个机体条件，推断现在该用哪一套逆变换。RT-1 原论文的动作还包含底盘 3 维和模式开关（臂 / 底盘 / 终止），OXE 的 RT-X 实验把控制对象收束到操作臂末端。你读代码时要看当前混合物用的是 RT-1 的 11 维风格还是 OXE 的 7 维风格，不要混。

Octo 的过滤更严：只保留图像观测和 delta 末端控制；夹爪约定统一为 +1 张开、0 闭合；缺失的相机通道零填充。OpenVLA 跟随“至少一路第三人称相机 + 单臂末端控制”，把每维动作按训练集 1% 与 99% 分位分到 256 箱，避开离群点把箱子拉宽，并覆盖 Llama 词表里最少使用的 256 个 token。第 25 课已经讲过分位和箱宽；本课只强调：分位是按混合物统计的。若 88% 样本来自厨房，1% 和 99% 分位几乎就是厨房动作的分位，双臂的关节行程会被压缩到少数箱，或者被当成离群点剪掉。

数学。记数据集 $d$ 的原始动作 $a^{\mathrm{raw}}\in\mathbb{R}^{k_d}$。粗对齐是一个数据集专属映射 $\phi_d:\mathbb{R}^{k_d}\to\mathbb{R}^{7}$，再按该数据集的分位 $q_{d,1},q_{d,99}$ 缩放到离散箱。训练看到的是 $\mathrm{bin}(\phi_d(a^{\mathrm{raw}}))$。政策输出箱编号后，必须用同一套 $\phi_d^{-1}$ 还原。若训练时 $d$ 从未以足够频率出现，$\phi_d^{-1}$ 会在错误的分位上工作。机体占位符的合法用途就在这里：它是选择 $\phi_d^{-1}$ 的索引，不是任务标签。一旦占位符能预测“这个实验室总是pick can”，它就越权了。

代码落点。OpenVLA 训练把动作当语言 token，损失只加在动作 token 上。Octo 用扩散头在连续末端空间去噪，夹爪单独对齐。RT-1 对每维 256 箱做分类交叉熵。三种头都假设 batch 内的 7 维已经是“同一件事”。本课不改这些头，只要求 sampler 在组 batch 前完成 $\phi_d$，并在日志里记录每个域的 $\phi_d$ 版本哈希。

验证。在玩具数据里给双臂域写关节动作、给其余域写 Δee。若对齐函数错误地把关节角当成末端增量送进同一归一化，泄漏探针会更早亮：模型靠“动作数值范围”就能分开域，连图像都不需要。CPU 实验不模拟这一步；互动实验用标签标明双臂是关节、其余是 7D Δee，提醒你对齐合同存在。真要测 $\phi_d$，在自己的 loader 里对每个域打印动作分位，确认厨房的 $q_{99}$ 没有覆盖掉双臂的行程。

### 5.4 相机外参：没写进动作向量的坐标系

直觉。第三路相机若永远从右肩往下看，物体在图像右侧就意味着“已经靠近夹爪”。换到正前方俯视，同一像素位移对应完全不同的末端增量。OXE 说相机观察仍因相对机体的位姿和相机本身差异而大不相同。Octo 预训练约 27% 含腕部相机，其余没有。把有腕和无腕的样本零填充成同一张量，模型可以学会：腕部全零就该用第三人称几何，腕部非零就该用近端几何。这是合法条件。若某机体永远有腕、某机体永远没有，腕部通道就泄漏了机体 ID。

机制。外参是相机相对机体或世界的位姿。公开数据集很少提供可训练的外参数值；它们被烤进像素。政策若在单域内成立，往往是因为外参固定。跨域以后，外参成为未观测混杂。粗对齐只做“选一路规范相机并 resize”，没有把像素坐标映射到机体坐标。OpenVLA 还把输入分辨率定在 224×224，因为 384×384 在他们的 Bridge 小实验里没有带来收益、训练却慢三倍。分辨率合同会抹掉腕部小物体，也会抹掉标定板。外参问题不会因为 resize 消失。

语言条件帮不上忙。指令写“把杯子放到盘子上”，没有写“相机在左肩 30 度”。模型必须从像素推断几何。若训练中 Google 厨房永远同一只相机，推断会退化成“看见这只相机外壳就执行厨房技能”。这和桌布捷径同构，只是特征从布变成了镜头畸变和支架。

数学。把像素 $u$ 与机体坐标 $x$ 的关系写成 $u=\pi(E_d x)$，其中 $E_d$ 是域 $d$ 的外参，$\pi$ 是投影。政策直接学 $a=f(u,\ell)$。若 $E_d$ 与任务标签 $y$ 在训练集上可互预测，最优 $f$ 可以忽略 $\ell$。负对照通过打乱 $\ell$ 或打乱域标签来拆开这条边。本课不估计 $E_d$，只要求评测集包含“同一机体、移动相机”或“同一相机位、换机体”。OXE 的评测没有系统扫外参；他们的跨机体迁移实验更多是换手臂、换数据集。外参仍是你自己 recipe 里要写明的风险。

代码落点。Octo 对第三人称做随机裁剪再缩到 256×256，腕部不随机裁、缩到 128×128。缺失相机被 mask。OpenVLA 限制为至少一路第三人称，把异构传感器留到未来工作。你若在缩小版里混入手腕，要给“有腕 / 无腕”单独做一张表，不要只报平均成功率。

验证。互动实验给四个域写了不同相机配置。泄漏关闭时，去掉语言准确率应落到约 31%；泄漏打开时，去掉语言仍约 89%。外参捷径和 ID 泄漏在教具里合成了一个开关。真数据上要把“移动相机支架”列为单独探针，本课不编造该探针的真机数字。

腕部通道是缺失模态混合物，不是锦上添花。Octo 明文写：约 27% 的预训练数据含腕部相机，微调时常常只用第三人称反而更好；他们把原因归于训练里腕部太少。这和 α 是同一类算术：字段存在于 schema，不等于字段在 batch 里以足够频率出现。零填充腕部之后，模型看见的多数是全零张量。全零本身可以当合法开关，也可以当机体 ID：永远有腕的机体和非零腕部通道一一对应。处理办法是把“有腕 / 无腕”当成第五个域轴，单独算 $p_{\text{wrist}}$，不要指望主 α 自动照顾它。本课四域玩具把 Franka 标成第三人称+腕、双臂标成双目，只是提醒你记日志，不在 CPU 实验里模拟像素。

Language Table 在 OpenVLA 表 3 里占 4.4%，BC-Z 占 7.5%。这两个集合的语言密度远高于平均 56%。若 α=1 无 cap，它们未必进得了 batch；若你关心语言接地，应对语言密度高的集合做下限，而不是只对机体做 cap。下限和上限会打架：给语言集合加 floor，厨房的份额必须再让出一块。recipe 里写清 floor 的来源（任务需求）和 cap 的来源（防淹没），避免事后把两颗螺丝拧到同一格。本课主路径没有 floor，互动实验也没有；你若在扩展里加 floor，CPU 侧要加一条 check：带 floor 后语言集合 $p_d$ 不低于设定值，且四域和仍为 1。

### 5.5 语言指令噪声：缺标注比错标注更隐蔽

直觉。Octo 预训练只有 56% 样本有语言。没有语言的样本用目标图像条件。训练时他们还会随机把语言或目标图像清零，以便推理时两种条件都能用。结果是：模型必须能在零语言下输出动作。这是能力，也是漏洞。零语言通路一旦足够强，带语言的样本也可以不读语言。OpenVLA 更依赖语言，评测里专门设了多物体语言接地任务；他们发现没有互联网预训练的 RT-1-X 和 Octo 在干扰物场景里经常伸错物体。语言是不是条件，要靠打乱指令来测，不能靠“训练集里有字符串”。

机制。语言噪声至少四类。缺失：字段为空，只能走目标图像或纯行为克隆。模板：`pick {object}` 填槽，模型和物体检测器共享同一套名词，换自然说法就失败。错配：后期补标，句子和实际动作对不上。捷径句：句子里含机体或房间名，“kitchen google pick can”把 ID 写进了文本。打乱指令（instruction shuffle）把句子与轨迹解开：图像和动作还是配对的，话是别人的。若准确率几乎不掉，语言不是条件。若掉到接近随机，语言是条件。两种结果都有用，必须先测再声称 grounding。

RT-1 的指令由动词加名词构成，并按技能分组。他们在未见指令上测到 76% 成功，下一档基线低 24 个百分点。这个数字来自 RT-1 自己的厨房机队和 3000 多次真实试验，不能平移到 OXE 混合物。OXE 的 RT-2-X 把 Bridge 里出现、Google Robot 数据里没有的技能搬到 Google Robot 上，emergent skills 从 RT-2 的 27.3% 升到 75.8%；去掉 Bridge 后降到 42.8%。这是跨数据集的技能迁移，前提是语言还能指出那些技能。若 Google Robot 靠外壳就能做厨房里的事，去掉 Bridge 不该掉这么多。OXE 用这条消融支持“真的发生了跨机体迁移”。本课的负对照是同一逻辑的缩小版：打乱的是指令，不是整个 Bridge 数据集。

数学。记样本 $(x, \ell, a, e)$，图像、指令、动作、机体。语言政策 $f(x,\ell)$，泄漏政策 $g(x,e)$。打乱 $\pi(\ell)$ 后：

$$
\mathrm{Acc}_{\mathrm{lang}}= \mathbb{E}[\mathbf{1}\{f(x,\pi(\ell))=a\}],\qquad
\mathrm{Acc}_{\mathrm{leak}}= \mathbb{E}[\mathbf{1}\{g(x,e)=a\}].
$$

无泄漏时真值 $a$ 由 $\ell$ 决定，打乱后 $\mathrm{Acc}_{\mathrm{lang}}$ 应明显下降。有泄漏时真值 $a$ 由 $e$ 决定，$\mathrm{Acc}_{\mathrm{leak}}$ 在打乱 $\ell$ 后保持 1，打乱 $e$ 后下降。本课夹具 8 条样本，指令轮转一位但真值标签不动：无泄漏时语言政策从 1.0 降到 0；有泄漏时语言政策仍只有 0.5（每机体两条指令里只有默认那条碰巧命中），泄漏政策保持 1.0。机体 ID 加一取模后，泄漏政策降到 0，语言政策仍为 1.0。数字是夹具的，不是论文表。打乱时必须把“演示当时的动作标签”冻住，只改输入里的句子或 ID；若标签跟着新句子重算，打乱对照永远满分，探针作废。

代码落点。Octo 对无语言数据永远用目标图像；有语言数据随机丢语言或目标。OpenVLA 把指令当 LLM 提示。RT-1 用 USE 嵌入经 FiLM 调图像编码器。三种实现都可能在无语言通路上走捷径。负对照不要改模型代码，只改评测输入。

验证。CPU 实验固定轮转打乱，断言无泄漏时语言政策准确率下降超过 0.4；有泄漏时泄漏政策在指令打乱后仍为 1.0；打乱机体 ID 后泄漏政策降到不超过 0.5。互动实验把四种对照做成单选：完整、去掉语言、打乱指令、打乱机体 ID。

### 5.6 机体占位符：合法索引与非法标签

直觉。跨机体政策需要知道“现在这只手臂的夹爪符号和分位表是哪一套”。占位符（embodiment placeholder：一个显式 ID token，或图像里可识别的外壳编码）可以当索引去查 $\phi_d^{-1}$。OXE 的 RT-X 没有单独把机器人 ID 当输入；他们指望图像里的机体外观自己说话。外观能说话，就能泄漏。WidowX 的外形几乎只和水槽数据一起出现时，外形=任务。把 ID 写进 batch 只是把泄漏从像素挪到表格，更容易测，也更容易滥用。

机制。合法占位符只调节归一化、动作维掩码、可用相机头，不直接进入动作分类器的捷径路径。非法占位符与任务标签在训练集上一一对应。RT-1 第 6.3 节把 Everyday Robots 的课堂数据和 Kuka QT-Opt 的 20.9 万次成功抓取混在一起：课堂评测只掉 2 个百分点，箱中抓取从 22% 升到 39%；只在 Kuka 上训再放到 Everyday Robots 的箱中任务是 0%。形态不同、动作分布不同（RL 对人类演示），RT-1 仍然靠共视觉模式迁移了一部分。那次混合没有提供“Kuka ID → 课堂技能”的短回路，因为评测机体和数据机体不一致。OXE 混合物里，评测机体往往就在训练里，短回路会重新出现。

OpenVLA 在 Franka 上微调时特意挑了社区常用机体，控制频率 5 Hz 和 15 Hz 两套。他们发现 Diffusion Policy 在窄的单指令任务上更强，OpenVLA 在多物体、要听语言的任务上更强。语言接地是占位符的对手：占位符越强，语言通路越容易失业。本课教具把泄漏做成开关，就是把这条对手关系单独拿出来。

数学。把政策写成 $f(x,\ell,e)$。若存在函数 $h(e)$ 使得训练上 $a\approx h(e)$，则最优解可以令 $\partial f/\partial \ell=0$。打乱 $e$ 会摧毁 $h$，准确率下降证明 $e$ 被用了。打乱 $\ell$ 不摧毁 $h$，准确率不降证明 $\ell$ 没被用。两套对照要成对做，只做一套会误判。

代码落点。本课不要求在 MiniMind-O 里加机体 token。[第 02 课](02_multimodal_connector.md) 的 connector 可以把 ID 嵌成前缀向量；[第 08 课](08_dynamic_vision.md) 的 image id 用来区分多图，不要和机体 ID 共用一个位置编码轴。若你真加占位符，给它单独的 embedding 表，并在评测时提供“打乱表索引”的开关。

验证。互动实验的第三项清单：打开“写入 batch”，选去掉语言或打乱指令，准确率仍高于 80%。CPU 实验对应 `leak_policy_survives_instruction_shuffle` 和 `leak_policy_breaks_when_embodiment_ids_shuffle`。

占位符的合法测试可以写成最小对照表。同一条“抓住杯子”的指令，两个机体、两套 $\phi_d^{-1}$：输出箱编号可以相同，还原后的米制位移必须不同。若占位符只改了还原、没改任务选择，打乱指令仍会掉点，打乱 ID 只会让手臂走错尺度，不会让它去抓另一个物体。若打乱 ID 之后抓的物体变了，占位符已经在选任务。本课夹具把后一种做成泄漏政策：ID 直接等于默认物体。你在自己的模型里看到“换 ID 就换物体”，不要解释成正迁移，先当捷径。

OXE 的 RT-X 不加 ID、靠图像里的外壳。外壳测试和 ID 测试同构，只是特征在像素里。打乱外壳做不到（你不能在评测时给 Google Robot 换 WidowX 的网格），所以他们用去 Bridge 消融：技能源不在评测机体的数据里，外壳帮不上忙，成功从 75.8% 掉到 42.8%。那是论文级的“去掉捷径来源”。本课没有 Bridge，只能打乱 ID 和指令。规模不同，逻辑相同。

### 5.7 在公开实现中定位这些机制

OXE 使用 RLDS / tfrecord，字段按数据集变化：RGB 路数、深度、点云、动作字典都不统一。读一份混合物之前，先打印每个数据集的 `observation` 与 `action` 键。RT-1-X 的公开检查点按 OXE 的 7 维末端+终止来部署。Octo 提供 JAX 预训练管线和 PyTorch 可用的 OXE 数据加载器；混合物在附录表 III，代码里是数据集名到权重的字典。OpenVLA 的 PyTorch 仓库声明对 OpenX 有内置支持，附录表 3 是权重来源。这些仓库会变。本课只锁定论文里写死的数字，不锁定 GitHub 行号。

对照本课玩具，公开实现多了三层工程：分布式读 RLDS、巨大的 shuffle buffer、按时间步而不是按轨迹的交错。Octo 附录 E 把“shuffle buffer 太小”列为会显著伤害零样本的事项。你若只用数据集拼接再随机切，等于 α=1 且 buffer=1。公式对了，加载器仍能把混合物作废。

### 5.8 错误实现对照：看起来像混合，梯度仍是单域

三种会在 code review 里通过、在 $p_d$ 表上失败的写法，值得单独钉死。

第一种，拼接后再随机打乱。列表长度 11300，每个位置被抽到的概率就是 $n_d/N$。这是 α=1，不管配置文件里写了什么 α。修复：先按 $p_d$ 抽域索引，再在该域的索引表里抽一条。

第二种，对已经归一化的 $p_d$ 做 `min(p_d, 0.4)` 再除以新的和。前面算过，88.5% clip 到 40% 后仍会回到约 78%。修复：cap 加在 $n_d$ 或未归一化权重 $n_d^\alpha$ 上。

第三种，按轨迹组 batch，同一条长 episode 的连续帧占满 256。Octo 因此限制每条轨迹最多随机抽 100 步，并把帧交错放到解码图像之前。否则 $p_d$ 只决定“哪条轨迹进 buffer”，batch 内部仍然是单房间、单桌布、单外参。捷径特征在时间上高度自相关，模型会把它当成稳定条件。

配套的最小日志是三行计数：配置里的 $p_d$、loader 报告的域频率、loss 反传前实际用到的域频率（有的实现会因缺失字段丢掉样本）。三行对不上，先修 loader，不准改 α 来“补”。

伪代码合同（不可运行，只标计算顺序）：

```text
n_eff_d = min(n_d, C)
p_d = n_eff_d ** alpha / sum_j(n_eff_j ** alpha)
each training step:
    d ~ Categorical(p)
    i ~ Uniform(0, n_d)   # 或在轨迹内再抽一帧
    x, a = load(d, i)
    a = phi_d(a)
    maybe_drop_language(x)
```

`phi_d` 必须带版本哈希。厨房的分位表不能悄悄用到双臂上。OpenVLA 用 1% 和 99% 分位切 256 箱，分位是混合物统计量：厨房占 88% 时，分位几乎就是厨房的分位。cap 不但改采样频率，也改分位表里谁有投票权。这是第 25 课分箱和第 26 课混合的交点：混合物一变，箱子边界跟着变。主路径的 CPU 实验不重算分位，但 recipe 必须写“分位在加权之后还是之前统计”。

采样和损失加权不是同一颗螺丝。有人把 $p_d$ 保持 α=1，却把小域的 loss 乘上 $1/p_d$。这叫再加权，不叫再采样。再加权不改变 batch 里小域出现的次数，只改变那几条样本的梯度幅度。小域若一个 batch 里是 0 条，乘数再大也没有梯度。小域若是 2 条，乘数 10 会让这两条的噪声被放大十倍，优化器看见的是高方差而不是多样性。本课主路径只改采样，不改 per-sample loss 乘数。若你要试再加权，必须另开一臂，并在报告里写清：batch 组成没有变，变的是梯度幅度。互动实验的条形图测的是组成，测不到乘数。

OXE 表 I 给了容量和混合物的关系：在 Bridge 与 RT-1 这种大数据域上，35M 的 RT-1-X 低于原方法和单域 RT-1，55B 的 RT-2-X 才能超过。混合物变宽以后，同一套权重既要表示 WidowX 水槽，又要表示 Google 厨房。容量不够时，大域会把共享表示占满，小域的正迁移还没发生，大域自己先欠拟合。本课的 $D_{\mathrm{eff}}$ 只描述 batch 多样性，不描述模型是否吃得下。α 降到 0 把 $D_{\mathrm{eff}}$ 拉到 4，35M 的骨干仍可能哪一域都学不好。缩小版线性头可以演示“频率变了、损失跟着变”；演示不了 55B 才吃得下 9 机体这件事。报告里这两句话要分开写。

RT-1 在单机队内部已经遇到过“多样性比数量更关键”的结论。他们用 13 台 Everyday Robots、17 个月、约 13 万条演示覆盖超过 700 条指令，并在消融里比较数据量和数据多样性。OXE 把这件事放大到跨实验室：数量冠军（xArm / Google Robot 的超大集合）和多样性冠军（Franka 的多场景）不是同一个机体。α=1 把票打给数量冠军；cap 和多样性加倍把票分给场景更多的集合。Octo 对“更多样”的集合加倍，就是在没有精确 α 公式时手工做这件事。OpenVLA 表 3 里 Bridge 13.3%、Fractal 12.7%、Kuka 12.7%，三个来源被压到接近同一量级，而原始条数绝不是 1:1:1。那张表是加权结果。把它读成“三个数据集一样大”，会在自己的 loader 里用 α=1 复现失败。

[第 01 课](01_baseline_reproduction.md) 的纪律在这里同样适用：混合物文件要有哈希，α、$C$、域名单写进配置，不能用会移动的 `latest` 充当版本。CPU 实验不读真实 OXE，所以它证明的是公式和夹具，不是加载器。加载器正确性只能用“每个域的实际 visitable 计数”来证明：训练 1000 step，记录各域出现次数，对 $e_d$ 做卡方或至少看相对误差。

缩小版主路径只用四域计数和 8 条负对照样本，不读图像。若要把同一套 α 和 cap 接到真实 RLDS，按下表扩，但仍不进入本课验收。

| 字段 | 缩小版 | 真实 OXE 子集（可选扩展） |
|---|---|---|

| $n_d$ | 10000/1000/200/100 | 你自己统计的 episode 数，写进报告 |
| 动作 | 标签：Δee 或关节 | $\phi_d$ 后的 7 维末端，分位按混合物重算 |
| 相机 | 标签 | 一路第三人称，分辨率按模型合同 |

| α | 0 / 0.5 / 1 | 先扫同一网格 |
| $C$ | 400 演示 | 按最大域的目标份额反推 |

OpenVLA 表 3 的百分比可以当“别人已经加过手工权重”的参考，不要当成 $n_d$。若你的 loader 按 episode 均匀读 Bridge，你得到的是 α=1 的 Bridge 份额，通常远高于 13.3%。13.3% 是他们混合物里的目标 $p_d$。为避免抄错，把原文列出的主要份额单独抄在报告里，并标明“已加权”：

Octo 表 III 只给出百分比、没有在 HTML 正文里保留数据集名，三个最大集合各 17.0%。不要把 17.0% 和 OpenVLA 的 13.3% 加在同一行当“同一数据集的两次测量”。两张表的过滤规则不同：Octo 只用 delta 末端、25 集、80 万条；OpenVLA 97 万条，并短暂纳入 DROID。DROID 的教训写得很硬：10% 的权重下动作 token 准确率长期偏低，他们判断模型或权重还吃不下那份多样性，于是丢掉以免拖垮其余集合。混合物不是纪念册，塞不进去就要拿下来，并在报告里写“何时拿下、权重去了哪”。

可选真实子集若只能选三个，不要选三个都是 Franka 桌面。OXE 图 0 说 Franka 场景多样但不是轨迹最多。三个 Franka 集合看起来“跨实验室”，机体捷径仍然在。至少跨两种可见外形，再跨一种动作约定（末端对关节），负对照才有机会失败。

推荐缩小配置：

```text
mixture:
  alpha: 1.0
  count_cap: 400
  domains:
    google_kitchen: 10000
    franka_table: 1000
    widowx_sink: 200
    bimanual_rare: 100
probes:
  instruction_shuffle: rotate_prev
  embodiment_shuffle: rotate_next
  drop_language: true
leak_id_in_batch: false
```

把 `leak_id_in_batch` 打开只允许发生在负对照臂，不允许发生在声称“跨机体通才”的主臂。主臂若需要占位符，占位符只能索引 $\phi_d$，并且必须能通过打乱 ID 探针。

训练预算（缩小版）：CPU 数秒。不要把这个数字写到和 OpenVLA 21500 A100-hours 同一张“我们训练了”的表里。若做可选 GPU 扩展：冻结视觉、只训一个线性动作头，单卡 24GB、少于 1 万 step、单 seed，用来看 $p_d$ 改变时各域训练损失的相对下降速度。失败判定：α 从 1 改到 0.5，小域损失曲线无稳定差异。那说明步数不够或头容量不够，不能得出混合物无用。

```bash
python3 run.py check 26
```

`checks` 必须全为真。重点看：α=1 最大域超过 75%；$C=400$ 后最小域回升；指令打乱打掉无泄漏语言政策；泄漏政策在打乱指令后仍满分、在打乱机体 ID 后下降。

### Step 2: 手算一张三行表

用同一组 $n_d$ 手算 α=1、α=0、$C=400$ 的 $p_d$。把最大域、最小域、$D_{\mathrm{eff}}$ 抄到实验记录。允许和程序有 $10^{-4}$ 级舍入差，不允许方向反了。建议按这个顺序算，避免漏归一化：

1. 写下 $n=(10000,1000,200,100)$，$N=11300$。
2. α=1：直接 $n_d/N$，最大项 $10000/11300=0.884956$。
3. α=0：四项都是 $1/4=0.25$，$D_{\mathrm{eff}}=4$。
4. $C=400$：有效条数 $(400,400,200,100)$，和为 1100，最大两项 $400/1100=0.3636$，最小 $100/1100=0.0909$。
5. $D_{\mathrm{eff}}$ 建议展开平方再加，避免心算跳步。α=1 时

$$
\begin{aligned}
p^2 &= (0.884956)^2+(0.088496)^2+(0.017699)^2+(0.008850)^2 \\
&= 0.783147+0.007832+0.000313+0.000078 \\
&= 0.791370,
\end{aligned}
$$

于是 $D_{\mathrm{eff}}=1/0.791370\approx 1.2636$。几乎全部质量都在第一项。加 $C=400$ 后 $p=(4/11,4/11,2/11,1/11)$，

$$
\sum p_d^2=\frac{16+16+4+1}{121}=\frac{37}{121}\approx 0.3058,\qquad D_{\mathrm{eff}}=\frac{121}{37}\approx 3.270.
$$

有效域数从 1.26 升到 3.27，不是因为磁盘上多出了机体，是因为 batch 不再是单域。CPU 实验打印的 `effective_domains_capped` 必须和 $121/37$ 对上。
6. $B=256$ 的期望条数：把 $p_d$ 乘 256。α=1 的双臂期望 2.27，加 cap 后 23.27。

第 6 步是给 loader 日志用的。若你之后真的读 RLDS，1000 个 step 里双臂出现次数应围绕 $1000\times p_d$，不要围绕 $1000\times n_d/N$。两者在 α=1 无 cap 时重合，在其余配置下必须分开。

手算时不要用计算器的百分比四舍五入代替分数。88% 和 88.5% 在验收阈值 75% 附近都不危险，但 9% 和 0.9% 差十倍，正好是 cap 是否生效的判据。把 0.00885 写成 0.09，检查会假装通过。

### Step 3: 互动实验，先预测再揭晓

打开本课页面的四域教具。默认 α=1、$C=10000$、泄漏关闭。先在三个选项里选出“α=1 且不加上限时最大域会超过 75%”，再按“揭晓 batch”。然后必须再揭晓两次：把 $C$ 降到 400 附近；打开机体 ID 泄漏并选择“去掉语言”或“打乱指令”。三项清单都亮，验收才通过。预测选错时，条形图仍可看，但 Gate 不通过。

教具上的数字必须能对上 Step 2 的手算。α=1、$C=10000$ 时最大条应显示约 88.5%，不要显示 25%。把 α 拖到 0，四条应接近等长。$C=400$ 时厨房和 Franka 应收成一样高，双臂应从几乎看不见变成约 9%。若条形图和手算差一个百分点以上，先怀疑你看的是未揭晓状态（显示为破折号）或浏览器缓存了旧脚本。教具标明“教学模拟，不是模型输出”：条形图来自 $n_d^\alpha$ 的确定性计算，准确率来自固定的泄漏开关表，没有任何神经网络在跑。

泄漏开关打开时，去掉语言的准确率应仍接近 89%；关闭时约 31%。打乱机体 ID 在泄漏打开时应掉到约 28%，关闭时应仍约 83%。这四格是教具的玩具政策，不要写进论文对照。它的用处是强迫你亲手把开关拨到会失败的一侧。只停留在默认 α=1、泄漏关闭、完整输入，三项清单不会全亮，Gate 保持未通过。这是故意的：默认配置就是“按条数混合、不测捷径”的工业常见错误。

### Step 4: 只读对照公开百分比

打开 OpenVLA 附录表 3 和 Octo 表 III 的论文页，确认你没有把 17.0% 或 13.3% 写进本课玩具的 $n_d$。可选：把表 3 的百分比当成已经加权的 $p_d$，反推若 α=1 则对应的相对 $n_d$，体会“百分比是结果不是原料”。

### Step 5: 可选真实 loader 冒烟（不纳入最低交付）

若磁盘允许，读两个大小差一个数量级以上的 RLDS 数据集，不训练，只统计 1000 个采样 step 的域频率。比较 α=1 与 cap 后的频率。失败判定：实现了 cap，最小域频率仍与 α=1 相同。那是 sampler 没生效。

不要在本课做 7B 预训练，不要把 LIBERO 成功率写进本课报告。第 27 课才处理自回归 VLA 的训练与延迟。

## 8. 评测与测量

本课评测对象是混合物和探针，不是政策成功率。指标如下。

| 指标 | 定义 | 合格方向 |
|---|---|---|
| 最大域份额 | $\max_d p_d$ | α=1 无 cap 时应 &gt;0.75；加 cap 后应明显下降 |
| 最小域份额 | $\min_d p_d$ | 加 $C=400$ 后应 &gt;0.08 |
| 有效域数 | $1/\sum p_d^2$ | cap 或降 α 后应上升 |
| 期望 batch 条数 | $B p_d$ | 与条形图一致 |
| 过采样倍数 $r_d$ | $p_d/(n_d/N)$ | 小域在 α&lt;1 时应 &gt;1 |
| 语言打乱准确率 | 见 5.5 | 无泄漏时应大降 |
| 去语言准确率 | 输入不含 $\ell$ | 无泄漏时应接近随机；有泄漏时应仍高 |
| 机体打乱准确率 | 打乱 $e$ | 泄漏政策应下降 |

RT-1、OXE、Octo、OpenVLA 论文里的成功率只允许出现在“论文对照”段，并且必须带评测机体和是否 in-distribution。禁止把教具上的 89% 写成 OpenVLA 的 16.5 个百分点优势。OpenVLA 摘要的 16.5% 是相对 RT-2-X（55B）、29 个任务、多个机体的绝对成功率差；20.4% 是相对从零训练的 Diffusion Policy。那些数字有自己的协议，本课探针借不到。

把论文数字和本课夹具并排时，用两张表，不要拼成一张。论文表要有：文献、机体、是否微调、试验次数。OXE 写他们总共做了 3600 次评测、覆盖 6 种机器人；Octo 微调表每个域 20 次试验、约 100 条目标域演示；OpenVLA 的 Bridge 套件 17 个任务各 10 次、Google Robot 12 个任务各 5 次。次数已经不多。再从里面抽出“平均成功率”当跨论文排名，误差会盖过差值。本课夹具表只有 8 个逻辑样本，连置信区间都不该写。它只回答“公式方向对不对、探针能不能亮”。

语言接地评测还要禁止一项：只报“有语言时的成功率”。必须同时报打乱指令和去掉语言。OpenVLA 在多物体场景里专门测政策是否伸向指令指定的物体；RT-1 在未见指令上测 76%。两套协议都还保留了语言。若你的缩小政策在打乱指令后几乎不掉，却把 OpenVLA 的接地数字抄进讨论，读者会以为你也测了接地。其实你测到的是捷径。

样本量。CPU 夹具 $N=8$，只能证明公式方向，不能证明真机。若你做可选真实评测，N=25 的二项区间会很宽，第 31 课会专门算。本课提前立规矩：N 太小的成功率不进标题。

训练过程中的 $p_d$ 还可能漂。DROID 被 OpenVLA 在后三分之一拿掉，其余集合的份额会整体抬升，厨房若原本 12.7%，再分配后会更高。你若只在 step 0 打一张混合物饼图，报告会和 step 20 万的真实频率对不上。最低交付要求配置里的静态 $p_d$；可选扩展要求每隔固定 step 记一次域频率，画成折线。折线若在没有改配置的情况下自己走形，loader 的 shard 或丢样本在改混合物。本课 CPU 实验是静态的，不会漂；真实训练会漂，要把漂当成故障而不是“模型自己学会了重加权”。

## 9. 验收条件

同时满足以下条款，本课才算完成。缺一条就不能把混合物标成“已平衡”。

1. CPU 实验 `checks` 全为真，产物哈希可复查。
2. 手算或程序给出的 α=1 最大域份额大于 75%。
3. $C=400$ 后最小域份额相对未截断 α=1 回升，且最大域下降。
4. 指令打乱使无泄漏语言政策准确率下降超过 0.4。
5. 机体 ID 泄漏政策在指令打乱后保持高准确率，在机体标签打乱后下降。
6. 互动实验先提交正确预测，再触发三张清单：α=1 过大域、cap 后小域回升、泄漏可触发。
7. 报告区分 OXE 仓库规模（22 机体、1M+）与各模型实际使用的子集（RT-X 9 种操作臂 / 35 万；Octo 80 万 / 25 集；OpenVLA 97 万）。
8. 没有把 CPU 或教具准确率写成真机成功率。

出现以下任一情况，验收失败：

- 用 clip 概率再归一化当作 cap，最小域没有回升；
- 只报平均 $p_d$，不报最大 / 最小；
- 负对照只打乱像素、不打乱指令和机体；
- 声称“模型不需要语言也能干”却没有泄漏开关的对照臂；
- 把 OpenVLA 表 3 的百分比填进本课 $n_d$；
- 把 OXE 的 22 种机体写成 RT-X 的训练机体；
- 把教具 89% 或夹具 1.0 写进真机成功率栏；
- 互动实验没有先提交预测就揭晓，三项清单未齐。

验收不是礼貌。混合物一旦写进后续 VLA 训练，错误会变成“模型结构不行”的假诊断。本课过关的唯一证据是：公式、cap、两套打乱，三件事都能在你的日志里复算。

## 10. 根据症状定位失败环节

| 症状 | 先查 | 不要先改 |
|---|---|---|
| α=1 最大域不到 75% | $n_d$ 是否被改成接近均匀 | 不要先改模型 |
| cap 后小域份额几乎不变 | 是否在归一化后的 $p_d$ 上 clip | 不要加大 $C$ 蒙混 |
| cap 后小域训练损失先降后升 | $r_d$ 是否过大、小域被读了几十遍 | 不要立刻再降 α |
| 打乱指令准确率不降 | 泄漏开关、桌布、相机是否绑死任务 | 不要加语言 dropout 当修复 |
| 打乱机体 ID 准确率不降 | 政策是否根本没用 $e$，或 $e$ 没进输入 | 不要宣称“已经鲁棒” |
| 去语言准确率仍高且泄漏关闭 | 图像里是否仍有可读的机体外壳或房间 | 加更强的视觉随机化，而不是加 α |
| 真实 loader 频率对不上 $p_d$ | shuffle buffer、按轨迹还是按步、是否每条轨迹抽固定步数 | 不要先改 α |
| 三行日志（配置 / loader / 反传）对不齐 | 缺失字段被静默丢弃、多卡各读各的 shard | 先修计数，再谈 α |
| 加 cap 后厨房动作分位表仍统治 256 箱 | 分位是否在加权前用原始 $n_d$ 统计 | 按 $p_d$ 重采样后再估计分位 |
| DROID 一类集合动作 token 准确率长期偏低 | 权重是否过大、动作空间是否仍异构 | 允许中途降权或踢出，并记录再分配 |
| 微调目标域在预训练里几乎没出现 | $e_d$ 是否小于 1 | 给该域单独加 floor，而不是只降 α |
| 双臂关节值被当成末端增量 | $\phi_d$ 版本哈希是否串了 | 按域单测反变换，不要先加正则 |
| 7 维动作在某机体上爆炸 | $\phi_d$ 和分位表是否用了厨房的统计 | 不要先加学习率 |
| 腕部全零的样本动作仍像有腕 | mask 是否没挡住腕部通道 | 不要先换扩散步数 |
| 报告里 22 和 9 混用 | 引用的是仓库还是 RT-X 实验混合物 | 改正文案，不改权重 |

Octo 附录 E 提供了一份“做过、没做成”的清单，和本课相邻：扩散头优于 MSE 和 256 箱离散；ViT 骨干在大数据混合物上优于 ResNet；只用 Bridge 单机数据的政策明显更弱。那些结论属于政策头和骨干，本课只借用一条：混合物变宽，零样本变好。他们的 WidowX 消融里，完整混合物 83%，RT-X 那档 11 集合 60%，单机 Bridge 43%（40 次试验平均，含语言和目标图像任务）。这是论文数字，复制时写明套件。本课四域玩具不重跑这条表。

## 12. 前沿对照与改造方向

公开方案。OXE 用粗对齐加 7 维末端，证明在小数据域上 RT-1-X 相对“原论文方法”和单域 RT-1 的平均成功更高，文中写均值高 50%；在大数据域上 35M 的 RT-1-X 欠拟合，55B 的 RT-2-X 才能超过单域。跨机体的 emergent skills 依赖 Bridge 这类外来技能源。表 II 把设计选择拆开，抄的时候必须带行号和评测列名（Emergent Skills / RT-2 Generalization）：

| 行 | 模型 | 数据 | Emergent Skills | Generalization |
|---|---|---|---:|---:|
| (1) | RT-2 55B | 仅 Google Robot | 27.3% | 62% |
| (2) | RT-2-X 55B | 机器人混合物 | 75.8% | 61% |
| (3) | RT-2-X 55B | 混合物去掉 Bridge | 42.8% | 54% |
| (4) | RT-2-X 5B，历史 2 帧 | 机器人混合物 | 44.4% | 52% |
| (5) | RT-2-X 5B，无历史 | 机器人混合物 | 14.5% | 30% |
| (6) | RT-2-X 5B，从零 | 机器人混合物，无 Web | 0% | 1% |
| (7) | RT-2-X 5B，Web 预训练后微调 | 机器人混合物，无 co-finetune | 48.7% | 47% |

行 (1)(2) 说明：评测机体自己已经有大数据时，泛化列几乎不涨（62% 对 61%），涨的是外来技能列。行 (2)(3) 说明：外来技能主要来自 Bridge，不是“数据量变大”四个字能概括。行 (4)(5) 说明历史帧对泛化有用，但也增加把桌布看稳的风险。行 (6) 说明没有 Web 预训练时，5B 几乎转不成可用政策。这些行都不能改写成本课夹具的 89%。它们回答的是“宽混合物加容量加预训练能不能迁移技能”，本课回答的是“窄混合物会不会根本看不见小域”。两个问题串起来才是完整故事：先看见，再谈迁移。Octo 把过滤做到只留 delta 末端，用扩散头和可插拔观察，强调微调到新传感器和新动作空间；评测 9 个真实平台。OpenVLA 把 VLM 骨干和更宽的 97 万条混合物结合起来，在 WidowX 与 Google Robot 上对 RT-2-X 做同任务对照，并开源微调。三者处理异构的方式不同：OXE 尽量少改结构、靠容量吞下粗对齐；Octo 用模块化 transformer 在微调时加观察；OpenVLA 把动作吞进词表，靠互联网预训练补视觉泛化。它们都没有在论文里把 $p_d\propto n_d^\alpha$ 写成主公式。Octo 写的是相对规模加手工加倍/降权；OpenVLA 直接复制那张表再加减 DROID。α 是本课为了把“按条数 / 按域均匀”连成一条轴而采用的标准温度混合，和多语言语料常用的 $n^\alpha$ 同源。不要把 α 写成 Octo 原文符号。

差距。缩小版和前沿的规模差是钱：64 张 A100 训 14 天、TPU v4-128 训 14 小时，本课都不做。机制差不是钱：α 与 cap 的公式、指令打乱、机体 ID 打乱，在 $N=8$ 和四域计数上就能做假。另一项机制差是真实 loader 的 shuffle buffer 与按步交错，CPU 实验覆盖不到；要补只能走 Step 5 的可选冒烟。OpenVLA 还发现冻结视觉编码器对 VLA 有害，必须微调视觉才能控臂。那是训练配方问题，本课不重做解冻顺序。[第 08 课](08_dynamic_vision.md)管动态分辨率和二维位置，本课的捷径探针不依赖 tile 数。本课只要求：混合物改变时，视觉捷径探针仍然有效。

动手改造（均在缩小版或单卡线性头，禁止把真机成功率当完成条件）：

1. **扫 α。** 改 CPU 实验或教具，对 α∈{0,0.25,0.5,0.75,1} 记录 $D_{\mathrm{eff}}$ 和最小域 $e_d$。预算：CPU 一分钟。预期：$D_{\mathrm{eff}}$ 随 α 下降单调递减。失败：某两个相邻 α 的 $p_d$ 完全相同，说明幂次实现写成了整数截断。建议同时画出 $r_{\text{双臂}}(\alpha)$：α=1 时为 1，α=0 时约 28。这条曲线比 $p_d$ 更直接地告诉你小域会被读多少遍。
2. **cap 与过拟合对打。** 固定 α=1，扫 $C\in\{100,200,400,1000,10000\}$，对最小域做训练损失对持出损失。预算：若只有计数，报告 $r_d$；若接上线性头，单卡少于 2 小时。预期：$C$ 太小则 $r_d$ 过大、持出损失升。失败：所有 $C$ 的持出曲线重叠，数据太少或头太弱。
3. **占位符合法化。** 给线性头一个 4 维机体 one-hot，但把动作真值保持为指令函数。训练后跑打乱指令和打乱 ID。预算：CPU 或单卡分钟级。预期：打乱指令掉点，打乱 ID 不应摧毁语言政策。失败：one-hot 存在时打乱指令不掉点，说明非法捷径已形成。
4. **Octo 式加倍。** 把四域里场景标签更杂的两域权重乘 2，再归一化，对比纯 $n^\alpha$。预算：CPU。预期：被加倍的域 $p_d$ 上升，且上升幅度可用手算复核。失败：乘 2 后份额不变，归一化写错。

顺手复现映射：

| 论文结论 | 缩小版对应 | 预期 |
|---|---|---|
| 按相对规模加权后仍有长尾（Octo 表 III 17% 到 &lt;0.1%） | 四域 α=1 的 88% 到 0.9% | 能复现方向：长尾存在 |
| 手工 cap/加倍改善多样性（Octo III-B） | $C=400$ | 能复现方向：最小域回升 |
| 去掉外来数据集，跨机体技能下降（OXE 去 Bridge，75.8%→42.8%） | 打乱或删除小域后看泄漏政策 | 不能复现绝对成功率，只能复现“缺数据则缺技能”的方向 |
| 语言接地需要多物体场景（OpenVLA） | 无泄漏时打乱指令掉点 | 能复现方向；绝对准确率是夹具 |
| RT-1-X 在小数据域正迁移、大数据域欠拟合（OXE） | 本课不训练 35M/55B | 不能复现，只在报告里引用原文条件 |

## 13. 论文与必读材料

读这些材料时带着本课的混合物问题，不要把它们读成“通才机器人已经完成”。

1. [Open X-Embodiment: Robotic Learning Datasets and RT-X Models](https://arxiv.org/abs/2310.08864)  
   带着什么问题读：摘要里的 22、21、527、160266、1M+ 各指仓库的哪一层？第 IV-A 节的粗对齐到底对齐了什么、明确没对齐什么？第 IV-C 节为何实验混合物是 9 种操作臂？图 2 的小数据域正迁移和表 I 的大数据域欠拟合，对你选择模型容量有何约束？去 Bridge 的 emergent skills 消融怎样成为“跨机体迁移”的证据，而不是平均分涨了？

2. [Octo: An Open-Source Generalist Robot Policy](https://arxiv.org/abs/2405.12213)  
   带着什么问题读：150 万到 80 万的过滤规则如何改变混合物？25 个数据集的权重为何“相对规模 + 手工”而不是纯 α？27% 腕部、56% 语言对零语言通路意味着什么？附录 E 的 shuffle buffer 和每轨迹最多 100 步，怎样能让一张漂亮的 $p_d$ 表在训练时作废？表 II 里完整混合物 83%、RT-X 混合 60%、单机 43%，评测次数和任务是什么？

3. [OpenVLA: An Open-Source Vision-Language-Action Model](https://arxiv.org/abs/2406.09246)  
   带着什么问题读：97 万条如何从“超过 200 万”的 OpenX 里筛出来？表 3 的百分比与 Octo 有何同构？DROID 10% 又在后三分之一被丢掉，说明加权不是一次定终身。16.5% 和 20.4% 的对照协议是什么机体、多少任务？微调段为何要单独看多物体语言接地，而不是只看单指令桌面任务？

4. [RT-1: Robotics Transformer for Real-World Control at Scale](https://arxiv.org/abs/2212.06817)  
   带着什么问题读：13 万条、13 台机器人、700+ 指令的单机队内部，数据多样性相对数据量的结论是什么？3 Hz、6 帧历史、81 个视觉 token 收到 8 个，这些效率选择如何限制它吞 OXE？第 6.3 节混合仿真物体和混合 Kuka 数据时，原任务掉多少、新任务升多少？那次跨机器人混合与 OXE 的 9 机体混合物有何不同？

读完四篇，下一课才处理自回归 VLA 的词表和串行延迟。数据能混、捷径能测之后，才能判断损失下降来自跨机体迁移，还是来自又认准了一块桌布。

四篇合在一起，只承诺三句可核对的话。第一句：仓库很大，22 机体、超过 100 万条，但任何一篇模型论文用的都是过滤后的子集。第二句：粗对齐把动作变成 7 维末端，并不统一坐标轴和夹爪语义，模型必须从像素或占位符知道自己在哪台机器上。第三句：没有打乱指令和打乱机体的负对照，你无法声称语言是条件、也无法声称没有 ID 捷径。本课的 α、$C$、八格探针就是把这三句话变成可计算的作业。做完作业，才配打开第 27 课去看词表为什么慢。

补充阅读问题时，把数字钉在章节上。OXE 摘要的 160266 项任务来自语言标注的统计，和 527 种技能不是同一粒度：技能是动词族，任务是动词加名词的具体指令。图 0 用 PaLM 从指令里抽物体和技能，长尾里有擦拭、装配这类非 pick-place。混合物若只按机体切、不按技能切，厨房里 90% 的 pick 仍然会淹没装配。α 解决的是域条数，不是技能条数。你若发现小机体域内部仍然全是 pick，需要第二张混合物表：域内再按技能加权。本课主路径不强制第二张表，但验收报告若声称“小域已覆盖装配”，必须拿出域内技能计数。

Octo 的 9 个评测平台含零样本和控制新观察、新动作、新机体的微调。Berkeley Insertion 加力/力矩，Berkeley Pick-Up 和双臂改关节位置，Berkeley Coke 与双臂是新机体。这些微调各用约 100 条目标域演示、同一套超参、单张 A5000 约 5 小时。它说明：混合物预训练的交付物常常是初始化，不是当场能换外壳的政策。本课的 $p_d$ 表要为这种微调留配额：目标域若会在下游出现，就不要在预训练里被压到每个 batch 期望 0.1 条。cap 是给预训练多样性留位置，也是给下游微调留可迁移的特征，而不是把所有小域都变成过拟合的 100 遍复读。

Octo 表 I 的微调平均成功率为 72%，从零训的对照更低，VC-1 视觉初始化也更低。这些是 6 个域、每域 20 次试验的平均，不是通用操作已经解决。本课不引用那张表里的单域百分比到标题，因为 HTML 转写会把列对齐弄乱；需要单域数字时打开 PDF 核对。本课只借用结构：同一套超参扫多个新机体，比只在厨房报一个高分更能暴露混合物有没有把特征学成外壳绑定。

零样本侧，Octo 写他们语言条件平均比公开的 RT-1-X 高 29 个百分点（三机体、每任务 10 次）。RT-2-X 55B 在 WidowX 和 RT-1 Robot 上与 Octo 接近。这些对照依赖“评测环境来自预训练数据”。换新场景、新技能时，Octo 附录写零样本会下降，新行为如翻转或精确插入下降更大。混合物再平衡解决的是“训练时能不能看见小域”，看不见则零样本更无从谈起；看见了也不保证新技能。本课验收停在“看见”和“探针”，不停在零样本成功。

RT-1 把仿真物体混进真实演示：在真实物体上的 seen skill 几乎不掉（文中 92 到 90），只在仿真里见过的物体上真实成功率从 23% 升到 87%。这是异构的另一种：同一机体、不同渲染。本课的桌布捷径是它的反面。仿真物体要迁移，模型必须忽略桌布和渲染统计、抓住物体形状；桌布捷径则是抓住了渲染统计。同一套视觉骨干，两种监督。负对照打乱指令之后，若准确率仍高，你更可能得到了桌布政策，而不是 RT-1 那种仿真到真实的物体迁移。不要把“去语言仍能抓”写成 RT-1 第 6.3 节的复现。

RT-1 自己的效率选择也限制了它能吞下多宽的混合物。35M 参数、TokenLearner 把每张图 81 个视觉 token 收到 8 个、6 帧历史拼成 48 个 token、3 Hz 控制。OXE 里 RT-1-X 把历史加长到 15 帧。帧数变长，时间上的桌布相关更稳，捷径更容易被当成“状态”。混合物变宽时，不要默认“多看几帧就能补多样性”。多看几帧往往是把同一块桌布看更久。本课教具没有时间维，CPU 实验也没有；你若在真实 loader 里开历史，评测打乱指令时必须打乱整段历史的语言字段，而不是只打乱当前帧。

Kuka 混合那组数字值得单独抄条件：QT-Opt 成功子集 20.9 万 episode，课堂评测 92% 对混合后约 90%（掉 2 个百分点），Everyday Robots 上的箱中抓取从 22% 升到 39%，只在 Kuka 上训再放到 Everyday Robots 为 0%。形态、动作来源（RL 对演示）、场景都不同。能升 17 个百分点，是因为评测机体在箱中任务上没有自己的大数据捷径可走，必须借用 Kuka 的抓取统计。OXE 的 9 机体评测常常是“评测机体就在训练混合物里”，捷径重新合法。本课泄漏开关模拟的是后一种：评测 ID 在训练集出现过。读 RT-1 第 6.3 节时，问自己评测机体的 ID 是否在训练里见过。见过，就要做打乱 ID；没见过，打乱 ID 测的是另一件事。
