# 第 41 课：用离散 token 统一图像与文本

> 内容：VQ 图像 token、统一词表、理解 / 生成注意力 mask 与共享 next-token 交叉熵<br>
> 建议周期：阅读约 75 分钟；CPU 实验数分钟<br>
> 硬件：无 GPU 可读完全文并跑 CPU 机制实验；复现论文规模需要多机多卡<br>
> 产物：两种 mask 表、码本索引范围夹具、Chameleon / Emu3 / Show-o 对照笔记

## 1. 图像离散 token 和文本怎样共用一套 next-token

[第 20 课](20_unified_understanding_generation.md) 把统一理解与生成拆成三条路。路线 C 走连续 VAE latent 和 flow matching，那是选修主线。路线 A 把图像查成离散编号，和文本进同一个自回归 Transformer。路线 B 让文本仍做 next-token，图像改成离散扩散式的“遮住再猜”。本课只做离散这条线：Chameleon（arXiv:2405.09818）、Emu3（arXiv:2409.18869）、Show-o（arXiv:2408.12528）。不重写速度场，不积分 ODE。

系统现在的限制很具体。MiniMind-O 和 Nemotron Omni 的视觉通路，默认是冻结编码器加投影，见[第 02 课](02_multimodal_connector.md)。那条路能回答“图里有什么”，但不能把同一组参数接着吐像素。第 20 课用 flow head 在连续 latent 上画图，训练目标和注意力规则都与语言模型不同。离散路线的主张更硬：图像先变成有限字典里的整数，之后的损失就是语言模型那一套交叉熵。

要改的模块是视觉进出口和注意力表，不是再挂一个外部绘图 API。图像进模型之前，必须经过向量量化分词器（VQ tokenizer：把图切成格子，每格在码本里找最近的编号）。文本仍走普通词表。两套编号拼成一张统一词表（unified vocabulary：同一个 softmax 要分的那一列整数）。验证改对了的标准有两条，都必须能在教学夹具里复现：理解路径的图像 query 能看见全部图像 key；生成路径的图像 query 不能看见光栅顺序上尚未生成的像素 token。CPU 实验再核对码本编号是否落在 $\{0,\ldots,K-1\}$。

把“共用 next-token”说死之后，还要能指出它不覆盖什么。它不覆盖第 20 课的直线路径速度场。它不覆盖下一课才处理的字、图、声日程和 KV 分段。它不覆盖 Janus 那种理解 / 生成分视觉编码器的分流，那张图留给交错日程课。本课覆盖的只有：一张图如何变成编号、编号如何写进词表、理解与生成各用哪张 mask、交叉熵盖在哪些位置。

“共用”这个词在实现里对应三处相等，必须逐项打勾。词表长度相等：分类头输出维是 $V_{\text{text}}+K$，不是两个头。嵌入矩阵相等：图像 id 和文本 id 查同一张表的不同行。损失公式相等：都是 $-\log\mathrm{softmax}(z)_x$。相等不意味着 mask 相等，也不意味着 $\mathcal{T}$ 相等。很多人只勾了第一处，就把模型叫做统一自回归。本课的验收要求三处都勾上，并且再勾第四处：生成路径未来格为 $0$。缺第四处，前三处仍然可以在泄漏下把 CE 做得很低。

从工程上看，离散路线像把[第 03 课](03_audio_codec.md) 的“声音变成编号”搬到图像上，再强迫编号走语言模型的那根因果链。差别是：声音有时间轴，图像要把二维光栅化；声音的 Talker 可以延迟几步，图像的未来格一旦泄漏，整张图的条件分布就作废。本课把泄漏写成可数的格子，而不是写成“生成质量不好”。

本课术语：

| 术语 | 简要解释 |
|---|---|
| VQ tokenizer | 把图像切块后查视觉字典，得到离散编号，也能把编号解回像素 |
| 码本 codebook | 那本有限字典，大小记为 $K$，每个编号对应一块视觉原型 |
| 统一词表 | 文本 id 与图像 id 拼成一张表，分类头输出维等于这张表的长度 |
| next-token | 根据已见前缀，预测下一个离散编号的条件分布 |
| 光栅顺序 | 图像 token 按行优先排成一维：先左后右、先上后下 |
| 理解 mask | 看图问答时的注意力表：图像格子互相可见，文本对图像可见、对自己因果 |
| 生成 mask | 文生图时的注意力表：提示因果，当前像素不能看未来像素 |
| MTP | mask token prediction：随机遮住图像编号再还原，Show-o 用来近似离散扩散 |
| NTP | next-token prediction：标准语言建模，Show-o 用来训文本 |
| QK-Norm | 对 attention 的 query 和 key 做归一化，用来压 softmax 输入的范数 |
| z-loss | 给最终 softmax 配分函数加惩罚，减缓 logit 漂移 |
| early-fusion | 一开始就把各模态编进同一序列，而不是先分塔再拼接 |

第 03 课的音频码本是声音版字典，见[第 03 课](03_audio_codec.md)。本课的码本是图像版，接口同构：整数进去、整数出来，重建有上限。第 08 课管动态分辨率和位置编码，不管这些整数从哪本字典来。

和第 03 课的差别也要写清。音频 RVQ 是同一帧上叠多本码本，Talker 还要处理 delay schedule。图像 VQ 在本课默认是单本码本、每个空间位置一个整数。Emu3 的时间压缩把若干帧收成更短的视觉段，仍然是单本字典，不是 8 路残差。不要把 Mimi 的 8 路编号表格直接抄到图像格子上。若你看到某篇工作用残差量化做图像，那是另一套 tokenizer，本课三篇主文献都不是。Show-o 的 lookup-free 量化器取消了“在码本向量里找最近邻”的查表，但输出仍是 $K$ 类整数，softmax 接口不变。

把“any-to-any”这个口号从机制里剥开。本课标题里的统一，指的是图像和文本共用 next-token 接口。它不自动包含语音、动作或屏幕点击。动作进词表是[第 24 课](24_vlm_to_vla.md) 的事；GUI 接地是[第 32 课](32_gui_agent_grounding.md) 的事；语音 codec 是第 03–04 课的事。有人把 Chameleon 能交错图文，写成已经会控臂，属于跨课挪用。交错本身也还没排日程：先出字再出图时 KV 怎么分段，是下一课的对象。本课结束时，你手里只有两张 mask 和一张词表，没有一份多模态时间表。

## 2. 本课解决的问题

离散统一的主流失败不是“词表里没有图像 id”，而是三件可以分开测量的错：tokenizer 自己已经重建不出的细节被写成模型弱；理解时把图像当成因果序列，左上角看不到右下角；生成时把整张图的双向注意力打开，未来格泄漏进当前预测。

本课要同时回答四个互相卡住的问题。

第一，图像怎样变成和文本同类的对象。Chameleon 把 $512\times 512$ 图编成 $1024$ 个离散 token，码本大小 $8192$，再训一个含这 $8192$ 个图像编号的 BPE 词表，总长 $65536$。Emu3 把 $512\times 512$ 图或 $4\times 512\times 512$ 视频编成 $4096$ 个离散 token，码本 $32768$，语言模型词表扩到 $184622$。Show-o 跟 MAGVIT-v2：把 $256\times 256$ 编成 $16\times 16$ 个 token，码本同样是 $8192$，在 Phi-1.5 的嵌入层上新加 $8192$ 行。三套数字不同，接口相同：每个空间位置一个整数，整数必须落在码本范围内。

第二，next-token 的 softmax 怎样共享。文本位置和图像位置可以盖不同的 loss mask，但分类头的输出维是同一张表。把图像 CE 写成“另一个头、另一套温度”，就不再是本课说的统一。Emu3 甚至把视觉 token 的损失权重写成 $0.5$，防止图像编号在长序列里压过文本；权重是标量，不是第二套分类器。

第三，理解为什么要看全图。看图问答时，问题里的“右边那只杯子”可能对应光栅顺序很靠后的格子。若图像 token 对自己也因果，左上的格子在算注意力时看不到右下，空间关系题会先垮。Show-o 把这件事画成 omni-attention：图像块全注意力，文本块因果，文本可以看全部已出现的图像。Chameleon / Emu3 的理解数据则把完整图像 token 当作前缀，后接要预测的文本；前缀内部若仍严格因果，那是实现选择，必须在 mask 表上核对，不能口头说“都是 AR”就结束。

第四，生成为什么不能看未来像素。文生图时，若第 $5$ 个图像 token 已经能读到第 $16$ 个位置上尚未决定的编号，训练就在作弊：teacher forcing 会把未来真值喂进来，推理时那些位置还是 mask 或尚未采样。Chameleon 和 Emu3 用因果 next-token 生成整张图，所以光栅上 $j>i$ 的格子对 query $i$ 必须为假。Show-o 生成图像时改用 MTP：当前步所有仍被 `[MASK]` 盖住的格子互相可见，但可见的是未遮或已预测的内容，不是“未来真值编号”。两种生成都禁止偷看未决定的像素真值，写法不同。

这四个问题不能分开买。只统一词表、mask 仍用纯文本因果，理解会变成“从左上往右下扫一眼”。只改理解 mask、生成仍双向看真值，采样曲线好看、推理必崩。只改 mask、编号越出 $K-1$，softmax 在错误切片上学习。所以本课的验收必须同时碰到 mask 和码本：一张表证明理解看见未来格，一张表证明生成看不见未来格，一组断言证明编号落在 $[0,K-1]$。

和第 20 课的边界写在这里。第 20 课问：同一组核心参数能否同时做视觉理解和图像生成，主实验走 VAE + flow。本课问：若坚持离散编号，理解和生成如何共用 softmax，又如何用 mask 分开信息可见性。第 20 课已经用一小节介绍过路线 A/B，本课把那两段扩成可执行协议。不重复 $x_t=(1-t)x_0+t\varepsilon$。

失败条件预先写死：

- 只报“一个 Transformer 既能 VQA 又能出图”，不报 mask 与 loss 位置；
- 把 Show-o 的图像全注意力，写成 Chameleon 生成时也可以看未来真值；
- 把 CLIP 连续特征的 Show-o‡ 数字，写成默认离散 Show-o 的数字；
- 把 Emu3 带 $\dagger$ 的 GenEval（短提示经过改写）写成原始短提示分数；
- 在 CPU 玩具上声称复现了 FID 或 POPE。

## 3. 开始前需要准备什么

本课不依赖 MiniMind-O 的训练脚本。需要的是因果语言模型的交叉熵，以及第 20 课“理解和生成不是同一张注意力表”的直觉。没有读过第 20 课也可以往下走，但遇到“为什么生成不能双向”时，要回到那一课的 mask 对照，而不是在本课里重做 flow 采样。

开始前把笔记本分成两栏。左栏只抄打开过的论文句：分辨率、码本、表号、步数。右栏写本课约定：教学图是 $4\times 4$、$K=8$、理解序列为图像在前、生成序列为文本在前、光栅行优先。左栏数字可以对外引用，右栏数字只能当夹具。有人把 Lab 里 $4\times 4$ 的“看 / 挡”写成“复现了 Chameleon-34B 的 captioning”，属于把右栏抄进左栏。

**上游事实（打开原文核对过）：**

- Chameleon：FAIR，arXiv:2405.09818v2；图像 tokenizer 基于 Gafni 等 2022 的方案，$512\times 512\to 1024$ token，码本 $8192$；
- Emu3：BAAI，arXiv:2409.18869；代码 [github.com/baaivision/Emu3](https://github.com/baaivision/Emu3)，视觉 tokenizer 权重 `BAAI/Emu3-VisionTokenizer`；
- Show-o：Show Lab / ByteDance，arXiv:2408.12528v7；代码 [github.com/showlab/Show-o](https://github.com/showlab/Show-o)，默认骨干 Phi-1.5（1.3B）。

**课程约定：**

- 浏览器里的 L 形色块是教学模拟，注意力由规则算出来，不是论文模型的前向输出；
- CPU 实验只证明公式可复核，不证明 MS-COCO FID 或 GenEval；
- 理解序列默认 `[图像 token][文本 token]`，生成序列默认 `[文本 token][图像 token]`。真实系统还有 `[SOI]` / `[EOI]` / `[MMU]` / `[T2I]` 之类特殊符，夹具省掉它们，以免和码本编号抢整数。

若只想核对公式，准备 Python 3.10 和本仓库 `experiments/` 即可。CPU 实验不读网、不写文件、不用 NumPy。不要为了“看起来更像训练”去对 mask 加随机噪声；本课要的是可复核。

硬件画像按三条路分开写，避免把 34B 的稳定问题和 1.3B 的 MTP 问题绑在同一张卡上。读完全文加 CPU 实验：笔记本即可。试 Show-o 官方推理：论文写当前版本基于 Phi-1.5 1.3B，单张 24GB 通常能放下 256 边长的前向，512 边长和视频微调另算显存。试 Emu3 tokenizer round-trip：视觉量化器比 8B 主干小，24GB 足够 encode-decode 一张图；跑 8B 生成需要按他们仓库的并行说明来，本课不提供配置。试 Chameleon-34B：论文表 2 写预训练用到 3072 卡并发、约 $4.28$M GPU hours 这一量级（7B 为 1024 卡、$0.86$M GPU hours）。这些数字只说明规模，不是本课最低交付。没有多机，不要把“没复现 34B 发散曲线”写成失败。

## 4. 完成后应具备的能力

1. 写出 $M=(H/f)(W/f)$ 和容量预算 $K\cdot M$，并指出 $K\cdot M$ 不是序列长度。
2. 写出共享 softmax 的交叉熵，标明图像 id 的偏移是 $V_{\text{text}}$。
3. 画出理解 mask 与生成 mask，指出图像 query 对未来格的真值。
4. 按原文区分 Chameleon 的全因果 early-fusion、Emu3 的纯 next-token、Show-o 的 NTP+MTP。
5. 解释 QK-Norm 和 z-loss 各压哪一处 softmax，不把训练发散写成数据不够。
6. 看到“统一模型 SOTA”时，能追问是 POPE、VQAv2、FID-30K 还是 GenEval，以及离散还是 CLIP 连续输入。

读完第 4 节，用这段自检，不通过就先别进公式。拿一张 $2\times 2$ 的图，编号 $0,1,2,3$，问题是“右下是什么颜色”。你应能指出：理解时 query 在文本，必须看见格子 $3$；生成时正在预测格子 $1$，不许看见格子 $2$ 和 $3$ 的真值。若你只能写出“都是 AR”，还没有把 mask 写成表。

再补一道：同一张图，Show-o 生成走到某一步，格子 $1$ 和 $3$ 仍是 `[MASK]`，格子 $0$ 和 $2$ 已经揭开。你应能指出：被遮的两格可以互看、也可以看已揭开的两格和全部提示，但输入里不得出现 $1$ 和 $3$ 的原编号。若你认为“反正都是全注意力，直接把原图喂进去”，MTP 已经作废。这道题和第 4 节第 3 条能力绑定：分不清 AR 因果和 MTP 全注意力，就还没读完 Show-o 图 5。

## 5. 原理：边造边讲

每个机制按同一节奏：为什么需要、怎么运转、精确定义、公开实现落在哪、怎么证明做对了。本课没有 MiniMind 源码，代码落点写在各小节末尾的公开仓库与论文公式里。

### 5.1 VQ：把图变成可查的编号

语言模型的分类头需要有限个类别。像素是连续的，直接对 RGB 做 softmax 没有词表。VQ 的办法是：先把图下采样成较小的特征图，再在每个空间位置把特征向量换成码本里最近的一项。得到的是整数网格，解码器再把整数变回像素。

类比：这像给每块瓷砖贴货号。贴完之后，仓库只记货号，不记每块瓷砖的全部纹理。类比失效处：货号冲突时两块不同的瓷砖会拿到同一号，重建必然糊；Chameleon 明确写了核心弱点是重建含大量文字的图像，所以 OCR 类任务被 tokenizer 自己卡住，后面的 Transformer 救不回来。

令图像为 $x\in\mathbb{R}^{3\times H\times W}$，下采样倍数为 $f$，码本 $\{e_k\}_{k=0}^{K-1}$。空间格子数

$$
M=\frac{H}{f}\cdot\frac{W}{f}
$$

每个位置输出 $u_j\in\{0,\ldots,K-1\}$。三篇论文的具体数字：

| 系统 | 输入 | $f$ 的空间部分 | $M$ | $K$ |
|---|---|---|---|---|
| Chameleon | $512\times 512$ | $1024$ token，约 $32\times 32$ | $1024$ | $8192$ |
| Show-o | $256\times 256$ | $16$ | $256$ | $8192$ |
| Emu3 | $512\times 512$ | $8$ | $4096$ | $32768$ |

Emu3 另有时间压缩 $4\times$，所以 $4$ 帧 $512\times 512$ 也是 $4096$ 个 token。Show-o 把 $3\times 17\times 256\times 256$ 的 $8$ FPS 片段压成 $5\times 16\times 16$。这些是 tokenizer 的压缩比，不是语言模型的层数。

空间 $f$ 不要和边长口头相除就交差。Chameleon 给出的是“$512\times 512$ 到 $1024$ token”，$1024=32\times 32$，对应空间步长 $16$。Show-o 写明 $256/16=16$。Emu3 写明空间 $8\times 8$ 压缩，$512/8=64$，$64\times 64=4096$。三套 $f$ 不同，同一张 $512$ 边长的图，序列长度可以差四倍。做对照实验时若没锁 $M$，你比较的是“谁的图更长”，不是“谁的 next-token 更好”。本课 CPU 实验把 $M$ 锁成 $4$，就是把这条变量冻住。

人脸和文字是两类 tokenizer 压力测试。Chameleon 给人脸上采样，因为生成人脸重要；同时又承认文字重建是弱点。Emu3 的重建样例强调 $512$ 和视频帧，没有在主文把 OCRBench $687$ 解释成 tokenizer 已经解决小字。理解侧 OCR 分数高，可能来自语言模型和后训练，不一定来自量化器保住了笔画。第 23 课的 OCR 探针在连续视觉编码器上问“看没看对位置”；离散这边要先问“量化器有没有把笔画留下来”。两个问题叠在一起，才会把“读错字”判到正确模块。

验证：encode 再 decode，记录重建误差。误差下不去的部分，禁止记成“统一模型还不够强”。Emu3 表 2 在 Pexels 视频上报告了 LPIPS / PSNR / SSIM，例如 $512\times 512$ 时 LPIPS $0.112$、PSNR $22.69$、SSIM $0.690$。那是 tokenizer 上限，不是 8B Transformer 的生成分。同一表还列了 $128$、$256$、$720$ 边长：LPIPS 大约在 $0.099$ 到 $0.112$ 之间，PSNR 从 $21.71$ 到 $24.30$，SSIM 从 $0.630$ 到 $0.771$。边长变大时 SSIM 上升，并不自动等于“格子越多理解越好”；理解涨点要另看语言模型侧，Show-o 表 4 才是那一列。

公开落点：Emu3 的 `BAAI/Emu3-VisionTokenizer`；Show-o 仓库里的 MAGVIT-v2 量化器；Chameleon 论文第 2.1 节，完整 tokenizer 权重以 FAIR 发布页为准。Chameleon 写明 tokenizer 只用许可图像训练，并在含人脸的图像上做过 $2$ 倍上采样，因为人脸生成重要。这些是数据选择，不是 mask 规则。缩小实验不要用人脸照片去“复现上采样”，用几何色块就够断言编号范围。

量化器的承诺损失（commitment loss）把编码器输出往码本向量拉。没有这项，编码器会把特征推离码本，整数 $u_j$ 变得不稳定，同一张图两次 encode 得到不同 id。Emu3 的训练目标把 L2、LPIPS、GAN 和 commitment 加在一起。本课 CPU 实验不训练量化器，所以把“同一张图两次 encode 必须得到同一串 id”写成纪律，而不是写成可学习项。若你微调量化器，先把这条纪律改成“允许的汉明距离上限”，并写进字段表。不写上限，后面的 DPO 存 token 就会和现场 encode 对不上，Emu3 才强调偏好对要存离散 id。

### 5.2 统一词表：偏移、特殊符、容量预算

有了图像整数，还要决定它们在语言模型里叫几号。两种接法。

接法一：图像编号占用文本词表里的一段，BPE 从一开始就包含它们。Chameleon 的 $65536$ 词表含 $8192$ 个图像 codebook token。

接法二：保留预训练 LLM 的文本词表，嵌入层追加 $K$ 行。Show-o 在 Phi-1.5 上“expand the size of the embedding layer by incorporating 8,192 new learnable embeddings”。Emu3 从零训，词表 $184622$，用 QwenTokenizer 处理多语言文本，再加视觉编号和特殊符。

令文本词表大小为 $V_{\text{text}}$（或追加前的大小）。图像 token 的统一编号

$$
\tilde{u}_j = V_{\text{text}} + u_j,\qquad u_j\in\{0,\ldots,K-1\}
$$

越界判定：若 $u_j<0$ 或 $u_j\ge K$，禁止写入序列。实现里常见的静默 `clip` 会把错误像素变成 $0$ 或 $K-1$，loss 仍下降，图在边角发糊。CPU 实验对 $-1$ 和 $K$ 要求抛错，另外再测一份 clip 对照，防止有人把 clip 当成合法编码。

特殊符另占整数，不算码本。Emu3 用 `[SOV]` 开视觉段、`[SOT]` 开视觉 token、`[EOV]` 结束，并在视觉序列里插入 `[EOL]` 换行、`[EOF]` 换帧；meta 文本用自然语言写分辨率、帧率、时长。Show-o 用 `[MMU]` / `[T2I]` 区分任务，`[SOI]` / `[EOI]` 包图像，`[SOT]` / `[EOT]` 包文本。Chameleon 在交错文档里用图像起止符把 $1024$ 个编号嵌进任意文本位置。本课夹具不模拟这些符，但你自己接公开权重时，必须先打印 tokenizer 的 special id，避免和码本切片重叠。

容量预算写成乘积，用来比较 tokenizer，不拿来当序列长度：

$$
C = K\cdot M = K\cdot\frac{H}{f}\cdot\frac{W}{f}
$$

Show-o 默认：$8192\times 256=2{,}097{,}152$。Chameleon：$8192\times 1024=8{,}388{,}608$。Emu3 单图：$32768\times 4096=134{,}217{,}728$。$C$ 更大只说明“每个空间位置的字典更肥、格子更多”，不说明生成一定更清晰。清晰还取决于解码器和训练数据。把 $C$ 写成参数量，是类别错误。

序列长度才是注意力的账单。$M=4096$ 的图，加上文本和特殊符，很容易顶满短上下文。Emu3 第一阶段上下文 $5120$、不进视频；第二阶段提到 $131072$ 才吃视频。Chameleon 上下文 $4$k，一张 $1024$ token 的图就会占掉四分之一窗口。这和第 08 课的 tile 账单同类：分辨率不是免费的。

### 5.3 共享 softmax：图像 CE 就是文本 CE

统一的数学定义是：在时刻 $t$，模型输出向量 $z_t\in\mathbb{R}^{V}$，$V=V_{\text{text}}+K$（加上特殊符后以实际词表为准），

$$
p_\theta(x_t\mid x_{<t})=\frac{\exp(z_{t,x_t})}{\sum_{v=1}^{V}\exp(z_{t,v})}
$$

$$
\mathcal{L}_{\text{CE}}=-\sum_{t\in\mathcal{T}}\log p_\theta(x_t\mid x_{<t})
$$

$\mathcal{T}$ 是计损失的位置。理解任务里 $\mathcal{T}$ 主要是答案文本；生成任务里 $\mathcal{T}$ 主要是图像编号。Emu3 预训练对视觉 token 再乘 $0.5$ 的权重，公式仍是这一条 CE，只是求和时图像项打折。Show-o 把文本位置的 CE 叫做 NTP，把被 mask 的图像位置的 CE 叫做 MTP，相加

$$
\mathcal{L}=\mathcal{L}_{\text{MTP}}+\alpha\mathcal{L}_{\text{NTP}}
$$

$\alpha$ 是超参。主文没有给出数值，其技术报告未公开该细节的，就不要编。两条 CE 仍共享同一个 $V$ 维 softmax。MTP 的 logits 写成 $\ell_i^t\in\mathbb{R}^{1\times(K+1)}$，多出来的一维是 `[MASK]` 本身，并不另开一套与文本无关的分类器。

验证三件事：

1. `logits.shape[-1]` 等于统一词表长度，而不是 $K$ 或 $V_{\text{text}}$ 之一；
2. 图像目标 id 等于 $V_{\text{text}}+u_j$，而不是裸的 $u_j$（除非词表设计就是重叠编码）；
3. 把目标写到文本切片里时，图像 CE 应变差。CPU 实验用正确图像 id 和邻号各算一次交叉熵，后者必须更大。

公开落点：Emu3 第 2.4 节 “we only need to train with the next-token prediction task using the standard cross-entropy loss”；Show-o 公式 (1)(2)(3)；Chameleon 第 2 节把图像和文本都当离散 token 做自回归。

手算一条，避免 softmax 维抄错。设 $V_{\text{text}}=32$、$K=8$，统一维 $V=40$。图像编号 $u=7$ 应写到目标 $39$。构造 logits：位置 $39$ 为 $2.4$，其余为 $0.05$。正确目标的交叉熵必须低于目标 $33$（编号 $1$）的交叉熵。CPU 实验里这两项分别约为 $1.55$ 和 $3.90$。若你把目标写成裸的 $7$，模型会在文本切片里找第 $7$ 个词，图像 CE 看起来在降，生成时解码器却去码本里取错行。偏移和 $K$ 范围是同一类接口错误，必须在进 Transformer 之前断言。

共享 CE 还有一个容易漏的切片：特殊符。`[MASK]`、`[SOI]`、`[EOI]` 若占用 $K$ 段内部的整数，量化器输出 $u=0$ 会和特殊符撞车。Show-o 把 `[MASK]` 放进图像 softmax 的第 $K+1$ 维，就是为了不和 $0,\ldots,K-1$ 抢号。Emu3 的 `[EOL]` / `[EOF]` 插在视觉序列里，但它们是词表里的特殊 id，不是码本条目。打印一次 `id_to_token[V_text:V_text+8]`，确认那八个是视觉原型而不是换行符。

### 5.4 理解 mask：看全图

注意力 mask $A_{qk}$ 为真表示 query $q$ 可以读 key $k$。理解一张图，空间上的依赖不是单向的：数“有几只红色物体”需要看见所有格子；读“左边是猫、右边是狗”需要同时看见两块区域。

本课教学用的理解布局：长度为 $M+N$ 的序列，前 $M$ 是图像，后 $N$ 是文本。

$$
A^{\text{und}}_{qk}=
\begin{cases}
[k<M] & q<M \\
[k<M]\ \text{或}\ [M\le k\le q] & q\ge M
\end{cases}
$$

图像 query 只看图像，而且看全部图像，包括光栅编号更大的“未来格”。文本 query 看全部图像，文本之间因果。图像 query 不看后面的文本，避免用答案泄漏去“看见”物体。

Show-o 图 5(a) 的 omni-attention 与此同类：图像全注意力，随后文本因果，文本能看前面的图像。它把任务符 `[MMU]` 放在序列结构里，不改变“看全图”这一条。

Chameleon 和 Emu3 在理解微调时，Emu3 写明“losses associated with vision tokens are disregarded for text-only prediction”：图像编号在前缀里，但不对它们计 CE。可见性仍取决于实现用的因果 mask 还是前缀双向。读权重时打印一帧 attention mask。若图像前缀是严格因果，那是全 AR 统一的代价：理解时左上确实看不到右下，空间题要靠更深的层把信息从右下往后传。本课夹具把理解路径设成图像双向，为的是把“看全图”写成可证伪的真值，而不是把三种论文按同一张表涂绿。

验收句：取图像 query 为光栅 $1$（$2\times 2$ 里的第二格），它必须看见格子 $2$ 和 $3$。看不见，理解 mask 就写成了生成 mask。

把 $M=4$、$N=2$ 的理解表整张写出来。序列下标 $0,1,2,3$ 是图像，$4,5$ 是文本。行是 query，列是 key，`1` 表示允许看见。

| q\k | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 0 图 | 1 | 1 | 1 | 1 | 0 | 0 |
| 1 图 | 1 | 1 | 1 | 1 | 0 | 0 |
| 2 图 | 1 | 1 | 1 | 1 | 0 | 0 |
| 3 图 | 1 | 1 | 1 | 1 | 0 | 0 |
| 4 文 | 1 | 1 | 1 | 1 | 1 | 0 |
| 5 文 | 1 | 1 | 1 | 1 | 1 | 1 |

读这张表的三个断言。图像行对图像列全是 $1$，这就是看全图。图像行对文本列全是 $0$，答案还没写出来，格子不许偷看即将出现的“右下是红的”。文本行对图像列全是 $1$，问句和答句都能读四个格子。文本行对文本列是下三角，第 $4$ 个 token 看不见第 $5$ 个。CPU 实验的 `understand_image_query_sees_all_image_tokens` 和 `understand_text_sees_full_image` 就是在核对第 $1$ 行和第 $4$ 行。你若自己实现时用了 `is_causal=True` 覆盖整张表，第 $0$ 行会变成 `1 0 0 0 0 0`，左右关系题在信息上已经不可达。

Show-o 的理解公式 (1) 与这张表一致：文本 token $v_i$ 的条件里写着全部图像 $u_1,\ldots,u_M$ 以及已经写出的文本 $v_{<i}$。它没有把 $u_j$ 再限制成 $j\le$ 某个光栅下标。谁在理解数据上对图像 token 做 next-token，等于要求模型从左上角预测右下角，那是生成目标，不该混进 VQA batch。

### 5.5 生成 mask：不能看未来像素 token

文生图时，像素 token 是要被预测的对象。训练若用 teacher forcing，未来位置上已经填着真值。若 mask 允许当前格读那些真值，模型学会的是抄后面的答案，不是根据提示和已生成的左边 / 上边去猜。

教学用的生成布局：前 $N$ 是提示文本，后 $M$ 是图像。

$$
A^{\text{gen}}_{qk}=
\begin{cases}
[k\le q]\ \text{且}\ [k<N] & q<N \\
[k<N]\ \text{或}\ [N\le k\le q] & q\ge N
\end{cases}
$$

提示因果，且看不见图像。图像 query 能看全部提示，图像内部只看光栅编号不超过自己的格子。对图像 query $i$（光栅序），未来像素集合 $\{i+1,\ldots,M-1\}$ 上 $A$ 必须为假。

这就是 Chameleon / Emu3 生成一张图时的账单：采样步数等于 $M$。Show-o 附录写，同样 $512\times 512$、下采样 $16$ 时，自回归需要 $1024$ 步；他们的离散扩散大约 $50$ 步，约为 $20$ 倍差距。步数差来自 mask，不是来自“模型更大”。

类比：写汉字可以看已经写完的左边，不能看纸上还没写的右边印好的标准答案。类比失效处：图像的“左边”在二维上还包括上面一行的右边，光栅顺序只是一种把二维压成一维的办法，并不是唯一的生成几何。Show-o 用全注意力 MTP，就是在质疑“必须按光栅因果”。

验收句：同一 query 光栅 $1$，生成 mask 看见的图像格只能是 $0$ 和 $1$，未来格计数为 $0$。提示 query 看见任何图像格，都算泄漏。

同一条长度 $6$ 的生成表。序列下标 $0,1$ 是提示，$2,3,4,5$ 是图像光栅 $0$–$3$。

| q\k | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 0 文 | 1 | 0 | 0 | 0 | 0 | 0 |
| 1 文 | 1 | 1 | 0 | 0 | 0 | 0 |
| 2 图0 | 1 | 1 | 1 | 0 | 0 | 0 |
| 3 图1 | 1 | 1 | 1 | 1 | 0 | 0 |
| 4 图2 | 1 | 1 | 1 | 1 | 1 | 0 |
| 5 图3 | 1 | 1 | 1 | 1 | 1 | 1 |

和理解表并排看。同样是“图1”当 query：理解表在下标 $1$，看见图像列 $0$–$3$；生成表在下标 $3$，只看见图像列 $2,3$（光栅 $0,1$），列 $4,5$ 必须为 $0$。CPU 实验把未来可见列表设成空表，对应这里第 $3$ 行的后两列。提示行对图像列全 $0$：写“画一个 L”时还没有图，不允许把即将出现的真值图当条件。若训练框架默认“padding 之外全可见”，提示行会变成整行 $1$，这是最常见的未来泄漏，CE 会异常好，推理时提示一结束图像立刻乱。

teacher forcing 在生成表上的含义也要写死。训练时第 $4$ 个位置的输入是真值光栅 $2$ 的编号，不是模型自己刚吐的编号。mask 只决定注意力，不决定输入来自真值还是预测。推理时没有真值，第 $4$ 个位置只能读已经采样的 $0,1$ 和当前自己。训练和推理的输入分布差叫 exposure bias，第 01 课已经用过这个词。本课多出来的约束是：就算输入是真值，注意力也不许读更后面的真值。只修采样、不修 mask，偏差还在。

### 5.6 Show-o 的第三张表：MTP 不是偷看真值

Show-o 不想为图像付 $M$ 步串行。它在图像段用 MaskGIT 式的简化离散扩散：按时间步把一部分图像 token 换成 `[MASK]`，用全注意力看未遮住的格子和全部文本，只在被遮位置上算 CE。推理时从全 mask 出发，每步并行预测所有 mask 格，保留置信度高的，低的再盖回去，迭代 $T$ 步。

训练时被遮位置的目标仍是原来的离散 id，条件是未遮区域，不是未来真值本身。若实现错误地把未遮逻辑写成“所有位置都能看原图 id”，MTP 就退化成复制。正确的 MTP loss mask 只在被遮的图像下标为真，提示位置为假。CPU 实验用提示 $2$ + 图像 $4$、遮住图像序 $\{1,3\}$，要求 loss 下标是 $[3,5]$（生成布局下的绝对位置）。

附录 D 还写了 CFG：同时算有条件和空文本条件的 logits 再合成。空文本是把条件换成空串，不是把图像真值泄漏进去。inpainting 之所以能零样本，是因为你可以只 mask 要改的那些图像 token，其余格保持可见：这张表仍是“被遮处预测、可见处当条件”，与理解用的看全图不是同一张表。

Show-o 默认理解也吃离散图像 token。表 4 说明：同样离散嵌入，数据从 $35$M 升到 $2.0$B、分辨率从 $256$ 升到 $512$，POPE 从 $73.8$ 到 $80.0$，VQAv2 从 $59.3$ 到 $69.4$。离散路线的理解不是免费附赠，要对新嵌入做大规模图文对齐。Show-o‡ 把理解输入换成 CLIP-ViT 连续特征后，POPE $84.5$、VQAv2 $74.7$，但那已经不是“图像也是 next-token 编号”的默认设定。引用时必须写有没有 $\ddagger$。

推理时的 mask 调度写成可执行步骤，避免和训练时的随机遮挡混为一谈。设图像格数 $M$，总步数 $T$，调度函数 $\gamma:[0,1]\to[0,1]$ 来自 MaskGIT，单调下降。第 $t$ 步仍被 mask 的数量 $m=\lceil\gamma(t/T)M\rceil$。对每个仍是 `[MASK]` 的位置 $i$ 采一个编号 $u_i^t$，置信度 $s_i$ 取该次采样的概率；已经揭开的位置把 $s_i$ 设成 $1$。然后把 $s_i$ 从小到大排序，最低的 $m$ 个位置重新盖上 `[MASK]`，其余保留。附录 D 还把有条件 logits $\ell_c^t$ 和无条件 $\ell_u^t$ 做 CFG 合成。关键约束：重新盖上的位置在下一步仍当作 mask，不得把“曾经预测过、又被盖回去”的编号当成可见真值。可见的只有本步保留下来的那些格，以及全部提示。这和生成 AR 表的“看不见未来真值”是同一条纪律，只是“未来”改成了“本步仍被 mask 的格”。

步数对照必须带分辨率。附录写：$512\times 512$、下采样 $16$ 时 AR 要 $1024$ 步；他们把 $5$ 步、 $25$ 步、$50$ 步的定性结果放在附录图里，$5$ 步大致能看出和提示有关，$25$ 步更贴提示，$50$ 步更细。主文“约 $20$ 倍”指的是 $1024/50$ 这一量级，不是任意分辨率都少二十倍。$256\times 256$ 的 $M=256$，AR 只要 $256$ 步，倍数会变。写进笔记时抄下采样率和边长。

### 5.7 Chameleon：从一开始就交错，稳定比堆层更先

Chameleon 的设定是 early-fusion：图像、文本、代码都是离散 token，同一个 Transformer 从零训到大约 $9.2$ 万亿 token、约 $2.1$ 个 epoch。第一阶段占 $80\%$：文本 $2.9$T、图文对 $1.5$T（$14$ 亿对）、交错文档 $400$B。图文对有一半时间图像在文本前，用来兼做 captioning。上下文 $4$k。7B 全局 batch 约 $8$M token，34B 约 $12$M token。

这条路在大于 $8$B、$1$T token 之后会在训练后期发散。论文把原因追到 softmax 的平移不变性：多模态熵差很大时，各模态通过抬范数抢 logit，bf16 范围被撑破。对策分三处：

1. QK-Norm：对 attention 内部的 query、key 做 layer norm，直接管进入 softmax 的范数。7B 去掉 QK-Norm 会在大约 $20\%$ epoch 处发散。
2. z-loss：对最终 softmax 的配分函数 $Z$ 加 $10^{-5}\log^2 Z$。这管的是词表上的 logit 漂移，不是 attention 内部。
3. 34B 把 RMSNorm 挪到残差分支上，写成 Swin 那种

$$
h=x+\mathrm{norm}(\mathrm{attn}(x)),\quad
y=h+\mathrm{norm}(\mathrm{ffn}(h))
$$

而 Llama-2 是先 norm 再进 attn/ffn。7B 另加 dropout $0.1$；34B 不用 dropout，因为和 norm 重排合不来。

这些稳定性细节看起来像训练玄学，其实和本课的共享 softmax 是同一件事：一张表要同时对低熵的图像编号和高熵的文本编号做归一化，范数会打架。只在数据配比上打补丁，不改 QK-Norm，34B 级的 early-fusion 会在你以为已经稳了之后突然 NaN。

评测上，Chameleon-34B 在文本基准上相对 Llama-2 有提升（论文表 6：MMLU $65.8$，GSM8k maj@1 $61.4$）。图到文方面，Show-o 表 1 转引 Chameleon-34B 的 Flickr30k $74.7$、VQAv2 $66.0$。人类对交错长文的偏好：相对 Gemini-Pro $60.4\%$，相对 GPT-4V $51.6\%$。胜率把平局记 $0.5$ 分。评测集有 $1048$ 条提示，其中 $441$ 条本身就是混合模态输入。绝对评价里 Chameleon 完全完成任务 $55.2\%$，对照 Gemini+ $37.6\%$、GPT-4V+ $44.7\%$；未加图的 Gemini / GPT-4V 更低，因为提示期望混合输出。论文自己提醒：提示来自众包不是真实用户日志，覆盖有限；OCR 和读图类任务几乎没出现；基线 API 只出文本，他们用 DALL-E 3 按模型自己写的 caption 补图得到 Gemini+ / GPT-4V+。引用 $60.4\%$ 时必须带着这些条件。图像生成不是它最强的卖点：Show-o 表 3 给 Chameleon-7B 的 GenEval overall $0.39$，Emu3 表 4 给 FID $26.74$。引用时写清模型尺寸和表号，不要把 34B 的 caption 和 7B 的 GenEval 合成一句“全面领先”。

SFT 阶段对模态配比敏感。论文写：若某一模态在 SFT 里严重失衡，模型会学到无条件的“该出图了 / 该出字了”先验，把该出的模态静音或过度触发。他们把 SFT 数据分成文本、代码、视觉对话、图像生成、交错生成和安全拒答；图像生成桶先用美学分类器筛到至少六分，再取最接近 $512\times 512$ 的 $64$K 张。视觉对话和交错数据用第三方高质量标注，不含 Meta 用户数据。安全桶覆盖文本和混合模态攻击。本课不复现这套对齐，但要把“SFT 配比会改变无条件模态先验”写进失败诊断：缩小实验若 $90\%$ 样本都在生成图像，模型会在纯文本问题上也开始吐图像 id。

推理还有一条和 mask 无关、和接口有关的约束。图像段长度固定为 $1024$，文本段变长。流式输出时，每一步都要把当前 id 拷回 CPU，判断是继续文本逻辑还是进入固定长度的图像块。非流式可以把整块图像 id 一次采完。两种实现的可见性规则必须相同：不能因为批处理就提前把后 $1023$ 个真值放进 key。教学实验不写这段控制流，只要求你在读社区推理代码时搜索 `image` 和 `mask` 两个词是不是同一处改的。

### 5.8 Emu3：只保留 next-token，视频也是编号

Emu3 把主张写进标题：Next-Token Prediction is All You Need。它从零训 $8$B（$32$ 层、隐 $4096$、中间 $14336$、$32$ 头、GQA 的 KV 头 $8$、RoPE base $10^6$、dropout $0.1$）。没有 CLIP 塔，没有扩散头。图像、文本、视频都进离散序列。表 3 把这些超参收成一列，上下文长度 $131072$ 也写在同一张表里。第一阶段并不使用这个长度，短上下文 $5120$ 才是图文从零训的起点。把 $131072$ 写成一开始就能吃视频，是读表错行。视觉 tokenizer 另有配置：基于 SBER-MoVQGAN-270M 预训练权重，码本 $32768$，latent 通道 $4$，压缩 $4\times 8\times 8$。主干 8B 和量化器约 270M 是两个模块，评测时不要把重建 LPIPS 写成 8B 的生成分，也不要把 8B 的 POPE 写成量化器的 OCR 能力。

数据格式：

`[BOS] {caption} [SOV] {meta} [SOT] {vision tokens} [EOV] [EOS]`

一部分样本把 caption 挪到 `[EOV]` 之后，专门构造理解数据。预训练两个阶段：先 $5120$ 上下文只吃图文，再 $131072$ 上下文加入视频。学习率 $5\times 10^{-5}$。视觉损失权重 $0.5$。

后训练按任务拆开。生成：质量微调只在视觉 token 上做 CE，分辨率从 $512$ 提到 $720$；再做 DPO，三名标注者打分，取最高 / 最低构成偏好对，token 直接存下来避免重新量化引入差异。理解：先图到文（视觉位置不计损失），再指令微调；图像短边按 $512$ 到 $1024$ 的窗口缩放。图像低于 $512$ 提到下限，高于 $1024$ 压到上限，中间保持原分辨率。这和 Show-o 把边长从 $256$ 统一拉到 $512$ 不同：Emu3 更强调保比例。保比例会让 $M$ 随宽高比变化，mask 表的宽度不再是常数。实现时不要写死 `M=4096` 而不读 meta 文本里的分辨率。meta 以纯文本形式写在 `[SOV]` 和 `[SOT]` 之间，模型先读到这些数字，再读视觉 id。漏读 meta、却假设所有图都是正方形，宽图的光栅会错位，未来格的定义跟着错。

结果用论文自己的表，不要升级成“已经替代所有扩散模型”。图像：带改写的 GenEval $0.66$，DPG-Bench $80.60$，DPO 后 DPG $81.60$ 但 FID 从 $12.8$ 升到 $19.3$（自动指标和审美偏好不是同一把尺）。视频：VBench 总分 $80.96$，类型标成 AR，对照表里其他公开系统多为扩散。理解：表 6 的 POPE $85.2$、VQAv2 $75.1^\*$、GQA $60.3^\*$、OCRBench $687$、MMMU $31.6$；星号表示相关训练图像被看见过。和 LLaVA-1.6-7B 比，Emu3 强调自己没有预训练 CLIP 和专用 LLM，这是架构声明，不是每一格都更高。

对机制课最有用的是两句。第一，视频未来预测也是 next-token：把 $2$ 秒 $24$ FPS 编成离散前缀，继续采样后面 $2$ 秒的编号，再解码。第二，DPO 可以直接加在自回归视觉 token 上，不必先把图送进扩散模型。本课不重做[第 16 课](16_multimodal_preference_optimization.md) 的 DPO 推导，只记下：偏好对必须存离散 token，重新 encode 会换编号。

打包（packing）是 Emu3 第一阶段能把上下文吃满的办法：多条图文样本拼进 $5120$，但完整图像不许从中间切断。切断会让一张图的下半出现在另一条样本的前缀里，理解 mask 的“看全图”对那张图不再成立，生成 mask 的光栅顺序也会跨样本错位。实现上要在文档边界插入不可见的注意力隔板，或者干脆保证 pack 只在 `[EOS]` 处切开。CPU 实验没有 packing，但字段表里的 `wrong_spatial_length` 就是在抓切错的图：一条样本的图像 id 个数必须等于 $(H/f)(W/f)$，多一个或少一个都是切段错误。

视频延长把同一条纪律沿时间复制。$2$ 秒前缀合法，继续采 $2$ 秒，再把这 $4$ 秒当新前缀。论文写他们观察到用 $2$ 秒上下文把未来扩到 $8$ 秒是可行的。教学上把它翻译成：时间维的 `[EOF]` 是帧边界，不是允许看见未来帧真值的许可证。生成下一帧时，已出现的帧可以看，尚未采样的帧不能看。这和图像内部的光栅因果同构，只是格子换成了帧。世界模型课会问预测像素还是预测表征；本课只要求：若你走离散 next-token，未来帧的真值编号就不得进入当前 key。

### 5.9 三条离散路线对照，以及和 flow 的分界

把三篇论文收成一张只含机制的表。能力数字仍回各自的评测节，不在这里横着减。

| | Chameleon | Emu3 | Show-o |
|---|---|---|---|
| 图像表示 | 离散 token | 离散 token | 默认离散；‡ 理解侧可换 CLIP |
| 文本目标 | 因果 CE | 因果 CE | NTP 因果 CE |
| 图像目标 | 因果 CE | 因果 CE | MTP（mask CE） |
| 图像注意力 | 与文本同一套因果 | 与文本同一套因果 | 图像全注意力 |
| 骨干 | 从零训 7B / 34B | 从零训 8B | 初始化 Phi-1.5 1.3B |
| 稳定手段 | QK-Norm、z-loss、34B norm 重排 | dropout 0.1、标准 LLM 件 | 每层前加 QK-Norm |
| 生成步数 | 等于 $M$ | 等于 $M$（视频可接着往后采） | 约 $50$ 步量级，主文写约少 $20$ 倍 |

第 20 课的路线 C 不进这张表。flow 的监督是速度向量，没有 $K$ 类 softmax。有人把 Show-o 的 MTP 叫做“离散 flow”，本课不采用：MTP 的样本空间是码本下标，flow matching 的样本空间是连续 latent。名字混用会把第 20 课的积分方向错抄到 mask 调度上。

Janus 在第 20 课里作为生成侧离散、理解侧语义编码器的对照。它的理解 / 生成分编码，以及 Show-o2、BAGEL、Transfusion 的阶段图，放到下一课的日程，不在本课展开。本课只要能指出：Janus 已经不是“同一套视觉 token 既理解又生成”。

读这张对照表时再问三个“同一”是否真的同一。同一套参数：三篇都声称一个 Transformer，Show-o‡ 在理解侧接 CLIP 时已经为理解开了第二条视觉路，生成仍走 MAGVIT 编号。同一套目标：Chameleon / Emu3 是，Show-o 把图像目标改成 MTP，文本仍是 NTP，损失相加。同一套 mask：只有 Chameleon / Emu3 在生成时坚持全因果；Show-o 图像段全注意力。三个“同一”里只要坏一个，口头上的“统一模型”就已经分叉。写实验报告时把这三个勾打在表头，不要只写模型名。

串行账单也要单独列。AR 生成一张 $M$ 格的图要 $M$ 次前向，每次 key 长度增加 $1$。MTP 生成要 $T$ 次前向，每次对当前仍 mask 的格并行分类，$T$ 由调度决定，Show-o 常用几十。理解一张图通常只要一次前向编码图像，再自回归吐文本。所以“统一”并不统一延迟：理解延迟像 VLM，AR 文生图延迟像超长补全，MTP 延迟像短步数扩散。第 10 课讨论过视频 token 不能无限增长；这里的 $M=4096$ 是同一类账单。Emu3 把单图 $M$ 做成 $4096$，必须配 $131072$ 的上下文才进得去视频。缩小实验用 $M=16$，延迟差不出来，但步数公式已经能写：$N_{\text{AR}}=M$，$N_{\text{MTP}}=T$。把 $T=50$、$M=1024$ 代入，就得到主文那句约 $20$ 倍。

### 5.10 把 mask 接到实现时要改哪几处

公开仓库里，mask 通常出现在三处，改一漏二会静默泄漏。

1. 训练时的 `attention_mask` 或 `is_causal` 开关。`is_causal=True` 会覆盖你手写的块状表。Show-o 这种图像全注意力，必须关掉全局因果，改用构造好的布尔矩阵。
2. loss 的 position mask。理解数据若对图像位置也算 CE，模型会把重建 tokenizer 当成主业。Emu3 理解阶段明确忽略视觉 token 损失。
3. 推理循环。AR 生成要逐步追加图像 id，每步的可见前缀只能到当前格。MTP 生成要维护哪些下标仍是 `[MASK]`，不能把尚未揭开的位置写成已采样 id 再让它们互看真值。

最小探针：构造一条长度为 $6$ 的序列，图像 $4$、文本 $2$，打印 $6\times 6$ 的 $A$。把本课 CPU 实验的两张表当 golden。差一个 `True`，就不要开始谈 FID。

下面这段伪代码与 CPU 实验同构，用来对照你自己的实现。不要把它贴进训练脚本就当论文复现。

```python
def understand_mask(n_image, n_text):
    length = n_image + n_text
    table = []
    for query in range(length):
        row = []
        for key in range(length):
            query_visual = query < n_image
            key_visual = key < n_image
            if query_visual:
                allowed = key_visual
            elif key_visual:
                allowed = True
            else:
                allowed = key <= query
            row.append(allowed)
        table.append(row)
    return table

def generate_mask(n_text, n_image):
    length = n_text + n_image
    table = []
    for query in range(length):
        row = []
        for key in range(length):
            query_visual = query >= n_text
            key_visual = key >= n_text
            if not query_visual:
                allowed = (not key_visual) and key <= query
            elif not key_visual:
                allowed = True
            else:
                allowed = key <= query
            row.append(allowed)
        table.append(row)
    return table
```

两张函数的参数顺序不同，是故意的：理解把图像个数写在前面，生成把文本个数写在前面，避免调用时把 $M$ 和 $N$ 对调。对调之后，生成提示会看见图像，泄漏探针会静默失败。CPU 实验的布局常量 `IMAGE_TOKENS` 和 `PROMPT_TOKENS` 与这里一致。你若在模型里用 `torch.tril` 生成理解表，先停下来，因为下三角恰恰删掉了未来格。

Show-o 仓库还要注意 task token：同一条图文，`[MMU]` 走理解 mask，`[T2I]` 走生成 mask。只换数据、不换 task token，等于把两张表平均掉。

inpainting 是同一套 MTP 表的零样本用法，不是新模型。把原图量化，只把要改的空间下标换成 `[MASK]`，其余格保持可见，提示换成“把红车改成蓝跑车”这类句子，再跑迭代揭开。外推同理：在图像网格外侧追加一整行或一整列 mask 格，让模型根据已有格子和提示去填。AR 路线要做同样的事，得先决定这些新格在光栅里插在哪、旧格是否还允许被改写，控制流立刻变长。Show-o 主文把“无需微调就能 inpaint / extrapolate”写成相对 AR 的产品优势。教学上只记一条：能零样本改局部，是因为生成表本来就按“哪些下标是 mask”工作，不是因为模型突然学会了编辑指令。

把 inpaint 写进自己的缩小实验时，字段表加一列 `keep_ids`：哪些空间下标必须原样保留。解码后这些位置的 id 必须等于输入。变了，说明 MTP 把可见格也更新了，或者你把可见格的 loss 打开了。CPU 实验没有 inpaint 夹具，这条作为可选断言，不计入八条必过。

Chameleon 推理另有工程约束：每步都要检查当前 token 是不是图像段，图像段长度固定为 $1024$，文本段变长。这不改变 mask 语义，但会改变你在哪一步从 GPU 把 id 拷回 CPU。教学实验不实现这一段。

### 5.11 tokenizer 上限、码本坍缩、越界：三种不同的糊

生成糊成一团时，先分三种病，不要一起加学习率。

Tokenizer 上限：encode(decode(encode($x$))) 已经丢了笔画。Chameleon 对重文字图像的重建失败属于这一类。对策在换量化器或提高 $M$，不在加 Transformer 层。

码本坍缩：训练后期只有一小部分 $k$ 被用到，$K$ 名义上是 $8192$，有效词表只有几百。利用率要单独记。Show-o 用 lookup-free 量化器，动机之一就是减轻查表坍缩；本课不展开 MAGVIT-v2 的公式，只要求你在日志里留利用率。

越界与偏移：模型吐出 $u=K$，或把文本 id 写进图像切片。统一词表越大，这种错越像“偶发乱码”。CPU 实验把 $u\in\{-1,K\}$ 标成必须拒绝，就是把这种错从采样故事里拿出来。

这三种糊和第 20 课 flow 积分方向反了导致的“纯噪声”不同。积分反了，分布走错方向。离散这边，分布仍在 simplex 上，错的是可见性或编号范围。诊断时先看 mask 和 id 范围，再看 CE 曲线。

### 5.12 一张 $2\times 2$ 图从量化走到预测

把前面的公式串成一条可手算的样本。图有四个格子，码本 $K=8$，编号 $u=(0,7,3,4)$。文本词表 $32$，统一 id 为 $(32,39,35,36)$。提示两个 token，id 为 $(4,11)$，对应教学里的“画”“L”。

理解样本的序列是 $[32,39,35,36,4,11]$，但计损失的只有最后两个位置，而且第二个提示其实应换成答案文本；这里为了和 CPU 实验同一套数字，仍用 $(4,11)$ 当文本。注意力用 5.4 节那张全 $1$ 图像块。query 落在下标 $1$（编号 $39$）时，它看见 $32,39,35,36$，看不见后面的 $4,11$。问句若是“右下是哪一个编号”，答案位置必须能看见下标 $3$ 上的 $36$，否则信息论上不可达。

生成样本的序列是 $[4,11,32,39,35,36]$。计损失的是后四个位置。query 落在下标 $3$（图像光栅 $1$，编号 $39$）时，允许看见的 key 是 $4,11,32,39$，不许看见 $35,36$。若训练框架把整段图像一次性放进 key 且不改 mask，下标 $3$ 会读到 $36$，也就是右下角真值。推理时右下角还不存在，于是你看到“验证 CE 很低、出图却在右下乱”。把这条样本的 mask 打印成 $6\times 6$，与 5.5 节的表逐格对。差一格就停。

MTP 样本在生成布局上把图像序 $\{1,3\}$ 换成 mask 符。序列变成 $[4,11,32,\mathrm{MASK},35,\mathrm{MASK}]$。loss 只在绝对下标 $3$ 和 $5$。那两个位置的目标仍是 $39$ 和 $36$。可见条件是提示加上未被遮的 $32$ 和 $35$，不是被遮位置上的原编号。若实现把目标写回输入再做全注意力，MTP 退化为复制，inpainting 会在不该动的区域跟着抖。

这条样本的容量预算 $C=K\cdot M=8\times 4=32$。它不表示序列长度 $6$，也不表示参数量。把它和 Show-o 的 $8192\times 256$ 放在同一列，只为了提醒：缩小实验缩小的是 $K$ 和 $M$，不是换了一种目标。目标始终是共享 softmax 上的 CE，加上一张不许偷看未决定像素真值的表。

## 6. 在公开实现中定位这些机制

本课没有 MiniMind 源码可改。读公开实现时按下面的字段搜，搜不到就在笔记里写“其发布未公开该细节”，不要用想象补。

**Show-o**（[showlab/Show-o](https://github.com/showlab/Show-o)）：搜 `MMU`、`T2I`、`MASK`、omni attention、`8192`。核对默认前向是否走离散 MAGVIT-v2，以及理解消融是不是另接了 CLIP（对应论文的 $\ddagger$）。训练步数对照附录 F：在 RefinedWeb、ImageNet-1K 与图文对上先 $500$K step 做语言、类条件生成和 caption；再用约 $35$M 图文对做 $1{,}000$K step 的文生图；48 张 A100 80GB、全局 batch $1152$、AdamW、weight decay $0.01$、warmup $5{,}000$、学习率 $1\times 10^{-4}$ 余弦。随后在 $2.0$B 对上再 $500$K，分辨率提到 $512$ 再 $500$K，最后约 $1$M 内部高质量对和 LLaVA 指令数据微调。

**Emu3**（[baaivision/Emu3](https://github.com/baaivision/Emu3)）：搜 `SOV`、`SOT`、`EOV`、`EOL`、`EOF`、`32768`、vision loss 权重。`processing_emu3.py` 把图像处理器、VQ 和文本 tokenizer 包在一起。生成与对话是两套后训练权重，不要把 `Emu3-Chat` 的 VQA 数字写到 `Emu3-Gen` 的 FID 下面。

**Chameleon**：以 arXiv:2405.09818 第 2–3 节为准。搜 QK-Norm、z-loss、$1024$ token、$65536$ 词表。交错推理若使用社区实现，核对图像段是否固定 $1024$、是否逐步把 id 拷回控制流。安全与拒答数据在论文第 3.1 节，本课不把它当成视觉机制。

读权重时另做一次 round-trip：同一张 $256\times 256$ 或 $512\times 512$ 的图，encode 得到的 id 必须在 $[0,K-1]$，decode 后再 encode，允许小幅抖动，不允许出现负号或 $\ge K$。这一步失败，后面所有 mask 实验作废。

## 7. 数据与训练 recipe

离散统一的数据不是“把 caption 数据集倒进 AR”。要按计损失的位置分桶，否则图像编号会淹没文本，或理解数据把生成 mask 练废。

**桶 A：纯文本。** 维持语言建模。Show-o 用 RefinedWeb；Emu3 用与 Aquila 相同的中英高质量语料；Chameleon 用 Llama-2 / CodeLlama 那一批，约 $2.9$T。损失只在文本。

**桶 B：图文对，图像在前。** 用来 caption 和理解。Chameleon 对图文对做 $50\%$ 旋转，一半图像在文本前。Emu3 把一部分 caption 挪到视觉段之后。损失在文本，图像作为可见前缀。

**桶 C：图文对，文本在前。** 用来文生图。损失在图像 token。Show-o 在阶段 ii 用约 $35$M 对做 T2I，阶段 iii 再用约 $1$M 高质量对。Emu3 质量微调只监督视觉 token。

**桶 D：交错文档。** Chameleon 的 $400$B 交错 token 是任意图文顺序。Show-o 用 GenHowTo 做关键帧与说明文字交错，单帧内部仍是扩散式，跨帧是时间上的自回归。损失位置随当前要预测的模态变。

**桶 E：视频。** Emu3 第二阶段才进；Show-o 把 MAGVIT-v2 胀成视频量化后再微调。不要在第一阶段短上下文里切视频，Emu3 的 $5120$ 包不住 $4096$ 视觉加文本加特殊符的余量。

教学规模（不是论文规模）建议：

| 桶 | 内容 | mask | 计损失 | 占比起点 |
|---|---|---|---|---|
| A | 短句 | 因果 | 文本 | $0.2$ |
| B | $4\times 4$ 图 + 问句 | 理解 | 文本 | $0.4$ |
| C | 短提示 + $4\times 4$ 图 | 生成 | 图像 | $0.4$ |

禁止用这张表去改写 Chameleon 的 $9.2$T 或 Show-o 的 $2.0$B。$\alpha$ 采样和第 15 课一样：按 token 数会让图像格淹没问句。

每条样本的最小合法字段：

| 字段 | 理解样本 | 生成样本 |
|---|---|---|
| 图像路径与 $(H,W)$ | 必填 | 必填 |
| 量化后的 $M$ 个 id | 必填，范围 $[0,K-1]$ | 同左 |
| 文本 token | 问题 + 答案 | 提示 |
| 序列布局 | 图像在前 | 文本在前 |
| 注意力表 id | `understand` | `generate` |
| loss 下标 | 答案文本 | 图像 id |
| tokenizer 哈希 | 必填 | 必填 |

缺哈希就不能对比两次 encode。缺 `attention表 id` 就会在同一 batch 里把两张 mask 混用。Show-o 用 task token 承担这个字段；你的缩小实验若没有 task token，就要在数据列里显式存。

batch 构造写成显式循环，避免“默认因果”把理解样本污染。设一个 batch 里理解样本集合为 $\mathcal{B}_{\mathrm{u}}$、生成样本为 $\mathcal{B}_{\mathrm{g}}$，共享参数 $\theta$ 的更新是两条 CE 之和：

$$
\theta \leftarrow \theta-\eta\nabla_\theta\Bigl(
\frac{1}{|\mathcal{B}_{\mathrm{u}}|}\sum_{\mathcal{B}_{\mathrm{u}}}\mathcal{L}_{\text{CE}}^{\text{text}}
+
\frac{1}{|\mathcal{B}_{\mathrm{g}}|}\sum_{\mathcal{B}_{\mathrm{g}}}\mathcal{L}_{\text{CE}}^{\text{image}}
\Bigr)
$$

每一条样本必须携带自己的 $A$。不能先把整个 batch 拼成一张大矩阵再套同一个下三角。混合精度下，错误的全 $1$ mask 不会立刻 NaN，只会让生成 CE 假性下降。日志里除了总 loss，还要打两行：理解样本的图像未来格可见数（目标 $M-q-1$ 的均值）和生成样本的图像未来格可见数（目标 $0$）。这两行比 loss 更能发现接错表。

Chameleon 第一阶段的 token 配比可以当对照，不能当缩小实验的采样权重。$2.9$T 文本、$1.5$T 图文、$400$B 交错，图像已经很多。Emu3 用 $0.5$ 的视觉损失权重，是因为即便条数相当，一张图的 $M$ 也会远大于一句 caption 的 $N$。缩小实验里 $M=16$、$N=6$，图像项仍可能压过文本。先按 token 数再按样本数各打一列占比，选让文本 CE 仍能下降的那一档。文本 CE 若连续多个 epoch 不降，先减图像项权重，不要先加层。

分辨率课程和第 08 课交接。Show-o 从表 4 把边长从 $256$ 提到 $512$，离散理解跟着涨，因为 $M$ 变大、能表示的空间关系变细。你的 $4\times 4$ 夹具没有资格说“已经验证了 $512$”。它只验证 mask 规则对 $M$ 是否同构：把 $M$ 改成 $4$ 或 $16$，理解仍应看见全部 $M$ 格，生成未来格仍应是 $0$。同构失败，放大分辨率只会把泄漏放大。

过滤函数至少返回原因码：`code_out_of_range`、`wrong_spatial_length`、`mask_layout_mismatch`。只返回布尔，你无法知道是码本越界多还是 $M$ 算错多。Chameleon 对含大量文字的图重建差，过滤时可以把 OCR 密度高的样本从生成桶挪走，不要假装模型能画小字。

Show-o 用 ShareGPT4V 对大规模图文重写 caption；Emu3 用 Emu2 微调出的 captioner 和 GPT-4V 标的约 $100$ 万对。合成 caption 会抬短提示评测上的改写收益，所以 Emu3 在 GenEval / T2I-CompBench 上报 $\dagger$。你自己的缩小数据若也是合成长描述，评测必须另备一列短提示，否则会把“会写长 caption”写成“会听短指令”。

### Step 2: 浏览器双板教具

打开本课页面的 Lab。左板是同一张 $4\times 4$ 的 L 形离散图，右板是当前路径的可见性。先在四个选项里选一句关于未来格的预测，再按“揭晓 mask”。揭晓后必须切换理解 / 生成各看一次：理解的可见格应是 $16/16$，且未来格计数等于 $16-\mathrm{query}-1$；生成的未来格计数应是 $0$。教具标题写明教学模拟。改 query 或改预测会清掉揭晓，防止先看数字再选答案。

教具内部的规则可以手工复核。理解序列把 $16$ 个图像 token 放在文本前，图像 query $q$ 对任意图像 key 为真。生成序列把 $3$ 个提示放在图像前，图像 query 只对光栅编号 $\le q$ 的图像 key 为真。L 形格子用码本色块表示编号 $1$，背景为 $0$，只为了让“同一张图”可辨认，不参与 mask 计算。

建议操作顺序：query 停在 $5$，选预测，揭晓理解路径，数未来格是不是都写“看”；切到生成路径，确认那些格改写成“挡”；再把 query 拖到 $0$，生成路径应只看见 $1$ 格，理解路径仍是 $16$。中途把预测改成“两条路都能看未来格”，验收必须失败。

指标行在揭晓前显示破折号，揭晓后显示三个数：可见图像格、其中未来格、码本范围。验收用的是理解路径 $16/16$ 且未来格等于 $16-q-1$，以及生成路径未来格 $0$。你只看当前路径的一行不够：必须切过去把另一条也揭晓过，`seenUnderstand` 和 `seenGenerate` 才会同时为真。这是故意的。只揭晓理解、口头说“生成应该挡住”，不算完成。教具把这条写成 Gate 文案，数字仍然来自规则而不是网络。

右板揭晓前每个格子只显示问号，左板始终显示同一张 L 形。这是验收句里的“同一张图”：路径切换不得换图、不得换码本着色，只换可见性。L 形占用光栅 $0,4,8,12,13,14,15$，背景为编号 $0$，色块为编号 $1$。编号范围写在指标行 `[0, 7]`，提醒你真实码本是 $K=8$ 的玩具切片，不是 MAGVIT 的 $8192$。query 不允许选最后一格，否则“未来格”集合为空，生成路径的 $0$ 计数会变成真空胜利。默认 query 为 $5$，未来格 $10$ 个，理解路径揭晓后这 $10$ 个必须显示“看”，生成路径必须显示“挡”。

若你自己改 Lab 坐标把 L 形挤到同一行，mask 规则不应跟着变。可见性只依赖光栅下标，不依赖颜色。有人根据“红色格子彼此可见”来猜答案，会在全背景图上失败。教具把颜色和 mask 分开，就是为了挡住这条捷径。

### Step 3: 可选，公开 tokenizer 的 round-trip

只在有 GPU 且你接受“这不是最低交付”时进行。用 Emu3 或 Show-o 的公开视觉 tokenizer，对一张自有照片 encode-decode，记录 id 最小值、最大值、$M$、重建是否可辨认。样本数小于 $25$ 时不要报成功率。若 id 出现负数或 $\ge K$，停止，不要进入生成采样。

### Step 4: 不要做的事

不要把 Lab 的“看 / 挡”写成 Chameleon 的人类胜率。不要在 CPU 实验通过后声称“any-to-any 已经验证”。不要把 Show-o‡ 的 CLIP 理解分写进默认离散模型的表。不要在本课积分 flow matching。

**本课最低测量。**

| 量 | 定义 | 通过 |

| $A^{\text{und}}$ 图像可见数 | 图像 query 看见的图像 key 个数 | 等于 $M$ |

## 10. 验收条件

课程通过只看机制，不看是否跑通 34B。

1. 课文第一个 H2 是“图像离散 token 和文本怎样共用一套 next-token”，并能用统一词表加两张 mask 解释。
2. CPU 实验八条 `checks` 全为 True。
3. 交互实验：先提交预测“理解看全图，生成不能看未来格”，再分别揭晓两条路径，理解可见 $16/16$、生成未来格 $0$。
4. 能指出 Show-o 的 MTP 与 Chameleon 因果 AR 在图像注意力上的差别，并且不把 MTP 写成偷看真值。
5. 能指出至少一处 tokenizer 上限：例如 Chameleon 对重文字图像的重建弱点，或 Emu3 表 2 的 LPIPS。
6. 引用 POPE / FID / GenEval 时写了模型名、是否离散、是否改写提示、表号。

出现以下任一情况，实验无效：揭晓前能看到“看 / 挡”；只跑理解路径却声称生成也过了；把 Show-o‡ 写成默认 Show-o；在本课推导 flow matching 速度场。

通过最低交付之后，还建议写一段“我改错了什么”的负对照记录。至少做改造清单里的第 1 条：把生成 mask 换成理解 mask，看到未来格计数从 $0$ 变成正数，再改回来。没有负对照，八条 `True` 也可能来自你把两张表写成了同一张全 $1$、却只断言了理解侧。负对照失败而主实验通过，主实验作废。这条纪律和第 01 课的 golden case 同类：先证明探针能响，再相信探针没响。

通过最低交付之后，允许加一条可选记录：query 取 $0$、$5$、$14$ 三档，列出生成路径可见格数，应分别是 $1$、$6$、$15$，理解路径始终 $16$。这条曲线给自己看，不写进对外的“论文复现”。

## 11. 根据症状定位失败环节

| 症状 | 先查 | 不是 |
|---|---|---|
| 理解答对全局题、答错左右 | 图像段是否双向；query 能否看见未来格 | 词表太小 |
| 训练 CE 很低、推理图像崩溃 | 生成 mask 是否看见未来真值；有没有全局 `is_causal=False` 却仍喂完整图 | 采样温度 |
| id 出现 $8192$ 或负数 | 偏移、clip、特殊符是否抢码本切片 | 学习率 |
| 图糊但 encode-decode 已经糊 | tokenizer 上限 | Transformer 层数 |
| 只有几种纹理 | 码本利用率 | mask |
| 文本能力突然掉 | 图像 CE 是否未降权、Emu3 那种 $0.5$ 有没有加 | QK-Norm |
| 34B 后期 NaN | QK-Norm、z-loss、norm 位置；Chameleon 图 8 / 图 12 | 单纯减学习率 |
| VQA 数字和论文对不上 | 是不是用了 CLIP 连续输入的 $\ddagger$ 变体 | 随机种子 |
| GenEval 很高、短提示很差 | 训练 caption 是否合成长描述，评测有没有改写 | FID |
| inpainting 改不动指定区域 | MTP 的 mask 有没有盖对那些空间下标 | 理解 mask |

两条快速裁定。未来格可见数大于 $0$ 且当前是生成路径：先修 mask，再谈模型。`min(ids)<0` 或 `max(ids)>=K`：先修 tokenizer 接口，再谈统一。

再补四条训练日志能抓到的病。图像 CE 远低于文本 CE、文本 CE 不降：图像项权重过大或 $M\gg N$ 且没有打折，先抄 Emu3 的 $0.5$ 再谈别的。图像 CE 和文本 CE 一起降、生成推理却像噪声：查生成 mask 的未来格计数，几乎一定大于 $0$。利用率集中在不到 $10\%$ 的码字：查量化器承诺损失和 codebook 重置，不要把 Transformer 学习率再加一档。QK 的输入范数在日志里单调爬升、loss 仍平稳：对照 Chameleon 图 8，平稳段可能只是 bf16 还没溢出，把 QK-Norm 和 z-loss 打开后再继续，不要等到 NaN 才回滚。

交错生成出了“该出图却一直出字”或相反，先查 SFT 配比，再查特殊符是否被学成无条件开关。Chameleon 写过模态失衡会学到无条件先验。缩小实验里把桶 B 和桶 C 的条数差一个数量级，就会复现同一症状。修法是调采样，不是加一个外挂分类器决定“现在该出图”。外挂分类器能把演示救活，但不再是共享 softmax 的统一模型。

评测数字对不上论文时，按下面的顺序问，不要直接改温度。第一，是不是 $\ddagger$ 或 $\dagger$ 变体。第二，是不是吃过该基准的训练图。第三，FID 用的是 $30$K 还是 $5$K，prompt 是否经过改写。第四，理解基准的解码是 open-ended 还是选项打分。Show-o 表 1 和 Emu3 表 6 的 VQAv2 都带自己的设定，相减没有意义。本课最低交付根本不报这些数，只报 mask 和范围；有余力再开第四张表，并且每格写来源。

## 13. 前沿对照与改造方向

**公开方案。** 同一问题，2024 年的离散统一分成三份公开实现。Chameleon 证明 early-fusion 全离散可以同时做文本、看图和交错生成，并给出 QK-Norm、z-loss、norm 重排这套稳定配方。Emu3 把扩散和 CLIP 塔都拿掉，只留 next-token，把视频也写成编号，并演示 AR 视觉 token 上的 DPO。Show-o 在 1.3B 上把文本 AR 和图像 MTP 塞进同一个 Transformer，用 omni-attention 让理解看全图、让生成不必走 $1024$ 步光栅。第 20 课的 Show-o2 / BAGEL / Janus 走连续或分流，不进本课主表。Qwen2.5-Omni / Qwen3-Omni 的公开技术报告以感知和语音为主，未把“图像离散 token 与文本共享 softmax”写成与 Emu3 同级的预训练目标。其技术报告未公开该细节。Moshi 是语音多码本，和本课图像码本同构的是“整数进出”，不是 next-token 统一图文。

规模能堆的部分要说具体。Show-o 从表 4 的 $35$M/$256$ 到 $2.0$B/$512$，POPE 加 $6.2$、VQAv2 加 $10.1$，这是数据与分辨率。Chameleon 看到 $9.2$T token，这是钱。Emu3 第二阶段上下文 $131072$，这是工程。缩小实验没有资格模仿这些数字，但可以模仿纪律：写入训练集之前必须检查 $u\in[0,K-1]$ 和 mask 布局，哪怕只有 $16$ 个格子。

离散嵌入从零学，和 CLIP 连续特征不是同一件预热。Show-o 写得很直：默认路线只有量化器给出的整数，必须在预训练里把图像嵌入和文本嵌入拉到能一起算注意力的位置；CLIP 特征已经在大规模图文上对过一次。表 4 的三行就是这笔预热账单。缩小实验若随机初始化 $K=8$ 的嵌入、只跑几十步 CE，不要指望 L 形能被文本问句指认。夹具验证的是 mask 和范围，不是离散 VQA。谁把 Lab 里“看全图”写成“已经学会指认 L 形”，把机制和能力又混了。

连续对照只在这里点一句：第 20 课的 VAE latent 没有 $K$ 类，谈不上越界；它的失败模式是积分方向和速度目标不一致。本课的失败模式是可见性和编号范围。两套日志字段不要共用一个 `loss` 列名。若你同时实现离散头和 flow 头，给它们分开的 tensor 名，像第 20 课要求的那样做 trace。本课交付不包含 flow 头。

**差距。** 规模差距：十亿级图文对、$8$B–$34$B 参数、十万亿 token，钱能堆。机制差距：统一词表偏移、两张 mask、共享 CE、MTP 的 loss 位置、QK-Norm 压哪一处 softmax，本课能做。评测差距：GenEval $0.68$ 和真实用户提示之间的洞，不是 $4\times 4$ 教具能填的；交错长文的人类评测更不是 CPU 实验的范围。

**改造实验。**

1. 把 CPU 实验的生成 mask 改成理解 mask，其余不变。预算：改十几行 Python，数秒。预期：`generate_future_visible` 不再为空，对应 check 必须失败。失败：改完未来格仍为 $0$，说明你改的不是那张表。
2. 把 $K$ 从 $8$ 改成 $4$，原编号 $7$ 应变越界。预算：CPU 一分钟。预期：`encode_image_token(7)` 抛错；若有人 clip 到 $3$，重建目标已经不是原来的码字。失败：越界后 CE 仍下降且没有错误。
3. 在 Lab 里把理解序列也改成纯因果（图像 query 看不见未来格）。预算：改教具规则，不训练。预期：query=$5$ 时理解未来格不再是 $10$，空间题“右下”的可见性下降。失败：改完界面仍显示 $16/16$。
4. 若有 $1\times 24$GB：跑 Show-o 官方采样，比较 $5$ 步与 $50$ 步的同一提示（附录写 $5$ 步大致相关、$25$ 步更贴提示、$50$ 步更细）。预算：单卡推理若干小时，不微调。预期：步数增加时提示符合度方向上升。失败：两种步数输出在像素上无差别且都不随提示变。样本不够 $25$ 只发逐例图，不报 FID。

**顺手复现映射。** Show-o“理解看全图、生成用 mask 迭代”对应 Lab 的两条路径：方向可复现，绝对值不能。Chameleon“softmax 范数增长预示发散”在教学规模只能做成“共享词表时把图像 id 和文本 id 的 logit 方差分开记”，看不到 34B 的 NaN。Emu3“视觉损失权重 $0.5$”对应：把玩具 CE 里图像项乘 $0.5$ 后，文本项梯度占比上升。谁把 $0.68$ GenEval 写进 $4\times 4$ 报告，就算评测造假。

改造实验的失败判定再补两条公共规则。任何一次 GPU 推理都要保存：权重哈希、tokenizer 哈希、$M$、$K$、mask 种类、以及生成步数。缺哈希的结果不能进对照表。任何一次声称“MTP 更快”的比较，必须在同一分辨率、同一 $M$ 上数步数；把 $256$ token 的 MTP 和 $1024$ token 的 AR 比步数，要像 Show-o 附录那样写明下采样率。

第 20 课讨论连续 latent 上的速度场。本课停在离散编号、两张 mask 和共享 softmax。下一课才处理一段回复里字、图、声音的输出日程，以及 Transfusion / Janus 那些连续加 AR 的阶段图。现在就把“统一”理解成“任意模态任意顺序已经解决”，会在日程课里和 KV 可见性对不上账。读完应能独立复述：共享的是词表和 CE；分开的是理解看全图、生成挡住未来像素；检验的是 mask 表和 $[0,K-1]$。能复述这三句，并且 CPU 实验八条为真，本课就收工。交互实验还要留下一次先预测后揭晓的记录。三项齐了，再去碰公开权重也不迟。公开权重只能检验同一套接口在真实量化器上是否仍越界，不能回头否定玩具里已经核对过的那两张表。

最后用一段自检堵住“我看过论文就算会了”。拿开着的 Show-o 图 5，用手指出理解序列里图像块为什么是满的、文本块为什么是下三角。再指出生成序列里图像块为什么也是满的——那是 MTP 的全注意力，不是 AR 的未来真值。两张“满”的颜色相同，含义不同：理解的满是原图编号互看；生成的满是 mask 与未遮格互看。分不清这两种满，Lab 里把生成路径也涂成 $16/16$ 就会显得很有道理，其实已经把本课的验收句推翻。把这句话抄在实验记录第一页：满注意力不等于可以看未来真值。AR 生成的空未来格，和 MTP 生成的 mask 格，才是“未决定像素”的两种合法写法。

若还想多做一页对照，把本课 $2\times 2$ 表和 Show-o 图 5 的三格并排抄：理解、文生图、纯文本。纯文本那一格退化为普通下三角，用来确认你的实现在没有图像时不会凭空打开全注意力。文生图那一格在 Show-o 里图像块是满的，在 Chameleon 里图像块是下三角。抄错这一格，三条路线就会被你合成一条。抄完之后合上论文，只看自己的 $6\times 6$ 数字，能讲出每一格为什么是 $0$ 或 $1$，本课的机制部分才算真正读过。数字讲不清，回去 5.4 和 5.5，不要跳到评测表。机制课的终点是一张可复核的表，不是一句“离散路线已经赢了”。表对了，再决定要不要花钱堆 $K$ 和 $M$。表不对，堆完仍会泄漏。CPU 实验、浏览器揭晓、论文表号，三件事分开写进同一份笔记的三栏，栏与栏之间禁止互抄数字。做到这一步，第 41 课可以关掉。下一课打开时，带上这两张 mask：日程课要问的是字、图、声谁先写进 KV，不再重问码本范围。范围已经在本课锁死。若有人下一课还在问 $u$ 能不能等于 $K$，把本课 CPU 实验的越界断言再跑一遍，不要在日程图里重写量化器。量化器负责把图变成合法编号，日程负责这些编号何时进入 KV，两件事接在同一条管道上，但验收标准不同。编号合法是本课的门；进出顺序是下一课的门。两门都过了，才谈得上交错生成。
