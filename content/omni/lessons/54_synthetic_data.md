# 第 54 课：用合成数据补分布而不是只加条数

> 内容：合成操作轨迹的分布账、物体中心变换、有效样本量与域混合<br>
> 建议周期：阅读约 70 分钟；CPU 实验数分钟<br>
> 硬件：无 GPU 可读完全文并跑 CPU 机制实验；复现 MimicGen / RoboCasa 论文规模需要仿真集群与遥操作工位<br>
> 产物：四域合成账本、唯一哈希与 $n_{\mathrm{eff}}$ 夹具、相对位姿变换核对、文献数字表

## 1. 合成轨迹补的是数量还是分布

第 26 课处理的是已经存在的真实异构数据：Open X-Embodiment 把几十种机体拼进同一个仓库，按条数采样时厨房会占满 batch，见[第 26 课](26_robot_data_mixture.md)。第 34 课处理的是世界模型当数据引擎：Cosmos 生成物理视频给别人训，评价看保真和物理违规，见[第 34 课](34_world_model_platform.md)。本课换一块更窄、也更容易被报告美化的材料：操作轨迹生成器。MimicGen 把少量人类演示切成物体中心片段，变换到新复位，执行成功后写进训练集。RoboCasa 把同一套生成器接到一百个厨房任务上，并报告合成数据规模化之后原子任务成功率上升。两边的论文标题都在说“大规模”。本课要问的是：这些新轨迹补的是长尾分布，还是把已经最多的技能再复制一遍。

要改的模块不是政策网络，是合成器写进哪一个域、每条轨迹有没有新的复位箱、混合物仍按什么 $n_d$ 计数。改对了的判据有三条，都可以在缩小版里用手算或浏览器教具复核：合成只加到最大域时，α=1 的有效域数下降；同样条数补最小域时，小域频率回升；把新轨迹写成已有哈希的重复时，有效样本量不得上升。它们不证明真机抓取成功率。

具体到本课夹具。四域真实条数定为厨房抓放 8000、抽屉开合 800、杯插入位 200、双臂摆盘 50，总和 9050。按条数抽样，厨房占 $8000/9050\approx 88.4\%$，双臂占 $0.553\%$。batch 大小 256 时，厨房期望 226.3 条，双臂期望 1.4 条。有的 step 里双臂是 0 条。这时若再调用一次生成器，把 2000 条新轨迹全部写进厨房，$N$ 变成 11050，厨房份额升到 $10000/11050\approx 90.5\%$，有效域数从 1.27 掉到 1.21。磁盘上多了 2000 条，batch 里能看见的域更少。若把同一笔 2000 条写进双臂，双臂份额升到 $2050/11050\approx 18.6\%$，有效域数升到 1.77。两条合成预算相同，混合物方向相反。报告若只写“我们额外生成了 2000 条”，检查者无法判断走的是哪一条。

MimicGen 的论文摘要给出的规模是：用约 200 条人类演示，生成超过 5 万条新演示，覆盖 18 个任务、两个仿真器和一台真实机械臂。每个任务默认在 $D_0$ 上采 10 条源演示（移动厨房 25 条，Square 复用 robomimic 的 10 条），再为每个任务变体生成 1000 条成功演示。RoboCasa 把这套流程接到厨房：25 个原子任务各 50 条人类演示共 1250 条；对其中 24 个任务（排除导航，因为当时 MimicGen 不能生成移动操作）各生成 3000 条，共 7.2 万；另外发布 2.8 万条含 AI 生成物体的轨迹，合计超过 10 万。这些数字回答“生成了多少”。本课回答“生成进了哪一个桶、桶里是不是同一条源轨迹的拷贝”。

把“长尾”拆成四条轴，后面每一节都对得上其中一条。第一条是复位：杯子在桌面上的位置、三脚架是否固定、抽屉开到哪一格。MimicGen 的 $D_0$、$D_1$、$D_2$ 就是这条轴。第二条是物体实例：同一类杯子换一只，十二只杯子一起出现。Mug Cleanup 的 $O_1$、$O_2$ 是这条轴。第三条是技能类型：抓放很多、插入很少、双臂更少。RoboCasa 原子任务里门容易、抓放难，复合任务接近零，是这条轴。第四条是机体：Panda 源演示生成到 UR5e。跨手臂表是这条轴。合成器可以只在第一条轴上把 $D_0$ 铺成 $D_1$，同时在第三、第四条轴上原地踏步。报告若只写“覆盖了更多初始状态”，检查者还要问另外三轴。

用一次具体生成把四条轴钉在时间线上。$t=0$，仿真把一只未见过的杯子抽到桌面右侧，这是复位轴和物体轴同时动了。$t=1$，生成器从 10 条源里抽出第 7 条的“靠近杯口”片段，按新杯子位姿变换。$t=2$，末端从当前姿态线性插值到新片段起点。$t=3$ 到 $t=3+K$，跟踪变换后的目标，夹爪开合同源片段。$t=4$，成功谓词看杯子是否离开桌面。成功则写入厨房域，失败则丢弃。若第 7 条源已经贡献了 170 条成功，这一次无论杯子在左还是在右，动作风格仍是第 7 条。复位轴上 $U$ 增加了 1，技能轴和源轴没有增加。Lab 的“新复位 / 重复”开关就是在 $t=4$ 之后决定记一个新哈希还是复用旧哈希。CPU 实验没有界面，所以它把进厨房、进双臂、重复三条账同时算完。

合成轨迹（synthetic trajectory：由程序根据已有人类演示或规划器写出来的状态-动作序列，不是操作员当时在现场遥操作的那一条）和数据增强（data augmentation：对已有样本做外观或几何扰动，通常不重新在物理里执行）要分开记账。MimicGen 要在新场景里真正执行变换后的末端目标，成功才入库，失败丢弃。给图像加噪声、随机裁切、改纹理，属于视觉增强，不经过成功谓词，也不产生新的末端目标。复制一条 hdf5 再改文件名，连执行这一步都没有，本课把它记成重复哈希，不允许记成新的有效样本。三种东西都能让 `len(dataset)` 变大，只有第一种有机会改复位轴；第一种若总是写进最大域，技能轴仍然不动。

本课术语：

| 术语 | 简要解释 |
|---|---|
| 源演示 / source demo | 人类遥操作留下的少量轨迹，MimicGen 默认每任务约 10 条 |
| 物体中心片段 | 相对单个物体坐标系写出的末端目标序列 |
| 复位分布 $D_0,D_1,D_2$ | 物体初始位姿的采样范围；下标越大，工作空间越宽 |
| 相对位姿变换 | 保持 $T^{C}_{O}$ 不变，按新物体位姿写出新的世界系目标 |
| 生成成功率 | 成功入库次数除以尝试次数，不是政策成功率 |
| 唯一哈希 | `(源演示 ID, 复位箱)`，用来判断两条轨迹是不是同一条的拷贝 |
| 有效样本量 $n_{\mathrm{eff}}$ | $(\sum n_i)^2/\sum n_i^2$，重复会把它压低 |
| 有效域数 $D_{\mathrm{eff}}$ | $1/\sum p_d^2$，与第 26 课同一条定义 |
| 原子任务 | RoboCasa 里只考一项基础技能的任务，共 25 个 |
| 复合任务 | 多项技能串起来的厨房活动，共 75 个 |

第 26 课的 α 和 cap 在本课原样沿用。本课新增的是：合成器输出要先过唯一哈希，再进入 $n_d$。第 34 课的数据引擎生成视频；本课生成器输出的是可执行的末端增量。两种产品都能把“条数”做大，门禁不同。视频看物体 ID 是否消失，轨迹看复位箱是否真的变了。

## 2. 本课解决的问题

把合成操作数据写进训练集，要同时处理三件会互相拆台的事。第一件是几何合同：片段是相对哪个物体写的，变换公式写反会直接错过物体。第二件是入库合同：生成成功率、政策成功率、复位覆盖率是三列数字。第三件是混合物合同：合成进了最大域还是最小域，重复哈希有没有被当成新样本。

本课结束时你要能交出一份缩小版合成账本，而不是一个在 LIBERO 上报过成功率的权重。账本必须写明：每个域的真实 $n_d$、合成 $s_d$、合成后 $p_d$、α、唯一哈希数、$n_{\mathrm{eff}}$，以及变换夹具有没有用对公式。对照必须能被参数组合触发：合成只加到最大域时 α=1 更糟；补最小域时小域频率回升；重复轨迹的 $n_{\mathrm{eff}}$ 不升。

本课可以独立阅读。完成第 26 课能少走弯路，因为 $p_d\propto n_d^\alpha$ 和 $D_{\mathrm{eff}}$ 已经手算过。第 34 课能说明“生成看起来像”和“能当训练数据”不是同一张表。没有这两课也可以：把真实条数当成已经给定的四元计数，把合成当成往其中一个桶里加整数。不要在本课重做机体 ID 打乱或重力符号探针；那些是第 26 课和第 34 课的对象。也不要在本课实现自回归 VLA 的词表替换：那是[第 27 课](27_autoregressive_vla.md)。本课只保证一件事：送进后续训练的合成轨迹，其域归属和唯一性是可审计的。

第 24 课把动作接进视觉语言模型，见[第 24 课](24_vlm_to_vla.md)。合成轨迹若要进 VLA，动作表示必须和第 25 课选定的箱或连续头一致。MimicGen 写的是末端增量。你若在 OpenVLA 风格的 256 箱里消化这些增量，分位表要用合成后的混合物估计，不能只用厨房真实轨迹的 1% 与 99% 分位。否则双臂合成即便 $s_d$ 很大，动作值仍会被厨房分位剪掉。本课不重做分位，只在 recipe 里留一列 `action_stats_from`：`real_only` 或 `real_plus_synth`。选错的症状是：双臂份额已经 18%，动作 token 准确率仍像没见过插入。

第 25 课比较过离散箱和连续动作，见[第 25 课](25_action_tokenization.md)。MimicGen 的动作约定是末端增量加夹爪开合，和 OXE 的粗对齐同一家族。合成器若在关节空间回放一条末端演示，几何合同先坏。本课夹具用二维平移把合同写死，不进入 7 维分箱。第 31 课禁止把仿真成功率横着写成真机能力，见[第 31 课](31_vla_evaluation.md)；本课把这条纪律接到合成器：生成成功率 82.3% 不能写成政策 82.3%，更不能写成真机 82.3%。

和[第 15 课](15_joint_multimodal_sft.md)的边界：15 课的桶是模态 token，担心 codec 比文本长。本课的桶是操作技能域，担心 8000 条厨房对 50 条双臂。合成器多出来的时间步如果再按 token 计，厨房会更满。本课主账本按轨迹条数，必要时再拆到步。写 recipe 时声明当前单位：本课默认“域级轨迹计数，哈希按条”。

失败条件预先写死：

- 只报生成了多少条，不报加进了哪一域；
- 把生成成功率写成政策成功率或真机成功率；
- 把同一条源演示的拷贝计成新的有效样本；
- 把附录 M 最后一行写反的公式直接抄进控制器；
- 把 RoboCasa 原子任务从 28.8% 升到 47.6% 写成复合任务或真机已经解决；
- 把教学 Lab 的 $D_{\mathrm{eff}}$ 写成 MimicGen 表里的 Square 90.7%。

## 3. 开始前需要准备什么

主路径不安装 Isaac Gym，不采集遥操作，不训练 BC-RNN。需要的是纸、计算器或本课 CPU 实验，以及浏览器里的四域教具。若你有磁盘和兴趣，可以打开 [NVlabs/mimicgen](https://github.com/NVlabs/mimicgen) 或 [robocasa/robocasa](https://github.com/robocasa/robocasa) 看任务配置里的子任务列表，但不把“成功 import 一个环境”当成验收。

**上游事实（打开原文核对过）：**

- MimicGen（arXiv:2310.17596，Mandlekar、Nasiriany 等，CoRL 2023）。项目页 [mimicgen.github.io](https://mimicgen.github.io)。摘要：约 200 条人类演示生成 50K+ 新演示，18 个任务。仓库后来公开的数据集写明 12 个任务、超过 4.8 万条，与论文 18 任务不是同一快照。
- RoboCasa（arXiv:2406.02523，Nasiriany 等，RSS 2024）。项目页 [robocasa.ai](https://robocasa.ai)。100 个任务、120 个厨房场景、2509 个物体、100K+ 轨迹。
- SkillMimicGen / SkillGen（arXiv:2410.18907，Garrett、Mandlekar 等，2024-10-24）。用 60 条人类演示生成 24K+ 条，18 个任务变体；生成成功率均值 75.4%，对照 MimicGen 40.7%。
- 第 26 课已引的 OXE / Octo / OpenVLA 规模表，本课不重抄，只在接到混合物时引用 α 公式。

**本课约定（你定的，不要写进“论文说”）：**

- 四域玩具计数固定为厨房 8000、抽屉 800、杯插入 200、双臂 50。
- 默认合成预算 $S=2000$。
- 唯一哈希为 `(source_id, reset_bin)`，复位箱在教具里按整数编号，不模拟连续 $SE(3)$。
- 变换夹具用二维平移：源物体在原点，新物体在 $(1,2)$，源目标 $(0.2,0)$ 与 $(0.4,0)$。
- CPU 实验和互动实验必须用同一组计数，禁止各写各的 $n_d$。

独立执行时固定：

| 锁定项 | 固定值 |
|---|---|
| 域计数 | 8000 / 800 / 200 / 50 |
| 合成预算 | 2000 |
| batch 大小（教具） | 256 |
| α 网格 | 0、1 |
| 合成目标 | 最大域 / 最小域 |
| 合成写法 | 新复位哈希 / 重复已有哈希 |

软件上只需要 Python 3.10 标准库和能打开本课页面的浏览器。不要为了本课新装 Isaac Sim 或 robosuite。没有仿真器，仍必须把三本账和变换夹具做完。有仿真器，也不允许跳过哈希直接报成功率。CPU 实验不读网、不写文件、不用 NumPy，跑完只在内存里留下一个字典。不要为了“看起来更像生成器”去加随机采样；本课要的是可复核，不是抽卡。

论文规模的硬件只作为对照，不作为本课门槛。MimicGen 的源演示由一名操作员用遥操作采集；真实机械臂实验另采 Stack 与 Coffee 各 10 条，再生成 200 与 100 条成功演示。RoboCasa 的 1250 条人类演示由四名操作员用 3D SpaceMouse 采集。没有这些工位，仍必须把 $p_d$ 表、哈希账和变换夹具做完。有这些工位，也不允许跳过哈希直接报成功率。生成 1000 条成功演示的墙钟取决于 $\rho$：厨房抓放可能几分钟，毫米级装配可能要一个数量级以上的尝试。墙钟不是本课验收项，尝试次数和成功次数必须分开写进日志。

官方后续页 [robocasa.ai](https://robocasa.ai) 还写了 RoboCasa365：365 个日常任务、2500 个厨房、600+ 小时人类演示、1600+ 小时合成演示。那是 2026 年发布页上的另一快照，不是 2406.02523 正文里的 100 任务 / 10 万条。引用时写清“发布页”还是“RSS 2024 论文”。本课主数字停在打开过的 2310.17596 与 2406.02523。

## 4. 完成后应具备的能力

完成后，拿到任意一份“我们用 MimicGen 扩了十倍数据”的声明，你应能完成以下检查：

1. 问清源演示条数、生成尝试次数、成功入库条数，以及生成成功率与政策成功率是否分开写。
2. 写出 $p_d\propto n_d^\alpha$，并算出合成进最大域、进最小域之后的 $p_d$ 与 $D_{\mathrm{eff}}$。
3. 写出 $T^{C'_t}_{W}=T^{O'_0}_{W}(T^{O_0}_{W})^{-1}T^{C_t}_{W}$，并指出附录 M 最后一行把两个物体位姿写反。
4. 用 `(源 ID, 复位箱)` 统计唯一哈希，算出 $n_{\mathrm{eff}}$，拒绝把拷贝写成新样本。
5. 指出源演示选择可以极不均匀：Factory Gear Assembly $D_1$ 的 1000 条里超过 850 条来自 3 条源演示。
6. 对照 RoboCasa：原子任务 Human-50 总体 28.8%、Generated-3000 总体 47.6%；五件复合任务微调后最高 12%，有的仍是 0%。
7. 解释为何“200 条 MimicGen 与 200 条人类接近”不能推出“再生成 5000 条一定继续涨”。
8. 把合成目标域、哈希规则、α、变换公式版本写进可复查的 recipe。

自我检查可以用四道题，答不出就还没学完。第一，$n=(8000,800,200,50)$ 再加 2000 条到厨房，α=1 的最大域有没有比 88.4% 更高？第二，同样 2000 条加到双臂，最小域从多少升到多少？第三，把 2000 条写成一条厨房轨迹的拷贝，$n_{\mathrm{eff}}$ 升还是降？第四，MimicGen 真实 Stack 的 82.3% 和 36% 分别是哪一列？四题都对应 checks 或论文原句，不需要 GPU。

第五题可选：附录 M 最后一行把哪个矩阵写反了，正确式把 $(0.2,0)$ 变到哪里？答 $(1.2,2)$ 才算几何合同落地。第六题可选：RoboCasa 的 28.8% 和 47.6% 是 25 个原子、24 个原子，还是 75 个复合？答错就把复合任务的 0% 藏进了平均值。五、六两题仍然不需要 GPU，只需要打开过的原文和本课夹具。

读完第 4 节再用这段情景。桌上已经有 8000 条厨房抓放。生成器又吐出 2000 条。你应能立刻问：这 2000 条的复位箱是新的吗，写进了哪个域，成功判定用的是哪条谓词。若你只能说出“数据变多了”，还没有拆开用途。

再补一条更硬的自检。给你两份日志，一份 $N=11050$、$U=9050$、$D_{\mathrm{eff}}=1.21$，一份 $N=11050$、$U=11050$、$D_{\mathrm{eff}}=1.77$。你应能立刻说出：第一份在灌最大域或在复制；第二份在补最小域且哈希是新的。两份的 `len(dataset)` 相同。条数相同不是通行证。若你需要看视频才能判断哪一份补了长尾，说明 $D_{\mathrm{eff}}$ 和 $U$ 还没变成第一反应。把两份日志打印成四域计数表和哈希直方图，不看像素，只看这两张表做判定。判定应与看生成回放一致。不一致时，先查哈希有没有只用文件名，再查 $s_d$ 有没有写错键。

## 5. 原理：边造边讲

以下机制按同一节奏：为什么需要、怎么运转、精确定义、公开实现落点、怎么证明做对了。本课没有 MiniMind 源码，代码落点写在公开仓库与本课夹具里。

### 5.1 条数账和分布账

直觉。训练日志里的 `num_samples` 加了 2000，loss 曲线更平滑，看起来像“数据变多了”。优化器看见的是按 $p_d$ 抽到的 batch。若这 2000 条和原来 8000 条厨房来自同一套复位、同一条源演示，batch 的碰撞熵不会升，长尾技能仍然每两百步才出现一次。条数账记录 $N$，分布账记录 $p_d$ 和唯一哈希。两本账对不上，合成就是在给最大域注水。

机制。记真实域计数 $n_d$，合成域计数 $s_d$，合成后

$$
\tilde n_d=n_d+s_d,\qquad
\tilde N=\sum_d\tilde n_d.
$$

温度混合仍用第 26 课的公式，只是把 $n_d$ 换成 $\tilde n_d$：

$$
p_d=\frac{\tilde n_d^{\alpha}}{\sum_j\tilde n_j^{\alpha}}.
$$

α=1 时 $p_d=\tilde n_d/\tilde N$。合成进哪一域，直接改这一域的分子。有效域数

$$
D_{\mathrm{eff}}=\frac{1}{\sum_d p_d^{2}}.
$$

四域均匀时 $D_{\mathrm{eff}}=4$。一个域占 88%、其余瓜分 12% 时，$D_{\mathrm{eff}}$ 掉到约 1.27，几乎等于单域训练。往已经最大的域再加水，这个数只会更小。

本课四域 $n=(8000,800,200,50)$，$N=9050$。α=1、尚未合成：

| 域 | $n_d$ | $p_d$ | $B=256$ 的 $e_d$ |
|---|---:|---:|---:|
| 厨房抓放 | 8000 | 0.883978 | 226.30 |
| 抽屉开合 | 800 | 0.088398 | 22.63 |
| 杯插入位 | 200 | 0.022099 | 5.66 |
| 双臂摆盘 | 50 | 0.005525 | 1.41 |

$D_{\mathrm{eff}}\approx 1.266$。双臂在 256 的 batch 里期望 1.4 条，有的 step 是 0。

加 $S=2000$ 到厨房：$\tilde n=(10000,800,200,50)$，$\tilde N=11050$，$p_{\text{厨房}}=0.904977$，$D_{\mathrm{eff}}\approx 1.213$。最大域份额上升约 2.1 个百分点，有效域数下降约 0.053。加到双臂：$\tilde n=(8000,800,200,2050)$，$p_{\text{双臂}}=0.185520$，$D_{\mathrm{eff}}\approx 1.773$。最小域份额上升约 18 个百分点。两笔合成的磁盘成本相同，对 $D_{\mathrm{eff}}$ 的符号相反。

代码落点。公开生成脚本通常按任务写 hdf5，任务名就是域。本课 CPU 实验的 `add_synth` 只做字典加法，用来先把符号钉死。互动教具把目标域做成单选：默认选厨房，就是工业常见错误。

验证。CPU 实验断言：加到最大域后 $D_{\mathrm{eff}}$ 下降至少 0.04、最大份额上升至少 0.01；加到最小域后最小份额上升至少 0.15、$D_{\mathrm{eff}}$ 上升至少 0.4。这四条都在 `lesson_54.py` 的 checks 里。

α=0 会把合成的域效应洗掉：四个域各 0.25，$D_{\mathrm{eff}}=4$，无论 2000 条进厨房还是进双臂。那不是合成变好了，是你不再按条数采样。recipe 必须同时写 α 和 $s_d$。只写其中一个，另一本账可以随便改。

有人看见 90.5% 就说“把厨房概率 clip 到 40% 再归一化”。第 26 课已经算过：clip 后再归一化，大域会胀回去。合成之后更严重。厨房 0.905、其余三个合计 0.095，clip 到 0.40 再归一化，厨房仍约 $0.40/(0.40+0.095)\approx 0.808$。最小域几乎不回升。你若既往厨房灌合成、又想靠 clip 概率补救，两步都在和最小域作对。上限必须加在计数上：先 $\tilde n_d'=\min(\tilde n_d,C)$ 再算 $p_d$。本课主路径不打开 cap，是为了让合成目标域的符号单独可见。你若在自己的 loader 里同时开 cap，必须另算一张表，写清 2000 条里有多少在加权前被截掉。

一个 epoch 的定义也必须写死。若 epoch 指“每条真实轨迹见一次”，合成轨迹要么额外循环、要么挤掉真实轨迹。若 epoch 指“固定 $T$ 次两段抽样”，厨房合成会按 $p_d$ 反复出现，双臂真实 50 条会被读很多遍或几乎读不到，取决于 $s_d$ 进了哪。OpenVLA 写他们跑了 27 个 epoch，那是针对已经加权过的真实混合物。你照抄 27 但自己用 α=1 且把 2000 条合成全写进厨房，等于让厨房再读 27 遍，双臂仍然只是厨房的零头。报告里要写：epoch 的分母是加权后的期望计数，还是原始 $n_d$，以及合成有没有单独的循环次数。

### 5.2 MimicGen 的三段式：切、变、跟

直觉。人类演示昂贵。robomimic 里把可乐罐从一只箱子挪到另一只，场景单一、物体单一、机器人单一，仍要 200 条演示才到 73.3% 成功。RT-1 用约 1.5 年、多名操作员、多间厨房，才把若干厨房整理任务做到文中写的 97%。MimicGen 的观察是：这些数据集里大量片段是同一类相对运动，只是物体换了位置。把“抓住马克杯”这一段从杯的坐标系写出来，换一个杯子位姿再变回去，就能少采很多人类数据。

机制。系统先把源数据集 $\mathcal{D}_{\mathrm{src}}$ 解析成片段。假设任务由已知的物体中心子任务序列 $(S_1(o_{S_1}),\ldots,S_M(o_{S_M}))$ 组成，每个子任务相对单个物体的坐标系。每条源轨迹 $\tau$ 被切成 $(\tau_1,\ldots,\tau_M)$。切点用可自动检测的子任务结束度量，附录 K 写了实现细节。然后，对新场景：为每个子任务选一段源片段，按新物体位姿变换，用末端控制器跟踪这串目标位姿，全部跑完后检查任务是否成功。成功才写入 $\mathcal{D}$。尝试次数和成功次数的比叫做数据生成率。

论文列了三条假设。第一，动作空间是末端增量加夹爪开合，于是一条演示可以当成控制器目标位姿序列。第二，任务由已知的物体中心子任务序列组成，序列通常由人指定。第三，生成期间（不是政策部署期间）能在每个子任务开始时观察到相关物体位姿。三条少一条，变换没有参照系，或者无法知道该切在哪。

数学。生成一次演示的过程可以写成：

$$
s_0\sim D,\quad
\tau_i\sim \mathrm{Select}(\mathcal{D}_{\mathrm{src}},S_i),\quad
\tau_i'=\mathrm{Warp}(\tau_i,T^{O_0}_{W},T^{O'_0}_{W}),
$$

$$
\tau'=\mathrm{Interp}(T^{E_0}_{W}, \tau_1')\,\|\,\tau_1'\,\|\,\cdots\,\|\,\tau_M',
$$

成功谓词 $\mathbf{1}[\mathrm{Success}(\tau')]=1$ 时才把执行日志写入 $\mathcal{D}$。$D$ 可以是 $D_0$、$D_1$ 或 $D_2$。源演示几乎都在 $D_0$ 上采集：$D_0$ 里有的物体根本不动，例如 Square 的柱、Threading 的三脚架、Three Piece Assembly 的底座；生成和训练却覆盖这些物体在工作空间里大幅移动的 $D_1$、$D_2$。

任务覆盖要按族读，避免把 18 当成 18 个互不相关的成功故事。基本堆叠：Stack、Stack Three。接触丰富：Square、Threading、Coffee、Three Piece Assembly、Hammer Cleanup、Mug Cleanup。长程：Kitchen、Nut Assembly、Pick Place、Coffee Preparation。移动：Mobile Kitchen。Factory / Isaac Gym：Nut-and-Bolt、Gear Assembly、Frame Assembly。同一套切-变-跟，接触公差从厘米级堆方块到毫米级装配。Factory 上名义 $D_0$ 政策 82%–99%，源演示只有 9%–15%；更宽的 $D_1$、$D_2$ 仍有 37%–81%。Mobile Kitchen 图像从 2.0% 到 46.7%，低维从 2.7% 到 76.7%。这些行证明生成器不绑定某一个仿真后端，不证明所有长程厨房都已经被合成解决。RoboCasa 后来单独证明：原子厨房能涨，复合厨房仍接近零。

和“再采人类”的对照写在图 4 右侧。Square、Threading 等任务上，200 条 MimicGen（从 10 条人类来）与 200 条人类演示的图像政策接近。作者因此提问：在有限标注预算下，是否还应该继续在同一复位里采人类，还是该把人的时间花在新的工作空间区域。本课把这个问题翻译成哈希：同一 $D_0$ 里再采 190 条人类，复位箱可能几乎不增加；把人送到 $D_1$ 去采 10 条，再生成 1000 条，复位轴才会动。论文没有直接做这组对照，只做了“同等条数合成对人类”。你写报告时不要把“接近”升级成“处处可替代”。

代码落点。公开实现把子任务边界、物体坐标系和控制器接口写在任务配置里，轨迹拼装用 `WaypointTrajectory`。教学夹具不调用该仓库。你若本地跑生成，先核对任务配置里的子任务列表是否和论文附录 L 一致，再谈 1000 条。仓库发布集写的是 12 个任务、超过 4.8 万条，论文正文是 18 任务、50K+。读代码时先看你拉到的是哪一份清单。

验证。列出三行：源 10 条上的政策、生成 1000 条 $D_0$ 上的政策、生成 1000 条 $D_1$ 上的政策。MimicGen 图 4 给出图像政策、三粒种子、取训练过程中的最高成功。Square 从 11.3% 到 90.7%，Threading 从 19.3% 到 98.0%，Three Piece Assembly 从 1.3% 到 82.0%。这些是论文数字，必须带任务名和 $D_0$。Hammer Cleanup 上，先前 BUDS 用 100 条人类报到 68.6%；本课引用的 BC-RNN 在 10 条源上 59.3%，在 1000 条 $D_0$ 生成上 100.0%，在锤子和抽屉都大幅移动的 $D_1$ 上 62.7%。Kitchen 同样：BUDS 72.0%，10 条源 54.7%，生成 $D_0$ 100.0%，$D_1$ 76.0%。本课夹具不训练政策，只核对变换和混合物。把 100.0% 抄进标题而不写 $D_0$，验收失败。

### 5.3 相对位姿变换与插值段

直觉。杯子从桌子左侧移到右侧，抓住它的相对动作几乎一样：靠近杯口、对齐、闭合。世界坐标系里的绝对轨迹完全不同。把源片段当成世界坐标回放，夹爪会去抓空气。正确的做法是：源片段相对源物体写出，再按新物体变回世界系。

机制。记 $T^{A}_{B}$ 为坐标系 $A$ 相对 $B$ 的 $4\times 4$ 齐次变换。源片段是一串控制器目标 $\tau_i=(T^{C_0}_{W},\ldots,T^{C_K}_{W})$。源物体在片段开始时的位姿是 $T^{O_0}_{W}$，新场景对应物体是 $T^{O'_0}_{W}$。相对位姿保持要求

$$
T^{C_t}_{O_0}=T^{C'_t}_{O'_0}.
$$

因为 $T^{C}_{O}=(T^{O}_{W})^{-1}T^{C}_{W}$，代入后左乘 $T^{O'_0}_{W}$ 得到

$$
T^{C'_t}_{W}=T^{O'_0}_{W}\,(T^{O_0}_{W})^{-1}\,T^{C_t}_{W}.
$$

这就是几何上唯一能保持物体系坐标的式子。SkillGen 第 4.4 节把它写成 $T^{A'_t}_{W}\leftarrow T^{O'_i}_{W}\,T^{A_t}_{O_i}$，与上式相同。

MimicGen 附录 M 前两行写出了 $(T^{O'_0}_{W})^{-1}T^{C'_t}_{W}=(T^{O_0}_{W})^{-1}T^{C_t}_{W}$，这一步是对的。同一附录最后一行把结果写成 $T^{C'_t}_{W}=T^{O_0}_{W}(T^{O'_0}_{W})^{-1}T^{C_t}_{W}$，两个物体位姿对调了。正文 4.2 节沿用了写反的那一行。本课夹具用几何正确式。你若按写反的式子实现，目标会跑到物体的反方向。

新片段的第一个目标 $T^{C'_0}_{W}$ 可能离当前末端 $T^{E_0}_{W}$ 很远。MimicGen 在片段前插入线性插值，从当前末端走到新片段起点。真实机械臂上他们把插值步数加到 50（仿真里常用 5），为的是硬件安全；论文 6.4 节把真实政策偏弱部分归到这些中间步：中间运动和观察之间缺少对应，模仿变难。线性插值不保证无碰撞。SkillGen 后来说这一点是 MimicGen 生成质量的主要缺口，改用运动规划连接接触段。

数学。二维平移夹具把旋转去掉，只留位移，便于手算。源物体 $O=(0,0)$，新物体 $O'=(1,2)$，源目标 $C\in\{(0.2,0),(0.4,0)\}$。正确变换

$$
C'=C+(O'-O),
$$

得到 $(1.2,2)$ 与 $(1.4,2)$。相对位移仍是 $(0.2,0)$ 与 $(0.4,0)$。写反的式子变成 $C'=C+(O-O')$，得到 $(-0.8,-2)$ 与 $(-0.6,-2)$，末端会往桌子另一头走。插值 $5$ 步从 $(0,0)$ 到 $(1.2,2)$，第 $k$ 步为

$$
\Bigl(\frac{k}{4}\cdot 1.2,\;\frac{k}{4}\cdot 2\Bigr),\qquad k=0,1,2,3,4.
$$

手算一遍附录 M 的两行，避免以后看见 $T^{A}_{B}$ 下标就晕。相对位姿保持要求 $(T^{O'}_{W})^{-1}T^{C'}_{W}=(T^{O}_{W})^{-1}T^{C}_{W}$。左乘 $T^{O'}_{W}$，左边变成 $T^{C'}_{W}$，右边变成 $T^{O'}_{W}(T^{O}_{W})^{-1}T^{C}_{W}$。把 $O$ 与 $O'$ 对调，等于用旧物体去“解释”新世界里的目标，末端会朝旧杯子的反方向走。本课夹具把旋转拿掉，就是为了让这一步的符号错误变成两个看得见的点：$(1.2,2)$ 对 $(-0.8,-2)$。加上旋转之后，写反的式子不仅平移错，姿态也会绕错轴，夹爪可能杯口朝下。那时你在图像里看到的是“乱拧”，根因仍是这一行乘法顺序。

插值段是第二处会引入新分布的地方。源片段本身是人类的接触运动，插值段是程序画的直线。政策若用行为克隆去学整段 $\tau'$，它既要学人类接触，也要学直线接近。真实机械臂把直线加长到 50 步之后，接近段在时间上比接触段还长，观察和动作的对应变弱。这是分布被合成器改写的另一种方式：不是复位箱重复，是动作风格被插值污染。SkillGen 后来用规划器替换这段直线，生成率从 40.7% 升到 75.4%，部分原因就是少了撞和少了别扭接近。本课夹具只检查端点，不检查中间是否穿模。recipe 的 `quality_filter` 就是为中间段预留的。

代码落点。本课 `warp_targets(..., swapped=False)` 实现正确式，`swapped=True` 复现附录最后一行，用来证明写反会错过物体。不要在自己的控制器里保留 `swapped=True` 这条路径。

验证。CPU 实验断言：正确变换后物体系相对位移不变，并且数值等于 $(1.2,2)$、$(1.4,2)$；写反后等于 $(-0.8,-2)$ 与 $(-0.6,-2)$；插值路径第一点是当前末端、最后一点是新片段起点。缺任何一条，几何合同还没落地。

SE(3) 上的“线性插值”还有旋转那一项。正确做法是对平移做线性、对旋转做球面线性（slerp），或者对齐次矩阵做逐元线性后再正交化。MimicGen 写的是线性插值。本课夹具没有旋转，避免把正交化误差和公式写反混在一起。你在真实现里若看到夹爪在插值段翻面，先查旋转插值，再查 $T_O$ 有没有用对。

### 5.4 拒绝采样：生成成功率不是政策成功率

直觉。变换加跟踪不是精确重放。运动学到不了、接触滑了、插值撞了，任务就会失败。MimicGen 的对策是拒绝采样：失败的尝试丢掉，直到凑满目标成功条数。于是“生成了 1000 条”背后可能是 1200 次尝试，也可能是 12000 次。生成成功率低，只说明过滤器严或变换难，不说明留下来的那 1000 条不能训出高成功政策。

机制。记尝试次数 $N_{\mathrm{attempt}}$、成功入库 $N_{\mathrm{keep}}$，生成率

$$
\rho=\frac{N_{\mathrm{keep}}}{N_{\mathrm{attempt}}}.
$$

政策成功率 $\pi_{\mathrm{succ}}$ 是另一列：在评测复位上滚政策，成功次数除以评测次数。MimicGen 6.3 节明确写：生成率和政策成功率不必相关。附录 P 举了反例。

| 任务变体 | 生成率 | 图像政策成功 |
|---|---:|---:|
| Object Cleanup $D_0$ | 29.5% | 82.0% |
| Three Piece Assembly $D_0$ | 35.6% | 74.7% |
| Coffee $D_2$ | 27.7% | 76.7% |
| Factory Gear Assembly $D_1$ | 8.2% | 76.0% |

生成很慢的集合，训出来仍可以高。反过来，生成很容易的集合，若复位覆盖窄或源演示单一，政策也不一定强。真实机械臂把两列差距拉得更开。第 6.4 节：Stack 生成率 82.3%（243 次尝试），Coffee 52.1%（192 次尝试）；同一批生成数据上，50 次评测里 Stack 政策 36%、Coffee 14%（豆荚抓住 60%、插入 20%）。源演示上训出的政策在更宽的 $D_1$ 上是 0%。本课 CPU 夹具用 Stack 的 200/243 与 0.36，断言两列差超过 0.3，防止有人把它们当成同一个数。

Mug Cleanup 还展示了物体迁移：源集合只有一只杯子，生成到未见过的一只杯子（$O_1$）政策 90.7%，生成到 12 只杯子（$O_2$）75.3%。数字来自正文 6.1 节。引用时写清是物体变体，不是 $D_1$ 复位变体。

跨机体是另一张表。源演示采在 Panda 上，生成到 Sawyer、IIWA、UR5e。正文写 Square $D_0$ 的生成率因手臂而异，范围 38%–74%，图像政策却落在 80%–91%。附录 F.1 表格说明里写 $D_0$ 生成率范围 20%–74%。两处范围不完全相同，引用时写“正文 6.1 节 38%–74%”或“附录 F.1 表注 20%–74%”，不要合成一个新区间。政策相近、生成率相差很大，再次说明 $\rho$ 不能代替 $\pi_{\mathrm{succ}}$。

代码落点。生成循环是 `while kept < target: attempt(); if success: keep()`。日志里应同时写 `attempts` 和 `kept`。只写 `kept=1000` 的 hdf5，本课视为缺字段。

生成率还会欺骗排期。$\rho=0.082$ 的 Factory Gear Assembly $D_1$ 要凑 1000 条成功，期望尝试约 1.22 万次。$\rho=0.82$ 的真实 Stack 只要约 243 次。墙钟差几十倍，写进磁盘的成功条数却都叫 1000。混合物若按 hdf5 条数加权，两个任务看起来一样大；按尝试成本加权，装配贵得多。本课主账本按成功条数，因为 α 吃的是 $\tilde n_d$。你若在集群上做生成，另开一列 `attempt_cost`，防止排期把所有机器都送给容易成功的厨房。

真实 Coffee 还拆了子成功：豆荚抓住 60%、插入 20%、全任务 14%。生成器的成功谓词通常是全任务。于是成功集合里每一条都插入成功，政策却在插入上只有 20%。原因写在插值：接近段长、和观察对应弱。这是“成功入库的轨迹，政策仍学不会其中一段”。哈希账看整条，子任务账要另切。本课最低交付不强制子任务 F1，但报告若只写 14% 而不写 60% / 20%，读者无法知道失败发生在接近还是接触。

验证。CPU 实验用 200/243 算出 $\rho\approx 0.823$，与夹具里的政策 0.36 相差超过 0.3。互动教具不模拟尝试次数，避免和 $n_d$ 账混在一起。你自己跑生成器时，把 $\rho$ 和 $\pi_{\mathrm{succ}}$ 写成两列，缺一列不得进入报告摘要。

### 5.5 源演示偏差：少数源轨迹霸占生成集

直觉。10 条源演示看起来已经“覆盖了抓法”。生成时若随机抽源片段，有的源几乎次次成功，有的几乎次次失败。拒绝采样之后，成功集合会塌缩到那几条好源上。磁盘上写着 1000 条，行为多样性接近 3 条。

机制。MimicGen 6.3 节写：Factory Gear Assembly $D_1$ 生成的 1000 条里，超过 850 条来自 3 条源演示；Threading $D_0$ 里一条源贡献超过 170 条，另一条不到 10 条。尝试次数对源大致均匀，成功次数不均匀。源片段的选择策略（随机还是按物体位姿近邻）对部分任务有影响，细节在附录 N。

用 1、10、50、200 条源再生成，Square 与 Three Piece Assembly 上政策差异只有 2 到 21 个百分点。只用 1 条源时，Square 明显变差，Three Piece Assembly 没有显著变化。作者写：更聪明地挑选源演示可能会再涨，但留给未来工作。对“再采 190 条人类就能换来本质不同的合成”这件事，论文自己的消融并不支持。

规模化也有尽头。图 4 右下：200、1000、5000 条生成数据。200 到 1000 有一大截，1000 到 5000 增益很小。200 条 MimicGen（从 10 条人类来）与 200 条人类演示上的政策接近。这句话经常被缩写成“合成等于人类”。原文条件是：同等条数、这些任务、BC-RNN、图像观察。它没有说 5000 条合成等于 5000 条人类，也没有说复合厨房任务成立。

数学。设源 $j$ 贡献了 $c_j$ 条成功生成，赫芬达尔有效源数

$$
J_{\mathrm{eff}}=\frac{(\sum_j c_j)^2}{\sum_j c_j^2}.
$$

Gear Assembly $D_1$ 若 850 条来自 3 条源、其余 150 条就算均匀摊在另外 7 条上，$J_{\mathrm{eff}}$ 仍远小于 10。本课 CPU 不实现这组不完整的摊分，避免编造那 150 条的分配。教学上只要记住：成功集合的源直方图必须记录。缺直方图，1000 条不能写成 10 条源的均匀覆盖。

代码落点。生成日志应给每条成功轨迹写 `source_demo_id`。本课唯一哈希的第一段就是这个字段。公开数据集若没有这个字段，你无法做本节的审计，只能把 $J_{\mathrm{eff}}$ 标成未知。

验证。最低交付不要求复现 850/1000。要求在自己的缩小日志里能数出每个 `source_demo_id` 的 $c_j$。若 90% 成功来自同一条源，报告必须写明，不得写“使用了 10 条源演示”而不写成功侧的直方图。

生成数据还会带伪影。附录 R 承认：只按任务成功过滤，集合可以有偏；线性插值能引入碰撞和别扭的中间姿态。RoboCasa 结论段再次写：许多生成轨迹技术上算成功，但有抖动和碰撞，部分可用仿真状态自动检出并丢弃。成功谓词过了，质量门禁还可以再加一层。本课不实现碰撞检出，只要求你在 recipe 里留一列 `quality_filter`：未做就写未做，不要假装成功谓词已经覆盖平滑性。

源演示条数的消融还要和“源多样性”分开。10、50、200 条源若都采在同一 $D_0$、同一只杯子、同一名操作员，条数增加只是给拒绝采样更多备选片段，复位轴和物体轴几乎不动。MimicGen 自己写差异只有 2 到 21 个百分点，并猜测更聪明的挑选可能会再涨。SkillGen 的 HSP-Class 把选择收成对源片段的分类，再按当前物体位姿变换，等于在部署时也显式依赖源库。源库若只有 3 条有效成功来源，分类器再准也只有 3 个模板。本课 $J_{\mathrm{eff}}$ 就是给这个库用的：部署侧的模板数上界，不能超过生成成功集合里活下来的源数。

无经验操作员那组实验（附录 I）常被读成“谁来采都行”。它比较的是：用这些源去生成之后，政策是否仍接近图 4。它没有比较源直方图会不会更塌缩。新手轨迹也许更难变换成功，于是拒绝采样之后更容易只留下那一两条碰巧能跟的。你若在自己的工位上换操作员，除了看最终政策，还要看 $J_{\mathrm{eff}}$。政策接近而 $J_{\mathrm{eff}}$ 下降，合成集更脆：换一个稍远的复位，成功模板不够用。

### 5.6 RoboCasa：厨房资产多样性与原子技能重复

直觉。MimicGen 的 18 个任务多数是桌面。家庭机器人面对的是一整间厨房：十种平面图、十二种风格、两千多个物体、开门、拧旋钮、插入、导航。RoboCasa 把仿真资产做大，再用 MimicGen 把原子技能的条数做大。资产多样性和轨迹多样性仍可能脱钩：120 间厨房里反复做同一种抓放，视觉变了，动作分布没变。

机制。RoboCasa 基于 robosuite / MuJoCo，扩展到移动操作、人形和带臂四足。10 种平面图、12 种风格，组合成 120 个厨房；墙、地、台面、柜门各 100 张 MidJourney 纹理做域随机。物体 2509 个、153 类，其中 1592 个来自 Luma.ai 的 text-to-3D。电器可开关门、拧旋钮，炉灶旋钮会点燃烧器。任务分两层。25 个原子任务覆盖八项基础技能：抓放、门、抽屉、旋钮、杠杆、按钮、插入、导航。75 个复合任务用 GPT-4 列出 20 类厨房活动，再由 GPT-4 与 Gemini 1.5 提议具体任务，人工过滤逻辑错误后实现。除少数绑定特定环境的任务外，复合任务可在任一厨房里仿真。

八项技能对应的原子任务在附录图 9。同一技能下可以有多个语言变体：抓放按物体类别消歧，炉灶按燃烧器消歧，导航按目标电器消歧。语言变体增加的是指令轴，不一定增加动作哈希。把“把红色杯子放到水槽”和“把蓝色杯子放到水槽”写成两个任务，复位箱可以完全重合。本课哈希不含指令字符串，就是为了避免语言改写制造假唯一。你若要审计指令覆盖，另开 `instruction_id` 一列，不要塞进 $U$。

人类数据：四名操作员、每个原子任务 50 条、随机厨房，共 1250 条，称为 Human-50。作者写：这个规模仍不够解决大多数任务。于是对 24 个原子任务（排除导航）各用 50 条源生成 3000 条，共 72000，称为 Generated-3000；再各取 1/10 与 1/30 得到 Generated-300（7200 条）和 Generated-100（2400 条）。发布集另含 2.8 万条 AI 物体轨迹，凑成 10 万。训练用 AI 纹理，评测用人工纹理；每任务 50 次试验、5 个固定场景，其中 2 个风格未见过；只评未见物体实例。政策是 RoboMimic 的 BC-Transformer，机体是带 Omron 底盘的 Franka。Objaverse 物体和 Luma 物体被拆开记账：主实验用 Objaverse，额外 28K 才是 AI 物体。引用 10 万时必须写清这两段，不能把 72K 主实验写成 10 万主实验。

图 5 按技能族汇总：Human-50 总体 28.8%，Generated-3000 总体 47.6%，并且 Generated-100、300、3000 呈上升趋势。开门开抽屉容易，抓放和插入难。作者的解释是多样性与灵巧：抓放涉及几十类物体和不同可供性，开门只涉及六种门。复合任务改成单任务政策。五件代表任务上，50 条人类从零训：ArrangeVegetables 2%，其余四件 0%。用 Generated-3000 的原子政策微调后：12%、2%、6%、4%、0%。PrepareCoffee 仍是 0%。作者把失败归到精细操作和阶段切换，并写基准仍有很大改进空间。

真机三件抓放（台面到水槽、水槽到台面、台面到柜子）在 DROID 硬件上评。仿真用操作空间控制、20 Hz，真机不是 OSC、15 Hz，外参、灯光、基座放置都不同。每任务 50 条真实演示、五类物体。Seen 物体：只真实 13.6%，真实加仿真 24.4%，相对提升 79%。Unseen 物体：2.6% 对 9.3%。三粒种子，表 8 给出均值和标准差。控制器不一致已经被写进正文，不能把 24.4% 写成“仿真已经对齐真机”。

导航原子任务没有合成数据。作者写 MimicGen 当时不能生成移动操作轨迹，留给未来。本课四域玩具因此不设“导航”域：没有 $s_d$ 的域，不能假装被合成补过。

代码落点。任务实现与数据集说明在 `robocasa` 仓库。仿真速度附录 VII：PickPlaceCounterToCab、RTX A5000 渲染，复位平均 9.50 秒，`env.step` 25.2 fps，与 25 fps 的仿真时钟几乎实时；无渲染时 31.9 fps。这些数字说明生成 3000 条的墙钟主要耗在复位和成功过滤，不是前向网络。

五件复合任务的字段值得单独抄，防止以后有人把名字记成“都会做一点”。ArrangeVegetables 属于切菜：水槽里两棵蔬菜放到砧板上。MicrowaveThawing 属于解冻：台面上的冷冻食品放进微波炉并打开。RestockPantry 属于补货：台面上多个罐子放进柜子，还要对齐柜子里已有罐子的左右侧。PreSoakPan 属于洗碗：平底锅和海绵放进水槽并开水龙头。PrepareCoffee 属于冲咖啡：柜子里拿杯子、放到咖啡机下、按按钮。从零训只有第一件 2%，其余 0%；微调后 12%、2%、6%、4%、0%。共同失败是精细操作和“何时切到下一阶段”。原子生成集里有大量抓放，所以微调后抓放看起来稳一些；没有足够的阶段切换监督，咖啡机按钮仍然按不到。本课不把这五件做成第五个域，避免和四域玩具分叉。你自己扩域时，复合任务应单独成桶，且 $s_d=0$ 必须写明。

120 间厨房改变的是视觉域。若合成轨迹的末端相对运动仍来自同一条源抓放，视觉多样性上升、动作多样性不升。评测“未见物体实例”测的是视觉泛化；测动作长尾要另看双臂、插入、复合阶段切换。本课最小域就是为后一项准备的。你若只在厨房抓放上复制 RoboCasa 的 3000 条，相当于把本课滑条锁死在最大域。纹理随机可以让第 26 课的桌布捷径变弱，这是好事；它不自动增加双臂哈希。两件事要分开写进 recipe：`visual_randomization` 一列，`skill_synth_target` 另一列。

验证。把 RoboCasa 的四档数据写成一行：$50$ 人类、$100$ 生成、$300$ 生成、$3000$ 生成。总体成功 28.8% 只属于第一档和第四档之间的对比，中间两档论文用图给出趋势、没有在正文写总体百分数。不要替图 5 编三个中间均值。复合任务五件必须单独成表，禁止和 47.6% 平均。真机三件必须再单独成表，并写 OSC 对非 OSC、20 Hz 对 15 Hz。

### 5.7 有效样本量：重复轨迹的哈希

直觉。两份 hdf5，轨迹条数都是 2000。一份每条对应不同复位箱，一份是同一条厨房演示复制 2000 次。第二份的 `len(dataset)` 仍然是 2000，优化器却在反复看见同一个 $(s,a)$。有效样本量必须能识破这件事。

机制。给每条轨迹一个哈希 $h=(\mathrm{source\_id},\;\mathrm{reset\_bin})$。复位箱是把连续物体位姿量化后的整数编号；本课教具里每个新复位就是一个新整数，每个拷贝复用旧整数。记哈希 $i$ 出现 $n_i$ 次。原始条数 $N=\sum_i n_i$，唯一哈希数 $U=|\{i:n_i>0\}|$，赫芬达尔有效样本量

$$
n_{\mathrm{eff}}=\frac{(\sum_i n_i)^2}{\sum_i n_i^2}.
$$

全部 $n_i=1$ 时 $n_{\mathrm{eff}}=U=N$。某一条被复制 $c$ 次、其余仍为 1 时，$n_{\mathrm{eff}}$ 迅速塌缩。本课真实侧 9050 条各不相同，$n_{\mathrm{eff}}=9050$。再把一条厨房轨迹复制 2000 次：$N=11050$，平方和 $2001^2+9049=4013050$，

$$
n_{\mathrm{eff}}=\frac{11050^{2}}{4013050}\approx 30.43.
$$

唯一哈希仍是 9050。条数账说你多了 2000，有效样本量从九千掉到三十。混合物若仍用 $\tilde n_d$ 计厨房条数，厨房份额还会上升。两本账同时变坏。

若 2000 条都是新复位哈希，$U=11050$，$n_{\mathrm{eff}}=11050$。这时条数账和有效样本量一起涨。合成有没有补分布，看的是 $U$ 和复位箱的直方图，不是 $N$。

数学。$n_{\mathrm{eff}}$ 就是种群有效容量，和 $D_{\mathrm{eff}}=1/\sum p_d^2$ 同族：一个是样本哈希的碰撞，一个是域概率的碰撞。$D_{\mathrm{eff}}$ 不能代替 $n_{\mathrm{eff}}$。把 2000 条独特双臂轨迹加进去，$D_{\mathrm{eff}}$ 与 $n_{\mathrm{eff}}$ 都升；把 2000 份厨房拷贝加进去，$D_{\mathrm{eff}}$ 降（α=1），$n_{\mathrm{eff}}$ 更降。只报其中一个，另一本可以作假。

复位箱的宽度是约定。箱太宽，两个差 2 cm 的杯子被当成同一哈希，会低估 $U$。箱太窄，控制器噪声也会制造假唯一。本课约定：教具里“新复位”模式每个合成样本一个新箱，“重复”模式全部复用箱 0。真实系统要把箱宽写进 recipe，例如平移 2 cm、旋转 15°。改箱宽视为另一份实验。

代码落点。`herfindahl_sample_size` 只吃多重数列表，不读文件。你在真实 hdf5 上复现时，先定义哈希函数，再跑同一条公式。哈希若只含文件名，复制改名就会骗过 $U$。必须落到源 ID 和复位箱。

验证。CPU 实验断言：重复后 $U$ 不变，$n_{\mathrm{eff}}$ 不升，且原始条数仍然变成 11050；新复位合成后 $U$ 增加 2000，$n_{\mathrm{eff}}=U$。四条缺一，哈希合同就还只是口头。

第 01 课用文件指纹防止“换了一份数据还叫同一基线”，见[第 01 课](01_baseline_reproduction.md)。本课的哈希是它在轨迹级的亲戚：防止“换了一个文件名还叫一条新演示”。01 课的 hash 对文件字节；本课的 hash 对源 ID 与复位。两层都要有。只有文件哈希，复制后再改时间戳仍能混进 $U$。

### 5.8 接到第 26 课混合物：合成加到哪一域

直觉。第 26 课的 cap 把大域截断，让小域回升。合成器是另一条螺丝：它能增加某一域的分子。两条螺丝可以对着拧。一边用 MimicGen 给厨房再灌 2000 条，一边把 cap 设成 400，厨房的合成预算有一半会在加权前被扔掉。不是不能这么做，但必须写在同一张 recipe 上，否则有人以为 2000 条都进了梯度。

机制。完整流水线是：生成到域 $d$ 得到 $s_d$，形成 $\tilde n_d$；可选 $\tilde n_d'=\min(\tilde n_d,C)$；再算 $p_d\propto (\tilde n_d')^\alpha$。本课主路径不把 cap 和合成同时打开，避免两颗螺丝的效应缠在一起。教具只动合成目标和哈希模式，α 默认为 1，因为验收句子写的是“α=1 更糟”。把 α 拖到 0，合成进哪一域都不影响 $p_d$，清单不会把“更糟”点亮，这是故意的。

第 26 课的机体捷径在合成数据上会换一张脸。MimicGen 可以跨手臂生成：Panda 源演示变成 UR5e 轨迹。若生成集里 UR5e 的成功几乎都来自同一条 Panda 源，模型仍可能在学那条源的桌面纹理，只是外壳换了。打乱指令和打乱机体仍然要做，方法见第 26 课。本课不重做那八格，只要求合成账本给第 26 课留出 `source_demo_id` 和机体字段。

第 34 课的数据引擎生成视频。Cosmos 自己写：当前模型不能当可靠物理仿真器，物体会消失、重力会违例。MimicGen 不生成视频，它在仿真或真机里执行末端命令，成功谓词来自环境。门禁因此更硬：失败尝试进不了 $\mathcal{D}$。硬门禁不等于分布门禁。成功的 1000 条仍可挤在 3 条源、同一只杯子、同一块桌布上。物理探针过了，长尾探针可以失败。两课的过滤器要串起来用：先问轨迹是否执行成功，再问成功集合覆盖了哪些复位和哪些域。

若有人把 Cosmos 生成的操作视频再送给 MimicGen 当“源演示”，合同会断在假设 1：视频里没有末端增量动作，只有像素。要从视频反解动作，那是另一篇论文、另一套标定。本课不允许把第 34 课的生成视频直接加进 $n_d$。可以加进视觉预训练，那是第 21–22 课的图文配方，动作监督仍为零。recipe 里视觉合成和动作合成必须分两行。

第 26 课四域是 10000/1000/200/100，本课是 8000/800/200/50。分母不同，是为了防止有人把两课的 $D_{\mathrm{eff}}$ 抄到同一张表而不改计数。26 课 α=1 的 $D_{\mathrm{eff}}\approx 1.26$，本课合成前也约 1.27，数量级相同、具体分数不同。检查作业时按本课 9050 复算。你若把 26 课的 11300 拿来跑本课 CPU，checks 会失败，这是故意的。

数学。定义合成增益

$$
\Delta D_{\mathrm{eff}}=D_{\mathrm{eff}}(\tilde n)-D_{\mathrm{eff}}(n),\qquad
\Delta p_{\min}=p_{\min}(\tilde n)-p_{\min}(n).
$$

验收：对最大域加水，$\Delta D_{\mathrm{eff}}<0$ 且 $\Delta p_{\max}>0$；对最小域加水，$\Delta p_{\min}>0$ 且 $\Delta D_{\mathrm{eff}}>0$。本课 $S=2000$ 时第一组 $\Delta D_{\mathrm{eff}}\approx -0.053$，第二组 $\Delta D_{\mathrm{eff}}\approx +0.506$、$\Delta p_{\min}\approx +0.180$。符号比绝对值重要。换一组 $n_d$ 只要保持两个数量级差，符号应保持。

代码落点。教具的三项清单对应三组参数：α=1、合成≥1500、目标=厨房且非重复；α=1、合成≥1500、目标=双臂；重复模式、合成≥1500。默认配置只点亮第一项所需的“厨房+2000”，必须再拨两次。CPU 实验把三组同时算完，用 checks 代替拨杆。

验证。互动实验必须先提交预测“合成只加到最大域时 α=1 的有效域数会下降”，再分别揭晓三组。预测选“无论加到哪一域有效域数都上升”或“重复会提高有效样本量”，Gate 不通过。数字在揭晓前显示为破折号，避免对着已经画好的条形图补理由。

## 8. 评测与测量

本课评测对象是合成账本，不是政策成功率。指标如下。

| 指标 | 定义 | 合格方向 |
|---|---|---|
| 最大域份额 | $\max_d p_d$ | 合成进最大域、α=1 时应高于合成前 |
| 最小域份额 | $\min_d p_d$ | 合成进最小域后应明显高于合成前 |
| 有效域数 | $1/\sum p_d^2$ | 进最大域应下降；进最小域应上升 |
| 唯一哈希 $U$ | 不同 `(源, 复位箱)` 个数 | 重复模式下应不变 |
| 有效样本量 | $(\sum n_i)^2/\sum n_i^2$ | 重复模式下应不升 |
| 相对位姿误差 | 变换后目标与 $C+O'-O$ 的距离 | 正确式应为 0 |
| 生成率 $\rho$ | $N_{\mathrm{keep}}/N_{\mathrm{attempt}}$ | 必须与政策成功分列 |
| 有效源数 $J_{\mathrm{eff}}$ | 成功集合上的源赫芬达尔 | 可选；缺直方图则标未知 |

MimicGen、RoboCasa、SkillGen 论文里的成功率只允许出现在“论文对照”段，并且必须带任务名、复位名称、是否图像观察、评测次数。禁止把教具上的 90.5% 写成 Square 的 90.7%。前者是厨房域份额，后者是 Square $D_0$ 图像政策最高成功。数字接近是巧合。

把论文数字和本课夹具并排时，用两张表。论文表要有：文献、任务、复位、观察、种子或次数。MimicGen 图像政策是 3 种子取最高；RoboCasa 原子是每任务 50 次、5 场景；真机是 3 种子。次数已经不多。再从里面抽出“平均成功率”当跨论文排名，误差会盖过差值。本课夹具表只有确定性算术，连置信区间都不该写。它只回答“公式方向对不对、哈希能不能识破拷贝”。

样本量。CPU 夹具的 $n_{\mathrm{eff}}$ 是公式值，不是试验次数。若你做可选真实评测，N=25 的二项区间会很宽，第 31 课会专门算。本课提前立规矩：N 太小的成功率不进标题；生成率进标题必须同时写尝试次数。

训练过程中的 $s_d$ 还可能漂。生成器若先把容易成功的厨房堆满，再慢慢补插入，前期 batch 会比 recipe 更偏厨房。最低交付要求配置里的静态 $s_d$；可选扩展要求按写入时间画 $U(t)$ 和 $p_d(t)$。折线若在没有改配置的情况下自己走形，生成器的拒绝采样在改混合物。

$U(t)$ 还有一种合法的走形：质量过滤器上线之后，$N$ 下降、$U$ 几乎不降。那说明丢掉的是重复姿态或碰撞段，不是新复位。若 $U$ 随过滤器一起暴跌，成功集合本来就挤在少数箱里。两种走形的修复不同。第一种可以接受，在 recipe 里记下过滤前后的 $N$ 和 $U$。第二种要回到源直方图和目标域，不能靠再生成一万条厨房来救。

评测复位必须和生成复位分开写。MimicGen 在 $D_1$ 上生成、也在 $D_1$ 上评，这是同分布。RoboCasa 训练用 AI 纹理、评测用人工纹理，这是视觉移位。真机共训的评测物体分 seen / unseen，这是物体轴移位。三套协议不能共用一个“成功率”列名。本课夹具没有评测复位，只有计数复位。你可选真实评测时，先写评测 $D$ 是不是生成 $D$，再写数字。同分布的高成功不能写成移位已经解决。

## 9. 验收条件

同时满足以下条款，本课才算完成。缺一条就不能把合成标成“已补分布”。

1. CPU 实验 `checks` 全为真。
2. 手算或程序给出：2000 条进厨房后 α=1 最大域份额高于 88.4%，$D_{\mathrm{eff}}$ 下降。
3. 2000 条进双臂后最小域份额相对合成前上升超过 15 个百分点。
4. 重复 2000 条后 $U$ 不变，$n_{\mathrm{eff}}$ 不升。
5. 变换夹具正确式打到 $(1.2,2)$，写反式打到 $(-0.8,-2)$。
6. 互动实验先提交正确预测，再触发三张清单：灌最大域更糟、补最小域回升、重复不增加 $n_{\mathrm{eff}}$。
7. 报告区分 MimicGen 论文 18 任务 / 50K+ 与仓库 12 任务 / 48K+，区分 RoboCasa 论文 100 任务 / 10 万与发布页 RoboCasa365。
8. 没有把 CPU、$D_{\mathrm{eff}}$ 或教具份额写成真机成功率。

出现以下任一情况，验收失败：

- 只报 $N$ 增加，不报 $s_d$ 进了哪一域；
- 用 α=0 的均匀混合物掩盖“灌进最大域”；
- 把生成成功率写成政策成功率；
- 哈希只用文件名，复制改名后 $U$ 上升；
- 把附录 M 最后一行写进控制器且没有对照夹具；
- 把 47.6% 写成复合任务或真机；
- 把 Square 90.7% 与教具 90.5% 抄在同一格；
- 互动实验没有先提交预测就揭晓，三项清单未齐。

验收不是礼貌。合成一旦写进后续 VLA 训练，错误会变成“模型结构不行”的假诊断。本课过关的唯一证据是：域去向、哈希、$n_{\mathrm{eff}}$、变换公式，四件事都能在你的日志里复算。缺哈希的 hdf5 可以训出一个看起来在降的 loss，那只说明厨房又被读了一遍。loss 下降不能代替账本。第 01 课要求每份数据有指纹，本课要求每条合成轨迹有源 ID 和复位箱。两层指纹缺一层，复现时你会以为换了一份更大的数据，其实只是把同一条厨房轨迹读得更勤。

## 10. 根据症状定位失败环节

| 症状 | 先查 | 不要先改 |
|---|---|---|
| 合成后 $D_{\mathrm{eff}}$ 几乎不变 | $s_d$ 是否其实是 0，或 α 被设成 0 | 不要先加生成条数 |
| 进厨房后 $D_{\mathrm{eff}}$ 上升 | 是否在归一化后的 $p_d$ 上做了均匀化 | 不要宣称“合成总能补多样性” |
| 进双臂后最小份额不动 | 加法是否加错键名，或仍在用合成前的 $n_d$ | 不要先降 α |
| $N$ 涨了，$U$ 不涨，$n_{\mathrm{eff}}$ 暴跌 | 是否在复制 hdf5 | 不要把复制当数据增强 |
| $U$ 涨了，政策仍只会厨房 | 新哈希是否都落在厨房复位箱 | 改目标域，不要先换骨干 |
| 变换后夹爪去抓空气 | 是否用了写反的 $T_O$、$T_{O'}$ | 不要先加插值步数 |
| 插值段撞物体 | 线性插值路径 | 不要先怪源演示 |
| 生成率很低、政策却不差 | 这是论文已报告的现象 | 不要用 $\rho$ 当早停 |
| 生成率很高、政策很差 | 复位是否仍停在 $D_0$，源直方图是否塌缩 | 不要只加条数 |
| 1000 条几乎来自 3 条源 | `source_demo_id` 直方图 | 不要写“用了 10 条源” |
| 原子任务涨、复合任务仍接近 0 | 这是 RoboCasa 图 6 的现象 | 不要把 47.6% 抄到复合栏 |
| 真机共训有提升但绝对值仍低 | 控制器频率、OSC、外参是否已写明 | 不要把 24.4% 写成已对齐 |
| 导航域没有合成条 | MimicGen 当时不支持移动操作 | 不要把厨房抓放的 $s_d$ 分给导航 |
| 跨手臂政策接近、生成率差一倍 | 正文 6.1 节已写 | 不要用生成率给手臂排名 |
| 与第 26 课 $D_{\mathrm{eff}}$ 对不上 | 计数是 8000/800/200/50，不是 10000/1000/200/100 | 不要改第 26 课夹具 |

RoboCasa 结论里计划用仿真状态自动丢掉抖动和碰撞。那是质量过滤器，不是分布过滤器。加上之后 $N$ 会下降，$U$ 可能几乎不降（丢掉的是坏姿态，不是重复复位）。若 $U$ 随质量过滤一起暴跌，说明成功集合本来就挤在少数箱里，过滤器只是把已经很窄的分布再剪一次。

## 12. 前沿对照与改造方向

公开方案。MimicGen 用物体中心切段加相对变换，把约 200 条人类演示扩成 50K+ 条，并在 $D_1$、$D_2$、新物体、新手臂和真实机械臂上展示政策。它自己的分析已经包含本课需要的三句冷水：生成率与政策成功不必相关；源演示贡献可以极不均匀；200 到 1000 有用，1000 到 5000 增益很小。作者还写：无经验操作员和不同遥操作设备采的源，生成后政策仍可与图 4 接近，细节在附录 I。这句话限制的是“源必须出自专家”的神话，不限制“源直方图可以塌缩”的事实。Nut Assembly 与 Pick Place 上，先前工作用超过 1000 条、10 名操作员的人类数据，也只在更简单的单阶段版本上训出可用政策；MimicGen 用 10 条源生成 1000 条后，低维 76.0% 与 58.7%，图像 53.3% 与 50.7%。对照要带“单阶段对完整任务”这一层，不能写成“10 条已经打败 1000 条人类”。

RoboCasa 把生成接到 24 个原子厨房任务，总体从 28.8% 到 47.6%，并在三件真机抓放上用仿真共训把 seen 物体从 13.6% 拉到 24.4%。同一篇文章里，五件复合任务微调后最高 12%，PrepareCoffee 为 0%；生成轨迹存在抖动和碰撞；导航没有合成数据。资产侧的数字同样要分家：120 场景、2509 物体、1592 个 text-to-3D，说的是视觉与可交互家具；72000 条 Generated-3000 说的是原子技能轨迹。两套规模可以同时很大，长尾技能仍然短。

SkillGen（2410.18907）把接触段留给变换，把自由空间段交给运动规划，生成率均值 75.4% 对 MimicGen 的 40.7%，政策平均高 24 个百分点。分变体更清楚：Square $D_2$ 生成率 87.7% 对 31.8%，Threading $D_2$ 74.3% 对 21.6%，Three Piece Assembly $D_2$ 69.3% 对 31.3%，Coffee $D_2$ 70.0% 对 27.7%。Coffee Prep $D_2$ 把抽屉和杯子放到桌子两端，MimicGen 生成 0 条，SkillGen 59.9%。杂乱变体 49.0%–72.0% 对 4.0%–16.5%。HSP-TAMP / Class / Reg 均值 85.7%、82.9%、72.6%，对照 MimicGen 数据上的 BC-RNN 59.1%。真机 3 条 HITL-TAMP 源加 100 条生成，Pick-Place-Milk 与 Cleanup-Butter-Trash 接近满分，Coffee 65%，对照 MimicGen 真机 Coffee 14%。采 10 条 HITL-TAMP 源每任务不到 4 分钟，采 200 条人类要 37–71 分钟。仿真到真实的螺母装配：仿真里 HSP-Class 92%、MimicGen 72%；真机全任务 35% 对 MimicGen 未能完成。部署时该实验不用视觉与位姿跟踪，只看本体感觉变化。这些是另一篇论文、另一套控制器（规划器加接触政策），不能回溯改写 2310.17596 的 BC-RNN 数字，也不能把 35% 写成通用仿真到真实已经解决。

第 34 课的 Cosmos 是视频数据引擎。它不执行末端命令，成功谓词不是环境里的杯子是否插入。把 Cosmos 视频和 MimicGen 轨迹加进同一个 $N$，单位已经坏了。视频补的是视觉外观与物理外观；MimicGen 补的是可执行动作。两份合成都要过各自的过滤器，再过本课的域去向过滤器。

差距。缩小版和前沿的规模差是钱：四名操作员采 1250 条、每任务生成 3000 条、真机 DROID 工位，本课都不做。机制差不是钱：α=1 时灌最大域会降 $D_{\mathrm{eff}}$、重复会降 $n_{\mathrm{eff}}$、写反 $T_O$ 会错过物体，在四域计数和二维平移上就能做假。另一项机制差是运动规划替代线性插值，CPU 实验覆盖不到；要补只能走 SkillGen 的可选阅读，不能在本课夹具里假装已经规划。RoboCasa 复合任务接近零成功，是规模加机制：原子技能预训练帮了一些抓放，帮不了阶段切换。本课不训练复合政策，只要求你拒绝把 47.6% 抄进复合栏。

动手改造（均在缩小版，禁止把真机成功率当完成条件）：

1. **扫合成目标。** 固定 $S=2000$、α=1，把合成依次加到四个域，记录 $D_{\mathrm{eff}}$ 与最小份额。预算：CPU 一分钟。预期：只有加到最小两域时 $D_{\mathrm{eff}}$ 明显上升。失败：四个目标的 $p_d$ 完全相同，说明加法没有进计数。
2. **哈希箱宽。** 把复位箱从“每条一个箱”改成每 5 条共用一箱，重算 $U$ 与 $n_{\mathrm{eff}}$。预算：CPU。预期：$U$ 下降，$n_{\mathrm{eff}}$ 下降。失败：箱宽改变后两数不变，哈希函数没吃到 `reset_bin`。
3. **源直方图。** 造 10 条源、按 $(850,50,40,20,10,10,10,5,3,2)$ 分配 1000 条成功，算 $J_{\mathrm{eff}}$。预算：CPU。预期：$J_{\mathrm{eff}}$ 远小于 10。失败：报告仍写“10 条源均匀覆盖”。
4. **变换对照。** 在二维夹具上对 8 个新物体位姿同时跑正确式与写反式，统计错过物体的次数。预算：CPU。预期：写反式 8 次全错。失败：两种公式输出重合，实现把 $T_O$ 当成了单位阵且 $O=O'$。

顺手复现映射：

| 论文结论 | 缩小版对应 | 预期 |
|---|---|---|
| 按条数加水不一定补多样性（本课主结论） | 2000 条进厨房 vs 进双臂 | 能复现方向：符号相反 |
| 源贡献极不均匀（MimicGen 6.3） | 改造 3 的 $J_{\mathrm{eff}}$ | 能复现方向；不能复现 850/1000 的原任务 |
| 1000 到 5000 增益小（MimicGen 图 4） | 本课不训练政策 | 不能复现，只在报告引用 |
| 原子任务随生成规模上升（RoboCasa 图 5） | 本课不训练 24 任务 | 不能复现绝对值，只能引用 28.8% 升到 47.6% |
| 复合任务仍然极难（RoboCasa 图 6） | 不训练 | 不能复现，必须分表 |
| 线性插值引入碰撞（两文 Limitations） | 夹具只测端点 | 不能复现碰撞，只测公式 |
| SkillGen 生成率更高（75.4% vs 40.7%） | 不实现规划器 | 不能复现，只引原文 |

## 13. 论文与必读材料

读这些材料时带着本课的分布问题，不要把它们读成“合成数据已经解决操作”。

1. [MimicGen: A Data Generation System for Scalable Robot Learning using Human Demonstrations](https://arxiv.org/abs/2310.17596)  
   带着什么问题读：约 200 条源和 50K+ 生成分别对应哪些任务、哪些变体？第 4.2 节与附录 M 的变换公式最后一行是否自洽？图 4 里 10 条源、200 条人类、200/1000/5000 条生成各比较了什么？6.3 节的源直方图和“生成率不必等于政策成功”分别限制你怎样写摘要？6.4 节真实 Stack 82.3% / 36%、Coffee 52.1% / 14% 为什么必须分列？Limitations 里的物体位姿、准静态、同类新物体，哪些直接限制你把系统接到灵巧手？

2. [RoboCasa: Large-Scale Simulation of Everyday Tasks for Generalist Robots](https://arxiv.org/abs/2406.02523)  
   带着什么问题读：25 原子加 75 复合是怎样用 LLM 提案再人工过滤的？Human-50、Generated-100/300/3000 的分母分别是什么，为什么导航不在生成集里？图 5 的 28.8% 与 47.6% 按技能族怎么拆，抓放为什么难、门为什么易？图 6 五件复合任务从零和微调的数字如何阻止你写“厨房已经会做”？图 8 真机 13.6% 对 24.4% 的控制器差异写在哪一段？结论里抖动、碰撞、复合任务、厨房以外场景，哪些是本课过滤器还没覆盖的？

3. [SkillMimicGen: Automated Demonstration Generation for Efficient Skill Learning and Deployment](https://arxiv.org/abs/2410.18907)  
   带着什么问题读：它如何把 MimicGen 的整段回放收成接触段加规划段？75.4% 对 40.7% 的生成率表在附录 F，政策平均 +24 个百分点的对照集是哪些变体？Coffee Prep $D_2$ 与 Clutter 变体说明线性插值在什么复位上崩溃？真机 3 条源加 100 条生成的 65% Coffee，与 MimicGen 真机 14% 是否同一任务定义？仿真到真实 35% 全任务成功的观察是什么（文中写明部署时不用视觉与位姿跟踪）？不要把 HSP 的规划器成功写成 BC-RNN 的模仿成功。

4. [Open X-Embodiment](https://arxiv.org/abs/2310.08864) 与本课第 26 课笔记  
   带着什么问题读：真实跨机体混合物的 $p_d$ 表，怎样接收一列叫做 `synthetic` 的新域？合成域要不要单独 cap？若 5 万条 MimicGen 桌面和 97 万条真实 OXE 倒进同一 loader，α=1 时谁被淹没？

读完四份，下一课才处理端侧量化对各模态 token 的损伤。合成账本能审计之后，才能判断部署误差来自量化，还是来自训练集里根本没有那条长尾技能。第 55 课若发现动作箱先跳类、文本 top-1 仍在，先回查本课：跳类的那些箱，训练时是否只在厨房域里出现过。量化损伤和长尾缺失会给出相似的“动作错了”，定位顺序必须先问 $s_d$ 和 $U$，再问 bit 宽。

四份合在一起，只承诺三句可核对的话。第一句：合成可以少采人类，MimicGen 用约 200 条做出 50K+，RoboCasa 用 1250 条人类加生成做出原子任务的规模化曲线。第二句：条数不是分布，灌进最大域会降 $D_{\mathrm{eff}}$，重复会降 $n_{\mathrm{eff}}$，少数源会霸占成功集合。第三句：原子任务上涨、复合任务接近零、真机共训有相对提升但绝对值仍低，三张表不能横着加。本课的目标域滑条、哈希和变换夹具就是把这三句话变成可计算的作业。做完作业，才配把合成 hdf5 交给后面的部署课。

补充阅读时把“人类时间花在哪”写成可执行规则。MimicGen 问过：同等条数下合成已经接近人类，人还要不要在同一复位里继续采。SkillGen 给出一种花法：人只演示接触段，自由空间交给规划，3 条源加 100 条生成就能在真机 Coffee 上到 65%。RoboCasa 给出另一种花法：人把 50 条原子演示采到随机厨房，再让生成器把每任务扩到 3000。两种花法都没有把人送去采 3000 条复合任务。复合任务仍然接近零，说明人的下一段时间也许不该继续堆原子条数，而该去标阶段边界、写更好的成功谓词、或者像 SkillGen 那样把长程切成可规划的接触段。本课不替你选花法，只要求任何花法的产物都能填进第 11 节那张账本。填不进去的生成流水线，先改日志，再谈规模。
