# 第 21 课：用对比学习建立图文共享空间

> 内容：双塔编码、InfoNCE、温度与 SigLIP 的 sigmoid 损失<br>
> 建议周期：2–4 天（阅读 + CPU 实验）<br>
> 硬件：CPU 完成本课机制实验；复现 CLIP / ALIGN 论文规模需要大规模 TPU / GPU 集群<br>
> 产物：手算 4×4 损失、可互动相似度矩阵、共享空间机制图

## 1. 图和字怎样被拉进同一空间

MiniMind-O 的眼睛是冻结的 SigLIP2：一张图切成固定大小的 patch（图像小方块，编码器逐块看图），变成一串向量，再经 [第 02 课](02_multimodal_connector.md) 的 connector 送进 Thinker。第 01 到 20 课把它当外部模块用，几乎不问它从哪来。本课补上这一问。

没有 ImageNet 那种预先印好的类别表时，一张图旁边往往只有一句网上抓来的话：商品标题、alt-text（网页里给图片写的替代文字）、社交配文。你不能把这句话当成 1000 类里的某一个编号。你能做的更朴素：在一个 batch（一次送进显存的一组样本）里，判断哪句字配哪张图。

这件事需要两座塔。图像编码器把像素压成一个向量 $x$，文字编码器把句子压成一个向量 $y$，两边先各自做 L2 归一化（把向量长度收成 1，之后内积就是余弦相似度）。配对的 $(x_i,y_i)$ 应该靠近，同 batch 里其他组合 $(x_i,y_j)$（$i\neq j$）应该推开。训练完成后，类名也可以送进文字塔，变成一组权重，和图像向量比谁更近。这就是零样本分类（zero-shot classification：下游任务不再单独训分类头，只靠文字描述选最近的类）。

本课不训练 4 亿对数据，也不改 MiniMind-O 的冻结权重。你要能在一张 $4\times 4$ 的相似度表上亲手算出 InfoNCE（对比学习里把“找正对”写成分类的损失）和 sigmoid 损失，并说明温度（temperature，记作 $\tau$，用来缩放 logits 的正数）过小或过大分别会把训练变成什么。浏览器里的互动实验是教学模拟，不是公开 CLIP 权重的输出。CPU 实验证明公式可复核，不证明真实 ImageNet 成功率。

若你已经做过第 01–20 课，本课是第七幕的入口：前面一直把 SigLIP2 当冻住的眼睛，现在要问这双眼睛的坐标系从哪来。若你从本课直接开始，不需要 Thinker、Talker 或 codec 的背景；你只需要接受一件事：后面的视觉语言模型会把这座图像塔冻住，接到一个语言模型上。冻得是否值得，取决于这座塔是否已经把图和字放进同一把尺子。尺子的刻度就是余弦，刻度是否灵敏由 $\tau$ 决定，尺子上谁是“同一对”由对角决定。

本课术语：

| 术语 | 简要解释 |
|---|---|
| 双塔 / dual encoder | 图像和文字各走一座编码器，中间不交叉注意力，只在向量空间比远近 |
| 共享空间 | 两个塔输出的同一维向量空间，余弦大表示“配得上” |
| 正对 / 负对 | 同一条训练样本的图和字是正对；同 batch 其他组合默认当负对 |
| InfoNCE | 把每一张图对 $N$ 句字做 softmax 分类，正对是正确答案 |
| 温度 $\tau$ | 除在 logits 上的正数：越小分布越尖，越大越平 |
| in-batch negative | 负样本不另采样，直接用当前 batch 里别人的图或字 |
| SigLIP | 用逐对 sigmoid 代替行内 softmax 的图文预训练 |
| LiT | Locked-image Tuning：锁住预训练图像塔，只训文字塔去读这些图像向量 |
| 零样本分类 | 用类名文本当分类器权重，不再用该数据集的训练图 |

第 22 课才会讲冻视觉、训投影、再解冻语言模型的标准 VLM 配方。第 08 课讲动态分辨率，不管共享空间怎么来。本课停在“空间是怎么被拉出来的”。学完之后你应能指着 MiniMind-O 的冻结视觉模块说：它能当眼睛，是因为预训练阶段已经用 InfoNCE 或 sigmoid 在大批图文对上把 $x$ 和 $y$ 拉近过；现在少了文字塔，只剩下 $x$，语言模型用投影层去读这些 $x$，不再做 $N\times N$ 对比。

## 2. 本课解决的问题

冻结视觉编码器能给语言模型当眼睛，前提是它的输出已经和语言住在可以比较的空间里。否则 connector 再怎么映射，也只是在搬一堆与文字无关的像素统计。

本课要回答三件具体的事：

1. 对比损失拉近的是配对样本的向量，推开的是同 batch 里其他组合。没有第三本“负样本词典”。
2. $\tau$ 过小，softmax 接近 one-hot（几乎只有正对位置是 1），训练对温度和噪声极敏感；$\tau$ 过大，正负对的概率差被抹平，梯度变弱。
3. InfoNCE 必须看见整行相似度才能做归一化；SigLIP 的 sigmoid 损失把每一格当成独立的“是不是一对”，不必做 batch 级 softmax。

出现以下任一情况时，不得声称“已经理解共享空间”：

- 只能复述“图和字被拉到一起”，说不出矩阵里哪一格是正对、哪一格是负对；
- 把 CLIP 的 ImageNet 零样本准确率直接写成下游看图问答准确率；
- 认为 batch 变小只影响速度，不改变 InfoNCE 的负样本集合；
- 把 LiT 说成“冻语言模型、只训视觉”。LiT 论文的定义是锁图像塔、训文字塔；
- 把温度当成学习率：$\tau$ 缩放的是 logits，不缩放梯度步长，也不能代替 weight decay；
- 把 L2 归一化省掉之后，用更大的 $\tau$ 去“补”，两个标量会缠在一起，论文数字全部失效。

本课要改的是你对冻结视觉模块的解释，不改 MiniMind-O 的权重文件。验证对错的手段是公式和 $4\times 4$ 夹具，不是再训一个 26M 的 Thinker。Thinker 的文本能力在本课必须保持原样：你没有动它。

本课主路径在无 GPU 时必须能读完并跑通 CPU 实验。若要加载公开 CLIP 小模型做检索演示，那是可选支线，报告里单独标记，不得和手算实验混成同一条成功率。

和前 20 课的边界再写一次，避免写改造时抢题。[第 02 课](02_multimodal_connector.md) 比较 MLP、Perceiver、Q-Former 三种把 $x$ 送进 Thinker 的接头，假定 $x$ 已经存在。本课回答 $x$ 如何存在，不重做三种接头。[第 08 课](08_dynamic_vision.md) 改分辨率、tile 和 M-RoPE，假定编码器权重冻住。本课不改分辨率。[第 07 课](07_full_duplex_routing.md) 的路由和本课的温度无关：那是话轮动作，这是 logits 缩放。[第 17 课](17_grpo_rlvr.md) 的可验证奖励也不在本课：对比损失的“对错”是对角是不是最大，不是单元测试是否通过。第 22 课才会把冻视觉、训投影、解冻 LLM 写成配方。你现在如果已经想改 Thinker 的解冻开关，先把本课的两个不等式做对。

## 3. 开始前需要准备什么

本课不依赖第 01–20 课的 checkpoint。会写 Python、知道 softmax 和交叉熵即可。开始前在笔记里分开写上游事实和本课约定。

**上游事实（来自已打开的论文页）：**

- CLIP：[Radford et al., arXiv:2103.00020](https://arxiv.org/abs/2103.00020)，数据集 WIT 约 4 亿图文对，从零训练图像塔和文字塔；

- 互动实验和 CPU 实验共用同一张固定 $4\times 4$ 余弦表，对角为正对；

## 4. 完成后应具备的能力

完成后，拿到任意一张图文相似度表，你应能完成以下检查。表可以来自本课夹具，也可以来自你自己用随机向量生成的 $N=8$ 练习，检查项不变：

1. 标出正对、负对，并写出 $N$ 张图对应 $N^2-N$ 个同 batch 负对；
2. 手算一行的 softmax，再写出对称 InfoNCE；
3. 说明把 $\tau$ 从 0.01 调到 0.2 时，正对概率峰值应下降；
4. 写出 sigmoid 损失，并指出它不需要对整行做归一化；
5. 解释 CLIP 把 $\tau$ 初始化为 0.07、并把 logit 乘数上限裁到 100 的含义；
6. 区分“冻图像塔训文字塔”（LiT）和“冻视觉编码器训语言模型”（后续 VLM 配方）；
7. 说明 CLIP 分数高不能推出 VQA 一定强；
8. 在没有 GPU 的机器上独立跑通 CPU 实验，并把 `checks` 全部打成 True；
9. 指出 Qwen3-Omni 视觉塔来自 SigLIP2-So400m、MiniMind-O 冻 SigLIP2，二者都是本课共享空间的下游用法，不是另一种对比损失。

## 5. 原理：边造边讲

下面按同一节奏展开：为什么需要、怎么运转、精确定义、代码落点、怎么证明做对了。5.1 到 5.8 是主干，5.9 到 5.13 是数值、误区和接到 LLM 时的边界，读主干即可做实验，读完全部才能写第 13 节的改造报告。

### 5.1 双塔：为什么不把图画进语言模型

若目标是给每张图写一句完整的话，模型必须生成每个词。CLIP 论文第 2.3 节把这种做法和更简单的词袋预测、再和对比目标放在同一张效率图里比较。一个 6300 万参数的文字 Transformer 已经比它的 ResNet-50 图像塔多用一倍计算，在 ImageNet 零样本上的学习速度仍只有词袋基线的约三分之一；把预测目标换成对比目标，相对词袋再快约 4 倍。图的横轴是处理过的图像数，从 200 万到 4 亿，纵轴是零样本 ImageNet 准确率。三条曲线分开得非常清楚：生成式 Transformer 最慢，词袋居中，对比最快。对比任务不问“这句话的每一个词是什么”，只问“哪一句和这张图是一对”。

效率差来自任务难度，不是来自“对比比较时髦”。网上和一张图一起出现的文字，可能是标题、评论、曝光参数或无关广告。要求模型复述每一个词，等于强迫它学习与像素无关的噪声模板。只要求它在 $N$ 句里认出哪一句属于这张图，噪声模板只要不碰巧和别的图更像，就不会主导梯度。这解释了为什么 ALIGN 敢用几乎不过滤的 alt-text：对比损失天然容忍“句子里有废话”，只要整句还比别的句子更贴这张图。生成式 caption 做不到这一点，所以 CLIP 最终没有把 captioning 当主损失。本课夹具里的四句字没有废话，也没有曝光参数，相当于已经过滤过的理想 caption。它适合学公式，不适合学“噪声有多大还能训起来”。噪声实验属于 SigLIP Figure 7 和 ALIGN 的 18 亿对，不要在 4 对干净句子上声称复现了噪声鲁棒性。

同一节还排除了另一种捷径：给图像塔接 ImageNet 预训练、给文字塔接语言预训练。CLIP 明确从零训练两边，并去掉非线性投影头。LiT 后来证明：如果图像塔已经很强，从零反而是浪费。两条路线不打架，它们的前提不同。CLIP 问的是“只靠图文对能不能从零造出视觉骨干”，LiT 问的是“已有骨干时怎样最省地接上语言”。本课两种都要会讲，实验只实现损失，不实现从零训练。

双塔的结构后果是：两座编码器在训练时不读对方的中间层。图像塔可以是 ResNet 或 ViT（Vision Transformer，把图切成 patch 再做自注意力），文字塔可以是 Transformer。各自经一层线性投影到同一维数 $d_e$，再 L2 归一化。CLIP 明确去掉了 SimCLR 里那种非线性投影头，只保留线性投影，并从零训练，不用 ImageNet 预训练初始化图像塔。

类比：两座塔像两个各自翻译的人，最后只比较译稿在词典空间里靠不靠得近。类比失效处在于：人可以回头问对方“你刚才那个词是什么意思”；标准 CLIP / ALIGN 塔在编码阶段没有这种交叉询问。需要词级对齐或短语定位时，要另加交叉注意力或 grounding 头，那是第 23 课的范围。

双塔还有一个工程后果：检索可以预先把图库全部编成 $x$，查询时只跑文字塔，或反过来。交叉注意力模型必须对每个查询重新看图，延迟随库大小线性涨。ALIGN 把这一点写成他们相对 UNITER、Oscar 这类交叉注意力方法的理由：双塔在 Flickr30K 和 MSCOCO 上仍然刷新了 R@1。本课不复现检索系统，但你要能指出：共享空间一旦造好，图库可以离线建索引。LiT 锁图像塔之后，连训练阶段都可以预计算 $x$，这是同一件事情的训练版。

CLIP 的图像塔有两条产品线。一条从 ResNet-50 出发，按 EfficientNet 的思路把计算量放大到大约 4 倍、16 倍、64 倍，得到 RN50x4、RN50x16、RN50x64；另一条是 ViT-B/32、ViT-B/16、ViT-L/14。八个模型几乎覆盖两个数量级的计算量，论文用它们说明零样本随计算量平滑上升。本课夹具没有模型宽度，谈不上缩放律；写报告时不要把 $4\times 4$ 上的损失差写成“等效于从 RN50 换到 ViT-L”。

验证：任意实现里，图像中间层的通道数可以和文字中间层不同，只有投影后的 $d_e$ 必须一致；输出向量的 L2 范数应接近 1。范数若没归一化，后面的温度会失去统一尺度。ALIGN 的消融还显示嵌入维数从 640 降到 80 时，MSCOCO 零样本从 51.7 掉到 42.0，ImageNet KNN 从 37.5 掉到 29.3。维数是共享空间的宽度，温度是刻度，两者不要混着调。

### 5.2 一张 $N\times N$ 表里发生了什么

取一个 batch $\{(I_i,T_i)\}_{i=1}^{N}$。记归一化后的图像向量为 $x_i$，文字向量为 $y_j$，相似度

$$
s_{ij}=x_i^\top y_j
$$

得到矩阵 $S\in\mathbb{R}^{N\times N}$。对角 $s_{ii}$ 是这对样本自己的图和字。其余格子是“这张图配别人的字”。CLIP 的训练目标就是：在这 $N\times N$ 种可能配对里，认出真正发生过的 $N$ 对。

本课 CPU 实验使用下面这张固定表，数字是教学夹具，不是某篇论文的权重：

|  | 橘猫 | 金毛 | 轿车 | 松树 |
|---|---|---|---|---|
| 猫 | 0.92 | 0.11 | 0.08 | 0.05 |
| 狗 | 0.10 | 0.88 | 0.14 | 0.07 |
| 车 | 0.06 | 0.12 | 0.90 | 0.09 |
| 树 | 0.04 | 0.08 | 0.10 | 0.86 |

每一行的对角都是该行最大项。把文字列循环左移一格之后，对角变成 0.11、0.14、0.09、0.04，不再是行内最大。损失必须能读出这种差别。

这四对不是随便选的。猫和狗共享“动物、四足、宠物”这些粗特征，车和树共享的更少。夹具因此故意把猫–金毛写成 0.11、狗–橘猫写成 0.10，比猫–轿车的 0.08 略高，模拟难负例的弱信号，但差距远小于对角的 0.88–0.92，小温度仍然能分开。若你把猫–金毛改成 0.85，第 5.11 节的难负例讨论才会出现。教学验收矩阵保持现状，改造实验可以另存一张表，不要覆盖 `ALIGNED_SIMILARITY`。

矩阵的单位是余弦，不是概率，也不是像素差。0.92 表示两个长度为 1 的向量夹角很小，不表示“92% 的把握是猫”。把余弦抄进准确率栏，是另一类单位错误。温度把余弦变成 logits，softmax 才把 logits 变成概率。三行管道：余弦表、除以 $\tau$、softmax。互动实验的格子上同时写 $s$ 和揭晓后的 $p$，就是为了强迫你看见单位换了。

ALIGN 把同一张表写成两个方向的分类：图找字，和字找图。温度在他们的记号里是 $\sigma$，出现在指数的分母上，和 CLIP 的 $\tau$ 是同一类缩放。

验证：打印 $S$ 的对角均值和每行 argmax。对齐夹具的 argmax 必须全在对角；打乱夹具不得全在对角。

### 5.3 InfoNCE：把配对写成分类

给定一行相似度，除以温度再做 softmax，第 $i$ 张图把第 $i$ 句字认成“正确答案”的概率是

$$
p_{\mathrm{i2t}}(i)=\frac{\exp(s_{ii}/\tau)}{\sum_{j=1}^{N}\exp(s_{ij}/\tau)}
$$

图像到文字的损失是这些概率的交叉熵：

$$
\mathcal{L}_{\mathrm{i2t}}=-\frac{1}{N}\sum_{i=1}^{N}\log p_{\mathrm{i2t}}(i)
$$

文字到图像把矩阵按列归一化：

$$
\mathcal{L}_{\mathrm{t2i}}=-\frac{1}{N}\sum_{i=1}^{N}\log\frac{\exp(s_{ii}/\tau)}{\sum_{j=1}^{N}\exp(s_{ji}/\tau)}
$$

CLIP 取对称平均

$$
\mathcal{L}=\frac{1}{2}(\mathcal{L}_{\mathrm{i2t}}+\mathcal{L}_{\mathrm{t2i}})
$$

论文把这一构造回溯到多类 N-pair 损失和 Oord 等人的 InfoNCE，并写明自己采用的是 ConVIRT 的简化版：从零训练、线性投影、只有随机裁剪一种增强。伪代码里 logits 写成 $I_e Y_e^\top \cdot \exp(t)$，再对行、列分别做交叉熵。这里的 $\exp(t)$ 是可学习的 logit 乘数，等价于 $1/\tau$。

softmax 对一行里同时加一个常数不变。因此把整张 $S$ 加上 0.3，InfoNCE 不变。这不是 trivia：它说明 InfoNCE 只关心一行里谁相对更大，不关心相似度的绝对零点。后面的 sigmoid 损失没有这个性质。

验证：CPU 实验检查 $\mathcal{L}$ 等于两个方向的平均，检查行 softmax 之和为 1，检查 $S$ 与 $S+0.3$ 的 InfoNCE 在 $10^{-10}$ 内一致。

下面把第一行在 $\tau=0.2$ 时完整算一遍，后面互动实验的数字必须能对上这一行。第一行相似度是 $0.92,0.11,0.08,0.05$，除以 $0.2$ 得到 $4.60,0.55,0.40,0.25$。减掉行内最大项 $4.60$ 之后，指数自变量变成 $0,-4.05,-4.20,-4.35$。对应的 $e$ 次方约为 $1$、$0.0174$、$0.0150$、$0.0129$，分母约 $1.0453$，正对概率约 $0.9566$。交叉熵是 $-\log 0.9566\approx 0.0443$。另外三行用同样手续，再对列做一遍，最后两个方向平均，就得到整张表在 $\tau=0.2$ 下的 InfoNCE，约 $0.0534$。$\tau=0.07$ 时同一行的 $s/\tau$ 变成约 $13.14,1.57,1.14,0.71$，减最大值后负指数小于 $-11$，正对概率已经是 $0.99998$ 量级，整表损失掉到 $3.5\times 10^{-5}$。$\tau=0.01$ 时正对概率在双精度下就是 $1$，损失记成 $0$。这三档温度会出现在 CPU 实验的 `metrics` 里，允许你对着手算。

打乱后第一行变成 $0.11,0.08,0.05,0.92$：原来的“猫–橘猫”被挪到最后一列，对角位置只剩 $0.11$。$\tau=0.07$ 时对角项不再是行内最大，softmax 把质量分给了错误的那一格，单行交叉熵会到 $10$ 以上，整表 InfoNCE 约 $11.36$。你不需要背这些小数，但必须能从矩阵重新算出它们。若你的实现和这些数对不上，先查三件事：有没有对行和列各做一次；有没有先减最大值再 $\exp$；打乱是不是改列而不是改行。

### 5.4 温度：从几乎 one-hot 到分不开

$\tau$ 越小，$s/\tau$ 的差距被放大，softmax 越尖。本课夹具在 $\tau=0.01$ 时，四行正对概率在双精度下都会变成 1，InfoNCE 掉到数值零附近。$\tau=0.2$ 时，正对概率峰值降到约 0.957。互动实验的验收写的就是这件事：温度从 0.01 调到 0.2，峰值必须下降。

CLIP 第 2.4 节：$\tau$ 初始化为 Wu et al. (2018) 的 0.07，并以对数参数化直接学习；同时把 logit 乘数裁剪到不超过 100，以避免训练发散。乘数上限 100 对应 $\tau$ 下限 0.01。本课把互动滑条的左端设在 0.01，不是随意选的。

ALIGN 的消融（他们的 Table 8，图像塔 EfficientNet-B5，文字塔 BERT-Base）更具体：可学习温度会收敛到大约 $1/64$；固定 $\sigma=1/64$ 或 $1/128$ 时 MSCOCO 零样本检索 52.2，略好于可学习的 51.7；固定 $\sigma=1/32$ 则掉到 39.6，ImageNet KNN 从 37.5 掉到 26.9。温度不是装饰系数，选错会让正负对挤在一起。

$\tau$ 过小的代价：几乎 one-hot 之后，梯度只打在当前这一对和极少数难负例上，数值也容易溢出。CLIP 才要裁剪乘数。$\tau$ 过大的代价：概率接近均匀，$1/N$，损失接近 $\log N$，模型分不清谁配谁。

验证：同一张对齐表，记录 $\tau\in\{0.01,0.07,0.2\}$ 的正对峰值，序列必须严格递减。

温度还有一个常被忽略的耦合：相似度本身已经被 L2 归一化限制在 $[-1,1]$。没有温度时，余弦 $0.92$ 和 $0.11$ 的指数比是 $e^{0.81}\approx 2.25$，分得不够开。除以 $0.07$ 之后变成 $e^{11.57}$，正对相对负对的优势被放大到成千上万倍。这就是为什么 CLIP 要把 $\tau$ 学成一个标量，而不是指望编码器自己把向量拉到很大的范数：范数已经被钉死，温度是唯一还剩的全局刻度。ALIGN 写明温度“通常在前 10 万步很快降到收敛值的约 1.2 倍，然后慢慢靠拢”，说明刻度会在训练早期被很快拧紧。你在 $4\times 4$ 上把 $\tau$ 从 0.2 拧到 0.01，就是在模拟这个拧紧过程的两端。

### 5.5 负样本来自同 batch

CLIP 把每个 batch 看成一个有 $N$ 个类、每类一张图的临时数据集，类名就是那 $N$ 句字。$N=32768$ 时，一次更新里每张图要在三万多个句子里找出自己的那句。负样本的难度和多样性都由 batch 组成决定。

ALIGN 在同一节消融里写：只用 batch 内 50% 的负例，MSCOCO 零样本从 51.7 降到 50.2；只用 25%，降到 48.7。负例不是越多越好到无穷，但少给会改变任务。

SigLIP 把这件事说得更极端。他们的 Figure 2：batch 小于 16k 时，sigmoid 明显优于 softmax；两边都大约在 32k 饱和；他们甚至把 SigLiT 的 batch 推到 100 万，收益很快变薄。摘要写：“a more reasonable batch size of 32k being sufficient”。大 batch 的好处有上限，小 batch 的 InfoNCE 则真的缺负例。

还有一个被默认掉的假设：同 batch 里 $i\neq j$ 的图和字“无关”。网上数据里两张图都是橘猫、两句字几乎同义，并不罕见。这时对角以外的格子其实是假负例（false negative）。InfoNCE 仍会推开它们。数据越吵，假负例越多。这是后文 sigmoid 和偏置项要处理的背景之一。

验证：在 $4\times 4$ 夹具上把文字循环移位，等于故意制造 4 个假正对。对齐 InfoNCE（$\tau=0.07$）约 $3.5\times 10^{-5}$，打乱后升到约 11.36。验收句是：打乱后损失不得低于对齐时。

### 5.6 推理：文字塔变成分类头

训练结束之后，不再需要 $N\times N$ 的训练矩阵。下游若是 ImageNet，就把 1000 个类名（或提示模板）送进文字塔，得到 1000 个向量，和一张图的 $x$ 比余弦，再经 $\tau$ 与 softmax 变成类别分布。CLIP 把文字塔解释成超网络（hypernetwork：一个网络给另一个分类器生成权重）：图像塔提特征，文字塔根据“这类长什么样”的句子写出线性分类器的权重。

提示词有可测的贡献。CLIP 用默认模板 “A photo of a {label}” 比直接嵌入类名提高 ImageNet 1.3 个百分点；再对 80 个上下文模板做嵌入空间平均，额外提高 3.5 个百分点；两项合计约 5 个百分点。ALIGN 复用同一套模板集成，并写明集成带来 2.9 个百分点。这些数字测的是提示协议，不是模型“突然更会看图”。

CLIP 最佳模型的 ImageNet 零样本 top-1 是 76.2%，没有使用该数据集 128 万张训练图；论文说这匹配了当年原始 ResNet-50 的水平。ALIGN 的零样本 ImageNet 是 76.4%。把视觉塔冻住只训分类头时，ALIGN 到 85.5%，全量微调到 88.64%。同一套向量，用法不同，数字不同，不要混抄。

验证：零样本协议必须冻结图像塔和文字塔，只改类名文本。若偷偷在 ImageNet 训练集上微调分类头，报告必须改称线性探测或微调，不得再写 zero-shot。

CLIP 把预训练的每一步也解释成零样本：当前 batch 的 32768 句字就是 32768 个临时类名，每类一张图。测试时只是把临时类名换成数据集的类名。这个观点有用，也有边界。有用的是：你不必另训一个分类头，文字塔已经会把任意句子变成权重。边界是：训练时每个“类”只有一张正例，而且负类是随机撞进 batch 的句子，不是 ImageNet 的 999 个互斥类。所以零样本能工作，并不表示训练目标已经是 ImageNet 分类。类名里的词义冲突（ImageNet 里既有起重机 crane 又有鹤 crane）要靠提示词补上下文，单靠预训练不一定消歧。

提示词集成在嵌入空间平均，而不是在概率空间平均。CLIP 写明这一点是为了缓存：80 个模板先各自编码，再平均成一个向量并重新 L2 归一化，推理成本与单模板相同。ALIGN 复用同一套模板，报告 ImageNet 提升 2.9 个百分点。若有人在本课夹具上对 4 句字做“模板集成”，那是把教学矩阵用坏了：夹具没有模板，句向量已经给定。

共享空间还允许图和字做向量算术。ALIGN 第 7 节用图像向量加减文字向量再检索：熊猫图加“澳大利亚”或减颜色词，检索结果会朝对应方向偏。他们发现文字向量乘 2、图像向量乘 1 的效果较好，1:1 也可以。这是共享空间的存在性演示，不是可复现的精度指标，本课不把它写进验收。你只需要知道：能加减，是因为两边已经被拉到同一套坐标；不能加减，往往是没做 L2 归一化，或者图、字用了不同的温度。

### 5.7 SigLIP：不再对整行做 softmax

InfoNCE 的分母要看见这一行所有 $s_{ij}$。分布式训练里，这通常意味着 all-gather 全部向量，并物化一张 $|B|\times|B|$ 的表。SigLIP 把问题改写成对所有配对做二分类：正对标签 $z_{ij}=+1$，负对 $z_{ij}=-1$。论文公式（第 3.2 节）为

$$
\mathcal{L}=-\frac{1}{|B|}\sum_{i=1}^{|B|}\sum_{j=1}^{|B|}\log\frac{1}{1+\exp\bigl(z_{ij}(-t\,x_i\cdot y_j+b)\bigr)}
$$

Algorithm 1 写成可执行的形式：$\mathrm{logits}=t\cdot S+b$，再对 $z_{ij}\cdot\mathrm{logits}_{ij}$ 取 $-\log\sigma$，最后除以 $n$。$b$ 的符号在公式和伪代码里差一个约定；本课实现以 Algorithm 1 为准，并采用论文写明的初始化：$t'=\log 10$（故 $t=10$），$b=-10$。这样在余弦接近 1 的正对上，初始 logit 约为 0；在余弦接近 0 的负对上，初始 logit 约为 $-10$，训练不必先花很多步去纠正“负例远多于正例”的偏置。

因为每一项只依赖一对 $(x_i,y_j)$，损失不再需要全局归一化。设备之间可以一块一块交换文字向量，任何时刻只需物化一块小方阵。论文用三台设备、全局 batch 12 的示意图说明：没有 all-gather，亮着的黄块始终是 $4\times 4$。

效果数字只引用摘要和表 1、表 3 里能对上的句子：

- 结合 LiT，4 块 TPUv4 两天训出的 SigLiT，ImageNet 零样本 84.5%（摘要与表 1 一致）。同一设定下，冻住公开 B/8 图像塔、训一天，摘要写 79.7%，表 1 写 79.8。引用时写来源，不要合并成一个数。
- 从零训的 SigLIP B/16，32 块 TPUv4 五天，表 1 为 73.4%。解冻公开 B/16 图像塔、16 块 TPUv4、batch 16k、三天，表 1 为 71.0%；同一设定把 weight decay 从预训练权重上拿掉后，正文写到 71%。从零、32 块、两天、batch 32k 为 72.1%。
- 表 3 里，公开对比：CLIP ViT-B 的 ImageNet 验证 68.3，同体量 SigLIP 为 76.2；Shape-Optimized 4 亿参数的 SigLIP 为 83.2，ObjectNet 82.9，COCO 文到图 R@1 为 52.0。
- 内存：四块 TPU-v4 上，Base SigLIP 能放下 batch 4096，对应 CLIP 模型只能放下 2048。这是“不必物化全矩阵、不必二次扫描最大值”的直接后果。
- 多语言 mSigLIP 把 WebLI 的 100 种语言都留下，看过 300 亿对。作者原以为更大 batch 能在同一 batch 里碰到更多同语言负例，结果 batch 超过 32k 之后，XM3600 三十六语言检索的平均分反而下降，ImageNet 零样本持平。表 2 里 batch 16k 到 240k，ImageNet 零样本在 71.6 到 73.2 之间波动，XM 平均从 34.8 掉到 32.7。32k 够用这条结论，在多语言设定里同样成立，而且更大并不总是更好。

sigmoid 对噪声的实验（Figure 7）用 M 规模模型、batch 16384、看过 36 亿对，分别按概率 $p$ 破坏图像、文字、batch 对齐。随着 $p$ 上升，sigmoid 仍然压着对应的 softmax 基线。本课的打乱相当于 $p=1$ 的 batch 对齐破坏，是这条曲线的最右端：两种损失都应变差，sigmoid 不必在 $N=4$ 上再去证明“更鲁棒”，那是论文规模的结果。

把整张 $S$ 加 0.3，sigmoid 损失会变，因为 $tS+b$ 的绝对位置变了。CPU 实验把这条和 InfoNCE 的平移不变对照，用来区分“行内相对比较”和“逐格打分”。

验证：打乱后 sigmoid 损失同样不得低于对齐时；给 $S$ 加常数，sigmoid 必须变，InfoNCE 必须几乎不变。

sigmoid 还有两个论文里写明、本课只做定性对照的性质。第一，正负例极度不平衡：batch 16k 时正对 16k、负对约 2.68 亿。作者用 mask 负例的方式把比例从 $1:16\mathrm{k}$ 调到接近 $1:1.6$，随机丢掉负例会掉点，丢掉容易的负例几乎毁掉训练，留下最难的负例则几乎保住质量。结论是：不平衡本身不是灾难，难负例才是学习信号。本课 $4\times 4$ 只有 4 个正对、12 个负对，比例已经接近“平衡”，不能用来复现 2.68 亿那个设定。第二，标签噪声。他们在图像、文字、batch 对齐上按概率 $p$ 做破坏，sigmoid 在各种破坏下仍优于对应的 softmax 基线。网上 alt-text 经常文不对题，这条性质解释了为什么 ALIGN 那种几乎不过滤的数据仍然能训起来。本课打乱是 $p=1$ 的 batch 对齐破坏：全部对角都错。损失必须上升，否则实现没有在对角上放正标签。

分块实现（论文 Figure 1）把全局 $N\times N$ 拆成设备本地的 $b\times b$ 黄块，$b=N/D$。设备先算自己的正对和本地负对，再轮换文字向量，把别的设备上的字当成新的负对累加进去。最终每个图像都和全部文字见过面，但显存峰值是 $b^2$ 而不是 $N^2$。InfoNCE 的稳定 softmax 往往还要多一次全 batch 的最大值扫描。教学上你只要记住：sigmoid 的“看见全部负对”可以分多次加起来，每次只依赖当前这块；InfoNCE 的归一化常数必须等全部格子到齐（或等价地做全局 log-sum-exp）。$N=4$、$D=1$ 时两种实现退化成同一张表，差异只在公式。

### 5.8 LiT：锁住图像塔，不是锁住语言模型

对比预训练同时在做两件事：学一套好的图像描述，以及学一套能读懂这套描述的文字描述。LiT 的判断是：图文对适合学对应关系，但不一定干净到能训出最强图像描述子。更干净的图像预训练（监督的 JFT / ImageNet-21k，或自监督）已经给出很强的 $x$。于是他们把图像塔锁住，只训练文字塔去读这些 $x$。

论文用两个字母标记设计。L：锁住并从预训练初始化；U：可训练且从预训练初始化；u：可训练且随机初始化。记号 Lu 就是 Locked-image Tuning。系统消融（YFCC100m-CLIP 上按不同步数各跑完全程）显示：锁图像塔几乎总是最好；用预训练图像塔全面有帮助；预训练文字塔只有很小增益；锁文字塔效果不好。

这和第 22 课将讲的“冻视觉、训投影和 LLM”方向相反。MiniMind-O 冻 SigLIP2、训 Thinker，属于后一种：视觉空间已经造好，语言模型来读它。LiT 属于前一种：视觉空间已经造好，文字塔来迁就它。两者都“冻图像”，冻完之后动的模块不是同一个。

LiT 用预训练 ViT-g/14 时，ImageNet 零样本 85.2%，ObjectNet 82.5%，论文写后者比当时此前最好结果高 10.2 个百分点。公开数据设定下的 PublicLiT，ImageNet 零样本 75.7%。同一张表里 CLIP 为 76.2%，ALIGN 为 76.4%。锁塔还能省图像侧梯度，并在无增强时预计算图像向量。这些是实现优势，不是把 LLM 冻住的借口。

验证：若有人在报告里写“LiT 冻 LLM 只训视觉”，判定为术语错误。正确检查项是：图像塔 `requires_grad=False`，文字塔有梯度。

锁图像塔时，对比损失在 LiT 所用的图文数据上往往更差，因为图像向量不能再挪位置去迁就噪声 caption。论文把这解释成优点：干净的图像描述子被保住了，文字塔负责去读它。下游零样本分类用的正是这些被保住的图像向量。若在噪声图文对上把图像塔一起微调，图像描述子会被网上的假标签拉歪，ImageNet 上的线性探测（论文用 10-shot 和全量微调作对照）会掉。所以“训练损失更低”在这里不是选方案的充分统计量。本课 CPU 夹具锁不住塔，因为没有可训练参数；互动实验也不更新权重。锁塔只能在第 13 节的改造 4 里用两层线性玩具验证梯度是否为 0。

### 5.9 形状、数值稳定和假梯度

把机制落到代码时，出错几乎都在形状和数值，而不在“有没有做对比”这句话上。

形状。图像编码输出必须是 `[N, d_e]`，文字同样 `[N, d_e]`，相似度 `[N, N]`。若某一步忘了 squeeze 空间维，图像变成 `[N, 1, d_e]`，广播后会对错误的轴做点积，对角不再对应同一条样本。label 必须是 `arange(N)`，不能是全 0，也不能是 one-hot 之后又对错的维做交叉熵。SigLIP 的标签矩阵是 $2I-1$：对角 $+1$，其余 $-1$，和 InfoNCE 的类别下标不是同一种东西。

数值稳定。`exp(s/τ)` 在 $\tau=0.01$、$s=0.92$ 时是 $e^{92}$，直接计算会 inf。标准写法是先减行内最大再 exp，即 log-sum-exp。CLIP 的乘数裁剪（不超过 100）是另一道闸：即使学出来的温度想把刻度拧得更紧，logits 也不会再放大。本课夹具在 $\tau=0.01$ 已经到达这道闸对应的刻度。若你的 CPU 实现在这一档出现 NaN，先改成减最大值，不要先改矩阵。

sigmoid 的稳定写法同样要按正负自变量分支：`log_sigmoid(x)` 在 $x\ge 0$ 时用 $-\log(1+e^{-x})$，在 $x<0$ 时用 $x-\log(1+e^{x})$，避免 `exp(x)` 爆炸。Algorithm 1 的 `log_sigmoid(labels * logits)` 正对大约在 0 附近，负对大约在 $-10$ 附近，两种分支都会用到。

假梯度。把温度写成 Python 的 `float` 而不是叶子张量，温度不会更新，这和 CLIP 的设定不符，但本课手算不更新参数，允许。真正的假梯度是：对 softmax 分母用了 `detach`，或者在分布式里只对本地 $n\times n$ 块算损失却把全局 batch 写成 $N$。ALIGN 和 CLIP 都强调跨设备拼接后再做归一化。LiT 附录也确认全局损失优于每卡独立再累加。本课 $N=4$ 没有设备边界，但报告里必须写清楚：论文的 $N$ 是全局 batch。

验证：CPU 实验里 `softmax_row_sum_error` 必须小于 $10^{-12}$；`infonce_is_mean_of_both_directions` 必须为真。这两条不过，后面的打乱对照没有意义。

### 5.10 零样本高分推不出看图问答强

本课最容易被带偏的句子是：“CLIP 都 76.2% 了，接上 LLM 一定更会答题。” 76.2% 测的是：用类名文本当 1000 个权重，看图像向量离哪个类名近。VQA 测的是：看见图里的物体、文字、数量和空间关系，再用语言模型组织一句答案。两件事共享同一座图像塔，不共享同一份损失。

对比预训练几乎不监督“左边是谁”“有几个”“图里有没有这个物体”。负对是别的句子，不是“物体不存在”。模型可以把“一只猫”和猫图拉得很近，同时答不出“猫在沙发左边还是右边”。第 23 课会用指代、OCR 和存在性探针拆开这些能力。本课只要你在报告里把检索 / 零样本分类 / VQA 分成三栏，禁止用第一栏的数字填第三栏。

另一个方向的误解是：batch 太小“只是收敛慢”。InfoNCE 的类别数等于 batch 大小。$N=4$ 时每张图在 4 个句子里做选择题；$N=32768$ 时在三万多个句子里做。负例的语义覆盖、难度、假负例比例全部随 $N$ 变。SigLIP 之所以在小 batch 上更稳，正是因为它不把任务定义绑死在“这 $N$ 个里选 1 个”。你用 $N=4$ 的夹具验证公式，不能用它估计 $N=32768$ 的准确率。

CLIP 自己的扩展实验也反对“一个分数概括一切”。他们按计算量训了 8 个模型，观察零样本随计算量平滑上升，而不是某一次结构改动突然把所有任务抬起来。花卉、飞机这类细粒度任务甚至会输给在 ResNet-50 特征上训的线性分类器。共享空间是一张通用地图，不是每一条街道都画得同样细。

### 5.11 难负例：猫和狗怎样互相抢概率

夹具里“猫”对“金毛”的相似度是 0.11，对“橘猫”是 0.92，差距足够大，小温度会把概率全部堆到对角。真实 batch 里经常出现两张都是动物、两句都含“dog”的样本。把第一行改成 $[0.84,0.79,0.08,0.05]$ 模拟这件事：正对仍是最大，但第二名只差 0.05。$\tau=0.2$ 时 $s/\tau$ 为 $4.20,3.95,0.40,0.25$，减最大值后指数约 $1,0.779,0.022,0.019$，正对概率大约只有 $0.55$。交叉熵从原来的 $0.044$ 升到约 $0.60$。$\tau=0.07$ 时差距被放大，$s/\tau$ 约 $12.00,11.29$，正对概率回到 $0.67$ 以上，仍然远不到 one-hot。难负例让温度的作用从“锦上添花”变成“能不能把 0.05 的余弦差拉开”。

InfoNCE 会把 0.79 那一格当错误类狠推。如果那一格其实也是一只猫的合法描述，这就是假负例。sigmoid 同样会把这一格当负对，但因为没有行内归一化，它不会为了把正对抬到 1 而必须把 0.79 压到 0。难负例上两种损失的梯度方向仍然都是“拉开”，强度不同。本课夹具不把 0.84/0.79 写进 CPU 实验，以免和固定验收矩阵冲突。你若自己改矩阵做改造 1，应同时记录“易负例版”和“难负例版”的损失差：易负例上打乱和对齐的差距极大，难负例上差距会缩小。差距缩小不是 bug，说明任务变难了。

列方向同样有难负例。第一列是所有图对“橘猫”这句字的相似度：$0.92,0.10,0.06,0.04$。狗图对橘猫只有 0.10，字到图这一向很轻松。若把狗图对橘猫改成 0.80，文字塔就必须在“橘猫”这句上把猫图和狗图分开。对称 InfoNCE 正是为了让两个方向都干活：只做图到字，文字塔可以偷懒输出几乎相同的向量；只做字到图，图像塔可以偷懒。CLIP 和 ALIGN 都写了双向。SigLIP 的双重循环 $i,j$ 覆盖了全部有序对，正对出现一次，不需要再写两则 softmax。

### 5.12 共享空间怎样接到语言模型

对比训练结束时，你手里有两座塔。零样本分类把文字塔留下来当分类头。视觉语言模型通常把文字塔丢掉，只留图像塔，再加一个投影，把 $x$ 或 patch 序列送到 LLM 的词嵌入维。MiniMind-O 走后一条路：SigLIP2 冻住，Thinker 是因果语言模型，损失是 next-token 交叉熵，不再出现 $N\times N$ 的 InfoNCE。本课的温度、batch 负例、sigmoid 偏置，全部停在“造 $x$”的阶段。接到 LLM 之后，新的失败模式是投影没训好、视觉 token 太多、LLM 遗忘文本，那些是第 22 课的账。

为什么可以丢掉文字塔？因为图像塔已经被文字监督过， $x$ 里已经编码了“能被句子区分的概念”。若图像塔只在 ImageNet 1000 类上训过， $x$ 会擅长那 1000 个名词，不擅长 OCR、动作和开放描述。CLIP 的引言把 OCR、视频动作、地理定位列为零样本能非平凡迁移的任务，依据是 30 多个数据集，不是某一个展示图。ALIGN 用 EfficientNet-L2 在 VTAB 19 个任务上平均 $79.99\pm 0.15$，其中 natural / specialized / structured 三个子组分别是 83.38、87.56、73.25，高于他们列出的 BiT-L 的 78.72。细粒度上 Oxford Flowers 99.65、Pets 96.19、Cars 96.13、Food101 95.88（全量微调设定）。这些数字说的是“图像塔本身能当通用视觉骨干”，支持后面把它冻住接到 LLM。它们仍然不是 Omni 对话分数。

丢掉文字塔也有代价。零样本时，新类只要会写名字就能加入。接到 LLM 之后，新视觉概念要靠指令数据和投影层重新学，不能只改一个类名字符串。这是两条产品线：检索 / 零样本分类保留双塔；对话 / VQA 通常只留图像塔。本课两种都讲，验收只要求你分得清。

### 5.13 公式和超参速查

把本课会用到的式子收在一页，避免翻来翻去抄错轴。所有向量都默认已经 L2 归一化，$s_{ij}=x_i^\top y_j\in[-1,1]$。

对称 InfoNCE（CLIP / ALIGN 的形式）：

$$
\mathcal{L}=\frac{1}{2N}\sum_{i=1}^{N}\left[
-\log\frac{e^{s_{ii}/\tau}}{\sum_j e^{s_{ij}/\tau}}
-\log\frac{e^{s_{ii}/\tau}}{\sum_j e^{s_{ji}/\tau}}
\right]
$$

CLIP 实现里乘数是 $\exp(t)$，对应 $1/\tau$。初值 $0.07$，乘数上限 $100$。ALIGN 把 $\tau$ 写成 $\sigma$，初值 $1.0$，消融里收敛到约 $1/64$。

SigLIP 的 Algorithm 1：

$$
\mathrm{logit}_{ij}=t s_{ij}+b,\qquad
z_{ij}=2\cdot\mathbf{1}_{i=j}-1,\qquad
\mathcal{L}=-\frac{1}{N}\sum_{i,j}\log\sigma(z_{ij}\,\mathrm{logit}_{ij})
$$

默认 $t=10$，$b=-10$。求和后除以 $N$，不要除以 $N^2$。

本课夹具验收不等式，必须同时成立：

$$
\mathcal{L}_{\mathrm{InfoNCE}}(S_{\mathrm{shuf}},0.07)
\ge
\mathcal{L}_{\mathrm{InfoNCE}}(S,0.07)
$$

$$
\max_i p_{\mathrm{i2t}}(i;S,0.01)
>
\max_i p_{\mathrm{i2t}}(i;S,0.20)
$$

sigmoid 损失在同一置换下也不得下降。InfoNCE 对 $S+c$ 不变，sigmoid 会变。四条全部写进 CPU 实验的 `checks`。

若你只记住一句话，记住这个：对角是正对，温度管尖度，softmax 看整行，sigmoid 看每一格，LiT 锁的是图像。

把同一套式子翻译成伪代码时，轴不要反。`logits[i, j]` 的第一个下标必须是图像，第二个必须是文字，和矩阵可视化的“行是图、列是字”一致。交叉熵的 `axis=1` 沿文字方向归一化，对应图到字；`axis=0` 沿图像方向归一化，对应字到图。谁和谁配对，看 `labels[i]=i`。SigLIP 没有 `labels[i]=i` 这种类别下标，它用整张 $2I-1$。把 InfoNCE 的 `arange` 拿去乘 sigmoid 的 logit，形状能跑通，梯度是错的。

温度写在哪也要固定。CLIP 伪代码把 $\exp(t)$ 乘在整张 logits 上，再进交叉熵。ALIGN 把 $\sigma$ 放在指数分母。两者等价于 $s/\tau$，差一个“$\tau$ 是除数还是乘数的倒数”的命名。本课互动滑条按除数 $\tau$ 来，左端 0.01 对应 CLIP 的乘数上限 100。不要在同一份笔记里一会儿写 $\tau=0.07$，一会儿写 $\mathrm{logit\_scale}=14.3$，却不标明它们互为倒数。

## 6. 在公开实现中定位这些机制

本课没有 MiniMind-O 源码可改。对照落点以论文伪代码和公开仓库为准。

CLIP 论文第 2.4 节的伪代码是最稳的实现说明：`image_encoder` / `text_encoder` 取出 $I_f$、$T_f$；乘上 $W_i$、$W_t$ 后按行 L2 归一化；`logits = I_e @ T_e.T * exp(t)`；`labels = arange(n)`；对 axis 0 和 axis 1 各做一次交叉熵再平均。官方推理仓库由论文指向 [https://github.com/OpenAI/CLIP](https://github.com/OpenAI/CLIP)。读推理代码时只核对：编码、归一化、余弦、温度，不要把预处理 resize 差异写成“对比损失不同”。

ALIGN 的公式在论文 (1)(2) 两式，记号是 $x_i^\top y_j/\sigma$，两向损失相加。图像塔 EfficientNet（全局池化，不训分类头里的 $1\times 1$），文字塔 BERT 的 `[CLS]`，上面再接线性层对齐维数。有效 batch 16384：1024 块 Cloud TPUv3，每核 16 个正对，跨核拼接向量后再算 softmax。

SigLIP 与 LiT 的训练代码在 Google 的 `big_vision` 仓库。论文 Algorithm 1 的 11 行已经足够手写一个 NumPy / PyTorch 对照。注意除以 $n$ 而不是 $n^2$，否则和论文损失尺度差一个 batch 因子。

MiniMind-O 侧只需要记住：[第 01 课](01_baseline_reproduction.md) 的冻结视觉模块、[第 02 课](02_multimodal_connector.md) 的投影、[第 08 课](08_dynamic_vision.md) 的 256×256 / 64 patch，用的都是已经训完的共享空间。本课不打开那些训练脚本。

读 MiniMind-O 时容易产生两个错觉。第一，以为 SigLIP2 输出的 64 个 patch 向量已经是“词”。它们仍是视觉塔的空间特征，要经过 projector 才能和 Thinker 的词嵌入相加或拼接。共享空间解决的是“视觉向量和文字向量可以比余弦”，并不自动等于“视觉向量已经是语言模型词表里的 token”。第二，以为对比预训练的温度还会出现在 Omni 推理里。MiniMind-O 问答走的是 next-token 交叉熵，不再把类名送进文字塔做零样本分类。对比温度留在视觉塔的预训练阶段；推理路径换了损失，温度不会以 CLIP 的形式再出现一次。第 08 课改分辨率时动的是 patch 网格和位置编码，不动 InfoNCE。

若去读 OpenCLIP 一类社区实现，损失文件名通常带 `ClipLoss`，内部仍是对称交叉熵；SigLIP 变体把矩阵换成逐元 `logsigmoid`。对照时抓住三件事即可：向量是否 L2 归一化、正对是否在对角、分母是行/列 softmax 还是逐格 sigmoid。文件名和类名会变，这三件事不会变。

建议你自己写三个不超过十行的断言，放在笔记里，不提交进 MiniMind-O 仓库：

1. 随机生成 `[4, 16]` 的图像和文字向量，L2 归一化后 $S=XY^\top$，对角加 0.5 再裁剪到 1，InfoNCE 必须低于未加对角之前。这检查正对是否真的在被拉近。
2. 把 $S$ 的列按 `SHUFFLE_PERM` 置换，InfoNCE 和 sigmoid 都必须上升。这检查正对是否被写死在对角。
3. 把温度从 0.05 改到 0.2，正对 softmax 峰值必须下降。这检查 $\tau$ 是除数。

三条都能过，才去动公开权重。公开权重的预处理均值、缩放、裁剪和本课夹具无关；夹具过了、推理仍错，问题在 processor，不在损失。SigLIP 论文自己也把模型和 demo 放到 `big_vision` 的 Colab，那是看检索的地方，不是改公式的地方。

## 7. 数据与训练 recipe

对比学习的数据不是“越好越干净越好”一件事，而是规模、噪声和过滤代价的交换。

CLIP 先说明现成数据不够：MS-COCO 与 Visual Genome 大约各 10 万训练图；YFCC100M 有 1 亿，但很多条目的“标题”其实是 `20160716_113957.JPG` 这种文件名，或曝光参数。滤成英文自然语言标题或描述之后只剩约 1500 万，和 ImageNet 同量级。他们另建 WIT（WebImageText）：从公开网页收集 4 亿对。查询词表以英文维基百科中至少出现 100 次的词为底，再加高 PMI 的双词和有检索量的维基标题，合计约 50 万查询；每个查询最多保留 2 万对，做粗略的类别平衡。论文写 WIT 的总词数和 GPT-2 的 WebText 相当。

50 万查询乘 2 万上限是 100 亿，实际只收到 4 亿，说明大量查询远远拿不满。长尾概念仍然稀缺，头部概念被截断。零样本在常见物体上更稳、在冷门飞机型号上更弱，和这套抽样一致。你不能从 “4 亿对” 推出“所有视觉概念都见过足够次数”。LiT 后来用公开的 YFCC100m-CLIP（约 1500 万）加 CC12M（他们实际用到约 1000 万，因为链接失效）做 PublicLiT，ImageNet 零样本 75.7%，已经接近 CLIP 的 76.2%，说明在锁住强图像塔之后，公开量级的图文对也够把文字塔读出来。私有大数据把同一路线推到 85.2%，差距写在数据与图像预训练上，不写在损失公式上。

ALIGN 走相反的过滤策略。他们按 Conceptual Captions 的流程拿原始英文 alt-text，但去掉大部分清洗，只留基于频率的规则：去掉短边小于 200 像素或宽高比大于 3 的图；一张图对应超过 1000 条 alt-text 则丢弃；去掉被超过 10 张图共享的 alt-text（例如分辨率字符串）；丢掉含稀有 token 的句子，以及少于 3 个或多于 20 个 unigram 的文本。结果是约 18 亿对，噪声明显更大。论文点名丢掉的文本包括 “1920x1080”、“alt_img”、“cristina” 这种和像素内容无关的串，以及 “image_tid 25&id ...” 这种查询参数。他们的 Figure 2 还标出一条明显文不对图的斜体样本，用来提醒读者：训练集里确实有错配。Table 10 写：同样 300 万规模时 ALIGN 数据远差于清洗过的 CC-3M；放到 4 倍大小，噪声数据反而超过 CC-3M。规模在这里补偿噪声。

过滤规则会改变负例的语义。若不过滤共享 alt-text，很多图会配上同一句 “click to enlarge”，对角变成同一句字配很多图，InfoNCE 的“类”塌缩。若不过滤过短文本，单字 “image” 会成为万能正对，也是万能负对，梯度接近随机。本课夹具的四句字互不相同且都长于一个词，就是为了避开这种退化。你构造自己的 4 对数据时，四句字不能是同一个模板填不同数字，否则打乱和对齐的差距会人为变小。

训练超参只抄论文写明的部分。CLIP：32 个 epoch；Adam，解耦 weight decay 不作用于 gain 和 bias；余弦学习率；batch 32768；混合精度；$\tau$ 初值 0.07 并裁剪乘数。图像增强只有随机方形裁剪。模型序列是 5 个 ResNet（RN50、RN101、RN50x4、RN50x16、RN50x64）和 3 个 ViT（B/32、B/16、L/14）。ALIGN：LAMB，weight decay $10^{-5}$，学习率 10k 步线性升到 $10^{-3}$，再经 120 万步（约 12 个 epoch）线性降到 0；输入先缩到 346 再随机裁 289；文字最长 64 wordpiece；label smoothing 0.1；$\sigma$ 初值 1.0。SigLIP 从零训练用 WebLI 的英文对，图像 224×224，文字最多 16 个 token；偏置与温度按第 5.7 节初始化。LiT 大设定：batch 32k，看到约 180 亿图文对。

这些 recipe 不能在本课的 CPU 上复现。你要复现的是它们的损失定义和温度行为。若有人用 128 的 batch 声称“复现了 CLIP”，报告必须写明负样本数是 127 而不是 32767。

把四篇的数据与 batch 放在同一张表里，只放正文出现过的数字：

| 模型 | 图文对 | 全局 batch | 图像塔 | 文字塔 | 对比形式 |
|---|---|---|---|---|---|
| CLIP | WIT 4 亿 | 32768 | RN / ViT，从零 | Transformer，从零 | 对称 InfoNCE |
| ALIGN | 约 18 亿 alt-text | 16384 | EfficientNet-L2，从零 | BERT-Large，从零 | 对称 softmax，$\sigma$ 可学 |
| SigLIP | WebLI 英文对 | 常用 16k–32k | ViT，可从零或微调 | Transformer | pairwise sigmoid |
| SigLiT / LiT | LiT 图文数据 | 32k（LiT 大设定） | 锁住的预训练 ViT | 可训练文字塔 | softmax 或 sigmoid |

CLIP 为了覆盖视觉概念，按查询做了上限 2 万的平衡；ALIGN 几乎按网页自然分布，只砍掉极端频率。两个选择都会在模型里留下痕迹：CLIP 更像“按概念抽样的百科”，ALIGN 更像“带噪声的原始日志”。零样本分类两边都能到 76% 左右，不能据此说过滤策略无影响，只能说在各自的模型和算力下，两条路都走到了同一量级。本课夹具两边都不抽样，只有 4 对，谈不上分布，只谈损失定义。

图像增强也属于 recipe。CLIP 只用随机方形裁剪；ALIGN 先把图缩到 346×346 再随机裁 289，评估用中心裁剪。增强越重，同一张图在不同 step 的 $x$ 抖动越大，对角 $s_{ii}$ 会被压低。教学矩阵把对角写成 0.86–0.92，相当于已经收敛、增强很轻时的余弦。你若在自训小模型时看到对角只有 0.3，先查归一化和温度，再查是不是裁剪和颜色抖动把正对拆散了。

文字长度同样被写进论文。ALIGN 因 alt-text 不超过 20 个 unigram，BERT 截到 64 个 wordpiece；SigLIP 从零训练只留 16 个 token。短截断会切掉长描述末尾的细粒度短语，这对检索里的“红色轿车停在松树旁”这类句子不公平，对 ImageNet 类名却几乎无影响，因为类名本来就短。评测检索和评测分类时，不要共用一个未声明的截断长度。

## 8. 按依赖顺序执行实验

先手算，再互动，最后才考虑加载公开权重。顺序反了，你会用检索 demo 的观感代替公式对错。

### Step 1：跑 CPU 夹具

在已安装课程实验包的环境里导入本课模块（编排者写入 registry 之前，不要走 `run.py run 21` 的总入口）：

```bash
python -c "from learn_omni_experiments.lessons.lesson_21 import run; print(run()['checks'])"
```

`checks` 必须全部为 True。重点看四条：打乱后 InfoNCE 不低于对齐；$\tau$ 从 0.01 到 0.2 峰值下降；sigmoid 同样不因打乱而下降；InfoNCE 对 $S+0.3$ 不变而 sigmoid 会变。

### Step 2：对照手算一行

取对齐表第一行 $[0.92,0.11,0.08,0.05]$，$\tau=0.2$。先算 $s/\tau$，再减最大值做 softmax，核对正对概率约 0.957，与互动实验 $\tau=0.20$ 的峰值一致。第一行对不上，不要进入下一步。

若要自己用计算器把四行都填完，按同一手续。第二行 $[0.10,0.88,0.14,0.07]$ 除以 $0.2$ 得 $0.50,4.40,0.70,0.35$，减 $4.40$ 后指数自变量为 $-3.90,0,-3.70,-4.05$。正对概率会略低于第一行，因为 $0.88$ 比 $0.92$ 小，且 $0.14$ 这个动物/车辆之外的干扰项比第一行的 $0.11$ 略大。第三行对角 $0.90$，第四行 $0.86$，峰值依次下降。整表正对峰值取四行里最大的那一个，所以验收看的是第一行的约 $0.957$，不是四行平均。CPU 实验的 `positive_peak_tau_0_2` 字段就是这个最大值。列方向不要漏：第一列 $[0.92,0.10,0.06,0.04]$ 对“橘猫”这句字几乎没有竞争，列 softmax 的正对概率会比行 softmax 更高。对称平均之后，整表损失约 $0.0534$，介于“只看行”和“只看列”之间。

sigmoid 手算建议先只算两个格子建立信心。正对 $(0,0)$ 的 logit 是 $10\times 0.92-10=-0.8$，标签 $+1$，单项损失 $-\log\sigma(-0.8)$。$\sigma(-0.8)\approx 0.310$，$-\log 0.310\approx 1.17$。负对 $(0,1)$ 的 logit 是 $10\times 0.11-10=-8.9$，标签 $-1$，乘到 logit 上变成 $+8.9$，$\sigma(8.9)\approx 1$，单项损失接近 $0$。$b=-10$ 时，负对几乎不贡献损失，正对因为余弦还没到 1，仍有大约 $1.17$ 的单项。把 16 个格子加起来再除以 $4$，得到约 $1.392$。打乱后对角变成小余弦，正对单项会从 $1.17$ 涨到很大，整表升到约 $9.34$。不必手算全部 16 格，但必须能解释：sigmoid 的大头在“声称是正对、其实余弦不高”的格子上。

### Step 3：互动实验

打开本课页面的“图文相似度矩阵”。必须先选择“打乱后 InfoNCE 升高 / 降低 / 几乎不变”，再点揭晓。然后分别记录对齐与打乱，并把温度滑到 0.01 和 0.20（对齐状态）记下正对峰值。验收：打乱损失不低于对齐；峰值随温度上升而下降。

### Step 4：可选检索演示

仅当你有公开 CLIP 权重和一张 GPU 时才做。固定 8 张本地图、8 句描述，计算 $8\times 8$ 余弦，检查对角是否最大。把一张图换成纯黑，对应行应整体变平或不再指向原来那句。此步失败只说明推理预处理或权重加载有问题，不能回写 Step 1 的公式结论。

### Step 5：写实验记录

记录矩阵原文、温度、打乱置换、InfoNCE 两个方向、sigmoid、$S$ 平移对照。任何数字必须能从矩阵重新算出来。

手算记录建议按下面的列写，避免事后对不上：

| 项 | 对齐 $\tau=0.07$ | 打乱 $\tau=0.07$ | 对齐 $\tau=0.01$ | 对齐 $\tau=0.20$ |
|---|---|---|---|---|
| $\mathcal{L}_{\mathrm{i2t}}$ | 自填 | 自填 | 自填 | 自填 |
| $\mathcal{L}_{\mathrm{t2i}}$ | 自填 | 自填 | 自填 | 自填 |
| $\mathcal{L}$ | 约 $3.5\times 10^{-5}$ | 约 $11.36$ | $0$ | 约 $0.0534$ |
| 正对峰值 | 约 $0.99998$ | 接近 $0$ | $1$ | 约 $0.9566$ |
| sigmoid | 约 $1.392$ | 约 $9.342$ | 与 $\tau$ 无关 | 与 $\tau$ 无关 |

最后一行“与 $\tau$ 无关”指的是本课 sigmoid 使用论文默认 $t=10$，不再复用 CLIP 的 $\tau$。若你把 $t$ 也设成 $1/\tau$，表格会变，必须在表头另开一列声明。CPU 实验的 `siglip_logit_temperature` 字段是 10，用来防止这种混用。

互动实验通过后，把页面上四个证据格（对齐 InfoNCE、打乱 InfoNCE、$\tau=0.01$ 峰值、$\tau=0.20$ 峰值）抄进同一张表。数字应与上表同方向、同数量级。若页面峰值在 $\tau=0.20$ 时仍显示 1.000，说明你还停在 $\tau=0.01$，滑条没有真正到右端。

## 9. 评测与测量

本课有两层评测，不要混。

**机制评测（必做）：** 以 CPU 实验的 `checks` 和互动实验的 Gate 为准。指标是损失差、正对峰值、平移不变性。没有准确率百分比。

**论文数字（只引用，不在本课复现）：**

| 系统 | 数据 | ImageNet 零样本 | 备注 |
|---|---|---|---|
| CLIP 最佳 | WIT 4 亿 | 76.2% | 未用 ImageNet 128 万训练图 |
| ALIGN | 18 亿 alt-text | 76.4% | EfficientNet-L2 + BERT-Large |
| ALIGN 冻特征 | 同上 | 85.5% | 只训分类头 |
| ALIGN 微调 | 同上 | 88.64% | 全量微调 |
| SigLiT g/14 | LiT 数据 + 锁图像 | 84.5% | 4×TPUv4，2 天 |
| LiT ViT-g/14 | 锁图像 | 85.2% | ObjectNet 82.5% |
| SigLIP SO-400M | 表 3 公开对比 | 83.2% | ObjectNet 82.9% |

CLIP 还在超过 30 个数据集上做零样本，覆盖 OCR、视频动作、地理定位、细粒度分类。STL10 上他们报告 99.3%。Kinetics700 上零样本 CLIP 比在 ResNet-50 特征上训的监督线性分类器高 14.5 个百分点。这些说明共享空间里装进了远超 1000 类名词的概念，包括动词。它们仍然不是 VQA 分数。

测量时把协议写死：类名是否带模板、是否 80 模板集成、图像分辨率、中心裁剪。ALIGN 写明冻特征时 train/eval 分辨率 289/360，微调时 475/600。换分辨率却引用同一数字，视为评测污染。

CLIP 论文还强调：同等 ImageNet 准确率下，零样本 CLIP 比监督 ImageNet 模型更抗分布偏移。他们把这写成政策与伦理讨论的入口（第 7 节），本课只取测量含义：零样本协议没有在目标数据集的训练集上拟合，分数更接近“换一个数据分布还能不能认”。监督模型在 ImageNet 验证集上很高，换到 ObjectNet、ImageNet-R 往往掉得更狠。LiT 把 ObjectNet 做到 82.5%，并写此前最好低 10.2 个百分点；同一 ViT-g/14 若在 ImageNet 上全量微调，ObjectNet 只有 70.5%。锁图像并配上自然语言，有时比在目标集上微调更抗分布偏移。这仍然不是 VQA。

CLIP 还把零样本和“在 ResNet-50 特征上训线性分类器”在 27 个数据集上对比，零样本赢了 16 个。细粒度上的分化很大：斯坦福车和 Food101 上零样本比该线性基线高 20 个百分点以上，花卉和飞机上则低 10 个百分点以上。动作识别里 Kinetics700 高 14.5 个百分点。论文把这种分化部分归因于 WIT 里动词和专名的覆盖，和 ImageNet 名词中心的监督不同。对本课的含义是：共享空间的“强弱”必须拆任务看，一个 ImageNet 数字盖不住花卉、飞机、动作和 OCR。

鲁棒性也要单独记账。ALIGN Table 4 给出零样本：CLIP 在 ImageNet / ImageNet-R / ImageNet-A / ImageNet-V2 上是 76.2 / 88.9 / 77.2 / 70.1，ALIGN 是 76.4 / 92.2 / 75.8 / 70.1。ImageNet-R 是艺术、卡通、素描等非自然照片，ALIGN 在这一栏更高；ImageNet-A 是对模型更难的自然图，CLIP 略高。两边都明显高于“只在 ImageNet 训练、换一种照片风格就塌”的经典监督模型，但具体哪一栏领先并不固定。抄数字时连测试集名字一起抄。

检索数字更容易被夸大。ALIGN 写他们在 Flickr30K 和 MSCOCO 的零样本及微调 R@1 上全面刷新，并说零样本图像检索相对 CLIP 提高超过 7 个百分点。SigLIP 表 3 另给一套公开模型对比：CLIP ViT-B 的 COCO 图到文 / 文到图 R@1 为 52.4 / 33.1，同体量 SigLIP 为 64.4 / 47.2。这些是检索，问的是“图和字能不能找回对方”，不是“看见图里的杯子能不能回答它在谁左边”。第 23 课才会把接地和幻觉分开测。

线性探测和全量微调是第三套数字。ALIGN 冻视觉特征只训头到 85.5%，全量微调 88.64%；CLIP ViT-L/14 冻特征 85.4%（ALIGN 表 5 的对照行）。零样本 76% 和冻特征 85% 测的不是同一种能力：前者文字塔必须立刻变成分类器，后者允许用 ImageNet 标签再学一个头。报告里三套数字要分开放，禁止平均成“CLIP 大约 80 分”。

## 11. 根据症状定位失败环节

| 症状 | 先查 | 不要先做 |
|---|---|---|
| 打乱后 InfoNCE 下降 | 是否把置换用在了行而不是列；对角是否仍被当作正对 | 改温度或改 SigLIP 偏置 |
| $\tau=0.01$ 峰值不比 $0.2$ 大 | softmax 是否没减最大值就 overflow 成 NaN；是否把 $\tau$ 乘到了 $s$ 上而不是除 | 换一张更“对齐”的矩阵掩盖数值错误 |
| sigmoid 与 InfoNCE 数值同阶且同步平移不变 | 是否对 sigmoid 也做了行内 softmax | 宣布两种损失等价 |
| 损失除 $n$ 和除 $n^2$ 对不上论文 | 重读 Algorithm 1 最后一行 `/ n` | 用学习率解释尺度 |
| 加载公开 CLIP 后检索全错 | 预处理均值方差、resize、是否 L2 归一化、温度是否乘反 | 判定“对比学习无效” |
| 零样本远低于论文 | 类名是否英文、是否缺模板、分辨率是否与模型匹配 | 用 4×4 夹具的损失去解释 ImageNet |
| 报告把 LiT 写成冻 LLM | 回论文 Figure 2 的 Lu | 继续写第 22 课配方 |
| 对角 0.92 的行，手算 $p$ 却是 0.25 | $\tau$ 是否写成了 $s\tau$；是否对整张表做了一次大 softmax 而不是按行 | 怀疑矩阵本身写错 |
| sigmoid 比 InfoNCE 小两个数量级 | 是否误除了 $n^2$；`log_sigmoid` 是否对整个矩阵求了均值再取负 | 用学习率补偿尺度 |
| 打乱后对角均值下降但损失几乎不动 | 损失是不是写死在对齐矩阵上，置换只改了显示 | 调温度“把差距拉开” |
| $S+0.3$ 后 InfoNCE 大变 | 实现没有减最大值，overflow 之后各行归一化已经坏了 | 换更小的平移 |
| 可选 CLIP demo 上黑图仍高置信选“猫” | 预处理是否把黑图变成训练集均值附近的灰图；类名模板是否全是动物 | 判定视觉塔没有学到东西 |
| 英文类名换成中文后零样本崩掉 | CLIP 的 WIT 以英文为主；ALIGN 有单独的多语言 18 亿设定 | 把中文崩掉写成“对比学习失败” |

SigLIP 的 Table 4 可以当另一张诊断表。Base 模型、batch 8k、看过 9 亿对：不启用 $b$ 且 $t'=\log 10$ 时 ImageNet 零样本 62.0； $b=-10$ 时 63.0；$b=0$ 且 $t'=\log 1$ 时掉到 53.7。偏置和温度初始化同时错，伤害最大。你的 $4\times 4$ 夹具改 $b$ 看不到 63.0 这种百分数，但可以看到损失是否对 $b$ 敏感。不敏感就说明 sigmoid 没把 $b$ 加进 logit。

互动实验若在揭晓前就看到损失，视为没走“先预测再揭晓”，验收无效，重置后再做。

预测选错时，页面会提示对角不再是原配对、交叉熵应升高。不要为了过 Gate 先把选项改成“升高”再点一次揭晓却不看矩阵：Gate 还要求你真的记录过对齐、打乱、$\tau=0.01$ 和 $\tau=0.20$ 四档。只改选项、不滑动温度，峰值两格会一直停在“未记录”。这是故意的：验收测的是你有没有操作过那两个旋钮，不是测你会不会点正确的单选。

CPU 实验失败时按字段倒推。`shuffled_infonce_not_below_aligned` 为假：置换写反了，或损失取成了准确率。`temperature_raise_drops_positive_peak` 为假：$\tau$ 被乘到了 $s$ 上。`infonce_invariant_to_global_shift` 为假：softmax 没有减最大值，overflow 之后各行已经不是同一把尺子。`sigmoid_changes_under_global_shift` 为假：sigmoid 被错误地做了行内归一化，退化成了 InfoNCE。`shuffle_breaks_diagonal_maximum` 为假：夹具矩阵被改过，对角不再是教学设定。不要改 `ALIGNED_SIMILARITY` 让检查变绿，那等于毁掉对照。

## 13. 前沿对照与改造方向

公开 Omni 系统把这套共享空间冻在视觉前端。Qwen2.5-Omni 技术报告（arXiv:2503.20215）写明音频和视觉编码器按块处理以支持流式输入，并把视觉能力与同尺寸的 Qwen2.5-VL 对照。Qwen3-Omni 技术报告（arXiv:2509.17765）正文写：视觉编码器来自 Qwen3-VL，由 SigLIP2-So400m 初始化，约 5.43 亿参数，同时处理图像和视频；其 Table 1 把该模块记为 540M。两个数字都来自同一份报告，引用时写来源，不要四舍五入成一个“大约 5 亿”却删掉出处。MiniMind-O 同样冻 SigLIP2。差别首先是规模：SigLIP 论文对照句写 CLIP 大约需要 256 块 TPUv3 训练 10 天，ALIGN 用 1024 块 TPUv3 训 120 万步；本课只有一张 $4\times 4$ 表。差别其次是机制：前沿把已经对齐的视觉塔接到 Thinker，并加上动态分辨率、时间戳和语音；本课只保留“如何对齐”这一段。钱能堆规模，堆不出对 InfoNCE 分母和 $\tau$ 的理解。

Qwen3-Omni 的预训练分三阶段，和 LiT 的锁塔选择要分开读。S1 锁住从 Qwen3 初始化的 LLM，分别训视觉、音频编码器和 adapter；作者明确放弃“编码器和 adapter 联合训、LLM 始终冻住”的旧阶段，理由是编码器可能去补偿被冻住的 LLM，伤害感知。S2 解冻全部参数，用约 2 万亿 token 的多模态混合。S3 把长度从 8192 拉到 32768。S1 冻的是 LLM，动的是视觉塔，这是“把已经有的语言空间当锚，让视觉去靠拢”。LiT 冻的是视觉塔，动的是文字塔，这是“把已经有的视觉空间当锚，让文字去靠拢”。两句话里都有“冻”，冻的模块相反。写改造报告时必须写清锁的是哪一座塔，否则第 22 课的解冻顺序会从一开始就反。

四个可执行改造，全部停在本课缩小设置里：

1. **负例数量。** 在 `lesson_21.py` 的 $4\times 4$ 表上，计算 InfoNCE 时只保留每行随机 1 个或 2 个负例，其余格子不进 softmax。预算：CPU 数秒。预期：负例越少，对齐损失越低、打乱与对齐的差距变窄。失败判定：只留 1 个负例时损失仍等于满 3 个负例（实现没有真正 mask）。
2. **温度扫描。** $\tau$ 从 0.01 走到 0.2，步长 0.01，画出正对峰值。预算：CPU 数秒。预期：单调不增，并在 0.01 附近饱和到 1。失败判定：峰值随 $\tau$ 上升。
3. **sigmoid 的偏置。** 固定 $t=10$，把 $b$ 从 $-10$ 改到 $0$。预算：CPU 数秒。预期：与 SigLIP Table 4 同方向：去掉合理负偏置后，小模型设定变差；本课夹具上至少应看到损失绝对值改变，且打乱/对齐的相对次序仍保持。失败判定：$b$ 从 $-10$ 变 $0$ 而损失完全不变。
4. **锁塔梯度。** 写一个两层线性的玩具双塔，对 $4\times 4$ 的 mini-batch 反传。一臂锁图像塔，一臂两塔都开。预算：CPU 一分钟。预期：锁图像塔时图像权重的梯度范数为 0，文字塔非 0。失败判定：锁塔后图像权重仍更新。不要把这臂的 loss 数字写成 85.2%。

顺手复现映射：

- CLIP“乘数裁剪到 100”对应本课 $\tau=0.01$ 几乎 one-hot：能复现方向，不能复现 ImageNet 76.2%。
- ALIGN“减少 in-batch 负例会掉点”对应改造 1：能复现方向。
- SigLIP“损失不依赖全局 softmax”对应平移对照与逐格求和：能复现机制。
- LiT“锁图像更好”对应改造 4：只能复现梯度被挡住，不能复现 85.2% 对 76.2% 的差距，那是规模和预训练数据。

[第 20 课](20_unified_understanding_generation.md) 的生成路径需要另一套连续 latent，不是本课的余弦表。不要把 flow matching 的速度场抄进对比损失。理解路径会继续用冻结的 SigLIP 类特征压成前缀；生成路径走 VAE latent。本课造出的共享空间只服务理解侧的“有什么”，不负责像素级的“长什么样”。若有人用对比损失去监督 VAE latent，余弦会丢掉颜色和纹理，图会变得“语义对、像素脏”。那是第 20 课的 interference，不要提前在本课的 $4\times 4$ 表上假装已经处理。

公开 Omni 里视觉塔仍走对比预训练的后代，并不改成本课的 InfoNCE 公式。Qwen3-Omni Table 1 把视觉编码器标成不流式（Streaming 一栏为空白），音频编码器 AuT 才是流式。对比塔通常看整张图或整帧，块级流式是后接的工程，不是 sigmoid 损失自动带来的能力。本课验收不要求流式。

4. **LiT**，Zhai et al.，[arXiv:2111.07991](https://arxiv.org/abs/2111.07991)。带着什么问题读：Lu / Uu / UU 在 Figure 3 上谁更好？锁图像塔时对比损失在 LiT 数据上其实更差，为什么下游零样本反而更好？85.2% 和 82.5% 分别对应哪个测试集？PublicLiT 的 75.7% 用了哪些公开数据？读完应能向别人纠正“LiT 冻 LLM”这句错话。论文还写：同一套锁塔做法在监督预训练和 DINO / MoCo-v3 自监督预训练上都能超过从零对比；在 ResNet、ViT、MLP-Mixer 上都成立。读的时候把“锁图像”当成与骨干种类无关的接口，不要记成“只有 ViT-g/14 才行”。早期 arXiv 版本把 ViT-g/14 的 ImageNet 写成 84.5%，v3 因修复权重加载改成 85.2%。引用时用 v3 摘要和正文的 85.2%，并知道 84.5% 是旧稿或 SigLiT 另一条设定，避免和 SigLIP 摘要里的 84.5% 对混。

以上四篇的数字均来自已打开的摘要或正文。未在正文出现的卡时、未公开的内部数据量，写“其技术报告未公开该细节”，不要补。

读的时候建议按“一张表、一个超参、一个反例”做笔记。CLIP 的表是 WIT 的查询平衡和 32768 的 batch，超参是 $\tau=0.07$ 与乘数裁剪 100，反例是花卉和飞机上零样本输给线性基线。ALIGN 的表是 18 亿对和 4 倍噪声数据超过 CC-3M，超参是学到的 $\sigma\approx 1/64$，反例是 $\sigma=1/32$ 时 MSCOCO 掉到 39.6。SigLIP 的表是 32k 已够用、百万 batch 收益变薄，超参是 $t=10,b=-10$，反例是 $b=0$ 且 $t'=0$ 时 ImageNet 掉到 53.7。LiT 的表是 Lu 优于 UU / Uu，超参是锁图像、batch 32k、180 亿对，反例是锁图像时对比训练损失其实更高。四组笔记写完，本课的公式和误区就能互相卡住，不容易只记住“对比学习很强”这一句空话。
