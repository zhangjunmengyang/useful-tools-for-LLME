# 文本怎么变成 token

模型看到的不是“词”，是一串整数。这串整数从哪来：先把字符串拆成 Unicode 码点，再由分词器（tokenizer）合成子词，再查表得到编号。

两件事常被混在一起。Unicode 管的是“这个字在电脑里是哪个码”。分词器管的是“这些码怎么切成模型认识的块”。全角 `Ａ` 和半角 `A` 看起来像同一个字母，码点不同；有的分词器会先做 NFKC 正规化，有的不会。所以同一段可见文字，进模型后长度可以不一样。

分词器通常按字节对（BPE）或类似规则合并常见片段。英文常见词往往一块走完，生僻词或中文可能被切得很碎。这不是对错问题，是这套词表在训练语料里见过什么。

## 学

先分清两层：

1. 字符层：复制一段带全角、重音、空格的文字，看每个码点的类别和字节数。
2. 分词层：同一段中英混排，换一个词表，数 token。

问自己：长度变了，是因为码点变了，还是因为切法变了？两边都变过，才算过关。

## 玩

下面两个工具都是现成的接口，不是演示动画。

1. 把 `Ａ café` 丢进 Unicode 分析。看全角 A 和 `é` 的码点，以及 NFC / NFKC 是否还相等。
2. 有本机缓存或能下模型时，再用 `openai-community/gpt2` 编一段中英混排。记下 token 数。再换一句同义改写，看长度怎么动。

`tokenizer_encode` 会拉 Hugging Face 词表，第一次可能较慢。只想先看字符层，跑第一个工具就够。
