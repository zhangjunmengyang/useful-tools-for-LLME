# KV Cache 为什么越生成越吃内存

解码时，每一步的注意力都要看见已经写出的前缀。若每步把前缀从头算一遍，时间和显存都会按长度平方涨。常见做法是把已经算过的 Key 和 Value 留下，这就是 KV Cache。

缓存大小大致跟这些量成正比：层数、头数、每头维数、当前序列长度、batch、数值精度。提示词很长，还没开始生成，缓存就已经占一块。之后每多写一个 token，再追加一截。

所以“同样 70 亿参数，上下文从 2K 开到 32K”会先在缓存上爆，不一定是权重装不下。量化权重和量化缓存也不是同一件事。

## 学

能用自己的话解释：权重是一份，缓存是按这次对话的长度另开的一张表。说不清这两笔账，后面估显存会对不上。

## 玩

默认按 32 层、4096 隐层、提示 1024、再生成 16 步来估。先跑 `kv_cache_growth`，看每一步 `cache_gb`。再把 `generation_length` 改成 128。比的是增量，不是绝对值是否像某张卡的广告。
