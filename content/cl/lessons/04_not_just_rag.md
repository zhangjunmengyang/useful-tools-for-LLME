# 第 04 课：把上下文塞满不等于学会了

> 类型：实战（同一份 20 条公司事实，对照 prompt 塞名录 / 检索再塞 / 改小模型权重）<br>
> 建议周期：2-4 天<br>
> 硬件：Mac / CPU 可完成检索对照和机制实验；135M 微调建议单张 8-24GB 卡，CPU 能跑但会慢<br>
> 锚定：公开小模型 [HuggingFaceTB/SmolLM2-135M](https://huggingface.co/HuggingFaceTB/SmolLM2-135M) 或其 Instruct 版；外挂记忆以 MemGPT（[arXiv:2310.08560](https://arxiv.org/abs/2310.08560)）作预告，细做在第 13 课<br>
> 产物：「上下文 / 检索 / 权重」三栏对照表、撤掉名录后的答题记录、一条新事实冲旧事实的遗忘记录

## 1. 这一课做什么

第一幕走到最后一课。你已经在 [第 01 课](01_catastrophic_forgetting.md) 看见接着训会忘，在 [第 02 课](02_stability_plasticity.md) 看见稳和塑对着干，在 [第 03 课](03_cl_evaluation.md) 学会用 $R$ 矩阵、ACC、BWT 和 prequential 打假。本课把量法对准一件更像上班的事：模型到底有没有学会「小王是谁」。

2026 年 5 月，DeepSeek 创始人梁文峰在一场闭门交流里举过这个例子：招一个员工，花两个月熟悉公司和同事；你说「把小王叫过来」，他知道小王是谁。现在的 AI 没有那两个月，你得把全部上下文每次重说一遍。这段话出自 2026-07 公开的录音转写（腾讯科技等渠道），DeepSeek 没有正式确认这份记录。课程只把它当作公开讨论中的路线判断，不当官方技术规格，也不引用转写里的算力、融资或定价。

工业界现在常用的权宜之计，正好对应「每次重说一遍」：把员工名录塞进 prompt，或者检索一段再塞。梁文峰说的下一级台阶是持续学习：两个月上岗之后，名录不用每次拎来，人已经把公司装进自己里。本课用一个 135M 小模型和一份固定的 20 条公司事实，把三种写法摆到同一张考卷上：

1. 每次把名录整段放进上下文（长 prompt / 工作记忆）。
2. 先检索再把命中片段放进上下文（RAG：retrieval-augmented generation，检索增强生成）。
3. 用几条问答样本微调权重（SFT：supervised fine-tuning，监督微调）。

两种考法：名录还在；把名录撤掉。预期你自己跑出来就能看见：有名录时大家都会；撤掉之后，只有改过权重的还答得上。再写入第 21 条新事实，看微调会不会把旧事实冲掉。这件事用第 03 课的协议记：新旧事实是两个任务，$R$ 至少是 $2\times 2$。

本课在循环里换的零件是「写到哪里」。前三课默认写进慢速权重。这里把上下文和外挂检索也摆上台面，证明它们能叫来小王，却不等于上岗。什么时候必须改权重，综合判断留在 [第 16 课](16_when_weights_must_move.md)；分层记忆系统留在 [第 13 课](13_external_memory.md)。MemGPT 本课只作预告：它把上下文当成操作系统的内存层次，该换页时换页，权重仍然可以不动。

Wu 等人 2024（[arXiv:2402.01364](https://arxiv.org/abs/2402.01364)）把大模型持续学习分成续预训练、指令微调、对齐三阶段，并单独对照 RAG 与模型编辑。本课落在「事实」这一格：RAG 很强，技能、偏好、流程还没轮到。第三幕才会把指令序列和续预训练接上第 03 课的 $R$。

术语速查：

| 术语 | 一句解释 |
|---|---|
| 工作记忆 / 上下文 | 这一次前向计算里模型能直接读到的 token；会话结束或你把名录删掉，它就没了 |
| RAG | 先按问题去文档库里找几段，再和问题一起塞进上下文；库还在就能查，库撤了就不会 |
| 权重写入 / SFT | 用梯度改模型参数，把事实编进网络；之后即使 prompt 里没有名录，也可能答得出 |
| 外挂记忆 | 日记写在模型外面（向量库、键值、文件系统），推理时再读回来；MemGPT 是这一类的代表 |
| 知识编辑 | 改一条事实、尽量别伤邻居，第 14 课做；本课的微调是整块事实集一起改 |
| 撤上下文测试 | 同一批题，推理时禁止再看名录；用来区分「这次查到了」和「已经学会了」 |
| SmolLM2-135M | Hugging Face 的 1.35 亿参数解码器语言模型，本课用它避免 7B 起步 |
| 幻觉 | 名录里没有、模型却编出一个工位或工号；检索和微调都要单独记这一列 |

## 2. 问题

现在能跑的 Agent，多半靠三样东西活着：越来越长的上下文窗口、RAG、会话摘要。演示很好看。你问「小王坐哪」，它答「3 楼 B12」，因为你刚把名录贴进系统提示。关掉系统提示再问同一句，它可能说不知道，也可能编一个听起来很像的座位。演示视频剪掉了后一次提问，观众就会以为 Agent 已经入职。本课把后一次提问写成必做项：同一批题，名录在和不在都要交卷。

这和持续学习要解决的事不是同一级。第 03 课已经禁止把「最后一次考试满分」当成学会。这里同样禁止把「这一次会话答对」当成学会。考卷必须包含「把名录藏起来」。

本课要回答：

1. 同一份 20 条事实、同一批问题，prompt 塞名录、检索再塞、微调权重，在「名录在 / 名录不在」两种测试下各得多少分？
2. 微调记住新事实之后，旧事实掉多少？用第 03 课的 BWT 怎么写？
3. 检索在事实查询上很强，为什么仍覆盖不了技能、偏好、流程、运动控制？本课实验能证明哪一句，哪一句只能口头划界？
4. 梁文峰说的「两个月上岗」和「每次把上下文重说一遍」，差在写到哪里？转写未确认，课内只引用 §0.1 已列判断。

本课不训 7B，不搭完整 MemGPT，不把内部 Agent 产品当事实。135M 会答得磕巴、会背不全 20 条，这没关系：我们比的是三种写法在撤上下文之后的相对差别，不是排行榜分数。如果你用 API 大模型做 prompt 臂、用 135M 做微调臂，那是在比模型和比写法，结论作废。三臂必须同一套权重出发。

## 3. 准备

- 第 03 课的协议模板（`PROTOCOL.md`）准备好复制一份，改成两任务：事实集 A（20 条）、事实集 A+新事实。
- Python 3.10+、能装 `transformers` 与 PyTorch。机制实验仍在 `learn-cl/experiments/`，不下载模型。
- 锚定实验需要能从 Hugging Face 拉 `HuggingFaceTB/SmolLM2-135M-Instruct`（指令版更适合问答；基座 `SmolLM2-135M` 也可，生成更散）。第一次下载约几百 MB 量级，记进笔记，不要把下载时间写成训练时间。
- 单卡 8-24GB 做全参数短微调或 LoRA 都够。只有 Mac CPU 时：检索对照和机制实验必须做完；微调标成加分，允许改用更少步数或只跑「假权重」对照（见 Step 6）。
- 20 条事实用课内虚构公司「青梧工作室」，不要换成你家公司的真名录，也不要写真实密码、工号体系。
- 浏览器打开本课「叫小王」实验。先选写法，再把名录藏起来，看 Agent 还能不能执行「把小王叫过来」。预测写在纸上再点运行，改选项后预测作废。

## 4. 学习目标

1. 用自己的话区分三种写入位置：上下文、检索库、权重；并指出各自在「撤名录」之后还剩什么。
2. 把 20 条事实编成可评分的问答对，写出有名录 / 无名录两套评测脚本，评分规则在跑模型前冻结。
3. 跑通或读通 SmolLM2-135M-Instruct 的三种推理路径；记录有名录时三法的答对数，无名录时三法的答对数。
4. 追加一条冲突或全新事实，微调后再测旧 20 条，用第 03 课公式报 ACC 与 BWT（至少 $2\times 2$）。
5. 写出三栏对照表的适用边界：检索擅长事实查询；技能、偏好、流程、控制本课实验不能证明，只能划界并指向第 16、21 课。
6. 复述梁文峰「叫小王 / 两个月上岗」的判断，并当场补上「转写未获 DeepSeek 确认」。

## 5. 原理

五个机制：写到哪里、三种写法怎么工作、撤上下文测试、微调遗忘、以及 RAG 覆盖不了的边界。

### 5.1 先决定写到哪里

循环的第一句是「新经验进来，先决定写到哪里」。公司名录是一条经验。你可以把它写进四个地方：

| 位置 | 这次会话还在吗 | 关掉会话 / 撤名录 | 改一条事实的代价 |
|---|---|---|---|
| 当前上下文 | 在，只要没截断 | 不在 | 改 prompt 即刻生效 |
| 外挂检索库 | 在，若检索命中 | 库还在就还在 | 改文档；冲突条目要你自己定规则 |
| 快速权重（LoRA、adapter） | 在 | 在（加载了这份 adapter） | 再训一小会儿；可能冲旧的 |
| 慢速权重（全参数） | 在 | 在 | 更贵，遗忘风险同类 |

梁文峰举的新员工，两个月后「小王」写进了慢速权重加长期记忆：你不用每次把花名册念一遍。现在的模型把花名册放在上下文里，会话一关就卸掉。MemGPT（Packer 等人，[arXiv:2310.08560](https://arxiv.org/abs/2310.08560)）承认上下文窗口是物理限制，于是在模型外面做虚拟内存：工作区、召回区、磁盘，靠模型自己发出的函数调用换页。它能让「小王」跨会话还在，但那是外挂记忆会了，不是权重会了。第 13 课再拆它的层。本课要你自己跑完撤库测试：外挂和上下文会一起失效。

类比：开卷考试、允许带一张小抄、把知识点背进脑子。开卷和小抄在收卷之后都没了。类比失效处：语言模型的「背」是分布式参数，一条事实没有单独的脑细胞，改新的可能把旧的一起改掉。这正是后面要测的 BWT。

### 5.2 三种写法：同一份事实，三条数据通路

固定知识库 $\mathcal{K}=\{f_1,\ldots,f_{20}\}$。问题 $q$（例如「小王坐哪」）。三种系统给出答案 $\hat{a}$。

**（a）整段塞进 prompt。** 构造

$$
\text{prompt}(q,\mathcal{K})=\bigl[\text{系统说明};\ \mathcal{K};\ q\bigr].
$$

模型做的是条件生成 $p_\theta(\hat{a}\mid \text{prompt}(q,\mathcal{K}))$。$\theta$ 可以是出厂权重，完全不更新。它「会」的前提是 $\mathcal{K}$ 出现在窗口里，且没有被截断、没有被其它指令挤掉。20 条很短，135M 的窗口装得下。换成半年的会议纪要，这条路先死在长度上。

**（b）检索再塞。** 用检索器 $r$ 从 $\mathcal{K}$ 取出 $k$ 条，再生成

$$
\hat{a}\sim p_\theta\bigl(\cdot \mid q,\ r(q,\mathcal{K},k)\bigr).
$$

本课检索器允许两档。CPU 档：字符重叠或 TF-IDF，不下载额外嵌入模型。加分档：用一个现成的句向量模型。$k=3$ 起步。检索失败时，模型会在空上下文上编。评测必须把「检索没命中」和「命中了但生成错」分开记。

**（c）改权重。** 把每条事实写成若干问答，例如 $(q_{i,1},a_i),\ldots$，最小化

$$
\mathcal{L}(\theta)=-\sum_{i}\sum_{j}\log p_\theta(a_i\mid q_{i,j}).
$$

可以用全参数几步 SGD，也可以只训 LoRA。本课不规定必须 LoRA；135M 全参数短训在 8GB 上通常可行。训完之后推理 prompt **不许**再带 $\mathcal{K}$，否则你分不清是权重会了还是又开卷了。

三条通路的验证不一样。（a）（b）在撤掉 $\mathcal{K}$ 之后应接近「未读过名录的基座」。（c）在撤掉 $\mathcal{K}$ 之后应高于基座。有 $\mathcal{K}$ 时三法都可以高，那一列不能当成功标准。这和第 03 课禁止把 LA 当 ACC 是同一条纪律。

### 5.3 撤上下文测试：把「查到了」和「学会了」拆开

对每个问题准备两个推理条件：

- `with_kb`：允许读 $\mathcal{K}$（整段或检索）。
- `no_kb`：系统提示里没有名录，检索器返回空，禁止读本地文件。

记 $s(\hat{a},a^\star)\in\{0,1\}$ 为规则匹配（见第 7 节：工位、工号、人名必须精确；允许同义问法）。方法 $m$ 的两列分数是

$$
\mathrm{Acc}^{\text{with}}_m=\frac{1}{N}\sum_{n}s(\hat{a}^{\text{with}}_{m,n},a^\star_n),\qquad
\mathrm{Acc}^{\text{no}}_m=\frac{1}{N}\sum_{n}s(\hat{a}^{\text{no}}_{m,n},a^\star_n).
$$

本课主结论用差

$$
\Delta_m=\mathrm{Acc}^{\text{with}}_m-\mathrm{Acc}^{\text{no}}_m.
$$

$\Delta$ 接近 0 且 `no_kb` 高：写进了权重（或写进了你没撤掉的外挂库，所以撤的时候要连库一起撤）。$\Delta$ 大且 `no_kb` 接近基座：它靠开卷。

浏览器实验「叫小王」是这件事的交互版。虚拟公司里有小王。你选「每次重说 / 检索 / 改权重」，系统先让你预测「把名录藏起来之后还能不能叫来人」，再运行。改权重应仍能叫来；前两种在藏名录后失败。预测对了才过关。

评分必须在看模型输出之前写死。否则你会把「3 楼靠窗」和「B12」一个算对一个算错，两次实验无法比。推荐主分用精确槽位（工位号、工号、星期），另开一列宽松分（自然语言包含关键词）。主表用精确槽位。

### 5.4 新事实进来，微调也会忘

持续学习没有在微调这里消失。把 20 条当任务 1，第 21 条（「小王换到 4 楼 D02」或一条全新项目）当任务 2，只在任务 2 的样本上继续训，再测任务 1。得到 $2\times 2$ 的 $R$：

$$
R=\begin{pmatrix}
R_{1,1} & R_{1,2} \\
R_{2,1} & R_{2,2}
\end{pmatrix}
$$

$R_{1,1}$ 是刚训完 20 条、撤名录后的准确率。$R_{2,1}$ 是再训新事实之后，旧 20 条还剩多少。BWT $=R_{2,1}-R_{1,1}$。135M 在极小语料上过拟合时，BWT 经常为负：它把「小王」的座位改成新的，旧座位问答一起塌，甚至把周衡的工位也带偏。

这和 RAG 的冲突写入不同。RAG 若两条文档都在，检索可能返回两条，模型在上下文里看见矛盾，表现是胡编或并列，不是参数里的灾难性遗忘。第 13 课专门测覆盖 / 并存 / 胡编。本课微调臂必须报 BWT，检索臂改报「冲突文档同时在库里时答哪一条」。

Wu 等人综述 Table 1 的对照：RAG 勾选「事实」，不勾选技能、价值观、偏好。本课实验只操作事实，所以只能验证表里「事实」这一行的一半（检索能查、撤库不会）。技能那一行需要第 16、21 课的矩阵。不要把本课 20 条事实的结论写成「RAG 什么都能替持续学习」。能叫来小王，只说明名录问题有解；两个月上岗还差技能和习惯进权重。这句话本身也是划界，不是本课测量出来的。

### 5.5 适用边界：叫得来小王，不等于两个月上岗

把名录撤掉之后还答得出座位，只说明「小王是谁」这类事实可以进权重或进外挂库。梁文峰说的两个月，还包括熟悉同事怎么协作、项目怎么推进、什么时候该叫人、什么时候不该。转写未获确认，课内把它读成：Agent 要在真实工作里积累技能、事实、偏好和流程，而不是每次会话从零开始。

四类经验里，本课只测量第一类：

| 经验类型 | 检索是否够 | 本课能否验证 |
|---|---|---|
| 事实（座位、工号） | 通常够 | 能：20 条问答 |
| 文档里写明的制度 | 够，若写进了库 | 能：周会时间、差旅上限 |
| 流程技能（一组惯用命令） | 不够，除非每次检索到完整剧本且会执行 | 不能；第 21 课技能库 |
| 偏好与协作习惯 | 不够 | 不能；第 16、24 课 |
| 新的计分规则 / 推理模式 | 不够 | 不能；要改权重或内环学习 |

验证边界的方法：本课交付物必须有一节「本实验证明了什么 / 没证明什么」。证明了 $\mathrm{Acc}^{\text{no}}$ 上权重臂高于 prompt 臂。没证明 135M 已经会当同事。没证明 RAG 在开放域问答上的排名。没证明 MemGPT 的换页策略。

## 6. 源码导读

本课没有单一「官方持续学习仓库」。锚定的是公开权重和你自己写的三条推理路径。读代码按数据流，不要按文件名字母序。

| 位置 | 带着什么问题读 |
|---|---|
| Hugging Face 模型卡 `HuggingFaceTB/SmolLM2-135M` 与 `...-Instruct` | 架构是解码器；Instruct 用哪套聊天模板？推理必须走 `apply_chat_template`，否则指令版也像基座一样散 |
| `transformers.AutoModelForCausalLM.from_pretrained` | `torch_dtype`、`device_map` 怎么写才不会在 8GB 上 OOM |
| `tokenizer.apply_chat_template` | 系统提示里放名录时，名录是 system 还是 user？本课约定：名录放 system，问题放 user，撤名录时 system 只留一句「你是青梧工作室助手」 |
| 课内 `facts.jsonl`（你自己建） | 每行是否同时包含 `id`、`fact`、`questions[]`、`slot`、`answer` |
| 课内检索函数 | 查询「小王坐哪」时，是否只靠「小王」两个字就能命中座位条？故意加一条也含「小王」的值班表，看 $k=1$ 会不会取错 |
| 微调循环或 `SFTTrainer` | label 有没有把问题部分 mask 掉？没 mask 就会学复读问题 |
| MemGPT 论文 / Letta 仓库（只读） | 工作记忆和外部存储之间靠什么调用移动数据？本课不跑，第 13 课再装 |

Instruct 版推理的最小形状（字段以模型卡为准，若聊天角色名不同，以 `tokenizer.chat_template` 为准）：

```python
from transformers import AutoModelForCausalLM, AutoTokenizer

model_id = "HuggingFaceTB/SmolLM2-135M-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id)
messages = [
    {"role": "system", "content": system_text},
    {"role": "user", "content": question},
]
inputs = tokenizer.apply_chat_template(
    messages, add_generation_prompt=True, return_tensors="pt"
)
```

生成后只把新 token 解码成答案，不要把整个 prompt 回显进评分器。135M 容易复读系统提示，评分器要先截断到第一行或第一个句号。

每条至少再写一个同义问法（「小王的座位号」「把小王叫过来」）。同义问法进评测集，不进检索文档正文，防止检索靠问句抄原文。

「把小王叫过来」在本课有两个合法答案槽位，必须事先拆开。作为事实题，它应对 id 16：把检索值班拉进当前工单。作为指人题，它应对 id 01+17：知道小王是谁、本周他哪天值班。浏览器实验考的是后者：名录藏起来以后，系统还知不知道该找谁。微调数据里这两种问法都要有，否则模型会把「叫小王」背成一句口号，工位和值班对不上。

评分示例。问题「小王坐哪」，标准槽位 `B12`。生成「小王在 3 楼靠窗，工位 B12。」精确分 1。生成「他坐在三楼靠窗。」精确分 0，宽松分 1。主表用精确分。生成「小王坐 C08。」精确分 0，并记一次张冠李戴。生成「我不清楚。」精确分 0，不算幻觉。幻觉只记在未知题上：名录没有的内容被编造出来。

### Step 2: CPU 机制实验

在 `learn-cl/experiments/`：

```bash
python3 run.py run 04
```

实验用纯 Python 结构体模拟三个后端，不加载神经网络。上下文臂和检索臂从名录字典取座位；撤掉名录后两者返回空。权重臂是线性联想记忆：在单位矩阵上把「人 → 座位」写成权重，推理时只看权重、不看名录。

预期 `artifacts/lesson04/result.json` 的五个 `checks` 全真。这层钉的是机制，不是论文分数：不是 SmolLM 微调分数。本机一次运行（Python 3.13.13，seed=4），有名录时 prompt/RAG 都是 1.0；撤掉后两者是 0；权重仍是 1.0。换机器会变，方向不应变。

真实 `checks` 键名：

- `prompt_perfect_with_context`：名录在时 prompt=1.0（本机 `prompt_with_context`=1.0）；
- `prompt_fails_without_context`：撤上下文后 prompt<0.15（本机 `prompt_without_context`=0.0）；
- `rag_works_with_kb`：知识库在时 RAG=1.0（本机 `rag_with_kb`=1.0）；
- `rag_fails_without_kb`：撤知识库后 RAG<0.15（本机 `rag_without_kb`=0.0）；
- `weights_survive_without_context`：改过权重后仍 >0.95（本机 `weights_without_context`=1.0）。

CPU 层不测「小王改到 D02」；冲突事实留给 Step 7 的 135M 微调。

### Step 3: 冻结问答集和评分器

在你的实验目录写 `facts.jsonl` 与 `eval.py`。评分器只认槽位字符串是否出现在生成文本中（大小写不敏感，工号保持连字符）。先对标准答案跑一遍，精确分必须是 20/20。再对故意写错的句子跑一遍，必须是 0。这两步不过，不许启动模型。

另准备 `probes.jsonl`：20 条主问题 + 至少 10 条同义问法 + 5 条名录里没有的题（「小王的猫叫什么」）。后 5 条用来记幻觉率：基座和三臂都应该拒绝或说不知道；编造了就记一笔，不进准确率分母。

### Step 4: 有名录时的三条推理

拉 Instruct 权重（基座作为对照可选）：

```bash
python3 -c "from transformers import AutoTokenizer; AutoTokenizer.from_pretrained('HuggingFaceTB/SmolLM2-135M-Instruct')"
```

上面这条只为预下载分词器；模型本体在你的脚本里 `from_pretrained`。写三个函数 `answer_prompt`、`answer_rag`、`answer_base`，全部 `with_kb=True`。`answer_base` 是无名录的出厂模型，当作随机 / 先验对照。

检索用 TF-IDF 即可。`scikit-learn` 若不想装，用词集合交集除以查询词数当分数。$k=3$。打印每个问题命中的 `id`，人工看「叫小王」有没有取到 id 16 而不是只取到 id 01。

预期：135M 即使有名录也不会 20/20。prompt 整段塞通常高于 RAG（文档短、整段更稳），两者都应明显高于 `answer_base`。把数字记进表，不要改评分器去凑满分。

### Step 5: 撤掉名录

同一批问题，三函数都把 $\mathcal{K}$ 设为空，检索返回 `[]`。再跑一遍。

预期方向（你的绝对数字以跑出来的为准）：

| 方法 | with_kb | no_kb | $\Delta$ |
|---|---|---|---|
| 整段 prompt | 较高 | 接近基座 | 大 |
| RAG | 中到高 | 接近基座 | 大 |
| 基座（对照） | 低 | 低 | 约 0 |

这一步还没有微调臂。先把「开卷会、闭卷不会」钉死，再进入改权重。若 prompt 在 `no_kb` 上意外很高，检查是不是系统提示里还残留名录，或评分器把「不知道」误判为含槽位。

### Step 6: 微调权重，再闭卷考

把 20 条各展开成 2-4 个问答，总共几十条，足够 135M 过拟合到课内集合。全参数示例超参（不是论文配方，是冒烟）：学习率 $1\times 10^{-5}$ 到 $5\times 10^{-5}$，1-3 个 epoch，batch 4，最长 256 token。8GB 卡用 LoRA（`r=8`，只挂 attention）也可以。Mac CPU 把 epoch 改成 1、样本改成 20 条各 1 问，能看到 `no_kb` 相对基座上升就算方向对。

训练样本写成聊天回合，和推理同一套模板，避免「训的是补全、测的是指令」。一条示例：

```text
system: 你是青梧工作室助手。用短句回答槽位，不要编造名录里没有的内容。
user: 小王坐哪
assistant: B12
```

注意：训练时的 system **不要**附上 20 条名录。否则模型仍然在开卷，闭卷测试会掉回基座。label 只在 assistant 段上计算交叉熵。生成时 `temperature=0` 或贪婪解码，`max_new_tokens=32`，`do_sample=False`。采样会让同一道题两次分数不同，协议里就没法写 BWT。

训完只跑 `no_kb`。预期：微调臂的 `Acc^{no}` 高于 Step 5 的 prompt 臂和 RAG 臂。达不到 20/20 正常。若完全不升，先查 label mask、学习率、是不是在 Instruct 模板外训练。

把微调当作任务 1 结束，记下 $R_{1,1}=\mathrm{Acc}^{no}$。

### Step 7: 第 21 条，测遗忘

只在「小王现在坐 4 楼 D02」及其同义问上继续训若干步。再测：

- 新问题「小王坐哪」是否产出 D02（$R_{2,2}$）
- 旧 20 条里所有仍成立的槽位（$R_{2,1}$；id 01 的正确答案此时应改为 D02，旧 B12 算错）

计算 BWT $=R_{2,1}-R_{1,1}$（分母按第 03 课：两个任务时就是一项）。预期：小模型上 BWT 为负的概率很高。把这个负值写进协议，不要当成实验失败。失败标准是：新事实没学会且旧事实也没动，说明学习率约等于 0。

检索臂做对照：把 D02 写进库、B12 删掉或留着。留着时记录模型答哪一个；删掉时 `no_kb` 仍应接近基座。检索不产生参数意义上的 BWT。

## 10. 排错

| 症状 | 最可能的原因 | 怎么确认 | 怎么修 |
|---|---|---|---|
| Instruct 模型胡言乱语 | 没走 `apply_chat_template` | 打印解码前的 input ids 对应文本 | 按模型卡用聊天模板，`add_generation_prompt=True` |
| `prompt_fails_without_context` 或 `rag_fails_without_kb` 为假 | 名录没真正撤掉 | 看 `prompt_without_context` / `rag_without_kb` | 两者本机一次运行都是 0；阈值 <0.15 |
| `weights_survive_without_context` 为假 | 线性联想没写进去，或评测仍在查名录 | 看 `weights_without_context` | 本机一次运行是 1.0；阈值 >0.95 |
| prompt 臂在 no_kb 上仍然全对 | 名录残留在默认 system，或评分器太松 | 打印实际 system 文本；看是否接受了「三楼」当 B12 | 撤名录时 system 只留身份句；精确分只认槽位 |
| RAG 全错、prompt 全对 | $k$ 太小或检索只用了停用词 | 打印命中 id | 先把 $k$ 加到 5；查询里保留「小王」「工位」 |
| 「叫小王」检索到座位、没检索到值班含义 | 词重叠被 id 01 压过 | 看 top-k | 加一句定义进文档；或评测时允许 $k=3$ 同时命中 01 与 16 |
| 微调 loss 降，`Acc^{no}` 不动 | 学了复读问题，或生成截断 | 看 raw 生成 | mask 掉 prompt token；增大 `max_new_tokens` 到 32-64 |
| 8GB OOM | 全参数 + 长 system 名录 | `nvidia-smi` | 微调时本来就不要带名录；用 LoRA 或缩短到 256 |
| Mac 微调一夜不涨 | 学习率过小或步数不够 | loss 是否下降 | 先过拟合 8 条，确认 `Acc^{no}` 能到 8/8，再扩到 20 |
| 第 21 条之后旧事实全还在、新的也不会 | 没真正更新到同一份权重 | 比较微调前后参数范数 | 确认 `save_pretrained` 与评测加载的是同一目录 |
| 未知题被算进准确率 | 分母用了 25 而不是 20 | 查评测脚本 | 未知题只进幻觉列 |
| 下载模型卡住 | 网络或缓存权限 | `HF_HUB_OFFLINE` | 换镜像或预拷 cache；机制实验不依赖下载 |

## 11. 前沿与改造

工业界叫得动「小王」的系统，2024-2026 年多半是 MemGPT / Letta 一类外挂记忆，加上 RAG。Wu 等人把它们和持续学习、模型编辑分列：RAG 改的是本次上下文，编辑改的是局部事实，持续学习改的是能力本身。本课用撤名录把前两者和第三者拆开。Harrington 等人把 prompt、SFT、RL 和上下文压缩放进同一套顺序协议；O'Neill 追问事实写进权重之后，再写几十条还能不能用。本课只做撤名录，那两篇的顺序写入留给第 16 课。差距在两头：一头是记忆系统会做冲突合并、分层召回（第 13 课），一头是技能与偏好仍要进权重或进测试时内环（第 16-21 课）。

梁文峰说全世界还没找到真正管用的长期持续学习方法（转写未确认）。本课 135M 过拟合 20 条，不是反例。它只证明：权宜之计和「写进权重」在闭卷条件下差一口气。

动手改造（选做）：

1. **同义问法压力测试。** 每条事实加到 5 种问法，只把其中 1 种放进微调数据。改动位置：`probes.jsonl` 与训练 jsonl。预算：不再训很久，单卡一小时内。预期：未见过的问法上 `Acc^{no}` 下降，但仍高于基座。失败：未见问法掉到基座，说明只背了句子没背槽位。
2. **检索冲突。** 库里同时放 B12 与 D02。$k=3$。预算：不微调。预期：答案在两条之间摇摆或并列，`no_kb` 仍差。失败：模型稳定只答一条且你无法从 top-k 解释为什么，先修检索日志。
3. **LoRA 与全参数的 BWT。** 同一 21 条，两套权重。预算：单卡数小时。预期：LoRA 的旧事实掉得更少或相当，新事实也能升。失败：LoRA 新事实完全不会，回到学习率或 r 是否过小。

顺手映射：本课不是正式复现。第 09 课的续预训练、第 10 课的顺序指令，会把这里的 $2\times 2$ 拉成更大的 $R$。第 13 课用同一 20 条喂 Letta / Mem0，再测冲突写入。到那时对照表会多出一列「外挂记忆，库还在、权重没动」，不要和本课的 SFT 列混成一个「都记住了」。

## 12. 论文与延伸

每篇对应一个能用本课实验回答或明确答不了的问题。读完把答案写进 `NOTES.md`。

1. Wu, Luo, Li, Pan, Vu & Haffari, 2024, *Continual Learning for Large Language Models: A Survey*, [arXiv:2402.01364](https://arxiv.org/abs/2402.01364)。
贡献：续预训练 / 指令微调 / 对齐的阶段划分，以及 RAG、编辑与持续学习各覆盖哪些信息。
机制：Table 1 把信息类型排成 Fact、Domain、Language、Task、Skills (Tool use)、Values、Preference。RAG 覆盖 Fact；Skills (Tool use)、Values、Preference 三格是叉。持续学习三阶段里，事实更新主要落在续预训练，工具技能落在指令微调。RAG 改的是这一次上下文，编辑改局部事实，持续学习改能力本身。
和本课：20 条公司事实落在 Table 1 的 Fact 行。`rag_works_with_kb` 与 `rag_fails_without_kb` 只验证「事实这一行、库在才能查」。技能、偏好本课实验没有执行器，答不了。
阅读问题：id 16「叫小王表示把检索值班拉进当前工单」，按 Table 1 该进 Fact 还是 Skills (Tool use)？若你只考槽位「检索值班」，它仍是事实，本课能打分；若要求模型真的去改工单，本课实验答不了。

2. Harrington et al., 2026, *When Does Continual Learning Require Learning*, [arXiv:2607.07847](https://arxiv.org/abs/2607.07847)。
贡献：同一套顺序协议里比较 prompt、SFT、RL 和上下文压缩，并问何时必须改权重、何时外挂脚手架就够。
机制：更新算子 $\mathcal{U}_k$ 可以改提示、改全参数、写外存或做测试时压缩。HTML Table 1：GEPA / ACE 跨阶段带走的是提示或 playbook，权重不动；SFT / GRPO 带走参数。摘要：prompt 方法新阶段拟合快、后面任务上掉；蒸馏累积更稳但改旧事实慢；压缩提高效率，几乎不提高学新任务的能力。脚手架够不够，取决于世界怎么变（新领域、事实漂移、智能体自己留下的状态）。
和本课：三臂就是三种 $\mathcal{U}$。`prompt_fails_without_context`、`rag_fails_without_kb` 对应「把脚手架撤掉」；`weights_survive_without_context` 对应「写进参数之后还在」。本课没有 GEPA / GRPO，也没有跨阶段事实漂移表。
阅读问题：名录一撤，prompt 臂与 RAG 臂分数掉到 0，权重臂仍 $>0.95$。按这篇的框架，这更像「必须学进权重」还是「外挂仍够」？本课 checks 支持前一句。他们在 Qwen3-8B 上的八方法表，本课实验答不了。

3. Hu, Long & Wang, 2026, *When Continual Learning Moves to Memory: A Study of Experience Reuse in LLM Agents*, [arXiv:2604.27003](https://arxiv.org/abs/2604.27003)。
贡献：说明外挂记忆没有取消持续学习，只是把瓶颈从改参数挪到检索时新旧经验抢窗口。
机制：$(k,v)$ 框架拆两轴：经验怎么表示、检索时怎么组织。顺序任务在 ALFWorld 与 BabyAI 上跑。摘要：抽象的程序性记忆比详细轨迹更好迁移；负迁移更伤难题。更细的组织不保证更好：前向迁移强的设计，也可能忘得更狠。
和本课：`rag_fails_without_kb` 是把库整本撤掉，不是窗口里新旧条目互挤。库还在时 `rag_works_with_kb` 满分，只说明本课 20 条没有发生检索竞争。ALFWorld 上的负迁移本课答不了。
阅读问题：若检索库同时留下 B12 和 D02，本课 RAG 臂还算「外挂解决了持续学习」吗？不能。那是检索冲突，课文改造清单第 2 条才测；CPU 实验的 `rag_with_kb` 是无冲突字典，答不了互挤。

4. Gutiérrez, Shu, Qi, Zhou & Su, 2025, *From RAG to Memory: Non-Parametric Continual Learning for Large Language Models*, [arXiv:2502.14802](https://arxiv.org/abs/2502.14802)。
贡献：把 HippoRAG 做成非参数持续学习，在事实、意义建构和联想记忆三类任务上同时超过标准向量 RAG。
机制：沿用 Personalized PageRank，加强段落接入，并让 LLM 在线更多地参与图上推理。针对「加了知识图之后，基础事实记忆反而掉到标准 RAG 以下」这一退步做修补。摘要称联想记忆任务比当时最强嵌入模型高 7%。知识仍写在图和文档里，不写进生成模型权重。
和本课：CPU 的 RAG 臂是精确字典，没有 PageRank，也没有联想题。`rag_works_with_kb` 只能看见「库在则满分」。那 7 个点本课答不了。库一撤，图也不在，路径与 `rag_fails_without_kb` 同类，但本课没跑他们的图。
阅读问题：HippoRAG 2 若把图和段落都撤掉，还能不能答「小王坐哪」？按非参数设定，不能。本课 `rag_fails_without_kb` 是这个判断的最小版；他们的 7% 本课实验答不了。

5. Gutiérrez, Shu, Gu, Yasunaga & Su, 2024, *HippoRAG: Neurobiologically Inspired Long-Term Memory for Large Language Models*, [arXiv:2405.14831](https://arxiv.org/abs/2405.14831)。
贡献：用海马索引的类比，把语料抽成开放知识图，再用 Personalized PageRank 做单步多跳检索。
机制：离线用 LLM 做 OpenIE，节点是名词短语，边是关系；检索编码器再加同义边。查询抽出实体，链到图上作为种子，跑 PPR，把节点概率汇总到段落。摘要：多跳 QA 上最多高约 20%；单步检索比 IRCoT 一类迭代检索便宜 10–30 倍、快 6–13 倍。改的是索引和检索，不是生成模型的慢速权重。
和本课：本课检索是词重叠或 TF-IDF，没有知识图。`rag_works_with_kb` 在 20 条无多跳时满分，说明「库在就能查」；多跳与路径发现本课答不了。
阅读问题：把 HippoRAG 的图当成名录，藏起来之后权重臂和检索臂谁还会？本课 checks：权重臂会（`weights_survive_without_context`），检索臂不会。PPR 本身本课不跑。

6. Cho, Moon, Chunara, Cho & Cha, 2025, *Forget Forgetting: Continual Learning in a World of Abundant Memory*, [arXiv:2502.07274](https://arxiv.org/abs/2502.07274)。
贡献：当示例记忆足够缓解遗忘、全量重训又太贵时，难题从稳定转到可塑；并提出权重空间巩固。
机制：充足缓冲让回放近似联合分布，遗忘下降，模型偏向旧任务，新任务变难学。方法把两件事合在权重里：按梯度信号把休眠参数重置回预训练值（恢复可塑），训练中做权重滑动平均（增强稳定）。在 class-IL 与 LLM 顺序指令（含 TRACE）上，成本接近朴素回放。
和本课：20 条检索库对座位查询算「记忆充足」。`rag_works_with_kb` 高、`rag_fails_without_kb` 低，说明充足记忆仍停在库里，撤库就不会。他们的参数重置本课不跑。课文微调臂的第 21 条才接近「后来的写入伤可塑性」，CPU 实验没有这一项。
阅读问题：记忆充足时，本课该不该把 RAG 的 `with_kb` 满分写成「已经持续学会」？不该。checks 要求 `no_kb` 上 RAG $<0.15$。GPU 成本对比本课答不了。

7. O'Neill, 2026, *Can a Language Model Learn Facts Continually in Its Weights?*, [arXiv:2607.11020](https://arxiv.org/abs/2607.11020)。
贡献：跟踪写进 Qwen3 权重的虚构事实，看一次写入会不会用、再写 20 到 100 条之后还在不在。
机制：对照是「原模型 + 把事实放进 prompt」。单句训练造成背诵，多样复述把背诵到使用的分差从 27.4 降到 5.4。20 次顺序写入之后单句事实剩 1%、宽数据剩 46%；忘了的事实仍留着写入抬高的对数概率，单句设定下 70% 的错答含最近一条事实。把忘了的学习事实再放回 prompt 恢复到 77–80%，可靠通道仍是上下文。
和本课：`weights_survive_without_context` 是一次写入 20 条、没有后续冲刷，所以闭卷仍 $>0.95$。这答得了「能写进权重」；答不了「再写 20 条之后还剩 1%」。课文 Step 7 的 $2\times 2$ $R$ 才接近顺序写入，CPU 实验没有 BWT。
阅读问题：若第 21 条把小王改到 D02 之后，旧题「B12」全错，按这篇该优先怀疑「权重里擦掉了」还是「问题被新事实抢走了」？本课 CPU 答不了 log-prob。课文要求你至少报 BWT；「再把 B12 塞回 prompt 能不能救回来」本课实验没做。

8. Wu, Wang, Yu, Zhang, Chang & Yu, 2024, *LongMemEval: Benchmarking Chat Assistants on Long-Term Interactive Memory*, [arXiv:2410.10813](https://arxiv.org/abs/2410.10813)。
贡献：用 500 道题考聊天助手的长期交互记忆，覆盖抽取、跨会话推理、时间推理、知识更新和拒答。
机制：证据藏进可加长的用户-助手历史。标准设定约 115k token，加长设定约 500 个会话。系统必须在线把会话写入记忆，全部结束后再答题。记忆拆成索引、检索、阅读。摘要：商业助手和长上下文模型在跨会话记事上准确率掉约 30%。优化包括按轮切分、用事实扩充键、按时间收窄查询。
和本课：20 条是单轮事实，对应五项里的信息抽取最小版。`prompt_perfect_with_context` 在名录仍在窗口时满分；跨会话、时间戳、拒答本课实验答不了。未知 5 题的幻觉列只是拒答的预习。
阅读问题：把名录藏起来之后 prompt 臂为 0，这算 LongMemEval 的哪一项失败？更接近信息抽取失败（证据不在当前窗口、又没有外存）。500 会话上的 30% 掉分本课答不了。

9. Lewis et al., 2020, *Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks*, [arXiv:2005.11401](https://arxiv.org/abs/2005.11401)。
贡献：把稠密检索到的文档当作生成条件，让参数记忆和非参数记忆一起做生成。机制发明处，不是本课主阅读。
机制：参数记忆是预训练 seq2seq，非参数记忆是 Wikipedia 的稠密向量索引，用预训练检索器访问。一种做法整段生成共用同一批段落，另一种每个 token 可以换段落。评测时知识源仍可访问。没有「把 Wikipedia 拔掉再考」这一列。
和本课：Step 4-5 的 RAG 臂是最小版，检索器不端到端训练。`rag_works_with_kb` 对应原文设定；`rag_fails_without_kb` 是本课多出来的闭卷列。原文开放域 QA 数字不能拿来宣称闭卷学会。
阅读问题：Lewis 原文的知识源在评测时还在吗？在。因此那些数字对应本课 `with_kb`。本课实验能答这一句；开放域 SOTA 表答不了。

10. Packer, Wooders, Lin, Fang, Patil, Stoica & Gonzalez, 2023, *MemGPT: Towards LLMs as Operating Systems*, [arXiv:2310.08560](https://arxiv.org/abs/2310.08560)。
贡献：用操作系统式的分层记忆和中断，在有限上下文里虚拟出更长的工作记忆。机制发明处，不是本课主阅读。
机制：上下文当物理内存，外部存储当磁盘。模型通过函数调用换页，用中断把控制交还用户。评测两块：超出窗口的文档分析，以及跨会话聊天。主记忆被换出时，底座权重按设定不变；会的是外挂层次，不是参数里的公司名录。
和本课：`rag_fails_without_kb` 类比把磁盘拔掉。完整换页、自我调用第 13 课再跑。本课没有会话中断。
阅读问题：MemGPT 把小王换出主上下文之后，生成模型的权重变了吗？论文设定下没变。本课 `no_kb` 能类比「外存不在则不会」；换页策略本身本课实验答不了。

公开小模型用 [SmolLM2-135M](https://huggingface.co/HuggingFaceTB/SmolLM2-135M) 或 [Instruct 版](https://huggingface.co/HuggingFaceTB/SmolLM2-135M-Instruct)，revision 写进协议。它们不是论文清单。

第一幕结束。你看见了遗忘，量过了遗忘，也拆开了「上下文里有」和「已经学会」。名录可以塞进 prompt，可以放进检索库，也可以写进 135M 的权重；只有第三种在撤掉名录之后还在，并且它会在第 21 条上露出遗忘。第二幕开始补丁：[第 05 课](05_ewc_regularization.md) 用 Fisher 信息给重要权重加弹簧，第一次在权重更新上正面对抗这件事。
