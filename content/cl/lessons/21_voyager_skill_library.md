# 第 21 课：把成功的程序放进技能库，下次检索再调用

> 类型：机制实验（课内网格世界）+ 体验档（Voyager 官方 Minecraft，只读论文图与公开技能库）<br>
> 建议周期：2-4 天<br>
> 硬件：机制档 CPU 即可；Minecraft 体验档需要 Java 版游戏、Node.js、可调用 GPT-4 的 API<br>
> 锚定仓库：[MineDojo/Voyager](https://github.com/MineDojo/Voyager)（Wang et al., arXiv:2305.16291）<br>
> 产物：技能库「有库 vs 每次从零写」对照、后续任务尝试次数、以及第 16 课矩阵上的书面定位

## 1. 这一课做什么

整门课走到第六幕：在岗学习。上一课（[第 20 课](20_seal_rl_razor.md)）把学习重新接到权重上，一边是 SEAL 那种「自己给自己出微调题」，一边是 RL's Razor 的判断：同样学一件新任务，on-policy 的强化学习比离线监督微调更不易把旧能力冲掉，因为新策略离原模型更近。那一课改的是参数。

本课换零件。新经验不再写进 $\theta$，而是写成一段能在环境里跑通的程序，放进技能库（skill library：按任务描述检索、可再执行的程序抽屉）。下次遇到相近任务，先把旧程序找出来当脚手架，再决定要不要改。Voyager 在 Minecraft 里就是这么干的：自动课程提出下一件不太难的事，语言模型写出可执行代码，环境跑一遍，失败就带着报错和物品栏重写，成功则把程序连同描述的嵌入一并存起来。论文把这叫 in-context lifelong learning（上下文里的终身学习：黑盒查询 GPT-4，不微调权重）。

梁文峰在 2026-05 那场交流的公开转写里说：现在 Agent 能力有限，是因为它不能有效地持续学习；招一个员工要花两个月熟悉公司和同事，你说「把小王叫过来」，他知道小王是谁。这段转写未获 DeepSeek 官方确认，课内只把它当路线判断。第 04、13 课已经能用上下文或外挂记忆处理「小王是谁」这种事实。本课处理另一类东西：一套做过、验证过、下次还能调用的流程。对应 [第 16 课](16_when_weights_must_move.md) 那张「四类经验 × 四种写入」表里的「流程技能 / 记忆」格。推理模式（一种新的计分规则、一种新的拆题习惯）仍然不在这格里，那一口要等权重或等价的内环学习，本课结束时必须把这句话写进交付。

课内分两档，不许混报分数。

体验档：读 [Voyager 项目页](https://voyager.minedojo.org/) 和论文图，按 README 把仓库装到能 import 的程度更好，完整 `learn()` 需要 Minecraft 1.19、Fabric、Mineflayer 和 GPT-4 API，费钱也费环境。官方数字只允许引用论文：160 次提示迭代里发现 63 种独特物品，独特物品数约是对照方法的 3.3 倍，木器科技树约快 15.3 倍，路程约 2.3 倍，技能库拿到新世界做零样本任务时对照方法在 50 次迭代内做不成。这些数字来自 GPT-4 + Minecraft，不是你电脑上那个网格世界。

机制档：课内一个会移动、拾取、合成的网格世界，复现同一条环：提出任务、写程序、环境验证、入库、检索复用。对照条件是每次从零写、不入库。要统计的是后续任务的尝试次数有没有下降。网格世界上的任何次数、成功率、库大小，都只能写成「课内机制数字」，禁止写成「复现了 Voyager」。

没有技能库会怎样：每个新任务都把旧程序扔掉，组合成的任务（先走到树边、再拾取、再合成）会反复在已经会的子步骤上失败。有库之后，旧子程序还在，后续尝试次数应该下降；下降的是「再写一遍」的次数，不是网络里那组权重的遗忘曲线。

术语速查：

| 术语 | 一句解释 |
|---|---|
| 技能库 | 验证过的程序外存：键是描述的向量，值是可执行代码 |
| 自动课程 | 根据当前物品栏和已完成/失败任务，提出下一件不太难的目标 |
| 迭代提示 | 把环境反馈、解释器报错、自我验证评语塞回提示，再写一版程序 |
| 自我验证 | 另一次模型调用，根据状态判断任务是否完成，失败则给修改建议 |
| 描述嵌入 | 把技能说明编成向量，用余弦相似度做近邻检索 |
| 尝试次数 | 同一任务从提出到验证通过，写了几版程序（含失败重写） |
| 机制档 | 课内网格世界，用来钉死「入库是否减少后续尝试」 |
| 体验档 | 官方 Minecraft + GPT-4，本课以读论文图和公开 `skill_library/` 为主 |
| 流程技能 | 第 16 课四类经验之一：一组可重复执行的步骤，不是一条事实 |
| 上下文终身学习 | Voyager 论文用语：能力涨在提示和技能库里，权重不动 |

## 2. 问题

核心问题只有一句：Voyager 把成功的程序放进技能库，下次检索再用不改权重。这算持续学习吗？差哪一口？

拆开是四件要你用实验回答的事。

第一，技能库到底防的是哪种「忘」。[第 01 课](01_catastrophic_forgetting.md) 的遗忘是梯度把旧决策边界抹掉；[第 05 课](05_ewc_regularization.md) 用弹簧钉权重，[第 06 课](06_replay_der.md) 把旧样本带在身上。Voyager 两边都不做。它防的是「提示窗口里不再出现旧程序」：旧代码还在磁盘上，新任务只要检索得到，就能再跑。论文消融里去掉技能库之后，后期发现物品的曲线会趋于平顶。那是探索效率掉下来，不是 CIFAR 上任务 1 的准确率塌掉。两件事都叫遗忘，机制不同，指标也不同。本课机制档用尝试次数，不用准确率热力图。

第二，从零写和入库再调用差在哪。对照组每件任务独立采样程序，成功也不保存。实验组成功就入库，下一件任务先检索再写。若第四件任务是前三件的组合，实验组的尝试次数应明显更低，并且检索日志里能看到旧技能的名字。若次数没有下降，优先查两件事：检索是不是根本没命中；验证器是不是把半成品也标成成功、脏程序进了库。

第三，失败的程序能不能进库。Voyager 的规则是：解释器报错或自我验证判定未完成，就进入下一轮重写；同一任务连续多轮（论文设定为 4 轮）仍过不了，就向课程要另一件任务，当前这版代码不入库。机制档必须断言：验证失败的程序不在库里。否则后续检索会把坏脚本当脚手架，尝试次数不降反升。

第四，这格还缺什么。第 16 课的矩阵里，流程技能用记忆可以通过，推理模式用记忆过不了。技能库能把「合成木板」写成函数，不能把「遇到新的计分规则时改用另一种拆法」写进网络。换一个世界、换一套 API，旧程序可能直接跑不通，而改过权重的策略有时还能摸过去。本课结束时你要能指出：技能库是经验的外存，对应「流程技能 / 记忆」；「推理模式写入权重」留给第 20 课那种更新，以及第 23、24 课的自迭代和上岗实验。

公开转写里还有一句：一次很强的训练不够，要像人一样做比较长期的持续学习。Voyager 的时间跨度是一次 Minecraft 会话里的上百次提示迭代，谈不上两个月上岗。它证明「不改权重也能在开放世界里越玩技能越多」，也把缺的那一口暴露出来：模型本身没有因为会合成钻石而变成更好的同事。

## 5. 原理

五个机制，每个按同一节奏：为什么需要、怎么运转、精确定义、代码落点、怎么验证。网格世界是课内实现，对照论文公式，标成非官方。Minecraft 路径以你克隆的 Voyager README 为准。

### 5.1 用程序当动作，才能把「会了」存下来

低层动作是「向前走一格、挥一次镐」。开放世界里的一件有意义的事（砍树、烧矿、打僵尸）是几十到上百步的时间延展，而且还要能嵌套：打僵尸会用到已经会的「合成木剑」。强化学习在原语动作上探索，组合爆炸很难过；把动作写成程序，组合变成函数调用。类比是厨房里的食谱卡片：卡片可以互相引用。失效处：食谱不会自己变好吃，执行时仍靠当前厨师（语言模型）读懂卡片并调用环境 API；API 换了，卡片可能整张作废。

Voyager 的动作空间是 JavaScript 程序，底层电机由 Mineflayer 提供。课内网格世界把动作收成三类原语：`move(x, y)`、`pick(item)`、`craft(recipe)`。技能是这些原语的有名函数，例如 `collect_wood()` 内部是走到最近的树并拾取。

记环境状态为 $s$，动作为程序 $p$。一次尝试把 $p$ 放到解释器里执行，得到轨迹和终止状态 $s'$。成功谓词 $V(s', g)\in\{0,1\}$ 由环境规则判定（网格世界）或由自我验证模型判定（Voyager）。技能库是集合

$$
\mathcal{L}=\{(d_i, p_i)\}_{i=1}^{N}
$$

其中 $d_i$ 是自然语言描述，$p_i$ 是通过了 $V$ 的程序。学习步骤不包含 $\nabla_\theta$。

官方落点：仓库根目录的 `skill_library/`（公开试验留下的程序和描述），以及 README 里用 `skill_library_dir="./skill_library/trial1"` 加载已有库的用法。课内落点：`experiments/src/learn_cl_experiments/lessons/lesson_21.py` 里的程序表和验证器。

验证：任意入库项执行一次，$V$ 必须为 1。若库里能找出 $V=0$ 的程序，入库门坏了。

### 5.2 自动课程：下一件事要刚好够得着

开放世界没有出题人。太容易则技能不增长，太难则永远写不出能过验证的程序。Voyager 把出题交给另一次 GPT-4 调用，总目标写在提示里：发现尽可能多的不同事物，且下一任务不要超过当前资源与技能。提示还带上物品栏、附近方块、已完成和已失败任务。论文把它看成一种上下文里的 novelty search（新奇搜索：优先做还没见过、但现在有机会做成的事）。类比是教练看你今天会什么再布置明天的课。失效处：模型会胡编不存在的物品（论文限制部分写过「铜剑」「铜胸甲」这种 Minecraft 里没有的目标），课程必须允许「做不出来就换题」，不能卡死。

记当前能力边界为已完成目标集合 $G^+$ 和失败集合 $G^-$。课程是映射

$$
g_{t+1}=C(s_t, G^+, G^-)
$$

约束是：$g_{t+1}$ 对当前 $s_t$ 和 $\mathcal{L}$ 既非平凡，也不是明显不可达。机制档把 $C$ 写成一张固定任务表加解锁规则：只有 `collect_wood` 成功后才提出 `craft_plank`，只有木板和木棍都在库里才提出 `craft_table`。这比 GPT-4 课程窄，但能在 CPU 上重复。

官方落点：论文第 2.1 节与附录 A.3 的课程提示结构。仓库用 `Voyager(...); voyager.learn()` 进入终身探索，课程在学习循环内部调用。机制档的任务顺序写在 `lesson_21.py`。

验证：打乱任务顺序、在没有木板的时候就要求合成工作台，尝试次数应爆炸或直接失败。课程有效的证据是：按解锁顺序时后期任务可完成，乱序时同一预算内完不成。

### 5.3 迭代提示：环境、报错、自我验证三份反馈

语言模型很难一次写出能在模拟器里跑通的程序。Voyager 的修法是把三种反馈写回提示，再生成下一版。环境反馈例如「还差 2 块木板才能合成木棍」；解释器报错指出语法错误或调用了不存在的 API（论文例子：不存在 acacia axe，应改成木斧）；自我验证是另一个 GPT-4 角色，读当前状态和目标，判断是否完成，失败则给评语。同一任务最多 4 轮代码生成，仍失败就向课程换题。类比是编译、运行、代码评审三条意见一起改作业。失效处：自我验证会漏判（论文写过没把蜘蛛丝识别成打赢蜘蛛的信号），网格世界因此改用确定性谓词，避免「评审自己的作业」。

记第 $k$ 版程序为 $p^{(k)}$。更新是

$$
p^{(k+1)}=G\!\left(p^{(k)},\; f_{\mathrm{env}},\; f_{\mathrm{err}},\; f_{\mathrm{crit}},\; \mathrm{top}\text{-}5(\mathcal{L})\right)
$$

$G$ 在官方系统里是 GPT-4；在机制档里是带噪声的模板改写器：从检索到的技能拷贝结构，按验证器给出的缺失物品做一次局部修改。尝试次数就是使 $V=1$ 的最小 $k$，或达到上限 $K$ 仍失败。

官方落点：论文第 2.3 节，图 5、图 6。机制档：验证器返回缺失物品列表，改写器最多 $K=8$ 次。

验证：人为塞一个缺材料的程序，下一轮提示（或改写器输入）必须出现那条缺失信息；连续失败 $K$ 次后该程序不得出现在 $\mathcal{L}$ 里。

### 5.4 技能库：描述嵌入、近邻检索、组合调用

库要解决两件事：找到相关旧技能，以及让新技能可以调用旧技能。Voyager 用 GPT-3.5 给程序写一段描述，再用 `text-embedding-ada-002` 把描述编成向量当键，程序当值。新任务到来时，先让模型写解题提纲，再和提纲、环境反馈一起查询，取 top-5 相关技能放进写代码的提示。复杂技能通过调用简单函数往上堆，能力按组合增长。类比是按菜名搜食谱，新菜谱可以写「先做高汤」。失效处：嵌入只看文字像不像，不保证程序在当前世界还能跑；「打蜘蛛」和「打僵尸」描述相近，API 也相近，换成「修漏水的淋浴头」这种第 24 课公司模拟里的任务，Minecraft 技能一张都用不上。

查询向量 $q$ 来自当前任务描述（机制档直接用任务名的词袋；官方用提纲嵌入）。检索分数

$$
\mathrm{sim}(q, d_i)=\frac{q^{\top} d_i}{\|q\|\,\|d_i\|}
$$

取最大的 $k$ 个（官方 $k=5$，机制档 $k=3$）作为 $G$ 的上下文。入库只在 $V(s',g)=1$ 之后发生：

$$
\mathcal{L}\leftarrow\mathcal{L}\cup\{(d_{\mathrm{new}}, p^{\star})\}
$$

$p^{\star}$ 是通过验证的那一版。$\theta$ 不进入这两条式子。这就是和 EWC、LoRA、SEAL 的分界：那些方法的状态在参数里，这里的状态在 $\mathcal{L}$ 里。

官方落点：README 的 `skill_library_dir` 与 `ckpt_dir` 必须分开，注释写明新事件仍会记到 `ckpt_dir`，不要和技能库用同一个目录。公开目录 `skill_library/trial1` 是论文试验留下的库，可当即插即用资产；论文表 2 里 AutoGPT 戴上这座库，部分零样本任务从 0/3 变成有成功。机制档用字典加词袋余弦，不调用嵌入 API。

验证分三条：入库后 $N$ 加一；对组合任务，命中的近邻应包含至少一个子技能名字；把库清空再跑同一组合任务，尝试次数应回升到从零写的水平。

纸面走一遍四件任务，方便你对 CPU 输出。假设写错概率 $0.4$，无库时每件任务独立重来。`collect_wood`、`craft_plank` 两边都大约 2 到 4 次。`craft_stick` 无库仍要重写「先有木板」这段，有库则直接调用 `craft_plank`。`craft_table` 无库要把走、拾、两步合成全部再蒙一遍，常见是 6 到 8 次打满上限；有库时检索应返回 `craft_plank` 与 `craft_stick`，再补一次「把两者放进工作台配方」，2 到 3 次就过。数字会随种子抖，方向不能反：后期任务的差距必须大于前期。若任务 1 就差出 5 次、任务 4 反而不差，是计数器把「检索本身」也算进了尝试，或把库预装进了对照组。

### 5.5 这算持续学习吗，差哪一口

Zheng et al. 2025（arXiv:2501.07278）把终身 LLM Agent 拆成感知、记忆、动作三块，记忆再分成工作记忆、情节记忆、语义记忆、参数记忆。Voyager 的技能库落在「动作（代码落地）」加「外置的程序性记忆」，不落在参数记忆。Generative Agents（Park et al., arXiv:2304.03442）的记忆流存的是自然语言观察、反思和计划，检索按近因、重要性和相关性加权；那是社会行为的日记，不是可执行技能。两者都证明：权重大块不动时，外存也能让行为跨时间变一致。两者也都停在同一条线外：模型没有因为这些外存而改掉自己的推理习惯。

第 16 课的通过矩阵里，流程技能允许走记忆，推理规则（新计分法；课程蓝图里也叫推理模式）要求走权重或测试时内环。本课实验能让「合成工作台」从第 4 次尝试降到第 2 次，不能让 Agent 在计分规则被改成「偶数格加倍」之后自己改策略。后一件事如果只往技能库里塞旧程序，检索到的还是旧计分法。

技能库缓解的遗忘，不是把旧权重钉住，而是根本不去改那些权重。代价同样清楚：环境 API 一变，外存里的程序成批失效，没有像 on-policy 小步更新那样把旧策略平滑迁到新分布上。第 22 课会把数据来源改成「环境自己长出新配方」，看三种数据河谁还能给库续上新卡片。

和前几幕的零件并排看，分工会清楚很多：

| 写法 | 状态写在哪 | 旧能力怎么保 | 本课实验看得到吗 |
|---|---|---|---|
| EWC / O-LoRA | 权重或低秩方向 | 弹簧、正交 | 看不到，本课不改 $\theta$ |
| 回放 / DER | 样本袋 + 权重 | 混旧数据再训 | 看不到 |
| RAG / MemGPT | 文档或日记 | 下次检索原文 | 第 13 课，存的是事实 |
| 技能库 | 程序文件 | 下次检索函数 | 本课主实验 |
| SEAL / on-policy | 权重 | 更新离原策略近 | 第 20 课，本课只对照 |

验证（书面，第 9 节打分）：你能指出本课对应第 16 课哪一格、缺哪一格；能解释为什么官方 3.3 倍独特物品不能写进机制档的 `result.json`。

这些是官方实现事实，不是本课要证明的假设：

- Voyager 用黑盒 GPT-4 查询，不微调模型参数。
- 动作是代码，不是像素上的鼠标键盘；和 VPT、DreamerV3 那种从画面输出键鼠的路线不可比分数。
- 去掉技能库之后，论文消融显示后期探索趋于平顶；木器、石器、铁器仍可能被自动课程推过去，钻石层在无库时 0/3。
- 技能库可以摘下来给 AutoGPT 用，论文把它写成即插即用资产。
- 论文自述的失败模式包括：GPT-4 费用约为 GPT-3.5 的 15 倍且代码质量不可替换、课程会提出不存在的物品、自我验证会漏判、生成代码会调用未提供的 API。

机制档故意砍掉的东西也写在这里，避免你回头对不上论文：没有 GPT，没有 Mineflayer，没有 3D 地形，检索是词袋余弦而不是 `text-embedding-ada-002`。它只负责钉死「入库是否减少后续尝试次数」。

## 7. 实验

三层都要做。浏览器层先预测再运行。CPU 层用断言钉机制。锚定仓库层以读公开技能库为主，完整 Minecraft 标成可选体验，成功与否不计入本课验收。

### Step 1: 浏览器实验「技能抽屉」

打开本课网页实验（课程元数据里的 `lab-21-skill-drawer`）。界面是三张已完成的卡片和第四件新任务。卡片是「走到箱子」「捡起木头」「合成木板」。第四件任务是「合成木棍」：对口检索是「合成木板」，不是从零写。

先预测，再运行。预测问题与 lab 一致：检索对口的「合成木板」后，尝试次数会比从零少吗？选项：「会更少」「不会更少」。过关条件：你选出「会更少」，并且检索的是「合成木板」这张卡。lab 里从零基线 16 次，检索合成木板 5 次；选错卡片（走到箱子 12、捡起木头 9）不会过关。改选卡片必须作废上次运行，重新预测。

这个实验不训练网络。它把 5.4 的检索写成一次点击：你选哪张卡片，就等于把哪段程序拼进当前提示。选错卡片（例如第四件任务去检索「走到地图另一角」）步数不会下降，用来演示「库在但检索错了等于没库」。

预测时先对照 lab 基线：从零写 16 次，检索「合成木板」5 次。差距来自少走的弯路，权重没有变。若你预测「不会更少」却看到次数腰斩，回头看自己有没有把「合成」理解成单步魔法。

### Step 2: CPU 机制实验

在 `experiments/` 目录：

```bash
python3 run.py run 21
```

脚本是 `src/learn_cl_experiments/lessons/lesson_21.py`，固定种子，结果写到 `artifacts/lesson21/result.json`。`python3 run.py run 21` 现在应当全绿。网格世界四件任务：`collect_wood`、`collect_stone`、`craft_plank`、`craft_axe`。后一件依赖前几件的技能。

程序生成器带噪声：同一任务会抽到错误原语，所以从零写需要多次尝试。有库时先按标签检索并组合旧程序，验证器用环境规则，不调用语言模型。

对照两条轨迹：无库全程不入库；有库成功即入库。只比较后两件的平均尝试次数（前两件两边都要从零学）。

`checks` 下列六条必须全真，并且必须能失败：

| 键 | 为真的条件 |
|---|---|
| `library_cuts_later_attempts` | 有库时后两件平均尝试次数小于无库 |
| `later_with_library_is_short` | 有库后期平均尝试次数不超过 2.0 |
| `library_grows_after_success` | 有库结束后库大小至少为 2 |
| `later_task_reuses_skill` | 后期任务检索到了旧技能 |
| `from_scratch_has_empty_library` | 无库轨迹的库大小为 0 |
| `all_tasks_eventually_succeed` | 两条轨迹上四件任务最终都成功 |

`metrics` 里看 `later_mean_with_library`、`later_mean_without_library`、`library_size`、`with_library_attempts`、`without_library_attempts`。本机一次运行：有库后期平均 1.00 次，从零 5.00 次；库 4 条。有库四件尝试次数是 3、15、1、1，无库是 3、14、8、2。换机器会变，方向不应变。这些是课内网格世界次数，不是 Voyager 官方 63 种物品。

本课技能库卸掉就空。要把流程编译进权重，再卸库仍能取出：

```bash
python3 run.py extra run skill
```

`library_empty_when_unplugged` 必须为真；`torch_survives_unplug_in_weights` 也必须为真。这是 Voyager 差的那一口：卡片是外存，巩固之后才是持续学习。

和新技能抢同一方向会冲掉旧的，对照：

```bash
python3 run.py extra run ortho
```

库里没有「火把」这张卡，两个已编译技能拼起来，卸掉库还能取：

```bash
python3 run.py extra run compose
```

日记、技能卡、提示名录一起卸掉，权重里还要留座位、流程、计分：

```bash
python3 run.py extra run graduate
```

GPU 上没有官方「把技能库蒸进权重」的一键脚本；能改权重的最近仓库是第 20 课的 SEAL 和 rl-razor-mnist。Voyager / AWM 本身见 `gpu print voyager`、`gpu print awm`。

### Step 3: 读公开技能库（体验档，不启动游戏）

```bash
git clone https://github.com/MineDojo/Voyager.git
```

论文表 2 的零样本任务（钻石镐、金剑、岩浆桶、指南针）是新世界、清空物品栏之后的测试。你在这一步只确认「库是普通文件，可以换目录加载」，不要根据自己没跑过的游戏去改论文表格。

```python
    "client_id": "YOUR_CLIENT_ID",
```

## 9. 验收

- 浏览器：先预测「检索合成木板会更少」，并选中那张卡，运行后反馈为对。
- CPU：`python3 run.py run 21` 的 `checks` 全真。本机一次运行有库后期平均 1.00 次、从零 5.00 次、库 4 条；换机器会变，方向不应变。
- 对照表：有库/无库的后两件尝试次数写在同一张表，注明「课内网格世界」，不要写成 Voyager 官方 63 物品。
- 书面判断（必交，五到十句）：本课对应第 16 课「流程技能 / 记忆」格；权重未变；还缺「推理模式写入权重」。点名至少一件技能库做不到的事（新计分规则、新 API、新运动策略）。
- 体验档若跑了 `learn()`：另开一节，标题写「体验档，非复现」，只对照论文图的方向，不把数字合并进机制表。
- 禁止项：标题或摘要出现「复现 Voyager」；把网格世界次数和 3.3 倍、15.3 倍写在同一单元格。

## 10. 排错

| 症状 | 原因 | 验证 | 修法 |
|---|---|---|---|
| `library_cuts_later_attempts` 为假 | 检索没命中，或对照也预装了库 | 看 `later_mean_with_library` 是否仍大于等于无库 | 先查 `later_task_reuses_skill`，再查 `from_scratch_has_empty_library` |
| 有库次数不下降 | 检索没命中，或组合程序没被调用 | 看 `later_task_reuses_skill` 和 `library_size` | 先确认成功才入库，再检查后期任务是否走了 `_compose` |
| 任务 4 两边都是 1 次 | 生成器没有噪声，对照被做塌 | 看写错概率是否为 0 | 恢复噪声，不要手写完美程序 |
| `pip install -e .` 失败 | Python 版本或依赖冲突 | `python3 --version` 是否 ≥ 3.9 | 单独虚拟环境，不要和日常包混装 |
| `Subprocess Mineflayer failed to start` | Node 依赖或 `tsc` 没做完 | FAQ：`node index.js` 有无监听 | 按 Step 4 重装 `voyager/env/mineflayer` |
| 课程提出不存在的物品 | GPT-4 幻觉，论文第 4 节写过 | 日志里是否出现铜剑、铜胸甲 | 体验档可忽略并换题；机制档用固定任务表 |
| 自我验证漏判成功 | 论文已知限制 | 物品栏其实没达标 | 机制档改用环境谓词，不要学这一步的「宽松」 |
| 想把官方 63 种物品写入 `result.json` | 档位混淆 | `result.json` 是否出现 Minecraft 字段 | 删掉。官方数字只留在书面体验档 |

## 11. 前沿与改造

前沿怎么做。2023 年之后，技能库思路被接到更多 Agent 框架里：程序当动作、检索当记忆、环境当验证器。Zheng et al. 2025 的路线图把它放在动作与外置记忆交叉处，并单独留出参数记忆一章，等于承认「只外存」不够。近两年同方向的主阅读是 Agent Workflow Memory（网页上的可复用工作流）和 Hu et al. 2026：外存把遗忘战场挪到检索，并不自动取消稳定性-可塑性。Voyager 自己列的后续是视觉感知、更便宜的开源写码模型和机器人约束。和本课同时存在的另一条线是第 20 课：SEAL 用强化学习优化「给自己的编辑」，RL's Razor 要求更新离原策略近。把技能库和 on-policy 更新接起来，才接近转写里那个「两个月后更熟的同事」。

我们差在哪。机制档没有语言模型，检索是词袋，课程是一张表。体验档能跑官方环，但权重仍冻着。两者都没有「新推理模式进 $\theta$」。网格世界也没有非平稳配方，那是第 22 课的零件。

动手改造清单：

1. 检索改成字符 n-gram 或本地句向量，文件仍在 `lesson_21.py` 的检索函数。预算：CPU 一小时。预期：任务名改写成同义短语后仍能命中。失败标准：同义查询命中率为 0，或无关技能排到第一。
2. 给库加过期：环境把 `craft_table` 的配方改掉之后，旧程序执行失败应降权或移出检索。预算：半小时改验证器。预期：过期后任务 4 尝试次数回升，且日志标出「旧技能失效」。失败标准：旧程序仍被当成成功脚手架。
3. 把第 20 课的二维图景接进来：同一套新任务，比较「只追加技能库」和「对程序选择器做 on-policy 小步」。预算：若 `lesson_20.py` 已落地，加一个对照开关即可。预期：只追加库时旧程序完整保留；小步更新时旧任务保持率下降但新任务泛化更好。失败标准：两种条件的旧任务保持率没有可解释的差别。
4. 体验档只读改造：从 `skill_library/trial1` 统计「被其他技能调用的函数比例」。预算：一次写脚本。预期：组合比例显著大于 0，和论文「compounding」叙述同方向。失败标准：全部技能都是叶子、互不调用，却仍在报告里写「看到了组合」。

顺手复现映射：本课不在 CURRICULUM §4 的五项正式复现里。官方 Minecraft 分数标「只讲 / 体验」。方向性现象「有库则后续尝试下降」是课内机制，不是 Wang et al. 2023 的复现声明。

## 12. 论文与延伸

1. Wang, Xie, Jiang, Mandlekar, Xiao, Zhu, Fan & Anandkumar, 2023, *Voyager: An Open-Ended Embodied Agent with Large Language Models*, [arXiv:2305.16291](https://arxiv.org/abs/2305.16291)。
贡献：自动课程 + 可执行技能库 + 迭代提示，黑盒查询 GPT-4，Minecraft 里做上下文终身学习。机制发明处，不是本课主阅读。
机制：课程提出下一件够得着的目标；成功的程序连同描述嵌入写入技能库；新任务用余弦取相关技能再写代码。摘要写独特物品约 3.3 倍、路程约 2.3 倍、科技树关键节点至多约 15.3 倍快。损失不碰到 $\theta$。失败带着环境反馈和报错重写，不入库。
和本课：五步环和 `lesson_21.py` 的入库门、检索、`_compose` 都从这里来。`library_cuts_later_attempts`、`later_task_reuses_skill`、`library_grows_after_success` 对应「有库则后续少试、会调旧程序」。3.3 倍那些数只许进体验档，写不进 `result.json`。
阅读问题：`from_scratch_has_empty_library` 为真时，无库轨迹还是四件都成功（`all_tasks_eventually_succeed`）。这能验证论文「去掉技能库则钻石层三局全失败」吗？若不能，差在本课没有一层「无库就完不成」的任务。

2. Wang, Mao, Fried & Neubig, 2024, *Agent Workflow Memory*, [arXiv:2409.07429](https://arxiv.org/abs/2409.07429)。
贡献：从经验里归纳可复用工作流，下次相关任务把工作流塞进提示，不改模型权重。
机制：工作流是一段常被复用的动作套路。离线可从训练例子先归纳，在线可在测试查询上当场归纳，再按需提供给智能体。改的是外存和工作流检索。摘要写 Mind2Web、WebArena 相对成功率分别提高 24.6% 和 51.1%，在线设定在任务分布差变大时仍比基线高 8.9 到 14.0 个绝对点。
和本课：同一句话「把成功流程留下，后续步数下降」。`library_cuts_later_attempts` 和 `later_with_library_is_short` 是网格世界版。网页基准上的百分点本课实验答不了。
阅读问题：AWM 的在线归纳对应本课哪一段代码：成功才 `add`，还是 `_compose` 调旧程序？用 `later_task_reuses_skill` 回答你看见的是哪一句；Mind2Web 的 24.6% 必须写「本课实验答不了，因为没有网页环境」。

3. Zheng, Shi, Cai, Li, Zhang, Li, Yu & Ma, 2025, *Lifelong Learning of Large Language Model based Agents: A Roadmap*, [arXiv:2501.07278](https://arxiv.org/abs/2501.07278)（v2, 2026-01-11；Comments 写 Accepted to IEEE TPAMI）。
贡献：把终身 LLM Agent 拆成感知、记忆、动作，并讨论如何把终身学习接进这三块。
机制：感知负责多模态输入，记忆负责随时间存取，动作负责跟活环境接地。记忆再分工作 / 情节 / 语义 / 参数。Voyager 式技能库落在外置程序性记忆加动作，不落在参数记忆。它不改你的损失，只给你一张格子图。
和本课：`from_scratch_has_empty_library` 为真、有库时 `library_grows_after_success` 为真，全程没有训练循环。这是「外存在长、$\theta$ 没动」的证据。路线图里参数记忆、感知模块本课答不了。
阅读问题：按他们的定义，本课实验有没有改到 parametric memory？把 `library_size` 和「有没有 `optimizer.step`」两件事一起写进答案。

4. Hu, Long & Wang, 2026, *When Continual Learning Moves to Memory: A Study of Experience Reuse in LLM Agents*, [arXiv:2604.27003](https://arxiv.org/abs/2604.27003)。
贡献：外存并不能取消持续学习，只是把稳定性-可塑性挪到记忆访问上。
机制：用 $(k,v)$ 框架拆开两根轴：经验怎么表示、怎么组织以便检索。窗口有限时，新旧经验在检索时互抢。ALFWorld 与 BabyAI 的顺序任务上，抽象的程序性记忆比细轨迹更好迁移；组织得更细不一定更好，前向迁移强的设计也可以带来更重的遗忘。
和本课：技能库的值是程序元组，键是标签，对应他们说的程序性表示。`later_task_reuses_skill` 能看见检索复用。本课库只增不删、没有容量上限，所以「窗口里新旧互抢」和「细组织伤遗忘」两句答不了。
阅读问题：若给 `SkillLibrary` 加一个容量 $N=2$，后期 `craft_axe` 还能否命中 `collect_wood`？本课默认实验没有这个上限，必须写「本课实验答不了，差在库无容量」；你若自己改了代码，用 `later_task_reuses_skill` 报方向。

5. Xu, Liang, Mei, Gao, Tan & Zhang, 2025, *A-MEM: Agentic Memory for LLM Agents*, [arXiv:2502.12110](https://arxiv.org/abs/2502.12110)（Comments 写 NeurIPS 2025）。
贡献：按卡片盒原则给记忆动态建链接，新记忆进来时允许改旧记忆的上下文表示。
机制：一条新记忆先写成带描述、关键词、标签的笔记，再在历史笔记里找相关链接。随后可以触发旧笔记的属性更新，记忆网自己长结构。改的是外存拓扑，不是 $\theta$。摘要写在六个基础模型上优于所列 SOTA，具体百分点摘要未列。
和本课：`SkillLibrary.add` 只追加，不改已有 `tags` / `program`。`library_grows_after_success` 验证的是「成功才多一条」，验证不了「旧技能被重写」。动态链接那句本课答不了。
阅读问题：任务 3 入库之后，任务 1 的 `collect_wood` 条目有没有被改写？打开 `lesson_21.py` 的 `add` 回答；若只看到 append，就说明本课没有 A-MEM 那种记忆演化。

6. Chhikara, Khant, Aryan, Singh & Yadav, 2025, *Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory*, [arXiv:2504.19413](https://arxiv.org/abs/2504.19413)。
贡献：从多轮对话里抽取、合并、检索要点，给生产 Agent 做可扩展长期记忆。
机制：对话进、短事实出，可选图结构记关系。评测在 LOCOMO 上对照记忆系统、不同块大小的 RAG、全上下文等。摘要写相对 OpenAI 的 LLM-as-a-Judge 提高 26%，相对全上下文 p95 延迟低 91%、token 费用低 90% 以上。存的是对话事实，不是可执行程序。
和本课：第 13 课的日记路径。本课 `_compose` 调的是程序元组，`_execute` 要求程序等于解。把 `collect_wood` 换成一句自然语言，任务 4 过不了这条门。LOCOMO 的 26% 本课答不了。
阅读问题：若检索返回的是日记句子而不是 `("goto_wood", "pickup")`，`library_cuts_later_attempts` 还会为真吗？用 `_execute` 的相等判定回答。

7. Gao, Geng, Hua, Hu, Juan 等, 2025, *A Survey of Self-Evolving Agents: What, When, How, and Where to Evolve on the Path to Artificial Super Intelligence*, [arXiv:2507.21046](https://arxiv.org/abs/2507.21046)（v4, 2026-01；Comments 写 TMLR 2026-01）。
贡献：按演化什么、何时演化、怎么演化整理自演化智能体，对象包括模型、记忆、工具、结构。
机制：把适应方法分成测试时之内和测试时之间，反馈可以是标量奖励或文本。它是分类框架，不给你一条新损失。本课技能库落在「演化记忆、任务与任务之间」：成功验证后把程序写入 $\mathcal{L}$。
和本课：`library_grows_after_success` 证明记忆在任务之间变了；代码里没有 `optimizer`，模型没演化。工具演化和结构演化本课答不了。
阅读问题：按这篇的 what / when / how，本课 CPU 实验演化的是哪一项？用 `library_size` 从 0 长到至少 2、以及「有没有改权重」两句作答。

8. Fang, Peng, Zhang, Wang, Yi 等, 2025, *A Comprehensive Survey of Self-Evolving AI Agents: A New Paradigm Bridging Foundation Models and Lifelong Agentic Systems*, [arXiv:2508.07407](https://arxiv.org/abs/2508.07407)。
贡献：用输入、智能体、环境、优化器四件描述自演化智能体，并按被优化的零件综述方法。
机制：反馈从环境回到优化器，优化器可以改提示、记忆、工具或权重。本课的优化器是：验证谓词 $V=1$ 才 `add`，梯度为 0。失败的候选在 `_solve` 里被丢掉，不进 `skills`。
和本课：入库门就是这篇说的「环境反馈驱动的优化」，只是优化对象是库不是 $\theta$。`library_grows_after_success` 为真时库至少 2 条。领域约束下的专用演化（生物医学、金融）本课答不了。
阅读问题：若把 `add` 挪到 `_execute` 为假时也执行，哪两条 check 应先翻？先猜 `library_cuts_later_attempts` 和 `later_task_reuses_skill`，再说明本课默认实验没有单独的「失败拒收」键，所以你必须改代码才能验证。

9. Tu, Fang, Wang, Xie & Yan, 2026, *Chain-of-Experience for Continual LLM Improvement*, [arXiv:2608.18027](https://arxiv.org/abs/2608.18027)。
贡献：把测试时反复和环境或自身反馈交互、留下经验再生成下一轮，叫做 Chain-of-Experience。
机制：反馈可以是对错、公开测试通过率，或模型自评。摘要写 8 个模型上总体提高 5.6%、API 费用低 19%，多数收益出现在迭代早期。改的是推理时的经验痕迹，不保证写成可跨任务调用的程序文件，也不改慢速权重。
和本课：同一任务里带噪声重采样，最多 `cap=24`，像一次测试时迭代。跨任务能少试，靠的是库还在：`later_task_reuses_skill`。5.6% 那张跨模型表本课答不了。
阅读问题：本课的尝试循环有没有把失败痕迹写成下一次提示里的工作流？看 `_solve`：失败只是换一个候选，不写回库。这和 CoE「留下经验痕迹」差在哪一句？用代码回答，不要用 5.6%。

10. Wu, Ji, Kawatkar, Kwan, Gu, Peng & Chang, 2026, *LongMemEval-V2: Evaluating Long-Term Agent Memory Toward Experienced Colleagues*, [arXiv:2605.12493](https://arxiv.org/abs/2605.12493)。
贡献：换一套评测：记忆系统有没有把环境里的界面、状态、工作流和坑内化成「熟同事」。
机制：451 道人工题，五类能力（静态状态、动态状态、工作流知识、环境坑、前提意识）。历史最长 500 条轨迹、115M token。记忆系统先消化历史，再交压缩证据去答题。AgentRunbook-C 把轨迹当文件、让写代码的智能体取证，摘要平均准确率 72.5%，最强 RAG 基线 48.5%。
和本课：五类里最接近的是工作流知识；`later_task_reuses_skill` 是缩小版「还会不会调用旧流程」。451 题、72.5%、115M token 本课答不了。
阅读问题：本课四件任务里，哪一件最像「工作流知识」，哪一件更像「静态状态召回」？用 `craft_axe` 是否调用 `collect_wood` / `collect_stone` 回答；论文里的环境坑（gotchas）必须写「本课实验答不了」。

现在系统多了一层外存：成功的流程可以留下，下次少试几次。权重仍是第 20 课结束时的那一份。下一课（[第 22 课](22_era_of_experience.md)）把网格世界改成会自己长出新配方，比较专家包、离线随机轨迹、on-policy 交互三条数据河。技能库解决「写到哪里」，经验时代要回答「数据从哪来」。
