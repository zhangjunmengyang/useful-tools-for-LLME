# 第 18 课：小模型的结论什么时候能外推

> 类型：研究（研究手艺课：在自己复现过的系统上设计并跑一个 mini scaling study）<br>
> 建议周期：5-8 天（人的操作集中在开头半天设计、结尾一天分析，中间大段是机器挂机）<br>
> 硬件：单张 24GB 卡；多点乘多种子是整门课最烧卡的作业，第 8 节给"最小可信配置"和"从简阉割版"两档预算；Mac/纯 CPU 可完成设计、读论文和分析日志，跑不动网格<br>
> 锚定仓库：[NM512/dreamerv3-torch](https://github.com/NM512/dreamerv3-torch)（第 06 课的设置原地复用，含基线），备选轨道 [eloialonso/iris](https://github.com/eloialonso/iris)（第 09 课的设置）<br>
> 产物：一份 mini scaling 报告，两条轴、九个网格点、每点三种子、连续与门槛两类指标，外加"这个实验能说什么/不能说什么"一节

## 1. 这一课做什么

前面的实验都使用缩小配置：较窄的 Dreamer、单游戏的 IRIS、CIFAR-10 上的 I-JEPA。
本课讨论这些结论在模型或数据放大后是否仍然成立。一次小规模实验没有提升，只能说明
某个想法在当前模型、数据和预算下没有提升；它不能自动推广到所有规模。

反过来，模型变大后刚好越过一个达成门槛，也不等于能力突然出现。若底层连续指标平滑
变化，而评测只输出“过线 / 未过线”，阶梯形状可能由量法本身产生。因此缩放实验需要
同时报告连续指标、门槛指标和种子方差。

常见做法是在正式投入大规模训练前，先用一系列较小模型拟合趋势。Genie 论文
专门有一节 Scaling Results（40M 到 2.7B 参数的动力学模型系列），DreamerV3 论文给
了 12M 到 400M 六个尺寸的单调曲线。第 12 节带你把这些原文逐段读掉。

接下来会用三档规模、三个随机种子画出误差棒图，再把同一批数据转换成达成率阶梯图，
比较两种呈现带来的结论差异。结果用于判断第 19 课的结构改动是否值得追加预算。下一幕
补 3D/4D 与物体槽，再接到桌宠；验证者是真实桌子上的物理后果。

术语速查：

| 术语 | 一句人话 |
|---|---|
| scaling study / 缩放实验 | 沿着某条"规模"轴（参数、数据……）摆一串点，每点跑同样的实验，看指标怎么随规模变 |
| 轴（axis） | 被缩放的那个量；本课四条候选轴：参数量、数据量、可见历史/想象长度、状态表示宽度 |
| 网格（grid） | 轴上的点乘上种子组成的实验矩阵；本课是 3 点乘 3 种子 |
| 幂律（power law） | $y = c \cdot x^{\alpha}$ 型的关系，在双对数坐标上是一条直线；缩放律的标准形状 |
| compute-optimal | 同一笔算力预算下，参数和数据怎么分配最划算，Chinchilla 回答的问题 |
| 连续指标 | 随规模平滑变化的读数，如 loss、评估回报均值 |
| 门槛指标 | 只回答"过没过线"的读数，如"评估回报是否达到 700"；能力类指标天生长这样 |
| 达成率 | 门槛指标的汇总：多少比例的种子（或局）过了线 |
| 涌现（emergence） | "小模型完全没有、大模型突然有"的能力跳变；本课的核心怀疑对象 |
| 种子方差 | 只换随机种子、其余全同的两次训练之间的差异；深度 RL 里大得出名 |
| 截面 | 网格在某个固定坐标上的切片，比如"所有 run 在 3e5 步时的评估回报" |
| 外推（extrapolation） | 在拟合区间之外使用趋势线；本课教你判断自己有没有资格这么做 |

## 2. 问题

三个问题，加一条界限。

1. 网格怎么设计才不白跑？四条轴选哪两条、点为什么要按等比排布、种子为什么是
   网格的一部分而不是可有可无的装饰、预算怎么在"点数、种子数、每点步数"三者之间
   分配。这些决定要在开跑前做完并写下来，跑完再改设计，等于让数据挑选结论。
2. 同一份数据怎么读出两种故事？每条 run 同时记两类指标：连续的（评估回报
   曲线）和门槛的（"过 X 分"的达成率）。你会看到它们讲出矛盾的故事，并学会
   识别两类经典错误：**把噪声当趋势**（种子太少，两点间的差异还没有种子间的散布
   大）、**把量法的锯齿当涌现**（连续指标平滑爬坡时，门槛指标照样会跳崖）。
3. 结论怎么写？本课的交付物是报告，报告的写法本身就是教学核心：结论只能写成
   "在这份数据、这个模型、这笔算力和这些种子下观察到什么"，不能写成"这个方向
   不行"。第 5.5 节给出句式模板和"什么时候有资格外推"的判断标准。

界限先划清。我们的网格是 3 点乘 3 种子乘单任务，加上从曲线上免费切出的数据轴，
总共覆盖不到一个数量级的规模跨度。这个体量够练手艺、够看方向、够识别两类错误，
不够下任何"规模趋势"的判决，Kaplan 那种趋势跨七个数量级的话语权，是几百个
模型买来的。我们买的是同款手艺的缩小版，不是同款话语权。报告里的每句话都要配得上
自己的预算。

## 4. 学习目标

1. 给任何一个你能训练的系统挑出两条缩放轴，写出完整预算表（点数、种子数、每点
   步数、预计卡时），并说清被扔掉的轴将来怎么补；
2. 解释网格设计的三条规矩：点按等比排布、每点至少三种子、预期在开跑前写死；
3. 从一堆 `metrics.jsonl` 里抽出任意截面，画出带种子散点的趋势图；
4. 用一行正态分布的数学解释：为什么连续指标平滑时门槛指标仍会跳变，并在自己的
   数据上演示"涌现点随门槛取值移动"；
5. 判断两个网格点之间的差异是趋势还是噪声（散布对比加排序交错检验）；
6. 把实验结论写成条件化观察句式，并说出外推需要的三个条件；
7. 对 Kaplan、Chinchilla、Schaeffer 三篇论文，各说出一句"它对我这份九条 run 的
   数据意味着什么"。

## 5. 原理

五个机制，老规矩五步走：直觉、机制、数学、代码落点、验证。前两个讲缩放律本身
（趋势线怎么画、算力怎么分），后三个讲读数的陷阱和结论的写法，后三个才是本课
重点。

### 5.1 缩放律：趋势线是怎么画出来的

买不起大的，就用一串小的画方向。这话听着像穷人的自我安慰，但它是过去
几年大模型工业的核心操作：在正式砸钱之前，用一系列小模型把"损失随规模怎么降"
的曲线画出来，如果这些点在某种坐标下排成直线，就赌它再往外延伸一段仍然是直线。
Kaplan 等人 2020 年那篇《Scaling Laws for Neural Language Models》把这件事变成了
方法：语言模型的交叉熵损失随参数量、数据量、算力各自呈幂律下降，部分趋势跨越
七个数量级依然成立。注意这句话的两个成分：幂律（形状）和七个数量级（拟合
区间）。形状给了外推的公式，区间给了外推的胆量，缺一个都只是猜。

幂律的可用性来自它在双对数坐标下是直线：把 x 轴和 y 轴都取对数，幂律
变成线性关系，三个点就能目测直不直，五个点就能拟合斜率。这决定了网格设计的第一
条规矩：**点要按等比排布**（128、256、512，而不是 128、192、256），等比的点在
log 轴上等距，趋势的形状才不被采样方式扭曲。本课的参数量轴就是这么排的：模型
宽度逐点翻倍。

Kaplan 形式的幂律，以参数量 $N$ 为例：

$$
L(N) \approx \left(\frac{N_c}{N}\right)^{\alpha_N}
$$

取对数：$\log L = \alpha_N \log N_c - \alpha_N \log N$，斜率 $-\alpha_N$ 就是
"规模每翻十倍，损失降多少"的汇率。数据量 $D$、算力 $C$ 各有一条同型的定律。
要小心的是这个公式的适用面：它描述的是**损失**这种连续、无上限饱和的量。你的
评估回报不是，walker_walk 满分 1000，曲线靠近上限时必然压扁，什么定律都会
失真。这是选任务时就要想到的事，第 10 节的症状表会再遇到它。

本课的参数量轴落在 `configs.yaml` 的三个顶层键上：`dyn_hidden`
（RSSM 内部各线性层的宽度）、`dyn_deter`（确定通道即 GRU 状态的宽度）、`units`
（reward/cont/actor/critic 各 MLP 头的宽度），三个键同步取 128、256、512。这是
自己造的缩放配方，锚定的 torch 仓库没有现成的尺寸预设（JAX 官方仓库
danijar/dreamerv3 有 size12m 到 size200m 的 size 家族段，torch 版的 configs.yaml
里没有对应物），而仓库自己的 crafter 段就是这么放大模型的：`dyn_deter: 4096`、
`dyn_hidden: 1024`、`units: 1024`。两处诚实标注：其一，CNN 编码解码器
（`encoder`/`decoder` 的 `cnn_depth`，嵌套键，第 06 课讲过命令行覆盖不可靠）和
随机通道（`dyn_stoch`/`dyn_discrete`）保持不动，所以这条轴缩放的只是 RSSM 加
各个头，不是整机等比放大；其二，"宽度翻倍"不等于"参数量翻倍"，稠密层参数
随宽度平方长，Step 2 的脚本会给你每档的真实参数量，报告里用真实数字说话，不许
拿 128/256/512 冒充参数量。

Step 5 的截面图：x 轴取宽度的 log，三点连线。看三件事，单调不单调、
直不直、种子散布相对趋势多大。看完问自己一个问题：敢不敢据此预测宽度 1024 的
分数？这个问题的答案在 5.5 节，先带着它往下读。

### 5.2 算力怎么分：Chinchilla 与互相纠缠的轴

缩放律不只是"越大越好"的赞美诗，它真正值钱的用途是**分配**：同一笔
算力，买参数还是买数据？2022 年的 Chinchilla 论文（《Training Compute-Optimal
Large Language Models》）用超过 400 个模型（70M 到 16B 参数、5B 到 500B token）
重做了这道题，结论把此前的行业配方推翻了一半：参数量和训练数据应当**等比例**
增长，此前的大模型普遍训练不足，70B 的 Chinchilla 用与 280B 的 Gopher 相同的
算力、四倍的数据，在一长串下游任务上全面胜出。对本课最有教育意义的地方不是结论
本身，而是这件事居然会发生：Kaplan 和 Chinchilla 都是一流团队、都拿着自己的数据
认真拟合，得出的最优分配却差那么远。缩放律是**对自家设置的经验总结**，设置变了
（学习率安排、数据构成、训练时长），拟出来的"定律"就跟着变。把自家趋势线当
普适真理，是这门手艺的头号职业病。

到了在线 RL 这里，分配问题多了一层拧巴：几种预算是互相锁死的。第 06
课算过那笔账，`train_ratio: 512` 把"环境步"和"梯度更新量"绑成固定汇率（每
2 个环境步一轮完整更新），所以你多采一步数据，就自动多买一份训练；模型加宽，
每轮更新的算力又跟着涨。这带来两个后果。好的一面：**数据轴几乎免费**，在线
训练的数据是边跑边长的，同一条 run 的评估曲线在 1e5、2e5、3e5 步处切三个截面，
就是数据轴上的三个点，一条 run 顶三个网格点用。坏的一面：我们的参数量轴**不是
等算力对比**，同样跑到 3e5 环境步，512 宽的 run 烧掉的浮点运算远多于 128 宽的。
所以这两条轴各自回答的问题要分清楚：数据轴回答"多交互能买来多少"（样本效率
视角），参数轴回答"同样的交互预算下，宽度值多少"（容量视角）；两者都不回答
"同一笔算力怎么花最划算"，那需要专门设计等算力网格，第 11 节的改造实验 3
教你怎么补。

Chinchilla 的结论可以压缩成一句：compute-optimal 时参数量和数据量对
算力的最优指数近似相等，算力翻倍，参数和数据各自大约乘 $\sqrt{2}$。而在我们的
设置里，固定 `train_ratio` 下总训练算力大致是"每步更新开销乘更新次数"，前者随
宽度平方长、后者随环境步线性长，两条轴对算力的贡献完全不同型。把这笔账摆在
桌面上，是为了让你在报告里写对比较的单位：**同环境步**的比较和**同算力**的比较
是两种实验，混着说就是错的。

汇率旋钮 `train_ratio`、`batch_size`、`batch_length` 全在
`configs.yaml` 顶层，本课一律不动（动了就换了汇率，宽度轴不再干净）。数据轴不改
任何键，靠分析脚本从 `metrics.jsonl` 切截面（Step 4）。

Step 4 的截面表本身就是验证：同一条 run 在三个截面的分数应当整体
向上（在线 RL 多数情况下多练多得），若某条 run 后期截面反而掉头，先查它的训练
曲线是不是塌了（第 10 节）。

### 5.3 种子：三个不是排场，是误差棒本身

深度 RL 的种子方差大得出名，同一份代码、同一套配置，只换随机种子，
最终分数可以差出天壤，这在 2017 年就被《Deep Reinforcement Learning that
Matters》拿一堆主流算法示众过。这意味着：你的网格上每个"点"其实是一朵云，
单种子的一次测量只是从云里随手抓了一滴水。两朵云之间要谈"谁高谁低"，先得知道
每朵云有多大，这是每点至少三种子的原因：不是统计洁癖，是没有三个数你连散布
的量级都估不出来。**种子是网格的一个维度，不是跑完主实验后补的装饰。**

本课网格的完整坐标是（宽度，种子），3 乘 3 共九个点位。比较宽度 A 和
宽度 B 时，规矩是：先看两组各三个数的散布，组间差距明显大于组内散布才有资格谈
趋势。有个零成本的目测法：把两组共六个数排序，如果两组的数交错混排（比如
A、B、A、B、B、A），这两点之间就不许写"上升"或"下降"，这个交错检验是
Step 7 的必做自查。

每个网格点报"均值加减标准差（n=3）"。想更进一步，均值的标准误是
$\mathrm{SE} = s/\sqrt{n}$，$n=3$ 时 $\mathrm{SE} \approx 0.58\,s$，三个种子把
对均值的不确定度压掉四成，聊胜于无，但离"显著"二字还远。所以本课报告的用词
上限是"观察到同方向的差异"，不出现"显著"这个词：显著性检验需要的样本量，
我们的预算买不起，买不起就不装。

`--seed 0/1/2` 命令行覆盖顶层键 `seed`。另一个相关键 `deterministic_run`
默认 `False`：即使种子相同，GPU 上的非确定性算子也不保证逐位复现。这不妨碍本课，
种子在这里的职责是**标注随机性的来源、撑开每个点的散布**，不是逐位重放；真需要
逐位复现（比如调试）再打开它，训练会变慢。

Step 7 的自查一：对每对相邻宽度做交错检验，把判决（分离/交错）写进
报告。这一步会直接决定你的报告里哪些句子允许存在。

### 5.4 门槛指标的锯齿：涌现的海市蜃楼

"能力"这个词天生是门槛式的：会不会走路、能不能过 700 分、下不下得
赢人。门槛读数直观、好传播，但它有个结构性毛病：**它把平滑的进步压缩成 0 和 1**。
一个模型从"平均 690 分"进步到"平均 710 分"，连续指标看是小步爬坡，"过 700"
这个门槛看是从无到有。2023 年 Schaeffer 等人的《Are Emergent Abilities of Large
Language Models a Mirage?》把这个怀疑扎扎实实做成了实验：大语言模型那些著名的
"涌现能力"，相当一部分随量法而生灭，换成连续量法，跳变消失，剩下平滑的
改进。他们的原话方向是：涌现可能来自研究者对量法的选择，未必来自模型行为的
突变。全文只用一次的句式留给这里：所谓涌现，很多时候不是出现在模型里，而是
出现在量法里。

把机制拆开看，三个零件缺一不可：连续的底层进步、带噪声的测量、一个
硬门槛。底层能力随规模平滑上升；每次测量在真实水平附近抖动；门槛把"均值离线
还差一点"和"均值刚过线一点"劈成 0 和 1 两个世界。于是在稀疏的网格上（我们只
有三个点！），门槛指标必然表现为：连续几个点全是 0，某个点突然变成 1，看起来
就像能力在那个规模"涌现"了。而它的全部秘密只是：均值曲线恰好在那两个点之间
穿过了门槛。Schaeffer 用三步验证了这套解释：在 GPT-3 家族上按预测改量法消除
涌现、在 BIG-Bench 元分析里确认涌现集中于非线性与不连续量法、以及最狠的一步，
在普通视觉模型上**人为选量法制造出涌现**。第三步你会在自己的数据上照做（Step 6），
零新算力。

设某宽度 $N$ 下评估回报近似 $\mathcal{N}(\mu(N), \sigma^2)$，$\mu(N)$
随 $N$ 平滑上升，门槛为 $X$，则"单次评估过线"的概率是：

$$
P(\text{return} \ge X) = \Phi\!\left(\frac{\mu(N) - X}{\sigma}\right)
$$

$\Phi$ 是标准正态的累积分布函数，一条 S 形曲线，在 $\mu(N) = X$ 附近最陡。
$\mu$ 平滑地穿过 $X$，$P$ 就从接近 0 冲到接近 1；网格越稀、$\sigma$ 越小、每点
测量次数越少，这段冲刺在图上越像悬崖。注意公式里 $X$ 是**你选的**：$X$ 一动，
悬崖跟着平移，这是 Step 6 要演示的"涌现点漂移"，也是判别真假涌现最便宜的
一把螺丝刀。

门槛指标不改训练代码，全在分析侧：Step 6 的脚本以
`metrics.jsonl` 里的 `eval_return`（它本身已是 10 局评估的均值，第 6 节有出处）
为原料，对每个（宽度，种子）判断"预算 B 步内是否达到过 X"，再对种子求比例。
想要每局粒度的达成率，`logdir` 下 `eval_eps/` 目录存着每局评估轨迹的 npz，逐个
把 `reward` 求和即可，第 01 课算随机基线的老手艺。

Step 6 跑三个门槛 $X \in \{400, 600, 800\}$：如果三张阶梯图的跳变
位置各不相同，而底下的连续曲线始终平滑，你就在自己的数据上复现了 Schaeffer 的
核心机制。反过来记住真涌现的长相：**连续指标也在同一位置拐弯**，且换几种量法
跳变位置不动，见到这样的证据才值得喊那两个字。

### 5.5 外推的资格：结论的写法

回到课名那个问题的两面。正面："小数据小模型跑不出的能力，凭什么不能
断言大模型也没有？"，因为你手里只有趋势线最左端的一小段，而能力类读数（门槛
指标）恰恰是最会骗人的那种（5.4）；能力不出现的原因还可能是容量以外的任何东西：
数据不够、训练没收敛、量法太粗、种子不巧。四个嫌疑人你一个都没排除，就把罪名
定给了"方向"。反面："那什么时候能外推？"，趋势线足够长（跨数量级，而不是
跨一倍）、趋势有机制解释（知道**为什么**会这样变，而不只是看到在变）、并且在
不止一个设置里重复出同方向。三样凑齐才有资格把线往外画，画的时候还得说明画了
多远。

落到笔头是一个句式。合格：**"在 walker_walk、dmc_vision 配置、3e5
环境步、宽度 128 到 512、种子 0/1/2 下，评估回报随宽度的变化是……"**。不合格：
"宽度不重要""这个方向不行""能力在 512 涌现"。条件前缀不是谦虚客套，它就是
结论本体，因为你测到的东西确实只在那些条件下成立；把前缀删掉的那一刻，观察就
变造了谣。诚实标注实验边界一句话就够（"这个实验只说明 A，不说明 B，因为 C"），
说完接着干活，不必反复表白。

外推的风险可以量出来：你的拟合区间是宽度 128 到 512，log 轴上 0.6
个数量级；Kaplan 的部分趋势有七个。往外推一格（宽度 1024）就已经站在拟合区间
之外赌"直线继续直"，而幂律弯头的例子在两篇缩放论文的正文里就有。另一头，
walker_walk 的 1000 分上限意味着连续指标本身在高分段被压扁，你的趋势线两头
都有变形区，能放心说话的只有中间那一小段。

Step 8 的报告模板，专门留了"这个实验能说什么/不能说什么"一节，
每边一句话起步：说"能"要带条件前缀，说"不能"要给出缺的是什么（跨度、种子、
任务面，选一个填进去）。

交报告前把每条结论过三问：有条件前缀吗？是趋势还是单点？门槛类结论
有连续指标背书吗？三问全过才算合格，第 9 节验收清单据此执行。

## 6. 源码导读

这里不改一行训练代码，但你要动的每个配置键、读的每个日志字段，都得知道出处。
仓库已归档只读，下面的行为不会漂移：

| 位置 | 管什么 | 带着什么问题读 |
|---|---|---|
| `configs.yaml` 顶层 `dyn_hidden` / `dyn_deter` / `units` | 参数量轴的三个旋钮 | crafter 段把它们放大到 1024/4096/1024，官方自己的"加大"配方和你的三键同步法一致吗？|
| `networks.py::RSSM.__init__` | 宽度落进结构 | `self._cell = GRUCell(self._hidden, self._deter)`：`dyn_deter` 是 GRU 状态宽度，`dyn_hidden` 是 RSSM 内部各线性层宽度，两者各自控制什么容量？|
| `models.py` 里的 `feat_size` | 为什么动 deter 牵动全身 | `feat_size = dyn_stoch * dyn_discrete + dyn_deter`：特征拼接宽度变了，reward/cont/actor/critic 每个头的输入层都跟着变，"只改三个键"实际改了多少层？|
| `models.py` 中 `config.units` 的四处消费点 | units 喂谁 | WorldModel 里的 reward/cont 头、ImagBehavior 里的 actor/critic 都吃它，数一数，还有谁的宽度没被这三个键管到？（答案：CNN 和随机通道，5.1 的诚实标注） |
| `dreamer.py` 尾部 argparse | 命令行覆盖 | 顶层键自动注册成同名旗标（第 06 课讲过），`--dyn_deter 128 --seed 2` 为什么合法、`encoder.cnn_depth` 为什么不能这么改？|
| `tools.py::Logger.write` | metrics.jsonl 的出生地 | 每次 write 往 `logdir/metrics.jsonl` 追加一行 `{"step": …, 各标量…}`，你的全部分析数据源就这一个文件，TensorBoard 只是它的镜像 |
| `tools.py::simulate` 尾部 eval 分支 | eval_return 的定义 | `score = sum(eval_scores) / len(eval_scores)`，攒满 `eval_episode_num: 10` 局才写一次，所以曲线上每个点自带 10 局平均，你的门槛指标是在"均值过线"上定义的 |
| `dreamer.py` 主函数 checkpoint 分支 | 断点续跑 | `latest.pt` 存 `agent_state_dict` 与 `optims_state_dict`，启动时存在即加载，网格挂到一半断电，哪几条 run 能原地续、怎么验证续对了？|
| `logdir/eval_eps/*.npz` | 每局评估轨迹 | 想要每局回报的分布（而不只是 10 局均值），逐 npz 把 `reward` 求和，第 01 课的老手艺在这里复活 |

## 7. 实验

主线：设计并写死预期（半天）、复用基线并起跑 8 条新 run（挂机数天）、抽取指标、
画两类图、做两项自查、写报告（一天）。备选轨道（IRIS）见第 11 节改造实验 2。

### Step 1: 定网格，写死预期

先把设计写进 `NOTES.md`，跑完不许改（真要改，另起一段注明改动与原因）。本课的
网格：

| 轴 | 点 | 实现方式 |
|---|---|---|
| 参数量（模型宽度 W） | 128 / 256 / 512 | `dyn_hidden`、`dyn_deter`、`units` 三键同步设为 W |
| 数据量（环境步数） | 1e5 / 2e5 / 3e5 | 不加 run：从每条 run 的评估曲线切三个截面 |
| 种子 | 0 / 1 / 2 | `--seed` 顶层键 |

宽度 512 就是第 06 课基线的默认配置，所以 (512, seed 0) 直接复用基线；其余
3 乘 3 减 1 等于 8 条新 run，每条 3e5 步。四条候选轴里另外两条，可见历史/想象
长度（`batch_length`/`imag_horizon`）和状态表示宽度（`dyn_stoch`/`dyn_discrete`）
，本课明确不动，动了它们的补法在第 11 节。

然后写预期，每条都要在跑之前落笔。给你三条示例（照抄不算写，改成你自己的判断）：

- 预期评估回报随宽度单调不减，且 128 与 512 之间的差距大于各自的种子散布；
- 预期数据轴上三个截面单调上升，128 宽度在 3e5 步仍未到平台；
- 若三个宽度的曲线挤在一起，结论候选是"walker_walk 在此区间对容量不敏感"，
  而不是"宽度没用"。

写预期不是仪式。它的作用是把"事后什么都能圆"变成"事前敢不敢押注"，报告里
预期与观察的对照表，比任何漂亮曲线都更能训练你的判断。

### Step 2: 复用基线，数清参数量

先确认第 06 课基线可用：`logdir/walker_base/metrics.jsonl` 存在，且 3e5 步之前
应有约 30 行含 `eval_return` 的记录（`eval_every: 1e4`）。这条 run 与本课新 run
除 `steps` 外逐键相同（新 run 用 `--steps 3e5` 提前收工），在 3e5 截面上可比，
第 06 课的消融就是这么用基线的。

再写第一段胶水：数清三个宽度档的真实参数量。等第一条新 run 存出 checkpoint
后（或直接用基线的 `latest.pt`），跑：

```python
import torch

ckpt = torch.load("logdir/walker_base/latest.pt", map_location="cpu")
state = ckpt["agent_state_dict"]
groups = {}
for name, tensor in state.items():
    if hasattr(tensor, "numel"):
        top = name.split(".")[0]
        groups[top] = groups.get(top, 0) + tensor.numel()
for top, n in sorted(groups.items()):
    print(f"{top:24s} {n/1e6:8.2f} M")
print(f"{'total':24s} {sum(groups.values())/1e6:8.2f} M")
```

对三个宽度档各跑一遍（换 checkpoint 路径），把三个总参数量记进 `NOTES.md`，
报告的 x 轴用这三个真实数字或宽度均可，但正文提"参数量"时必须是脚本给的数。
顺带看一眼分组：`compile: True` 时键名会带编译包装的前缀，按最外层分组照样能读。

### Step 3: 起跑 8 条新 run

命名规则 `w{宽度}_s{种子}`，一条命令一个样：

```bash
python3 dreamer.py --configs dmc_vision --task dmc_walker_walk --steps 3e5 --dyn_hidden 128 --dyn_deter 128 --units 128 --seed 0 --logdir ./logdir/scale/w128_s0
```

其余 7 条把三处宽度和 `--seed` 按网格换成对应值，`--logdir` 跟着改名。八条的
清单（宽度，种子）：(128,0) (128,1) (128,2) (256,0) (256,1) (256,2) (512,1)
(512,2)，(512,0) 是基线。排队建议：

- 串行最省心。24GB 显存塞得下两条并发，但会互抢算力：曲线以环境步为轴不受
  影响，墙钟记录会互相污染，想在报告里提任何训练速度的话，只用串行 run 的数据。
- 每条 run 起跑后第一次日志打印时，核对开头输出的完整配置：`dyn_hidden`、
  `dyn_deter`、`units`、`seed` 四个键的值必须与 run 名一致。改错网格点是本课
  最贵的事故，一分钟的核对能救三小时的卡时。
- 断点不慌：`latest.pt` 存在即自动续跑（第 6 节最后一行的出处）。

### Step 4: 抽取截面，生成 CSV

全部 run 结束后（或边跑边看），用一段脚本把九条 `metrics.jsonl` 汇成一张表：

```python
import json, glob, csv

rows = []
runs = {(512, 0): "logdir/walker_base"}
for w in (128, 256, 512):
    for s in (0, 1, 2):
        runs.setdefault((w, s), f"logdir/scale/w{w}_s{s}")
for (w, s), d in runs.items():
    for line in open(f"{d}/metrics.jsonl"):
        rec = json.loads(line)
        if "eval_return" in rec:
            rows.append({"width": w, "seed": s,
                         "step": rec["step"], "eval_return": rec["eval_return"]})
with open("scaling.csv", "w", newline="") as f:
    wr = csv.DictWriter(f, fieldnames=["width", "seed", "step", "eval_return"])
    wr.writeheader()
    wr.writerows(rows)
print(len(rows), "eval points")
```

再从 CSV 里取三个截面：对每条 run，取 step 不超过 1e5 / 2e5 / 3e5 的最后一个
评估点。预期产物是一张 9 行乘 3 列（截面）的数表，它就是你的全部原始证据，
后面所有图都从它长出来。

### Step 5: 画连续指标的两张图

图 1，样本效率曲线族：x 轴环境步，y 轴 `eval_return`；每个宽度一组，同组三个
种子画细线、均值画粗线。这张图回答数据轴的问题，同样的交互预算下谁学得快。

图 2，宽度截面图：x 轴取宽度（log2 刻度），y 轴取 3e5 截面的 `eval_return`；
每个宽度画三个种子的散点，叠均值与标准差。这张图回答参数轴的问题。画完对照
Step 1 的预期逐条记录：命中、落空，还是"数据不够格回答"。三种结局都合法，
只有第三种最容易被新手硬写成前两种，散布图就在旁边，别骗自己。

### Step 6: 造门槛指标，再滑动门槛

零新算力的一步，也是全课最有戏剧性的一步。定义达成率：给定门槛 $X$ 和预算 $B$，
某宽度的达成率等于"三个种子里，有几个在 $B$ 步内 `eval_return` 达到过 $X$"，
除以三。脚本接着 Step 4 的 CSV 写：

```python
import csv
from collections import defaultdict

data = defaultdict(list)
for r in csv.DictReader(open("scaling.csv")):
    data[(int(r["width"]), int(r["seed"]))].append(
        (float(r["step"]), float(r["eval_return"])))
for X in (400, 600, 800):
    print(f"门槛 X={X}")
    for B in (1e5, 2e5, 3e5):
        line = []
        for w in (128, 256, 512):
            hit = sum(any(s <= B and v >= X for s, v in data[(w, sd)])
                      for sd in (0, 1, 2))
            line.append(f"w{w}: {hit}/3")
        print(f"  B={B:.0e}  " + "  ".join(line))
```

对每个 $X$ 画一张阶梯图（x 轴宽度，y 轴达成率），三张并排放。预期看到的现象：
某个 $X$ 下达成率从 0/3 跳到 3/3，看起来像"能力在这个宽度突然出现"；换一个
$X$，跳变挪了位置。跳变位置随你选的门槛移动，而图 1 的连续曲线全程平滑，
这是 5.4 的 $\Phi$ 公式在你自己的数据上现形，也是 Schaeffer 那篇论文第三步
验证（自己动手制造涌现）的缩小版复现。三张图配一句说明存档。

### Step 7: 两类经典错误的自查

自查一，**把噪声当趋势**。对相邻宽度对（128 对 256、256 对 512）分别做 5.3 的
交错检验：两组各三个 3e5 截面分数，共六个数排序，看是否交错混排。判决只有两种
写法："分离，两点间的方向性差异大于种子散布"或"交错，两点间不构成可报告
的差异"。判决写进报告，后面的每一句结论都要与它一致：被判"交错"的两点之间，
正文不许出现任何"涨了/掉了"。

自查二，**把量法的锯齿当涌现**。把 Step 6 的三张阶梯图和图 1 的连续曲线放进
同一页，回答三个问题并写下答案：连续指标在阶梯跳变的位置有没有同步拐弯？跳变
位置随 $X$ 动了没有？如果只给你看阶梯图，你会得出什么错误结论？第三问的答案
建议原样放进报告，把自己差点犯的错误示众，是这门手艺最快的长进方式。

### Step 8: 写 mini scaling 报告

报告骨架照抄，逐节填：

```text
一、设置：任务、配置（dmc_vision 全默认，改动仅三宽度键与 seed）、代码 commit、
    三档真实参数量（Step 2 脚本输出）
二、网格：两条轴、九个点位、每点三种子；Step 1 的预期原文（不许事后修饰）
三、图：样本效率曲线族、宽度截面图、三张达成率阶梯图
四、观察：每条都带条件前缀（任务、配置、步数、宽度区间、种子），标注"趋势/
    单点/不够格"三选一，与 Step 7 的判决一致
五、两类错误自查：交错检验判决表；涌现点漂移演示与三问答案
六、这个实验能说什么/不能说什么：各一句起步，能说的带条件前缀；不能说的
    写明缺什么（跨度、种子、任务面）
七、下一步：若要让这份网格支撑一个真实决策（比如第 19 课的手术立项），最先补
    哪个点、预算多少
```

第六节示范一对合格的句子。能说："在 walker_walk、dmc_vision 默认配置、3e5 步、
种子 0/1/2 下，宽度 128 到 512 的评估回报呈（你观察到的）方向。"不能说："宽度
对 Dreamer 不重要"，单任务、0.6 个数量级、三种子，撑不起一个不带条件的全称
判断。一句话说清界限就翻篇，不用起誓也不用道歉。

## 8. 配置与预算

多点乘多种子就是烧卡，账要摆在明面上。参考第 06 课的实测量级（1M 步基线数小时
到一两天，3e5 步约为其三分之一），两档任选：

| 档位 | 设置 | run 数 | 每条步数 | 单卡墙钟（量级） | 能说什么 |
|---|---|---|---|---|---|
| 最小可信配置（主线） | dmc_vision walker_walk，宽度 {128,256,512} 乘种子 {0,1,2}，复用 06 课基线 | 8 条新 | 3e5 | 约 2.5-3 条 1M 基线的时间，单卡数天 | 两条轴各 3 点、每点 3 种子，够做全部自查与报告 |
| 从简阉割版 | dmc_proprio walker_walk（向量观察，无 CNN 编解码、无视频日志），同样 3 乘 3 网格 | 9 条全新 | 3e5 | 每条明显快于 vision 档，总墙钟为主线的几分之一 | 手艺流程完整走一遍；代价见下 |

阉割版的代价要写进自己的报告：观察空间从像素换成了本体感受向量，**与第 06 课
基线不可比**，"参数量轴"里编码器变成了 MLP，结论只覆盖 proprio 设置。它保住的
是本课的教学主体，网格、种子、两类指标、两项自查、报告写法，一样不缺。

几条实操账：

- 预算再紧，砍点不砍种子。宁可两点乘三种子，不要三点乘单种子：前者至少能
  做交错检验，后者整张网格没有误差棒，是本课明令的反面教材。单种子网格出的图，
  一条曲线的抖动就能伪造出任何"趋势"。
- 宽度往上加点（1024）比往下加（64）贵得多：稠密层算力和显存随宽度平方长。
  想加 1024 档先单独试跑几千步看显存和速度，再决定进不进网格。
- 曲线挤在一起时的加点顺序：先往下加 64（便宜，且拉开容量差距），不要先
  往上加。
- 8 张 A100 短租（课程蓝图第 5 节的可选加餐）：网格天然并行，九条 run 摊到
  多卡上是最无脑的加速，唯一要守的规矩是每张卡跑完整的 run，不做数据并行拆分
  ，拆了 batch 语义就变了。
- 磁盘：九条 run 预留 40GB；分析产物（CSV、图）可忽略不计。

## 10. 排错

| 症状 | 最可能的原因 | 怎么确认 | 怎么修 |
|---|---|---|---|
| 三个宽度的曲线挤成一团 | walker_walk 在此区间对容量不敏感，或全都顶到了任务上限 | 看 128 是否也进入高位平台；平台值是否逼近满分区 | 这本身就是合法结论（按 5.5 句式写）；想拉开差距，往下加 64 宽度点，或换同域更难任务（如 dmc_walker_run）重跑网格 |
| 128 宽度的 run 学不动或中途崩 | 容量不足，或默认超参（为 512 调的学习率等）在小模型上失配 | 对照 `metrics.jsonl` 里的模型损失与 `kl` 曲线 | 如实记录，"最小点失败"是数据点不是事故；严禁单独给它调参救活（那就多改了一个变量，网格作废） |
| 某个种子明显离群 | 深度 RL 的正常现象（5.3） | 看该 run 的曲线是否早期长期趴在随机水位 | 不许删。保留并在报告标注；不放心就三个宽度各加第 4 个种子，加就全加，只给离群点加是挑数据 |
| 达成率全 0/3 或全 3/3，阶梯图没信息 | 门槛 $X$ 选在了值域之外 | 对照图 1 的连续曲线值域 | $X$ 取 3e5 截面分数的中段再滑动；全 0 或全 1 的门槛图不含信息，换 $X$ 重画（零成本） |
| 复用的基线与新 run 对不上 | 基线不是 dmc_vision 默认配置，或当年动过键 | 逐键比对两条 run 训练日志开头打印的完整配置 | 只要除 `steps` 外逐键一致即可在 3e5 截面比；不一致就放弃复用，把 (512, 0) 当第九条重跑 |
| 新 run 起跑后配置没生效 | 旗标拼写错误或写进了嵌套键 | 日志开头的配置回显里找那个键的实际值 | 三个宽度键都是顶层键，`--dyn_hidden 128` 这类写法才有效；发现错立即杀掉重跑，别心疼前几千步 |
| 两条并发 run 的墙钟数据没法用 | 互抢算力（第 06 课同款教训） | 比较并发段与串行段的 `fps` | 以环境步为轴的分析全部有效；墙钟相关的任何说法只用串行 run 支撑 |
| 想加 1024 宽度点就 OOM | 稠密层显存随宽度平方长 | `nvidia-smi` | 单独跑不并发；仍不行就放弃该点并在报告注明，严禁砍 `batch_size` 硬塞（变量又多了一个） |
| 曲线在 2e5 步后反常下跌 | 训练不稳或评估抖动 | 看是单种子跌还是同宽度三种子齐跌 | 单种子跌按离群处理；齐跌是真现象，如实入报告并回第 06 课症状表排查 |

## 11. 前沿与改造

你这份作业的"大人版"长什么样，三个可核对的样本。DreamerV3
论文自己就有 Scaling properties 一段：12M 到 400M 六个模型尺寸，结论是性能随
尺寸单调上升、更大的模型还更省环境交互，本课的参数量轴就是它的缩小复刻。
Genie 论文的 3.1 节 Scaling Results：固定视频 tokenizer 和动作模型，把动力学
模型从 40M 扫到 2.7B，最终训练损失随参数量一致下降，另用 2.3B 模型扫了
128/256/448 三档 batch size，据此才敢把最终模型放大到 11B。Kaplan 与 Chinchilla
则是方法论本身的两座路标。对照之下有个耐人寻味的共性：**前沿缩放研究普遍单
种子、大跨度，我们是多种子、小跨度**，他们用横跨数量级的点数压制噪声（趋势
线足够长，单点抖动掀不翻），我们的区间太短，只能靠种子把每个点的云画出来。
两种买法，付的都是同一种货币：对随机性的控制。

规模侧：跨度（他们两到七个数量级，我们 0.6 个）、任务面（他们
150 多个任务或海量视频域，我们一个 walker）、指标性质（他们缩放的是无上限的
损失，我们的回报有 1000 分天花板，高分段趋势必然压扁）。机制侧：没有差距，
等比取点、多点拟合、量法自觉，手艺是同一套，这正是本课敢叫"缩小版"而不叫
"玩具版"的原因。

动手改造清单。

1. 第三条轴，想象长度：`--imag_horizon` 取 5/15/30（顶层键，命令行直接
   覆盖），每点 3 种子，各 3e5 步，共 9 条 run（15 档可复用主网格的三条 512
   run，如果你主网格跑的是 512 基线宽度）。预算与主网格同级。预期：15 附近
   最好，30 不增反抖，第 03 课的误差滚雪球在给想象长度定价。失败判据：三点
   乱序且在模型损失、`kl` 等中间指标上找不到任何解释。
2. IRIS 轨道复刻（第 09 课的设置）：把同一套手艺搬到 token 世界模型上。
   参数量轴用 Hydra 覆盖 `world_model.num_layers=5/10/20`（默认 10）或
   `world_model.embed_dim=128/256/512`（默认 256），种子用 `common.seed`，
   命令是在第 09 课的训练命令 `python src/main.py env.train.id=BreakoutNoFrameskip-v4 common.device=cuda:0 wandb.mode=disabled` 后面追加上述覆盖项。
   连续指标看世界模型损失和评估回报两条，门槛指标自定分数线。
   预算：IRIS 单游戏训练乘 9，很贵；可用 `common.epochs=300`（默认 600）减半。
   预期亮点：世界模型损失多半随深度平滑改善，回报未必跟，"损失缩放不等于
   能力缩放"，正是 Genie 那节 Scaling Results 只报损失留下的悬念的缩小版。
3. 等算力对照（Chinchilla 的缩小版问题）：固定墙钟预算（比如每条 12 小时），
   128 宽跑到时间用完对 512 宽跑到时间用完，各 3 种子，比最终回报。这才是
   "同一笔算力买宽度还是买步数"的正确问法，注意它和主网格的"同环境步"
   比较回答的不是一个问题（5.2）。预期不预设方向；失败判据只有一个：墙钟没记
   干净（并发污染、机器波动没记录），等算力实验里墙钟就是一切。
4. 顺手复现：两项零成本或近零成本。其一，Schaeffer 的核心机制你在 Step 6
   已经复现，涌现点随量法移动，这是那篇论文第三步验证的缩小版。其二，
   DreamerV3 的 Scaling properties 段：若你的图 2 单调向上，即在单任务预算下
   复现了"更大更好"的方向；若压扁不动，报告里给出三个解释候选（任务上限、
   区间太窄、种子太少），这个"没复现出来但知道为什么"的结论，和复现成功
   一样值钱。

## 12. 论文与延伸

1. Scaling Laws for Neural Language Models（Kaplan, McCandlish et al., 2020，
   [arXiv:2001.08361](https://arxiv.org/abs/2001.08361)），缩放律的成文处：损失
   对参数、数据、算力各呈幂律，部分趋势跨七个数量级。带着三个问题读：七个数量级
   的拟合区间是拿什么买来的（多少个模型、怎么统一设置）？论文里哪些地方明说了
   幂律会弯（数据瓶颈、小模型端）？把你的 0.6 个数量级画到他们的图上，是多短的
   一截，这截够你说哪些话？
2. Training Compute-Optimal Large Language Models（Hoffmann et al., 2022，
   [arXiv:2203.15556](https://arxiv.org/abs/2203.15556)），Chinchilla：400 多个
   模型重拟合，结论是参数与数据应等比例长，70B 加四倍数据胜过同算力的 280B。
   带着三个问题读：同样是认真拟合，它和 Kaplan 的最优分配为什么差这么远，
   设置里到底什么变了？他们的三种估计方法互相印证，对应到你的作业里是什么
   （提示：你只有一种量法时才最该害怕）？在线 RL 里"训练 token 数"对应什么，
   `train_ratio` 把哪两样东西锁死了？
3. Are Emergent Abilities of Large Language Models a Mirage?（Schaeffer,
   Miranda & Koyejo, 2023，[arXiv:2304.15004](https://arxiv.org/abs/2304.15004)）
   ，本课门槛陷阱的原典：涌现能力可能来自量法选择而非模型行为突变；非线性或
   不连续量法制造跳变，连续量法还原平滑。带着三个问题读，全部对着你自己的
   Step 6 图回答：他们的三步验证（改量法消除涌现、BIG-Bench 元分析、在视觉模型
   上人造涌现），你的达成率实验对应哪一步？如果审稿人只给你看一张达成率阶梯图
   就宣称涌现，你会开出哪三张检查单？什么样的证据能让你反过来相信一个真涌现
   ，连续指标在同一位置拐弯算不算、多种量法同点跳变算不算？
4. Genie: Generative Interactive Environments（Bruce, Dennis et al., 2024，
   [arXiv:2402.15391](https://arxiv.org/abs/2402.15391)），只读它的 3.1 节
   Scaling Results 和附录 D：动力学模型 40M 到 2.7B 的系列、batch size 三档
   扫描，然后才是 11B 的最终模型。带着两个问题读：他们缩放的全是训练损失，
   损失单调下降能保证"可玩性"（latent action 的可控性）同步变好吗，这中间
   缺一节什么实验？整个缩放系列看不到误差棒，大模型研究为什么普遍这么干、
   拿什么补偿（对照第 11 节"两种买法"的说法）？
5. DreamerV3（Hafner et al., [arXiv:2301.04104](https://arxiv.org/abs/2301.04104)）
   ，第 06 课读过正文，这次只重读 Scaling properties 一段和对应的图：12M 到
   400M 六个尺寸，性能单调、交互更省。带着两个问题读：这一段就是你作业的官方
   大版本，他们的尺寸配方同时动了哪些键（对照你只动三个）？你的图 2 复现出
   同方向了吗，没有的话你的三个解释候选里哪个最有嫌疑？
6. 选读：**Deep Reinforcement Learning that Matters**（Henderson et al., 2017，
   [arXiv:1709.06560](https://arxiv.org/abs/1709.06560)），深度 RL 可复现性
   问题的老警钟，种子方差一节至今没过时。带着一个问题读：他们列的坑里，哪几个
   你在本课靠网格设计躲开了，哪几个只是被你的小预算暂时掩盖着？

收个尾。到这一课为止，第五幕的研究手艺凑齐了两件：第 17 课的量法（把"好"拆开
量，知道每个指标照亮哪个侧面），本课的规模判断（知道自己的结论在多大范围内
成立、花小钱时怎么不说大话）。第 19 课把两件手艺押上手术台：换掉
一个器官，给 RSSM 换 Transformer 骨干、把 JEPA 目标接进 Dreamer、或给 IRIS 换
连续 token。手术贵、变量多、极容易白跑，你将用上本课的全部纪律：预算先算、预期
先写、对照选好、失败判据定死，然后无论成败，都交出一份诊断清楚的报告。
