# 第 41 课：把驾驶世界模型的条件拆进动作、外生和风格

> 类型：只讲（GAIA-1 / GAIA-2 / GAIA-3、DriveDreamer、Drive-WM）+ 文档体验（Vista 官方建议采样至少 32GB；OccWorld 在已有 nuScenes 时可按 README 在 24GB 评测）<br>
> 建议周期：1-2 天<br>
> 硬件：主线不训练、不声称 24GB 能跑高清多相机生成。Mac / 纯 CPU 可完成全部阅读、条件分类和打分<br>
> 锚定：无主训练仓库。对照 [OpenDriveLab/Vista](https://github.com/OpenDriveLab/Vista)（可 clone，采样文档写至少 32GB）、[wzzheng/OccWorld](https://github.com/wzzheng/OccWorld)（README 写 RTX 4090 24GB 可训可评，依赖 nuScenes 与 Occ3D）、NVIDIA Cosmos Cookbook 的 [AV 域适应页](https://nvidia-cosmos.github.io/cosmos-cookbook/gallery/av_inference.html)（Transfer 2.5，分类时诚实：这是可控生成，不一定是世界模型）<br>
> 产物：一张 GAIA-2 条件分类表、一次驾驶条件板作答、给「开环合成数据生成器」打的 E0 或 E1 档、一份开源对照笔记

## 1. 这一课做什么

第九幕在读 2025 到 2026 年的刷榜系统和配方，毕业标准仍在第 32、33 课。第 40 课讲的是工业流水线：给视频生成器补上低层动作通道，再谈不谈规划。本课把同一把尺子搬到路上。路上的观察是多相机，条件比桌面上密得多：自车速度、转向曲率、他车位置、行人、天气、车道类型、红绿灯。验证者是路，不是桌子。路不会 `reset()`，合成一段撞车视频也不等于规划已经被验证。

主干循环没变：

```text
观察 先压成状态 再按动作预测下一状态 然后展开多条未来 给未来打分 最后选动作
```

驾驶世界模型通常停在「按条件播未来视频」。Wayve 的 GAIA-1（Hu 等，arXiv:2309.17080）把驾驶视频、文本和自车动作编成离散 token，用自回归 Transformer 当世界模型，再用扩散解码器把 token 画成高分辨率视频。[第 22 课](22_foundation_video_wm.md) 已经用它当只讲对照，本课把它展开。GAIA-2（Russell 等，arXiv:2503.20523）换成连续潜空间上的流匹配扩散，条件扩成自车动力学、他车配置、环境因素和道路语义，一次最多五路相机。GAIA-3 是 Wayve 2025 年 12 月 2 日的新闻稿：宣称 15B 参数、tokenizer 更大、数据大约十倍，用途从视觉合成转向离线评测。三份都无公开权重，不能练。

本课加的零件是条件分类，不是车。你要能把一份条件列表翻译成本课语言：哪些是动作 $a_t$，哪些是外生事件，哪些是风格或场景条件。对照桌宠：自车转向和速度对应关节命令；他车和行人对应 [第 31 课](31_interaction_memory.md) 那个你控制不了的人；天气更像房间灯光，不该进动作端口。再用 [第 33 课](33_embodiment_degrees.md) 的是否题，给「开环合成数据生成器」打一档。高清多相机仍然可以是 E0 或 E1。分辨率不升档。

开源对照写课前核对过仓库和论文号：Vista（Gao 等，arXiv:2405.17398，[OpenDriveLab/Vista](https://github.com/OpenDriveLab/Vista)）、DriveDreamer（Wang 等，arXiv:2309.09777，[JeffWang987/DriveDreamer](https://github.com/JeffWang987/DriveDreamer)）、OccWorld（Zheng 等，arXiv:2311.16038，[wzzheng/OccWorld](https://github.com/wzzheng/OccWorld)）、Drive-WM（Wang 等，arXiv:2311.17918，[BraveGroup/Drive-WM](https://github.com/BraveGroup/Drive-WM) 权重仍写在 TODO）。Vista 的 `docs/SAMPLING.md` 写采样建议至少 32GB，24GB 主线不够，只读文档。OccWorld 的 README 写 4090 24GB 可训可评，但数据是 nuScenes 全量加 Occ3D，本课不把下载这份数据写成作业。

术语速查：

| 术语 | 一句人话 |
|---|---|
| 驾驶世界模型 | 吃当前路况和一组条件，生成未来驾驶视频或占用；名称本身不保证能拿去选动作 |
| 自车（ego） | 装相机的那辆车；它的速度和转向曲率才是本课的 $a_t$ |
| 结构化条件 | 速度、曲率、3D 框、天气、车道类型这类有字段的输入，不是一句自由文本 |
| 外生事件 | 模型控制不了、却必须预测或指定的他者：对向来车、横穿行人 |
| 风格 / 场景条件 | 天气、时段、国家、相机几何；改它们不该等于「自车做了一个动作」 |
| 多相机时空一致 | 同一时刻前视、侧视、后视必须是同一个世界，不能各编各的 |
| 开环合成 | 先生成视频或占用，再拿去训感知或策略；生成器自己不在路上踩油门 |
| 流匹配 | 学一条从噪声指向真实潜变量的速度场，推理时积分；GAIA-2 世界模型用它训练 |
| AdaLN | 自适应层归一化：把动作这类全局信号乘加进每个 token，GAIA-2 用来注入速度和曲率 |
| 只讲 | 无公开权重或不满足 24GB；读论文和文档，把宣称和可核对事实分开写 |

## 2. 问题

驾驶域把第 12 课的三问和第 17 课的三分评测压到同一句广告里：「世界模型可以合成罕见事故」。这句话里至少混了三件不同的事。本课把它们拆开。

1. 条件接口比桌面密一个数量级。GAIA-1 的动作只有速度和曲率两个标量，文本另走一条。GAIA-2 把自车动力学、他车 3D 框、天气、车道、红绿灯、CLIP 向量和内部场景嵌入塞进同一个生成器。若把雨和对向来车都写进 $a_t$，动作对换实验会失去意义：你分不清模型听的是方向盘还是天气预报。
2. 验证者换了。CarRacing 和 PushT 可以 `reset()`，桌宠的杯子掉下去你还能扶起来。路上的验证者是碰撞、法规和不可重复的长尾。合成一段「打方向冲进对向车道」的视频，只说明生成器能按条件画画。它不说明有人用这个模型在真实交通里选过动作，更不说明规划已经通过。
3. 开源和封闭不在同一档。Wayve 的数据是内部车队，GAIA 系列无权重。开源侧 Vista 有权重可 clone，但官方采样建议 32GB，还依赖 nuScenes。OccWorld 能在 24GB 上跑，吃的是占用栅格不是多相机视频。Cosmos Cookbook 的 AV 页是 Transfer 2.5 的天气和时段迁移，控制信号是深度、边缘、分割和外观，不是 $a_t$。分类必须诚实，不能因为页面写了 Autonomous Vehicle 就把域适应记成世界模型。

一条界限先划清。本课不复现 Wayve 的封闭数据，不把合成事故视频写成已经验证了规划，也不去训车。你交的是条件分类表和一档 E0 或 E1，不是一份能上路的检查点。

## 5. 原理

八个机制。每个都落到「这条条件该进哪个端口」和「生成真能不能冒充规划好」。

### 5.1 验证者是路：生成真在驾驶里可以是产品

[第 12 课](12_frontier_landscape.md) 把「好」拆成预测准、生成真、规划好。[第 17 课](17_evaluating_world_models.md) 写成协议。桌宠毕业设计要规划好：伸手会不会扫杯，必须先在模型里分岔再决定动不动。自动驾驶公司还有另一张账单。罕见事故在真实道路上贵、险、少。若生成器能按指定条件吐出「雨夜、对向来车突然刹、自车保持车速」的多相机视频，感知和策略就有了可重复的训练样本。这一档里，生成真本身就是产品。

GAIA-2 摘要把用途写清楚：在一个生成框架里统一多相机、结构化条件和罕见场景仿真，服务自动驾驶系统的开发。报告没有把它写成在线规划器。GAIA-1 同样：用途声明是造场景和学表示，不是在模型里搜方向盘。[第 22 课](22_foundation_video_wm.md) 已经写过这句。本课补上后半句：用途声明为「合成数据」时，第三问默认不及格，直到有人拿出用它选动作再回真路验收的记录。

类比：这像飞行模拟器的视景系统。视景可以极真，飞行员仍要在另一套动力学和教员规则里练。类比失效处：视景系统通常不冒充自己已经通过了适航。驾驶世界模型的广告经常把视景和适航写在同一句里。本课的作业就是把两句拆开。

数学上，开环合成器学的是条件视频分布：

$$
P(o_{t+1:t+H} \mid o_{\le t}, a_{t:t+H}, c_{t:t+H})
$$

$o$ 是多相机像素或占用，$a$ 是自车动作，$c$ 是其余条件，$H$ 是地平线。规划器要的是在这个分布上对 $a$ 求最大或求安全。两件事共享同一个 $P$，验收协议完全不同。FID、FVD、FDD 量的是生成真。动作对换量的是第一问。真路上的碰撞率才是规划好。本课只做前两件的纸面分类，第三件标「本课不验收」。

### 5.2 GAIA-1：下一 token 当世界模型，扩散当画师

GAIA-1 把世界建模写成无监督序列建模。图像先过离散 tokenizer：分辨率 $288\times 512$，下采样 16 倍，每帧 $18\times 32=576$ 个图像 token，词表大小 8192。文本用预训练 T5-large，每步 32 个 token。动作是两个标量，速度和曲率，各映射成一个 $d$ 维向量。每一步按文本、图像、动作的顺序交织，空间位置嵌入一共 $32+576+2=610$ 个。世界模型是 65 亿参数的因果 Transformer，在 6.25 Hz 上预测下一个图像 token：

$$
\mathcal{L}_{\text{world model}}=-\sum_{t=1}^{T}\sum_{i=1}^{n}\log p(z_{t,i}\mid z_{1:t-1},z_{t,1:i-1},c_{1:t},a_{1:t-1})
$$

注意动作条件是 $a_{1:t-1}$：预测当前帧的图像 token 时，用的是过去的动作，不含当前动作。训练时随机丢掉条件，以便无条件、只看动作、只看文本三种生成都能做。视频从 25 Hz 抽到 6.25 Hz，再靠 26 亿参数的 3D U-Net 扩散解码器做时域超分，回到 25 Hz。解码器分辨率仍是 $288\times 512$。

数据是 Wayve 内部约 4700 小时伦敦驾驶，25 Hz，大约 4.2 亿张不重复图像。论文写明 proprietary。你无法复现这份数据。官方博客另有一篇缩放笔记，把整套系统说到超过 90 亿参数；正文里世界模型 65 亿、解码器 26 亿、tokenizer 3 亿，相加接近那个量级。本课引用以 arXiv 正文为准。

第一问在驾驶域成立：速度和曲率是逐步动作端口，不是一句「向左转」。论文图 13 展示同一段上下文，左打、大左打、右打、大右打，几何跟着变，对向车辆会做出避让。这是作者提供的定性证据，不是你的动作对换记录。第三问：论文把 GAIA-1 定位为神经仿真器和表示学习，明确写了尚未实时。不要把它读成已经在路上做 MPC。

和本课已学系统的同构：[第 09 课](09_iris_token_world_model.md) 的 IRIS 也是离散 token 加自回归世界模型；[第 10 课](10_diamond_diffusion_world_model.md) 的 DIAMOND 把扩散放进动力学。GAIA-1 把两段拼起来：token 空间里想下一步，像素空间里把想的结果画清楚。DINO-WM 后来把规划留在特征里、像素当可选可视化，是同一分工的另一边。

### 5.3 GAIA-2：连续潜空间、流匹配、多相机

GAIA-2 把离散 token 换成连续潜空间。作者的理由写在第 2 节：连续潜变量改善时间平滑和重建保真，并腾出更灵活的条件接口。系统仍是两段：视频 tokenizer 和潜空间世界模型。

Tokenizer 是时空分解的 Transformer，编码器约 8500 万参数，解码器约 2 亿。空间压缩 32 倍（常见潜扩散是 8 倍），时间压缩 8 倍，潜通道 64。一组 $(T_v,H_v,W_v)=(24,448,960)$ 的视频变成 $(T_L,H,W)=(3,14,30)$ 的潜变量，总压缩大约 384 到 400 倍。潜空间用 KL 正则成高斯，并加 DINOv2 蒸馏。解码器后训一小段 GAN。每路相机独立编码，多路潜变量在世界模型里才拼到一起。

世界模型 84 亿参数，22 个时空分解 Transformer 块，隐维 4096，32 头。训练用流匹配。上下文帧数 $t$ 从 0 到 $T-1$ 随机抽，$t=0$ 就是从纯噪声从零生成。未来潜变量与高斯噪声线性插值：

$$
\mathbf{x}_{t+1:T}^{\tau}=\tau\mathbf{x}_{t+1:T}+(1-\tau)\boldsymbol{\epsilon}_{t+1:T}
$$

速度目标是 $\mathbf{v}_{t+1:T}=\mathbf{x}_{t+1:T}-\boldsymbol{\epsilon}_{t+1:T}$。模型预测

$$
\hat{\mathbf{v}}_{t+1:T}=f_\theta(\mathbf{x}_{t+1:T}^{\tau}\mid\mathbf{x}_{1:t},\mathbf{a}_{1:T},\mathbf{c}_{1:T},\tau)
$$

损失是这支速度的 $L_2$。$\tau$ 用双峰 logit-normal：主峰在中等噪声，次峰贴近纯噪声，让模型既学结构也学细节。推理用 50 步线性-二次噪声日程，默认不用分类器自由引导；罕见他车配置才把引导尺度开到 2 到 20，并且可以只在 3D 框覆盖的空间位置上引导。

多相机：最多五路，$448\times 960$，英国、美国、德国，轿车和面包车多种相机架。论文图 2 把相机内参、外参、畸变加成位置编码。从零生成、按上下文滚动、空间 inpainting、对真实视频部分加噪再换条件，是同一套去噪过程的四种用法。长滚动用重叠滑窗，训练窗口之外靠自己刚生成的帧当新上下文。这和第 12 课量过的自回归失忆是同一类记忆：窗口外的东西只能靠先验补。

数据仍是内部的：约 2500 万段 2 秒视频，2019 到 2024，三国、多种车、20/25/30 Hz 混采。地理围栏留验证集。你没有这份数据。

### 5.4 三个端口：动作、外生、风格

GAIA-2 第 2.2.3 节的条件列表，必须翻译成本课语言。论文自己已经把动作和其他条件分开注入：速度和曲率走 AdaLN，其余走交叉注意力。作者写，动作影响每一个空间 token，AdaLN 提供显式门，比再学一层注意力更准。这是工程提示，也是概念提示：动作是全局干预，天气和他车框不是同一种干预。

**动作 $a_t$（自车动力学）。** 速度，单位 m/s，范围论文写 0 到 75；曲率，单位 m$^{-1}$，范围 $10^{-4}$ 到 $0.1$。两者跨数量级，先做对称对数 `symlog` 再缩到 $[-1,1]$。曲率的尺度系数 $s=1000$，速度的 $s=3.6$（相当于按 km/h 来看）。这就是本课的 $a_t$：你这辆车下一步打算怎么走。论文图 8 展示只给速度曲线、丢掉原始视频，模型仍能生成「红黄灯变绿起步」「跟在出租车后减速」「美国路口 U 形掉头」。图 9 把曲率扭向对向车道，对向车会躲。这些是条件生成，不是实车实验。

**外生事件（他车、行人、动态体）。** 3D 检测器给出的框：位置、朝向、尺寸、类别。框先投到各相机的 2D，再编码。训练时按维和按实例做 dropout，推理可以只给 2D 框、省略朝向、或改变实例个数。论文图 11 用框指定急刹、超车、闯路口。对向来车属于这一口。你不能把它当成 $a_t$：那不是自车的执行器。你也不能把它当成纯风格：换一辆对向来车，未来的碰撞几何必须变。

**风格与场景条件。** 国家、天气、时段；限速；车道数量和类型（可行驶、公交、自行车）；人行横道；红绿灯及其状态；单行线和路口类型（环岛等）。这些是离散元数据，各有嵌入。相机几何、时间戳、CLIP 图像或文本向量、内部驾驶模型的场景嵌入，也走这一侧。雨、夜、雪、换一个国家，属于这一口。论文图 6 对真实视频部分加噪，只改天气和时段，自车轨迹保持。这正好说明风格可以独立于 $a_t$ 被改写。

三口可以同时打开。危险场景的配方经常是：动作口给一个过猛的曲率，外生口给一辆对向车，风格口给雨夜。生成器的工作是让三口在像素里自洽。规划器的工作才是决定动作口到底填什么。本课只训练你认口，不训练你填规划。

GAIA-1 已经有这个萌芽：动作两个标量，文本管天气和灯色。GAIA-2 把文本里挤在一起的东西拆成字段，并加上他车框。拆开之后，才能问第 7 节那道题：自车速度、雨、对向来车，哪一项进动作端口。

### 5.5 开源对照：能 clone 的不等于能在 24GB 上播多相机

四个核对过的系统，用途和接口都不一样。

**Vista**（Gao 等，NeurIPS 2024，arXiv:2405.17398）。基于 Stable Video Diffusion 的潜扩散，公开数据约 1740 小时，10 Hz，$576\times 1024$，单相机前视。动作模态比 GAIA 还杂：转角和速度、轨迹、导航命令、目标点，统一接口注入。仓库 [OpenDriveLab/Vista](https://github.com/OpenDriveLab/Vista)，权重 `vista.safetensors` 在 Hugging Face `OpenDriveLab/Vista`。`sample.py` 的 `--action` 可取 `traj`、`cmd`、`steer`、`goal`；`--n_rounds` 每多一轮大约加 2.3 秒。`docs/SAMPLING.md` 写采样建议至少 32GB，另有 `--low_vram` 给不到 80GB 的卡。24GB 低于官方建议，本课不写「能跑」的体验命令。论文还用 Vista 自己当奖励模型，不访问真值动作；那是离线评估动作，仍不是上路。

**DriveDreamer**（Wang 等，ECCV 2024，arXiv:2309.09777）。扩散模型 Auto-DM，两阶段：先学 HD 地图和 3D 框这些交通结构，再按动作更新结构并预测未来视频。文本管晴、雨、夜。另有一个动作头，从历史动作和 Auto-DM 特征预测未来动作，并在 nuScenes 上报告开环规划。仓库 [JeffWang987/DriveDreamer](https://github.com/JeffWang987/DriveDreamer)，后续更新指向 GigaAI-research。它同时有生成头和动作头，读的时候不要合成一个「已经在规划的世界模型」：开环规划数字是轨迹误差，不是第 03 课那种对换。

**Drive-WM**（Wang 等，CVPR 2024，arXiv:2311.17918）。多相机（论文写最多六路）潜扩散，条件包括自车动作、动态体和环境因素，并宣称可接到已有端到端规划器上。仓库 [BraveGroup/Drive-WM](https://github.com/BraveGroup/Drive-WM) 基于 diffusers，README 的 TODO 仍列着条件图像、条件视频、动作条件视频的权重和训练代码「即将放出」。本课按无公开权重处理，只读论文。

**OccWorld**（Zheng 等，ECCV 2024，arXiv:2311.16038）。状态不是像素，是 3D 语义占用。VQ-VAE 把占用压成离散场景 token，再一个类 GPT 的时空 Transformer 自回归预测下一场景 token 和自车 token。输出是未来占用和自车轨迹。论文在 nuScenes 上报告：2 秒历史预测 3 秒未来，平均 IoU 26.63、mIoU 17.13；规划 L2 误差 1.16，且不用实例框和地图监督。关键接口：默认设定里，自车轨迹是预测目标，不是你可以任意改的 $a_t$。你不能直接做「同一占用、只把方向盘打满」的对换，除非改输入协议。仓库 [wzzheng/OccWorld](https://github.com/wzzheng/OccWorld)，README 写在 RTX 4090 24GB 上训 VQ-VAE、训 OccWorld、跑 `eval_metric_stp3.py`。数据门槛是 nuScenes 全量、Occ3D 的 `gts`、以及清华云盘上的 pkl 与预训练。有这份数据的人可以可视化；本课不把下载写成作业。

四家和 GAIA 的对照一句话：GAIA-2 把 $a_t$、他车框、风格拆得最干净，但你跑不了；Vista 动作模态最全，24GB 不够；DriveDreamer 有结构条件和动作头，开环规划不要写成路上验证；OccWorld 能进 24GB，但吃占用、自车默认是输出。

### 5.6 Cosmos Transfer 的 AV 页：域适应不是 $P(s_{t+1}\mid s_t,a_t)$

NVIDIA Cosmos Cookbook 的 [Autonomous Vehicle Domain Adaptation Gallery](https://nvidia-cosmos.github.io/cosmos-cookbook/gallery/av_inference.html)（Wagwani 等，2025-11-12）展示 Cosmos Transfer 2.5 把同一段行车视频迁到大雨、夜晚、雪、黄昏。控制权重是 depth、edge、seg、vis，再加文本提示。输入已经是一段有运动的视频，模型改的是外观和部分语义，尽量保住结构和运动。

Cosmos-Transfer1 论文（arXiv:2503.14492）自称 conditional world generation：用分割、深度、边缘等多模态空间控制生成世界。Cookbook 的 AV 页把这件事用在自动驾驶数据增广。本课的分类是：这是世界到世界的迁移，控制口是空间图，不是自车 $a_t$。你可以指定「大雨」，不能用同一接口指定「方向盘向右 30 度」。因此它很适合当生成对照，不适合当第 03 课那种动作条件世界模型。第 40 课的工业动作条件，指的是另一条后训练支路，不要和 Transfer 的 AV 画廊混成一步。

若有人把这段雨夜视频拿去训感知，那是下游的规划好或检测 mAP，裁判是下游任务，不是 Transfer 自己。本课验收不看你是否复现了 cookbook 里的 JSON 权重。

### 5.7 开环合成数据生成器：通常是 E0 或 E1

把第 33 课的是否题套上来。升级只看是否题，不看分辨率、相机路数、参数量。

1. 动作对换是否分岔？
2. 预测是否用于选动作或过滤动作？
3. 传感器与执行器是否共享同一物理世界？
4. 失败之后是否可以无限重置？
5. 接触或碰撞是否进入代价？
6. 是否存在控制不了、却必须预测的他者？
7. 不确定时停下是否算成功？

开环合成器的典型答案：Q3 否（生成器没有车身，路是视频里的路）。Q2 否（它不在动作出口上被查询，视频先写到磁盘）。Q4 对生成器自己是是（再 sample 一次就行），对路是否。Q6 在数据里经常是是（他车、行人），但那是条件字段，不是具身意义上的他者互动。

于是主档只看 Q1。

- 纯天气迁移、无 $a_t$，或有动作口但对换不分岔：E0。Cosmos Transfer AV 页落在这里。无动作的高清驾驶视频生成器也在这里。
- 有 $a_t$，论文或代码显示换速度或曲率未来会分岔，但对换和规划都在离线数据或梦里：E1。按论文描述，GAIA-1、GAIA-2、Vista 的动作条件生成属于这一档。你没有做对换，打分必须写成「按论文描述，不是我测得」。
- 不要因为多相机、15B、合成了事故，就升到 E2。E2 要求把动作送给 gym 或其它外部步进器。视频文件不是 `env.step`。
- 不要升到 E4。E4 要求物理身体且预测进入动作回路。开环合成按定义不在回路里。

GAIA-3 新闻稿宣称用途是离线评测和验证，包括安全关键场景、跨车身迁移、可控视觉多样性。即使接受全部宣称，它仍是开环工具，档仍是 E1（若动作口还在）或「未知」（若新闻稿没让你核对动作对换）。新闻稿不是技术报告，本课不编造它的层数、损失或相机路数。

OccWorld 容易打高。它输出规划轨迹，论文有 L2。Q2 仍建议答否或「部分」：开环轨迹误差是模仿专家轨迹，不是「同一占用下换一条候选 $a_t$，占用预测分岔，再丢掉危险动作」。没有对换记录，不要写成 E2。

### 5.8 搬回桌子：三端口对照桌宠

桌宠不需要五路相机，但需要同一张分类表。

| 驾驶字段 | 端口 | 桌子上的对应 |
|---|---|---|
| 自车速度、转向曲率 | 动作 $a_t$ | 转头、伸手、夹爪开合，[第 30 课](30_desk_world_model.md) 世界模型的动作维 |
| 他车 3D 框、行人、骑行者 | 外生事件 | 对面那个人的头和手，[第 31 课](31_interaction_memory.md) 要预测、不能当 $a_t$ 发 |
| 天气、时段、国家 | 风格 / 条件 | 房间灯光、窗帘、白天还是台灯 |
| 车道数、斑马线、红绿灯 | 场景语义条件 | 桌垫边界、杯沿、屏幕亮着与否；是状态的一部分，不是关节命令 |
| 相机内参外参 | 传感器几何 | 桌宠摄像头的外参；换机位不等于换动作 |
| CLIP / 文本「雨夜」 | 风格提示 | 「把灯调暗」这种话；话可以当指令走 VLA，不能冒充动力学输入 |

常见错法：把「下雨」写进桌宠的动作维，模型会以为自己选择了下雨。把「人伸手过来」写进 $a_t$，安全层会以为是自己的关节造成的。[第 31 课](31_interaction_memory.md) 已经要求人是外生过程；本课只是给这条要求一张来自驾驶的对照表。

桌宠用途到此为止。学的是条件怎么拆。下一课第 42 课才回到机器人基础模型的三个头。本课结束时你仍然没有一辆车。

## 7. 实验

实验是分类和打分，不是拟合。GPU 不是及格条件。网页若提供驾驶条件板，用网页；没有就用纸和本节表格。

### Step 1: 开驾驶条件板，只勾动作口

三张开关：自车速度、雨、对向来车。问：哪一项该进动作端口？

先自己勾，再对答案。

| 开关 | 进哪一口 | 理由 |
|---|---|---|
| 自车速度 | 动作 $a_t$ | 这是自车执行器；GAIA-1/2 的速度标量，Vista 的 speed / traj |
| 雨 | 风格 / 条件 | 天气元数据或文本；Transfer AV 页改的就是这一口 |
| 对向来车 | 外生事件 | 他车 3D 框；不是你的方向盘，也不是滤镜 |

三项全勾进动作口，算本步失败：后面的对换会把天气和他车当成自己的关节。只勾速度，才过。若你认为「对向来车可以由自车动作间接引起」，写在笔记里，但端口仍是外生：引起是动力学的结果，指定对向车出现是条件输入。

### Step 2: 翻译 GAIA-2 条件列表

对着 GAIA-2 第 2.2.3 节，把字段填进三列。不要凭记忆发明新字段。论文写了的才进表。

| 字段 | 端口 | 注入方式（论文） |
|---|---|---|
| 速度、曲率 | 动作 | AdaLN；先 `symlog` |
| 3D 框（位置、朝向、尺寸、类别） | 外生 | 交叉注意力；训练时按维和按实例 dropout |
| 国家、天气、时段 | 风格 | 离散嵌入，交叉注意力 |
| 限速、车道数与类型 | 场景条件 | 同上 |
| 斑马线、红绿灯及灯态、单行线、路口类型 | 场景条件 | 同上 |
| 相机内参、外参、畸变 | 传感器几何 | 加到 token 上的位置编码 |
| 时间戳 / 帧率 | 时间条件 | 正弦编码加 MLP |
| CLIP 向量 | 风格 / 语义 | 线性投影后交叉注意力 |
| 内部场景嵌入 | 场景条件 | 论文写 proprietary，本课不假装见过这个向量 |

交表时写一句：动作口只有速度和曲率。灯态和斑马线再重要，也不是 $a_t$。

### Step 3: 给开环合成器打档

用第 33 课七条是否题，给下面四个系统各打一档。答案只能是是、否、部分。部分必须写清。没有自己的对换记录时，Q1 写成「按论文描述」或「未知」，不要写成「我测得」。

| 系统 | Q1 | Q2 | Q3 | 档 | 依据 |
|---|---|---|---|---|---|
| 只改雨夜的 Transfer AV 生成 | 否（无 $a_t$） | 否 | 否 | E0 | cookbook JSON 无动作字段 |
| GAIA-2 按论文 | 是（AdaLN 注入速度曲率） | 否（用途是合成） | 否 | E1 | arXiv:2503.20523 第 2.2.3 与第 6 节 |
| Vista 按论文 | 是（多模态动作） | 否或部分（可当奖励，不上路） | 否 | E1 | arXiv:2405.17398；采样文档 |
| OccWorld 按论文 | 未知或否（自车默认是输出） | 部分（开环 L2，无对换） | 否 | E0 或 E1，取保守则 E0 | arXiv:2311.16038；不要因 L2 升 E2 |

参考答案：高清多相机的 GAIA-2 仍是 E1。理由是 Q2 否、Q3 否，主档不能过 E1。15B 的 GAIA-3 新闻稿不升档。

### Step 4: 读 Vista 采样文档，写下 24GB 结论

打开 `docs/SAMPLING.md`（clone 后本地读，或 GitHub 网页）。抄三行到笔记：建议显存、`--action` 的合法取值、`--low_vram` 的适用对象。然后写一句本课结论：主线 24GB 低于官方建议的 32GB，本课对 Vista 只读文档。不要补一条「我用 24GB 加上 low_vram 跑通了所以课程写错了」当验收；那是你自己的加餐，数字归你，不改本课档位。

### Step 5: 选做 OccWorld 可视化，或读输出约定

若你已经有 nuScenes、Occ3D `gts`、pkl 和预训练，按 README 跑 `visualize_demo.py`，看 `i` 与 `i_input` 在 t=2 秒是否还能认出车道和旁边的车。这只证明占用滚动能出图，不证明动作对换。

若没有数据，打开 `visualize_demo.py` 的参数列表，把 `--scene-idx` 和两个输出文件夹的含义抄进笔记。本步仍然及格。

### Step 6: 写桌宠对照四行

用 Step 2 的同一张三端口表，给桌宠填四行：伸手、对面的人把头转开、把灯关掉、杯沿。伸手必须进动作口；人转头必须进外生；关灯进风格或环境条件；杯沿进场景语义（状态），不是 $a_t$。四行口令错一口，回去重做 Step 1。

## 11. 前沿与改造

同一问题，2023 到 2026 年公开材料走了四条路。

第一条，封闭车队加结构化条件。GAIA-1 用离散 token 和两个动作标量；GAIA-2 用连续潜空间、五路相机和拆开的条件口；GAIA-3 新闻稿把产品从合成改口到离线评测。规模（65 亿到宣称 150 亿、数据到宣称十倍）是钱能买的。机制上真正多出来的，是把 $a_t$、他车、风格分成不同注入通道，以及多相机几何。本课能做的缩小版，是分类表，不是 256 张 H100。

第二条，公开数据上的单相机或占用世界模型。Vista 用 OpenDV 加 SVD，动作模态最全，奖励估计是它多出来的应用。OccWorld 把状态换成占用，规划头和场景头焊在一起。DriveDreamer 用 HD 地图和 3D 框降低扩散的搜索空间。这些你至少能 clone。24GB 能碰的只有 OccWorld 这条占用线，还要先过 nuScenes 许可证。

第三条，平台型可控生成。Cosmos Transfer 把深度、边缘、分割当成世界到世界的控制。AV cookbook 证明它可以做天气和时段。它补的是生成真和域间隙，不补动作对换。

第四条，把生成器接到规划器。Drive-WM 论文朝这边写，权重在仓库 TODO 里。DriveDreamer 的动作头、OccWorld 的轨迹头、Vista 的奖励，都是「生成之后还有一个动作分数」的变体。没有对换、没有外部步进器，它们仍停在 E1。

我们差在哪。规模差：你没有 4700 小时伦敦车队，也没有五路 $448\times 960$ 的同步视频。机制不差在「会不会扩散」，差在条件口有没有拆干净，以及验证者是磁盘上的视频还是会拒绝你的路。本课把机制差补在分类表上。规模差不补。

动手改造清单（都不新训驾驶大模型，24GB 预算）：

1. 把 [第 30 课](30_desk_world_model.md) 桌面世界模型的动作维打印出来，按本课三端口重新贴标签。预算：1 小时。预期：关节命令留在 $a_t$，灯光和时间戳从动作维拿掉。失败：发现训练时把「灯亮」当成了动作之一，对换会跟着灯走，那是数据协议问题，改采集，不改本课档位。
2. 在 [第 31 课](31_interaction_memory.md) 的人预测日志上，把「人伸手」标成外生事件，写一句它为什么不能进 $a_t$。预算：30 分钟。预期：安全层查询的是 $P(\text{人}_{t+1}\mid s_t,a_t^{\text{自}})$，人不是 $a_t^{\text{自}}$。失败：日志里人的动作和自车关节拼在同一个动作向量里。
3. 若有 nuScenes 且显存够跑 OccWorld 可视化：同一场景看 t=3 秒的占用，旁边是否无中生有一辆车。预算：一次可视化。预期：论文自己写了「新进视野的车难预测」。失败：把凭空出现的车当成规划已验证。
4. 加餐，不占主线：租到 ≥32GB 的卡时，按 Vista `docs/SAMPLING.md` 跑 `--action steer` 与默认无动作各一段，肉眼看弯道是否分岔。预算：读文档加一次采样。预期：有动作条件时应看到转向相关的画面差。失败：两段几乎一样，先查检查点是否匹配，再查 `--action` 是否真的读入。数字归你的加餐笔记，不写进本课复现。

论文结论到缩小版的映射：GAIA-2「动作用 AdaLN 更准」对应改造 1 的贴标签，缩小版只能对应到「动作必须有独立端口」，不能复现他们的消融数字。Vista「世界模型可当奖励」对应加餐 4 的分岔观察，方向可看，FID 不能比。OccWorld「占用空间能做开环规划」对应改造 3 的可视化，IoU 绝对值和 L2 绝对值你没有资格对照，除非完整复现评测脚本。

## 12. 论文与延伸

1. GAIA-1（Hu, Russell 等，[arXiv:2309.17080](https://arxiv.org/abs/2309.17080)）。带着问题读：第 2.1 节文本、图像、动作如何交织？公式 (1) 里动作条件为什么是过去动作、不含当前步？第 7.3 节出分布转向是定性展示还是定量对换？论文有没有把模型当成在线规划器？对照 [第 22 课](22_foundation_video_wm.md) 第 11 节，哪些句子本课补充了，哪些不要重复测量。
2. GAIA-2（Russell, Hu 等，[arXiv:2503.20523](https://arxiv.org/abs/2503.20523)）。带着问题读：第 2.2.3 节哪些字段走 AdaLN、哪些走交叉注意力？动态体 dropout 让推理可以缺哪几维？第 6 节安全关键场景是自车引起还是他车引起，对应本课哪一口？FDD / FID / FVMD / 框 IoU 各量的是三分评测里的哪一根尺子？
3. Vista（Gao 等，[arXiv:2405.17398](https://arxiv.org/abs/2405.17398)，仓库 [OpenDriveLab/Vista](https://github.com/OpenDriveLab/Vista)）。带着问题读：表 1 里 GAIA-1 与 Vista 在数据是否公开、帧率、分辨率、动作模态上各差什么？长滚动的 latent replacement 在补第 12 课的哪一种失忆？奖励实验有没有真值动作？`docs/SAMPLING.md` 的 32GB 和 `--action` 取值是否仍与当前仓库一致？
4. DriveDreamer（Wang 等，[arXiv:2309.09777](https://arxiv.org/abs/2309.09777)）。带着问题读：两阶段各自的输入输出是什么？HD 地图和 3D 框属于三端口的哪一口？动作头预测的 $A$ 和条件里的 driving actions 是不是同一个张量？nuScenes 开环规划数字能支持第 33 课哪一条是否题？
5. OccWorld（Zheng 等，[arXiv:2311.16038](https://arxiv.org/abs/2311.16038)，仓库 [wzzheng/OccWorld](https://github.com/wzzheng/OccWorld)）。带着问题读：占用 tokenizer 和 GPT 式时空注意力怎样对应 [第 09 课](09_iris_token_world_model.md)？自车 token 是条件还是预测目标？图 1 自己承认的失败（新车进视野）和 [第 21 课](21_persistent_4d.md) 物体恒常是不是同一类问题？规划 L2 为什么不够升到 E2？
6. Drive-WM（Wang 等，[arXiv:2311.17918](https://arxiv.org/abs/2311.17918)）。带着问题读：多相机一致性怎样训练？它怎样宣称接到端到端规划器？仓库 README 的 TODO 今天是否仍未放权重？
7. Cosmos-Transfer1（NVIDIA，[arXiv:2503.14492](https://arxiv.org/abs/2503.14492)）与 Cookbook AV 页。带着问题读：空间控制（深度、边缘、分割）和 $a_t$ 的差别？AV 画廊的 JSON 里有没有速度或曲率？为什么域适应可以服务驾驶数据，仍可能是 E0？
8. 回访 Ha 和 Schmidhuber 2018 的 World Models，以及 [第 33 课](33_embodiment_degrees.md) 第 5.6 节。带着问题读：开环合成器满足 Wilson 的哪一条、不满足哪一条？Brooks 会怎样批评一份与当前车身脱节的漂亮多相机视频？
9. 选读 DriveDreamer-2（[arXiv:2403.06845](https://arxiv.org/abs/2403.06845)）。带着问题读：LLM 写的用户场景，进的是风格口还是动作口？「车辆突然切入」在本课分类里是外生事件，提示词写出来并不等于模型有了 3D 框端口。

现在系统会：把驾驶生成器的条件拆成动作、外生事件和风格，并给开环合成器打 E0 或 E1。多相机高清是生成真，验证者仍是路。下一课第 42 课处理机器人基础模型：理解头、生成头、动作头焊在同一句广告里时，要会拆。桌宠继续用第 30 课的小世界模型当过滤器即可，不必换上一辆车，也不必换上 150 亿参数。
